# 본문·도우미 읽기 스타일

원고와 도우미의 답변을 편안하게 읽을 수 있도록 글꼴, 크기, 간격, 인용 부호 서식을 조절하는 기능이에요.

읽기 설정은 사용하는 웹 브라우저의 로컬 환경에 공통으로 저장돼요. 작품별로 별도 설정을 분리하거나 문맥의 의미를 임의로 해석해 줄을 나누지 않으며, 사용자가 정한 규칙에 따라 화면에 표시해요.

## 본문 읽기와 장면 조작

원고를 열어 둔 동안 본문 생성 진행률이나 번역 작업 상태만 바뀌면 리더는 현재 장면 목록을 재사용해요. 새 장면이 생기거나 장면 이름·플롯·요청문이 바뀌면 목록을 다시 받아요.

### 장면 메뉴와 번역 조작

- **최신 장면 조작**: 최신 장면에서는 **복사**, **수정**, **책갈피**, **원문/번역 전환** 버튼을 화면에서 바로 사용할 수 있어요.
- **이전 장면 작업**: 이전 장면은 책갈피 버튼만 바로 노출하고, 나머지 복사·수정·원문/번역 전환은 **장면 작업** 메뉴 안에 모아서 제공해요. 읽기 언어 기본값과 다른 표시(원문/번역)를 보고 있을 때만 장면 머리글에 그 상태를 표시해요.
- **번역 상태 표시**:
  - 번역이 없는 경우: **번역 생성**
  - 번역이 실패한 경우: **번역 다시 시도** (실패 안내와 함께 노출)
  - 번역이 저장된 경우: **번역 보기** (저장된 결과를 열며 모델을 다시 호출하지 않음)
  - 기존 번역이 있어도 새로 번역하고 싶을 때는 장면 메뉴의 **현재 설정으로 새 번역**을 사용해요.
  - 번역 확인은 저장된 본문 원문이나 작성된 HTML을 바꾸지 않아요.
- **자동 번역이 끝났을 때**: 원문으로 읽고 있는 장면의 자동 번역이 끝나면, 번역을 요청한 뒤 그 장면에서 스크롤하거나 글을 선택하거나 편집한 경우, 그리고 번역이 끝난 순간 그 장면의 글이 선택돼 있거나 편집기가 열려 있는 경우에는 화면을 바꾸지 않고 장면 머리글에 **번역이 준비됐어요** 배지를 보여 줘요. 배지를 누르면 번역으로 바꿔요. 아무 조작 없이 기다리고 있었다면 번역으로 바꾸되 읽던 위치를 지켜요. 그 장면에서 원문이나 번역을 직접 골랐거나 읽기 언어 기본값이 원문이면 바꾸지 않아요.
- **선택한 글의 작업**: 본문에서 글을 선택하면 다듬기, 도우미에게 묻기, 책갈피, 복사 막대가 떠요. 동작과 조건은 [읽는 중에 다듬기](EDITING.md#읽는-중에-다듬기)에 있어요.

### 작업 취소와 화면 정리

- **재생성 취소**: 기존 응답의 다시 쓰기(재생성)를 취소하면, 취소된 시도는 원고 화면에서 접고 기존 응답을 보여줘요.
- **새 장면 생성 취소**: 새 장면 생성을 취소하면 요청문, 취소 안내문과 함께 **다시 시도**, **화면에서 정리**, **작업 기록** 버튼이 나타나요.
  - **화면에서 정리**: 취소된 카드를 화면에서 숨겨요. 서버에 영속화되어 새로고침하거나 다른 기기에서 열어도 정리된 상태가 유지돼요. (요청문, 일부 수신된 응답, 사용량, 재시도 기록은 데이터베이스에 보존돼요.)
  - 요청문을 편집하는 동안에는 화면 정리를 누를 수 없어요.
  - 실패·중단·결과 불확실 상태의 작업은 자동으로 숨기지 않으며, 취소 처리보다 완료 확정이 먼저 도착하면 완성된 원고를 보여줘요.
- **장면 삭제 결과 확인**: 장면 삭제의 응답을 확인하지 못하면 장면이 이미 화면에서 사라졌거나 새로고침했어도 해당 채팅에서 **삭제 결과 다시 확인**을 열 수 있어요. 확인 전에는 삭제 범위와 기존 요청을 보관하며, 다시 확인할 때에만 같은 요청을 보내요. 늦은 삭제 응답은 그동안 새로 선택한 읽기 위치를 바꾸지 않아요.

## 읽기 설정과 인용 스타일

**설정 → 일반 → 원고 읽기** 또는 채팅 메뉴의 **읽기 설정**에서 변경할 수 있어요.

### 본문 스타일과 프리셋

- **본문 크기**: 9px부터 28px까지 1px 단위로 조절할 수 있으며 기본값은 18px이에요.
- **글꼴과 폭**: 원하는 글꼴과 본문 폭, 줄간격 및 문단 간격을 지정하고 예문으로 미리 볼 수 있어요.
- **스타일 프리셋**:

| 프리셋 | 특징과 동작 |
| --- | --- |
| **기본** | 인용 강조와 대사/생각 줄바꿈을 모두 끄고 기본 간격으로 표시해요. |
| **여유롭게** | 행간 2.2와 문단 간격 1.5em을 적용해 쾌적한 줄간격을 제공해요. |
| **대사 중심** | 은은한 대사 강조와 대사 줄바꿈을 켜서 대화가 돋보이게 해요. (생각 줄바꿈은 꺼짐) |
| **사용자 설정** | 강조, 줄바꿈, 간격을 원하는 대로 직접 조절한 상태예요. |

**읽기 스타일 초기화**를 누르면 부호별 역할을 포함한 읽기 스타일이 기본값으로 돌아가며, 설정해 둔 글꼴·크기·본문 폭·기본 보기 선택은 유지돼요.

### 부호별 역할과 줄바꿈

문장 부호에 따라 대사, 생각, 일반 인용으로 분류하고 시각적인 줄바꿈을 부여해요.

- **기본 부호 역할**:
  - 대사: `"…"` (큰따옴표), `“…”` (둥근 큰따옴표), `「…」` (낫표)
  - 생각: `'…'` (작은따옴표), `‘…’` (둥근 작은따옴표)
  - 일반 인용: `『…』` (겹낫표)
- **역할 변경**: 각 부호는 대사, 생각, 일반 인용, 또는 처리 안 함으로 자유롭게 변경할 수 있어요.
- **대사 줄바꿈 / 생각 줄바꿈**:
  - 완결된 최상위 인용 부호의 앞뒤를 화면 표시 상에서 독립된 문단처럼 띄워요.
  - 기존 본문에 이미 존재하는 줄바꿈이나 문단 경계는 보존하며, 줄바꿈이 없는 방향에만 표시용 여백을 추가해요.
  - 중첩된 인용 내부에서는 줄을 다시 나누지 않으며, 짝이 닫히지 않은 인용은 그대로 표시해요.
  - 영문 아포스트로피(`'`), 코드 블록, URL, HTML 태그 속성, 루비 문자 내부, 보호 토큰은 분석에서 제외돼요.
  - `“괜찮아”라고 말했다.`처럼 인용문 뒤에 조사나 서술어가 바로 붙어 있어도, 대사 줄바꿈이 켜져 있다면 닫는 부호 뒤에서 시각적 줄바꿈이 적용돼요.

## Native Risu 첫 메시지

봇에 작성된 초기 인삿말을 첫 메시지로 다루고, 독자가 읽기 편하도록 장면을 체계적으로 안내해요.

### 첫 메시지 관리와 시작

- **장면 번호 체계**: 봇의 첫 인삿말은 **첫 메시지**로 구분해 표시하고, 사용자와의 대화로 생성된 첫 결과부터 **장면 1**로 번호를 매겨요. 장면 목록에서도 첫 메시지는 번호 대신 전용 아이콘과 제목으로 구분돼요.
- **새 채팅 시작**: 새 채팅 창에서 첫 메시지를 고르고 **미리보기**를 펼치면 봇 제작자가 꾸며둔 화면 구성을 미리 확인할 수 있어요. 첫 메시지 없이 시작할 수도 있어요.
- **첫 메시지 변경**: 첫 메시지가 등록된 봇은 첫 메시지 카드 하단의 **장면 작업 메뉴 → 첫 메시지 바꾸기**를 통해 다른 인삿말로 교체할 수 있어요. 목록에서 **첫 메시지 없이 시작**을 누르면 첫 메시지를 비울 수도 있어요. 후속 요청이나 봇 상호작용으로 대화가 본격적으로 진행되기 전까지 자유롭게 변경할 수 있어요. (이전 메시지 기록은 데이터베이스에 보존돼요.) 첫 메시지 변경의 응답이 불명확하면 같은 요청으로 결과를 확인하며, 확인 중 오류가 나도 기존 요청과 선택을 유지해요.

### 장면 탐색과 모바일 내비게이션

- **모바일 상단 내비게이터**: 모바일 화면에서는 상단 채팅 제목 아래에 현재 장면과 전체 장면 수(예: `3 / 12`)가 표시돼요. 제목을 탭하면 장면 목록이 열려 번호, 이름, 요청 요약으로 원하는 장면을 찾아 바로 이동할 수 있어요.
- **맨 아래로 이동**: 최신 읽기 위치에서 위로 스크롤해 올라간 경우, 입력창 도구 영역에 맨 아래 이동 아이콘이 나타나요. (입력창에 포커스가 있거나 원문을 편집하는 중에는 숨겨져요.)
- **집중 읽기와 설정**: 읽기 설정에서 채팅 내비게이터를 끌 수 있으며, 집중 읽기 모드에서는 내비게이터 눈금과 이동 버튼이 자동으로 숨겨져요. 데스크톱에서는 좌측 장면 눈금 레일이 유지돼요.
- **스크롤 위치 보존**: 원문이나 번역을 직접 수정하는 동안에는 편집창이 열리고 읽기 영역은 잠시 숨겨져요. 저장을 완료하거나 취소하면 읽던 스크롤 위치와 화면 선택이 정확하게 복원돼요.

## 도우미 세션 활용

원고 집필, 서재 자료 제작, 프롬프트 수정을 돕는 도우미(Helper) 작업 공간이에요.

### 중앙 작업 공간과 프로젝트 탐색

- **작업 공간 전환**: 공통 사이드바의 **채팅**과 **도우미** 아이콘으로 중앙 화면을 전환해요. 원고 옆에 열어두는 사이드 도우미와 중앙 전체 화면 도우미(**도우미 크게 보기**)를 오가더라도 진행 중인 작업, 입력 초안, 참조 자료가 이어져요.
- **우측 패널**: 데스크톱에서 원고 옆 패널은 **도우미**, **플롯**, **창작 옵션** 탭을 가진 하나의 영역이에요. 채팅 머리글의 도우미와 플롯 버튼은 열린 탭을 눌린 상태로 보여 주고, 창작 옵션은 입력창 더보기 메뉴에서 열어요. 탭을 바꿔도 도우미 초안과 스크롤, 플롯의 선택과 편집 중인 항목, 창작 옵션 초안이 남아요. `Ctrl/Cmd+\`는 마지막으로 쓴 탭으로 패널을 열고 닫아요. 원고와 패널 사이 경계선을 끌거나, 경계선에 포커스를 두고 좌우 화살표 키로 폭을 바꿔요. 원고 영역은 768px보다 좁아지지 않고, 패널은 360px(플롯 탭은 400px)보다 좁아지지 않아요. 폭은 놓을 때 이 브라우저에 저장돼요. 좁은 화면에서는 도우미와 창작 옵션이 원고 위에 겹쳐 열리고 플롯은 전체 화면으로 열려요.
- **프로젝트로 대화 정리**:
  - 도우미 대화 목록은 채팅 목록과 같은 모양이에요. 위쪽의 **탐색**과 **활동** 탭 옆 목록 메뉴에서 **프로젝트 만들기**로 관련 대화를 묶고, 정렬을 최근 활동순, 이름순, 수동 정렬(드래그 또는 위/아래 이동) 중에서 골라요.
  - 대화와 프로젝트의 메뉴는 마우스를 올리거나 키보드로 포커스하면 나타나고, 터치 화면과 좁은 화면에서는 늘 보여요. 대화 메뉴에서 프로젝트 이동, 제목 변경, 대화 복사, 삭제를 지원해요. 프로젝트를 삭제하더라도 포함되어 있던 대화는 삭제되지 않고 유지돼요.
  - 도우미를 열기만 해도 그 채팅의 기본 대화가 만들어져요. 요청을 한 번도 보내지 않았고 이름이나 말투, 프로젝트도 바꾸지 않은 기본 대화는 다른 채팅의 목록과 전체 목록에 나오지 않아요. 열어 보기만 한 채팅의 빈 대화가 목록을 채우지 않게 하려는 거예요. 그 채팅 자체의 목록에는 늘 보이고, 이 탭에서 한 번 연 대화는 탭을 새로 고칠 때까지 계속 보여요. 입력창 초안은 브라우저에만 있어서 서버가 알 수 없으므로, 초안을 쓰던 대화로 돌아갈 길을 이 두 조건으로 남겨요. 대화는 지우지 않아요. **새 대화**로 직접 만든 대화는 비어 있어도 늘 보여요.
  - 마지막 작업이 실패했거나 중단, 취소된 대화는 탐색 목록과 최근 대화에 그 상태를 표시해요. 새 작업이 진행 중이면 진행 표시만 보여요.
- **활동 모니터링**: 확인할 활동, 진행 중인 작업, 최근 대화를 한눈에 볼 수 있으며, 완료나 실패 알림은 대화를 확인하면 자동으로 정리돼요. 확인한 상태는 서버에 저장되므로 다른 브라우저나 기기에서도 확인한 대화로 보여요. 제목이나 프로젝트를 바꾸는 것은 새 활동으로 치지 않아요.

### 입력창과 실행 편의 기능

- **컨텍스트 칩**: 고정된 자료, 현재 열려 있는 활성 편집기, 선택한 계층형 플롯, 본문 선택 구절이 도우미 입력창 안에 인라인 칩 형태로 자동 연결돼요. 대화별로 열려 있는 편집기를 캡처하므로 다른 대화의 편집기가 숨겨진 채 잘못 전달되지 않아요.
- **요청 방식(바로 적용과 계획)**: 입력창 도구 줄의 요청 방식 버튼이나 도우미 안에서 `Alt+M`(Apple 기기는 `Option+M`)으로 다음 요청을 **계획**으로 보낼지 정해요. 계획을 고르면 버튼에 **계획**이 표시되고, 바로 적용일 때는 연필 아이콘만 보여요. 계획 요청에서 도우미는 읽기만 하고 아무것도 저장하지 않으며, 그 작업의 상태 줄에 **계획** 표시가 붙어요. 답변은 계획 카드로 보이고, 길면 일부만 보이다가 **계획 모두 보기**로 펼쳐요. 마지막 작업이 계획이면 카드의 **이 계획대로 진행**이 그 계획을 실행하는 일반 요청을 보내고, 요청 방식을 바로 적용으로 되돌려요. 고른 방식은 대화마다 따로 기억하며 이 탭을 새로 열면 바로 적용으로 돌아가요.
- **진행 과정 실시간 관측**: 도우미가 작업 중일 때는 입력창 위에서 진행 단계와 도구 호출 현황을 실시간으로 보여줘요. 연달아 읽은 장면과 자료는 "장면 2개, 자료 1개"처럼 한 줄로 묶이고, 누르면 호출마다 펼쳐져요. 상태 줄은 지금 기다리는 것을 말해요. 모델의 응답이면 몇 번째 호출인지, 도구면 종류와 대상, 프로바이더 오류 뒤의 대기면 몇 초 뒤에 몇 번째로 다시 시도하는지를 보여 줘요. 목록은 새 단계를 따라 내려가고, 위로 올려 읽는 동안에는 따라 내려가지 않아요. Gemini 모델을 쓰면 모델이 응답을 만드는 동안 [생각 요약](EXECUTION.md#생각-요약)이 응답 자리에 흐려진 글씨로 보이고, 그 호출이 끝나면 사라져요. 생각 요약은 저장하지 않아요.
  - **현재 작업에 추가**: 실행 중인 도우미 작업에 추가 지시를 전달해요.
  - **다음 요청**: 현재 작업이 끝난 뒤 실행될 별도 요청으로 접수해요.
- **작업 기록과 복사**:
  - 도우미 **작업 기록**에서 긴 요청문은 **요청 전체 보기**로 펼쳐 원문 공백과 줄바꿈 그대로 복사할 수 있어요.
  - 완성된 답변 안의 코드 블록에는 개별 복사 버튼이 있어 해당 블록의 내용만 손쉽게 복사할 수 있어요.
  - 입력창 도구 줄의 **컨텍스트 약 …**은 이 대화의 마지막 요청 입력을 이 기기에서 센 추정치예요. 작은 막대는 입력 예산 대비 비율이고, 눈금은 자동 정리가 시작되는 지점(예산의 85%)이에요. 누르면 지시문, 도구 설명, 대화, 원문과 자료, 도구 결과로 나눈 내역을 보여 줘요. 측정하지 못한 값은 미확인으로 두고, 네이티브 에이전트는 스스로 컨텍스트를 관리하므로 보고된 마지막 입력만 보여 주고 막대는 그리지 않아요.
  - 사용량 요약의 작은 막대는 마지막 전송 입력의 추정치와 당시 입력 예산을 비교해요. 정확한 수치, 캐시, 추론, 호출 수와 비용은 펼쳐서 확인해요. 누적 입력 토큰이나 네이티브 에이전트의 현재 컨텍스트 점유율을 나타내는 막대는 아니며, 입력 예산 기록이 없는 과거 작업은 저장된 모델 스냅샷의 한도를 사용할 수 있을 때만 막대를 표시해요.
- **대화 내용 편집과 가지치기**:
  - 메시지 메뉴에서 과거의 요청이나 답변을 직접 편집해 저장할 수 있어요. (다시 실행하지 않고 다음 대화에 반영돼요.)
  - 특정 요청·답변 한 쌍을 삭제하거나, 해당 위치부터 이후의 대화를 일괄 삭제할 수 있어요. 이미 완료된 자료 수정 결과와 사용량 기록은 유지돼요.
- 첨부 파일의 지원 형식과 보존 정책은 [도우미 첨부](HELPER-ATTACHMENTS.md)를 참고해요.

## 도우미 모델 선택·재시도와 이어서 하기

- 모델을 변경하면 다음 요청을 위한 역할별 모델의 도우미 역할이 갱신되며, 현재 채팅의 본편 작문 모델이나 다른 역할은 변경하지 않아요.
- 대화별 호출 한도는 수동 편집하지 않아요.
- 새로 접수되는 도우미 작업은 내부 정책에 따라 **도우미 판단 64회**, **전체 모델 호출 128회**, **호스트 도구 호출 256회**와 설정의 **도우미 작업 제한 시간**(기본 60분)을 적용해요.
- 이미 접수된 작업은 접수 당시 저장된 호출 한도를 보존해요.
- 프로바이더가 요청 한도 초과(429)나 일시적인 서버 오류(5xx)로 답하면, 도우미는 5초, 20초, 60초를 차례로 기다리며 같은 호출을 최대 세 번 다시 보내요. 그때까지 읽은 자료와 저장한 변경은 그대로 이어 써요. 세 번 뒤에도 같은 오류면 작업을 실패로 끝내요. 기다리는 동안에도 작업을 멈출 수 있고, 다시 보낸 호출도 전체 모델 호출 한도에 들어가요.
- 프로바이더가 응답을 거절하면 도우미는 기다리지 않고 같은 호출을 바로 다시 보내요. 횟수는 **앱 설정 → 새 채팅 기본값**의 **거절되면 자동으로 다시 생성**을 따르고(기본 켜짐, 최대 2회), 채팅마다 따로 정한 값은 도우미에 적용하지 않아요. 거절된 호출마다 횟수를 새로 세고, 다시 보낸 호출도 전체 모델 호출 한도에 들어가요. 횟수를 다 쓰고도 거절되면 작업을 실패로 끝내고 **다시 시도**나 **이어서 하기**를 기다려요.
- 실패했거나 멈춘 작업이 그 전에 자료를 읽었거나 변경을 저장했으면 **이어서 하기**가 보여요. 누르면 같은 요청을 새 작업으로 시작하면서, 앞 작업이 읽은 내용과 저장한 변경의 기록을 그대로 넘겨줘요. 그래서 이미 저장한 변경을 다시 하지 않고 남은 일만 이어 가요. 변경을 저장한 뒤 실패한 작업은 **다시 시도**(처음부터)를 할 수 없고 이어서 하기만 할 수 있어요. 이어 가는 작업은 자기 호출 한도와 제한 시간을 새로 받고, 현재 설정의 도우미 모델을 써요. 요청 한도 초과가 몇 분씩 이어져서 다시 시도가 소진된 경우에도 잠시 뒤에 이어서 하기로 이어 가면 돼요. 앞 작업의 기록이 정리되었거나, 삭제한 장면을 포함한 작업이거나, 네이티브 Codex 실행기로 돌린 작업은 이어서 할 수 없어요.

# 본문·도우미 읽기 스타일

원고와 도우미의 답변을 편안하게 읽을 수 있도록 글꼴, 크기, 간격, 인용 부호 서식을 조절하는 기능이에요.

읽기 설정은 사용하는 웹 브라우저의 로컬 환경에 공통으로 저장돼요. 작품별로 별도 설정을 분리하거나 문맥의 의미를 임의로 해석해 줄을 나누지 않으며, 사용자가 정한 규칙에 따라 화면에 표시해요.

## 본문 읽기와 장면 조작

### 장면 메뉴와 번역 조작

- **최신 장면 조작**: 최신 장면에서는 **복사**, **수정**, **책갈피**, **원문/번역 전환** 버튼을 화면에서 바로 사용할 수 있어요.
- **이전 장면 작업**: 이전 장면은 책갈피 버튼만 바로 노출하고, 나머지 복사·수정·원문/번역 전환은 **장면 작업** 메뉴 안에 모아서 제공해요. 현재 읽고 있는 표시 상태(원문/번역)는 각 장면 머리글에서 확인해요.
- **번역 상태 표시**:
  - 번역이 없는 경우: **번역 생성**
  - 번역이 실패한 경우: **번역 다시 시도** (실패 안내와 함께 노출)
  - 번역이 저장된 경우: **번역 보기** (저장된 결과를 열며 모델을 다시 호출하지 않음)
  - 기존 번역이 있어도 새로 번역하고 싶을 때는 장면 메뉴의 **다시 번역**을 사용해요.
  - 번역 확인은 저장된 본문 원문이나 작성된 HTML을 바꾸지 않아요.

### 작업 취소와 화면 정리

- **재생성 취소**: 기존 응답의 다시 쓰기(재생성)를 취소하면, 취소된 시도는 원고 화면에서 접고 기존에 완성되어 있던 응답을 안전하게 유지해요.
- **새 장면 생성 취소**: 새 장면 생성을 취소하면 요청문, 취소 안내문과 함께 **다시 시도**, **화면에서 정리**, **작업 기록** 버튼이 나타나요.
  - **화면에서 정리**: 취소된 카드를 화면에서 숨겨요. 서버에 영속화되어 새로고침하거나 다른 기기에서 열어도 정리된 상태가 유지돼요. (요청문, 일부 수신된 응답, 사용량, 재시도 기록은 데이터베이스에 보존돼요.)
  - 요청문을 편집하는 동안에는 화면 정리를 누를 수 없어요.
  - 실패·중단·결과 불확실 상태의 작업은 자동으로 숨기지 않으며, 취소 처리보다 완료 확정이 먼저 도착하면 완성된 원고를 보여줘요.
- **장면 삭제 결과 확인**: 장면 삭제의 응답을 확인하지 못하면 장면이 이미 화면에서 사라졌거나 새로고침했어도 해당 채팅에서 **삭제 결과 다시 확인**을 열 수 있어요. 확인 전에는 삭제 범위와 기존 요청을 보관하며, 다시 확인할 때에만 같은 요청을 보내요. 늦은 삭제 응답은 그동안 새로 선택한 읽기 위치를 바꾸지 않아요.

## 읽기 설정과 인용 스타일

**설정 → 일반 → 원고 읽기** 또는 채팅 메뉴의 **읽기 설정**에서 변경할 수 있어요.

### 본문 스타일과 프리셋

- **본문 크기**: 9px부터 28px까지 1px 단위로 조절할 수 있으며 기본값은 18px이에요.
- **글꼴과 폭**: 원하는 글꼴과 본문 폭, 줄간격 및 문단 간격을 지정하고 예문으로 미리 볼 수 있어요.
- **스타일 프리셋**:

| 프리셋 | 특징과 동작 |
| --- | --- |
| **기본** | 인용 강조와 대사/생각 줄바꿈을 모두 끄고 기본 간격으로 표시해요. |
| **여유롭게** | 행간 2.2와 문단 간격 1.5em을 적용해 쾌적한 줄간격을 제공해요. |
| **대사 중심** | 은은한 대사 강조와 대사 줄바꿈을 켜서 대화가 돋보이게 해요. (생각 줄바꿈은 꺼짐) |
| **사용자 설정** | 강조, 줄바꿈, 간격을 원하는 대로 직접 조절한 상태예요. |

**읽기 스타일 초기화**를 누르면 부호별 역할을 포함한 읽기 스타일이 기본값으로 돌아가며, 설정해 둔 글꼴·크기·본문 폭·기본 보기 선택은 유지돼요.

### 부호별 역할과 줄바꿈

문장 부호에 따라 대사, 생각, 일반 인용으로 분류하고 시각적인 줄바꿈을 부여해요.

- **기본 부호 역할**:
  - 대사: `"…"` (큰따옴표), `“…”` (둥근 큰따옴표), `「…」` (낫표)
  - 생각: `'…'` (작은따옴표), `‘…’` (둥근 작은따옴표)
  - 일반 인용: `『…』` (겹낫표)
- **역할 변경**: 각 부호는 대사, 생각, 일반 인용, 또는 처리 안 함으로 자유롭게 변경할 수 있어요.
- **대사 줄바꿈 / 생각 줄바꿈**:
  - 완결된 최상위 인용 부호의 앞뒤를 화면 표시 상에서 독립된 문단처럼 띄워요.
  - 기존 본문에 이미 존재하는 줄바꿈이나 문단 경계는 보존하며, 줄바꿈이 없는 방향에만 표시용 여백을 추가해요.
  - 중첩된 인용 내부에서는 줄을 다시 나누지 않으며, 짝이 닫히지 않은 인용은 그대로 표시해요.
  - 영문 아포스트로피(`'`), 코드 블록, URL, HTML 태그 속성, 루비 문자 내부, 보호 토큰은 분석에서 안전하게 제외돼요.
  - `“괜찮아”라고 말했다.`처럼 인용문 뒤에 조사나 서술어가 바로 붙어 있어도, 대사 줄바꿈이 켜져 있다면 닫는 부호 뒤에서 시각적 줄바꿈이 적용돼요.

## Native Risu 첫 메시지

봇에 작성된 초기 인삿말을 첫 메시지로 다루고, 독자가 읽기 편하도록 장면을 체계적으로 안내해요.

### 첫 메시지 관리와 시작

- **장면 번호 체계**: 봇의 첫 인삿말은 **첫 메시지**로 구분해 표시하고, 사용자와의 대화로 생성된 첫 결과부터 **장면 1**로 번호를 매겨요. 장면 목록에서도 첫 메시지는 번호 대신 전용 아이콘과 제목으로 구분돼요.
- **새 채팅 시작**: 새 채팅 창에서 첫 메시지를 고르고 **미리보기**를 펼치면 봇 제작자가 꾸며둔 화면 구성을 미리 확인할 수 있어요. 첫 메시지 없이 시작할 수도 있으며, 첫 메시지를 선택해 채팅을 생성해도 본문 텍스트 모델을 불필요하게 호출하지 않아요.
- **첫 메시지 변경**: 첫 메시지가 등록된 봇은 첫 메시지 카드 하단의 **장면 작업 메뉴 → 첫 메시지 바꾸기**를 통해 다른 인삿말로 교체할 수 있어요. 목록에서 **첫 메시지 없이 시작**을 누르면 첫 메시지를 비울 수도 있어요. 후속 요청이나 봇 상호작용으로 대화가 본격적으로 진행되기 전까지 자유롭게 변경할 수 있어요. (이전 메시지 기록은 데이터베이스에 보존돼요.) 첫 메시지 변경의 응답이 불명확하면 같은 요청으로 결과를 확인하며, 확인 중 오류가 나도 기존 요청과 선택을 유지해요.

### 장면 탐색과 모바일 내비게이션

- **모바일 상단 내비게이터**: 모바일 화면에서는 상단 채팅 제목 아래에 현재 장면과 전체 장면 수(예: `3 / 12`)가 표시돼요. 제목을 탭하면 장면 목록이 열려 번호, 이름, 요청 요약으로 원하는 장면을 찾아 바로 이동할 수 있어요.
- **맨 아래로 이동**: 최신 읽기 위치에서 위로 스크롤해 올라간 경우, 입력창 도구 영역에 맨 아래 이동 아이콘이 나타나요. (입력창에 포커스가 있거나 원문을 편집하는 중에는 숨겨져요.)
- **집중 읽기와 설정**: 읽기 설정에서 채팅 내비게이터를 끌 수 있으며, 집중 읽기 모드에서는 내비게이터 눈금과 이동 버튼이 자동으로 숨겨져요. 데스크톱에서는 좌측 장면 눈금 레일이 유지돼요.
- **스크롤 위치 보존**: 원문이나 번역을 직접 수정하는 동안에는 편집창이 열리고 읽기 영역은 잠시 숨겨져요. 저장을 완료하거나 취소하면 읽던 스크롤 위치와 화면 선택이 정확하게 복원돼요.

## 도우미 세션 활용

원고 집필, 서재 자료 제작, 프롬프트 수정을 돕는 도우미(Helper) 작업 공간이에요.

### 중앙 작업 공간과 프로젝트 탐색

- **작업 공간 전환**: 공통 사이드바의 **채팅**과 **도우미** 아이콘으로 중앙 화면을 전환해요. 원고 옆에 열어두는 사이드 도우미와 중앙 전체 화면 도우미(**도우미 크게 보기**)를 오가더라도 진행 중인 작업, 입력 초안, 참조 자료가 안전하게 이어져요.
- **프로젝트로 대화 정리**:
  - 도우미 탐색 메뉴에서 **프로젝트**를 만들어 관련 대화들을 묶어서 정리할 수 있어요.
  - 대화 메뉴에서 프로젝트 이동, 제목 변경, 대화 복사, 삭제를 지원해요. 프로젝트를 삭제하더라도 포함되어 있던 대화는 삭제되지 않고 유지돼요.
  - 탐색 목록은 최근순, 이름순, 수동 정렬(드래그 또는 위/아래 이동)을 지원해요.
- **활동 모니터링**: 확인할 활동, 진행 중인 작업, 최근 대화를 한눈에 볼 수 있으며, 완료나 실패 알림은 대화를 확인하면 자동으로 정리돼요.

### 입력창과 실행 편의 기능

- **컨텍스트 칩**: 고정된 자료, 현재 열려 있는 활성 편집기, 선택한 계층형 구성, 본문 선택 구절이 도우미 입력창 안에 인라인 칩 형태로 자동 연결돼요. 대화별로 열려 있는 편집기를 캡처하므로 다른 대화의 편집기가 숨겨진 채 잘못 전달되지 않아요.
- **진행 과정 실시간 관측**: 도우미가 작업 중일 때는 입력창 위에서 진행 단계와 도구 호출 현황을 실시간으로 보여줘요.
  - **현재 작업에 추가**: 실행 중인 도우미 작업에 추가 지시를 전달해요.
  - **다음 요청**: 현재 작업이 끝난 뒤 실행될 별도 요청으로 접수해요.
- **작업 기록과 복사**:
  - 도우미 **작업 기록**에서 긴 요청문은 **요청 전체 보기**로 펼쳐 원문 공백과 줄바꿈 그대로 복사할 수 있어요.
  - 완성된 답변 안의 코드 블록에는 개별 복사 버튼이 있어 해당 블록의 내용만 손쉽게 복사할 수 있어요.
  - 사용량 요약의 작은 막대는 마지막 전송 입력의 추정치와 당시 입력 예산을 비교해요. 정확한 수치, 캐시, 추론, 호출 수와 비용은 펼쳐서 확인해요. 누적 입력 토큰이나 네이티브 에이전트의 현재 컨텍스트 점유율을 나타내는 막대는 아니며, 입력 예산 기록이 없는 과거 작업은 저장된 모델 스냅샷의 한도를 사용할 수 있을 때만 막대를 표시해요.
- **대화 내용 편집과 가지치기**:
  - 메시지 메뉴에서 과거의 요청이나 답변을 직접 편집해 저장할 수 있어요. (다시 실행하지 않고 다음 대화에 반영돼요.)
  - 특정 요청·답변 한 쌍을 삭제하거나, 해당 위치부터 이후의 대화를 일괄 삭제할 수 있어요. 이미 완료된 자료 수정 결과와 사용량 기록은 유지돼요.
- 첨부 파일의 지원 형식과 보존 정책은 [도우미 첨부](HELPER-ATTACHMENTS.md)를 참고해요.

## 구현 참고

### Reader 이동 상태와 SSE 동기화

- **단일 이동 상태 머신**: 채팅, 원문, 화면 표시는 `web/reader-navigation.ts`의 단일 상태 머신으로 제어해요. 주소가 동일한 반복 이동(A→B→A)이나 동일 원문 재선택도 새로운 사용자 의도로 취급하여, 이전 조회나 지연된 재시도 완료가 새 화면을 덮어쓰거나 다른 채팅으로 튕기지 않도록 방어해요.
- **SSE 커서와 백오프**: Reader는 SSE의 목표 cursor까지 조회를 이어가며, 네트워크 일시 실패 시 새 이벤트 없이도 최대 5초 간격의 지수 백오프로 재시도해요. 전체 재동기화는 응답이 화면에 완전히 적용된 후에만 완료 처리되며, 채팅을 벗어나면 재시도 타이머를 즉시 취소해요.
- **유휴 탭 절전**: 서재를 보거나 브라우저 탭이 백그라운드로 숨겨지면 Reader 조회와 재시도 타이머를 일시 정지하고 최신 cursor와 필수 알림만 유지해요. 원고 화면으로 복귀할 때 누적된 변경 사항을 한 번에 읽어와요. 카드 입력창도 유휴 조회를 반복하지 않고 기존 SSE의 입력 요청·응답/취소·작업 종료 알림, 재접속, 화면 복귀 때 확인해요. 다른 기기에서 응답한 입력은 작업이 끝나기 전에도 닫히며, 이전 응답의 접수 확인이 늦게 도착해도 다음 질문에 쓰던 초안은 유지해요. 겹친 확인 요청은 순서대로 합치고 실패한 조회만 재시도하므로 카드의 대기 작업을 재실행하지 않아요.
- **요청 복구 키와 멱등성**: 수락 여부가 불확실한 생성 요청은 로컬 요청 키로 상태를 확인하며, 확인 도중에는 전송 버튼이 '이전 요청 확인'으로 유지되어 의도치 않은 취소 동작으로 전환되는 것을 막아요. 404나 충돌이 발생해도 확인 기록을 보존하며 사용자가 위험을 인지하고 명시적으로 삭제할 수 있어요.

### 렌더러 아키텍처와 DOM 계약

- **코드 구조**:
  - `web/reading-preferences.ts`: 기본값 및 localStorage 저장 검증
  - `web/useReadingPreferences.ts`: 설정 영속화, 탭 간 동기화, 스크롤 위치 복원
  - `web/ReadabilitySettings.tsx`: 읽기 설정 대화상자 UI
  - `web/Prose.tsx`: 도우미 본문, 안전한 일반 Markdown, 설정 예문 렌더러
  - `web/RisuMessageSurface.tsx`: Risu 메시지 전용 렌더러 (열린 Shadow DOM 사용)
  - `core/reading-markdown.ts`: 공통 markdown-it 파서
  - `web/reading-quotes.ts`: 문장 부호 짝맞춤 및 역할 분석
  - `web/reading-dom.ts`: 완료 본문 DOM 장식 및 인용 스타일링
  - `web/reading-prose.css`: 공통 인용 및 타이포그래피 스타일
  - `web/PlainProse.tsx`: 스트리밍 중 보호 토큰 및 문자 그대로 표시 처리
  - `web/reader-dom.ts`: Shadow DOM 내 선택 영역 및 읽기 좌표 연결
- **안전한 Markdown 규격**: 속성 없는 HTML 중 루비 문자(`ruby`, `rb`, `rt`, `rp`), 밑줄(`u`), 위/아래 첨자(`sup`, `sub`), 형광펜 강조(`mark`), 작은 글씨(`small`), 단순 서식(`b`, `i`, `s`), 줄바꿈(`br`)만 제한적으로 렌더링해요. 그 외의 모든 임의 HTML 태그나 속성이 포함된 태그는 문자 그대로 이스케이프하여 노출해요. 삽화는 완결된 Markdown 컨테이너 뒤에만 넣고, 목록·표 중간처럼 안전한 경계가 없는 기존 이미지와 삽화는 본문 아래에 표시해요.
- **Geometry Marker와 스크롤 복원**: 표시 변환을 거친 본문과 실제 렌더링된 DOM 엘리먼트 사이의 좌표를 임시 geometry marker로 연결해요. 이 마커는 사용자 텍스트 선택, 클릭, 접근성 트리, 레이아웃에 일절 참여하지 않으며 창 크기나 폰트가 변경될 때 재계산돼요.
- **보호 토큰 최적화**: `{{…}}` 문법은 닫는 괄호의 위치를 먼저 확인해 닫히지 않은 토큰이 긴 문단에서 반복되더라도 성능 저하 없이 빠르게 건너뛰어요.
- **원문 불변성 원칙**: 읽기 설정은 표시 레이어의 CSS 및 React 컴포넌트에만 적용되며, 저장된 원문 텍스트, 번역문, SHA hash, 문자 offset, block anchor를 절대 수정하지 않아요. 모델 입력 프롬프트나 백업 데이터에도 읽기 스타일은 포함되지 않아요. 드래그 선택 복사는 브라우저의 시각적 개행 처리를 따를 수 있어요.

### Helper sessions

- **세션 소유권과 독립성**: 각 독립 채팅은 여러 개의 도우미 세션을 소유할 수 있어요. 각 세션은 고유한 대화 이력, 입력 초안, 활성 컨텍스트를 소유하며, 도우미 패널을 닫거나 다른 세션으로 전환하더라도 백그라운드에서 진행 중인 작업은 취소되지 않아요. 도구는 사용자가 명시적으로 요청할 때 다른 채팅을 대상으로 실행될 수 있어요. 채팅 복사는 독립된 새 채팅을 생성하며 변경 가능한 기본 설정을 공유하지 않아요.
- **트랜스크립트 수정과 컨텍스트 격리**:
  - 도우미 메시지를 편집하거나 삭제하면 원본 실행 증거는 분리하여 보존해요.
  - 수정 및 삭제된 내용은 대화 조회와 향후 도우미 문맥(복사된 시드 메시지 및 재시도 그룹 포함)에 즉시 반영돼요.
  - 메시지가 변경되면 활성화되어 있던 도우미 요약(summary)을 즉시 분리(detach)하여, 오래된 텍스트가 컨텍스트 압축을 통해 다음 요청에 다시 유입되는 것을 방지해요.
  - 기존 작업 스냅샷이나 이미 커밋된 리소스 수정 내용은 과거로 되돌아가서 재작성되거나 취소되지 않아요.
- **헤더, 모델 선택, CAS 수정 번호**:
  - 도우미 헤더가 세션 전환, 생성, 관리를 주관하며 말투 설정은 관리 메뉴에 위치해요.
  - 입력창 툴바에서 검색 가능한 모델 선택기를 바로 열 수 있어요.
  - 모델을 변경하면 다음 요청을 위한 전역 도우미 역할(global helper role)이 갱신되며, 현재 채팅의 본편 작문 모델이나 다른 역할은 변경하지 않아요.
  - 지연 도착한 응답보다 최신 확정된 리비전이 우선권을 가져요.
- **동시 실행 및 호출 한도**:
  - 대화별 호출 한도는 수동 편집하지 않아요.
  - 새로 접수되는 도우미 작업은 내부 정책에 따라 **도우미 판단 64회**, **전체 모델 호출 128회**, **호스트 도구 호출 256회**, **20분 실행 기한**을 적용해요.
  - 이미 접수된 작업은 접수 당시 저장된 호출 한도를 보존해요.
- **라이브 디스플레이 컨텍스트와 이벤트 커서**:
  - Reader나 도우미를 열 때는 현재 뷰와 이벤트 커서를 가져온 뒤 그 이후의 최신 변경 사항만 추적해요. 화면을 다시 빌드하기 위해 과거의 알림들을 처음부터 재생하지 않아요.
  - 메시지 내용이 갱신되어도 읽기 스크롤 위치를 유지하며, Risu 네이티브 HTML과 일반 Prose는 동일한 외부 블록 앵커를 공유해요.
- **완료된 Risu 메시지 표현**: 현재 패키지/프로필 프로젝션을 복원하고 실시간 메시지 이력을 한 번만 조립해요. 버려진 생성 이력이나 이야기 컨텍스트를 불필요하게 재구성하지 않아요. 원문/번역 렌더링, CBS/Lua 메시지 순서, 현재 변수 상태와 액션 리비전 검사는 이 라이브 디스플레이 컨텍스트를 사용해요.
- **원문 및 번역 이력 보존**: 직접 원문 편집 시 불변의 최초 작성 원문, 최신 2개의 편집 버전, 그리고 아직 완료되지 않은 작업이 참조 중인 버전들을 보존해요. 번역 이력은 현재 및 직전의 성공한 번역 텍스트와 활성 이미지 타깃을 보존해요.

# 테마 제작 가이드

Uimori 테마는 **화면 표현만 바꾸는 독립 자료**예요. 이야기 원문·번역·모델 프롬프트·카드 변수와는 완전히 분리되어 있어요. HTML/CSS 파일을 직접 실행하는 플러그인이 아니며, Risu의 `guiHTML`/CBS/JavaScript를 자동으로 호환하지 않아요.

## 사용과 제작 흐름

### 화면 모드와 테마 선택
- **화면 모드**: 실제 앱의 밝기(밝은 모드/어두운 모드)는 **설정 → 일반 → 화면**에서 한 번만 설정해요.
- **적용 화면**: **설정 → 테마와 색상**에서 적용 범위를 고른 뒤 **레이아웃**, **팔레트**, **글꼴**을 바로 선택해요.
- **글꼴 범위**: 글꼴 선택은 범위와 관계없이 작업실 전체에 적용돼요.
- **레이아웃과 원래 색상**: 기본 레이아웃은 기본·시네마틱·편지지·스크랩북·클래식 프레임이며, 팔레트는 어떤 레이아웃에도 적용할 수 있어요. **레이아웃 원래 색상**은 해당 레이아웃이나 사용자 테마에 저장된 고유 색상을 사용해요.

### 테마 편집과 미리 적용
- **꾸미기 시작**: 기본으로 접혀 있는 **테마 관리**에서 테마와 팔레트를 새로 만들거나 가져올 수 있어요. 기본 테마의 **꾸미기**를 누르면 관리 영역이 열리고 사본 편집을 시작해요.
- **색상 모드 전환**: **미리보기 색상**은 카드 미리보기와 편집할 색상 모드를 결정해요. 편집기의 색상 입력 바로 위 **편집할 색상**에서도 밝은 색/어두운 색을 바꿀 수 있으며, 두 선택은 함께 연동돼요.
- **고급 편집 영역**: 고급 편집에서는 앱 CSS, 본문 CSS, 레이아웃 HTML, 레이아웃 CSS를 직접 작성할 수 있어요.
- **미리 적용과 저장**:
  - **미리 적용**: 이 탭에서 임시로 화면을 확인하는 기능이며 서버 설정을 바꾸지 않아요. 다른 설정으로 이동하거나 설정을 닫으면 종료돼요.
  - **테마 저장**: 테마 저장 아이콘은 자료만 저장해요. 저장 후 테마 카드를 눌러야 선택한 범위에 실제로 적용돼요.
- **편집 초안 관리**:
  - 기본 테마는 읽기 전용이며, 사용자 테마는 이름 변경·복제·삭제·내보내기를 지원해요 (복제와 삭제는 카드 상단 관리 메뉴에 있어요).
  - 편집 초안은 편집기가 열려 있는 동안만 보관해요. 미저장 상태로 설정을 닫으면 저장할지 버릴지 확인해요.
  - 편집 취소 아이콘은 현재 편집 내용을 버리고 편집기를 닫아요. 새로고침 후 초안 복원은 제공하지 않아요.
- **가져오기**: **테마 가져오기**를 누르면 파일 내용을 먼저 편집기에 열어 보여줘요. 내용을 확인하고 저장하면 항상 새 ID로 추가하며 기존 자료를 덮어쓰지 않아요.

### 저장 위치와 동기화
- **기기별 설정**: 화면 모드, 기본 고딕/명조 글꼴, 읽기 글자 크기는 각 기기 브라우저에 저장돼요.
- **서버 저장**: 테마, 팔레트, 등록 글꼴 및 서버 선택 상태는 SQLite에 보관돼요.
- **반영 주기**: 다른 탭은 변경 알림을 통해, 다른 기기는 창으로 돌아올 때 최신 선택을 다시 읽어요. 실시간 기기 간 푸시 동기화는 아니에요.

## 적용 범위와 상속 순서

레이아웃과 팔레트는 각각 다음 순서로 우선순위를 따져 상속해요.

1. **현재 채팅** (가장 우선)
2. **현재 봇**
3. **작업실 기본** (기본값)

- **상속 표시**: 직접 선택한 항목은 카드의 체크 표시로 구분돼요. 상위 범위를 따를 때는 영역 제목 아래에 실제 적용값과 상속 원본을 함께 표시해요.
- **기본값**: 최종 기본값은 기본 레이아웃과 테마에 저장된 원래 색상이에요.
- **독립성**: 팔레트를 바꾸어도 레이아웃, 글꼴, 읽기 글자 크기는 바뀌지 않아요.
- **상위 설정 따르기**:
  - 명시적으로 선택한 **레이아웃 원래 색상**은 상위 팔레트를 따르지 않아요.
  - 범위별 **상위 팔레트 따르기**를 누르면 해당 범위의 색상 선택만 해제돼요.
  - 채팅을 연 상태에서 설정을 열면 봇/채팅 범위를 바로 고를 수 있으며, **상위 설정 따르기**로 개별 선택을 해제할 수 있어요.
- **사용자 테마 삭제 시**: 현재 선택 중인 사용자 테마를 삭제하면 해당 테마를 가리키던 선택만 제거되고 상위 테마로 안전하게 돌아가요.

## 내장 레이아웃과 특징

내장 레이아웃은 긴 원고를 몰입감 있게 읽을 수 있도록 각기 다른 개성을 제공해요.

- **기본**: 일반 페이지 스크롤 방식을 유지해요. 봇 이미지는 원형(데스크톱 72px, 모바일 60px)으로 표시되며 기존 공통 확대를 지원해요. 사용자 요청 오른쪽에는 페르소나 이미지를 읽기 좋은 크기로 보여줘요.
- **시네마틱**: 가장자리로 자연스럽게 스며드는 오른쪽 인물 배치를 사용해요.
- **편지지**: 작은 인물 머리글과 편지지 특유의 종이 여백을 살려요.
- **스크랩북**: 왼쪽 테이프 사진 스타일로 인물을 배치해요.
- **클래식 프레임**: 왼쪽 직사각 인물 사진, 얇은 이중 프레임, 높이가 정돈된 본문 상자를 사용해요 (모바일에서는 넓은 사진을 본문 위에 배치해요).

### 상자형 읽기 방식과 스크롤 규칙
- 시네마틱·편지지·스크랩북·클래식 프레임은 사용자가 요청한 **상자형 읽기 방식**을 사용해요. 봇 이미지·제목·작업 버튼은 제자리에 고정되고, 본문만 화면 높이에 맞춘 영역 안에서 스크롤돼요.
- **내부 스크롤 규격**:
  - 좁은 이야기 레이아웃의 긴 본문은 앱 머리글과 입력창을 제외한 실제 Reader 높이의 60%를 기준으로 200–560px 범위 안에서 내부 스크롤해요.
  - 입력창이 커지면 본문 높이도 함께 줄어들며, 짧은 본문은 내용 높이에 맞춰 표시돼요.
  - 사진·제목·버튼까지 한 화면에 강제로 욱여넣지 않으며 바깥 페이지 스크롤로 접근할 수 있어요.
  - 여백 규격: 모바일 아래 여백은 24px이며 맨 아래 이동 버튼은 본문 위가 아닌 입력창 도구 영역에 표시해요. 데스크톱 아래 여백은 48px이며 접힌 생성 사용량 행의 높이와 여백도 제외해 계산해요 (사용량을 펼쳐 늘어난 내용은 바깥 스크롤로 접근해요).

### 등장인물 이미지와 확대
- 대표 이미지는 현재 봇/페르소나 수정 번호의 이미지를 사용해요.
- 편지지 머리글, 모바일 인물 사진, 작은 페르소나 사진은 일부가 잘려 보일 수 있지만, 사진을 눌러 확대하면 원본의 전체 비율을 온전히 보존해요.
- 대표 이미지가 없거나 불러오지 못하면 이름 첫 글자로 대체해요. 페르소나를 선택하지 않은 상태에서는 빈 카드를 만들지 않아요.
- 확대 창은 Escape 키를 누르거나 닫기 버튼을 눌러 닫을 수 있어요.

## 사용자 팔레트와 글꼴

### 사용자 팔레트 제작과 공유
- **팔레트 관리**: **테마와 색상 → 테마 관리**에서 팔레트를 새로 만들거나 기존 팔레트를 복제해 밝은 모드와 어두운 모드의 글자색, 배경, 강조색 등을 편집할 수 있어요.
- **임시 확인과 적용**: 미리보기는 이 탭에만 임시로 적용되고, 저장을 누르면 새 자료로 추가돼요. 저장한 팔레트를 선택하면 기존 레이아웃을 유지하면서 해당 범위에 적용돼요.
- **삭제 시 동작**: 선택 중인 사용자 팔레트를 삭제하면 그 팔레트를 가리키던 선택만 해제돼요.
- **공유 형식**: 팔레트 공유 JSON은 다음 구조를 사용해요.
  ```json
  {
    "format": "uimori-palette",
    "version": 1,
    "palette": {
      "title": "내 색상",
      "description": "",
      "colors": {
        "light": { "text": "#302820" },
        "dark": { "text": "#eee4d8" }
      }
    }
  }
  ```
- 색상 키와 HEX 규칙은 테마와 동일하며 ID, 수정 번호, 적용 범위, 글꼴 파일은 포함하지 않아요. 가져온 파일은 편집 후 저장할 때 새 자료로 추가돼요. 사용자 색상은 자동 보정하지 않으므로 실제 밝은 화면과 어두운 화면에서 글자와 배경 대비를 직접 확인해 주세요.

### 글꼴 관리
- **예문 확인**: 글꼴 선택 아래 예문은 마지막으로 변경한 앱·본문 대상의 실제 적용 글꼴을 보여줘요. 예문은 이효석의 저작권 만료 작품 「메밀꽃 필 무렵」 일부를 사용하며 작가와 작품명을 함께 표시해요 ([공유마당의 만료 작품 목록](https://gongu.copyright.or.kr/gongu/search/search/list.do?kwd=%EB%8B%A8%ED%8E%B8%EC%86%8C%EC%84%A4&menuNo=200070), [위키문헌의 본문 판본](https://ko.wikisource.org/w/index.php?title=%EB%A9%94%EB%B0%80%EA%BD%83_%ED%95%84_%EB%AC%B4%EB%A0%B5&oldid=426852) 참고).
- **글꼴 파일 등록**: **글꼴 관리**를 열면 WOFF2, WOFF, TTF, OTF 파일을 등록하거나 삭제할 수 있어요 (패널을 접어도 입력 중인 파일과 이름은 유지돼요).
  - 등록 한도: 파일 1개당 최대 20 MiB, 작업실 전체 보관 한도는 100개·총 200 MiB예요.
  - 중복 파일: 동일한 파일을 다시 올리면 기존 등록을 재사용하고 최초 이름을 유지해요.
- **적용 규칙**: 등록만으로 글꼴이 적용되지는 않으며, 앱·본문 글꼴 선택을 통해 작업실 전체에 적용해요. 본문 크기, 행간, 기기별 기본 고딕/명조 설정은 유지돼요.
- **초기화 및 해제**: 선택을 해제하거나 사용 중인 글꼴을 삭제하면 기본 글꼴로 돌아가요. 비상 테마 끄기 시 커스텀 글꼴도 잠시 해제돼요.
- **보안 및 제약**: URL 등록은 공개 HTTPS에 한정하며 사설 네트워크나 인증 정보가 포함된 URL은 거부하고 다운로드 크기와 시간을 제한해요. 파일 헤더와 크기 검증이 글리프 전체나 사용 권한을 검증하는 것은 아니므로, 브라우저가 지원하지 않거나 글자가 누락된 폰트는 기본 글꼴로 표시될 수 있어요.

## 본문 바깥 배경 설정

- **배경 등록**: **본문 바깥 배경**에서 이미지 파일을 선택하면 기존 이미지 업로드 경로를 통해 검증 및 WebP 변환 후 저장돼요. 미리보기를 확인하고 **배경 저장**을 누르면 적용돼요. 제목 옆에 저장 후 적용 여부와 미저장 변경 상태가 표시돼요.
- **효과 조절**:
  - 흐림: 0–30px 범위로 조절해요.
  - 덮개: 밝은 모드의 흰 덮개와 어두운 모드의 검은 덮개를 각각 0–100% 범위로 지정해요 (100%는 이미지를 완전히 가려요).
  - 장식 분리: 이미지는 본문 상자 바깥 읽기 영역에만 표시되며, 흐림과 덮개는 별도 장식 레이어에 들어가 본문과 버튼을 흐리게 하지 않아요. 본문 바탕은 불투명하게 유지돼요.
- **상속과 해제**:
  - 배경 설정도 `현재 채팅 → 현재 봇 → 작업실 기본` 순서로 상속하지만 레이아웃·팔레트 선택과는 독립적이에요.
  - **배경 이미지 지우기** 후 저장하면 해당 범위에서 배경을 끄고, **배경 상위 설정 따르기**를 누르면 해당 범위의 개별 선택만 해제돼요.
  - 배경 이미지를 지워도 다른 곳에서 공유 중인 원본 이미지 파일은 삭제되지 않아요.
  - 배경 변경 사항은 저장하거나 취소한 뒤에 범위나 레이아웃을 변경해 주세요 (설정을 닫을 때 미저장 배경도 저장/버리기 확인창에 포함돼요).

## 비상 복구 수단

테마 CSS 오류로 화면을 조작하기 어려운 경우 다음 탈출구를 사용할 수 있어요.

- 단축키: **Ctrl/Cmd + .**를 누르면 현재 탭의 테마와 커스텀 글꼴, 배경을 즉시 끄거나 다시 켤 수 있어요.
- 안전 모드 주소: 브라우저 주소창 끝에 `?theme-safe=1` (다른 쿼리가 이미 있으면 `&theme-safe=1`)을 붙여 접속하세요.
- 이 복구 동작은 저장된 테마나 설정을 삭제하지 않으며, 깨진 테마를 안전하게 수정할 수 있도록 도와줘요.

## 파일 형식과 스타일 작성 규칙

### 파일 규격 (.uimori-theme.json)
`.uimori-theme.json`은 UTF-8 인코딩의 JSON 파일이에요.

```json
{
  "format": "uimori-theme",
  "version": 1,
  "theme": {
    "title": "내 서재",
    "description": "종이색 배경과 따뜻한 강조색",
    "colors": {
      "light": { "bg": "#f6f1e7", "accent": "#785137" },
      "dark": { "bg": "#211d19", "accent": "#dcb98b" }
    },
    "appCss": "[data-uimori-part='scene'] { border-radius: 16px; }",
    "messageCss": "p { letter-spacing: 0.01em; }",
    "templateHtml": "",
    "templateCss": ""
  }
}
```

- **입력 제한**: `title`은 필수이며 최대 100자, `description`은 최대 2,000자예요. CSS 필드 3개(`appCss`, `messageCss`, `templateCss`)는 각각 최대 1,000,000자, `templateHtml`은 최대 100,000자까지 허용돼요. 가져올 JSON 파일 전체 용량은 4MiB 이하이어야 해요.
- **식별 정보 제외**: ID, 수정 번호, 적용 대상 설정은 내보내기 파일에 포함되지 않아요.

### 색상 키와 팔레트 체계
색상 이름에는 앞의 `--`를 붙이지 않아요. 기준 키 목록(`core/themes.ts`의 `THEME_COLOR_KEYS`)은 다음과 같아요.

```text
bg, nav, panel, surface, surface-raised, surface-active, hover,
line, input-border, border-hover, focus-ring, text, muted, faint,
accent, accent-ink, accent-hover, accent-hover-ink, accent-text, accent-line, accent-soft,
user, error, error-ink, error-bg, error-line, error-solid, error-hover,
success, success-bg, success-line, warning, warning-bg, warning-line,
info, info-bg, info-line, shade
```

- **표기법**: 색상 값은 HEX (`#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA`) 형식을 사용해요. 생략한 값은 Uimori 기본 CSS를 상속해요 (`--border`는 `--line`을 가리키는 기존 별칭이에요).
- **Radix Colors 단계 기준**: 내장 팔레트는 [Radix Colors의 단계별 용도](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)를 따라요.
  - 배경: 1–2단계
  - 조작부 상태: 3–5단계
  - 경계선: 6–8단계 (`input-border`는 neutral 8, 장식 구분선 `line`은 neutral 6)
  - 단색 버튼: 9–10단계 (`accent`는 버튼 배경, `accent-ink`/`accent-hover-ink`는 일반/호버 버튼 텍스트)
  - 글자: 11–12단계 (강조 글자는 `accent-text`, 밝은 세이지 팔레트의 강조 글자는 대비를 위해 jade 12 사용)
  - 선택 배경: `accent-soft`는 밝은 모드에서 accent 3, 어두운 모드에서 accent 4를 사용해요.
- **기본 레이아웃 원래 색상**: 따뜻한 종이와 차분한 차콜 바탕에 크림색 헤일로를 더했어요. 어두운 모드는 `#1d1f22` 바탕에 `#ffe5c8` 강조색, 밝은 모드는 `#f2f0eb` 종이색 바탕에 금갈색 `#73572f` 강조색과 크림색 버튼 글자를 사용해요 (밝은 모드 보조 글자는 호버 배경에서도 4.5:1 이상 대비를 유지해요).
- **어두운 모드 패널**: 모달과 도우미/창작 옵션 패널은 `panel`을 사용하고, 원고 바탕은 `bg`를 유지해요.
- **비활성 버튼**: 버튼 안의 강조/삭제 색상 변수를 `surface`, `muted`, `line`으로 전환하며 기존 흐림과 크기를 유지해요 (앱 조작부에만 적용되며 테마 색상이나 봇 작성 Shadow DOM은 건드리지 않아요).
- **표준 치수 토큰**:
  - 글자 크기: `--font-small`(12px), `--font-body`(14px), `--font-heading`(16px), 경계선: `--hairline`(0.5px)
  - 곡률: `--radius-small`(4px), `--radius-control`(6px), `--radius-panel`(10px) (중첩된 표면은 안쪽 여백만큼 곡률을 줄여요)

### 세 가지 스타일 영역
스타일은 적용 대상에 따라 명확히 분리돼요.

| 영역 | 입력 필드 | 적용 대상 |
| --- | --- | --- |
| 앱 | `colors`, `appCss` | 사이드바·입력창·패널·장면 바깥쪽. 색상 변수는 본문에도 상속돼요. |
| Risu 본문 | `messageCss` | 각 `RisuMessageSurface`의 Shadow DOM. 작성된 봇 HTML의 구조는 바꾸지 않아요. |
| 장면 레이아웃 | `templateHtml`, `templateCss` | 요청·제목·본문·작업 버튼이 놓일 자리와 그 바깥 장식. 별도 Shadow DOM이에요. |

- 앱의 일반 CSS 선택자는 Shadow DOM 내부로 침투하지 않아요. 본문을 꾸밀 때는 반드시 `messageCss`를 사용하세요.
- 본문 CSS는 `uimori-message-theme` 레이어로 주입되므로 일반 작성자 CSS와 사용자의 명시적 읽기 설정이 우선해요.
- 동일한 테마 시트를 메시지들이 공유하므로 CSS 변경만으로 메시지 HTML을 다시 만들지 않아요.
- 본문 스타일시트에서는 `@import`를 지원하지 않아요. 필요한 스타일은 파일 안에 직접 작성하고 웹폰트는 앱 CSS에 선언해 주세요. 사용자의 글꼴, 글자 크기, 행간 등 읽기 설정을 `!important`로 강제 덮어쓰지 마세요.

### 안정적인 스타일 표식
CSS 작성 시 안정적으로 참조할 수 있는 데이터 속성은 다음과 같아요.

```css
[data-uimori-part="scene"]          /* 하나의 저장 장면 */
[data-uimori-part="scene-frame"]    /* 레이아웃 Shadow DOM 호스트 */
[data-uimori-part="request"]        /* 사용자 요청 */
[data-uimori-part="heading"]        /* 제목·상태·원문/번역 전환 */
[data-uimori-part="body"]           /* 본문·편집·삽화·후속 상태 */
[data-uimori-part="actions"]        /* 복사·수정·장면 작업 */
[data-uimori-part="composer-input"] /* 요청 입력창 */
[data-uimori-part="scene-portraits"] /* 장면의 portrait 슬롯 노드 */
[data-uimori-part="request-persona"] /* 요청 오른쪽 페르소나 */
[data-uimori-body-scroll]           /* 선택형 내부 스크롤 본문 */
[data-uimori-part="portrait-group"] /* 봇·페르소나 이미지 묶음 */
[data-uimori-part="bot-portrait"]
[data-uimori-part="persona-portrait"]
```

- 테마 상태 셀렉터: `html[data-theme="light"|"dark"]`는 명암 모드, `html[data-uimori-theme]`는 실제 테마 ID예요. 저장 ID에 디자인을 하드코딩하지 마세요. 내부 클래스도 앱 CSS에서 사용할 수 있지만 공식 표식보다 변경에 민감해요.
- Risu 본문 내부 셀렉터: `.risu-message-content`, `.risu-chat-text`, `[data-uimori-prose]`를 활용할 수 있어요 (`body`나 `html` 선택자를 메시지 문서로 재해석하지 않아요).
- 이전 사용자 테마 호환성을 위해 Reader 공통 영역의 `[data-uimori-part="gallery"]`도 유지돼요 (기본은 숨김 상태이며 테마에서 표시 가능).

### HTML 레이아웃과 슬롯
HTML 레이아웃 템플릿(`templateHtml`)을 정의할 때는 아래 4개 슬롯이 **정확히 한 번씩** 포함되어야 해요 (빈 HTML을 지정하면 앱 기본 배치를 사용해요).

```html
<slot name="request"></slot>
<section class="paper">
  <header><slot name="heading"></slot></header>
  <main><slot name="body"></slot></main>
  <footer><slot name="actions"></slot></footer>
</section>
```

```css
.paper {
  background: var(--panel);
  border: var(--hairline) solid var(--line);
  border-radius: var(--radius-panel);
  padding: clamp(14px, 3vw, 30px);
}
header { border-bottom: var(--hairline) solid var(--line); margin-bottom: 20px; }
footer { margin-top: 16px; }
@media (max-width: 600px) { .paper { padding: 14px; } }
```

- **네이티브 슬롯 매핑**: 본문, 버튼, 편집기는 React가 관리하는 노드로 브라우저 표준 `<slot>`에 투영돼요. 템플릿 변경 시 노드를 복제하거나 다른 컨테이너에 재렌더링하지 않아요.
- **슬롯 누락 및 중복 방지**: 슬롯이 누락되거나 중복되면 미리보기와 가져오기에서 오류를 안내해요. 서버를 통해 잘못 저장된 테마라도 Reader에서는 기본 레이아웃으로 안전하게 대체돼요. 추가 안내를 위한 기본 `<slot></slot>`을 생략하면 자동으로 맨 끝에 보충돼요.
- **선택형 슬롯**:
  - `<slot name="portrait"></slot>`: **한 번** 추가할 수 있으며, 앱 소유 등장인물 이미지·이름·확대 버튼을 장면 내에 배치할 수 있어요.
  - `<slot name="request-persona"></slot>`: 사용자 요청에 대응하는 페르소나 이미지를 배치해요.
  - 내장 테마는 봇을 응답에, 페르소나를 요청 오른쪽에 배치해요 (모바일에서는 각 메시지 위로 쌓고 페르소나는 작은 인물 표시로 유지해요).
  - 본문 슬롯처럼 React가 관리하며 테마에 이미지 URL이나 캐릭터 이름을 넣을 필요가 없어요. 슬롯이 없으면 장면별 이미지를 만들지 않아요 (편집기 예문에는 실제 채팅 이미지가 없을 수 있어요).
- **본문 내부 스크롤 지정**: 본문만 내부 스크롤하도록 구성하려면 `<slot name="body" data-uimori-body-scroll></slot>`을 사용하세요. 앱 소유 본문 노드에 표시가 붙어 읽기 위치, 북마크, 편집 복귀가 내부 스크롤을 인식해요. 화면 크기에 맞는 최대 높이를 두고 제목·작업 버튼은 스크롤 영역 밖에 남겨요 (일반 사용자 템플릿에는 이 동작을 강제로 적용하지 않아요).
- **외부 리소스 주의**: CSS `url(...)`이나 data URL을 사용할 수 있지만 테마 JSON은 외부 이미지를 함께 패키징하지 않아요. 외부 URL은 그대로 남아 네트워크·브라우저 정책을 따르며, 다른 서버의 `/api/...` 주소를 내보냈다고 이미지가 함께 옮겨지지는 않아요. 등록 글꼴은 테마 JSON에 자동 포함되지 않아요. 전체 화면 `position: fixed`, 무거운 배경 필터, 끊임없는 애니메이션은 피하고, 긴 한국어 본문과 작은 화면을 먼저 고려하세요. 애니메이션이 있다면 `prefers-reduced-motion`을 준수해 주세요. 템플릿 안에 앱 버튼을 새로 만들어 동작을 재구현하지 마세요. 슬롯은 브라우저의 실제 `<slot>`이며 이전 논의의 `data-uimori-slot` 예시는 구현 문법이 아니에요. 테마는 임의 JavaScript 실행이나 폼 제출 기능이 아니에요. 표시용 컨트롤과 스타일의 구체적인 범위는 [템플릿 지원 범위](#템플릿-지원-범위와-갱신)를 참고하고, 레이아웃 CSS는 `templateCss`에 모아 작성하세요.

## 템플릿 지원 범위와 갱신

일반적인 표시용 HTML, 표준 슬롯, 인라인 `style` 요소와 제출 기능이 없는 `input`, `select`, `textarea` 컨트롤을 지원해요.

- **미지원 마크업**: JavaScript 실행, CBS 문법, 폼 제출, `iframe`/`object` 문서 삽입은 지원하지 않아요. 실행 가능한 속성이나 문서 수준의 지원하지 않는 마크업이 포함되어 있으면 이유를 화면에 표시하고 기본 레이아웃을 사용해요. 저장한 내용이 정상 표시되는 것처럼 일부를 조용히 제거하지 않아요.
- **스타일 분리 권장**: 앱 전체 스타일은 `appCss`, 메시지 스타일은 `messageCss`, 레이아웃 내부 스타일은 `templateCss`에 작성해 주세요.
- **태그 검증 순서**: HTML 맨 앞의 `style` 태그도 레이아웃 안에 보존돼요. 템플릿은 비활성 HTML 조각으로 파싱한 뒤 검증하므로, 맨 앞의 `script`가 문서 머리로 옮겨져 조용히 사라지는 대신 미지원 마크업으로 안내돼요.
- **갱신 최적화**: 동일한 테마 수정 번호는 적용된 DOM과 CSS를 유지해요. 테마 목록은 조건부 HTTP 재검증을 지원하며, 도우미의 일반 활동이 아니라 실제 테마 변경이 있을 때 테마를 갱신해요.

## 에이전트 및 구현 참고

### 에이전트 작업 순서
1. **요구사항 확인**: 사용자 요청의 분위기, 봇의 설정, 이미지 사용 가능 범위를 확인하고 기존 테마 또는 `fixtures/themes/` 예제를 읽어요. 관련 없는 대화 기록이나 키를 테마 파일에 넣지 않아요.
2. **점진적 작성**: 색상과 CSS만으로 가능한 부분부터 만들고, 배치 변경이 필요할 때만 HTML을 추가해요. 테마 때문에 봇 스크립트·원문·메모를 수정하지 않아요.
3. **환경별 검증**: 테마 파일을 가져와 예문과 실제 합성 채팅에서 밝게/어둡게, 412px/1440px 화면을 확인해요. 긴 본문·번역 전환·메뉴·읽기 설정·작성자 입력 상태를 확인해요.
4. **결과 제공**: 미리 적용한 화면을 실제로 보고 수정한 뒤 저장 가능한 JSON을 제공해요. 실행하지 않은 브라우저 검증이나 실제 모델 품질을 확인했다고 쓰지 않아요.

### 도우미 도구 호출 계약
- **조회 및 편집**: 내장 도우미는 `theme.guide`, `theme.list`를 먼저 읽고 테마 편집에 `resource.read/save/undo/delete`의 `kind: "theme"`를 사용해요. 기존 테마 수정은 최신 `expectedRevision`을 사용하며 기본 테마는 새 ID로 복제해요.
- **팔레트와 글꼴**:
  - 팔레트: `palette.list/save/delete`로 관리해요.
  - 글꼴: `font.list/register/select/delete`로 관리해요.
  - 글꼴 다운로드: `font.register`는 이름과 공개 HTTPS 폰트 파일 URL을 받아 다운로드해요. URL은 다운로드 입력으로만 쓰며 등록된 글꼴의 출처·라이선스 메타데이터는 저장하지 않아요 (웹 임베딩을 허용하는 글꼴을 사용해요).
  - 기존 메타데이터 정리: 글꼴 설정에서는 파일과 이름만 등록해요. 기존 글꼴에 앱이 따로 저장했던 출처·라이선스 필드는 서버가 글꼴 저장소를 초기화할 때 제거해요. 글꼴 파일 원본 바이트와 내부 권리 고지, ID·이름·등록일·현재 선택은 유지해요.
- **적용 명령**: 등록·저장과 적용은 별개예요. 후보나 미리보기만 요청받았다면 저장하거나 선택하지 않아요. 적용 요청을 받으면 `theme.select`로 레이아웃 또는 팔레트와 적용 범위를 지정하고, `font.select`로 작업실 전체의 앱·본문 글꼴을 각각 지정해요. 선택 전에 목록에서 최신 선택과 수정 번호를 읽고 관련 없는 선택은 유지해요. 앱 밖의 에이전트가 파일을 만들 때도 인증 키를 내보내기에 넣지 않아요.

### 내장 레이아웃과 팔레트 내부 원본
- 레이아웃 원본: `core/narrative-themes.ts`가 레이아웃의 단일 원본이에요.
- 팔레트 원본: `core/theme-palettes.ts`가 팔레트 목록이에요.
- 구조 통합 및 호환성:
  - 기존 숲·미드나이트·벚꽃의 동일 구조는 **기본** 레이아웃과 팔레트로 합쳤어요. 이전 선택은 같은 색을 유지하도록 읽을 때 해석하며, 기존 서재의 별도 종이 배치는 이전 선택에 한해 보존해요 (새로운 목록에는 별도 서재 카드가 없어요).
  - Liquid Gallery는 기본 목록에서 제거하고 그 ID 선택만 시네마틱으로 연결해요.
  - 복제·가져오기한 사용자 테마와 그 색상은 삭제하거나 덮어쓰지 않아요. 이전 선택에 포함된 사용자 색은 범위 경계를 유지해 새 상위 팔레트가 뜻하지 않게 덮어쓰지 않아요.
  - 이전 `verify:liquid-gallery`는 기본 목록 대신 **사용자 테마 사본**을 통해 기존 공통 갤러리 호환성을 확인해요. 이 호환성 자료는 [테스트 fixture](../tests/fixtures/liquid-gallery.ts)에 보관해요.
- 데이터 백업: 테마 JSON에는 레이아웃에 저장된 원래 색상이 포함되고, 별도로 선택한 팔레트·적용 범위는 포함하지 않아요. 별도 팔레트 자료와 선택은 작업실 SQLite 백업에 보존돼요. 테마 삭제/편집은 원문이나 모델 입력을 변경하지 않아요. 표정 패널·BGM·TTS·입력 번역은 이번 기능의 범위가 아니에요.

### 테스트 및 검증 명령어
```sh
npm run check
npm test -- tests/themes.test.ts
npm run build
npm run verify:themes
npm run verify:narrative-themes
```

- `verify:themes`: 테마 화면과 기존 Risu 메시지 표면 회귀 검사를 격리된 합성 서버에서 수행해요. 결과와 화면은 `output/playwright/themes-*/`에 남아요. 테스트에서 캡처한 이미지를 실제로 열어 확인하세요. 캡처 성공만으로 미적 품질이나 물리 기기 동작이 보장되지는 않아요.
- `verify:narrative-themes`: 새 레이아웃 검사는 합성 이미지와 긴 한국어 원고, 1440/412px, 밝게/어둡게, 팔레트 독립성·확대·편집·복사·번역·읽기 설정·복구를 검증해요. 실제 API 품질이나 물리 기기 성능을 보장하지 않아요.
- 시각 데모 폴더: 개인 시각 검토에는 `UIMORI_NARRATIVE_DEMO_DIR`에 `bot.webp`(2:3)와 `persona.webp`(1:1)가 있는 폴더를 지정할 수 있어요. 이 입력은 격리된 합성 서버에만 저장하며 결과는 무시되는 `output/`에 남겨요. 지정하지 않은 일반 검사는 결정적인 합성 이미지를 사용해요. 이미지 파일은 저장소에 넣지 않아요.

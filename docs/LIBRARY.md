# 서재와 자료 편집

서재는 봇·페르소나·모듈을, 프롬프트 목록은 작문·번역 프리셋을 관리해요. 자료 목록에서 선택하고 **편집**을 열어요. 저장되지 않은 입력은 이 기기 편집기에만 있으며 다른 기기로 동기화하지 않아요.

검색 옆의 카드·목록 아이콘으로 보기 방식을 바로 바꿔요. 선택한 방식은 강조 표시되고 분류별로 이 기기에 기억해요. 정렬·카드 비율·여러 자료 선택은 **목록 관리**에서 열어요.

프롬프트도 **목록 관리 → 수동 정렬**에서 다른 프롬프트 위로 끌어 순서를 바꿔요. 정렬 방식과 자료 순서는 이 브라우저에 기억하며, 폴더 이동과 폴더 순서는 서버에 저장돼요. 프롬프트를 폴더에 끌어 놓아 이동하고, 폴더끼리 끌어 순서를 바꿀 수 있어요. 드래그가 어려우면 프롬프트 메뉴의 이동·위아래 이동을 사용해요.

서재·프롬프트와 상세 조회는 200ms 이상 걸릴 때 작은 진행 표시를 보여 줘요. 조회 실패는 오류 안내로 바뀌며, 다시 불러오기로 조회를 재시도할 수 있어요. 화면 코드 자체를 불러오지 못한 경우에는 작성 중인 내용을 보관한 뒤 새로고침해 주세요.

사이드바에서 봇을 폴더에 끌어 놓아 분류를 바꾸고, 봇 사이에 놓아 순서를 바꿔요. 폴더 순서는 사이드바와 서재에서 폴더를 다른 폴더 앞뒤에 끌어 놓아 바꾸며 두 화면에서 공유해요. 채팅 이동도 기존 드래그 앤 드롭을 사용해요. 자료가 이미 폴더 안에 있으면 전체 목록의 미분류 영역에 새 자료 만들기 안내를 표시하지 않아요.

채팅이 없는 봇도 왼쪽 봇 목록에 표시해요. 봇의 **+**로 원할 때 첫 채팅을 시작하고, **관리 → 기본 페르소나**에서 새 채팅의 기본값을 정해요. **폴더 기본값 따르기**, **페르소나 없음**, **페르소나 지정** 중 선택할 수 있어요. 새 채팅에서 직접 고른 값이 가장 우선하며, 그다음 봇 기본값, 채팅 폴더 기본값 순서예요. 기존 채팅의 페르소나는 바꾸지 않아요. 선택한 페르소나를 편집하면 새 채팅은 현재 저장본을 쓰고, 삭제하면 다른 값을 직접 고르도록 알려줘요.

봇 기본 페르소나는 이 작업실의 설정으로 전체 DB 백업에 포함돼요. 개별 봇 파일이나 개별 자료 백업에는 포함하지 않아요.

## 저장과 취소

**변경사항 저장**은 현재 자료를 갱신하고, **편집 취소**는 저장본을 다시 불러와요. 직전 저장 한 번을 되돌릴 수 있어요. 도우미도 같은 저장 기능을 사용하며, 작은 원문 수정은 해당 필드만 바꿀 수 있어요. 수정 번호 충돌이면 입력을 보존하고 최신 자료를 다시 읽도록 알려줘요. 별도 서버 초안·변경 제안·영구 저장 이력 검토 화면은 없어요.

원문 JSON·정규식·트리거도 저장할 때 함께 확인해요. 잘못된 입력은 지우지 않아요. `폼에 반영`은 원문 수정 후 GUI 편집을 계속할 때 사용하는 선택 동작이에요. [편집과 복구 상태](EDITING.md)

## 편집 영역

봇은 기본 정보·첫 메시지·로어북·에셋·고급 설정·제작 정보로 나눠요. 고급 설정에는 지침, 기본 변수·토글, HTML/CSS, Lua·정규식·트리거, 연결 모듈과 원문 JSON이 있어요. 프리셋은 구성·기본 옵션·변수·토글·정규식·협업을 편집해요.

저장된 봇·모듈·프리셋은 다음 생성부터 사용해요. 이미 작성한 대화 본문을 새 설정으로 다시 생성하지 않아요. 자료마다 모든 과거 저장본을 보관하지 않으며, 보관할 별도 저장본은 명시적으로 사본이나 [개별 백업](NATIVE-TRANSFER.md)으로 남겨요.

## 이미지 이름·설명과 WebP

에셋을 선택해 **이미지 이름**, **설명**, **에셋 용도**를 편집하고 자료를 저장해요. 목록·검색과 JEV 선택은 이 메타데이터를 사용하고, 본문이 포함된 용도만 자동 이미지 배치 후보가 돼요. 현재 대표 이미지는 프로필 사용을 유지해야 해요. 기존 Risu 스크립트가 사용하는 참조 이름은 별도로 유지해요. 이름을 바꿔도 이미지 바이트를 다시 인코딩하지 않아요. 업로드 이미지의 이름·설명을 저장하는 동안 해당 입력을 잠그고, 실패하면 입력과 오류를 남겨 다시 저장할 수 있어요.

JEV 이미지 선택에는 문단 발췌와 이미지 이름·설명·인물·복장·위치·사용 범위를 보내요. 원문 hash와 이미지 revision/hash는 판정 입력을 식별하는 호스트 영수증에 유지하고 모델 본문에서는 생략해요. 후보 순서·선택 범위와 저장된 판정의 검증은 유지하며, 이전 형식으로 기록된 판정도 원래 입력과 대조해요.

작은 이미지 목록이 입력 예산과 선택지 한도에 들어가면 전체 후보를 판단해요. 큰 목록은 고정된 에셋 메타데이터 전체를 로컬 검색해 판단 대상 문단마다 최대 16개 후보를 고르되, 문단별 초기 토큰 몫으로 첫 후보부터 확보해요. 초기 몫에 맞는 후보가 없던 문단은 남은 예산에서 저렴한 후보를 다시 확인하고, 그 후에 각 문단의 추가 후보를 번갈아 넣어요. 긴 설명을 가진 앞 문단의 후보가 예산을 먼저 차지하는 일을 줄이고, 최종 토큰 조정에서도 여러 후보가 있는 문단부터 줄여요. 원고 전체에서 많이 등장하는 한 인물의 이미지가 다른 장면의 후보를 독점하지 않도록 문단별 선택지를 사용해요. JEV 호출은 한 번으로 묶으며 `none`을 포함한 질문별 선택지 최대 255개와 실제 전송 토큰 예산을 모두 확인해요. 문단은 기존처럼 전체에서 최대 16개를 뽑아 판단하고 최종 배치는 최대 4개예요. 작업 카탈로그의 최대 10,000개 제한과 프로필 전용 이미지 제외는 유지해요.

이 검색은 별도 설정·다운로드·추가 모델 호출 없이 작동해요. 이미지 바이트의 표정·구도를 읽거나 단어가 다른 모든 의미상 유사성을 찾는 기능은 아니며, 기존 메타데이터와 JEV 판단을 사용해요. 이미 저장된 이전 형식의 유료 판정은 당시 입력 구성 방식으로 검증해요.

업로드 이미지는 서버 공통 경계에서 고품질 WebP로 변환해요. 해상도·투명도·애니메이션을 유지하는 방식으로 처리하며 픽셀 단위 무손실을 보장하는 설정은 아니에요. 기존 WebP는 그대로 저장하고 원본을 함께 이중 보관하지 않아요. 2MB 제한은 없고 입력 파일 64MiB 및 처리 픽셀·프레임 상한을 사용해요. 여러 파일은 제한된 동시 처리 수로 변환해요. [장면 삽화](ILLUSTRATIONS.md)도 같은 미디어 저장소를 사용해요.

## 정리와 교환

폴더·검색·대표 이미지는 서재 탐색용 정보예요. 원본 Risu 내보내기는 [Risu 교환](RISU-EXPORT.md), Uimori 설정과 의존 자료를 함께 옮길 때는 개별 백업을 사용해요. 키는 개별 내보내기에 들어가지 않아요. [삭제](DELETION.md), [전체 DB 복구](DATA-MIGRATIONS.md)

봇에는 [번역 지침](TRANSLATION-GUIDES.md) 편집 영역도 있어요. 자유 지침과 표기 목록을 같은 자료에 저장하며 페르소나·모듈에는 이 편집 영역을 표시하지 않아요.

목록 조회는 봇 본문뿐 아니라 프롬프트 program도 생략해요. 선택·편집·복제는 대상 자료의 상세 조회를 사용하며 다른 프리셋의 본문을 같이 내려받지 않아요. 삭제 자료와 고아 이미지의 실제 정리는 [삭제](DELETION.md) 계약을 따르며, 현재 사용 중인 자료와 직전 저장 되돌리기의 참조는 유지해요.

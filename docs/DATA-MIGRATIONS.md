# 개인 작업실 데이터

## 현재 버전

개인 작업실 DB는 스키마 **5**, 형식 표시는 `uimori-personal-v1`이에요. 빈 DB는 초기화하고, 같은 개인 작업실 형식의 schema 1·2·3·4는 한 번의 트랜잭션으로 전환해요. 다른 형식이나 미래 버전의 DB는 자동으로 추측해 변경하지 않아요. 전환 전 서버를 멈추고 DB와 사용한 이미지 버전을 백업해요. 전환한 DB를 구버전 앱으로 다시 여는 다운그레이드는 지원하지 않아요.

요약은 현재 값과 실제 출처만 보관해요. 전체 원고·프롬프트를 복사한 checkpoint 입력, 완료된 요약 작업 입력, 편집 결과의 전체 화면 사본은 제거해요. 같은 편집 요청의 재전송은 다시 적용하지 않고 현재 상태를 반환해요. 진행 중이거나 재시도 가능한 실행이 참조하는 요약은 유지하며 작업이 끝나면 더 이상 필요한 참조가 없는 과거 후보를 정리해요.

변수 변경 기록은 요청 키·해시·개정만 보관해요. 변수 현재값과 과거 장면에서 독립 사본을 만들 때 사용하는 변수 체크포인트는 유지해요. 사용하지 않는 삭제 자료와 이미지도 전환 때 정리해요. 현재 메시지·자료·직전 저장 되돌리기·미완료 작업이 쓰는 참조는 보존해요.

### 현재 원문·번역과 이미지 정리

원문은 실제 메시지 구성에서 쓰는 최초 원문과 최신 수정본 두 개를 보관해요. 진행 중이거나 재시도 가능한 작업이 정확한 수정본을 참조하면 작업이 끝날 때까지 그 버전도 남겨요. 번역은 최신·직전 성공 결과와 현재 이미지 배치의 대상, 미완료 작업의 입력을 유지하고 그 밖의 전문은 정리해요. 비용 기록이 있는 작업은 작은 사용량·실행 메타데이터로 남기며 수동 편집만으로 생긴 낡은 작업 행은 제거해요.

스키마 5 전환에서 기존 이력을 이 기준으로 한 번 정리해요. 최신 내용이나 실제 참조를 잃지 않도록 전체 전환은 하나의 DB 트랜잭션으로 실행해요.

작업 때문에 당장 지울 수 없는 이미지 해시는 `image_cleanup_candidates`에 남겨요. 마지막 작업이 끝나거나 서버가 재시작하면 이 후보만 다시 정리하므로 삭제 요청을 잊어버리지 않아요. 삭제 후보와 숨김 자료가 없는 일반 정리는 원고 전문을 훑지 않고 끝나요.

### 구형 공유 분기의 일회성 전환

한 채팅에 여러 내부 분기가 남아 있으면 각 분기를 완전한 독립 채팅으로 옮겨요. **해당 구형 채팅만 새 ID를 갖기 때문에 예전 채팅 URL은 바뀌어요.** 일반적인 단일 분기 채팅의 ID는 유지해요. 이전 ID와 새 채팅 ID 목록은 `app_metadata`의 `schema4-independent-chats`에 남아요.

각 경로의 원문·완료된 번역·메모·변수·고정/1회 옵션·이미지와 도우미 대화·가정 장면을 보존해요. 완료되지 않은 요청은 텍스트와 부분 응답을 남기되 공급자를 자동 재실행하지 않아요. 공통 앞부분도 각 새 채팅의 메시지로 복사하므로 이후 삭제와 수정은 서로 독립적이에요. 이 전환은 [채팅 복사](CHAT-BACKUP.md)와 같은 자료 중심 계약이며, 이동한 분기의 자동 요약은 원문과 메모로 다시 만들어요. 단일 채팅의 현재 요약은 출처를 유지하면서 새 의존성 기준으로 변환해요.

분기 관리 화면·이름 생성·기본 분기 전환·공유 그래프 삭제 API는 더 이상 제공하지 않아요. 서버 내부의 단일 branch ID는 실행/문맥 소유자를 가리키는 키로만 남아요. 새로운 이야기는 별도 채팅으로 복사해요.

## 이전 schema 24에서 한 번 옮기기

다른 옛 형식인 schema 24는 별도 변환 도구를 사용해요. 원본 서버를 멈추고 DB를 보관한 뒤 새 버전에서 실행해요.

```sh
npm run build
npm run transfer:personal -- --source /absolute/old.sqlite --target /absolute/new.sqlite
```

원본은 읽기 전용이며 목적지는 존재하지 않는 새 파일이어야 해요. 임시 DB에서 변환과 외래키 검증을 마치고 결과를 게시해요. 자료·채팅·메모·변수·이미지를 옮기며 예전 분기는 독립 채팅이 돼요. 전송 입력·서버 초안·진단 기록·자동 요약·예약 작업은 이 별도 옛 형식의 전환에 포함하지 않아요.

접근 가능한 JEV/서비스 계정 파일은 DB로 옮겨요. 예전 일반 API 키를 환경변수에 넣었다면 `--environment-keys`를 명시해야 참조된 변수만 읽어요. 로그에는 키를 출력하지 않아요. 결과를 확인한 뒤 `UIMORI_DB`나 배포 볼륨을 바꾸며 실제 배포는 별도 작업이에요.

## 복구와 자료 교환

현재 자료와 수정 번호가 기준이에요. 일반 자료 저장의 직전본 한 개는 되돌리기에 사용하지만 모든 과거 개정이나 실행 입력을 영구 재현하지 않아요.

전체 작업실 복구는 SQLite 스냅샷을 사용해요. API 키와 이미지도 포함되므로 개인적으로 보관해요. 외부 Codex 로그인 디렉터리는 DB 백업 범위가 아니에요. [개별 자료](NATIVE-TRANSFER.md)와 [채팅 백업](CHAT-BACKUP.md)은 현재 사용자 자료를 새 사본으로 가져오며 내부 실행 기록을 재생하지 않아요.

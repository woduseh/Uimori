# 개인 작업실 데이터

## 현재 버전

개인 작업실 DB는 스키마 **2**, 형식 표시는 `uimori-personal-v1`이에요. 버전 숫자만 같은 구형 DB와 구분해요. 전체 DDL 서명을 비교하지 않으며 보조 인덱스를 추가했다고 시작을 차단하지 않아요. 빈 DB는 새로 초기화하고, 개인 작업실 schema 1은 한 번의 트랜잭션으로 schema 2로 올려요. 다른 형식과 미래 버전은 변경하지 않아요.

1→2 전환은 폐기된 옵션 위임 테이블·예약·증빙을 제거하고 Reader 조회 인덱스를 추가해요. 원문·번역·메모·이미지·채팅 고정값과 일반 1회 옵션은 보존해요. 실행 중인 서버를 종료하고 SQLite 백업을 보관한 뒤 새 앱으로 열어요. 이후 서버 경로에서 옛 형식의 위임이나 compiler를 해석하는 호환 계층은 사용하지 않아요.

자료는 현재 저장본과 수정 번호를 사용해요. 일반 저장의 직전본 한 개는 되돌리기용으로 남기지만 모든 과거 개정·서버 초안·자동 동기화 기록을 보존하지 않아요. 완료된 대화는 메시지·메모·변수·이미지가 기준이고, 전체 모델 입력을 영구 재현하는 아카이브가 아니에요.

## 이전 schema 24에서 한 번 옮기기

기존 서버를 멈추고 DB와 실행 버전을 먼저 별도로 보관해요. 새 버전에서 빌드한 뒤 다음 명령을 사용해요.

```sh
npm run build
npm run transfer:personal -- --source /absolute/old.sqlite --target /absolute/new.sqlite
```

원본은 읽기 전용으로 열며 **목적지는 존재하지 않는 새 파일**이어야 해요. 임시 DB에 변환한 뒤 외래키를 검사하고 새 파일로 게시해요. 실패하면 원본이나 이미 존재하는 목적지 파일을 덮어쓰지 않아요. 변환본을 확인한 뒤 `UIMORI_DB`를 새 파일로 지정해요. 운영 볼륨 전환과 배포는 별도 작업이에요.

봇·페르소나·모듈·프리셋·모델 설정·채팅·유효한 메모·변수·이미지를 옮겨요. 기존 분기는 각각 독립 채팅으로 만들어요. JEV의 기존 키 파일과 등록된 서비스 계정 파일은 접근 가능하면 DB로 옮겨요. 예전 일반 API 키를 환경변수에 넣었다면 같은 명령에 `--environment-keys`를 명시적으로 추가해야 해당 프로바이더가 참조하는 변수만 읽어요. 기본은 앱에서 키를 다시 등록하는 방식이에요. 로그에는 키 값을 출력하지 않아요.

과거 전체 실행 입력, 서버 초안, 권한 기록, 스트리밍 청크, 자동 요약, 폴더 배치, 예약 작업과 일회성 옵션은 이전하지 않아요. 원문·메모로 계속 쓰고 요약은 다시 만들 수 있어요. 변환 결과의 notices를 확인해요. 이 코드는 일반 서버의 호환 계층이 아닌 별도 일회성 도구예요.

## 복구와 자료 교환

전체 작업실 복구에는 SQLite 스냅샷을 사용해요. API 키와 WebP 이미지도 DB에 있으므로 백업은 비밀 자료예요. 외부 Codex 실행기의 로그인은 DB 백업 범위가 아니에요.

개별 자료는 [독립 자료 교환](NATIVE-TRANSFER.md), 대화는 [채팅 백업](CHAT-BACKUP.md)을 사용해요. 두 기능 모두 현재 형식의 사용자 자료를 새 사본으로 가져오며 내부 실행 기록을 재생하지 않아요. 구형 전체 JSON 아카이브 복원은 제거했어요.

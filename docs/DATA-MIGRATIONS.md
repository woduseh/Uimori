# 개인 작업실 데이터

## 현재 버전과 전환

개인 작업실 DB는 스키마 **15**, 형식 표시는 `uimori-personal-v1`이에요. 빈 DB는 초기화하고, 같은 형식의 **스키마 13·14만** 한 번의 트랜잭션으로 전환해요. 스키마 1~12, 다른 형식, 미래 버전은 DB를 변경하기 전에 명시적으로 거절해요. 지원하지 않는 파일을 추측해 열거나 백업을 삭제하지 않아요. 전환 전 서버를 멈추고 DB와 해당 앱 이미지 버전을 함께 보관해요. 전환된 DB를 구버전 앱으로 다시 여는 다운그레이드는 지원하지 않아요.

채팅이 원문 머리와 실행 상태의 유일한 소유자예요. `branches` 테이블과 `branch_id` 열, API의 `branchId`는 제공하지 않아요. 현재 머리는 `chats.head_revision` 한 곳에 저장하고, 새로운 이야기는 자료를 복사한 독립 채팅으로 만들어요.

전환은 기존 채팅마다 내부 식별자가 정확히 하나인지, 모든 참조가 같은 채팅에 속하는지 먼저 확인해요. 스키마 13에서는 채팅과 기존 기본 경로의 머리도 일치해야 해요. 모순이 있으면 어느 쪽도 선택하거나 덮어쓰지 않고 전체 전환을 취소해요. 복합 키를 바꿀 때는 남는 모든 열과 행 순서를 복사하고, 외래키 검증을 통과한 뒤 버전과 변경을 함께 확정해요.

본문·번역과 배치 정보·설정·변수·옵션·구성·메모·도우미 대화·읽기 위치·책갈피·사용량과 작업 ID를 보존해요. 문맥 소유 키가 바뀌는 체크포인트는 해시와 저장된 참조를 함께 변환해요. 공급자 요청 원문과 응답, 작업의 owner/generation, 실패·부분 응답·불확실한 결과는 임의로 재작성하거나 재실행하지 않아요. 사용자 JSON이나 변수에 같은 이름의 필드가 있어도 변경하지 않아요.

본문 요청과 문맥 예약처럼 명령 원문이 남은 영수증은 제거된 필드만 변환하고 동일한 요청 키로 기존 결과를 확인해요. 옵션·로어 수정·문맥 편집처럼 해시만 남은 과거 영수증은 그대로 보존해요. 변환 후 같은 키의 내용이 맞지 않으면 409로 거절하며 다시 적용하지 않아요. 변경 요청에 이전 API 필드를 넣으면 입력 검증에서 거절해요.

브라우저의 미저장 초안과 미확정 요청은 서버 DB와 별도예요. 브라우저 전환은 저장된 내용을 새 채팅 키로 옮기되 충돌한 원본을 지우거나 자동 전송하지 않아요. 현재 형식의 파일 백업과 원본 SQLite 스냅샷은 그대로 보관할 수 있어요.

## 현재 자료와 보관 범위

요약은 현재 값과 실제 출처를 보관해요. 전체 원고·프롬프트를 중복한 완료 작업 입력은 정리하지만, 진행 중이거나 재시도 가능한 실행이 참조하는 요약과 정확한 입력은 유지해요. 변수 현재값과 과거 장면에서 독립 사본을 만들 때 필요한 변수 체크포인트도 유지해요.

원문은 실제 메시지 구성에서 쓰는 최초 원문과 최신 수정본을 보관해요. 진행 중이거나 재시도 가능한 작업이 정확한 수정본을 참조하면 작업이 끝날 때까지 그 버전도 남겨요. 번역은 최신·직전 성공 결과, 현재 이미지 배치의 대상과 미완료 작업의 입력을 유지해요. 비용 기록이 있는 작업은 작은 사용량·실행 메타데이터로 남아요. 이 일반 보관 정책은 소유권 전환을 위해 본문을 다시 쓰거나 추가로 정리한다는 뜻이 아니에요.

작업 때문에 당장 지울 수 없는 이미지 해시는 `image_cleanup_candidates`에 남겨요. 마지막 작업이 끝나거나 서버가 재시작하면 이 후보를 다시 정리해요. 현재 자료·직전 저장 되돌리기·미완료 작업이 참조하는 내용은 보존해요.

## 이전 schema 24에서 한 번 옮기기

다른 옛 형식인 schema 24는 별도 변환 도구를 사용해요. 원본 서버를 멈추고 DB를 보관한 뒤 새 버전에서 실행해요.

```sh
npm run build
npm run transfer:personal -- --source /absolute/old.sqlite --target /absolute/new.sqlite
```

원본은 읽기 전용이며 목적지는 존재하지 않는 새 파일이어야 해요. 임시 DB에서 변환과 외래키 검증을 마치고 결과를 게시해요. 자료·채팅·메모·변수·이미지를 옮기며 예전 분기는 독립 채팅이 돼요. 전송 입력·서버 초안·진단 기록·자동 요약·예약 작업은 이 별도 옛 형식의 전환에 포함하지 않아요.

접근 가능한 JEV/서비스 계정 파일은 DB로 옮겨요. 예전 일반 API 키를 환경변수에 넣었다면 `--environment-keys`를 명시해야 참조된 변수만 읽어요. 로그에는 키를 출력하지 않아요. 결과를 확인한 뒤 `UIMORI_DB`나 배포 볼륨을 바꾸며 실제 배포는 별도 작업이에요.

## 복구와 자료 교환

현재 자료와 수정 번호가 기준이에요. 일반 자료 저장의 직전본 한 개는 되돌리기에 사용하지만 모든 과거 개정이나 실행 입력을 영구 재현하지 않아요.

전체 작업실 복구는 SQLite 스냅샷을 사용해요. API 키와 이미지도 포함되므로 개인적으로 보관해요. 외부 Codex 로그인 디렉터리는 DB 백업 범위가 아니에요. [개별 자료](NATIVE-TRANSFER.md)와 [채팅 백업](CHAT-BACKUP.md)은 현재 사용자 자료를 새 사본으로 가져오며 내부 실행 기록을 재생하지 않아요. 스키마 13·14 스냅샷도 위의 같은 전환을 거쳐 사용할 수 있어요. 그보다 오래된 백업은 지원되는 당시 앱과 함께 별도로 보관해야 해요.

### 채팅 실행 설정

채팅 설정은 장면 해설 자동 생성(`status`)과 본문 작업 호출 한도(`maxCalls`)를 저장해요. 예전 DB·휴대용 백업의 `preset`, `mode`, `translation` 필드는 읽기·복원 경계에서 무시하고 이후 저장에서 제외해요. 실제 번역 기능과 번역 정책은 유지해요.

### 삽화 프리셋 초기화

프리셋 도입 이전의 `illustration_settings`에 있던 `styleGuidance`, `comfyui.workflow`, `comfyui.negativeGuidance`는 첫 실행 때 **기존 삽화 설정** 자료로 한 번 옮겨 작업실 기본으로 선택해요. 비어 있었다면 내장 기본을 사용해요. 공통 `versions`와 `app_metadata`를 사용해요.

세 필드는 전역 설정에서 제거하고 설정 수정 번호를 올려 이미 열려 있던 구형 편집기의 저장과 충돌시키며, 생성기·모델·연결 주소·인증·자동 생성 정책은 유지해요. 자료 생성·선택·전역 설정 변경은 하나의 트랜잭션이고 실패하면 전부 취소해요. 초기화 완료 표시가 있어 재시작하거나 옮긴 프리셋을 삭제해도 다시 만들지 않아요. 기존 삽화와 작업의 고정 입력은 다시 쓰지 않아요. 전체 DB 백업은 카탈로그와 선택을 포함해요. 사용·교환 계약은 [장면 삽화](ILLUSTRATIONS.md#삽화-프리셋)를 참고해요.

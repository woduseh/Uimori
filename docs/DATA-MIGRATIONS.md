# 개인 작업실 데이터

Uimori 개인 작업실 데이터베이스의 현재 스키마 버전, 보관 범위, 백업 및 복구 원칙, 기능별 데이터 저장 정책을 안내해요.

## 현재 버전

- **스키마 버전과 형식 식별자**: 개인 작업실 DB는 스키마 **15**, 형식 표시는 `uimori-personal-v1`이에요.
- **초기화 및 호환성 거절 원칙**:
  - 데이터가 없는 빈 DB는 스키마 15로 새로 초기화해요.
  - 기존 DB는 현재 형식(`uimori-personal-v1` 스키마 15)인 경우에만 열어요.
  - 이전 버전이나 미래 버전 스키마, 또는 다른 형식의 파일은 DB를 변경하기 전에 명시적으로 열기를 거절해요.
  - 완료된 과거 DB나 브라우저 마이그레이션 코드는 포함하지 않으며, 호환되지 않는 DB 파일을 자동으로 변환하거나 덮어써서 초기화하지 않아요.
- **채팅 중심의 단일 소유권 모델**: 채팅이 원문 머리(head)와 실행 상태의 유일한 소유자예요. 새로운 전개나 이야기 분기는 자료를 복사한 독립 채팅으로 생성해 이어가요.
- **기존 데이터의 호환성 유지**:
  - 과거 도우미 세션 분기에서 복제된 대화문은 스키마 15 내에서 계속 읽고 이어갈 수 있어요.
  - 실행 진단 메타데이터도 스키마 15 내에서 관리돼요.
  - 서재 폴더의 표지 이미지 선택도 스키마 15 내의 별도 표에 보관하며, 표가 없는 기존 DB에는 열 때 추가해요.
  - 플롯의 진행 중 항목(`outline_focus` 표)과 원문 연결 종류(`outline_writings.origin` 열, 기본값 `planned`)도 같은 방식으로 기존 DB를 열 때 추가해요. 이전 앱은 이 표와 열을 무시하므로 되돌린 앱도 같은 DB를 열 수 있어요.
  - 도우미 변경 기록(`helper_changes` 표)도 기존 DB를 열 때 빈 표로 추가하고, 표가 이미 있으면 되돌리기에 쓰는 열(`result`, `foreign_edit`, `rolled_back_at`)을 기존 행을 그대로 둔 채 더해요.
  - 별도의 스키마 버전 변경 없이 기존 스키마 15 DB를 열고 사용할 수 있어요.

## 현재 자료와 보관 범위

- **요약 및 문맥 데이터**: 요약은 현재 값과 실제 출처를 보관해요. 전체 원고나 프롬프트를 복제했던 완료된 작업 입력은 정리하지만, 현재 진행 중이거나 재시도 가능한 작업이 참조하는 요약과 정확한 입력은 보존해요. 변수 현재값과 과거 장면에서 독립 사본을 만들 때 필요한 변수 체크포인트도 유지해요.
- **원문 텍스트**: 실제 메시지 구성에 사용되는 최초 원문과 최신·직전 수정본을 보관해요. 원문 편집기의 저장본 비교는 이 범위를 읽어서 제공해요. 진행 중이거나 재시도 가능한 작업이 특정 수정본을 참조하고 있다면 그 작업이 끝날 때까지 해당 저장본을 유지해요. 완료되지 않고 끝난 본문 실행은 고정했던 대화 기록 사본을 정리하고 현재 원문으로 재시도하므로 수정본을 붙잡지 않아요. JEV 판정을 다시 받을 수 있는 실행은 예외로 고정 입력을 유지해요.
- **끝난 실행의 고정 입력 정리**: 실행이 끝날 때 고정 입력을 정리해요. 실행의 요청·상태·오류·사용량·부분 결과는 바뀌지 않아요.
- **번역 및 실행 메타데이터**: 최신 및 직전 성공 번역 결과, 현재 이미지 배치의 대상, 미완료 작업의 입력을 유지해요. 비용 기록이 있는 작업은 작은 크기의 사용량 및 실행 메타데이터로 남겨요.
- **선택적 장면 제목**: 장면 제목은 기존 메타데이터에 보관되며 스키마 15를 그대로 유지해요. 채팅 삭제 시 해당 이름도 함께 정리되고, 독립 사본 복사나 개별 백업 시에는 새로운 장면 ID에 이름이 연결돼요. 제목이 없는 기존 데이터에 대한 별도 변환 작업은 필요하지 않아요.
- **도우미 변경 기록**: 도우미 작업이 바꾼 대상마다 바꾸기 전 상태와 차이를 보관해요. 대화마다 최근 15개 작업, 30일까지만 글을 보관하고, 그 뒤에는 무엇을 바꿨는지만 남겨요. 삭제할 때의 정리는 [도우미 변경 기록](DELETION.md#도우미-변경-기록)에 있어요.
- **작업 중 이미지 보존**: 진행 중인 작업으로 인해 당장 삭제할 수 없는 이미지 해시는 임시 후보로 보관했다가, 마지막 작업이 끝나거나 서버가 재시작될 때 정리해요. 현재 자료, 직전 저장 되돌리기, 미완료 작업, 보관 중인 도우미 변경 기록이 참조하는 이미지는 보존돼요.
- **브라우저 미저장 초안**: 브라우저의 미저장 초안과 미확정 요청은 서버 DB와 분리되어 있어요. 현재 채팅 키에 따른 초안·읽기 위치와 IndexedDB의 편집기·도우미 복구 버퍼를 사용해요. 이전 형식의 브라우저 키(예: 세션 저장소의 활동 확인 키, 수정 번호나 복구 토큰이 없는 버퍼)는 읽거나 삭제하지 않아요. 요청·도우미 첨부 초안은 v0.13.0까지 쓰던, 이미지를 한 기록에 담은 형식도 읽어요. 기준 수정 번호가 없는 대기 중 시작 설정은 저장된 설정 사용 여부를 묻는 충돌로 안내해요. 복구 가능한 현재 요청은 기존 요청 키로 서버 수락 여부를 확인하되 자동으로 새 작업을 만들지는 않아요.

## 서버를 열 때 정리하는 저장 형식

서버는 DB를 열 때마다 한 트랜잭션에서 이전 모양으로 남은 행만 현재 모양으로 바꿔요(`server/stored-shape-upgrades.ts`). 수정 번호는 바꾸지 않고, 이미 현재 모양인 행은 다시 쓰지 않아요. 전체 백업에서 복원한 DB도 처음 열 때 같은 정리를 거쳐요.

- **자동 제목 등록 언어**: 언어 대신 채팅 ID가 저장된 `chat.title.eligible` 기록은 한국어(`ko`)로 바꿔요.
- **도우미 확인 인자**: 더 이상 확인할 수 없는 보류 호출과, 끝났거나 다시 시도한 작업이 받은 확인 호출에서 호출 인자를 지워요([도우미 도구](HELPER-TOOLS.md#confirmation-before-destructive-or-bulk-operations)).
- **도우미 한도와 입력 측정**: 대화 한도와 작업 스냅샷 한도의 `artifacts`를 지우고, `inputTokenLimit`가 없는 입력 측정 기록에는 작업 스냅샷의 모델 한도가 있으면 복사해요.
- **삽화 설정·프리셋·참고 이미지·작업 입력**: [삽화 프리셋](#삽화-프리셋)과 [문단 삽화](#문단-삽화)에 적은 대로 채워요.
- **평가 도구 폐지 설정**: 모델 프리셋의 `evaluationTools`에서 `maximumToolRounds`·`terminalLateCorrections`·`outputRecovery`를 지워요. 이후 이 필드가 있는 평가 설정은 저장과 검증 모두에서 거부돼요.
- **이전 채팅 복사 기록**: 복사 명령이 기록되지 않은 이전 복사 기록은 고치지 않고 더 이상 복구에 쓰지 않아요. 그 기록의 요청 키로 다시 복사하면 `CHAT_COPY_RECEIPT_UNVERIFIED`(409)를 안내하고 브라우저에 남은 요청 키를 지워서, 다음 시도는 새 사본을 만들어요.

## 복구와 자료 교환

- **최신 자료와 수정 번호 기준**: 항상 현재 자료와 최신 수정 번호가 복구와 교환의 기준이 돼요. 일반 자료 저장에서 직전본 1개는 되돌리기에 사용되지만, 모든 과거 저장본이나 실행 입력을 영구적으로 재현하지는 않아요.
- **전체 작업실 복구**: 현재 스키마의 SQLite 스냅샷 파일을 사용해요. 원문, 이미지, API 키가 모두 포함되어 있으므로 개인 저장소에 안전하게 보관하세요. 외부 Codex 로그인 디렉터리는 DB 백업 범위에 포함되지 않아요.
- **개별 자료 교환**: [개별 자료](NATIVE-TRANSFER.md)와 [채팅 백업](CHAT-BACKUP.md)은 현재 사용자 자료를 새 사본으로 가져오며, 내부 실행 기록을 재생하지 않아요.
- **구형 스키마 DB 백업 관리**: 이전 스키마의 DB 백업은 해당 형식을 지원했던 앱 버전과 함께 별도로 보관해 주세요. 복구할 때는 운영 서버를 중지하고 별도 경로에 사본을 둔 뒤 호환 앱을 사용해야 해요. 현재 운영 DB를 라이브로 덮어쓰거나 구형 백업을 현재 앱으로 자동 변환하지 않아요. (과거 DB 변환 코드의 정리는 기존 백업이나 운영 자료를 삭제한다는 뜻이 아니에요.)

### 채팅 실행 설정

- **호출 한도 저장**: 채팅 설정에는 본문 작업의 모델 호출 한도(`maxCalls`)를 저장해요.
- **장면 해설 자동 생성 종료**:
  - 장면 해설 자동 생성 기능은 완전히 종료되었어요.
  - `status` 설정과 역할별 해설 모델은 새로운 생성에 사용하지 않아요.
  - 물리적 스키마는 15로 유지돼요.
- **기존 데이터 보존**: 기존 DB 및 백업에 남아 있는 설정, 해설 결과, job, 사용량 기록은 삭제하거나 다른 작업으로 자동 변환하지 않아요.
- **읽기 화면 및 실행 제어**: 읽기 화면에는 해설을 표시하지 않으며, 기존 job은 진단용으로 조회할 수 있지만 새로운 해설 생성이나 재시도는 허용하지 않아요. 서버가 시작될 때 기존 해설 작업을 다시 실행하지도 않아요.
- **번역 기능 유지**: 실제 본문 번역 기능과 번역 정책은 변함없이 정상 유지돼요.

### 도우미의 과거 가정 장면

- **가정 장면 기능 종료**:
  - 도우미를 통한 가정 장면(artifact)의 신규 생성, AI 재작성, 직접 편집 기능은 종료되었어요.
  - `artifact.generate` 및 `PATCH /api/helper/artifacts/:id`는 제공하지 않아요.
  - `artifact.read`와 장면 조회 GET 요청은 과거에 저장된 원문, 요청, 수정 이력을 열람하는 읽기 전용 목적으로 유지돼요.
  - 다른 이야기 전개를 시도하려면 채팅 사본을 만든 뒤 일반 집필로 작성해 주세요.
- **기존 데이터와 한도 유지**:
  - 물리적 스키마는 15로 유지되며, 기존 `helper_artifacts`, `helper_artifact_jobs` 테이블과 저장된 장면 원문, 요청, 수정 이력은 삭제하거나 다른 형식으로 변경하지 않아요.
  - 저장된 대화 한도와 작업 스냅샷 한도의 `artifacts` 항목은 서버를 열 때 제거해요. `HelperLimits`는 `totalCalls`와 `helperCalls`만 사용해요.
- **미완료 작업 및 초안 처리**:
  - 남아 있던 실행 중 가정 장면 job은 기존 서버 중단 처리로 종료하며, 새 생성이나 재시도는 하지 않아요.
  - 브라우저에 남아 있는 과거 편집 초안(수정 번호가 기록된 형식)은 자동 삭제하지 않고 내용 확인 및 복사 기능을 제공해요. 수정 번호가 없는 이전 형식 초안은 표시하지 않아요.

### 삽화 프리셋

- **저장 위치**: 삽화 프리셋은 공통 `versions` 테이블에, 사용자의 선택 상태는 `app_metadata`에 저장해요.
- **기본 프리셋과 하위 호환**:
  - 프리셋 선택이 없는 새 작업실은 내장 기본 프리셋을 사용하며, 사용자가 선택할 때 저장돼요.
  - 기존 프리셋, 사용자 선택 상태, 진행 중인 작업의 고정 입력은 변경하지 않아요. 전체 DB 백업에는 카탈로그와 선택 상태가 모두 포함돼요.
- **v1 및 v2 호환 규칙**:
  - 프리셋 v2는 생성기 정보를 포함하며, 생성 실행 환경은 로컬 공용 설정에 남아요.
  - 생성기가 없는 v1 프리셋 파일은 워크플로가 있으면 ComfyUI, 없으면 Codex로 읽어요. 저장된 v1 프리셋과 직전 저장본에는 서버를 열 때 같은 규칙으로 `generator`를 채우며, 수정 번호와 고정 작업 입력은 바꾸지 않아요.
  - `novelai` 항목이 없는 프리셋 파일은 NovelAI 제외 지침을 빈 값으로 읽어요. 저장된 프리셋과 삽화 설정에 빠진 `novelai` 블록과 기본 항목은 서버를 열 때 기본값으로 채워요(수정 번호 유지). NovelAI 토큰은 공통 `credentials` 테이블(`novelai`)에만 저장해요.
  - 과거 `generator=none` 설정은 서버를 열 때 자동 생성을 끈 상태로 바꾸고 `generator` 키를 지워요. 설정의 `generator`에는 테스트 모드의 `fixture`만 저장돼요.
  - 새로운 요청은 프리셋에 지정된 생성기를 사용하고, 과거 작업의 재시도는 당시 고정된 생성기를 유지해요.
  - 자세한 사용 및 자료 교환 계약은 [장면 삽화](ILLUSTRATIONS.md#삽화-프리셋)를 참고해요.

### 문단 삽화

- **스키마 및 입력 저장**: 물리적인 DB 스키마는 15로 유지해요. `task` 필드가 없는 기존 삽화 작업 입력에는 서버를 열 때 `render`를 채워요. `codex.promptModel`이 없는 과거 완료 작업은 그대로 두며, 그런 입력을 실행하면 `ILLUSTRATION_PROMPT_MODEL_REQUIRED`로 실패해요. 새로운 `plan / render / placement`와 타깃 정보는 JSON 입력에 저장해요.
- **표시 선택 메타데이터**: 응답별 대표 이미지, 표시 선택, 번역 위치는 `app_metadata`의 `illustration-presentation:<sourceId>`에 보관해요.
- **삭제 및 교환 범위**: 채팅을 삭제하면 관련 삽화 메타데이터도 함께 정리돼요. 채팅 복사 및 개별 백업 시에는 내부 실행 기록이나 모델 호출 로그 대신 성공한 컷, 변형 그룹, 검증 가능한 위치 정보만 옮겨요.
- **자동 생성 기본값**: 컷 수 모드가 없는 기존 자동 생성 설정은 서버를 열 때 고정 모드(최소 0컷, 최대는 기존 값 또는 1컷)로 채워요.
- **채팅 참고 이미지**: 배열로 저장된 과거 채팅 참고 이미지 목록은 서버를 열 때 `{references, characterProfiles: []}` 모양으로 바꿔요(수정 번호 유지).

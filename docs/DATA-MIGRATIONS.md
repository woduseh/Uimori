# 개인 작업실 데이터

## 현재 버전

개인 작업실 DB는 스키마 **15**, 형식 표시는 `uimori-personal-v1`이에요. 빈 DB는 초기화하고, 기존 DB는 현재 형식만 열어요. 이전·미래 스키마와 다른 형식은 DB를 변경하기 전에 명시적으로 거절해요. 완료된 DB·브라우저 전환 코드는 제공하지 않으며, 지원하지 않는 파일을 자동 변환하거나 초기화하지 않아요.

채팅이 원문 머리와 실행 상태의 유일한 소유자예요. `branches` 테이블과 `branch_id` 열, API의 `branchId`는 제공하지 않아요. 현재 머리는 `chats.head_revision` 한 곳에 저장하고, 새로운 이야기는 자료를 복사한 독립 채팅으로 만들어요. 작업의 owner/generation, 개정 충돌, 취소 후 늦은 저장 차단과 요청 키에 따른 중복 실행 방지는 유지해요.

## 현재 자료와 보관 범위

요약은 현재 값과 실제 출처를 보관해요. 전체 원고·프롬프트를 중복한 완료 작업 입력은 정리하지만, 진행 중이거나 재시도 가능한 실행이 참조하는 요약과 정확한 입력은 유지해요. 변수 현재값과 과거 장면에서 독립 사본을 만들 때 필요한 변수 체크포인트도 유지해요.

원문은 실제 메시지 구성에서 쓰는 최초 원문과 최신 수정본을 보관해요. 진행 중이거나 재시도 가능한 작업이 정확한 수정본을 참조하면 작업이 끝날 때까지 그 버전도 남겨요. 번역은 최신·직전 성공 결과, 현재 이미지 배치의 대상과 미완료 작업의 입력을 유지해요. 비용 기록이 있는 작업은 작은 사용량·실행 메타데이터로 남아요.

작업 때문에 당장 지울 수 없는 이미지 해시는 `image_cleanup_candidates`에 남겨요. 마지막 작업이 끝나거나 서버가 재시작하면 이 후보를 다시 정리해요. 현재 자료·직전 저장 되돌리기·미완료 작업이 참조하는 내용은 보존해요.

브라우저의 미저장 초안과 미확정 요청은 서버 DB와 별도예요. 현재 채팅 키의 초안·읽기 위치와 IndexedDB의 편집기·도우미 복구 버퍼를 사용해요. 이전 형식의 브라우저 키를 해석하거나 삭제하지 않아요. 복구 가능한 현재 요청은 기존 요청 키로 수락 여부를 확인하며 자동으로 새 작업을 만들지 않아요.

## 복구와 자료 교환

현재 자료와 수정 번호가 기준이에요. 일반 자료 저장의 직전본 한 개는 되돌리기에 사용하지만 모든 과거 개정이나 실행 입력을 영구 재현하지 않아요.

전체 작업실 복구는 현재 스키마의 SQLite 스냅샷을 사용해요. API 키와 이미지도 포함되므로 개인적으로 보관해요. 외부 Codex 로그인 디렉터리는 DB 백업 범위가 아니에요. [개별 자료](NATIVE-TRANSFER.md)와 [채팅 백업](CHAT-BACKUP.md)은 현재 사용자 자료를 새 사본으로 가져오며 내부 실행 기록을 재생하지 않아요.

이전 스키마의 DB 백업은 해당 형식을 지원했던 앱 버전과 함께 보관해요. 복구할 때는 서버를 멈추고 별도 경로의 백업과 맞는 앱을 사용해요. 현재 운영 DB를 덮어쓰거나 구형 백업을 현재 앱으로 자동 변환하지 않아요. DB 변환 코드 제거는 기존 백업·운영 자료의 삭제를 뜻하지 않아요.

### 채팅 실행 설정

채팅 설정은 장면 해설 자동 생성(`status`)과 본문 작업 호출 한도(`maxCalls`)를 저장해요. 실제 번역 기능과 번역 정책은 유지해요.

### 삽화 프리셋

삽화 프리셋은 공통 `versions`에, 선택은 `app_metadata`에 저장해요. 선택이 없는 새 작업실은 내장 기본 프리셋을 사용하며 선택할 때 저장해요. 기존 프리셋·선택과 진행 중 작업의 고정 입력은 변경하지 않아요. 전체 DB 백업은 카탈로그와 선택을 포함해요. 사용·교환 계약은 [장면 삽화](ILLUSTRATIONS.md#삽화-프리셋)를 참고해요.

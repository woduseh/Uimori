# 공개된 AI 제품 디자인 원칙과 Uimori 적용안

2026-09-10에 조사·검토한 **제안 문서**예요. ChatGPT·Codex·Claude가 공개한 디자인 원칙이 무엇인지 확인하고, 그중 Uimori에 가져올 원칙을 고르고, 오늘 실행 화면(합성 자료, 390×844·1440×900, 다크 테마)에서 그 원칙과 어긋나는 곳을 측정해 적용 순서를 제안해요. [UI 원칙 v1.1](UI-PRINCIPLES.md)의 판단 순서·아이콘 규칙·시작값과 [UI 설계 v2](UI-DESIGN-V2.md)의 세 층 모델은 그대로 유효하고, 이 문서는 그 위에 **외부 원칙과의 대조**와 **오늘 측정한 차이**를 더해요. 구현·검증 전이며 아래 제안 중 결정이 필요한 항목은 따로 표시했어요.

## 1. 무엇이 공개되어 있나

ChatGPT·Codex·Claude **제품 자체**의 디자인 원칙 문서는 세 회사 모두 공개하지 않았어요. 공개된 것은 그 제품 **안에서 동작하는 제3자 UI**를 위한 가이드라인과, 프론트엔드를 만들 때 모델에게 주는 지침이에요. 제3자 가이드라인은 결국 "우리 제품처럼 보이고 움직이려면 이렇게 하라"는 문서라서, 그 제품이 스스로 지키는 규칙을 가장 가깝게 드러내요.

Google PAIR Guidebook과 Microsoft HAX Toolkit도 사람-AI 상호작용의 일반 지침을 공개하고 있지만 이번 범위에서는 위 세 회사와 Apple만 대조했어요. 제3자 블로그가 "Claude의 디자인 원칙"으로 정리한 글들은 Anthropic의 공식 문서가 아니라 인용하지 않았어요.

## 2. Uimori에 가져올 원칙

Uimori는 원고를 읽고 이어 쓰는 앱이라 ChatGPT·Claude보다 **읽기 폭과 본문 비율**이 더 중요하고, 봇·페르소나·모듈·프롬프트·모델처럼 고유 개념이 많아 **이름의 일관성**이 더 중요해요. 아래는 외부 원칙 중 Uimori에 그대로 가져올 것과, 이미 있는 규칙에 무엇을 더하는지예요.

| P1 | 상시 표시는 헤더·내용·입력 세 가지 | ChatGPT·Claude 공통 구조, v2 | 세 층 모델, "완료는 상태가 아니다" | 화면별 **0층 제어 개수 상한**을 검사 수치로 둬요: 모바일 헤더 4개 이하, 빈 입력창 52px, 요청 하나당 상시 행동 1개 이하 |

## 3. 오늘 화면 검토에서 본 차이

합성 봇 2개·채팅 3개·장면 3개, 모델 미등록, 프롬프트 없음, 다크 테마, macOS Edge 152 Playwright(390×844 터치·1440×900)에서 측정했어요. 실기기·라이트 테마·모델 등록 상태는 보지 않았어요. 아래는 원칙과 어긋난 정도가 큰 순서예요.

### F1 · 모바일 장면 ⋯ 메뉴가 화면 위로 잘려요 (결함, P2)

첫 장면의 ⋯을 누르면 메뉴 상자가 `y = −27px`에서 시작하고 첫 항목 "도우미에게 물어보기"의 상단이 `−20px`이에요. 헤더 아래쪽이 56px이니 첫 항목은 보이지 않고 두 번째 항목도 헤더에 절반 가려요. 항목이 8개(44px × 8 = 394px)라 위로 열면 390×844에서 들어갈 자리가 없어요. Anthropic이 팝오버를 피하라고 한 이유가 정확히 이 현상이에요.

제안: `pointer: coarse` 또는 600px 이하에서는 장면 ⋯·채팅 ⋯·입력창 ⋯을 **하단 시트**로 열고, 넓은 화면에서는 팝오버를 뷰포트 안으로 clamp해요. 항목도 줄여요 — `원문 연결 정보`와 `본문 추정 비용`은 행동이 아니라 정보라서 장면 헤더 줄을 눌러 펼치는 작업 상세(v2 1단계)로 옮기면 메뉴는 6개가 돼요.

### F2 · 모바일 헤더 제어가 5개이고 모델 칩이 입력창 위로 내려왔어요 (P1)

헤더에 `탐색 메뉴`·`도우미 열기`·`장면 목록 열기(제목)`·`채팅 설정`·`채팅 메뉴` 5개가 있어요. v2 목표는 4개였고, 모델 칩은 헤더에서 빠져 입력창 위의 44px 칩(`현재 본문 모델 · 본문 모델을 선택해 주세요`)이 됐어요. 그래서 빈 입력창 dock이 52px이 아니라 **113px**이에요. `도우미 열기`는 이름 없는 말풍선 아이콘이라 아이콘 규칙의 "문맥이 필요한 행동" 기준에도 걸려요.

제안: 모바일 헤더를 `[☰] [제목 / 봇 · 페르소나] [모델 칩(짧은 이름)] [⋯]` 4개로 되돌려요. `채팅 설정`과 `도우미`는 ⋯의 첫 두 항목으로, 도우미는 입력창 ⋯에서도 열 수 있게 해요(장면 ⋯의 "도우미에게 물어보기"와 같은 이름). 모델 칩이 헤더로 가면 입력창 위 상태 줄은 진행·실패·불확실에만 나타나고 dock은 52px로 돌아가요. 데스크톱은 현재 `[모델 칩] [채팅 설정] [⋯]`을 유지해도 4개 이하예요.

### F3 · 요청 말풍선마다 연필 버튼 한 줄이 상시 표시돼요 (P1·P3)

`request-message.css`가 `hover: none`·`pointer: coarse`·600px 이하에서 `.request-message-actions`를 항상 보이게 해요. 요청 하나당 44px 행이 추가되고, 첫 화면에서 말풍선 아래(129px)부터 장면 헤더(192px)까지 63px 중 44px을 이 버튼이 써요. 요청 수정은 가끔 쓰는 행동이에요. ChatGPT·Claude 모바일은 사용자 메시지의 수정·복사를 길게 누르기나 탭으로 열어요.

제안: 터치에서는 말풍선을 탭하면 `복사 · 수정` 두 항목의 작은 시트를 열고 상시 연필은 없애요. 길게 누르기만 쓰지는 않아요(발견이 어려워요). 절충안은 **마지막 요청에만** 연필을 남기는 것이에요.

### F4 · 드로어 채팅 행에 아이콘 3개, 그중 삭제가 0층이에요 (P3·P4·P11)

모바일 드로어의 채팅 행마다 `⋯ · 이동 · 삭제(빨강)` 세 아이콘이 항상 보여요. 삭제는 확인 단계가 있지만 빨간 아이콘이 목록 전체에 반복되고, 행당 상시 행동 상한 2개를 넘어요. 드로어 첫 줄 56px은 닫기 X 하나만 있고, 새 채팅과 검색은 봇 행을 펼치거나 서재로 가야 나와요. ChatGPT·Claude·Codex 사이드바는 모두 첫 줄이 **새 채팅 + 검색**이에요.

제안: 채팅 행은 `⋯` 하나만 남기고 `이름 변경 · 이동 · 삭제`를 그 안에 둬요. 드로어 첫 줄은 `[닫기] [새 채팅] [검색]`으로 쓰고, 새 채팅은 봇 선택 시트를 열어요. **결정 필요:** "채팅 없는 봇은 서재에만 산다"는 [REDESIGN](../project-plan/REDESIGN.md)의 결정과 겹쳐요. 봇 선택 시트가 서재의 봇 탭을 그대로 여는 방식이면 그 결정을 유지하면서 진입점만 더하는 셈이에요.

### F5 · "모델"이 세 곳에서 다른 범위를 가리켜요 (P7)

설정에 `현재 모델`과 `프로바이더와 모델`이 나란히 있고, 채팅 설정에도 `모델`이 있어요. 첫째는 역할별 전역 선택, 둘째는 등록·연결, 셋째는 이 채팅의 덮어쓰기예요. 같은 단어가 세 범위를 가리켜요.

제안(결정 필요): `현재 모델` → `역할별 모델`, `프로바이더와 모델` → `프로바이더·모델 등록`, 채팅 설정의 `모델` → `이 채팅의 모델`. 또는 `현재 모델`을 `프로바이더와 모델`의 첫 탭 "사용 중"으로 합쳐 설정 항목을 7개로 줄여요.

### F6 · 포크가 두 이름이에요 (P7)

채팅 ⋯의 `여기까지 새 채팅으로 복사`와 장면 ⋯의 `여기서 새 이야기로 이어가기`는 둘 다 새 채팅을 만들어요. 명사(채팅/이야기)와 동사(복사/이어가기)가 달라 다른 기능처럼 읽혀요.

제안: 명사는 `채팅`으로 통일하고 범위만 다르게 써요 — `여기까지 새 채팅으로 복사`와 `이 장면까지 새 채팅으로 복사`. 즉시 복사 동작과 복사 뒤 "원본으로 돌아가기" 알림(v2)은 그대로예요.

### F7 · "최신으로" 버튼이 본문 위에 떠 있어요 (P1·P11)

44px 원형 버튼이 `x 330, y 673`에 있고 본문 폭은 `x 20~370`이라 오른쪽 끝 글자를 가려요. 스크롤 위치와 무관하게 첫 화면에도 보여요.

제안: 입력창 바로 위 가운데에 두고, 최신 장면이 화면 밖으로 한 화면 이상 벗어났을 때만 1층(연하게)으로 나타나요. 위치를 가운데로 옮기면 본문 오른쪽을 가리지 않아요.

### F8 · 채팅 설정과 폼이 카드 키트예요 (P6)

데스크톱 채팅 설정 첫 화면에 `소속 봇 · 고정`, `패키지 추가` 두 fieldset 상자가 있고 그 안에 select와 비활성 `패키지 장착` 버튼, 그 아래 스위치 두 개가 이어져요. 상자가 정보를 더하지 않고 여백만 써요.

제안: fieldset 상자를 제목 줄로 바꾸고 테두리는 select·입력·주 버튼에만 남겨요. 반경은 6·10·999px 세 종으로 정리해요(오늘 8·9·10·12px이 각 20곳 이상).

### 잘 맞는 곳

서재의 제목·탭·폴더·검색·목록 구성, 설정과 채팅 설정의 목록→상세 전환, 프로바이더와 프롬프트의 빈 화면(안내 한 줄 + 주 행동 하나), 입력창 ⋯의 페르소나·로어 제외, 장면 헤더 줄과 장면 끝 도구 줄은 위 원칙과 맞아요. 모바일 첫 화면의 본문 비율은 **59%**(239~736px)로 v2 목표 60%에 근접하고, F2·F3를 적용하면 넘어요.

검증(2026-09-10, macOS Edge 152, Node 24, 격리 서버·새 DB): `quality` 통과, Vitest **1,716 PASS / 1 skip**. 라벨·탐색을 쓰는 브라우저 spec 21개 파일을 두 묶음으로 직접 실행해 **108 PASS / 8 FAIL**이었고, 실패 8건을 단독 재실행과 main `ca8d4d6` 격리 내보내기 A/B로 나눴어요. `LOADUI02`는 main에서도 같은 자리(390px에서 장면 ⋯ 시트를 연 뒤 도구 줄 연필을 누름)에서 실패하는 1~2단계의 기존 검사 결함이라 spec을 연필 직접 클릭으로 고쳐 통과했어요. `GMUI01 1440`·`P01`·`PMUI11`·`UI01`·`OUTUI04 390`은 묶음 안에서만 시간 초과이고 단독 실행은 두 트리 모두 통과예요(같은 시간대에 검사 효율화 세션의 갤러리 캡처가 겹쳐 돌았어요). `CSUI04`·`P09`는 두 트리 모두 같은 이유(기존 환경 결함·이미지 선택 loopback 픽스처 필요)로 실패해요. 새 `ORG08` 두 폭과 고친 `ORG01`·`ORG03`·`ORG05`·`DEL` 행 조작은 통과했어요. 전체 `verify:redesign`과 Windows CI는 돌리지 않았어요.

측정: 채팅 행 상시 버튼 **3 → 1개**(⋯), 드로어 첫 줄 제어 **1 → 3개**(새 채팅·전체 채팅 검색·닫기), 새 채팅까지 드로어에서 **2번**(새 채팅 → 서재 봇 행의 새 채팅). 설정·채팅 설정에서 "모델" 단독 라벨은 봇 편집기의 자료 모델 탭만 남아요.
## 5. 이번 검토의 한계

- 합성 자료·다크 테마·모델 미등록 상태만 봤어요. 모델이 있을 때의 헤더 칩 길이, 라이트 테마의 대비, 진행 중·실패 상태의 dock 높이는 측정하지 않았어요.
- 뷰포트는 390×844와 1440×900 두 개예요. 360·430·768·1024는 v2 후속 3의 결과를 그대로 신뢰해요.
- 검사 효율화 세션의 갤러리(커밋 06817a5)가 3~4단계 뒤에 본 후속 두 가지는 5단계에 넘겨요: 390px에서 `최신 장면으로`가 가운데로 옮겨진 뒤에도 본문 마지막 줄 글자를 덮어요(F7의 "한 화면 이상 벗어났을 때만 표시" 조건은 아직 미적용). 포크 직후 `원본으로 돌아가기` 안내가 입력창 dock을 109px(390)·117px(1440)로 밀고 안내 글자가 10~11px이에요(11px 이하 0곳 목표 위반).
- 외부 원칙은 2026-09-10에 읽은 공개 문서 기준이에요. Apps SDK 문서는 일부 경로가 plugins 문서로 이동 중이라 링크가 바뀔 수 있어요.
- 1~4단계는 구현·합성 검증까지이고 실기기 확인 전이에요. 5단계(F8·스타일 토큰)는 남아 있어요. [UI 설계 v2](UI-DESIGN-V2.md)의 드로어·장면 ⋯ 절과 [서재 문서](LIBRARY.md#사이드바의-봇-트리)·[사용 안내](USAGE.md)는 3~4단계 이름에 맞춰 고쳤어요.

# Risu 콘텐츠와 Uimori 저장 정보

봇·페르소나·모듈은 Risu 원문을 기준으로 저장·편집·실행해요. 카드의 description, first_mes, alternate_greetings, character_book, 확장 필드와 모듈의 lorebook, regex, trigger를 보존해요. CBS·Lua·정규식·HTML/CSS는 원래 표현으로 실행하며 별도 Uimori 문법으로 변환하지 않아요.

Uimori 저장 정보에는 ID·개정, 원본 파일 영수증, 이미지 바이트와 원래 에셋 이름의 연결, 공통 모듈 참조가 들어가요. 본문·로어·시작문·기본 변수 등의 필드는 서재와 모델 문맥을 위한 원문의 투영이에요. 저장과 가져오기는 같은 함수로 원문에서 다시 계산하며 투영 필드를 독립적으로 편집하지 않아요.

## 실행과 상태

채팅에는 정확한 콘텐츠 ID·개정·역할을 연결해요. 실행 예약은 원문, 변수, 대화, 모델과 프롬프트를 고정해요. 서버의 네이티브 런타임이 CBS·정규식·Lua를 실행하고 그 결과를 해당 실행에 저장해요. 이후 프롬프트 구성과 복원은 고정된 결과를 사용하며 스크립트나 유료 호출을 자동 반복하지 않아요.

카드 변수는 원본 스크립트가 관리해요. Uimori의 이야기 요약과 메모는 대화에서 발생한 사건을 기억하며 카드 변수의 별도 계산기가 아니에요. 메시지 버튼은 네이티브 동작을 호출하고, HTML/CSS는 격리된 프레임 안에 표시돼요. 자세한 API 지원과 제한은 [Risu 가져오기](RISU-IMPORT.md)를 봐요.

## 로어와 이미지

항상 포함하는 로어와 비활성 여부, 삽입 위치는 원본에서 읽어요. 선택 가능한 로어는 JEV가 현재 문맥·사용자 입력과 관련성을 평가하고 Uimori가 한도 안에서 공급해요. 선택되지 않은 로어도 작문 모델의 조회 도구로 읽을 수 있어요. 생성형 판단 모델이나 키워드 활성화 실행기는 두지 않아요. [로어 문맥](LORE-CONTEXT.md)에 예산과 실패 계약이 있어요.

이미지 이름과 원본 치환 스크립트는 보존해요. 자동 삽화는 설정한 지시의 전달과 이미지 태그 선택을 대신하며, 실제 이미지 박스 렌더링은 카드의 정규식·CSS를 사용해요. 새로운 삽화 생성은 Uimori의 생성기가 담당해요. 라이트보드 전체를 내장하지 않아요. [삽화](ILLUSTRATIONS.md)를 참고해요.

## 저장과 교환

수정은 현재 개정 번호가 맞을 때 새 개정으로 저장해요. 실행 중인 채팅은 예약한 개정과 입력을 유지해요. 전체 원본 및 이미지 이동은 [네이티브 자료 교환](NATIVE-TRANSFER.md), 채팅의 원문·분기·변수·기억 보존은 [채팅 백업](CHAT-BACKUP.md)을 사용해요.

구형 Uimori 콘텐츠 DSL, 프롬프트 AST, 패널·행동 프로그램, 변환기와 해당 데이터의 복원은 지원하지 않아요. 현재 형식과 DB 정책은 [데이터 형식](DATA-MIGRATIONS.md)에 있어요.

## 출처를 보존하는 요청 컨텍스트

봇·페르소나·모듈의 요청 투영은 `risuSource`에 연결 역할·자료 이름·자료 ID를 보존해요. 로어는 항목 ID·제목도 함께 전달해요. 같은 자료를 다른 역할로 연결하거나 여러 자료의 로어 제목이 같아도 출처를 구분하며, 내용의 우선순위나 지식 소유권을 자동으로 정하지 않아요.

이 정보는 저장된 `nativeRisu.card`·`nativeRisu.module`·프리셋 원문에 삽입하지 않아요. 선택된 본문과 출처를 요청 단계에서 조립하며 원본 해시와 내보내기 자료를 바꾸지 않아요. 슬롯·위치 지정·대체 참고 메시지의 직렬화 계약과 검증은 [PROMPT-RUNTIME](PROMPT-RUNTIME.md#출처를-보존하는-요청-컨텍스트)에 있어요.

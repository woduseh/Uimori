# 이야기 가이드

채팅 메뉴의 **이야기 가이드**, 또는 **채팅 설정 → 이야기 가이드**에서 원작 설정과 현재 이야기의 차이를 함께 살펴봐요. 기본은 꺼져 있고, 켜면 현재 본문 모델이 집필 전에 짧은 참고문을 만들어요. 프롬프트 프리셋을 바꿔도 채팅의 가이드 설정은 유지돼요.

## 사용 흐름

1. **작품·세계관**에 작품 이름과 필요한 판본을 적어요. **기준 시점·스포일러 범위**로 참고할 시점을 정하고, 기존 카드·로어에 없는 자료는 **추가 참고 자료**에 덧붙여요.
2. 기본은 원작의 설정·성격과 현재 이야기에서 달라진 선택을 함께 존중해요. 사건의 진행도 참고하고 싶을 때 **원작의 사건 전개도 참고**를 켜요.
3. 설정을 저장하고 평소처럼 집필해요. **마지막 집필 참고문**에서 전달한 분석을 볼 수 있어요. 원작 정보, 현재 이야기의 근거, 앞으로의 제안을 구분하며 인물의 지식과 독자의 지식을 같은 사실로 취급하지 않도록 안내해요.
4. **미리보기 만들기**는 현재 작성 중인 요청으로 분석해요. **원작에 물어보기**는 별도의 질문에 답해요. 빈 질문의 **말투·관계 / 세계관·설정 / 다음 전개**를 누르면 질문 초안을 채워요. 자유롭게 고친 뒤 **질문하기**를 눌러 실행해요. 자동 가이드를 꺼도 둘 다 사용할 수 있어요. 이 답변은 패널에만 표시되며 마지막 집필 참고문이나 이야기를 바꾸지 않아요.
5. 직접 정정할 내용은 같은 패널의 **메모**에 저장해요. 기존 작가 메모를 사용하므로 기억·로어 화면에서도 같은 정정을 볼 수 있어요. 질문이나 모델의 제안을 자동으로 메모에 저장하지 않아요.

처음 열 때는 **가이드 설정**을 펼쳐 보여주고, 설정을 저장한 뒤 다시 열면 접어서 분석과 질문을 바로 사용할 수 있어요. 긴 미리보기도 접을 수 있어요. 원문·참고 자료·메모·설정이나 작성 중인 요청이 바뀌면 이전 수동 분석은 비워요. 질문 입력과 미저장 설정은 유지하며, **마지막 집필 참고문**은 당시 기록으로 따로 보존해요.

원작 전문을 자동으로 내려받거나 웹을 검색하지 않아요. 모델 지식에 의존한 부분은 `모델 지식·원문 미확인`으로 구분하도록 요청해요. 모델이 작성한 분석의 정확성이나 스포일러 준수를 보장하는 검증기는 아니에요.

## 실행과 보관

- 자동 가이드는 준비된 사용자·모델 대화, 현재 요약, 카드·페르소나·로어, 카드의 예시 대화, 작가 메모와 채팅의 작가 노트, 해당 집필의 구성과 요청을 사용해요. 예시 대화는 인물의 말투를 참고하는 자료이며 실제 발생한 사건으로 취급하지 않아요. 이전 참고문을 누적해서 새로운 이야기 기억으로 삼지 않아요. 재생성할 때는 교체할 응답을 제외한 입력을 사용해요.
- 보통 모델 한 번으로 분석해요. 필요한 원문을 읽는 경우 기존 읽기 도구를 한 번 묶어 실행하고 한 번 더 답변받아요. 집필과 거절 판정에 필요한 호출 한도는 남겨둬요. 가이드 호출도 사용량의 **이야기 가이드**에 기록해요.
- 모델의 추론·생성 설정은 그대로 사용하고, 집필에 넣을 참고문 길이는 따로 제한해요. 따라서 실제 분석 시간과 사용량은 선택한 본문 모델의 설정에 따라 달라져요.
- 입력·설정·모델·가이드 프롬프트가 같은 경우에만 저장된 결과를 재사용해요. 추가 원문 읽기를 사용한 결과는 별도 읽기 캐시를 두지 않아 보수적으로 다시 분석해요.
- 기존 대화에 요약이 필요하면 가이드의 입력 공간까지 고려해 한 번에 묶어요. 원래 입력이 충분히 들어가면 가이드만을 위해 추가 요약을 시작하지 않아요. 실제 참고문을 넣은 최종 집필 입력을 다시 측정하며, 가이드 실패나 한도 부족 시 해당 가이드 없이 집필을 이어가요. 이전 참고문을 대신 넣지 않으며 취소는 모델 호출까지 전달해요.
- 채팅에는 설정과 마지막 자동 참고문을 저장하고, 완료된 집필에는 사용한 참고문과 실패 여부만 작은 기록으로 남겨요. 전체 분석 입력과 설정 전문을 매 장면에 계속 복제하지 않아요. 수동 분석은 서버에서 별도 결과나 작업을 저장하지 않아요.
- 채팅 복사와 휴대용 백업은 가이드 **설정만** 옮겨요. 복사한 채팅은 자기 자료로 다시 분석해요. 전체 SQLite 백업에는 기존 참고문도 포함돼요.

수동 미리보기는 카드의 CBS·정규식 읽기용 처리를 사용하지만 Lua 콜백이나 별도 집필 작업은 실행하지 않아요. 실제 집필에서 카드 콜백이 입력을 바꾸면 수동 미리보기와 자동 참고문이 달라질 수 있어요.

## 원작 플러그인에서 가져온 범위

RisuAI용 **원작견 개조판 v3.9.1**의 기능 의도를 다음처럼 적용했어요. 가이드는 아래 내용을 현재 장면에 필요한 만큼만 다루도록 지시하며, 모든 항목을 매번 출력하거나 별도 장부로 저장하지 않아요.

| 원작 플러그인의 기능 | 이야기 가이드에서의 적용 |
| --- | --- |
| 인물별 말투·태도·행동 참고 | 카드의 예시 대화와 현재 관계를 바탕으로 호칭·존댓말/반말·말버릇·행동을 살펴봐요. 제안 대사를 원작 인용이나 실제 발언으로 취급하지 않아요. |
| 장면에 맞는 원작 설정 Q&A | 작품·판본과 현재 장면을 기준으로 필요한 세계관 정보를 골라요. 수동 질문은 관심 있는 부분을 직접 좁힐 수 있어요. |
| OC와 원작 분기의 존중 | 창작 인물·사용자 페르소나·변경 설정을 원작 오류로 교정하지 않아요. 초기 설정과 실제로 일어난 사건도 구분해요. |
| 관계·약속·플레이어 상태의 분기 장부 | 기존 대화·요약·메모로 현재 관계, 동행·소지품·부상, 약속의 조건과 이행·포기 여부를 살펴봐요. 독립 장부를 만들거나 가이드 결과를 기억으로 누적하지 않으므로 원본 장부의 항목별 영구 보존과 동일한 기능은 아니에요. |
| 원작 시점·비밀·세계 상태 | 인물별 앎/오해와 독자의 지식, 현재 비밀과 아직 일어나지 않은 사건을 구분해요. 시간이 지났다는 이유만으로 관계 해결이나 사건 완료를 단정하지 않아요. |
| 다음 원작 사건과 분기 브리핑 | 원작 전개 참고를 켜거나 관련 질문을 하면 사건의 인물·장소·조건과 현재 분기를 비교해 선택지로 제안해요. 스포일러 범위와 해당 집필에 연결된 구성의 공개 시점을 함께 고려해요. 수동 질문에는 구성 대상이 자동으로 연결되지 않아요. |
| 브리핑·수동 정정 | 미리보기와 질문은 읽기 전용으로 제공하고, 사용자가 남긴 정정은 기존 메모에서 관리해요. |

원본의 인물/설정별 다중 호출·2차 모델 검증, 자동 시점 이동·화면 밖 사건 진행, 별도 장부 관리, 질문 이력 누적, 공급자별 검색·PDF·번역 체계는 추가하지 않았어요. 짧은 가이드 한 번과 필요한 로컬 원문 읽기로 범위를 유지해요. 원문을 영구 보존하는 것과 요약에 모든 관계 변화가 빠짐없이 남는 것은 다른 문제이므로, 계속 지켜야 할 조건은 사용자가 메모로 고정할 수 있어요.

## 구현과 검증

`core/story-guide.ts`가 데이터 형식을, `server/story-guide-store.ts`가 채팅별 저장을, `server/story-guide-runtime.ts`가 입력·분석·재사용·사용량을 맡아요. `server/story-guide-routes.ts`는 설정과 취소 가능한 수동 호출을 연결하고, `web/StoryGuidePanel.tsx`에서 사용자 흐름을 제공해요. DB 스키마 15에 작은 테이블을 추가하며 별도의 큐·기억 저장소·검색 인덱스는 만들지 않아요.

`tests/story-guide-*.test.ts`는 실제 저장·복사, API의 데이터 불변·늦은 응답, 입력과 캐시·예산, 합성 HTTP 집필 전달·실패·취소를 확인해요. `tests/chat-settings-browser.spec.ts`의 `CSUI10`은 패널의 설정·미리보기·질문·정정 흐름을 확인해요. 합성 검증은 실제 모델의 원작 지식이나 문학적 품질을 입증하지 않아요.

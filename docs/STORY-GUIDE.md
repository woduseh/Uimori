# 원작 참고

원작 소설·게임·만화의 세계관 설정, 인물의 고유한 말투와 성격, 그리고 현재 이야기에서 달라진 사건 분기를 살펴보고 집필 직전에 짧은 참고문을 전달하는 기능이에요.

채팅 메뉴의 **원작 참고** 또는 **채팅 설정 → 원작 참고**에서 사용할 수 있어요. **집필 전에 원작 참고**는 기본으로 꺼져 있는 선택 기능이에요. 이 설정을 켜면 본문 모델이 집필 전에 참고문을 먼저 작성해 집필 프롬프트에 포함해요. 참고문 작성에는 별도의 모델 호출과 비용이 발생할 수 있어요. 프롬프트 프리셋을 변경하더라도 채팅별 원작 참고 설정은 그대로 유지돼요.

## 설정과 사용 방법

### 1. 참고 설정 입력

패널을 열면 다음 항목을 지정할 수 있어요.

- **작품·판본·세계관**: 참고할 원작 이름과 구체적인 판본(소설판, 코믹스판, 극장판 등)을 적어요.
- **기준 시점·스포일러 범위**: 이야기에서 공개하거나 참고해도 되는 최대 시점을 지정해요. 이 시점 이후의 전개는 미리 드러내지 않도록 요청해요.
- **추가 참고 자료**: 카드나 로어북에 등록되지 않은 추가 설정, 뒷이야기, 특별한 규칙을 덧붙여요.
- **원작의 사건 전개도 참고**: 원작의 원형 사건 진행을 비교하고 다음 전개 선택지로 제안받고 싶을 때 켜요. 현재 이야기의 독자적인 분기를 원작으로 강제 복귀시키는 기능은 아니에요.
- **원작 정보를 웹에서 확인**: 기본값은 꺼져 있어요. 켜면 지원하는 모델 연결(Responses, Claude, Gemini, Vertex, Codex)에 웹 검색을 요청해요. 모델과 계정에 따라 실제 검색 지원 여부가 다르며, 검색 비용이 추가될 수 있어요. 또한 검색 결과 자체에는 설정한 기준 시점 이후의 스포일러가 포함될 수 있어요.
- **메모·정정**: 원작과 달라진 설정이나 이야기 진행 중 반드시 지켜야 할 조건은 패널 하단의 **메모·정정**에 저장해요. 기존 작가 메모와 연동되므로 기억과 메모 화면에서도 같은 정정 사항을 공유해요.

### 2. 집필과 참고문 확인

- **자동 참고문 작성**: 설정을 저장하고 평소처럼 입력창에서 장면 생성을 요청하면, 본문 모델이 먼저 참고문을 작성한 뒤 이를 참고하여 본문을 써요.
- **마지막 집필 참고문**: 패널에서 직전 집필에 실제로 전달된 참고문을 확인할 수 있어요. 원작 정보, 현재 이야기의 근거, 앞으로의 제안을 명확히 구분하며, 인물이 아는 사실과 독자만 아는 지식을 혼동하지 않도록 유도해요. 웹 검색을 사용한 경우 참고한 출처 링크가 표시되며, Google 검색을 거쳤다면 제공된 검색 제안도 함께 보여줘요.
- **패널 동작과 충돌 처리**: 화면을 처음 열 때는 **참고 설정**이 펼쳐져 있고, 설정을 한 번 저장한 뒤 다시 열면 설정은 접히고 **마지막 집필 참고문**을 먼저 보여줘요. 다른 브라우저 탭에서 설정이 바뀌더라도 현재 작성 중인 입력은 보호되며, 충돌 시 기존 저장본을 검토할 수 있어요.
- **도우미 질문**: 원작 설정이나 인물에 관해 직접 묻고 답을 얻고 싶다면 기존 **도우미**를 사용해요. 채팅 도우미는 `context.read`로 동일한 작품·판본, 스포일러 범위, 추가 자료, 메모를 조회할 수 있어요. (원작 참고 전용의 별도 질문 실행이나 미리보기 기능은 제공하지 않아요.)

### 3. 참고 원칙과 범위

RisuAI용 **원작견 개조판 v3.9.1**의 핵심 의도를 Uimori의 단일 사용자 작업실 환경에 맞게 간결하게 반영했어요.

| 참고 대상 | 반영 방식 |
| --- | --- |
| **인물의 말투·태도·행동** | 카드의 예시 대화와 현재 관계를 바탕으로 호칭, 존댓말/반말, 말버릇, 고유 행동을 살펴봐요. 제안된 대사를 원작의 실제 발언으로 단정하지 않아요. |
| **원작 설정·판본** | 지정된 작품과 판본에 부합하는 세계관 정보를 골라요. 서로 다른 미디어 믹스 판본의 설정이 뒤섞이지 않도록 요청해요. |
| **창작 인물과 달라진 이야기** | 창작 캐릭터, 사용자 페르소나, 원작과 달라진 전개를 오류로 취급해 원작대로 교정하지 않아요. |
| **관계·약속·현재 상태** | 기존 대화, 요약, 메모를 종합해 인물 간 호감도, 동행 여부, 부상·소지품 상태, 약속의 이행 여부를 확인해요. 별도 장부를 만들거나 기억으로 누적하지 않아요. |
| **시점·비밀·사건 조건** | 인물별로 알고 있는 사실과 오해, 독자만 아는 정보, 아직 일어나지 않은 사건을 엄격히 구분해요. 시간 경과만으로 사건이 해결되었다고 넘겨짚지 않아요. |
| **다음 전개** | 사건 전개 참고가 켜져 있으면 필요한 조건과 현재 분기를 비교해 선택지를 제안해요. 스포일러 범위와 연결된 구성 단위의 공개 시점을 함께 존중해요. |

원작 전문을 자동으로 다운로드하거나 웹 문서를 무단 수집하지 않아요. 웹 검색이 꺼져 있으면 모델이 자체 지식에 기반한 내용임을 명시하도록 유도하며, 검색을 켠 경우에도 출처가 확보된 정보만 본문 생성에 전달해요.

## 구현 참고

### 실행 파이프라인과 캐시 정책

- **컨텍스트 구성**: 자동 참고문 생성에는 사용자·모델 대화, 현재 요약, 캐릭터 카드·페르소나·로어북, 카드의 예시 대화, 작가 메모와 작가 노트, 해당 집필의 계층형 구성 및 요청문이 전달돼요. 카드의 예시 대화는 어조 참고 자료로만 사용하며 실제 발생한 사실로 취급하지 않아요. 재생성 시에는 교체 대상 응답을 제외한 입력을 전달해요.
- **호출 구조**: 일반적으로 1회의 모델 호출로 참고문을 완성해요. 추가 원문 확인이 필요한 경우에 한해 기존 읽기 도구를 1회 묶어 실행한 뒤 최종 답변을 받아요. 본문 집필과 거절 감지에 필요한 실행 호출 한도를 보장해요. 참고문 생성 호출은 사용량 화면의 원작 참고 항목에 기록돼요.
- **캐시 재사용 조건**: 입력 컨텍스트, 설정값, 모델, 참고 프롬프트가 완전히 일치할 때만 저장된 참고문 결과를 재사용해요. 추가 원문을 읽어서 작성된 결과는 재사용하지 않고 매번 새로 검토해요.
- **입력 예산과 요약**: 대화 이력에 컨텍스트 요약이 필요한 경우, 참고문이 차지할 토큰 예산까지 고려해 한 번에 묶어 요약을 진행해요. 원래 입력 공간이 충분하다면 참고문만을 위해 불필요한 추가 요약을 하지 않아요. 참고문 생성에 실패하거나 입력 한도가 부족하면 참고문 없이 본문 생성을 이어가며, 이전 참고문을 임의로 끼워 넣지 않아요. 취소 요청은 모델 호출까지 즉시 전달돼요.
- **기록 소유권**: **마지막 집필 참고문**은 단순 생성 캐시가 아니라 실제 본문 모델 호출의 최종 입력에 포함된 기록을 기준으로 표시해요. 참고문 생성 후 본문 호출 전에 취소하거나 요청 수정에서 참고문을 제외하면 직전 집필의 참고문 기록을 유지해요.

### 코드 구조와 DB 스키마

- **코드 매핑**:
  - `core/story-guide.ts`: 데이터 인터페이스 및 유효성 검증
  - `server/story-guide-store.ts`: 채팅별 설정 및 마지막 참고문 영속화
  - `server/story-guide-runtime.ts`: 프롬프트 구성, 실행, 캐시, 사용량 기록
  - `server/story-guide-routes.ts`: 설정 조회·저장 및 마지막 참고문 조회 API
  - `web/StoryGuidePanel.tsx`: 원작 참고 설정, 당시 참고문, 메모·정정 UI
  - `server/helper-context.ts`: 채팅 도우미에 원작 참고 설정 제공
- **데이터베이스 계약**:
  - SQLite 스키마 버전 15의 테이블을 사용해요.
  - 별도의 작업 큐 테이블, 장기 기억 저장소, 전문 검색 인덱스는 두지 않으며 채팅 레코드에 종속된 가벼운 메타데이터로 관리해요.
- **복사와 백업**:
  - 독립 채팅 복사와 휴대용 채팅 백업은 원작 참고 **설정만** 복제해요. 복사된 새 채팅은 자체 컨텍스트로 새로 참고문을 작성해요.
  - 전체 SQLite 데이터베이스 백업에는 기존에 생성된 참고문과 이력이 모두 포함돼요.

### 검증 테스트

- `tests/story-guide-*.test.ts`: 설정 저장 및 복사, 동시 저장 충돌, 지원 종료된 수동 API의 모델 호출 방지, 도우미의 동일 설정 읽기, 입력 토큰 예산 및 캐시, 합성 HTTP 집필 전달·실패·취소 계약을 검증해요.
- `tests/chat-settings-browser.spec.ts` (`CSUI10`): 설정 변경, 당시 참고문 렌더링, 메모·정정 연동 화면 흐름을 브라우저 환경에서 검증해요.
- 합성 테스트로 시스템 파이프라인의 동작을 확인해요.

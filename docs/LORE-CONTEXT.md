# 로어 선별과 현재 문맥 유지

카드·모듈의 Risu 원문이 작성 기준이에요. 고정 로어는 매 요청에 제공하고, 선택 로어는 JEV로 선별하거나 작문 모델이 읽기 도구로 조회해요. 자료를 탐색하는 화면의 폴더 순서와 실제 프롬프트 배치는 구분해요.

## 포함과 배치

`loading: pinned`인 항목은 본문을 제공하고 `discoverable`인 항목은 목록에서 찾거나 `knowledge.read`로 읽어요. `loreContext.placement`의 `background`와 `scene`은 고정 자료의 배치를 정해요. 생략하면 배경이에요. 같은 패키지·부착 역할 안에서 그룹은 등장 순서, 그룹 안 항목은 `order` 오름차순으로 정렬해요. 같은 값이면 원래 배열 순서를 유지해요.

Risu 프리셋의 `promptTemplate`이 캐릭터·페르소나·로어·대화의 역할과 순서를 정해요. Uimori는 실제 출력에 사용자 메모·구성·보존한 조회 구간을 연결해요. 별도의 Uimori 슬롯 언어로 원문을 바꾸지 않아요.

모델에게 제공하는 목록은 ID·revision·종류·제목·짧은 설명 중심이에요. 본문을 이미 제공한 고정 자료를 목록에서 다시 크게 반복하지 않아요. 목록 예산 때문에 생략된 항목은 `knowledge.search`로 찾을 수 있어요.

## JEV 사전 선별

`loreActivation.mode: model`은 JEV 사전 선별, `discoverable`은 작문 모델의 선택적 조회예요. 상시 포함 항목과 명시적 CBS 조건을 먼저 적용해요. 키워드 문자열은 원본 데이터로 보존하되 별도의 키워드 활성화 엔진은 두지 않아요.

JEV 키는 **설정 → 프로바이더·모델 → TypeSafe AI**에서 등록해 DB에 저장해요. 관련성 정책은 `threshold`, `maxSelectedTokens`, `maxInputTokens`로 표현해요. 기본값은 관련성 0.65, 선택 본문 8,000토큰, 판단 입력 28,000토큰이에요.

장착 자료의 후보를 묶어 최근 대화와 현재 요청을 함께 보내요. 자료별 로어 ID가 같아도 구분하며 결과를 자료에 연결해요. 관련성 점수가 원본의 명시적 조건이나 배치 순서를 바꾸지는 않아요. 판정 실패 시 다른 생성 모델로 자동 대체하거나 유료 요청을 무조건 재시도하지 않고 작문 모델의 조회 대상으로 남겨요.

선별 결과는 해당 실행 중에 고정해요. 완료 후에는 과거 판정 요청·입력 해시·호출 영수증을 통째로 백업해 재생하지 않아요. 독립 채팅 사본에서 새 생성은 현재 자료와 필요한 선별을 사용해요. 실제 관련성 품질과 공급자 지연은 합성 테스트의 보장 범위가 아니에요.

## 읽은 구간 유지

`knowledge.read`는 항상 `ids` 배열을 받고 한 번에 최대 16개 ID를 읽어요. 하나만 읽을 때도 `ids: [id]`를 사용하며 각 항목은 최대 4,096자예요. 항목별 성공·오류와 `nextOffset`을 독립적으로 반환하고 조회 범위는 UTF-16 단위예요.

성공한 본문 실행에서 실제로 읽은 로어 구간만 다음 요청의 참고 자료로 유지해요. 검색 결과, 실패한 읽기, 읽지 않은 나머지 본문, 보조 역할의 읽기는 포함하지 않아요. `story.read`와 `skills.load`는 이 로어 유지 기능의 대상이 아니에요. 사용자 메모는 별도 읽기 도구가 아니라 유효한 메모 전체를 host context로 제공해요.

상태는 **채팅 분기별 최신 `chat_lore_state` 한 개**로 보관해요. 다음 요청에 필요한 문맥과 읽은 구간은 남기되 전체 모델 입력·tool event를 영구 이력으로 쌓지 않아요. 기존 구간은 유지하고 겹치지 않는 새 구간을 더해요. 읽은 텍스트를 매 턴 다시 요약하는 모델 호출은 없어요.

참고 자료는 처음 읽은 원문 근처에 별도 사용자 역할 메시지로 배치해요. 원래 위치가 요약으로 정리됐으면 요약 뒤·최근 대화 앞에 둬요. 실제 대화 메시지나 새 도구 호출을 조작하는 방식은 아니에요.

## 예산과 초기화

**채팅 설정 → 기억·로어**에서 고정 자료와 조회 자료의 예산을 조절해요. 기본 조회 유지 예산은 16,000토큰·64구간, 고정 자료는 64,000토큰이에요. 이는 본문 예산이며 도구 선언·메시지 포맷까지 포함한 최종 요청 한도와 달라요.

로컬 `o200k_base` 기반 계산을 사용해요. 텍스트 조각의 계산 결과는 제한된 캐시에 재사용하고 원격 토큰 계산을 호출하지 않아요. 다른 모델의 실제 과금 토큰과 정확히 같다는 보장은 없어요. 토큰 계산을 위해 원문을 수정하거나 CBS·Lua를 별도로 실행하지 않아요.

조회 예산을 넘으면 오래 사용하지 않은 구간을 제외해요. 제외한 구간은 과거 모든 실행 기록을 재탐색해 복원하지 않으며 모델이 다시 읽으면 새 읽기로 포함돼요. 고정 입력 자체가 너무 크면 `LORE_PINNED_BUDGET_EXCEEDED`로 알려요. 전체 입력 planner와의 순서는 [입력 한도](CONTEXT-LIMITS.md)를 참고해요.

입력창 **더보기 → 다음 생성에서 조회 로어 제외**는 이번 요청의 이전 조회 문맥을 비워요. 새 장면에서 다시 읽은 구간은 이후 유지할 수 있어요. 이 선택을 해석하는 별도 장면 판정 모델은 없어요.

## 무효화·복원·검사

새 요청은 현재 자료 ID·revision·본문 hash와 실제 원문·메모를 확인해요. 자료 수정·첨부 해제는 영향을 받는 구간을 제외하고, 읽기 당시의 원문 또는 선행 원문·메모가 바뀌면 그 문맥에서 얻은 조회 결과를 무효화해요. 조회 자료가 고정 자료로 바뀌면 이중 제공하지 않아요.

개별 채팅 백업은 사용자 원문·메모·현재 변수·채팅 전용 로어를 보존해 이어 쓸 수 있게 해요. 과거 모든 선별/조회 기록을 보존하는 아카이브는 아니며 새 사본에서는 필요한 문맥을 다시 구성해요. 전체 DB 스냅샷은 현재 DB 상태를 함께 보관해요. [실행 입력 수명](EXECUTION.md)

구현은 [선택·유지](../server/lore-context.ts), [현재 상태 저장](../server/lore-retention-state.ts), [범위·배치](../core/lore-context.ts), [요청 조립](../server/prompt-snapshot.ts)에 있어요. `tests/lore-context.test.ts`는 읽은 구간·무효화·예산·실제 다음 요청을 검사하고, `tests/lore-token-selection.test.ts`는 토큰 계산과 JEV 선별을 검사해요.

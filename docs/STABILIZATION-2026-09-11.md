# 안정화 결정 · 2026-09-11

`eebbf5933562402550c23097e763ef01fbc277a0`의 두 분석 뒤 사용자가 확정한 후속 범위예요. 이 문서는 결정과 실행 경계를 소유하며, 구현·검증 결과는 완료한 증거만 추가해요.

## 이번 범위

- 명확한 사용자 요청에 한정한 도우미 수정·저장 권한, 본문 보존과 백업 왕복, 업무 오류에 맞는 복구 안내를 바로잡아요.
- 대용량 가져오기의 저장량·지연을 측정하고, 문맥 한도 초과·응답 EOF와 저장 효과를 구분하며 이미 완료된 변경을 중복 실행하지 않아요.
- 반복 압축 뒤 발언자·관계·약속·조건·사용자 정정을 보존하고 원문으로 오류를 정정하는지 재평가해요. 새 조회 도구의 실제 효율도 같은 범위에서 관찰해요.
- 채팅 목록의 늦은 응답, 긴 입력을 다시 줄였을 때의 공통 입력창, 최신 이동과 관련 용어·현행 문서를 정리해요.

## 채팅 백업과 본문 복사

- **본문 복사**는 특정 응답 하나의 텍스트를 클립보드에 복사해요.
- **채팅 내보내기**는 해당 채팅의 모든 분기와 복원에 필요한 자료·설정·이미지·이력을 함께 보관해요. 한 분기의 본문만 담는 기존 transcript를 완전 백업이라고 부르지 않아요.
- 가져오기는 기존 채팅을 덮어쓰지 않고 새 채팅을 만들어요. 사용자는 같은 백업을 반복해서 새 채팅으로 복제하는 범위까지 선택했어요. 확정된 원문·효과를 다시 생성하거나 미완료 외부 요청을 자동 재전송하지 않아요. 같은 요청 키의 통신 재시도는 기존 복원 결과를 반환해요.
- 백업 형식과 버전은 **DB 스키마와 독립**이에요. 앞으로 읽을 수 있도록 관리하되, 개발 단계에서는 형식 자체의 개편과 호환 범위 변경을 허용해요. 이는 모든 개발 버전의 영구 호환이나 구형 DB 이관을 약속하는 것이 아니에요.
- 지원하지 않는 형식·버전은 명확히 거절해요. 복원 성공으로 처리한 데이터는 조용히 누락하거나 잘라내지 않아요.

## 최신 이동

플로팅 최신 이동은 마지막 장면의 시작이 아니라 **본문 맨 아래**로 이동해요. 실제 스크롤 거리를 기준으로 표시하고, 사용자가 위를 읽는 동안 새 응답이 사용자를 강제로 끌어내리지 않아요.

## 실모델 실행 승인

2026-09-11 추가 확인으로 입력·출력 토큰, 호출 횟수, timeout, 요약 기준 등 통상적인 하네스 설정은 개발·검증 중 필요하면 에이전트가 판단해 조정해요. 개발 중 정한 값을 고정된 사용자 요구로 다루지 않으며, 변경 이유와 적용 범위·결과를 기록해요. 이번 16,384 입력 한도는 반복 요약을 보기 위한 평가용 설정이고, 등록된 두 모델은 별도 입력 한도가 없어 현재 앱 기본값 272,000을 사용해요. 집중 회귀에서는 같은 기준 자료의 16k와 32k 사례를 구분해 확인해요.

이번 새 평가에 **로컬에 등록된 Gemini 계열 모델과 신규 총예산 $100**을 사용하도록 사용자가 승인했어요. 2026-09-10 이전 평가의 예산과 합치지 않아요. 이번 안정화 평가 안의 R1부터 R4까지는 같은 승인 장부를 공유하며 앞선 실행의 예약을 차감한 나머지 한도로 진행해요. 모델·연결·단가는 실행 전에 확인하고, 독립 DB의 공개 원문·합성 사실을 사용해요. 사용자 작품·원본 CharX는 평가 데이터에 넣지 않아요. 전송 전 attempt, 작업별 호출·출력·취소 한도, 불확실 요청의 자동 재전송 금지와 비용 상한을 유지해요. 로컬 검증과 실모델 결과를 따로 기록하며 실패·중단을 PASS로 바꾸지 않아요.

# Risu 네이티브 개편 작업 계획

## 합의한 제품 방향

- CHARX의 카드·내장 모듈·CBS·정규식·Lua·구조화 트리거·HTML/CSS·배경을 원형으로 저장하고 실행한다. 자체 행동/템플릿 DSL로의 변환을 신규 카드의 필수 경로로 삼지 않는다.
- 봇 본문, 첫 화면, 버튼, 이미지, 채팅 동작은 Risu의 의미를 보존한다. 서재·설정·편집기는 Uimori에 맞춘다. 앱 전체 테마 커스텀은 후속이다.
- 완료 기준은 같은 선택 화면과 버튼·상태창·이미지를 사용할 수 있고 선택 결과가 다음 대화에 이어지는 것이다. 내부 렌더링 순서를 전부 복제할 필요는 없다. 청원고의 설정 중 `Calendar Date Error`는 원본 카드의 상태 표시이며 Uimori 오류로 세지 않는다.
- RISUP의 프롬프트 구성·CBS·토글·기본 변수·정규식은 보존하되 모델·연결·자격 증명·실행 매개변수는 Uimori가 관리한다.
- 카드 변수와 이벤트는 카드 스크립트가 관리한다. Uimori 기억은 Hypa v3을 대신해 해당 채팅/분기의 이야기 전개를 요약하고 조회한다.
- 상시 로어, 명시적 조건, 위치·순서는 보존한다. 선택 로어의 키워드 매칭은 관련성 선별로 대체하고 누락 자료를 작문 모델이 한 번에 보충 조회할 수 있게 한다. JEV는 선택적인 판단 백엔드다.
- 기존 이미지 자동 배치는 이미지 태그 작성 지시와 태그 선택·삽입을 대신한다. 카드의 이미지 제약과 기존 표시 정규식·CSS는 보존한다.
- 새 이미지 생성은 Uimori 자체 삽화 생성기가 담당한다. 라이트보드 삽화는 기능 참고 사례이며 라이트보드 내장이나 의존성 도입을 요구하지 않는다.
- Lua의 기존 모델 호출은 자동 변환하지 않는다. 가져오기에서 판단/이미지 기능의 대체 후보를 안내할 수 있다. JEV는 자유문·이미지 생성 자체를 대체하지 않는다.
- 오래된 변환 코드는 실행 경로가 대체되면 제거한다. 기존 채팅·분기·자료·백업의 읽기와 복원은 유지한다.

## 실행 순서와 완료 기준

1. **네이티브 자료와 실행 기반** — 원본 카드/모듈과 에셋을 저장하고, 격리된 CBS/정규식/Lua/V2 실행 및 HTML/CSS 표시를 연결한다. 기존 변환 경로와 중복 실행하지 않는다.
2. **첫 화면부터 대화까지** — Cheongwon High School, Harper, Fujimiya Hinano의 실제 카드로 첫 화면, 선택 버튼, 상태·메시지 변경, 다음 턴, 새로고침, 분기 격리를 확인한다. 일반 채팅·기존 자료 경로도 회귀 검사한다.
3. **프롬프트와 기억** — RISUP를 프롬프트 전용 네이티브 원본으로 편집·실행하고 Uimori 모델 설정을 보존한다. 카드 상태와 이야기 기억의 소유 경계를 유지한다.
4. **로어와 판단** — 스크립트 실행 뒤의 상태로 선별하고 상시/조건 로어를 보존한다. 중복 조회 지시를 제거하고 다건 보충 조회를 제공한다. JEV 연결·번역 거절 분류는 후보 보존·취소·사용량 계약을 따른다.
5. **이미지 역할 이관** — 태그 선택·위치를 Uimori가 맡고 원작의 표시를 재사용한다. 삽화 생성기는 독립적으로 발전시킨다. 본문 모델과 보조 기능의 중복 호출을 피한다.
6. **정리와 검증** — 더 이상 쓰지 않는 변환 경로/편집 표면을 제거하고 소유 문서를 갱신한다. 변경 영향에 맞는 타입·단위·통합·브라우저 검증을 마친 뒤 로컬 커밋한다.

## 검증 구분

- 실제 카드 원본은 사용자 소유 로컬 파일로 읽으며 저장소에 복제하거나 수정하지 않는다. 합성 fixture는 재현 가능한 최소 동작을 검사한다.
- 정적 import/render 검사, 격리된 스크립트 실행, 브라우저 동작, 실제 공급자 호출과 창작 품질을 구분해서 기록한다.
- 도입문 버튼과 표시만으로 전체 카드 호환을 주장하지 않는다. 미지원 API는 명시적 오류로 드러내며 빈 성공으로 처리하지 않는다.
- 운영 데이터 변경·배포·원격 push는 이번 로컬 구현 작업에 포함하지 않는다.

## 진행 기록

- 시작 기준: `main@531195a`, 깨끗한 작업 트리. 작업 브랜치: `codex/risu-native-runtime`.
- 원형 import, 실행 worker, CBS/표시의 독립 구현을 분담하고 호스트의 저장·API·채팅 연결은 함께 통합한다.
- 원형 import, 256 MiB native transfer, 기본 도입문 자동 생성과 idempotency를 구현했다. 사용자 소유 Harper를 포함한 세 CHARX의 실제 자료 준비와 native export/reimport/archive 복원을 집중 검증했다.
- 원본 CBS/정규식과 격리 HTML/CSS iframe, Lua/V2 및 지속 VM을 구현했다. 실제 세 카드의 첫 화면/선택 함수를 정적 렌더·격리 실행한 뒤, 앱 전체의 가져오기→선택→분기→모의 작문→새로고침 브라우저 경로도 통과했다.
- 서버 카드 action의 분기별 변수/CAS/idempotency, 메시지 변경의 copy-on-write, 새로고침 표시를 연결했다. 입력/선택 대화상자는 동일 Lua 호출을 기다렸다가 재개하며 중복 응답을 거절한다.
- 카드 입력→프롬프트 필드 평가→출력 콜백→변수 저장 경로를 연결했다. 원본과 실행 receipt를 분리했고, native callback이 바꾼 대화는 해당 분기의 논리 대화에 투영한다. 백업·포크·후보·기억 무효화 회귀를 확인했다.
- RISUP 원본 프롬프트/토글/정규식의 편집·실행을 구현했다. 모델 설정은 기존 Uimori workspace가 유지한다. native 카드 편집은 저장 때 원본으로부터 라이브러리 표시 필드를 다시 계산한다.
- 선택적 JEV 로어 판단과 다건 보충 조회, 번역 거절 판단, 이미지 지시 이관·표시를 구현하고 모의 transport/저장 회귀를 확인했다.
- 실제 카드 확인 중 Cheongwon의 일부 장면 이미지가 외부 CWHA 모듈을 참조하며 제공된 CHARX에는 포함되지 않은 것을 확인했다. 없는 에셋을 임의 대체하거나 전체 호환 성공으로 취급하지 않는다.

## 통합 구현과 검증 범위

- 기본 CHARX 시작문부터 원본 HTML/CSS·CBS·Lua/V2 버튼을 사용하는 경로를 연결했다. Risu처럼 Markdown의 들여쓰기 코드 블록을 끄고 명시적인 fenced code는 유지한다. 선택 후 새 표시 리비전이 준비될 때까지 버튼을 잠그며, 변경된 분기에서 오래된 Reader 커서는 현재 자료로 다시 연결한다.
- 입력·전체 전송 메시지 편집·출력 콜백을 서버 Run에 연결했다. 추가 Lua 모델 호출은 기존 호출 예산·사용량·취소 기록을 사용한다. 백업·복원·분기·응답 후보가 불확실한 외부 호출을 재실행하지 않도록 검사한다.
- JEV 로어 선별은 장착 자료 후보를 한 요청에 모아 평가한다. 추가 읽기도 여러 ID를 한 번에 받을 수 있다. 번역 거절 판정은 선택적 JEV로 연결했고, 불확실한 판정에서 번역 후보를 버리지 않는다.
- 원본 이미지 지시의 범위를 작문 입력에서 선택 모델로 이관하고 CBS 조건·복장 제약을 유지한다. 정확한 에셋으로 연결되는 원본 태그·정규식·이미지 상자를 재사용한다. Uimori의 기존 생성 큐는 독립적으로 사용하며 Lightboard를 내장하지 않는다.
- 새 자료에 필요 없어진 변환기를 제거했다. 이전 저장 자료의 wrapper·CBS·키워드 활성화·권한·CAS·백업 회귀는 테스트 전용 이전 형식 fixture로 유지한다.
- 지원 범위와 차이는 `docs/RISU-IMPORT.md`에 기록한다. 일부 host 특수 지시/API, 표시 콜백의 지속 local/global 의존, 특수 postEverything 슬롯 위치까지 전면 호환했다고 주장하지 않는다.

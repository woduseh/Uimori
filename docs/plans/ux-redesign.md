# UI/UX와 도우미 하네스 개선 계획

이 문서는 2026-11-21에 작성한 구현 계획이에요. Gemini와 함께 만든 원본 계획(저장소 밖 작업 폴더의 마스터 플랜, UX 감사, 도우미 편집 분석, 독립 검토 보고서)을 코드와 대조해 검토한 뒤, 그 결과를 반영해 다시 쓴 것이에요. 이 문서만 읽고 착수할 수 있게 썼어요. 코드는 아직 바꾸지 않았어요.

계획은 상시 지침이 아니에요. 단계를 마칠 때마다 그 단계 항목을 이 문서에서 지우고, 채택한 규약은 소유 문서로 옮겨요. 마지막 단계가 끝나면 이 파일을 삭제해요.

## 목표와 전제

- **목표**: 장문 읽기와 쓰기에 맞는 차분한 작업 공간을 유지하면서, 실행 과정이 보이고, 도우미가 바꾼 내용을 확인하고 되돌릴 수 있고, 키보드로 빠르게 움직일 수 있게 해요.
- **브라우저**: 데스크톱 Chromium과 Android Edge만 대상으로 해요. Safari와 Firefox용 폴백은 새로 쓰지 않아요.
- **UI 규칙**: [UI-PRINCIPLES](../UI-PRINCIPLES.md)는 앱 전체의 통일감을 지키는 목적만 남기고 줄여요. 이 개정이 0단계이고, 뒤 단계는 개정된 문서를 기준으로 해요.
- **규모**: 단일 사용자 셀프호스팅 앱이에요. 새 테이블, 새 모드, 새 설정은 지금 겪는 문제를 근거로 넣어요.

## 확정된 설계 결정

원본 계획의 D1부터 D11까지를 유지하고, 검토에서 바뀐 부분을 표에 반영했어요.

| ID | 영역 | 결정 |
| --- | --- | --- |
| D1 | 모션과 UI 규칙 | 금지 목록을 이름 붙은 모션 토큰 두세 개로 바꿔요. 범위 값(예: 120–180ms)은 쓰지 않고, 새 값은 토큰을 추가하는 방식으로만 들여요. `prefers-reduced-motion`, 합성 친화 속성 우선, 본문 레이아웃 이동 금지는 유지해요. |
| D2 | 설정 화면 | 풀 페이지로 옮기지 않고 데스크톱 설정 다이얼로그를 넓혀요. 프로바이더 설정의 중첩 모달은 오른쪽 영역 안의 드릴다운으로 펼치고, 테마 설정에 원고 미리보기를 둬요. |
| D3 | 도우미 편집 | 두 가지 모드(바로 적용, 계획)로 해요. 턴 단위 순변경 기록과 인라인 diff, 세 도메인(서재 자료, 장면 원문과 번역, 개요와 작가 노트)의 턴 롤백, 파괴적이거나 대량인 작업의 승인을 넣어요. 영속 제안 세트와 열린 초안으로의 실시간 병합은 하지 않아요. |
| D4 | 전송 키 | 메인과 도우미 입력창이 설정 하나를 따라요. 기본값은 `Enter` 줄바꿈, `Ctrl/Cmd+Enter` 전송이에요. |
| D5 | 단축키와 팔레트 | 고정 프리셋, 전역 켜기와 끄기, 커맨드 팔레트를 넣어요. 사용자 재바인딩 화면은 만들지 않아요(아래 제외 항목 참고). |
| D6 | 데스크톱 작업 공간 | 오른쪽 사이드카에 도우미, 플롯, 창작 옵션 탭을 두고 경계선을 끌어 폭을 바꿔요. 지금의 전체 플롯 작업 공간(왼쪽 플롯, 오른쪽 도우미)은 그대로 둬요. |
| D7 | 읽기 모드 퇴고와 번역 | 본문을 선택하면 작업 막대가 뜨고, 안전한 범위에서 원문과 번역을 그 자리에서 다듬어요. 자동 번역 전환은 사용자가 스크롤, 선택, 편집을 하는 동안에만 미뤄요. |
| D8 | 메인 입력창 | 단계별 실행 상태와 한 줄 활성 컨텍스트 표시를 넣어요. 집필 중 다음 요청 예약은 하지 않아요(아래 제외 항목 참고). |
| D9 | 스트리밍 | 기존 SSE 엔드포인트로 바꾸고, 완성 본문과 같은 렌더러와 글꼴로 흘려 보내고, 메인 리더에 하단 추적 스크롤을 넣어요. 추론 요약 스트리밍은 마지막 단계의 선택 항목이에요. 기본값은 도우미 켜짐, 메인 꺼짐이에요. |
| D10 | 시각 마감 | 포커스 링을 2px로 해요. 화면 폭 기준은 뜻이 같은 것만 합쳐요(4단계 참고). |
| D11 | 도우미 사이드바 | 채팅 사이드바와 같은 규격(글자 탭, 호버 시 메뉴, 한 줄 정렬)으로 맞추고, 읽음 상태를 서버에 저장해요. |

## 지켜야 할 불변식

### 삭제와 보존

도우미가 바꾼 내용의 diff와 턴 체크포인트는 원고와 자료 본문의 새 사본이에요. 지금의 삭제와 보존 경로가 이 사본을 모르면, 사용자가 지운 글이 DB에 남아요.

- 장면 삭제는 그 채팅의 도우미 이벤트에서 인자 미리보기를 지우고 작업 스냅샷을 비워요([scene-deletion.ts](../../server/scene-deletion.ts)). 채팅 삭제와 도우미 대화 삭제는 [chat-deletion.ts](../../server/chat-deletion.ts)와 [helper-workspace.ts](../../server/helper-workspace.ts)가 맡아요.
- 도우미 작업이 끝나면 `releaseCompletedHelperInputs`가 도구 결과와 작업 스냅샷의 본문을 비워요([execution-retention.ts](../../server/execution-retention.ts)). 그래서 diff를 도구 결과나 작업 스냅샷에 얹어 둘 수 없어요. 자기 저장 위치와 수명을 가져야 해요.
- 새로 만드는 변경 기록과 체크포인트는 장면 삭제, 채팅 삭제, 도우미 대화 삭제, 자료 삭제에서 함께 지워져야 해요. 이 네 경로 각각에 "삭제 뒤 본문이 남지 않는다"는 테스트를 둬요.
- 자료를 삭제하면 그 자료의 체크포인트도 바로 지워요. 삭제는 턴 롤백으로 되돌릴 수 없고, 그래서 삭제 앞의 승인 단계가 의미를 가져요.
- 체크포인트 수명은 대화당 최근 15턴, 30일이에요. [DELETION](../DELETION.md)과 [DATA-MIGRATIONS](../DATA-MIGRATIONS.md)에 이 보관 범위를 적어요.
- 진행 표시에 쓰는 대상 이름은 구조화된 대상(종류, ID, 제목)에서 만들어요. 인자 미리보기 문자열을 그대로 보여 주지 않아요.

### 도우미 변경 추적과 롤백

- 변경 기록과 체크포인트는 도구 실행기뿐 아니라 `uimori apply` 셸의 장면 직접 저장 경로([helper-shell.ts](../../server/helper-shell.ts)의 `store.editSource` 호출)도 거쳐야 해요.
- 체크포인트가 참조하는 이미지와 글꼴을 미사용 자료 정리([unused-data.ts](../../server/unused-data.ts), [theme-assets.ts](../../server/theme-assets.ts))의 보존 대상에 넣어요. 지금 두 파일이 되돌리기용 저장본으로 읽는 곳은 `resource_undo`뿐이에요.
- 원문과 번역을 함께 바꾼 턴을 되돌릴 때는 원문을 먼저 복원하고, 새 원문 해시를 기준으로 직전 번역을 다시 저장해요. 번역 삽화 배치는 복원되지 않는다는 점을 화면에 알려요.
- 턴 롤백이 생기면 도우미 되돌리기의 경로는 그것 하나예요. 지금의 "마지막 자료 수정 되돌리기" 바는 턴 롤백으로 대체해요. 편집기의 직전 저장 되돌리기는 사용자 저장용으로 그대로 둬요.
- 패치 매칭은 정확 일치, 줄바꿈 차이 허용, 줄 끝 공백 무시의 세 단계까지만 넓혀요. 따옴표와 대시를 바꿔 맞추는 단계는 문체를 조용히 바꾸므로 넣지 않아요. [helper-resource-editing.ts](../../server/helper-resource-editing.ts)의 기존 대상 결정 로직을 재사용하고, `data.search`가 돌려주는 경로만 패치가 받는 형식으로 맞춰요.
- 열린 편집기의 미저장 입력은 [resource-editor-session.ts](../../web/resource-editor-session.ts)가 단독으로 소유해요. 도우미는 그 입력에 직접 쓰지 않아요.

### 읽기 모드 퇴고

- 원문 퇴고는 원문 해시와 수정 번호로, 번역 퇴고는 최신 번역의 수정 번호, 원문 해시, 표시 중인 번역 본문 해시로 확인한 뒤 저장해요.
- 번역을 고치면 진행 중인 재번역이 취소되고 번역 쪽 삽화 배치가 무효가 돼요([source-editing.ts](../../server/source-editing.ts)의 `editTranslation`). 적용 전에 이 결과를 알려요.
- Risu 표시 화면, 표시용 정규식으로 바뀐 본문, 이야기 UI 블록, 그리고 선택한 글이 원문에서 한 곳으로 정해지지 않는 경우에는 그 자리 퇴고를 하지 않고 도우미에게 묻기나 편집기로 보내요.

### 스트리밍

- [response-stream.ts](../../server/response-stream.ts)의 청크 순번과 오프셋 계약, 클라이언트의 오프셋 검증을 유지해요. 추론 텍스트는 본문과 다른 채널로 보내고 저장하지 않아요.
- 스트리밍 표시는 완성 본문과 같은 컴파일러([reading-markdown.ts](../../core/reading-markdown.ts)의 `compileReadingMarkdown`)를 써요. 두 번째 마크다운 렌더러를 만들지 않아요.
- 인증 실패(401, 403)는 종료, 404는 작업 상태를 확인한 뒤 판단하는 지금의 구분을 유지해요.

### 화면과 테마

- 사용자 테마가 쓰는 공식 표식(`data-uimori-part` 등, [THEME-AUTHORING](../THEME-AUTHORING.md))과 저작 콘텐츠 경계를 유지해요.
- 다이얼로그에 `transform`이나 `will-change`를 남겨 두지 않아요. 다이얼로그 안의 메뉴가 `position: fixed`로 배치돼서 위치가 틀어져요. 진입 애니메이션이 끝나면 `transform`이 `none`이어야 해요.
- 초안, 선택, 읽기 위치, 포커스 보존과 늦게 온 응답 무시, 결과가 불확실한 쓰기 처리는 UI 규칙을 줄여도 남는 계약이에요.

## 단계

원본의 Wave 1을 0단계에서 4단계로 나눴어요. 각 단계의 항목은 서로 독립이면 따로 커밋해요.

### 0단계. UI 규칙 개정

동작은 바꾸지 않고 문서와 토큰 정의만 바꿔요.

- [UI-PRINCIPLES](../UI-PRINCIPLES.md)를 세 부분으로 다시 써요. 통일 수단(간격, 모서리, 색, 모션 토큰과 공용 컨트롤), 유지할 계약(위 불변식의 화면 계약, 로딩과 빈 상태와 실패의 구분, 접근성 이름과 터치 영역), 한국어 용어예요.
- 개별 화면의 배치를 정한 문단은 그 내용을 담고 있는 컴포넌트나 테스트를 찾은 뒤에 지워요. 담고 있는 곳이 없으면 남겨요.
- 이 계획이 뒤집는 규약을 문서에서 고쳐요: 메뉴와 다이얼로그 즉시 열림, 0.5px 포커스 외곽선, 도우미 입력창의 하드웨어 키보드 `Enter` 전송, 지난 결과에 diff와 줄 단위 되돌리기를 두지 않는다는 문장.
- [모션 스킬](../../.agents/skills/uimori-motion/SKILL.md)의 표와 제약을 토큰 기준으로 고치고, [DEVELOPMENT](../DEVELOPMENT.md)의 공용 컨트롤 모션 문단을 맞춰요.
- [style.css](../../web/style.css)에 모션 토큰을 정의해요. 적용은 4단계에서 해요.

완료 기준: 개정된 문서가 위 결정 표와 모순되지 않아요. `node scripts/check-documentation.mjs`가 통과해요. 화면 동작과 기존 테스트 결과는 그대로예요. 개정 초안은 사용자가 확인한 뒤 확정해요.

### 1단계. 유실 방지와 전송 키

- 원고 편집기에서 `Esc`를 누르면 변경이 있을 때 폐기 확인을 보여 줘요. 변경이 없으면 지금처럼 닫아요. 취소 버튼의 동작은 그대로 둬요.
- 선택 구절 퇴고 입력창의 `Esc`는 퇴고 패널만 닫고(요청 중이면 요청 취소) 편집기로 전파하지 않아요. 지금은 [SelectionRevision.tsx](../../web/SelectionRevision.tsx)에 키 처리가 없어서 [SourceReader.tsx](../../web/SourceReader.tsx)의 편집기 form이 받아 장면 초안을 지워요.
- 요청 편집기([RequestMessage.tsx](../../web/RequestMessage.tsx))의 `Esc`가 같은 유실을 일으키는지 확인하고, 그렇다면 같은 규칙을 적용해요.
- 도우미 입력창이 데스크톱에서 설정을 무시하고 `Enter`로 전송하는 부분([HelperPanel.tsx](../../web/HelperPanel.tsx)의 `hardwareKeyboard`)을 없애고 앱 설정을 따르게 해요. macOS에서는 `Cmd` 표기를 써요. 한글 조합 가드는 [ChatComposer.tsx](../../web/ChatComposer.tsx)의 것을 함께 써요.
- [HelperResourceUndo.tsx](../../web/HelperResourceUndo.tsx)에서 도달하지 않는 분기만 정리해요. 되돌릴 수 있을 때만 바를 보이는 동작은 2026-11-19 커밋 `1208b41d`의 결정이고 [EDITING](../EDITING.md)에 적혀 있으므로 바꾸지 않아요. 되돌릴 수 없는 사유 표시는 7단계에서 턴 롤백과 함께 정해요.

완료 기준: 변경이 있는 편집기에서 `Esc`를 누르고 폐기를 취소하면 초안과 세션 보관본이 남아요. 퇴고 입력창에서 `Esc`를 눌러도 장면 초안이 남아요. 설정이 수정키 전송일 때 데스크톱 도우미에서 `Enter`는 줄바꿈이고, 한글 조합 중 `Enter`는 전송하지 않아요. 전송 키를 설명하는 사용자 문서가 맞춰져 있어요.

### 2단계. 스트리밍 코어

- [StreamingResponse.tsx](../../web/StreamingResponse.tsx)의 300ms 폴링을 기존 SSE 엔드포인트(`/api/response-streams/:taskKind/:taskId/events`)를 읽는 `fetch` 스트림으로 바꿔요. 커서 이어받기, 탭이 숨겨졌을 때 연결 해제, 오프셋 검증은 지금 동작을 유지해요.
- 스트리밍 중인 글을 완성 본문과 같은 글꼴과 줄 간격으로 보여 줘요. 끝난 문단은 완성 본문과 같은 컴파일러로 렌더하고, 쓰는 중인 마지막 문단만 일반 글로 둬요. 닫히지 않은 코드 펜스와 이야기 UI 블록은 끝난 문단으로 치지 않아요.
- 표시용 정규식을 쓰는 Risu 채팅은 완성 시 화면이 달라지는 것이 정상이라 "완료 시 이동 없음" 기준에서 빼요.
- 메인 리더에 하단 추적 스크롤을 넣어요. 도우미 패널의 추적 로직을 공용으로 뽑아 함께 써요. 사용자가 위로 올리면 멈추고 하단으로 돌아오면 다시 따라가요.
- 메인 실행의 단계(컨텍스트 정리, 로어 선별, 원작 참고, 본문 작성)를 기존 `run.context.updated` 이벤트로 보여 줘요.
- 도우미 활동 조회([helper-activity.ts](../../server/helper-activity.ts))에 `tool.started`와 대상 이름을 넣고, 클라이언트의 도구 분류에서 빠진 도구를 채워요.

완료 기준: 일반 채팅에서 완료 전후로 이미 보이던 문단의 위치와 글꼴 계산값이 같아요(브라우저 테스트). 탭을 숨겼다가 돌아오면 중복이나 누락 없이 이어져요. 끝난 도우미 작업의 활동 표시가 보존 정책이 비운 값을 다시 보여 주지 않아요.

### 3단계. 단축키와 팔레트

- 단축키는 등록 방식으로 만들어요. 동작을 가진 컴포넌트가 자기 처리기를 등록하고, 전역 처리기는 이미 처리된 이벤트, 열린 다이얼로그와 메뉴, 한글 조합 중에는 움직이지 않아요. 중앙의 한 함수가 각 화면 내부에 손을 넣는 구조는 피해요.
- 프리셋: `Cmd/Ctrl+K` 팔레트, `Cmd/Ctrl+B` 왼쪽 사이드바, `Cmd/Ctrl+\` 오른쪽 사이드카, `Cmd/Ctrl+,` 설정, `Cmd/Ctrl+S` 저장, `Cmd/Ctrl+Shift+F` 원고 검색, `Alt+M` 도우미 모드. 브라우저의 `Cmd/Ctrl+F`는 건드리지 않아요.
- 생성 중단은 `Esc` 두 번이에요. 첫 번째에 안내를 보이고, 다이얼로그나 메뉴를 닫은 직후 1.5초 동안은 세지 않아요.
- 전역 켜기와 끄기 설정을 둬요.
- 팔레트는 이동과 명령만 다뤄요(채팅, 서재 자료, 설정 구역, 플롯과 도우미 열기). 원고 본문 검색은 기존 원고 검색으로 넘겨요. 터치 화면용 진입점은 만들지 않아요.

완료 기준: 각 단축키가 글 입력을 방해하지 않아요. 기존 `Esc` 처리(메뉴, 다이얼로그, 장면 탐색기, 요청 편집기)가 그대로 동작해요.

### 4단계. 시각 마감

- 0단계의 모션 토큰을 다이얼로그, 메뉴, 토스트, 호버에 적용해요. CSS만으로 구현하고(`@starting-style`과 개별 전환 속성), 닫힘 타이머나 애니메이션용 React 상태를 두지 않아요.
- 포커스 링을 2px로 바꿔요.
- 헤어라인: Chromium은 1 디바이스 픽셀보다 얇은 테두리와 외곽선을 1픽셀로 올려 그려요([motion-browser.spec.ts](../../tests/motion-browser.spec.ts)의 주석에 규격 출처가 있어요). 그래서 테두리와 외곽선으로 쓴 약 290곳은 그대로 둬요. `height`, `box-shadow`, `width`로 쓴 13곳만 100% 배율 화면에서 확인하고 필요한 곳을 고쳐요.
- 화면 폭 기준: 760, 761, 767, 768px은 같은 뜻(좁은 레이아웃)이라 하나로 합쳐요. 600px(바텀시트)과 1023px(사이드바)은 뜻이 다른 기준이라 남겨요. 허용하는 폭 값 목록을 테스트로 고정해요([style-spacing.test.ts](../../tests/style-spacing.test.ts)와 같은 방식).
- 합치는 기준이 사용자 테마의 `@media`와 어긋나지 않는지 기본 테마와 갤러리로 확인해요.
- [motion-browser.spec.ts](../../tests/motion-browser.spec.ts)의 단언(애니메이션 없음, `transform` 없음, 0.25초 ease-out)을 새 토큰 기준으로 고쳐요.

완료 기준: `npm run verify:ui -- --grep MOTION`과 `npm run verify:liquid-gallery`가 통과해요. 모션 줄이기 설정에서 이동이 없어요. 다이얼로그 안에서 연 메뉴의 위치가 바뀌지 않아요. 100%와 200% 배율 스크린샷을 확인했어요.

### 5단계. 공간 구조

세 항목은 서로 독립이에요.

- **설정 다이얼로그(D2)**: 폭과 높이를 넓히고(지금은 `--settings-w` 960px, 최대 높이 760px), [ProviderManagement.tsx](../../web/ProviderManagement.tsx)가 설정 다이얼로그 위에 여는 다이얼로그를 오른쪽 영역의 드릴다운으로 바꾸고, 테마 설정에 원고 미리보기를 둬요. 구역을 옮겨도 초안, 포커스, 스크롤이 남는 지금의 계약을 유지해요. 좁은 화면은 그대로예요.
- **오른쪽 사이드카(D6)**: 도우미, 플롯, 창작 옵션 탭과 드래그 폭 조절(폭 저장)을 넣어요. 플롯 탭은 본문 옆에서 보는 간략한 보기예요. 전체 플롯 작업 공간과 그 진입 버튼은 남겨요.
- **도우미 사이드바와 읽음 상태(D11)**: 탭과 메뉴 규격을 채팅 사이드바에 맞춰요. 읽음 상태는 채팅 활동 확인 기록(`/api/chats/:id/activity-acknowledgements`, 브라우저 기록 병합)과 같은 방식으로 서버에 저장해요. 새 테이블보다 그 저장 방식을 재사용할 수 있는지 먼저 봐요.

완료 기준: 1440px과 2560px 데스크톱, 412px 모바일에서 밝은 테마와 어두운 테마 스크린샷을 확인했어요. 다른 기기에서 읽은 도우미 대화가 읽음으로 보여요.

### 6단계. 도우미 변경 가시화

- 턴 단위 순변경 기록: 한 턴에서 같은 대상을 여러 번 고쳐도 턴 시작 대비 변경 하나로 남겨요. 저장 위치와 수명은 위 "삭제와 보존" 절을 따라요.
- 인라인 diff 카드: 산문(원문, 번역, 로어 본문, 개요)은 어절 단위, JSON과 정규식과 프롬프트 구조는 줄 단위로 보여 줘요. diff 계산에 크기와 시간 상한을 두고, 넘으면 생략했다고 표시해요.
- 읽기와 검색 호출은 한 줄로 묶고, 변경은 항목별 카드로 보여 줘요.
- 카드의 열기 동작은 도우미를 닫지 않고 해당 항목으로 이동해요.
- 패치 매칭 세 단계와 `data.search` 경로 맞춤을 넣어요.

완료 기준: 셸의 장면 저장 경로로 바꾼 것도 기록에 나와요. 장면, 채팅, 도우미 대화, 자료를 삭제한 뒤 기록에 본문이 남지 않아요(테스트 네 개). 원고의 곡선 따옴표가 패치 뒤에도 그대로예요.

### 7단계. 턴 롤백과 계획 모드

- 세 도메인의 턴 체크포인트와 턴 롤백, 항목별 되돌리기를 넣어요. 다른 도메인(채팅 로어, 변수, 설정 등)은 대상이 아니라고 화면에 밝혀요.
- 계획 모드: 쓰기 도구를 서버에서 막고 계획만 받아요. 계획 카드에서 실행으로 넘어가요.
- 승인: 자료 삭제와 여러 자료 일괄 수정(3건 이상)은 기본으로 확인을 받아요. 유료 생성(`scene.request`, `scene.translate`) 확인은 기본으로 꺼 두고 설정으로 켜요.
- 턴 롤백이 막히거나 일부만 되는 경우 그 사유를 보여 줘요. 1단계에서 미룬 사유 표시를 여기서 정해요.

불변식과 검사: 임의의 도구 호출 순서 뒤에 턴을 롤백하면 대상의 상태가 턴 시작 때와 같아요. 그 사이 사용자가 고친 대상은 바꾸지 않고 빼며 사유를 알려요. 롤백을 두 번 해도 한 번 한 것과 같아요. 이 세 가지는 경우의 수가 많아서 예시 테스트 대신 속성 기반 테스트로 확인해요. 저장소에 그 도구가 아직 없으므로 도입을 먼저 제안해요. 이 검사는 서버 저장 경로를 대상으로 하고, 열린 편집기의 미저장 입력과의 상호작용은 따로 브라우저 테스트로 봐요.

완료 기준: 위 속성 검사와 자산 정리 테스트(체크포인트가 참조하는 이미지가 정리되지 않음)가 통과해요. [EDITING](../EDITING.md)과 [HELPER-TOOLS](../HELPER-TOOLS.md)가 새 되돌리기 경계를 설명해요.

### 8단계. 읽기 모드 퇴고와 메인 상태 표시

- 본문 선택 작업 막대(다듬기, 도우미에게 묻기, 책갈피, 복사)와 그 자리 퇴고를 넣어요. 위 "읽기 모드 퇴고" 불변식을 따라요.
- 터치 화면에서는 브라우저의 선택 메뉴와 겹쳐요. 정밀 포인터 환경에서 먼저 넣고, Android Edge는 위치를 확인한 뒤 넣어요.
- 자동 번역이 끝났을 때 사용자가 스크롤, 선택, 편집 중이면 전환 대신 배지를 보여 주고, 가만히 기다리는 중이면 읽던 위치를 지키며 전환해요.
- 메인 입력창 위에 다음 요청에 적용될 상태(진행 중 플롯, 1회 옵션 예약, 원작 참고)를 한 줄로 보여 줘요.

완료 기준: 수정 번호나 해시가 어긋나면 저장하지 않고 알려요. 번역 퇴고 뒤 삽화 무효화가 안내돼요. 안전 범위 밖 선택에서는 그 자리 퇴고가 나오지 않아요.

### 9단계. 선택 항목

필요가 확인될 때 하나씩 해요.

- 추론 요약 스트리밍: OpenAI, Anthropic, Gemini, Codex 네이티브. OpenAI에서 조직 인증이 없어 400이 오면 요약 없이 다시 보내요. 표시만 하고 저장하지 않아요.
- 도우미 입력창의 `@` 대상 지정, 선택지 질문 카드(`helper.ask`), 추가 지시와 대기 요청의 구분 표시.
- 열린 초안에 대한 읽기 전용 diff 제안. 적용은 사용자가 초안을 저장한 뒤 적용하거나 제안으로 초안을 바꾸는 명시적 동작으로만 해요.

## 사용자가 정할 것

1. 위 제외 항목 중 처음 두 가지(예약, 재바인딩)를 빼는 데 동의하는지.
2. 감사 문서에는 있었지만 원본 확정본에서 설명 없이 빠진 항목을 넣을지: 도우미 정지 버튼 위치 고정, 도우미 컨텍스트 사용량 표시와 수동 압축, 첫 실행 안내, 한글 두 글자 자동 검색, 카드 변수의 미저장 경고. 이 항목들의 코드 사실은 이번 검토에서 확인하지 않았어요.
3. [PWA](../PWA.md)가 안내하는 iOS Safari 설치를 문서에서 어떻게 할지. 대상 브라우저 결정과 어긋나요.
4. 앱 글자 크기 단계(12, 14, 16px)에 제목용 한 단계를 더할지. 0단계에서 함께 정해요.
5. 턴 체크포인트를 채팅 백업과 채팅 사본에 넣을지. 권고는 넣지 않는 쪽이에요.

## 작업 규칙

- 단계의 항목이 독립이면 항목 단위로 검증하고 커밋해요.
- 파일은 이름과 심볼로 찾아요. 이 문서는 줄 번호를 적지 않았어요.
- 영역을 고치기 전에 그 파일의 최근 커밋 메시지를 읽어요. 2026-11-19의 UI 검토 커밋들은 채택하지 않은 안과 그 이유를 본문에 적어 두었어요.
- 화면 문구를 더하면 모든 UI 언어에 넣고 `npm run check:i18n`과 `npm run verify:copy`를 돌려요.
- 새 테이블이나 열은 [DATA-MIGRATIONS](../DATA-MIGRATIONS.md)의 방식(스키마 버전을 올리지 않고 열 때 추가, 이전 앱이 무시할 수 있는 형태)을 따르고, 착수 전에 사용자 확인을 받아요.
- 검증 선택은 [DEVELOPMENT](../DEVELOPMENT.md)를 따라요.

## 검토에서 확인한 사실

원본 계획의 근거 중 코드에서 직접 확인한 것이에요.

- 클라이언트는 300ms 폴링을 하고, SSE 엔드포인트와 그 테스트는 이미 있어요.
- 원고 편집기의 `Esc`는 변경 여부를 보지 않고 세션 보관본을 지워요. 선택 구절 퇴고는 그 form 안에 있고 키 처리가 없어요.
- 앱의 전역 단축키는 테마 안전 모드 하나예요.
- 메인 전송 키 기본값은 이미 수정키 전송이고, 도우미만 데스크톱에서 `Enter` 전송을 강제해요.
- 도우미 활동 조회는 `tool.started`를 빼요.
- 플롯을 열면 본문 작업 공간이 `visibility: hidden`이 돼요.
- 도우미 읽음 상태는 브라우저 `localStorage`에 있어요.
- 채팅당 실행 중인 생성은 하나로 제한돼요(`one_active_run_per_chat`).
- `uimori apply`는 장면을 `store.editSource`로 직접 저장하고, 자료만 공통 변경 경로를 거쳐요.
- 미사용 자료 정리가 되돌리기용 저장본으로 읽는 곳은 `resource_undo`뿐이에요.
- 메인 리더에는 하단 추적 스크롤이 없고, 도우미 패널에는 있어요.

원본과 다르게 확인된 것은 두 가지예요. 되돌리기 바가 사유 없이 사라지는 것은 버그가 아니라 최근의 결정이었고, 0.5px 테두리가 100% 배율에서 사라진다는 전제는 Chromium에서 맞지 않아요.

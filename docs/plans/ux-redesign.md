# UI/UX와 도우미 하네스 개선 계획

이 문서는 2026-11-21에 작성한 구현 계획이에요. Gemini와 함께 만든 원본 계획(저장소 밖 작업 폴더의 마스터 플랜, UX 감사, 도우미 편집 분석, 독립 검토 보고서)을 코드와 대조해 검토한 뒤, 그 결과를 반영해 다시 쓴 것이에요. 0단계부터 8단계와 9단계의 일부(도우미 `@` 대상 지정·`helper.ask` 선택지 질문 카드·추가 지시와 대기 요청 구분, 단축키 재바인딩, 도우미 수동 컨텍스트 압축)는 2026-11-22에 구현을 마치고 이 문서에서 지웠어요. 남은 것은 보류한 9단계 선택 항목 셋과 아래 "남은 문제"예요.

계획은 상시 지침이 아니에요. 단계를 마칠 때마다 그 단계 항목을 이 문서에서 지우고, 채택한 규약은 소유 문서로 옮겨요. 마지막 단계가 끝나면 이 파일을 삭제해요.

## 목표와 전제

- **목표**: 장문 읽기와 쓰기에 맞는 차분한 작업 공간을 유지하면서, 실행 과정이 보이고, 도우미가 바꾼 내용을 확인하고 되돌릴 수 있고, 키보드로 빠르게 움직일 수 있게 해요.
- **브라우저**: 데스크톱 Chromium과 Android Edge만 대상으로 해요. Safari와 Firefox용 폴백은 새로 쓰지 않아요.
- **UI 규칙**: [UI-PRINCIPLES](../UI-PRINCIPLES.md)는 앱 전체의 통일감을 지키는 목적만 남기고 줄여요. 이 개정이 0단계이고, 뒤 단계는 개정된 문서를 기준으로 해요.
- **규모**: 단일 사용자 셀프호스팅 앱이에요. 새 테이블, 새 모드, 새 설정은 지금 겪는 문제를 근거로 넣어요.

## 확정된 설계 결정

원본 계획의 D1부터 D11까지를 유지하고, 검토에서 바뀐 부분을 표에 반영했어요.

| ID | 영역 | 결정 |
| --- | --- | --- |
| D1 | 모션과 UI 규칙 | 금지 목록을 이름 붙은 모션 토큰 두세 개로 바꿔요. 범위 값(예: 120–180ms)은 쓰지 않고, 새 값은 토큰을 추가하는 방식으로만 들여요. `prefers-reduced-motion`, 합성 친화 속성 우선, 본문 레이아웃 이동 금지는 유지해요. |
| D2 | 설정 화면 | 풀 페이지로 옮기지 않고 데스크톱 설정 다이얼로그를 넓혀요. 프로바이더 설정의 중첩 모달은 오른쪽 영역 안의 드릴다운으로 펼치고, 테마 설정에 원고 미리보기를 둬요. |
| D3 | 도우미 편집 | 두 가지 모드(바로 적용, 계획)로 해요. 턴 단위 순변경 기록과 인라인 diff, 세 도메인(서재 자료, 장면 원문과 번역, 개요와 작가 노트)의 턴 롤백, 파괴적이거나 대량인 작업의 승인을 넣어요. 영속 제안 세트와 열린 초안으로의 실시간 병합은 하지 않아요. |
| D4 | 전송 키 | 메인과 도우미 입력창이 설정 하나를 따라요. 기본값은 `Enter` 줄바꿈, `Ctrl/Cmd+Enter` 전송이에요. |
| D5 | 단축키와 팔레트 | 기본 프리셋, 전역 켜기와 끄기, 커맨드 팔레트를 넣어요. 단축키 정의는 동작과 키의 표로 두고, 그 표를 바꾸는 재바인딩 화면은 9단계에서 넣어요. |
| D6 | 데스크톱 작업 공간 | 오른쪽 사이드카에 도우미, 플롯, 창작 옵션 탭을 두고 경계선을 끌어 폭을 바꿔요. 지금의 전체 플롯 작업 공간(왼쪽 플롯, 오른쪽 도우미)은 그대로 둬요. |
| D7 | 읽기 모드 퇴고와 번역 | 본문을 선택하면 작업 막대가 뜨고, 안전한 범위에서 원문과 번역을 그 자리에서 다듬어요. 자동 번역 전환은 사용자가 스크롤, 선택, 편집을 하는 동안에만 미뤄요. |
| D8 | 메인 입력창 | 단계별 실행 상태와 한 줄 활성 컨텍스트 표시를 넣어요. 집필 중에 다음 요청 1건을 이 탭에 예약할 수 있고, [조건](../GENERATION.md#실행-중-다음-요청-예약)이 모두 맞을 때만 자동으로 보내요. |
| D9 | 스트리밍 | 클라이언트는 커서 조회 폴링을 유지하되 간격을 줄여요(글이 오는 동안 120ms, 빈 페이지일 때 300ms). SSE로 바꿨다가 되돌렸어요. 응답마다 열린 연결을 두면 일반 HTTP/1.1의 출처당 6개 연결 제한에 걸려, 같은 출처의 탭 셋에서 화면 자산을 받지 못했어요(`tests/browser.spec.ts`의 F02 F03 F05). 완성 본문과 같은 렌더러와 글꼴로 흘려 보내고, 메인 리더에 하단 추적 스크롤을 넣어요. 추론 요약 스트리밍은 마지막 단계의 선택 항목이에요. 기본값은 도우미 켜짐, 메인 꺼짐이에요. |
| D10 | 시각 마감 | 포커스 링을 2px로 해요. 화면 폭 기준은 뜻이 같은 것만 합쳐요(좁은 레이아웃 760px, 바텀시트 600px, 사이드바 1023px). 앱 글자 크기(12, 14, 16px)에 제목용 단계를 하나 더해요. |
| D11 | 도우미 사이드바 | 채팅 사이드바와 같은 규격(글자 탭, 호버 시 메뉴, 한 줄 정렬)으로 맞추고, 읽음 상태를 서버에 저장해요. |

## 지켜야 할 불변식

### 삭제와 보존

도우미가 바꾼 내용의 diff와 턴 체크포인트는 원고와 자료 본문의 새 사본이에요. 지금의 삭제와 보존 경로가 이 사본을 모르면, 사용자가 지운 글이 DB에 남아요.

- 장면 삭제는 그 채팅의 도우미 이벤트에서 인자 미리보기를 지우고 작업 스냅샷을 비워요([scene-deletion.ts](../../server/scene-deletion.ts)). 채팅 삭제와 도우미 대화 삭제는 [chat-deletion.ts](../../server/chat-deletion.ts)와 [helper-workspace.ts](../../server/helper-workspace.ts)가 맡아요.
- 도우미 작업이 끝나면 `releaseCompletedHelperInputs`가 도구 결과와 작업 스냅샷의 본문을 비워요([execution-retention.ts](../../server/execution-retention.ts)). 그래서 diff를 도구 결과나 작업 스냅샷에 얹어 둘 수 없어요. 자기 저장 위치와 수명을 가져야 해요.
- 변경 기록(`helper_changes`)은 6단계에서 이 네 경로와 보관 범위를 갖췄어요([DELETION](../DELETION.md#도우미-변경-기록)). 7단계의 롤백은 그 `baseline`으로 되돌려서 체크포인트 사본을 따로 두지 않았어요.
- 자료를 삭제하면 그 자료의 체크포인트도 바로 지워요. 삭제는 턴 롤백으로 되돌릴 수 없고, 그래서 삭제 앞의 승인 단계가 의미를 가져요.
- 체크포인트 수명은 대화당 최근 15턴, 30일이에요. [DELETION](../DELETION.md)과 [DATA-MIGRATIONS](../DATA-MIGRATIONS.md)에 이 보관 범위를 적어요.
- 진행 표시에 쓰는 대상 이름은 구조화된 대상(종류, ID, 제목)에서 만들어요. 인자 미리보기 문자열을 그대로 보여 주지 않아요.

### 도우미 변경 추적과 롤백

- 체크포인트도 변경 기록처럼 `uimori apply` 셸의 장면 직접 저장 경로를 거쳐야 해요. 변경 기록은 [helper-changes.ts](../../server/helper-changes.ts)의 `withHelperChange`로 그 경로를 덮어요.
- 미사용 자료 정리([unused-data.ts](../../server/unused-data.ts), [theme-assets.ts](../../server/theme-assets.ts))는 `resource_undo`와 변경 기록의 `baseline`이 참조하는 이미지와 글꼴을 남겨요. 체크포인트를 따로 두면 그것도 보존 대상에 넣어요.
- 원문과 번역을 함께 바꾼 턴을 되돌릴 때는 원문을 먼저 복원하고, 새 원문 해시를 기준으로 직전 번역을 다시 저장해요. 번역 삽화 배치는 복원되지 않는다는 점을 화면에 알려요.
- 턴 롤백이 생기면 도우미 되돌리기의 경로는 그것 하나예요. 지금의 "마지막 자료 수정 되돌리기" 바는 턴 롤백으로 대체해요. 편집기의 직전 저장 되돌리기는 사용자 저장용으로 그대로 둬요.
- 열린 편집기의 미저장 입력은 [resource-editor-session.ts](../../web/resource-editor-session.ts)가 단독으로 소유해요. 도우미는 그 입력에 직접 쓰지 않아요.

### 스트리밍

- [response-stream.ts](../../server/response-stream.ts)의 청크 순번과 오프셋 계약, 클라이언트의 오프셋 검증을 유지해요. 클라이언트는 응답마다 오래 열린 연결을 두지 않고 짧은 간격의 커서 조회로 읽어요. 채팅 이벤트, 본편 응답, 도우미 응답이 각각 연결을 잡으면 HTTP/1.1의 출처당 연결 제한 때문에 바쁜 탭 둘만으로 다른 요청이 멈추기 때문이에요. 추론 텍스트는 본문과 다른 채널로 보내고 저장하지 않아요.
- 스트리밍 표시는 완성 본문과 같은 컴파일러([reading-markdown.ts](../../core/reading-markdown.ts)의 `compileReadingMarkdown`)를 써요. 두 번째 마크다운 렌더러를 만들지 않아요.
- 인증 실패(401, 403)는 종료, 404는 작업 상태를 확인한 뒤 판단하는 지금의 구분을 유지해요.

### 화면과 테마

- 사용자 테마가 쓰는 공식 표식(`data-uimori-part` 등, [THEME-AUTHORING](../THEME-AUTHORING.md))과 저작 콘텐츠 경계를 유지해요.
- 다이얼로그에 `transform`이나 `will-change`를 남겨 두지 않아요. 다이얼로그 안의 메뉴가 `position: fixed`로 배치돼서 위치가 틀어져요. 진입 애니메이션이 끝나면 `transform`이 `none`이어야 해요.
- 초안, 선택, 읽기 위치, 포커스 보존과 늦게 온 응답 무시, 결과가 불확실한 쓰기 처리는 UI 규칙을 줄여도 남는 계약이에요.

## 단계

0단계부터 8단계까지는 끝났어요. 각 단계의 항목은 서로 독립이면 따로 커밋해요.

### 9단계. 남은 선택 항목

필요가 확인될 때 하나씩 해요.

- 추론 요약 스트리밍: OpenAI, Anthropic, Gemini, Codex 네이티브. OpenAI에서 조직 인증이 없어 400이 오면 요약 없이 다시 보내요. 표시만 하고 저장하지 않아요.
- 열린 초안에 대한 읽기 전용 diff 제안. 적용은 사용자가 초안을 저장한 뒤 적용하거나 제안으로 초안을 바꾸는 명시적 동작으로만 해요.
- 첫 실행 안내: 프로바이더, 모델, 봇이 비어 있을 때의 진행 안내예요. 빈 작업실에서 지금 무엇이 보이는지는 이번 검토에서 확인하지 못했으므로 그것부터 확인해요.

## 남은 문제

- **완료 순간의 세로 이동**: 봇이 있는 채팅은 완성 장면을 서버의 Risu 렌더러가 장면 테마 틀 안에 그려요. 생성 중인 응답은 그 틀 밖에 있어서, 글꼴과 줄 폭은 같아도 완료 순간 글이 위아래로 움직여요. 생성 중인 응답을 장면 틀에 넣으면 [THEME-AUTHORING](../THEME-AUTHORING.md)의 공개 테마 계약이 바뀌므로 소유자의 결정이 필요해요.
- **밀어 주는 전달**: 줄인 간격의 폴링도 글이 덩어리져 보이면, 본편 응답 페이지를 이미 열려 있는 채팅별 이벤트 스트림(`/api/chats/:id/events`)에 실어 보내는 방식으로 되돌아올 수 있어요. 이 방식은 연결을 더 만들지 않아요.
- **Risu 렌더러 장면의 변경 위치**: 서버의 Risu 렌더러가 그린 장면에는 문단마다 따로 된 요소가 없어요. 그래서 그런 장면에서 도우미 변경을 열면 바뀐 문단이 아니라 대략의 위치에만 닿아요. 그 문단이 글 전체에서 차지하는 비율만큼 스크롤하고, 테두리는 본문 전체에 그려요.

### 검토할 때 확인할 것

구현을 마친 시점(2026-11-22, 커밋 `c0742b0b`)의 상태예요. 이 커밋에서 전체 브라우저 스위트 607개, UI 스위트 54개, Vitest 2,998개가 통과했어요.

- **실제 모델로 써 보지 않았어요.** 화면은 스크린샷과 합성 픽스처 테스트로만 확인했어요. 스트리밍, 도우미 되돌리기, 다음 요청 예약은 실제 프로바이더를 붙여 한 번 써 봐야 해요.
- **POSIX 전용 셸 테스트는 Windows에서 건너뛰어져요.** `uimori apply`로 바꾼 것이 롤백되는지 보는 테스트가 여기에 들어 있어서, 이 경로는 리눅스 CI에서 처음 실행돼요.
- **RACOM05가 전체 실행에서 한 번 실패했어요.** 장면의 번역 보기 버튼을 찾지 못했고, 따로 세 번 돌리면 통과했어요. 마지막 전체 실행에서는 나오지 않았고 원인은 조사하지 않았어요.
- **제목 글자 크기는 18px로 두었어요.** 20px과의 비교 스크린샷은 저장소의 무시되는 출력 폴더 아래 `playwright/title-size-comparison`에 있어요. 값은 `--font-title` 토큰 하나예요.
- **선택 작업 막대는 정밀 포인터에서만 떠요.** 터치 화면에서는 브라우저의 선택 메뉴와 겹치는 문제를 풀지 않았어요.

| 턴 체크포인트를 채팅 백업과 사본에 포함 | 독립 채팅 백업에는 도우미 대화가 들어가지 않아서 체크포인트가 붙을 턴이 없어요. 수명도 15턴, 30일로 짧아요. 자동 백업은 DB 전체를 담으므로 따로 할 일이 없어요. |
| 조건부 헤어라인 | Chromium은 1 디바이스 픽셀보다 얇은 테두리와 외곽선을 1픽셀로 올려 그려서 효과가 없어요. |
| 화면 폭 기준 3단 통일 | 바텀시트 기준과 좁은 레이아웃 기준은 뜻이 달라요. |
| 영속 제안 세트, 열 개 도메인 체크포인트, 열린 초안 실시간 병합, 따옴표 정규화 매칭 | 원본의 독립 검토에서 이미 뺐어요. 이유는 각각 후속 도구 호출과의 일관성, 유지 비용, 편집 세션 단독 소유, 문체 훼손이에요. |

## 2026-11-21에 정한 것

- 예약과 재바인딩은 넣어요. 예약은 8단계, 재바인딩은 9단계예요.
- 감사 문서에만 있던 항목은 코드에서 확인한 뒤 넣었어요: 도우미 정지 버튼 위치 고정(1단계), 한글 두 글자 자동 검색(3단계), 도우미 컨텍스트 사용량 표시(6단계), 도우미 수동 압축과 첫 실행 안내(9단계). 첫 모델 자동 배정과 카드 변수 미저장 경고는 위 표의 이유로 뺐어요.
- [PWA](../PWA.md)에서 iOS Safari 설치 안내를 지웠어요.
- 앱 글자 크기에 제목용 단계를 하나 더해요(0단계).
- 턴 체크포인트는 채팅 백업과 사본에 넣지 않아요.

## 작업 규칙

- 단계의 항목이 독립이면 항목 단위로 검증하고 커밋해요.
- 파일은 이름과 심볼로 찾아요. 이 문서는 줄 번호를 적지 않았어요.
- 영역을 고치기 전에 그 파일의 최근 커밋 메시지를 읽어요. 2026-11-19의 UI 검토 커밋들은 채택하지 않은 안과 그 이유를 본문에 적어 두었어요.
- 화면 문구를 더하면 모든 UI 언어에 넣고 `npm run check:i18n`과 `npm run verify:copy`를 돌려요.
- 새 테이블이나 열은 [DATA-MIGRATIONS](../DATA-MIGRATIONS.md)의 방식(스키마 버전을 올리지 않고 열 때 추가, 이전 앱이 무시할 수 있는 형태)을 따라요. 사용자가 2026-11-21에 이 계획의 스키마 변경을 미리 승인했고, 조건은 마이그레이션 지원이에요. 기존 작업실 DB가 데이터 손실 없이 그대로 열리고 새 구조가 채워져야 하며, 그 경로를 [database-schema.test.ts](../../tests/database-schema.test.ts)에서 기존 DB를 여는 테스트로 확인해요.
- 검증 선택은 [DEVELOPMENT](../DEVELOPMENT.md)를 따라요.

## 검토에서 확인한 사실

원본 계획의 근거 중 코드에서 직접 확인한 것이에요.

- 클라이언트는 300ms 폴링을 하고, SSE 엔드포인트와 그 테스트는 이미 있어요.
- 원고 편집기의 `Esc`는 변경 여부를 보지 않고 세션 보관본을 지워요. 선택 구절 퇴고는 그 form 안에 있고 키 처리가 없어요.
- 앱의 전역 단축키는 테마 안전 모드 하나예요.
- 메인 전송 키 기본값은 이미 수정키 전송이고, 도우미만 데스크톱에서 `Enter` 전송을 강제해요.
- 도우미 활동 조회는 `tool.started`를 빼요.
- 플롯을 열면 본문 작업 공간이 `visibility: hidden`이 돼요.
- 도우미 읽음 상태는 브라우저 `localStorage`에 있어요.
- 채팅당 실행 중인 생성은 하나로 제한돼요(`one_active_run_per_chat`).
- 메인 리더에는 하단 추적 스크롤이 없고, 도우미 패널에는 있어요.

원본과 다르게 확인된 것은 두 가지예요. 되돌리기 바가 사유 없이 사라지는 것은 버그가 아니라 최근의 결정이었고, 0.5px 테두리가 100% 배율에서 사라진다는 전제는 Chromium에서 맞지 않아요.

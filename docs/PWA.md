# 앱 설치와 활동 알림

Uimori를 브라우저에서 PWA(Progressive Web App)로 설치하는 방법과 앱 내부 활동 모드, 그리고 백그라운드 Web Push 완료 알림에 관한 안내예요.

---

## PWA 앱 설치 안내

### 기기별 설치 방법
- **설정 화면에서 설치**: **설정 → 일반 → 앱과 알림 → 앱 설치**로 이동해요. Chromium 기반 브라우저가 설치 이벤트를 제공한 경우에만 앱 안에 실제 설치 버튼이 활성화돼요.
- **브라우저 메뉴에서 설치**: 브라우저 주소창이나 더보기 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 눌러 설치할 수 있어요.
- **iPhone 및 iPad (iOS/iPadOS Safari)**: Safari 하단의 공유 버튼을 누르고 **홈 화면에 추가**를 선택한 후 생성된 홈 화면 아이콘으로 접속해요.
- **설치 취소 시**: 설치 대화상자를 취소하더라도 앱이 권한을 강제로 다시 요청하지 않아요. 지원되지 않는 환경에서는 같은 영역의 **설치 안내**를 펼쳐 상세 방법을 확인할 수 있어요. PWA 등록 자체는 알림 권한을 요청하지 않아요.

### 설치 앱의 동작 특성과 주의사항
- **독립 창 실행 (standalone)**: PWA로 설치해 실행하더라도 기존 브라우저와 동일한 로그인 세션, 서버 서재 자료, 읽기 위치를 유지해요.
- **설치와 오프라인 편집의 분리**:
  - **Uimori의 서비스 워커는 원고나 API 응답을 로컬에 임의 캐시하지 않아요.**
  - 네트워크가 끊긴 상태에서 작성 요청을 백그라운드에 쌓아두거나 재연결 시 자동으로 재전송하지 않아요 (fetch 가로채기나 Background Sync를 등록하지 않음).
  - 단, 현재 브라우저 탭에 입력 중인 작성 초안 보호와 서버에 저장된 작업 상태 복구는 기존 방식대로 안전하게 동작해요.
- **보안 컨텍스트 필수**: PWA 설치 및 푸시 기능을 사용하려면 HTTPS 또는 `localhost`와 같은 안전한 보안 컨텍스트 접속이 필요해요.

## 앱 내부 활동 모드

좌측 사이드바(모바일 환경에서는 탐색 서랍) 상단의 말풍선/받은 편지함 아이콘을 눌러 **봇 탐색**과 **활동** 화면을 언제든 전환할 수 있어요.

### 활동 피드 3개 그룹
활동 화면은 작업 상태에 따라 세 가지 그룹으로 나누어 보여줘요.

1. **확인할 활동**: 생성이 완료되었거나 확인이 필요한 실패 작업이 모여요. 실패한 작업이 목록 상단에 먼저 표시돼요.
2. **진행 중**: 현재 서버에서 실행 중인 본문 작성, 번역, 도우미 작업이 실시간으로 표시돼요.
3. **최근 채팅**: 최근 대화를 나눈 채팅 목록이에요. 미확인 또는 진행 중인 채팅도 포함돼요.

- **접기/펼침 상태 저장**: 각 그룹은 개별적으로 접고 펼칠 수 있으며, 펼침 상태는 브라우저 로컬에 저장돼요.
- **페이지 표시 단위**: 펼쳐진 그룹에는 처음에 5개 항목이 표시되며, 하단의 「더 보기」를 누르면 20개씩 추가로 표시돼요. 접었다가 다시 펼쳐도 추가 표시 수는 유지되지만, 페이지를 새로고침하면 처음 5개부터 다시 시작해요. 봇 내부 채팅 폴더도 처음 5개를 보여주고 이후 20개씩 추가해요.
- **날짜 묶음 기준**: 최근 채팅과 종료된 도우미 작업은 마지막 활동 현지 날짜를 기준으로 오늘, 어제, 지난 7일, 지난 30일, 연월 단위로 묶여 표시돼요 (도우미 세션 선택에도 동일 적용). 최근 채팅은 마지막 생성 요청 시각을 기준으로 정렬해요.
- **도우미 대화 탐색**: 도우미 대화는 공통 탐색의 **도우미**에서 사용자 지정 프로젝트와 최근 대화로 찾을 수 있어요. 프로젝트 소속은 자동으로 바뀌지 않으며, 다른 화면에서도 도우미 메뉴의 진행 표시로 실행 여부를 확인할 수 있어요.
- **선택 채팅 바로가기**: 현재 선택된 채팅이 스크롤 범위 밖에 있더라도 정렬 목록 상단에 이동 전용 바로가기가 고정되어 쉽게 접근할 수 있어요.

### 활동 확인과 알림 정리
- **결과 확인**: 활동 목록에서 완료된 항목을 선택하면 해당 장면의 원고나 번역 화면으로 바로 이동해요.
- **알림 정리**: 항목의 확인 버튼을 누르거나 실제 원고/번역을 확인하면 해당 실행의 활동 알림만 정리돼요. 실패나 실행 불확실 상태는 알림 정리 여부와 관계없이 작업 기록에 그대로 보존돼요. 이미 종료된 실행 불확실 작업은 확인으로 알림만 정리할 수 있으며, 서버 작업 상태는 변경하지 않아요.
- **자동 번역 묶음**: 본문 생성 뒤 이어지는 자동 번역은 최종 완료 결과 하나로 묶여 표시돼요.

### 빠른 채팅 복사
- 봇 대화 목록이나 최근 채팅의 **… → 채팅 복사**를 누르면 현재 표시된 마지막 장면까지를 포함하는 독립 사본 채팅이 즉시 생성돼요.
- 빈 채팅도 복사할 수 있으며, 원본 채팅에서 작성 중이던 입력 초안은 안전하게 보존돼요.

### 요청 불확실 상태 복구
장면 작성 전송 중 네트워크 단절 등으로 접수 여부가 불확실해지면:
- 현재 탭에 보관된 동일 요청 키로만 서버에 접수 여부를 안전하게 재확인해요 (이미 접수된 요청의 중복 생성을 방지).
- 하단의 「나중에」 버튼을 누르면 해당 경고만 숨기며, 작성창의 「이전 요청 확인」 버튼과 미확인 요청 복구 정보는 그대로 유지돼요.

## 작업 완료 Web Push 알림

브라우저 창을 닫아두거나 다른 앱을 사용하는 동안 작업이 완료되면 운영체제 Web Push 알림을 받을 수 있어요.

### 알림 설정 경로
1. **설정 → 일반 → 앱과 알림**으로 이동해요.
2. **작업 완료 알림** 스위치를 켜요.
3. 브라우저에서 권한을 요청하면 허용해요. 만약 이전에 거부했다면 브라우저 사이트 설정에서 권한을 변경한 뒤 **권한 다시 확인**을 눌러요. 알림을 지원하지 않는 브라우저는 비활성 이유를 스위치 아래에 안내해요.
4. **알림 옵션**을 열어 테스트 알림을 발송해 볼 수 있어요.

### 알림 발송 조건과 옵션
- **기본 알림 대상**: 본문 생성 완료와 확인이 필요한 생성 실패 시 알림을 보내요.
- **선택 알림 옵션**: 개별 수동 번역 및 삽화 완료 알림은 기본적으로 꺼져 있어요.
- **채팅 제목 표시**: 새 구독에서는 알림에 채팅 제목을 표시하도록 기본 설정돼요 (기존 구독 설정은 유지). 잠금 화면에 민감한 제목이 노출되지 않도록 옵션에서 끌 수 있어요. 원고 본문 문장, 이미지 미리보기, 도구 실행 결과는 푸시 페이로드에 절대 포함하지 않아요.
- **자동 번역 연계**:
  - **설정 → 일반 → 생성 기본값**에서 '본문 생성 후 자동 번역'을 켤 수 있으며, 채팅별 **생성 설정 → 본문 번역**에서 세부 동작(전체 기본값 따르기 / 이 채팅에서 켜기 / 이 채팅에서 끄기)을 지정해요.
  - 자동 번역이 켜져 있으면 본문 저장 시 바로 알리지 않고, 번역까지 모두 완성된 후 알림을 한 번만 보내요 (`채팅 제목 · 번역까지 완성`). 번역을 시작하지 못했거나 실패한 경우에는 실패 알림 설정을 따르며 원문은 유지돼요. 서버 재시작으로 번역 모델 결과를 확인할 수 없게 되면 완료 대신 중단 알림을 보내요.
  - 자동 번역이 꺼져 있으면 본문이 저장되는 즉시 알림이 발송돼요 (`Uimori · 본문 완성`).
  - 수동으로 직접 취소한 작업, 수동 본문/번역 저장, 과거 자료 가져오기 및 내부 도구 호출은 완료 알림을 보내지 않아요.

### 알림 클릭 시 화면 이동 및 초안 보호
- 도착한 푸시 알림을 누르면 해당 채팅의 장면 및 원문/번역 화면으로 바로 이동해요.
- 브라우저에 이미 열려 있는 창이 있으면 페이지를 새로고침하지 않고 기존 창으로 포커스하여 이동 의도만 전달해요.
- **편집 이탈 방지**: 원고, 책갈피 메모, 설정을 편집 중이거나 책갈피 저장 요청이 진행 중인 상태에서 알림을 누르면, 작성 중인 내용을 잃지 않도록 먼저 안내하고 편집을 마친 뒤 이동하게 해요.

### 푸시 사전 요구조건
- **접속 토큰 기반 HTTPS 서버**: Web Push는 접속 토큰으로 로그인한 HTTPS 개인 서버에서만 활성화돼요. 로컬 무인증 모드에서는 PWA 설치는 가능하지만 푸시 알림은 동작하지 않아요.
- **표준 브라우저 Push 중계 활용**: OS 및 브라우저의 표준 Push 서비스(FCM, Apple Push, Mozilla, Windows Push)를 사용하며, 별도의 서드파티 중계 서버나 외부 클라우드 계정을 요구하지 않아요.

## 구현 참고

이 섹션은 PWA Manifest 자원, 활동 피드 스키마, Web Push 큐 및 VAPID 암호화 규약을 설명하는 개발자/에이전트 계약이에요.

### PWA Manifest, 아이콘 생성 및 서비스 워커 사양
- **Manifest 규격**: 앱 ID, 시작 주소, scope는 `/`로 고정되며 개인 채팅 경로나 세션 토큰을 포함하지 않아요. [화면 언어](I18N.md)에 대응하는 정적 manifest 파일을 제공해요.
- **아이콘 자산 구조**:
  - 사이드바 로고: 배경을 제거한 [투명 SVG](../web/public/icons/halo-mark.svg).
  - 탭 아이콘 및 앱 정보 로고: 남청색 바탕에 크림색 원형 문양의 반응형 SVG.
  - [초소형 SVG 원본](../web/public/icons/halo-tiny.svg): 16px 뷰포트 (2개 원).
  - [소형 SVG 원본](../web/public/icons/halo-small.svg): 32px 뷰포트 (3개 원).
  - [정교한 SVG 원본](../web/public/icons/halo.svg): 48/64px 및 180/192/512px (정교한 동심원과 구획선).
  - [반응형 SVG](../web/public/favicon.svg): 16px과 32px에서 간결한 문양으로 전환.
  - 파생 SVG/PNG 재생성 스크립트: `node scripts/generate-app-icons.mjs`.
  - Maskable 아이콘은 안전 영역을 고려해 여백을 배치하고, 설치 배경색은 다크 네이비 테마 색상을 적용해요.
- **서비스 워커 캐시 비개입**: `sw.js`는 HTTP 캐시를 우회해 갱신되며, 원고 데이터나 API 응답에 대한 CacheStorage 복제를 수행하지 않아요. UI 언어는 `uimori-presentation` IndexedDB의 `settings/ui-language`에 보관해요.

### 활동 피드 및 확인 기록 API
- **활동 피드 조회**: `GET /api/activity-feed`는 최근 작업 500개를 대상으로 조회하며 원고 본문과 이미지 파일은 제외해요. 첫 업데이트 서버 시작 전에 끝난 작업을 새 미확인으로 재생하지 않아요.
- **확인 기록 저장**: `GET/POST /api/chats/:id/activity-acknowledgements`는 스키마 15의 `app_metadata` 테이블에 개별 실행별 확인 상태를 영속화하고 브라우저 로컬 기록을 병합해요. 채팅 삭제 시 해당 채팅의 확인 기록도 함께 정리돼요.

### Web Push 발송 대기열 및 VAPID 아키텍처
- **원자적 발송 큐**: 작업 완료 이벤트를 기록하는 트랜잭션에서 각 구독별 발송 대기열 레코드를 함께 기록해요.
- **처리 한도 및 타임아웃**: 프로세스당 최대 4건씩 병렬 처리하며 발송 요청 타임아웃은 10초예요. 일시적 네트워크 오류나 429/5xx 응답 시 최대 3회 재시도해요.
- **만료 및 정리**: 일반 대기 알림은 2시간, 테스트 알림은 2분 후 만료돼요. 중계 서버가 404/410을 반환하면 만료된 구독을 DB에서 제거하며, 성공한 발송 기록은 7일 후 자동 정리해요.
- **세션 결합 및 보안**: 구독은 개별 access session에 종속돼요. 사용자가 로그아웃하거나 접속 토큰을 변경하면 연결된 푸시 구독과 대기열이 즉시 해제돼요. DB 백업에는 VAPID 비밀 키와 구독 capability가 포함되므로 비공개로 보관해야 해요. 다른 HTTPS origin으로 복원하면 기존 origin의 구독은 정상 서버 시작 시 제거해요.
- **안드로이드 Chrome 주의사항**: 안드로이드 Chrome이 알림 카드에 자체적으로 표시하는 ‘구독 취소’ 메뉴는 브라우저 고유 UI이며 앱에서 임의로 제거할 수 없어요.
- **Codex 자동 번역 사전 검증**: Codex를 통한 자동 번역은 JEV 사전 콘텐츠 검사를 통과한 경우에만 진행돼요. 검증 실패 시 자동 번역을 보류하고 사용자가 수동 요청하도록 유도해요.
- **전송 계층 및 엔드포인트**: 암호화와 서명은 Web Push 라이브러리에, DNS·TLS·소켓·취소는 표준 fetch에 맡겨요. 중계 HTTPS 주소 제한과 리다이렉트 금지를 유지해요. `GET /api/push?clientId=...`, `POST /api/push/prepare`, `POST/PUT/DELETE /api/push/subscription`, `POST /api/push/test`. 구독 수정 시 기존 수정 번호를 검증하며, GET과 구독 응답은 공개 VAPID 키와 기기 상태만 반환하고 비밀 키나 암호화 capability는 반환하지 않아요.

```sh
# PWA 매니페스트, 서비스 워커 캐시 비개입 및 정적 자원 검증
npx vitest run tests/pwa.test.ts

# 푸시 서비스 DB 큐, 중복 방지, 세션 해제 및 복원 검증
npx vitest run tests/push-service.test.ts

# Web Push VAPID 암호화, HTTPS 중계 주소 및 워커 포커스 검증
npx vitest run tests/push-transport.test.ts

# 개인 기능 브라우저 종합 검증 (SW 등록, 명시적 설치 UI, CacheStorage 비사용)

# Web Push 브라우저 알림 UI 시나리오 검증
npm run verify:push
```

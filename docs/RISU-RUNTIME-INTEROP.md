# Risu CBS·Lua·트리거·정규식의 실행 순서

Risu 카드·모듈·프롬프트 프리셋의 CBS, Lua, 구조화 트리거, 정규식이 Uimori에서 언제 어떤 순서로 실행되고 어떤 상태를 함께 쓰는지 정리했어요. RisuAI 실행 순서 문서를 바탕으로 Uimori의 실제 실행 순서에 맞게 고쳤어요. 둘 이상의 층이 얽힌 코드를 고칠 때 읽어요. 각 함수는 [Risu Lua 트리거 API](RISU-LUA-API.md)와 도우미 가이드 `CBS-REFERENCE`에 있어요.

## 함께 쓰는 상태

채팅 변수는 모든 층이 같은 저장소를 써요.

| 층 | 읽기 | 쓰기 | 참고 |
| --- | --- | --- | --- |
| CBS | `{{getvar::키}}`, `{{? $키}}`, `{{#when::var::키}}` | `{{setvar::키::값}}`, `{{addvar::…}}`, `{{setdefaultvar::…}}` | 값은 문자열이에요. |
| Lua | `getChatVar(id, 키)` | `setChatVar(id, 키, 값)` | `getState`·`setState`는 `__키` 변수에 JSON으로 저장해요. |
| 구조화 트리거 | 조건의 `var` | `setvar`, `v2SetVar` | 같은 채팅 변수예요. |
| 기본 변수 | 카드의 `defaultVariables`, 프리셋의 `templateDefaultVariables` | — | 값이 없는 변수의 기본값이에요. |

토글은 전역 값 `toggle_<키>`로 읽어요. CBS는 `{{getglobalvar::toggle_키}}`나 `{{#when::toggle::키}}`, Lua는 `getGlobalVar(id, 'toggle_키')`로 읽고, 스크립트가 바꿀 수는 없어요. 값은 채팅 설정의 토글 선택에서 와요. `{{tempvar::…}}`·`{{settempvar::…}}`의 임시 변수는 한 번의 평가 안에서만 살아요.

값이 없는 채팅 변수는 문자열 `"null"`로 읽혀요. Lua의 `nil`, 빈 문자열과 다르게 다뤄요.

## 한 번의 전송

사용자가 메시지를 보내면 Uimori는 다음 순서로 실행해요.

1. `input` 트리거와 Lua `onInput`이 실행돼요. 사용자 메시지는 아직 대화에 없어요. 여기서 `stopChat`이나 `false`를 돌려주면 전송을 멈춰요.
2. Lua `editInput` 콜백이 사용자 글을 고쳐요.
3. 사용자 글에 CBS와 `editinput` 정규식을 적용하고 대화 끝에 넣어요.
4. `start` 트리거와 Lua `onStart`가 실행돼요. 여기서도 전송을 멈출 수 있어요.
5. 봇·모듈의 설명, 로어, 예시 대화의 CBS를 평가해요. 이전 대화와 첫 메시지에는 CBS와 `editprocess` 정규식을 적용해요.
6. 프롬프트 프리셋 블록의 CBS를 평가하고 요청을 조립해요.
7. Lua `editRequest` 콜백이 모델에 보낼 메시지 배열을 고쳐요. 배열을 고친다고 대화에 저장된 메시지가 바뀌지는 않아요.
8. 모델을 불러요.
9. Lua `editOutput` 콜백이 응답을 고치고, CBS와 `editoutput` 정규식을 적용한 뒤 대화에 넣어요.
10. `output` 트리거와 Lua `onOutput`이 실행돼요.

화면에 보여 줄 때는 별도로 Lua `editDisplay` 콜백, 에셋 태그, CBS, `editdisplay` 정규식을 적용하고 배경 HTML을 붙여요. 저장된 메시지는 바뀌지 않고, 표시 중의 변수 변경도 그 표시에만 쓰여요. 같은 메시지를 다시 그릴 때마다 다시 실행되므로 표시 단계에서는 오래 남는 변경을 하지 않아요.

정규식 단계 이름은 Risu 정규식의 `type` 값 그대로예요. Uimori는 `editinput`, `editoutput`, `editprocess`, `editdisplay`만 실행하고 다른 `type`의 스크립트는 실행하지 않아요. 한 단계 안에서는 `<order N>` 값이 큰 스크립트부터, 같으면 목록 순서대로 실행해요. 치환 결과에는 다시 CBS를 적용하고, 패턴에 `<cbs>` 표시가 있으면 패턴도 먼저 CBS로 평가해요. 치환문 앞의 `@@move_top`·`@@move_bottom`은 일치한 부분을 앞이나 뒤로 옮기고, 그 밖의 `@@` 명령은 실행하지 않고 문제로 보고해요.

봇에 붙인 모듈의 정규식과 트리거도 함께 실행돼요. 프롬프트 프리셋의 정규식은 봇과 모듈의 정규식보다 앞에 놓여요. 로어는 봇의 로어가 먼저이고 모듈 로어가 뒤에 와요.

## Lua 수명과 멈춤

- 한 채팅의 같은 자료 판본에서는 Lua 실행 환경이 이어져서 전역 값이 다음 호출까지 남아요. 재시작, 시간 초과, 실패, 자료 수정 때는 처음부터 다시 만들어요. 오래 남길 값은 채팅 변수나 `setState`에 저장해요.
- 첫 메시지 미리보기, 읽기 화면의 표시 변환, 도우미의 확인 도구는 저장된 상태를 복사한 일회성 환경에서 실행하고 아무것도 저장하지 않아요. 이전 실행의 Lua 전역 값에 기대는 표시 코드는 이 경우 다르게 보일 수 있어요.
- `stopChat`이나 콜백의 `false`는 1~4단계에서 전송을 멈춰요.
- 한 트리거 안에 `triggerlua` 효과와 다른 효과를 섞으면 Uimori는 그 트리거를 실행하지 않고 실패해요. Lua를 쓰는 트리거는 Lua 효과만 담아요.
- 표시 단계, 편집 콜백(`editInput`, `editOutput`, `editRequest`, `editDisplay`), 버튼과 폼 실행에서는 트리거의 조건을 확인하지 않아요. 조건은 `input`, `start`, `output`과 수동 트리거에서만 확인해요.

## 다시 실행되는 코드

- 다시 생성하거나 다시 쓰면 같은 대화에서 전송 단계가 다시 실행돼요. 트리거와 콜백은 같은 대화에서 여러 번 실행될 수 있다고 보고 작성해요.
- 수동 트리거는 버튼을 누를 때마다 실행돼요.
- 표시 단계는 화면을 다시 그릴 때마다 실행되므로 같은 입력에 같은 결과를 내도록 써요. `{{random}}`처럼 매번 달라지는 CBS는 다시 그릴 때 바뀔 수 있어요.

## 모듈과 권한

- 봇에 붙인 모듈의 로어, 정규식, 트리거, 에셋, 배경은 실행 때 합쳐지고, 봇의 정체성은 바뀌지 않아요.
- 모델을 부르는 Lua 함수는 그 코드가 들어 있는 카드나 모듈의 `lowLevelAccess`를 따르고, 함께 붙인 자료의 권한을 빌려 쓰지 않아요.
- CHARX 카드 안의 내장 모듈은 카드에 직접 적힌 정규식·트리거·로어를 대신해요. 자세한 규칙은 [Risu 자료 가져오기](RISU-IMPORT.md#자주-겪는-문제와-대처-방법)에 있어요.

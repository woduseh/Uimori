# v0.1.0 베타 방향 결정 · 2026-09-12

사용자가 확정한 제품 원칙과 공개 조건이에요. 구현·검증 상태는 [베타 실행 계획](../project-plan/BETA-PLAN.md)과 [CURRENT](../project-plan/CURRENT.md), 표본별 근거는 [기능 대응표](../project-plan/BETA-SAMPLES.md)가 소유해요. 원칙에서 특정 런타임·자료형·화면·수치를 추론해 사용자 확정 사항으로 만들지 않아요.

사용자는 이 순서에 따른 설계·구현·검증 진행을 승인했어요. 이미 결정된 원칙 안의 기술 선택은 구현자가 처리하고, 사용자 경험·자료 의미·공개 범위에 영향을 주는 실질적 선택은 구체적인 결과와 대안을 준비해 논의해요. 새로운 유료 평가·개인 자료의 외부 전송·배포는 해당 실행의 범위를 준비한 뒤 기존 승인 여부를 확인해요.

## 제품과 사용자

Uimori는 개인이 설치해 자기 API 키로 사용하는 AI 소설·채팅 앱이에요. 첫 베타는 기존 Risu 봇·프리셋·모듈을 활용하려는 사용자를 주요 대상으로 해요. 공식 설치·업데이트의 첫 지원 환경은 Linux/Docker 개인 서버예요.

이미 사용하는 동시 채팅·진행 표시·자율 조회·문맥 관리 기반을 유지하고 발전시켜요. 사용 경험으로 제시된 대기 시간은 품질을 위해 기다릴 수 있다는 근거이며 고정 timeout이나 호출 예산이 아니에요.

## 제품 원칙

- **사용자가 통제할 수 있는 자동화**: 사용자의 권한과 명시적 변경이 자동 처리보다 우선해요. 자동화는 적극 활용하되 사용자가 변경을 인지하고 개입할 수 있어야 해요. 안내를 모든 작업의 반복 승인으로 확대하지 않아요.
- **창작 경험 우선**: 좋은 응답에 필요한 작업을 허용하고 부가 기능의 실패가 채팅을 막지 않게 해요. 정상적인 준비는 기다림을 기본으로 하되 사용자가 건너뛰고 취소할 수 있어야 해요. 핵심 모델·저장 자체의 실패와 부가 기능의 실패는 구분해요.
- **강력하고 안전한 자율성**: 모델과 제작자가 자료·스킬·도구·코드를 폭넓게 활용하게 해요. 권한·저장·작업·취소·복구는 호스트가 책임져요. 특정 봇·모듈·플러그인 이름에 종속된 본체 기능을 추가하지 않아요.
- **편리함과 신뢰**: 원문·작성된 설정·사용자 지시·자동 해석의 의미와 출처를 보존하면서 편리하게 사용하게 해요. 내부 복잡성을 사용자에게 떠넘기지 않고 필요할 때 동작과 결과를 이해하고 바로잡을 수 있게 해요.
- **개인정보 보호**: 기본 진단은 최소 기록이며 상세 추적은 필요할 때 켜요. 개인 채팅·비밀을 보호하고 외부 공유는 사용자가 통제해요. 백업·실행에 필요한 기록과 진단용 추가 수집은 구분해요.
- **독립성**: Uimori 자체 데이터 모델과 확장 API를 기준으로 발전해요. 외부 자료를 폭넓게 활용하되 RisuAI·RisuAI-Next의 미래 변경을 자동 추종하지 않아요.

## 확장과 호환 지원

2026-09-13 작업 방식 채택: Risu의 고정 명세·공개 API와 실제 실행 동작을 호환 계약의 근거로 삼고 Uimori 공통 API에 대응시켜요. 6단계를 유지하면서 2~3단계의 필요한 보완과 4단계의 기능 연결을 실제 사용 결과 단위로 진행해요. 첫 묶음은 프리셋의 프롬프트·토글·정규식 가져오기와 채팅 적용이며 세부 완료 조건은 [베타 계획](../project-plan/BETA-PLAN.md)이 소유해요. 특정 표본 전용 본체 기능·미래 버전 자동 추종·공개 조건의 임의 확대는 하지 않아요.

제작자가 작성한 코드를 실행할 수 있는 확장 기반을 마련해요. 단순 선언형으로 표현할 수 없는 기능을 본체에 자료별 예외로 옮기지 않아요. 앱에 포함하는 확장도 공통 API와 안전 경계를 사용해요.

주 앱 DOM 전체 접근은 현재 지원 범위에서 제외해요. 확장 소유 화면·패널·테마 등 필요한 표현 수단은 공통 API로 제공할 수 있어요. Risu의 기존 권한과 API는 참고 자료이며 Uimori의 안전 경계를 대체하지 않아요.

자료 지원은 가져오기·표현 변환·선택적 호환 실행·네이티브 이식을 조합해요. 지원 범위와 동작 차이를 밝히고 기능과 사용자 경험을 보존해요. 원본 코드 무수정·화면의 완전한 재현·미래 버전의 완전 호환을 일괄 약속하지 않아요. 원본 보존과 호환 실행을 기본으로 채택하는 것은 별개예요.

자동 분석은 알려진 지원/미지원 요소와 필요한 설정을 찾되 임의 코드의 모든 동작을 증명한다고 주장하지 않아요. 미지원·불확실한 동작을 조용히 삭제하지 않으며 기술적 지원, 실행 권한, 제작자의 이용 조건을 구분해요. 개별 이식에서 필요한 의미 판단은 해당 내용을 보존한 초안으로 확인해요.

프리셋 이식의 중심은 프롬프트·커스텀 토글·정규식이에요. 모델·프로바이더·모델 파라미터·도구 설정의 복제는 그 프리셋의 기능 보존 조건으로 삼지 않으며, 이를 가져오지 않는 것을 미지원 손실로 세지 않아요.

### CharX 가져오기 범위 · 2026-09-13 후속 선택

사용자는 CharX의 메인 프롬프트 덮어쓰기(`system_prompt`)와 성격(`personality`)·시나리오(`scenario`) 필드를 지원 대상에서 제외했어요. 값이 있어도 봇 본문·추가 지시로 합치지 않고 원본 파일에 보존하며 가져오기에서 제외 사실을 안내해요. 이미 저장된 자료·과거 Run은 변경하지 않아요.

글로벌 노트 덮어쓰기(`post_history_instructions`)는 원래 덮어쓰기 기능 대신 **봇의 추가 작문 지침**으로 가져와요. 사용자가 선택한 Uimori 작문 프롬프트와 함께 기존 공통 패키지 지시 경로로 전달하고, 전역 설정·선택한 프롬프트·다른 봇이나 채팅을 수정하지 않아요. 원래 메시지 삽입 위치나 지침 교체 기능을 재현하는 결정이 아니에요. `{{original}}` 참조는 기존 프롬프트를 중복 삽입하지 않도록 변환에서 비우며 이 차이를 안내하고 원본은 보존해요. 별도의 기본 OFF 덮어쓰기 권한이나 교체 기능은 추가하지 않아요.

독립 `.risum` 파일 가져오기는 베타 지원 목표에서 제외해요. CharX 안에 담긴 `module.risum`을 해독하는 것은 필요한 CharX 콘텐츠를 읽는 내부 구현과 구분해요. 히든 스토리 같은 모듈의 기능 보존 목표는 유지하되 기존 프로젝트 추출이나 CharX 경로를 사용해요.

## 자료와 업데이트

v0.1.0부터 지원하는 업그레이드 경로에서 자료·프롬프트·채팅·확장 상태를 보존해요. DB와 교환 파일, 확장 API와 상태의 버전을 구분해 변경과 복구를 관리해요. 모든 과거 개발 버전의 이관을 요구하는 결정은 아니며 사용자 자료를 임의로 삭제할 권한도 아니에요.

정상 업데이트는 Update 한 번으로 준비·백업·변경·상태 확인·필요한 복구를 이어가게 해요. 자료·프롬프트는 다른 설치에서도 안정적으로 옮겨 사용할 수 있어야 해요. 백업 생성 성공과 실제 복원 가능 여부는 각각 확인해요. 불확실한 외부 요청을 복구 과정에서 자동 재전송하지 않아요.

## 문서와 공개 조건

2026-09-13 최초 선택(아래 후속 승인으로 대체됨): 저장소는 이미 GitHub public이지만 공개 라이선스 정책은 당시 미정이었어요. 사용자는 RPack의 기존 AGPL 조건 구현을 포함하는 대신 독립 구현이나 대체 수단을 우선하기로 했어요. 이 결정으로 Uimori의 라이선스를 새로 지정하지 않아요. 기존 RPack 코드·치환표를 복사하거나 번들에 포함하지 않고, 형식 읽기와 native 자료 변환을 분리해 진행해요.

2026-09-13 후속 승인: 사용자는 RPack 치환표 포함과 그에 필요한 라이선스 적용이 더 효율적이면 진행해도 된다고 허용했어요. 이에 `.risup` 직접 가져오기에 원본 해독 치환표를 사용하고 Uimori 프로젝트 소스에 **AGPL-3.0-only**를 적용했어요. [LICENSE](../LICENSE)와 [제3자 고지](../THIRD_PARTY_NOTICES.md)에 원본 조건·저작권·변경 내용을 보존해요. 사용자 자료·생성 결과에는 각자의 권리가 유지돼요. Uimori 자체 API·데이터 모델과 Risu 런타임의 독립성은 유지해요. 배포한 수정본과 일치하는 대응 소스를 원격 이용자에게 제공해야 하며, 이 승인은 Git push나 외부 배포까지 허용하지 않아요. 로컬 변경만 있는 시점에는 공개 저장소가 해당 빌드의 대응 소스를 제공한다고 주장하지 않아요.

지원하는 자료의 일상적인 사용은 에이전트 없이 가능하게 해요. 고급 제작과 복잡한 이식에는 에이전트와 코드를 활용할 수 있어요. 사람이 읽는 설치·시작·지원 범위·복구·문제 신고는 짧고 완결되게 유지하고, 에이전트용 문서는 현재 계약과 근거를 정확히 찾을 수 있게 해요.

이번에 제공한 모든 표본 버전의 필요한 전체 기능을 완성하고 검증한 뒤 베타를 공개해요. [표본 기준](../project-plan/BETA-SAMPLES.json)은 파일 지문과 기능·근거·미확인을 구분해요. 새 자료나 새 Risu 버전이 나올 때마다 공개 조건을 자동 확대하지 않아요. 내부 구현 단계를 나누는 것은 공개 조건을 축소하는 결정이 아니에요.

정적 조사·합성 검사·실제 모델/기기/지원 환경 검증·사용자 경험 판단을 구분해요. 다른 방식으로 옮긴 기능의 만족도와 공개 여부는 구체적인 결과를 보고 사용자와 판단해요.

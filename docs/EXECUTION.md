# 실행 입력의 수명

요청이 시작되면 필요한 현재 자료와 설정을 읽어 그 실행의 입력을 구성해요. 진행 중인 요청에 다른 편집을 섞지 않으며 DB 트랜잭션 안에서 외부 모델이나 카드 코드를 실행하지 않아요. 네이티브 Risu CBS·Lua·정규식 준비는 기존 실행 경계를 사용해요.

완성된 프롬프트의 모델 적합성은 설정한 토큰 예산으로 판단해요. 개별 텍스트 50만 자나 전체 프롬프트 150만 자 같은 별도 제한으로 정상 입력을 거절하거나 요약 모델을 호출하지 않아요. 자료 형상·식별자 검증과 조립된 입력의 메모리 보호 상한은 유지해요.

서재 프리셋 저장·수정, 전역 프롬프트 편집과 미리보기도 같은 큰 입력을 처리해요. CBS 표현식이 없는 긴 본문은 원문 그대로 통과하고, 실제 CBS 코드에는 시간·출력 메모리 감시를 적용해요. 평가 도구의 설명·진행 방향은 모델 출력 토큰 계약을 따르며 최종 본문에는 다른 저장 경로와 같은 원고 보존 상한을 적용해요.

부분 문맥이 필요한 보조 작업은 `textTokenExcerpt`로 토큰 수를 계산해 원문의 앞이나 뒤를 발췌해요. 생략 표시도 토큰 예산에 포함하고 유니코드 문자를 중간에서 자르지 않아요. 로어 관련성 판단은 사용자 요청 전체와 토큰 예산에 맞는 카탈로그를 받으며, 최근 대화 발췌에는 생략 여부를 명시해요. 제목과 삽화의 참고 문맥, JEV의 문단 발췌에도 같은 기준을 사용하고 최종 요청은 각 모델의 전체 토큰 한도를 다시 확인해요.

Lua의 전체 대화 전달은 개별 스크립트 JSON 값과 예산을 구분해요. 대화 snapshot과 전체 메시지 읽기·수정은 원문을 자르지 않고 최대 64 MiB UTF-8로 전달하며, 개별 `json.encode`·외부 host 호출은 2 MiB 값 한도를 사용해요. 지속 VM은 실제 입력 크기에 맞춰 메모리와 JSON 처리 CPU 여유를 늘려 다음 턴을 받아요. Lua 메모리·Wasm 메모리의 최종 상한, 무한 실행 감시, 취소, 표시 중 메시지 쓰기 제한과 스크립트별 모델 권한은 유지해요.

작업이 완료되면 메시지·변수 결과·사용량과 필요한 화면 메타데이터가 영구 결과예요. 성공한 본문 실행은 전체 모델 입력·도구 이벤트를 정리해요. 보조 작업은 누적 입력·도구 진단을 제거하되 표시와 후속 이미지 작업이 쓰는 카탈로그·대상·설정은 남겨요. 성공한 도우미 작업은 누적 대화 입력과 편집·집필 snapshot을 제거하고 별도 저장된 대화 메시지를 사용해요. 실패한 작업은 필요한 재시도 입력을 보존해요. 요청·응답 진단도 완료 후 큰 본문 대신 모델·상태·사용량·오류 정보를 남겨요. 실패한 JEV 판정을 다시 수행하는 데 필요한 후보 본문은 별도로 유지해요.

`server/execution-snapshot.ts`가 완료 상태를 작은 표현으로 바꾸고, 필요한 새 작업에서는 현재 자료와 실제 메시지에서 실행 문맥을 다시 구성해요. SQL 컬럼 이름에 따라 JSON이 자동으로 펼쳐지는 DatabaseSync 하위 클래스나 텍스트 공유 트리거는 사용하지 않아요.

완료된 스트리밍 청크는 최종 원문·도우미 메시지와 중복 보관하지 않아요. 진행 중 재접속과 실패·중단 시 부분 출력용 청크는 유지하고, 완료 조회는 종료 상태와 저장된 최종 메시지로 전환해요.

상태 확인은 `server/run-projections.ts`의 경량 조회를 사용해요. Reader는 과거 실패 전체 대신 현재 페이지·최신 실패·활성 작업을 조회하고, 전체 작업 이력은 별도로 불러와요. 재진입 시 기본 분기를 확인하는 중간 응답은 내부에서만 사용하고, 저장된 읽기 위치의 페이지가 확정된 뒤 원고를 표시해요. 일반 원고의 논리 대화 구성은 원본·선택한 편집본의 무결성을 검증하되 Reader 문단 블록이나 번역 리비전을 만들지 않아요. 표시 변환은 전역 이벤트 커서가 아니라 원문·변수·자료·이미지 결과 변경에 반응해요. 원문 전체를 읽어야 하는 요청에서만 본문을 가져와요. 재작성·분기는 [독립 채팅 사본](CHAT-BACKUP.md)이며 과거 전체 실행의 결정적 재생을 제공하지 않아요.

## 복구 가능한 Anthropic Batch Run

일반 실시간 provider 요청은 서버가 끊기면 결과를 확정할 수 없으므로 기존처럼 active Run을 `interrupted`로 바꿔 자동 재전송하지 않아요. 반면 main 모델의 Anthropic Batch 실행은 `anthropic_batches`의 durable 상태가 있고 모든 외부 호출이 Batch 기록에 연결된 Run만 다시 `queued`로 되돌려 worker가 이어 받아요. 실시간 요약·판정·스크립트 모델 호출 등이 섞였으면 완료 기록이 있어도 자동 재진입하지 않아요. 원격 호출 완료와 로컬 재생 영수증 저장 사이의 중단을 구분할 수 없기 때문이에요. 안전하게 저장된 실시간 준비 호출이 있는 경우도 수동 확인 대상으로 남기는 보수적인 경계예요.

복구 worker는 Run을 처음부터 임의 재실행하는 대신 같은 `runMain`을 재진입해 Batch 라운드 순서와 요청 해시를 대조해요. 이미 `batchId`가 있는 라운드는 생성 API를 다시 호출하지 않고 조회부터 시작하고, 이미 결과 JSONL을 회수한 라운드는 저장된 결과를 다시 decode해요. provider tool call 뒤에 저장된 `tool_events`도 replay receipt로 사용하므로 읽기·도우미·문맥 도구나 terminal 제출을 중복 실행하지 않아요. `context.new` 같은 상태성 도구는 저장된 checkpoint를 바탕으로 실행 중 상태만 복원하고 새 checkpoint를 만들지 않아요. 거절된 도구 기록은 상태 변경으로 재생하지 않아요. Lua `editRequest`는 저장된 요청 순번·입력 hash·수정 prompt를 대조해 재사용하며, 같은 입력이라도 정상 후속 라운드는 별도로 실행해요. 도구 후속 요청의 크기 추정에는 실제 전송된 수정 prompt를 사용하고, 추정을 위해 Lua를 추가 실행하지 않아요. 실제 전송은 해당 라운드의 수정 결과와 공급자 연결 조건을 다시 확인해요.

새 Batch를 만들기 전에는 로컬 row를 `reserved`로 먼저 기록해요. `reserved` 상태는 아직 원격 생성 시도를 시작하지 않았으므로 재시작 후 안전하게 생성할 수 있어요. 원격 생성 시도 직전에 `creating`으로 바꾸며, `creating`인데 `batchId`가 없으면 응답 수신 전 서버가 끊긴 것인지 알 수 없으므로 자동 재전송하지 않아요. 중복 과금 방지가 자동 복구보다 우선이에요.

재개가 승인된 Batch Run은 기존 응답 스트림을 새 writer에게 인계해요. 일반 실행은 같은 스트림을 중복 생성할 수 없고, 이전 writer는 더 이상 기록하거나 종료할 수 없어요. 본문 스트림은 사용자 취소를 `cancelled`, 서버 종료를 `interrupted`로 구분해요.

성공해 source가 commit되면 복구에 필요했던 원본 Batch 결과 본문은 제거하고 Batch/attempt 식별 메타데이터만 남겨요.

## 이어 쓰기에 필요한 결과

Lua가 추가·수정·이동한 메시지는 `messageChanges` 변경분으로 남겨요. 사용자 원문 수정과 충돌하면 당시 source hash를 비교해 새 사용자 수정을 보존해요. 채팅 복사와 휴대용 복원에서는 이 메시지의 식별자도 새 자료에 맞게 연결해요.

로어 유지 상태는 `chat_lore_state`에 채팅 분기별 한 개를 저장해요. 읽은 구간과 현재 문맥만 이어가고 매 턴의 전체 모델 입력을 다시 보관하지 않아요. 원문이나 메모를 수정하면 이 상태의 출처를 확인해 무효화해요.

## 도우미 기록과 화면 전환

성공한 도우미 작업의 큰 도구 결과와 일반 작업 영수증 본문은 축약해요. 가정 장면 개정은 텍스트와 작은 메타데이터만 저장하고, 재전송 확인은 장면 ID·개정 참조를 사용해요. 새로운 AI 재작성은 당시의 거대한 입력 사본 대신 현재 작업의 문맥을 사용해요. 실패 작업은 재시도 판단에 필요한 결과를 유지해요.

도우미 화면 갱신 API는 이벤트 종류·순번만 조회하며 도구 결과 본문을 보내지 않아요. 요약 체크포인트는 실제 저장된 대화 메시지의 출처를 유지하고, 완료 후 제거되는 도구 payload의 사용하지 않는 해시 목록은 보관하지 않아요. 실행 중의 요약·문맥 전환에서는 실제 도구 결과와 완료된 변경을 전달하되 반복 실행하지 않는 기존 동작을 유지해요.

서버의 스트리밍 완료와 최종 메시지 조회는 도착 순서가 다를 수 있어요. 이미 표시한 응답은 브라우저에서 유지하고, 최종 메시지가 준비될 때 교체해요. 서버 청크 영구 보관으로 이 화면 문제를 해결하지 않아요.

## 현재 요약과 목록

문맥 checkpoint는 요약문·출처·유효성 판단에 필요한 plan만 저장하고 전체 Run 입력은 복사하지 않아요. 수동 요약 작업 입력은 종료 시 제거하며 편집 영수증은 작은 요청 해시/개정으로 남겨요. 활성 또는 재시도 가능한 작업이 참조하는 checkpoint는 작업 중 유지하고, 참조가 사라진 과거 후보는 정리해요.

프롬프트 목록 응답에는 ID·수정 번호·제목·역할만 담아요. 편집기나 채팅에 고정한 프롬프트는 선택된 항목을 상세 조회해요. 특정 모델/연결의 새 상태를 확인할 때 서재 전체를 내려받지 않아요.

## 실행과 브라우저의 경계

`server/run-executor.ts`는 본문 준비·모델 호출·판정·원자적 저장·종료 처리를 맡고, `server/app.ts`는 HTTP 경로와 후속 작업을 연결해요. 삽화와 보조 작업 큐는 서로 분리해 유지해요.

전송 버퍼가 차면 해당 구독자만 다음 페이지 읽기를 쉬고 `drain`에서 이어 보내요. 이미 수락한 페이지의 cursor는 전진하므로 같은 청크를 다시 보내지 않으며 다른 구독자나 모델 실행을 기다리게 하지 않아요.

도우미 화면은 현재 대화와 최근 네 대화를 메모리에 유지해요. 현재 대화에서 펼친 과거 메시지는 자르지 않고 캐시에서 비운 대화는 다시 조회해요. 관련 cursor와 요청 식별자도 함께 정리하며 이전 조회가 늦게 끝나 새 조회를 덮어쓰지 않아요.

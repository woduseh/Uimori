# 실행 입력의 수명

요청이 시작되면 필요한 현재 자료와 설정을 읽어 그 실행의 입력을 구성해요. 진행 중인 요청에 다른 편집을 섞지 않으며 DB 트랜잭션 안에서 외부 모델이나 카드 코드를 실행하지 않아요. 네이티브 Risu CBS·Lua·정규식 준비는 기존 실행 경계를 사용해요.

참고 이미지는 `RunSnapshot.requestImages`의 사용자 요청 첨부로 보존하고, 이미지 바이트는 `image_blobs`에 해시별 한 번만 저장해요. 보존본은 정지 이미지의 픽셀을 손실 없이 WebP로 정규화하며, 전송본은 긴 변 2048px·2MiB 이내로 따로 고정해요. 입력 파일과 보존본은 각각 64MiB 이내예요. 변환은 DB 트랜잭션 밖에서 기존 이미지 처리 동시 실행 제한을 공유하고, 최종 바이트와 요청의 귀속은 같은 수락 트랜잭션에 저장해요. 접수 재확인은 소비되거나 만료된 업로드 파일을 읽기 전에 기존 영수증을 확인해요.

미전송 초안의 본문은 입력 즉시 sessionStorage에 보관해요. IndexedDB에는 본문과 첨부 목록을 한 트랜잭션으로 저장하며, 이미지 파일은 추가하거나 제거할 때만 기록을 변경해요. sessionStorage의 세대와 수락 토큰으로 오래된 복구본이 최신 글이나 수락된 요청을 되살리지 않게 해요. Web Locks로 활성 탭의 초안 이름 공간을 소유하고 복제된 탭은 별도 공간에 복사해요. Web Locks 미지원 브라우저에서도 일반 새 탭은 분리하지만 sessionStorage를 복제하는 탭의 동시 편집은 분리되지 않을 수 있어요.

요청 이미지의 원본 메시지 식별자를 프롬프트 가공까지 유지해요. 선택된 `chat` 범위의 사용자 메시지만 첨부를 전달하며 CBS로 복사한 ChatML 문자열에는 이미지를 추정해 붙이지 않아요. Lua `editRequest`는 메시지 `id`를 보존해야 이미지의 재정렬을 지원해요. 이미지가 있는 메시지의 식별자가 유실·중복되거나 역할이 바뀌면 명확한 오류로 중단해요. 빈 텍스트의 이미지 턴과 삭제된 턴을 구분하고, 삭제된 이미지 턴을 다시 생성하지 않아요. 이미지를 쓰지 않는 기존 스크립트의 텍스트 계약은 유지해요.

네이티브 버튼·수동 트리거가 장면을 다시 저장할 때도 사용자 메시지별 첨부 연결을 보존해요. 여러 메시지를 한 장면으로 합쳐 첨부가 8장을 넘으면 저장 전에 중단하고 기존 본문·첨부·변수 상태를 유지해요. 서로 다른 장면에 각각 8장이 있는 대화는 그대로 이어갈 수 있어요.

모델 요청·후속 도구 상태·진단에는 이미지의 불변 참조만 보관하고, 실제 전송 직전에 고정된 첨부와 SHA-256을 확인해 바이트를 해결해요. Anthropic Batch 복구도 고정된 전송본으로 같은 요청 해시를 사용해요. 이미지 base64를 텍스트 토큰으로 계산하지 않으며 `conservative-dimensions-v1`의 해상도 기반 여유량을 별도로 더해요. 이는 모델별 공식 계산식이나 실제 청구값이 아닌 추정치예요. 전송 바이트 제한은 토큰 예산과 별도로 검사해요.

본문 입력의 대화 이력은 원문 검증이 반환한 새 항목을 사용해요. 곧 덮어쓸 전체 이력 사본이나 최근 장면을 선택한 뒤의 추가 복제는 만들지 않아요. 요청용 항목과 원본 snapshot의 분리는 유지해요. 같은 원문 객체의 텍스트가 그대로면 계산한 hash를 재사용하고, 텍스트가 달라지면 다시 계산해요. 제공된 hash와 현재 원문의 일치 여부는 계속 확인해요. 캐시는 객체 수명에 따르는 WeakMap이라 별도 만료 설정·무효화 서비스·원문 복제본을 만들지 않아요.

완성된 프롬프트의 모델 적합성은 설정한 토큰 예산으로 판단해요. 개별 텍스트 50만 자나 전체 프롬프트 150만 자 같은 별도 제한으로 정상 입력을 거절하거나 요약 모델을 호출하지 않아요. 자료 형상·식별자 검증과 조립된 입력의 메모리 보호 상한은 유지해요.

서재 프리셋 저장·수정, 현재 프롬프트 편집과 미리보기도 같은 큰 입력을 처리해요. CBS 표현식이 없는 긴 본문은 원문 그대로 통과하고, 실제 CBS 코드에는 시간·출력 메모리 감시를 적용해요. 평가 도구의 설명·진행 방향은 모델 출력 토큰 계약을 따르며 최종 본문에는 다른 저장 경로와 같은 원고 보존 상한을 적용해요.

일반 본문만 처리하는 동안은 CBS 평가용 카드 사본과 데이터베이스 뷰도 만들지 않아요. 같은 평가기에서 실제 CBS 구문이나 네이티브 별칭을 처음 만날 때 초기화하며, 이후 변수 쓰기·필드와 메시지 순서·역할·경고는 기존 평가 경로를 사용해요. 일반 텍스트에도 입력 길이 한도를 적용하고, 평가기는 해당 Worker 호출 수명 안에서만 사용해요. 요청 사이에 결과나 카드 사본을 보관하지 않아요.

부분 컨텍스트가 필요한 보조 작업은 `textTokenExcerpt`로 토큰 수를 계산해 원문의 앞이나 뒤를 발췌해요. 생략 표시도 토큰 예산에 포함하고 유니코드 문자를 중간에서 자르지 않아요. 로어 관련성 판단은 사용자 요청 전체와 토큰 예산에 맞는 카탈로그를 받으며, 최근 대화 발췌에는 생략 여부를 명시해요. 제목과 삽화의 참고 컨텍스트, 판단 모델의 문단 발췌에도 같은 기준을 사용하고 최종 요청은 각 모델의 전체 토큰 한도를 다시 확인해요.

본문은 유효한 이전 로어를 불러오고 필요한 대화 정리를 마친 뒤 필요하면 로어를 선별해요. 작은 목록이 입력 예산에 들어가면 전체를 판단해요. 큰 목록은 실행에 고정된 모든 첨부 자료의 선택 가능한 로어를 먼저 로컬 검색하고, 현재 요청·최근 대화와 관련된 순서로 본문 전체를 판단 모델의 입력 예산에 넣어요. 폴더나 앞쪽 첨부 위치로 검색 대상을 제한하지 않으며, 한 항목이 남은 예산보다 크면 다음 항목도 검토해요. 로컬 검색은 제목·본문의 단어 희소성과 반복 빈도, 한국어·일본어의 두 글자 단서를 사용하며 추가 API·임베딩 모델·영구 색인 설정은 없어요.

검색에는 채팅별 수정과 native 처리 후의 고정된 실제 로어를 사용해요. 공유 자료를 한 번 컴파일해 사용하고 검색 도중 최신 DB 본문을 섞지 않아요. 필요할 때 판단 모델을 한 번 호출하며, 모든 첨부와 기존 보존분이 선택 토큰·개수 예산을 공유해요. 이미 전문을 보존한 동일 자료는 신규 후보에서 제외해요. 최종 요청을 다시 측정해 실제 입력 한도를 넘는 신규 선택만 제외하고, 기존 보존분을 임의로 교체하지 않아요. 고정 로어는 기존 규칙대로 포함하고, 평가하지 않은 로어는 불필요 판정으로 기록하지 않으며 작문 모델의 조회 대상으로 남겨요. 새 기록은 장면 작업 박스의 로어 줄에 자동 선별 대상·판단·선택 개수를 함께 보여줘요. 실패한 선별은 별도로 표시하고, 이전 기록에 없는 숫자를 추정하지 않아요.

로어의 제목·설명도 채팅에서 수정한 실제 값으로 검색하고 판단해요. 공유 모듈의 같은 로어가 연결마다 다르면 기존처럼 한 로어 ID로 함께 선택하되, 모든 연결의 제목·설명·본문을 판단 대상으로 묶고 실제 포함될 본문들의 토큰 합을 예산과 선택 기록에 사용해요. 검색 후보를 만들기 위한 80토큰 본문 발췌는 만들지 않아요. 호출 전 입력 해시는 연결별 실제 내용을 모두 검증하며, 이미 저장된 선별 기록은 새 호출 없이 그대로 사용해요.

Lua의 모델 호출 대기는 프로바이더의 timeout과 호출자의 취소를 따르며, 별도의 5분 제한으로 먼저 끊지 않아요. Lua 자체 실행 시간과 유휴 세션 수명은 별개로 유지해요.

Lua의 전체 대화 전달은 개별 스크립트 JSON 값과 예산을 구분해요. 대화 snapshot과 전체 메시지 읽기·수정은 원문을 자르지 않고 최대 64 MiB UTF-8로 전달하며, 개별 `json.encode`·외부 host 호출은 2 MiB 값 한도를 사용해요. 지속 VM은 실제 입력 크기에 맞춰 메모리와 JSON 처리 CPU 여유를 늘려 다음 턴을 받아요. Lua 메모리·Wasm 메모리의 최종 상한, 무한 실행 감시, 취소, 표시 중 메시지 쓰기 제한과 스크립트별 모델 권한은 유지해요.

작업이 완료되면 메시지·변수 결과·사용량과 필요한 화면 메타데이터가 영구 결과예요. 성공한 본문 실행은 전체 모델 입력·재실행용 도구 이벤트를 정리해요. 보조 작업은 누적 입력·큰 도구 결과를 제거하되 표시와 후속 이미지 작업이 쓰는 카탈로그·대상·설정은 남겨요. 별도의 작은 도구 진단은 시작·종료 상태, 제한된 인자 미리보기·해시, 시간·오류·출력량을 보존해요. 성공한 도우미 작업은 누적 대화 입력과 편집·집필 snapshot을 제거하고 별도 저장된 대화 메시지를 사용해요. 실패한 작업은 필요한 재시도 입력을 보존해요. 요청·응답 진단도 완료 후 큰 본문 대신 모델·상태·사용량·오류·종료 시각과 관측 시간을 남겨요. 실패한 판단 모델 판정을 다시 수행하는 데 필요한 후보 본문은 별도로 유지해요. 각 장면은 마지막 본문 호출의 프로바이더 보고 요청·응답 토큰을 표시해요. 일반 API의 컨텍스트 비율은 보고된 입력 토큰을 우선 사용하고, 보고가 없으면 전송 전 로컬 추정치를 사용해요. Codex는 내부 여러 호출의 누적 사용량을 보고하므로 요청·응답 숫자는 누적량으로 표시하되 컨텍스트 비율에는 앱 전송 시점의 추정치를 사용해요. 분모인 입력 한도는 당시 사용자 설정과 출력 예약을 반영한 값으로, 프로바이더의 전체 최대 컨텍스트와 다를 수 있어요. 로컬 요청 추정에는 10% 여유를 포함하며 Codex 내부 후속 작업은 포함하지 않아요. 완료 후에도 이 작은 숫자·추정 방식·포함 로어의 이름·출처·전달 방식 메타데이터를 남기되 본문은 보관하지 않아요. 보존 이전 장면이나 가져온 원고에 없는 기록을 현재 설정으로 역산하지 않아요.

입력창 더보기의 **마지막 장면의 로어**는 마지막 완료 장면의 마지막 본문 요청에 실제 첨부된 기록을 보여줘요. 다음 요청의 로어 목록을 예측하지 않으며, 포함 기록 없음과 확인된 빈 목록을 구분해요. 같은 메뉴의 수동 압축은 기존 컨텍스트 작업의 수정 번호 검사·중복 요청 확인·취소 경계를 사용해요. 선택 입력인 4,000자 이내 우선순위는 해당 명령에 고정하고 그 압축의 요약 모델에만 전달해요. 강조할 근거를 고르는 옵션이며 새로운 사건·설정이나 지속 지시로 취급하지 않아요. 원문은 유지하고 정리할 구간이 있을 때만 모델을 호출해요.

완료되지 않고 끝난 본문 실행(실패·취소·중단·거절·부분 결과)도 끝나는 시점에 고정했던 대화 기록·자료·프롬프트 사본을 정리해요. 표시와 재시도에 쓰는 요청, 첨부 이미지, 모델 표시 이름, 컨텍스트 계획, 읽었던 장면의 ID 목록은 남겨요. 재시도는 현재 원문에서 컨텍스트를 다시 만들어요. 보존한 본문의 판단 모델 판정을 다시 받을 수 있는 실행만 고정 입력 전체를 유지해요.

완료된 실행은 작은 메타데이터만 남기고, 새 작업이 실제 컨텍스트를 요구할 때 현재 자료와 메시지에서 다시 구성해요. 로어 승계는 완료된 부모 실행을 되살리지 않고 채팅별 최신 로어 유지 상태의 원문·조상·메모 출처를 검증해요.

완료된 스트리밍 조각은 최종 원문·도우미 메시지와 중복 보관하지 않아요. 진행 중 재접속과 실패·중단 시 부분 출력용 조각은 유지하고, 완료 조회는 종료 상태와 저장된 최종 메시지로 전환해요. 서버를 시작할 때 화면이 더 이상 보여 줄 수 없는 본문 실행의 조각은 정리하되, 부분 결과 없이 취소된 실행은 작업 목록이 부분 응답을 보여 주므로 남겨요.

읽기 화면은 과거 실패 전체 대신 현재 페이지·최신 실패·활성 작업을 조회하고, 전체 작업 이력은 별도로 불러와요. 저장된 읽기 위치의 페이지가 확정된 뒤 원고를 표시해요. 중간 장면에서 다시 쓰기는 [독립 채팅 사본](CHAT-BACKUP.md)으로 만들어요. 마지막 완료 응답은 새 채팅에서 다시 요청하거나 기존 응답을 교체할 수 있으며, 교체는 새 본문 저장이 성공한 뒤에만 적용해요. 두 방식 모두 현재 설정과 해당 응답 직전의 대화·변수 체크포인트를 사용하고 과거 전체 실행의 결정적 재생을 제공하지 않아요.

장면 제목을 펼친 작업 박스는 호출 당시 모델 ID·표시 이름, 선택한 프롬프트·페르소나의 이름과 대화 요약 포함 여부를 바로 보여줘요. 프롬프트 ID·수정 번호와 페르소나 첨부 ID·수정 번호도 작은 `requestReceipt`에 보존하며 화면에서는 수정 번호를 생략해요. 선택 메타데이터는 해당 프롬프트·페르소나의 모든 본문이 전송됐다는 증거는 아니에요. 대화 요약은 준비된 plan의 요약문이 최종 전송 body에서 확인될 때만 포함 확인으로 표시하고, 요약한 장면 수만 남겨요. 원문·요약문·프롬프트 본문은 영수증에 저장하지 않아요. 예전 호출에 없는 메타데이터를 현재 서재에서 다시 채우지 않아요.

캐시와 로어 상세는 작업 박스를 처음 열 때 해당 attempt의 작은 SQL projection으로 읽어요. 캐시는 프로바이더가 보고한 읽기·쓰기 토큰이며 입력 토큰에 다시 더하지 않아요. 보고가 없는 값은 미확인으로 표시하고 캐시 설정으로 hit를 추정하지 않아요. 로어의 전체 본문 전달은 별도 꼬리표를 생략하고 읽은 구간·요약·포함 미확인 구분은 표시해요. 이전 요청의 로어는 **이전 요청 포함**으로 표시해요. 컨텍스트 비율과 입력 숫자에 로컬 추정치를 사용하면 **약**으로 구분하고, 토크나이저를 불러오지 못해 일반 추정치를 쓴 경우 막대 아래에 알려요. 막대의 세로선은 앞선 장면을 요약하기 시작하는 입력 비율이에요.

종료된 장면 해설(`status`) job은 새로 예약하거나 재시도하지 않아요. 기존 작업·결과·사용량 기록은 진단용으로 보존하지만 읽기 화면의 후속 작업에 포함하지 않으며, 서버 재시작도 해설 모델 호출을 재개하지 않아요. 물리 DB 스키마와 백업은 변경하지 않아요. [자료 보관 계약](DATA-MIGRATIONS.md#채팅-실행-설정)

이미지 배치 작업이 실제 판단 모델 호출 기록을 남긴 뒤 비정상 종료되면 결과를 알 수 없으므로 재시작 시 자동 재전송하지 않고 사용자의 재시도를 기다려요. 호출 기록이 없거나 합성 작업만 있었다면 대기열로 돌아가요. 같은 작업의 이전 시도와 현재 세대를 구별할 기록이 없는 경우에도 중복 호출을 피하기 위해 명시적 재시도가 필요해요.

## 복구 가능한 Anthropic Batch Run

일반 실시간 provider 요청은 서버가 끊기면 결과를 확정할 수 없으므로 기존처럼 active Run을 `interrupted`로 바꿔 자동 재전송하지 않아요. 반면 main 모델의 Anthropic Batch 실행은 `anthropic_batches`의 durable 상태가 있고 모든 외부 호출이 Batch 기록에 연결된 Run만 다시 `queued`로 되돌려 worker가 이어 받아요. 실시간 요약·판정·스크립트 모델 호출 등이 섞였으면 완료 기록이 있어도 자동 재진입하지 않아요. 원격 호출 완료와 로컬 재생 영수증 저장 사이의 중단을 구분할 수 없기 때문이에요. 안전하게 저장된 실시간 준비 호출이 있는 경우도 수동 확인 대상으로 남기는 보수적인 경계예요.

복구 worker는 Run을 처음부터 임의 재실행하는 대신 같은 `runMain`을 재진입해 Batch 라운드 순서와 요청 해시를 대조해요. 이미 `batchId`가 있는 라운드는 생성 API를 다시 호출하지 않고 조회부터 시작하고, 이미 결과 JSONL을 회수한 라운드는 저장된 결과를 다시 decode해요. provider tool call 뒤에 저장된 `tool_events`도 replay receipt로 사용하므로 읽기·도우미·평가 도구나 terminal 제출을 중복 실행하지 않아요. 거절된 도구 기록은 상태 변경으로 재생하지 않아요. Lua `editRequest`는 저장된 요청 순번·입력 hash·수정 prompt를 대조해 재사용하며, 같은 입력이라도 정상 후속 라운드는 별도로 실행해요. 도구 후속 요청의 크기 추정에는 실제 전송된 수정 prompt를 사용하고, 추정을 위해 Lua를 추가 실행하지 않아요. 실제 전송은 해당 라운드의 수정 결과와 프로바이더 연결 조건을 다시 확인해요.

새 Batch를 만들기 전에는 로컬 row를 `reserved`로 먼저 기록해요. `reserved` 상태는 아직 원격 생성 시도를 시작하지 않았으므로 재시작 후 안전하게 생성할 수 있어요. 원격 생성 시도 직전에 `creating`으로 바꾸며, `creating`인데 `batchId`가 없으면 응답 수신 전 서버가 끊긴 것인지 알 수 없으므로 자동 재전송하지 않아요. 중복 과금 방지가 자동 복구보다 우선이에요.

평가 도구의 세션은 같은 Run ID와 예약된 실행 시각을 사용하고, case·receipt ID는 세션과 도구 호출 ID에서 정해져요. 같은 실행 계약에서는 재시작 때 새로운 임의 값을 만들지 않으므로 preloaded 초기 요청과 후속 평가 영수증도 동일하게 재구성돼요. 평가·제출의 의미나 모델의 판단 단계를 합치지는 않아요. 임의 세션으로 시작한 Batch, 제거된 컨텍스트 도구를 사용 중인 Batch와 함께, 평가 도구 단순화 전 계약으로 예약·제출된 모든 대기·진행 중 평가 Batch는 구버전에서 완료한 뒤 업데이트해야 해요. `model-selected`·`preloaded`의 최종 제출 필수화, 고정 10회 비최종 도구 교환 한도, `source-bound`·찾아바꾸기 제거는 기존 요청·영수증을 새 계약으로 재해석하지 않아요. 과거 snapshot·receipt 원본은 읽을 수 있게 보존하지만 구형 평가 실행 엔진이나 버전별 실행 경로는 제공하지 않아요. 서로 다른 계약의 요청 해시를 무시하는 복구나 자동 재전송도 제공하지 않아요. 자세한 현재 계약은 [평가 도구](EVALUATION-TOOLS.md)를 봐요.

재개가 승인된 Batch Run은 기존 응답 스트림을 새 writer에게 인계해요. 일반 실행은 같은 스트림을 중복 생성할 수 없고, 이전 writer는 더 이상 기록하거나 종료할 수 없어요. 본문 스트림은 사용자 취소를 `cancelled`, 서버 종료를 `interrupted`로 구분해요.

응답 스트림은 도착한 글을 즉시 구독 화면에 전달하면서 주기적으로 저장해 다른 탭이나 재접속한 화면도 같은 순번으로 이어 받아요. 번역 작업도 진행 표시용 스트림을 가지며, 거절 뒤 재시도는 이전 시도와 구분해 보여 줘요. 번역 스트림은 완료·실패·취소·재시작 어느 쪽으로 끝나도 조각을 지우고 상태만 남겨요.

### 생각 요약

Gemini 모델로 도우미 호출을 보낼 때는 생각 요약을 함께 요청하고(`thinkingConfig.includeThoughts`), 모델이 응답을 만드는 동안 도착하는 요약을 응답 자리에 보여줘요. 한 호출이 길게 이어질 때 화면이 멈춘 것처럼 보이지 않게 하려는 표시예요. 요약은 응답 스트림의 메모리에만 두고 DB, 이벤트, 호출 기록 어디에도 저장하지 않아요. 호출이 끝나면 지우고, 서버를 다시 시작하면 사라져요. 프로바이더가 계산하는 요금은 요약을 받든 안 받든 생각 토큰 전체 기준이라 달라지지 않아요.

서명이 없는 요약 부분은 다음 호출에 다시 보내는 모델 응답에서 빼요. 요약은 표시용 글이고 모델의 추론 맥락은 서명이 들고 있어서, 요약을 되돌려 보내면 입력만 늘어나요. 서명이 붙은 부분은 받은 그대로 돌려보내야 해서, 그 부분의 글은 다른 모델 응답 부분처럼 연속 상태에 남아요. 프로바이더가 요약 요청이 든 호출을 HTTP 400으로 거절하면 그 작업은 요약 없이 한 번 다시 보내고, 남은 호출에서도 요청하지 않아요. 400의 원인이 요약 요청이 아니면 다시 보낸 호출도 같은 오류로 끝나요.

본편 실행과 Gemini가 아닌 프로바이더는 요약을 요청하지 않아요.

성공해 source가 commit되면 복구에 필요했던 원본 Batch 결과 본문은 제거하고 Batch/attempt 식별 메타데이터만 남겨요.

## 이어 쓰기에 필요한 결과

Lua가 추가·수정·이동한 메시지는 `messageChanges` 변경분으로 남겨요. 사용자 원문 수정과 충돌하면 당시 source hash를 비교해 새 사용자 수정을 보존해요. 채팅 복사와 휴대용 복원에서는 이 메시지의 식별자도 새 자료에 맞게 연결해요.

로어 유지 상태는 채팅별 한 개를 저장해요. 읽은 구간과 현재 컨텍스트만 이어가고 매 턴의 전체 모델 입력을 다시 보관하지 않아요. 원문이나 메모를 수정하면 이 상태의 출처를 확인해 무효화해요.

## 도우미 기록과 화면 전환

도우미 활동 조회는 도구가 끝나기 전에도 지금 실행 중인 도구를 보여 줘요. 대상 이름은 시작 기록에 남긴 대상 종류와 ID(또는 일괄 작업 개수)에서 조회 시점의 현재 제목으로 만들어요. 인자 미리보기 문자열은 보여 주지 않으므로, 장면 삭제가 지운 미리보기나 작업 완료 뒤 보존 정리가 비운 도구 세부가 활동 표시로 돌아오지 않아요. 지워진 장면과 숨긴 자료는 대상 이름 없이 도구 종류만 남아요.

화면은 시작과 끝을 호출 ID로 짝지은 뒤, 이어지는 읽기·목록·검색·확인 호출을 한 줄로 접어 본 장면과 자료 수, 그 밖의 조회 횟수를 보여 줘요. 펼치면 호출마다 대상과 도구 이름이 보여요. 저장하는 호출과 실패한 읽기는 따로 한 줄씩 남아요.

실행 중 상태 줄의 문구는 마지막 실행 중 단계에서 만들어요. 호출 순번은 조회가 돌려주는 최근 기록 창과 따로 작업 전체에서 세기 때문에 도구를 많이 쓴 긴 작업에서도 순번이 밀리지 않아요. 프로바이더 오류 뒤의 대기는 재시도 대기 기록에서 오며 다음 기록이 생기면 지난 일로 봐요. 펼친 기록은 호출의 결과를 말로 보여 주고 도구의 기술 이름만 그대로 둬요.

성공한 도우미 작업의 큰 도구 결과와 일반 작업 영수증 본문은 축약해요. 과거 가정 장면의 원문·요청·수정 이력은 읽기와 복사용으로 보존하며 새 생성·재작성·편집은 제공하지 않아요. 실패 작업은 재시도 판단에 필요한 결과를 유지해요.

도우미 화면 갱신 API는 이벤트 종류·순번만 조회하며 도구 결과 본문을 보내지 않아요. 요약 체크포인트는 실제 저장된 대화 메시지의 출처를 유지하고, 완료 후 제거되는 도구 payload의 사용하지 않는 해시 목록은 보관하지 않아요. 실행 중의 요약·컨텍스트 전환에서는 실제 도구 결과와 완료된 변경을 전달하되 반복 실행하지 않는 기존 동작을 유지해요.

서버의 스트리밍 완료와 최종 메시지 조회는 도착 순서가 다를 수 있어요. 이미 표시한 응답은 브라우저에서 유지하고, 최종 메시지가 준비될 때 교체해요. 서버 청크 영구 보관으로 이 화면 문제를 해결하지 않아요.

## 현재 요약과 목록

컨텍스트 checkpoint는 요약문·출처·유효성 판단에 필요한 plan만 저장하고 전체 Run 입력은 복사하지 않아요. 수동 요약 작업 입력은 종료 시 제거하며 편집 영수증은 작은 요청 해시/수정 번호로 남겨요. 활성 또는 재시도 가능한 작업이 참조하는 checkpoint는 작업 중 유지하고, 참조가 사라진 과거 후보는 정리해요.

프롬프트 목록 응답에는 ID·수정 번호·제목·역할만 담아요. 편집기나 채팅에 고정한 프롬프트는 선택된 항목을 상세 조회해요. 특정 모델/연결의 새 상태를 확인할 때 서재 전체를 내려받지 않아요.

Reader의 현재 채팅 설정도 첨부 자료의 ID·수정 번호와 역할별 모델 선택만 조회해요. 이 화면 갱신을 위해 카드 본문이나 전체 프롬프트를 다시 읽고 검증하지 않아요. 새 실행은 기존 snapshot 생성 경계에서 필요한 본문과 설정을 검증하고 고정해요.

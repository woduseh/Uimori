# 채팅 전체 백업과 복원

`uimori-chat-backup` v1은 **채팅 하나의 모든 분기와 관련 기록을 새 채팅으로 복원하는 JSON**이에요. 기존 채팅이 있는 작업공간에서도 가져올 수 있고, 원본 채팅과 복원한 사본 모두 다시 백업할 수 있어요. DB 전체를 바꾸는 작업공간 archive나 한 분기의 글만 담는 [본문 JSON](CHAT-TRANSCRIPT.md)과 용도가 달라요.

## 화면과 API

- **채팅 메뉴(⋯) → 채팅 백업 내보내기**에서 `<채팅 제목>.uimori-chat.json`을 받아요. 읽고 있는 분기뿐 아니라 그 채팅의 모든 분기를 담아요.
- **설정 → 데이터 관리 → 채팅 백업 가져오기**에서 파일을 선택하고 제목·분기 수·본문 수를 확인한 뒤 **새 채팅으로 가져오기**를 눌러요. 파일 선택만으로 복원하지 않아요.
- `GET /api/chats/:id/backup`은 백업을 반환해요. `POST /api/chats/import-backup`은 `{ backup, idempotencyKey }`를 받아 `{ chat, created, branches, sources }`를 반환해요.
- 같은 파일을 다시 선택해 가져오면 다른 ID의 새 채팅을 만들어요. 응답 유실로 같은 요청 키를 재전송하면 이미 만든 채팅을 `created: false`로 반환해요. 같은 키에 다른 파일을 보내면 `CHAT_BACKUP_IMPORT_CONFLICT`로 거절해요.

파일의 최상위 필드는 `format`, `version`, `createdAt`, `chatId`, `records`예요. `records`는 명시적으로 정의한 공개 collection과 필드를 사용하며 SQLite 표나 SQL을 파일에서 지정할 수 없어요. JSON 크기는 256MiB, collection별 레코드는 최대 100,000개예요. 다른 형식·지원하지 않는 버전·알 수 없는 필드·빠진 필수 필드는 거절해요.

## 보존 범위

| 범위 | 포함하는 기록 |
| --- | --- |
| 글과 전개 | 모든 분기, 요청·Run·예약 snapshot, 원문과 수정 이력, 번역·보조 작업 결과, 사용자 메모·정정, 구성과 집필 연결 |
| 실행 증거 | 전송 attempt·사용량, 모델 입력·도구 이벤트, 공개 답변 스트림과 중단 상태, 문맥 checkpoint·활성 연결·명령 영수증 |
| 자료와 이미지 | 참조하는 공유 자료·프롬프트의 불변 개정, 모델·연결 정의, 채팅 이미지 에셋, 삽화와 참조 설정 |
| 패키지 동작 | 상태·journal·의존성·출력, 추첨과 원래 entropy 증거, 판정 기회·실행 진행·다음 요청 예약 |
| 도우미와 편집 | 해당 채팅의 도우미 대화·작업·산출물·권한·변경 영수증, 참조한 서버 초안·제안·미적용 JSON, 채팅 로어 변경·옵션·위임 |
| 채팅 설정 | 프로필·고정 프롬프트/본문 모델 선택, 봇 소속과 채팅 폴더, 관련 환경의 보관 기록 |

다른 채팅의 이력이나 관계없는 서버 초안을 함께 가져오지 않아요. 브라우저에만 남아 서버에 동기화되지 않은 입력은 파일에 포함되지 않아요.

새 채팅에 속해야 하는 ID와 그 ID를 참조하는 연결·파생 hash만 다시 만들어요. 원문·번역·요청·메모와 사용자 JSON의 일반 문자열, 저장한 상태 값·추첨 결과·계산 당시 입력은 원래 값을 유지해요. 내용을 새로 생성하거나 추첨하지 않아요. 원 요청 전체를 보관하지 않은 영수증의 digest는 역사 증거로 유지하며 새 요청의 digest로 간주하지 않아요.

진행 중이던 요청은 복원본에서 중단 상태로 정리해요. 완료 여부가 불확실한 외부 호출을 자동 재전송하지 않으며, 백업·복원 자체도 모델이나 이미지 생성기를 호출하지 않아요. 원본 DB의 진행 상태는 내보내기로 바뀌지 않아요.

## 기존 작업공간과 함께 복원하기

현재 작업공간의 전역 프롬프트·역할 모델·삽화 설정을 유지해요. 원본 환경은 `chat.backup-environment` 기록으로 보관하며 복원한 사본을 다시 백업할 때도 남아요. 이 기록에는 실행 비활성화 정규화 전의 연결·삽화 선택값을 남기므로 원래 생성기와 자동 생성 여부도 유지돼요. 다만 프로바이더의 `credentialEnv`·`catalogCredentialEnv`와 ComfyUI의 `authorizationEnv` 같은 인증 참조는 제거해요. 내보내기는 임시 DB에 이 보관 기록을 추가하므로 원본 DB를 바꾸지 않아요.

환경 기록은 참고용이며 목적지 실행 설정에 적용하지 않아요. 실제 복원 레코드는 기존의 인증 제거·실행 비활성화 정규화를 거치고 목적지 전역 설정은 유지해요. 채팅에 고정한 작문 프롬프트·본문 모델 ID는 채팅 설정으로 유지하며, 고정하지 않은 새 실행은 목적지의 전역 설정을 사용해요. 과거 Run은 당시 snapshot을 보존해요.

참조 자료가 없으면 필요한 불변 개정을 가져오고, 같은 ID·revision의 저장 내용이 같으면 재사용해요. 같은 ID·revision의 내용이 다르면 `CHAT_BACKUP_LIBRARY_CONFLICT`로 전체 가져오기를 거절해요. 기존 공유 자료의 표시·분류·폴더 선택은 목적지 설정을 유지하며 원본의 숨김·분류·폴더 metadata는 환경 기록에 보존해요. 원본의 참조와 목적지의 현재 선택을 섞어 과거 실행을 재해석하지 않아요.

비밀키와 인증 파일은 백업으로 옮기지 않아요. 새로 가져온 연결은 비활성 상태이며, 다음 실제 실행에는 목적지에서 유효한 연결·인증·모델 설정이 필요해요. 이미 있는 연결 정의와 전역 역할 선택을 덮어쓰지 않아요.

가져온 전역 프롬프트 초안은 기존 편집기와 분리한 보관본이에요. 원본 전역 개정 번호가 목적지보다 높아도 초안과 기준본·원시 입력을 유지해요. 현재 저장본과 비교해 명시적으로 다시 연결하기 전에는 저장·되돌리기·자동 갱신을 막아요. 자세한 계약은 [백업의 편집 초안](CHAT-BACKUP-DRAFTS.md)에 있어요.

## 검증과 실패 경계

파일을 독립 임시 DB에서 검증하고 정규화한 뒤, 새 소유 ID와 파생 hash를 만든 사본도 다시 검증해요. 두 검증이 끝난 뒤에만 목적지 transaction에서 새 채팅과 관련 기록을 함께 붙여요. 이 단계에서 공유 자료 충돌이나 연결 무결성 오류가 나도 새 채팅·자료 일부만 남기지 않아요. 내보내기 검증 실패를 작은 본문 파일로 대신 성공 처리하지 않아요.

파일 버전은 SQLite schema 버전과 독립이에요. 현재 구현은 v1 공개 형식과 v15 저장 구조 사이의 명시적 adapter를 사용해요. DB 구조가 바뀌면 adapter 또는 지원 형식의 reader를 함께 갱신해야 하며, 정식 배포 전 모든 개발 버전 파일의 영구 호환을 약속하지 않아요. 지원하지 않는 버전은 명시적으로 거절해요.

구현은 `core/chat-backup.ts`, `server/chat-backup.ts`와 `server/chat-backup-*.ts`에 있어요. `tests/chat-backup.test.ts`, `tests/chat-backup-context.test.ts`, `tests/chat-backup-helper.test.ts`는 반복 복원·사본 재백업·소유권/hash·원값 보존·충돌 rollback·분리 초안을 확인해요. 통합 검증 결과는 [안정화 기록](STABILIZATION-2026-09-11.md)과 [CURRENT](../project-plan/CURRENT.md)에 기록해요. 파일 계약 검증은 실제 공급자 호출이나 실제 모델 의미 품질의 증거가 아니에요.

# 독립 채팅 백업

독립 채팅 백업은 대화를 다른 작업실로 옮기거나 안전하게 보관하여 언제든 다시 읽고 이어 쓸 수 있도록 돕는 기능이에요. 대화 메시지와 설정뿐 아니라 연결된 봇, 페르소나, 이미지까지 자립 가능한 하나의 패키지로 묶어 저장해요.

## 독립 채팅 백업의 내용과 특징

### 백업에 포함되는 데이터
- **본문 및 대화 기록**: 장면 메시지, 사용자 요청, 완료된 번역, 작성자 메모, 카드 변수.
- **연결 자료**: 연결된 봇, 페르소나, 모듈, 고정 프리셋 원본.
- **참고 이미지**: 사용자 요청에 첨부되었던 참고 이미지의 원본 보존본과 모델 전송용 변환본.
- **문맥 및 구성 설정**: 이야기 구성과 장면 연결, 고정 옵션, 채팅 전용 로어북, 각 장면의 요청·본문 문맥 포함/제외 설정, 원작 참고 설정.
- **장면 이름과 책갈피**: 사용자가 직접 지정한 장면 이름, 책갈피(이름, 메모, 짧은 인용구, 해당 장면 위치).

### 백업에서 제외되는 데이터
- **임시 및 중간 기록**: 자동 요약, 내부 실행 기록, 진행 중인 작업, 서버 임시 초안, 일회성 실행 옵션.
- **파생 산출물**: 생성된 원작 참고문, 구성의 실행 및 검토 기록.
- **미전송 이미지**: 브라우저에만 남아 있던 미전송 이미지 초안.
- **과거 편집 판본**: 원문 편집기의 과거 저장본 이력(현재 최종 원고 판본만 보존돼요).
- **기기 종속 설정**: 각 브라우저 기기별 읽기 위치.
- **인증 정보**: API 키와 프로바이더 연결 정보는 포함되지 않으며, 가져온 작업실에 등록된 모델을 사용해요.

## 백업 내보내기와 가져오기

### 내보내기 방법
- **접근 경로**: 채팅 화면의 **채팅 내보내기 → 채팅 백업**을 선택해요.
- **파일 형식**: `.chat.uimori` 확장자의 압축 아카이브 파일로 다운로드돼요.
- **대상**: 현재 선택한 채팅 1개를 내보내요.

### 가져오기 방법
- **접근 경로**: **설정 → 데이터 관리 → 백업 파일 가져오기**를 열어요 (일반 자료 백업과 같은 입구를 사용해요).
- **검토 및 등록**:
  1. 파일을 선택하면 시스템이 파일 내용을 자동으로 분석해 채팅 제목과 본문(장면) 수를 미리보기로 보여줘요.
  2. 내용을 확인한 뒤 **새 채팅으로 가져오기**를 누르면 등록이 완료돼요.
  3. 잘못된 파일인 경우 가져오기 화면에 명확한 오류를 표시하고 다시 선택할 수 있게 안내해요.
- **가져오기 원칙**:
  - 가져오기는 항상 **새 ID의 자료와 새 채팅**을 생성해요. 기존 자료의 이름이나 수정 번호와 비교해 덮어쓰거나 강제로 병합하지 않으며, 묶음 내부의 상호 참조만 새 ID로 안전하게 연결해요.
  - 동일한 통신 요청을 재전송할 때는 중복 사본을 만들지 않지만, 사용자가 새 가져오기 작업을 시작하면 독립된 새 사본을 생성해요.
- **용량 한도**:
  - `.uimori` 아카이브 파일은 전체 최대 512MiB, 메타데이터 최대 32MiB까지 지원해요.
  - 기존 JSON 형식 백업 파일도 계속 가져올 수 있으며 전체 최대 256MiB까지 읽을 수 있어요.
  - 저장된 장면이나 메모 개수만으로 복원을 거절하지 않으며, 개별 원문·번역의 공통 저장 한도(2,000,000자)를 유지해요.

## 읽기용 원고 내보내기

대화를 텍스트 문서로 깔끔하게 정리해 소장하거나 읽고 싶을 때는 원고 내보내기를 사용해요.

- **접근 경로**: **채팅 내보내기 → 원고 내보내기**를 선택해요.
- **범위 선택**: 전체 채팅을 내보내거나 시작 장면과 끝 장면을 지정해 원하는 구간만 `.md` 파일로 저장할 수 있어요. 첫 메시지가 있는 봇인 경우 첫 메시지 포함 여부도 선택할 수 있어요.
- **원문과 번역**: 원문은 현재 저장된 최신 수정본을, 번역은 해당 원문과 연결된 유효한 완료 번역만 담아요.
  - 선택한 범위 내에 유효한 번역이 없는 장면이 포함되어 있으면 해당 장면을 안내하고 다운로드를 거절해요 (원문을 임의로 섞거나 장면을 조용히 누락하지 않아요).
- **텍스트 형식**: 사용자 요청, 작업 기록, 메모는 제외하고 본문 텍스트만 빈 줄로 연결해요. HTML이나 Risu 상태창 표기도 텍스트 그대로 보존돼요.
- **주의사항**: 원고 파일은 순수 읽기·편집용 마크다운 파일이며, 채팅 백업 복원이나 이어 쓰기를 위한 가져오기 파일이 아니에요 (이미지 묶음이나 EPUB 형식은 지원하지 않아요). 내보내기 작업은 모델 호출이나 저장된 자료의 변경을 일으키지 않아요.

## 채팅 복사와 다시 쓰기

### 특정 장면까지 복사
- **이 장면까지 새 채팅으로 복사**: 원고의 원하는 장면에서 이 메뉴를 누르면 해당 지점까지의 모든 대화를 포함하는 독립된 새 채팅이 생성돼요. 복사 이후의 수정이나 삭제는 원본 채팅에 아무런 영향을 주지 않아요.
- **사본 제목 규칙**: 기본 제목은 **원래 제목 · 사본 1**, **원래 제목 · 사본 2**처럼 현재 동일한 제목을 가진 사본 중 가장 큰 번호 다음 번호로 자동 부여돼요. 사본을 다시 복사하거나 `· 새 이야기`, `(사본)` 등이 붙은 제목에서 복사해도 접미사가 지저분하게 겹쳐 붙지 않아요. 사용자가 직접 수정한 제목은 그대로 유지돼요.
- **페르소나 유지**: 복원과 복사는 원본 채팅의 페르소나 선택 상태를 그대로 따르며, 페르소나를 선택하지 않았던 상태도 그대로 보존돼요 (현재 봇이나 폴더의 기본 페르소나로 임의 교체하지 않아요).

### 마지막 응답 다시 쓰기와 기존 응답 교체
마지막으로 완료된 응답을 다시 생성할 때는 두 가지 방식을 선택할 수 있어요.

- **기존 응답 교체**:
  - 직전 응답 직전까지의 대화 문맥과 카드 변수 체크포인트를 바탕으로 현재 자료와 모델 설정을 사용해 새로 생성해요.
  - 새 본문이 서버에 성공적으로 저장되었을 때만 기존 응답을 교체해요. 생성이 실패하거나 취소·거절되면 기존 본문과 상태를 그대로 유지해요.
  - 대기 중에 사용자가 기존 원문을 직접 수정했다면 새 수정본을 덮어쓰지 않고 교체를 안전하게 거절해요.
  - 교체 완료 시 기존 응답의 원문과 완료 번역, 작업 기록은 내부 저장 이력에 남지만 현재 원고에는 새 응답만 표시돼요 (기존 응답에 딸린 미완료 번역이나 이미지 작업은 취소돼요).
- **새 채팅에서 다시 요청**:
  - 기존 대화를 건드리지 않고 새로운 독립 채팅 사본을 만들어 그곳에 새 응답을 생성해요.
- **중간 장면 다시 쓰기**:
  - 중간 장면은 이후 대화를 실수로 덮어쓰지 않도록 반드시 독립 채팅 사본에서만 다시 요청할 수 있어요. 당시의 변수 체크포인트가 없다면 미래 상태를 과거에 섞지 않고 기본 상태에서 안전하게 시작해요.

## 에이전트 및 구현 참고

### `.chat.uimori` 아카이브 구조와 BLOB 중복 제거
- **파일 포맷**: `uimori-archive` 버전 1의 무압축 ZIP 컨테이너를 사용해요.
- **내부 구조**:
  - 루트의 `uimori-personal-chat` v1 메타데이터 JSON
  - 이미지 바이너리 파일: `images/<SHA-256>.bin`
- **BLOB 중복 제거**: 자료 대표 이미지, 본문 첨부 이미지, 장면에 표시된 삽화는 바이트 해시(SHA-256)로 관리되며, 동일한 바이트는 ZIP 파일 안에 단 한 번만 저장해요.
- **원자적 등록**: 서버에 파일을 업로드하고 이미지 검증과 WebP 변환을 마친 뒤 검토 결과를 보여주며, 확인 시 원자적으로 등록해요. 대용량 이미지를 base64 JSON 문자열로 직렬화하지 않아요.
- **API 계약**: 새 채팅 백업은 archive 형식으로만 생성돼요. 레거시 JSON 신규 출력 API인 `GET /api/chats/:id/backup`는 제거되어 404를 반환해요 (단, 기존 JSON 백업 파일의 복원은 계속 지원해요). 본문 교환용 transcript JSON 내보내기는 별도 기능으로 유지돼요.
- **다중 채팅 호환**: 백업 내보내기는 선택한 1개 채팅만 담지만, 메타데이터의 `chats` 배열 구조를 유지하므로 과거 다중 독립 채팅 백업 파일도 정상적으로 복원할 수 있어요.

### 준비(Staging) 파일 라이프사이클과 동시성 보호
- **준비 파일 정리**: 복원이 성공하면 준비 단계에서 생성된 임시 파일은 즉시 정리돼요.
- **만료 정책**: 완료되지 않은 준비 결과는 24시간 후 만료되며, 쓰기가 열린 서버 시작 시점과 실행 중 매시간 자동으로 정리돼요 (완료한 같은 요청은 임시 파일이 없어도 영수증으로 확인할 수 있어요).
- **동시성 잠금**: 백업 준비 작업은 다른 Risu 파일이나 자료 백업 준비 작업과 동시에 실행되지 않고 프로세스당 1건씩 순차 실행돼요. 클라이언트 연결이 끊기면 진행 중이던 준비 산출물을 즉시 정리해요.
- **이미지 참조 카운팅**: 독립 사본과 복원은 불변 BLOB을 재사용하되 원본 채팅의 이미지 행에 직접 의존하지 않아요. 원본 채팅을 삭제하더라도 사본이 참조하는 이미지는 보존되며, 마지막 소유 참조가 제거될 때 기존 이미지 정리 경로를 통해 안전하게 회수돼요.

### 재시도 및 복사 API (`/api/runs/:id/retry`)
- **API 엔드포인트**: `POST /api/runs/:id/retry`
- **파라미터**: `mode`는 `'replace'` 또는 `'copy'` (생략 시 기존 사본 생성 규칙 적용). 실패한 교체 요청을 다시 시도하면 교체 대상으로 예약했던 마지막 응답을 그대로 사용해요.
- **멱등성 보장**: 복사 결과를 확인하는 도중 오류가 발생하더라도 이전 요청 키를 유지해 중복 사본 생성을 방지해요. 대상 사본이 이미 삭제되었음이 확인되면 안내 후 새 복사를 시작할 수 있어요.
- **외부 부수효과 방지**: 복원 과정에서 외부 모델 호출이나 Risu 카드 콜백을 재실행하지 않아요.
- **관련 구현**: `server/chat-backup.ts`, `server/chat-copy.ts`, `server/chat-fork.ts`, `server/run-retry.ts`, `server/chat-media.ts`.
- **전체 작업실 복원**: API 키와 프로바이더를 포함한 전체 작업실 복구는 [DB 스냅샷](DATA-MIGRATIONS.md)을 사용하고, 기기별 읽기 위치와 책갈피 연동은 [읽기 위치와 책갈피](READING-STATE.md)를 참고하세요.

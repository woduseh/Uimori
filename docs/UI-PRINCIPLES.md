# UI 원칙 · 데스크톱과 모바일

2026-09-08 사용자가 요청한 방향을 구체화한 v1.1 설계 기준이에요. **내용은 바로 보이고, 자주 쓰는 행동은 가까이 있으며, 나머지는 필요할 때 열려요.** ChatGPT처럼 간결하고 익숙한 사용 경험을 지향하며 Uimori의 데스크톱·모바일 창작·자료·모델 설정에 적용해요. 두 환경에서 기능의 의미·이름·아이콘·행동의 묶음을 공유하고, 사용 가능한 화면 폭과 입력 방식에 맞춰 배치를 바꿔요. 이 문서는 Uimori의 설계 기준이며 ChatGPT의 현재 화면을 실측하거나 그대로 재현한 명세는 아니에요.

> 2026-09-08 후속: 채팅 리더·입력창·탐색·서재 상세의 배치는 [UI 설계 v2](UI-DESIGN-V2.md)에서 한 화면 단위로 다시 판단했어요. 이 원칙 문서의 판단 순서·아이콘 규칙·시작값은 유효하고, v2는 "완료는 상태가 아니다"와 세 층(상시·근접·열어서) 모델을 더해요. v2는 제안이며 구현·검증 전이에요.

원칙과 후속 적용안을 기록한 문서예요. 설정·서재·연결·데이터는 [공통 UI 구현 결과](../project-plan/UI-COMPACT-IMPLEMENTATION.md), 채팅 설정·고급 패키지·프롬프트·장면 메뉴는 [상세 화면 구현 결과](../project-plan/UI-DETAIL-IMPLEMENTATION.md)에서 적용과 검증을 확인해요. 전체 상태와 실기기 검증은 [CURRENT](../project-plan/CURRENT.md)에서 별도로 확인해요. 기존 [서재 계약](LIBRARY.md), [개편 계약](../project-plan/REDESIGN.md), 원문·실행·저장 계약을 함께 유지해요.

설정·서재·연결과 모델의 실제 배치, 메뉴·빈 화면·편집 복귀와 아이콘 후보는 [화면 설계](UI-SCREEN-DESIGN.md)에 구체화해요. 이미지 시안과 후속 제품 구현을 구분해요.

## 판단 순서

선택이 충돌하면 **읽기·입력·접근성과 작업 보호 → 주된 행동의 발견 → 화면의 간결함 → 시각적 통일** 순서로 결정해요. 화면을 얇게 만들기 위해 필요한 상태를 감추거나 글자와 터치 영역을 무리하게 줄이지 않아요. 색감·서체·읽기 설정을 존중하면서 정보의 우선순위와 배치를 먼저 정리해요.

## 공통 원칙

| 원칙 | 적용 기준 |
| --- | --- |
| 한 화면에서 할 일을 분명하게 해요 | 현재 위치를 알려주는 제목은 한 번 표시해요. 같은 작업 영역에서 주된 행동 하나를 강조하고 나머지는 보조 버튼이나 메뉴로 구분해요. 여러 자료 행의 개별 행동까지 하나로 제한하는 규칙은 아니에요. |
| 내용이 조작부보다 먼저 눈에 들어와요 | 채팅은 본문과 입력창, 서재는 자료, 설정은 현재 설정 내용을 중심으로 배치해요. 반복 설명·개수·폴더 표시를 줄이고 같은 생성 행동을 헤더와 빈 화면에서 경쟁시키지 않아요. |
| 자주 쓰는 기능은 직접, 관리는 한 번 열어서 써요 | 보내기·새 채팅·검색·저장처럼 해당 화면의 주된 기능은 바로 접근해요. 정렬·보기 전환·선택·폴더 관리는 역할이 드러나는 메뉴에 모아요. 자주 쓰는 보조 기능을 메뉴 안의 또 다른 메뉴에 묻지 않아요. |
| 화면 폭에 맞춰 작업 공간을 구성해요 | 좁은 화면에서는 목록→상세로 한 단계씩 이동하고, 넓은 화면에서는 현재 작업에 도움이 되는 목록과 상세를 나란히 보여줘요. 짧은 선택은 메뉴, 긴 편집은 충분한 본문 공간을 확보한 화면을 사용해요. |
| 한 줄의 구성은 의도적으로 정해요 | 제목과 행동, 탭, 검색처럼 같은 역할끼리 정렬해요. 공간 부족으로 버튼 하나만 다음 줄에 남지 않도록 축약·메뉴 전환·전체 그룹의 세로 배치를 명시해요. 긴 본문과 필드 설명은 자연스럽게 줄바꿈해요. |
| 조용한 화면에서도 필요한 상태는 보여요 | 진행 중 작업·취소·실패·재시도 판단에 필요한 불확실 상태·미저장 변경은 발견할 수 있게 유지해요. 짧은 상태 요약에서 상세를 열 수 있게 하며, 과거 작업 로그가 기본 화면을 계속 차지하지 않게 해요. |
| 돌아왔을 때 작업을 이어갈 수 있어요 | 상세·메뉴·편집에서 돌아오면 가능한 한 읽던 위치·초점·검색·폴더·초안을 복원해요. 뒤로가기와 닫기는 일관되게 작동하고, 미적용 초안을 버리는 경우는 기존 보호 절차를 유지해요. |
| 말과 모양만으로 행동을 알 수 있어요 | 같은 기능에는 같은 이름·아이콘·행동의 묶음을 사용해요. 탭은 선택 상태를, 버튼은 행동을 표현해요. 아이콘 단독 사용은 아래의 의미·대상 기준으로 판단하며, 아이콘 버튼에는 접근 가능한 이름을 제공해요. |

## 같은 원칙을 화면 폭에 맞춰 적용해요

데스크톱의 넓은 공간은 읽기 폭·목록 탐색·편집과 미리보기에 사용해요. 기본 노출할 제어는 사용 빈도와 현재 작업에 필요한지를 기준으로 고르고, 사용자의 사이드바·보기 선택을 유지해요. 자주 반복하는 행동은 넓은 화면에서 같은 그룹의 도구막대로 바로 접근하게 할 수 있어요. 사용 빈도가 낮은 관리 기능은 공통 메뉴에 남겨요.

| 영역 | 넓은 화면 | 좁은 화면 | 공유할 의미와 동작 |
| --- | --- | --- | --- |
| 전체 탐색 | 이름이 있는 사이드바, 사용자가 접고 펼치기 | 같은 탐색 항목을 여는 drawer | 항목 이름·아이콘·순서·현재 위치 |
| 설정 | 왼쪽 항목 목록과 오른쪽 상세 | 항목 목록→상세, 뒤로가기로 복귀 | 항목 분류·이름·입력과 저장 규칙 |
| 서재 | 폴더 탐색과 자료 목록, 필요할 때 상세 | 폴더 선택과 자료 목록, 항목을 열어 상세 | 검색·폴더 범위·보기 선택·관리 메뉴 |
| 짧은 선택 | 대상 가까이에서 여는 메뉴나 popover | 메뉴 또는 하단 시트 | 선택지·현재 선택·적용과 취소 |
| 긴 편집 | 읽을 수 있는 폭의 편집 화면, 도움이 될 때 미리보기 병치 | 본문을 확보한 상세 화면 | 필드 순서·초안·오류·저장과 취소 |
| 채팅 | 적절한 읽기 폭의 본문과 입력창, 필요할 때 보조 패널 | 본문과 입력창 중심, 보조 내용은 열어서 보기 | 메시지별 행동·모델 확인·생성과 취소·이력 귀속 |

넓은 모니터에서도 원고와 긴 폼을 화면 전체 폭으로 늘리지 않아요. 좁힌 데스크톱 창과 글자 확대도 같은 전환 규칙을 따르며, 기기 이름이나 운영체제만으로 배치를 결정하지 않아요. 폭이 바뀌어도 선택·검색·초안·진행 중 작업을 초기화하지 않고 초점이 숨은 요소에 남지 않도록 해요.

## 공통 아이콘 사용 규칙

**익숙한 조작은 아이콘으로 줄이고, 개념·선택값·중요한 결과는 이름으로 전달해요.** 직관성은 모양·위치·대상을 함께 보고 판단해요. 메뉴를 여는 입구는 아이콘으로 간결하게 만들 수 있고, 열린 메뉴에서는 아이콘과 행동 이름을 함께 보여줘요.

| 정보의 종류 | 예 | 기본 표현 |
| --- | --- | --- |
| 익숙한 공통 조작 | 닫기·뒤로가기·검색·더보기·복사 | 대상이 분명한 위치에서 아이콘 단독 사용 가능 |
| 문맥이 필요한 행동 | 추가·편집·목록 새로고침·보기 전환·보내기·생성 중지 | 대상 바로 옆에서 사용. 추가할 대상이나 행동 범위가 여러 개면 이름 또는 선택 메뉴 제공 |
| 앱의 개념과 탐색 항목 | 봇·페르소나·모듈·프롬프트·모델·에이전트 | 아이콘과 짧은 이름. 아이콘은 항목을 찾는 표식으로 사용 |
| 현재 선택과 중요한 상태 | 모델·페르소나 이름, 미저장 변경·실패·실행 불확실 | 실제 값이나 짧은 상태 문구 유지. 색·배지·아이콘만으로 전달하지 않기 |
| 결과·범위의 확인이 필요한 행동 | 다시 생성·원문 직접 수정·조회 로어 제외·삭제·백업 복원 | 실행을 결정하는 위치에서 행동 이름과 필요한 범위를 확인할 수 있게 하기 |

- **아이콘 어휘를 공유해요.** 현재 사용하는 `lucide-react` 계열을 이어가고, 같은 의미의 아이콘·크기·선 굵기·상태 표현을 양쪽 화면에서 공유해요. 실제 구현에서는 공통 제어부터 재사용하며 화면마다 별도 아이콘 체계를 만들지 않아요.
- **의미의 충돌을 먼저 정리해요.** 최초 조사에서는 서재와 프롬프트가 `BookOpen`, 연결과 모델 및 에이전트가 `Plug`를 공유했어요. 공통 구현의 `web/ui-icons.ts`에서 주요 개념별 도상을 구별하고 이름을 함께 유지해요. 대상만 다른 편집·더보기처럼 의미가 같은 공통 행동은 같은 아이콘을 재사용해요.
- **아이콘 단독 탐색은 제한해요.** 데스크톱 사이드바도 기본은 아이콘과 이름이에요. 사용자가 접은 상태는 대상이 구별될 때 아이콘을 남길 수 있으며, 전체 이름이 있는 탐색으로 쉽게 돌아갈 수 있어야 해요. 공간 부족을 이유로 고유 개념의 이름부터 없애지 않아요.
- **서로 다른 실행을 구별해요.** 목록 새로고침과 새 모델 호출을 만드는 다시 생성을 같은 회전 화살표만으로 구분하게 하지 않아요. 응답별 메뉴에서 다시 생성을 제공한다면 메뉴 안에 행동 이름을 유지해요. 직접 저장과 새 응답 생성도 서로 다른 이름을 사용해요.
- **설명은 입력 방식에 의존하지 않아요.** 데스크톱의 hover·키보드 focus 툴팁은 보조 설명이에요. 필수 의미는 보이는 문구·명확한 문맥·열린 메뉴에 있어야 해요. 터치에서도 같은 기능을 찾고 실행할 수 있어야 하며 이름·초점·선택 상태를 접근 가능하게 제공해요.
- **밀도와 누르기 쉬움을 함께 관리해요.** 기본 아이콘은 18~20 CSS px에서 시작하고 작은 그림이 곧 작은 클릭·터치 영역이 되지 않게 해요. 아이콘을 추가해도 대상 이름과 주요 행동을 밀어내거나 모든 행에 장식 아이콘을 붙이지 않아요.

새 아이콘 단독 제어는 설명 없이 보았을 때 대상과 예상 행동을 구별할 수 있는지 실제 배치에서 확인해요. 의미를 맞히기 어렵거나 같은 화면의 다른 제어와 혼동되면 이름을 복원하거나 이름이 있는 메뉴로 옮겨요. 아이콘 수나 텍스트 감소량을 성공 기준으로 삼지 않아요.

## 공통 배치의 시작값

아래 수치는 Uimori에서 비교할 설계 시작값이에요. 실제 화면과 글자 확대 결과에 따라 조정하며 기기 모델에만 맞춘 고정 크기로 사용하지 않아요.

| 항목 | 시작값과 예외 |
| --- | --- |
| 좌우 여백과 본문 폭 | 모바일 기본 16 CSS px, 데스크톱 작업 영역은 24px에서 시작해요. 넓은 화면의 원고·긴 폼은 읽을 수 있는 최대 폭을 정하고, 읽기 화면은 사용자의 읽기 설정을 유지해요. |
| 간격 | 같은 그룹 8px, 그룹 내부 구분 12~16px, 큰 영역 사이 24px를 기본으로 사용해요. 중첩된 margin·padding으로 간격이 누적되지 않게 해요. |
| 기본 헤더 | 보통 글자 크기에서 약 56px 한 줄을 목표로 해요. 긴 제목은 본문이나 상세에서 전체를 확인할 수 있게 하고 확대 시 높이를 유연하게 늘려요. |
| 조작 영역 | 일반 버튼·아이콘 버튼은 최소 44×44 CSS px의 터치 영역을 확보해요. 보이는 아이콘·배경은 더 작을 수 있어요. |
| 입력과 글자 | 모바일 입력 글자는 기본 16px, 관리 화면 본문은 14~16px, 화면 제목은 18~20px에서 시작해요. 원고의 서체·크기·줄간격은 읽기 설정을 우선해요. |
| 테두리와 강조 | 입력창·선택 상태·주요 행동에 우선 사용해요. 제목·설명·목록·버튼 전체를 각각 두꺼운 카드로 감싸지 않아요. 선택·초점·눌림·비활성 상태를 구분해요. |
| 화면 높이 | 브라우저 주소창·하단 도구막대·safe area·키보드에 따라 달라지는 사용 가능 높이를 기준으로 해요. 콘텐츠의 세로 스크롤은 허용하며 글자 확대를 가로 넘침이나 가림으로 해결하지 않아요. |

## 화면별 적용 방향

| 화면 | 기본 화면에 남길 것 | 필요할 때 열 것 |
| --- | --- | --- |
| 채팅 | 현재 대화, 원고, 입력창, 본문 모델 확인, 보내기 또는 진행 중 취소 | 대화 탐색, 페르소나·모듈·창작 옵션, 응답별 작업 상세 |
| 서재 | 제목과 만들기, 분류 탭, 현재 폴더, 검색, 자료 목록 | 목록 관리의 정렬·보기·다중 선택, 폴더 관리의 생성·변경 |
| 설정 탐색 | 설정 항목의 간단한 목록. 넓은 화면은 상세와 병치 | 좁은 화면에서 선택한 설정의 상세 화면 |
| 설정 상세 | 현재 항목 이름·설정 내용. 좁은 화면은 뒤로가기와 닫기 제공 | 다른 항목은 넓은 화면의 목록 또는 좁은 화면의 뒤로가기로 선택. 긴 도움말은 해당 항목에서 열기 |
| 연결과 모델 | 간단한 모델/연결 탭, 목록이 있을 때 검색·추가, 같은 줄의 목록 새로고침 | 공급자별 고급 옵션, 진단 상세, 모델 등록의 보조 경로 |
| 데이터 관리 | 백업 받기와 가져오기, 형식별 짧은 용도, 파일 선택, 복원 가능 조건 | JSON/SQLite의 상세 보관 범위, 서버 경로·서버 종료 등 자세한 복원 절차 |
| 자료·프롬프트 편집 | 이름·핵심 내용, 저장과 취소, 오류 위치 | 대표 이미지·선택 설정·고급 편집·전송 미리보기. 접혀도 기존 값과 초안을 보존 |

좁은 화면의 설정 목록→상세 전환과 공통 아이콘은 [공통 UI 구현](../project-plan/UI-COMPACT-IMPLEMENTATION.md)에 적용했어요. 이 범위의 완료를 모든 화면과 실기기 검증의 완료로 취급하지 않아요. 탭은 같은 수준의 소수 항목을 전환할 때 사용하며, 설정 전체 항목과 내부 탭을 여러 줄로 동시에 쌓지 않아요. 탭이 넘치면 더 있는 항목을 알 수 있는 가로 탐색이나 명시적 선택기로 전환하고 모든 글자를 억지로 축소하지 않아요.

## 빈 화면과 실패 화면

- **전체 자료가 없음:** 짧은 안내와 시작 행동 하나를 중심으로 보여줘요. 검색·정렬·다중 선택처럼 아직 쓸 수 없는 도구는 숨겨요. 가져오기 등 유효한 대안은 보조 행동으로 접근할 수 있게 해요.
- **현재 폴더만 비어 있음:** 폴더 전환과 만들기·이동 경로를 유지해요. 전체 자료가 없는 것으로 안내하지 않아요.
- **검색 결과가 없음:** 검색창·검색어·활성 필터와 해제 경로를 유지해요. 검색 도구를 숨겨 복구할 수 없게 만들지 않아요.
- **연결이 없음:** 연결 시작을 주된 행동으로 보여줘요. 연결과 모델의 다음 단계를 짧게 설명하고 동등한 시작 버튼 여러 개를 경쟁시키지 않아요.
- **로딩·실패·충돌:** 각각 구별해요. 읽어둔 목록과 편집 초안을 가능한 한 유지하고, 실패를 빈 목록으로 바꾸지 않아요. 자동 재시도가 허용되지 않는 불확실 실행은 명시적 상태로 남겨요.

## 창작 앱의 동작을 보존해요

메시지 수정·다시 생성·버전 전환은 사용자가 보고 있는 메시지 가까이에서 이해할 수 있게 설계해요. 새 응답 생성과 원문 직접 저장은 서로 다른 행동으로 구분하고, 이전 메시지에서 새 전개를 만들더라도 원래 대화 경로를 보존해요. 완료된 요청의 재생성·메시지 버전 전환 등 아직 남은 기능은 [후속 UI 범위](../project-plan/UIUX-IMPROVEMENTS-2026-09-08.md)의 구현 상태와 구분해요.

간결한 문구를 위해 Run·snapshot·CAS 같은 내부 이름을 기본 화면에 노출하지 않아요. 반면 모델 ID·연결 상태·전송 대상·복원 조건처럼 사용자의 선택에 필요한 정보는 필요한 위치에서 정확히 확인할 수 있게 해요. UI를 접거나 재배치해도 원문 귀속·이력·저장 충돌·삭제 보호·취소·번역의 명시적 실행·공급자 호출 권한은 유지해요.

## 적용 순서와 확인 기준

1. **실행 화면과 소스부터 맞춰요.** 사용자가 제공한 S25U 사진과 로컬 소스에는 설정 메뉴·서재 폴더·목록 관리 표시의 차이가 있어요. 같은 배포본인지와 스타일 적용 상태를 확인한 뒤 남아 있는 문제를 재현해요. 사진만으로 캐시나 특정 브라우저를 원인으로 확정하지 않아요.
2. **설정·서재에서 공통 배치와 아이콘을 정해요.** 양쪽 화면의 설정 목록/상세, 제목·탭·검색·관리 메뉴, 빈 화면을 기준으로 만들어 연결·데이터 관리에 적용해요. 공통 조작→탐색 항목의 아이콘·이름→문맥이 필요한 행동 순서로 정리해요. 이미 간결해진 기능은 현재 화면을 확인하고 필요한 차이만 수정해요.
3. **실제로 어긋나는 정렬을 바로잡아요.** 검색 아이콘 중앙 정렬, 버튼·선택기 높이, 긴 한글과 모델 ID, 전역 label 규칙과 화면별 스타일의 충돌을 확인해요. 문제 없는 기능의 재작성은 선행 조건으로 두지 않아요.
4. **모바일과 데스크톱을 함께 확인해요.** 변경된 대표 흐름을 360·390·430 및 중간 폭 768·1024·넓은 화면 1440 CSS px에서 확인해요. 이 수치는 확인 표본이며 CSS 전환점을 강제하지 않아요. 데스크톱 창 크기 변경·글자 확대·마우스·키보드와 터치 접근을 확인해요. S25U는 실제 브라우저의 CSS viewport·글자 크기·확대 설정을 기록하고 주소창 접힘/펼침, 키보드 열림/닫힘, 한글 입력과 가로 회전을 확인해요. 합성 viewport 결과와 실기기 결과를 분리해요.

변경된 화면의 검토에서는 다음을 확인해요. 이 목록은 향후 UI 구현의 완료 기준이며 이번 문서 작성으로 통과한 검사는 아니에요.

- 기본 글자 크기·키보드가 닫힌 모바일 첫 화면에서 실제 자료 행이나 빈 화면의 시작 행동이 보여요. 관리 도구 때문에 그것을 찾으러 스크롤하지 않아요.
- 좁은 화면의 설정 상세는 공통 헤더 뒤에서 해당 설정 내용이 시작되고 넓은 화면에서는 목록 옆에서 시작돼요. 제목·현재 폴더·현재 위치를 같은 의미로 반복하지 않아요.
- 버튼 하나만 어중간하게 다음 줄에 남거나 아이콘이 입력 글자와 수직으로 어긋나지 않아요. 긴 내용과 글자 확대에서도 주요 행동·접근 가능한 이름을 잃지 않아요.
- 양쪽 화면에서 같은 아이콘·이름은 같은 기능과 범위를 뜻해요. 현재 모델·페르소나·필수 상태를 아이콘으로 대체하지 않아요.
- 터치·마우스·키보드·보조 기술로 메뉴를 열고 닫을 수 있고, 초점과 선택 상태가 구분돼요. 필요한 행동과 설명을 hover에만 의존하지 않아요.
- 창 크기 변경으로 탐색이나 편집 배치가 전환돼도 선택·검색·초안·초점을 잃지 않아요. 넓은 화면의 원고와 폼도 읽기 쉬운 폭을 유지해요.
- 입력 중에도 보내기·취소·저장에 도달할 수 있어요. 고정 영역이나 브라우저 UI가 입력 내용과 오류를 가리지 않아요.
- 뒤로가기·닫기·저장 실패 뒤에 초안·검색·읽던 위치가 의도대로 남아요. 화면 뒤로가기와 브라우저 뒤로가기를 각각 확인해요.
- 빈 데이터·빈 폴더·검색 결과 없음·로딩·실패·진행 중·미저장 상태를 구분하고 각 상태에서 다음 행동을 찾을 수 있어요.
- 해당 변경의 [품질 검사](QUALITY.md)와 관련 합성 브라우저 검사를 통과하고 소스/빌드·화면 증거를 남겨요. 실제 기기에서 확인하지 않은 동작은 미확인으로 기록해요.

새 제어를 추가할 때는 **이 화면의 주된 작업에 지금 필요한가, 기본 화면에 계속 보여야 하는가, 기존 메뉴·상태 표시와 겹치는가**를 먼저 판단해요. 추가 줄·고정 영역·기본 노출이 필요하면 그 사용 이유를 해당 변경 설명에 남겨요.

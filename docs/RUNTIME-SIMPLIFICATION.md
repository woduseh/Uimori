# 현재 프롬프트와 전체 원문 번역

새 DB의 초기 작문·번역은 Phēmē·Hermēneía예요. 프롬프트 관리의 기본 제공 목록에는 협업 프리셋 3종도 있으며, 추가한 사본은 일반 프리셋처럼 편집·선택해요. 기존 작업본을 자동 교체하지 않아요. [기본 제공 프롬프트](BUILTIN-PROMPTS.md)를 참고해요.

작문과 번역의 전역 현재 프롬프트는 앱 전체에서 각각 한 벌을 사용해요. `prompt_workspace`에 프로그램·선택값·번역 정책·역할 모델을 저장하고 `expectedRevision`으로 동시 편집을 보호해요. 채팅 프로필은 봇·페르소나·모듈과 선택적인 작문 프리셋·본문 모델 고정을 관리해요. 고정하지 않은 채팅은 전역 기본값을 따라요. [전역 역할 모델 계약](GLOBAL-MODELS.md)을 참고해요.

저장된 프롬프트 프리셋을 적용하면 내용과 옵션을 현재 작업본으로 복사하고 `CurrentPrompt.presetId`에 출처를 유지해요. 프리셋의 후속 수정·삭제는 현재 작업본을 바꾸지 않아요. 새 요청은 그때의 작업본과 옵션을 자기 snapshot에 고정하며, 과거 실행은 현재 작업본으로 다시 해석하지 않아요.

채팅의 작문 프리셋 고정은 `ChatProfile.pinned.mainPromptPresetId`로 저장해 같은 ID의 최신 저장본을 다음 요청에서 읽어요. 삭제되거나 작문 역할이 아닌 프리셋은 새 본문 실행을 막고 채팅 설정에서 다시 선택하도록 표시해요. 전역 복귀·고정 변경은 과거와 진행 중인 Run을 바꾸지 않아요. 번역 프롬프트는 계속 전역 작업본을 사용해요.

## 설정과 제작 화면

설정의 현재 프롬프트는 역할별 프롬프트 선택·현재 창작 옵션·협업 사용 여부만 다뤄요. 이름·Risu 본문·토글 선언·기본 옵션·협업 상세는 프롬프트 탭에서 편집하고 전체 저장 버튼 하나로 저장해요. 설정의 프롬프트 편집 링크는 선택한 프리셋을 열어요. 프리셋 저장은 전역 작업본에 자동 반영하지 않고 설정의 최신 버전 적용으로 명시적으로 다시 복사해요. 해당 프리셋을 고정한 채팅의 다음 요청에는 최신 저장본을 사용해요.

설정에서 옵션을 변경하거나 조합을 불러오면 현재 선택을 자동 저장해요. 연속 입력은 직렬 저장하며 늦은 응답으로 뒤의 입력을 덮어쓰지 않아요. 실패·동시 변경·복구한 초안은 선택을 유지하고 다시 저장 또는 기존 초안 비교·복구 동작을 제공해요. 이미 예약한 실행은 바꾸지 않아요. 프롬프트 교체 동안은 이전 프롬프트의 옵션 입력을 막아요.

프롬프트 적용 때 기본 선택값도 `CurrentPrompt.defaultValues`로 복사해요. 설정의 기본값 선택은 적용 당시 기본 옵션을 복원하며, 라이브러리의 후속 수정으로 기본값이 바뀌지 않아요. 이 필드는 현재 설정용이며 Run의 프롬프트 snapshot에는 넣지 않아요. 필드가 없는 작업본은 프로그램에 정의된 기본값을 사용해요.

협업은 설정에서 켜고 끄기만 제공해요. 구성이 없으면 프롬프트 편집에서 구성하도록 안내해요. 제작 화면에서는 헤더 스위치와 왼쪽 펼침 화살표를 분리하며, 사용 여부를 바꾸거나 저장해도 펼침 상태를 자동 변경하지 않아요.

프롬프트 JSON은 `title`, `role` (`main`/`translation`), `program`, `values`를 함께 내보내고 가져와요. 협업은 `program.collaboration`에 포함해요. 이름·역할이 없는 단독 프로그램 JSON도 읽으며 없는 메타데이터를 추측하지 않아요. 기존 프리셋에 다른 역할의 JSON을 덮어쓰지 않고 새 프롬프트에서 가져오도록 안내해요. 같은 역할의 가져오기는 구성과 옵션을 함께 실행 취소할 수 있어요.

## 옵션 조합의 소속과 적용

옵션 조합은 선택값과 함께 소속 및 저장 당시 `controls` 정의를 보관해요. 소속은 저장된 프리셋 ID 또는 프리셋 출처가 없는 기본 현재 작업본의 역할이에요. 프리셋에서 복사한 현재 작업본은 출처 프리셋의 조합을 사용하고, 출처가 없는 작문·번역 작업본은 각각 자기 역할에 속한 조합을 사용해요.

목록 표시와 적용은 **같은 소속·같은 역할·같은 옵션 정의**를 모두 만족해야 해요. 서로 다른 프리셋이 같은 control ID나 같은 값 타입을 사용해도 조합을 공유하지 않아요. 같은 프리셋이라도 옵션 정의가 달라지면 이전 정의로 저장한 조합을 제외해요. 호환되지 않는 조합을 현재 기본값으로 조정해서 적용하지 않아요. 본문만 바뀌고 옵션 정의가 같으면 같은 소속의 조합을 사용할 수 있어요.

조합은 설정의 창작 옵션에서 불러오고 새로 저장하거나 관리해요. 조합을 불러온 뒤 직접 바꾼 현재 선택이 우선하며 저장된 조합 자체는 바뀌지 않아요. 재사용하고 싶을 때만 현재 선택을 새 조합으로 저장해요.

조합 적용은 현재 옵션 값만 바꾸며 프롬프트 본문·옵션 정의·프리셋 출처를 바꾸지 않아요. 서버도 소속과 정의 일치를 검증하므로 UI 목록을 우회한 요청으로 다른 프롬프트의 값을 적용할 수 없어요. 현재 작업본 저장과 적용의 revision CAS 및 편집 중 초안 보호를 유지해요.

채팅에 작문 프리셋을 고정하면 빠른 옵션 조합은 그 프리셋의 소속·정의에 맞는 조합만 표시하고 해당 채팅의 고정 옵션으로 저장해요. 창작 옵션 패널의 `모든 채팅`은 전역 작업본, `이 채팅`은 채팅에 실제 적용하는 프롬프트를 읽어요. 고정 프리셋 변경·최신 옵션 정의 변경을 감지하면 미저장 옵션을 보존하고 최신 정의 검토를 요구해요. 모델·프롬프트 고정과 옵션 고정은 별개의 설정이에요.

옵션 조합에는 소속과 현재 옵션 정의가 필수예요. 현재 형식 검증에 실패하는 조합은 읽기·복원·적용에서 거부하며 구형 조합을 위한 변환 경로는 없어요. 운영 데이터의 물리 삭제나 자동 청소는 수행하지 않아요.

## 본문 응답 판정

본문 서비스 거절 감지가 켜져 있으면 생성 전에 TypeSafe AI의 JEV 연결과 최소 호출 예산을 확인해요. 실제 생성 응답을 받으면 Lua 출력 후처리 전에 JEV로 명시적 서비스 거절 하나만 판정해요. 장르·문체·허구 여부·품질을 심사하지 않으며 계획·분석·질문·대사도 정상 응답에 포함해요. 작품 속 인물의 거절이나 인용을 서비스 거절로 취급하지 않도록 지시해요.

본문 생성문 전체를 `state.response`로 보내며 `explicitRefusal >= mainJudgmentThreshold`이면 거절, 미만이면 정상 채택해요. 본문 확신 기준은 기본 0.9이며 0.5 초과~1 범위에서 조절해요. 보조 점수나 불확실 판정은 없어요. 채택한 결과만 원래 카드의 Lua 출력 콜백을 거쳐 확정 원문이 돼요. 거절·판정 실패는 원래 출력과 호출 기록을 보존하고, 본문·이야기 기억에 채택하거나 자동 재생성하지 않아요. 원본 Lua 자체의 모델 호출은 이 판정과 별개로 유지해요.

판정 1회는 Run 전체 `maxCalls` 안에서 예약해요. 같은 입력 후보도 자신의 생성 결과를 새로 판정하며 원래 후보의 판정 기록을 가져다 쓰지 않아요. JEV 입력 지문과 전체 생성문을 `main-refusal-jev-v2` snapshot 영수증에 저장하고 현재 형식 archive에서 해당 요청과 일치하는지 검증해요. 연결·설정은 [프로바이더 안내](PROVIDERS.md)를 참고해요. 합성 테스트는 실행·보존 계약을 검증하며 실제 분류 품질을 보장하지 않아요.

본문·번역 거절 감지의 활성화 설정은 역할별 모델에서 각각 바꿔요. 기본값은 켜짐이에요. `mainJudgmentEnabled`와 `mainJudgmentThreshold`는 Run snapshot에, `translationPolicy.judgment.enabled`는 번역 작업 입력에 예약 시 고정해요. 비활성화한 역할은 JEV 거절 검사·키 확인·판정 예산을 건너뛰고 정상 생성 결과를 채택해요. 원래 생성 오류와 취소·소유권·저장 검증은 유지하고, 로어·이미지 JEV는 변경하지 않아요.

## 번역

전체 원문을 한 번의 번역 입력으로 보내고 일반 텍스트를 받아요. 분할 계획·구간 재시도·JSON 번역 형식·보호 토큰·자연어 구조 검증은 제거했어요. 원문 ID/hash와 작업 소유권·세대·CAS 검증은 유지해요. 번역 프롬프트 외에도 원문 시점의 봇·페르소나·로어·번역 지침과 허용된 요약·메모·자료 조회를 제공해요. 다른 채팅이나 나중에 수정된 자료를 섞지 않아요.

`server/product-auxiliary.ts`는 `source`·`context`·`catalog`·`notes` 슬롯을 실제로 사용하고 그 전체 값이 컴파일된 메시지에 남았을 때만 같은 데이터의 호스트 전달을 생략해요. 슬롯이 없거나 비활성 분기에 있거나 템플릿이 원문을 잘랐다면 전체 데이터를 계속 전달해요. 원문 ID/hash와 역할 개정 메타데이터는 유지하고, 준비 입력과 저장 snapshot은 변경하지 않아요. 사용자 메모는 `notes` 슬롯 또는 호스트의 `source.notes`로 전달해요. `context`를 사용하면 그 안의 봇·페르소나·모듈·패키지 지침을 별도 슬롯에 다시 넣지 않아도 돼요. 원문 시점·인물 지식·출처 정보는 문맥에 그대로 있어요.

메인과 번역의 `story.list/search/read`·`notes.list/read` 정의는 `core/story-read-tools.ts`를 공유해요. 검색어 없이 원문을 찾을 때는 `story.list`, 알려진 회차는 `story.read`의 `sceneNumber`를 사용해요. 공백뿐인 `story.search` 검색어는 수정 가능한 인수 오류이며 출처 무결성 오류는 계속 종료 조건이에요. 관련 회귀는 `tests/translation-prompt-delivery.test.ts`, `tests/story-read-tools.test.ts`에서 확인해요.

번역 서비스 거절 감지가 켜져 있을 때 판정은 JEV만 사용해요. 판단용 생성형 모델 선택이나 실패 시 대체 호출은 없어요. 판정 요청은 번역 응답 전체를 받고 원문·자료·도구·대화 기록을 받지 않아요. 번역 거절이 명확할 때만 전체 번역을 자동 재요청해요. 추가 재요청은 기본 1회, 0~5회로 설정해요. 번역·조회 후속 요청·판정은 한 작업의 전체 호출 한도(기본 16, 2~64)에 포함해요.

**프로바이더·모델 → 프로바이더 추가 → TypeSafe AI**에서 저장한 키를 사용하며 저장 키가 없으면 서버의 `TYPESAFE_API_KEY`로 연결해요. 작문·번역 생성 모델은 별도로 선택해요. **역할별 모델 → 작업 동작 → 거절 감지 → 번역**에서 확신 기준과 재시도 한도를 조절하고, 같은 작업 동작의 번역 작업에서 전체 호출 한도를 조절해요. `translationPolicy.judgment.threshold`는 작업 예약 시 고정하며 기본값은 0.9, 범위는 0.5 초과–1이에요.

전체 번역 생성문을 `state.response`에 담아 명시적 거절 여부 하나만 `noul`로 판단해요. `explicitRefusal >= translationPolicy.judgment.threshold`이면 기존 한도 내에서 자동 재요청하고, 미만이면 채택해요. 판정 실패·취소에서는 후보 텍스트와 이전 성공 번역을 보존하고 자동 재호출하지 않아요. 전체 입력과 질문·본문 해시를 검증하고 `translation-refusal-jev-v2` 입력 지문으로 귀속해요. 요청·응답·실제 또는 미상 사용량은 기존 attempt에 남고 인증키는 제외해요. Mock transport 테스트는 실행 계약만 검증하며 실제 거절 구분 성능은 별도 평가가 필요해요.

본문·번역의 앱 내부 JEV 입력 상한(6,000/5,000 추정 토큰)과 발췌 fallback은 제거했어요. [공식 모델 사양](https://docs.typesafe.ai/models)의 요청 합계 64,000토큰과 state + 가장 긴 질문 32,000토큰 한도를 `o200k_base` 추정치로 사전 검사해요. 초과 시 호출하지 않고 `JEV_INPUT_BUDGET`으로 실패해요. 공급자 토크나이저와 동일한 계산을 보장하지 않으므로 실제 API 한도 오류도 처리해요. 공급자의 명시적 `max_tokens_exceeded` 응답은 `JEV_INPUT_BUDGET`으로 기록해요. 전체 입력 전송 실패는 출력을 보존하는 기존 오류 경로로 처리해요. 로어·이미지의 별도 입력 예산은 유지해요. [실제 장문 입력 검증](JEV-INPUT-VERIFICATION.md)은 합성 회귀 테스트와 구분해 기록해요. 기존 저장 데이터를 자동 변환하거나 삭제하지 않으며 v1 판정 archive 호환은 지원 범위에서 제외해요.

빈 응답·부분 응답·판정 실패·HTTP 오류·취소·한도 초과는 자동 재생하지 않아요. 판정 실패의 후보 텍스트는 진단 기록에 보존하지만 성공 번역으로 표시하지 않아요. 실제 문학 번역 품질이나 경량 모델의 판정 정확도는 로컬 합성 검사의 증거 범위 밖이에요.

수동 재번역은 성공·실패 모두 현재 모델·현재 번역 프롬프트·현재 정책으로 새 작업을 만들어요. 진행 중인 중복 요청은 기존 작업을 반환해요. 새 작업이 실패·취소되면 같은 원문 hash의 마지막 성공 번역을 계속 표시해요. 직접 번역 수정도 새 완료본으로 저장하고 모델을 호출하지 않아요. 원문이 바뀌면 이전 hash의 결과를 최신 번역으로 재사용하지 않아요.

## 전송 미리보기와 오류 알림

목록의 작문 미리보기는 합성 이전 입력·응답·현재 요청으로 구성해요. 번역 미리보기는 입력한 원문과 합성 문맥을 `core/translation-preview.ts`에서 만들고, 실제 번역과 같은 `core/translation-prompt.ts`의 컴파일 함수를 사용해요. 번역 대화에는 현재 번역 요청 하나만 넣고 원문은 `source` 슬롯과 런타임 source로 제공해요. 실제 채팅 자료나 모델을 사용하지 않고 결과를 저장하지 않아요. 채팅 연결 미리보기는 기존 서버 경로의 원문·문맥을 사용해요.

프롬프트 구성·미리보기 오류는 편집기 안에 표시하고 전역 알림으로 중복 전달하지 않아요. 오류 알림은 닫기 버튼으로 확인 후 숨길 수 있고, 재시도·구성 수정·역할 전환에 따라 이전 알림을 정리해요. 전역 오류도 닫거나 주 화면을 이동하면 해제해요. 알림을 닫아도 `PROMPT_HISTORY_OMITTED` 같은 검증 규칙과 실패 기록은 바꾸지 않아요.

## 작문 재요청과 도구

`POST /api/runs/:id/retry`는 원래 요청 직전 위치에서 새 분기를 만들고 현재 설정으로 다시 생성해요. 이전 성공 원문·실패 기록을 수정하지 않아요. idempotency key 재전송은 같은 새 실행을 반환해요. 별도의 같은 입력 후보 실험은 기존 고정 snapshot 계약을 유지해요.

도구 오류는 허용된 로컬 교정 가능 오류와 권한·실행 실패를 구분해요. 잘못된 입력처럼 명시적으로 `recoverable`인 결과는 모델에 돌려줘 수정할 수 있어요. 수정은 실행기의 호출·시간·문맥 예산 안에서 계속할 수 있어요. 권한 거절과 분류되지 않은 실패는 즉시 종료하며, 이 정책은 외부 공급자 요청의 불확실한 재실행을 허용하지 않아요.

## 삭제와 보관

서재 항목·프리셋·옵션 조합·모델·프로바이더·업로드 이미지는 참조 때문에 삭제를 막지 않고 새 목록·선택에서 제외해요. 과거 자료·이미지·실행 snapshot은 내부에 보존해요. 프로바이더 삭제는 이후 전송 권한을 회수해요. 전용 모델을 삭제한 작문 보조는 자동으로 다른 모델에 보내지 않도록 협업을 꺼요. JEV 키 삭제는 이후 판단 연결에 적용되며 생성형 판정 모델로 전환하지 않아요.

schema·archive의 현재 버전은 [DB·archive·백업 버전](DATA-MIGRATIONS.md#현재-버전)을 봐요. archive는 현재 프롬프트 한 행과 숨김 목록을 포함하고 필수 행·참조·원문·실행 입력을 검증해요. 변경된 현재 프롬프트가 있으면 빈 DB로 간주하지 않아요.

관련 구현: `server/prompt-workspace.ts`, `server/source-editing.ts`, `server/product-auxiliary.ts`, `core/tool-outcome.ts`, `server/library-deletion.ts`.

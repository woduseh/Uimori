# 이야기 UI

원고 안에 메신저 대화, 게시판과 댓글, 뉴스 기사, 위키 문서, 상태창, 관계도, 작전 지도, 달력, 조우 알림, 선택지 같은 화면을 넣을 수 있어요. 모델이 본문을 생성할 때 화면도 함께 구성하며, 등장인물이 그 화면을 마주하는 본문 위치에 놓아요.

## 켜기와 사용하기

**채팅 설정 → 생성 설정 → 이야기 UI**를 켜고 저장해요. 새 채팅은 [생성 기본값](CONTEXT-LIMITS.md#새-채팅-생성-기본값)을 복사하며, 저장 뒤 시작하는 생성부터 화면 구성 방법을 모델에 전달해요. 필요한 장면이라면 요청에 원하는 화면과 담을 내용을 적어 주세요(예: “조사팀의 통화 기록을 표로 보여 주고, 다음에 전화할 사람을 선택할 수 있게 해 줘”).

**이야기 UI 스타일** 기본값은 **자동**이에요. 모델이 화면마다 고른 스타일을 저장하며, 선택이 없거나 유효하지 않으면 기본 스타일로 표시해요. 기본 제공 스타일이나 사용자 테마를 직접 선택하면 저장된 화면과 생성 중인 화면에 적용돼요.

동양풍(목판본 책장: 굵고 가는 이중 테두리·어미가 달린 판심 머리글·세로 이름표·붉은 인장 버튼), 서양 판타지(채색 연대기: 양쪽 끝이 사라지는 금선·눈금 새긴 원형 게이지·붉은 머리글자·깃발 탭), 현대(색 번짐 위의 반투명 유리 패널·큰 숫자·알약 버튼), 시대극(인쇄물과 서류: 굵은 괘선 사이의 제호·장부 칸·표 조각 버튼·고무도장 배지·무성영화 자막 카드 대사창), 블루 아카이브(밝은 기하학 패널·하늘색 조작부·노란 선택선), 아이돌 스테이지(흰 바탕·강한 분홍 하나·홀로그램 테두리·큰 기울임 등급 글자), 네온(검은 바탕·신호색 노랑 버튼·청록 선·잘린 모서리), 호러(거의 흑백·상자 없는 패널·가는 글자·위험에만 쓰는 붉은색), 택티컬(현장 보고서: 모서리 꺾쇠·테두리에 박힌 항목 이름·무전 기록 줄·서류철 탭·경고에만 쓰는 사선 띠), 로맨스(꾸민 일기장: 마스킹 테이프·형광펜 밑줄·스티커 배지·폴라로이드 초상), 팝(검정·흰색·강한 색 하나·굵은 테두리와 딱딱한 그림자·기울어진 판)을 선택할 수 있고, 도우미로 켜기와 스타일을 바꿀 수도 있어요.

서양 판타지, 로맨스, 아이돌 스테이지, 네온, 택티컬은 블록 모서리에 장식 그림을 그리고, 기본·현대·블루 아카이브를 뺀 스타일은 장식 구분선(`Divider`)이나 종이 결 같은 바탕 무늬를 함께 써요. 장식은 앱에 내장된 그림이라 따로 내려받지 않고, 사용자 테마를 적용한 화면에는 모서리 장식을 그리지 않아요. 네온과 택티컬의 표기용 글자는 영문과 숫자만 고정폭으로 쓰고 한글은 본문 글꼴을 써요.

탭 전환이나 입력값 편집 중에는 모델을 호출하지 않아요. 최신 장면에서 버튼을 누르면 전송 방식 선택이 열리며, 미전송 입력은 같은 브라우저 탭의 세션에 보관해 원문·번역 전환 시에도 유지해요(원문 수정 시 이전 초안은 초기화).

- **이 대화만 이어가기**를 선택하면 모델에 해당 상호작용의 짧은 응답을 요청해요.
- **다음 장면으로 이어가기**를 선택하면 제출한 행동을 반영해 다음 장면 생성을 요청해요.

응답이 완성되면 새 장면으로 이동하고, 기다리는 동안 다른 장면이나 채팅을 보고 있었다면 읽던 위치를 유지해요. 생성 중에도 완성된 화면 블록은 먼저 표시되고, 아직 쓰는 중인 블록 자리에는 구성 중 표시가 나와요. 버튼 제출은 장면 저장이 끝난 뒤에 가능해요.

**보내기**를 누르면 현재 모델로 새 요청을 시작해요. 이야기 UI를 끄면 저장된 화면은 읽기 전용으로 남고, 이전 장면에서 다시 선택하려면 장면 메뉴의 **이 장면까지 새 채팅으로 분기**를 사용해요. [채팅 백업과 분기](CHAT-BACKUP.md)

### 현황 탭

상태창, 파티, 소지품, 관계도처럼 장면을 넘어 이어지는 정보는 모델이 블록에 고정 이름(`$/_uimori/pin = "status"`)을 붙여 써요. 지금 읽고 있는 장면까지 고정된 블록이 있으면 데스크톱 오른쪽 사이드 패널에 **현황** 탭이 생기고, 이름별로 가장 최근에 고정된 블록을 보여 줘요. 첫 고정 블록보다 앞을 읽는 동안에는 탭이 없으며, 패널을 열어 둔 채 그 앞으로 스크롤하면 패널은 닫지 않고 빈 상태를 보여 줘요. 이전 장면으로 스크롤하거나 분기한 채팅을 열면 그 시점의 현황이 보이고, 장면을 고치거나 다시 생성하면 바로 반영돼요. 이름이 둘 이상이면 패널 위의 칩으로 바꿔 볼 수 있고(최대 4개), 읽기 언어가 번역이면 번역된 화면을 보여 줘요.

고정된 블록도 본문의 제자리에 그대로 남고, 패널의 화면은 읽기 전용이에요. 버튼 선택은 본문의 화면에서 해요. 좁은 화면에는 사이드 패널이 없으므로 본문의 블록으로 확인해요. 패널 본문은 보이는 블록의 기본 제공 스타일 색을 따라가고(기본 스타일이면 앱 모습 그대로), 봇의 이야기 UI 테마에 **현황 패널 CSS**를 넣으면 그 봇의 채팅에서 패널 바탕과 칩을 따로 꾸밀 수 있어요. [제작 문법](THEME-AUTHORING.md#이야기-ui-테마) 모델은 다음 장면을 쓸 때 고정된 블록을 문맥(`storyUi.pinned`)으로 받아 이어 쓰고, 상태가 바뀐 장면에서만 같은 이름의 블록을 새로 써요.

## 화면 구성

### 봇을 위한 사용자 테마

해당 봇의 채팅을 열고 **설정 → 테마와 색상 → 적용 범위: 현재 봇의 기본 → 이야기 UI 테마 만들기**에서 이름, 기반 스타일, CSS를 편집해요. **저장**은 테마 자료만 저장하며, **봇의 이야기 UI 기본값**에서 테마를 고르면 앱 레이아웃·팔레트와 별개로 적용돼요.

도우미에게 봇 설정에 어울리는 이야기 UI 테마 생성·적용을 요청할 수도 있어요. 도우미가 이야기 UI 테마를 만들거나 고치면 답변의 변경 카드 아래에 그 테마의 미리보기가 나와서, 설정 화면을 열지 않고 대화하면서 다듬을 수 있어요. 모델에는 선택 가능한 테마의 ID·이름·설명·기반 스타일만 전달해요.

스타일 우선순위는 채팅 직접 선택 → 봇 기본 테마 → 모델 선택 → 기본 순이에요. 테마를 삭제하면 모델 선택이나 기본 스타일로 돌아가요.

사용자 테마는 **테마 JSON 내보내기·가져오기**로 공유해요(봇 파일 내보내기에는 포함되지 않음). [제작 문법과 CSS 범위](THEME-AUTHORING.md#이야기-ui-테마)

### 모델의 화면 조합

모델은 A2UI 1.0의 Express 형식으로 본문 사이에 `<a2ui>…</a2ui>` 블록을 만들어요. 각 블록은 자체 화면과 상태를 정의하며, 한 응답에 여러 개를 본문 중간중간 둘 수 있어요. Uimori는 아래 구성 요소의 조합으로 화면을 표현해요.

이야기 UI를 켠 채팅은 장면 배치 예시와 함께 카탈로그에서 만든 간결한 문법표를 모델에 보내요. 각 구성 요소와 함수의 인자 순서, 필수 여부, 허용값, 목록 항목의 구조를 담고, 여러 구성 요소가 공유하는 색상과 아이콘 목록은 한 번만 전달해요.

| 용도 | 구성 요소 |
| --- | --- |
| 매체의 틀 | `Frame` (`kind`: `panel`, `app`, `page`, `paper`, `terminal`, `system`, `note`, `accent`: 대표색 10가지) |
| 배치와 탐색 | `Row`, `Column`, `List`, `Grid`, `Card`, `Stack`, `Carousel`, `Tabs`, `Details`, `Modal`, `Divider` |
| 글과 그림 | `Text` (`display`, `headline`, `title`, `label`, `body`, `caption`, `quote`, `mono`), `Image`, `Avatar`, `Icon`, `Badge` |
| 연출 | `Hero` (그림이나 대표색 위의 큰 제목), `Dialogue` (이름표와 초상화가 붙은 대사창) |
| 인물과 물건 | `Profile` (초상화·이름·소개·항목을 묶은 인물 카드), `Slot` (아이템 칸: 수량, 등급 `rarity`, 상태 `empty`·`locked`·`equipped`), `Rank` (큰 등급 도장과 별점) |
| 대화와 게시물 | `Message`, `Post` (`post`, `article`, `comment`, 답글 중첩), `Notice` |
| 수치와 기록 | `Stat`, `Gauge`, `Ring`, `KeyValue`, `Timeline`, `DataTable`, `BarChart`, `LineChart`, `PieChart`, `RadarChart`, `Compare` (크기 비율대로 나란히 선 실루엣이나 막대), `Combatant` (전투 상태창 한 줄: 이름, 초상화, HP·MP 같은 자원 막대, 상태 이상, 아군·적, 행동 중·방어·전투 불능) |
| 일정과 장소 | `Schedule` (요일별 시간표), `Calendar` (한 달 달력: 실제 월 `month="2026-12"`은 요일을 계산하고, 가상의 달력은 첫날 위치 `start`와 날수 `length`로 그림), `Route` (장소를 잇는 이동 경로), `Map` (위에서 본 칸 지도: 방·벽·물·미탐색 구역과 인물·유닛 표식, 좌표 머리글 `coords`, 표식 범례) |
| 관계 | `Graph` (노드와 이름 붙은 연결선: 관계도, 수사 보드, 스킬 트리, 가계도. 배치는 모델이 아니라 Uimori가 정해요. `ring`은 원형으로 두르고 `center`의 인물을 가운데 두며, `tree`는 연결 방향을 따라 아래로 내려가요. 서로를 향한 두 선은 갈라져 그려져요.) |
| 행동과 입력 | `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `DateTimeInput` |

`Text`, `Notice`, `Badge`, `Stat`, `Gauge`, `Ring`의 `tone`(`neutral`, `accent`, `positive`, `caution`, `danger`, `info`)은 의미에 맞는 색을 지정해요.

### 꾸밈

- `Frame`과 `Card`의 `surface`는 칠하는 방식을 정해요: `outline`(채움 없이 강조색 테두리), `tint`(옅은 강조색), `gradient`(강조색 그러데이션과 밝은 글자), `glass`(반투명과 흐림), `glow`(빛나는 테두리). `Card`도 `accent`를 받아요.
- `Frame`의 `backdrop`은 저장된 이미지를 내용 뒤에 깔고 글자가 읽히도록 바탕색을 덧씌워요. `ornament`는 `corners`(모서리 표식), `inset`(안쪽 선), `ribbon`(접힌 모서리), `stripes`(위아래 경고 띠)를 그려요.
- `Stack`은 첫 자식 위에 나머지를 겹쳐 놓고(`align`으로 위치 지정), `Carousel`은 옆으로 넘기며 한 장씩 멈추는 줄을 만들어요.

### 모델이 직접 쓰는 CSS

정해진 옵션으로 부족하면 모델이 블록마다 `$/_uimori/css`에 CSS를 써서 화면을 꾸밀 수 있어요. 문법은 [사용자 테마](THEME-AUTHORING.md#이야기-ui-테마)와 같아요: `&`는 블록 자체이고, `--story-*` 변수와 `story-ui-*` 클래스를 쓰며, 모든 구성 요소의 `look="이름"`은 `look-이름` 클래스를 붙여 줘요. 그러데이션, 그림자, `clip-path`, 가상 요소, `@keyframes` 애니메이션 등을 쓸 수 있어요.

구조와 문구는 계속 구성 요소로 저장하므로 검증, 번역, 문맥 전달은 그대로 동작해요. CSS는 번역하지 않고, 이야기 UI를 끈 채팅이나 요약에는 전달하지 않아요. 모델이 쓴 글이므로 사용자 테마보다 좁게 적용해요.

- 해당 블록 안에만 적용하고, 블록 밖으로 나가는 그림은 잘라내요. `position: fixed`도 블록을 벗어나지 못해요.
- `url()`은 저장된 이미지 경로만 허용하고, 외부 주소를 여는 선언은 버려요. `@import`, `@font-face`, `@property`와 `!important`는 적용하지 않아요.
- `@keyframes` 이름은 블록마다 따로 붙여 앱이나 다른 블록의 애니메이션과 겹치지 않아요. 기기에서 동작 줄이기를 켜면 애니메이션과 전환을 멈춰요.
- 스타일이 **자동**이고 사용자 테마가 적용되지 않을 때만 써요. 채팅에서 스타일이나 테마를 직접 고르거나 봇 기본 테마가 있으면 모델의 CSS는 적용하지 않으니, 모델이 꾸민 화면이 마음에 들지 않을 때는 스타일을 직접 선택하면 돼요.

예를 들어 아래 블록은 메신저 화면이에요. `Frame`이 매체의 틀과 대표색을 정하고, 그 안에 말풍선을 쌓아요.

```text
<a2ui>
root = Frame(chat, "한서윤", kind="app", accent="amber")
chat = Column([
  Message("어디야", "한서윤", "23:41", avatar="{{img::서윤_교복_웃음}}"),
  Message("집 앞인데 왜", side="right", time="23:42")
])
</a2ui>
```

모델에는 화면을 언제(등장인물이 형태가 있는 것을 볼 때, 구조가 의미를 전할 때, 사용자가 결정할 차례일 때), 어디에(마주하는 본문 위치에), 어떻게(매체에 맞는 틀과 그 세계의 말투로) 쓰는지를 예시와 함께 전달해요. 응답 끝마다 선택지와 요약을 붙이는 방식은 피하도록 안내해요. 실제 사용 빈도와 구성은 모델과 프롬프트에 따라 달라져요.

CHARX 카드에서 본문용으로 사용할 수 있는 그림은 `{{img::이름}}`으로 넣을 수 있어요. 위 예시의 `서윤_교복_웃음`처럼 카드에 등록된 에셋 이름을 쓰면 Uimori가 장면을 생성할 때 그림을 찾아요. 메신저의 `avatar`, 대사창의 `portrait`, 화면 배경의 `backdrop` 등 이미지 속성에서 쓸 수 있고, 목록 데이터에 넣어 바인딩할 때도 같은 표기를 써요. 저장된 에셋, 패키지 이미지, 삽화의 로컬 경로도 사용할 수 있어요.

이야기 UI는 본문 사용이 허용된 그림을 찾아요. 카드가 본문에서 쓰는 `{{image::이름}}`, `{{asset::이름}}`, `{{emotion::이름}}`, `{{raw::이름}}`, `{{path::이름}}`도 같은 이름으로 읽어요. 이름을 찾을 수 없거나, 같은 이름이 서로 다른 그림을 가리키거나, 값이 이름도 저장된 경로도 아니면(이름만 적은 값, 외부 주소 등) 해당 그림만 생략하고 화면의 나머지는 그대로 보여 줘요. 찾은 그림은 장면에 고정되어 원문과 번역에서 함께 사용해요. 이미지 모델이 본문 그림을 맡는 채팅에서도 화면 안의 그림은 쓰는 모델이 정해요.

서버는 저장된 화면에 선언된 버튼·이벤트와 입력값을 검증해 다음 요청으로 전달해요. `roll` 이벤트의 주사위 면 수와 개수는 화면 정의에서 확인해 서버가 굴리며, 같은 제출을 재확인할 때는 기록된 결과를 재사용해요.

## 저장, 읽기와 번역

서버는 본문 저장 시 완성된 `<a2ui>` 블록을 `uimori-ui` 코드 펜스 JSON(`version: 1`, `expression`, `messages`)으로 변환해 원문과 함께 보관해요. 검증을 통과하지 못한 원문은 그대로 보존하며, 읽기 화면에서 **이야기 화면을 표시할 수 없어요**를 펼치면 변환 오류와 원문을 볼 수 있어요.

원문을 직접 편집하면 화면 블록은 `<a2ui>` 원형으로 보여요. 저장할 때 바뀐 블록만 다시 변환하고, 손대지 않은 블록은 저장된 화면과 그림 연결을 그대로 유지해요. 오류를 고쳐 저장하면 바로 화면으로 표시되며, 도우미가 장면을 고칠 때도 같아요. 번역 편집에서는 번역문의 화면 데이터를 그대로 보여 줘요.

이야기 UI를 켠 채팅에서는 이어 쓸 문맥에 이전 장면의 화면을 모델이 쓴 `<a2ui>` 원형 그대로 전달해, 화면이 놓였던 위치와 구성을 모델이 이어 갈 수 있게 해요. 이야기 UI를 끈 채팅, 요약, 번역 참고에는 화면의 문구와 데이터만 투영해요. Risu 표시 변환 채팅에서도 유지된 이야기 UI 블록은 본문 안에서 정상 동작해요.

번역 시 화면 문자열만 모델에 전달해 저장된 구조에 복원하며, 구성 요소·이벤트·수치 값은 원본을 유지해요. 번역 결과에 화면 블록이 빠져 복원할 수 없으면, 먼저 모델이 번역을 거절한 것인지 판정해요. 거절이면 다른 거절과 같이 다시 시도하고, 아니면 번역 실패로 표시해요. 어느 쪽이든 원문은 그대로 읽을 수 있어요.

액션 제출은 최신 장면의 원문 해시를 확인하므로 원문이 수정되면 이전 화면의 선택을 보낼 수 없어요. 채팅 복사본에서는 복사본의 최신 장면을 기준으로 선택을 보낼 수 있어요.

`core/story-ui-scan.ts`는 zod와 A2UI 카탈로그 없이 태그 유무만 판별해요. `web/story-ui-parser.ts`를 쓰는 화면(`web/StreamingResponse.tsx`, `web/SourceReader.tsx`)은 태그가 없는 본문을 바로 문단으로 그리고, 태그가 있을 때만 검증기(`core/story-ui.ts`)를 불러오며 그동안 결과 자리 표시를 보여 줘요. 시작 번들이 검증기를 다시 끌어오지 않도록 웹 코드는 `core/story-ui.ts`를 정적으로 가져오지 않아요. 이미지 태그를 감추는 `core/image-placement.ts`처럼 블록의 범위만 필요한 코드는 `core/story-ui-scan.ts`의 `scanStoryUi`를 검증 없이 써요. 서버는 계속 `core/story-ui.ts`로 같은 검증을 동기로 해요. 직접 편집과 도우미 장면 편집은 `server/story-ui-assets.ts`의 `compileEditedSourceText`를 거쳐 저장해요. 도우미 되돌리기는 저장했던 원문을 정확히 복원해야 하므로 이 변환을 거치지 않아요. 편집 왕복은 `tests/story-ui-lifecycle.test.ts`가 확인해요. 현황 탭은 `core/story-ui.ts`의 `latestStoryUiPins`가 장면 체인에서 고르고(`tests/story-ui-pins.test.ts`), `server/story-ui-routes.ts`의 `/api/chats/:id/story-ui/pins`와 `web/StoryBoardPanel.tsx`가 보여 줘요. 고정 블록을 따로 저장하지 않고 매번 장면에서 다시 고르므로 편집, 재생성, 분기, 백업에 별도 상태가 없어요. 현재 장면은 `web/useStory.ts`가 읽기 위치와 같은 기준(`readerLocation`)으로 정해요.

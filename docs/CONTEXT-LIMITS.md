# 입력 컨텍스트 한도와 자동 요약

모델 편집의 **입력 컨텍스트 한도**는 앱이 다음 요청을 준비할 때 사용하는 토큰 추정 한도예요. 기본값은 **272,000**, 직접 지정 범위는 **8,192–1,000,000**이에요. 출력 토큰 한도는 별개이며 이번 변경으로 늘리지 않았어요.

확인된 native 모델은 모델별 전체 문맥에서 선택한 출력 예약량을 뺀 값도 실효 입력 한도에 적용해요. 설정값은 유지하고 실행 화면에는 실효 한도를 표시해요. Codex 실행기·Vercel 경로·미등록 모델에 API 모델의 전체 문맥 크기를 추정 적용하지 않아요.

## 요청을 준비하는 과정

1. 원문 전체 이력과 실제 user/assistant 쌍, 모델·연결·자료·정사·원문 구간 정책을 Run에 고정해요.
2. 정확한 최종 요청 body의 system·메시지·도구·카탈로그·출력 스키마를 모두 세어요. 캐시 읽기 토큰도 입력 문맥에서 빼지 않아요.
3. 입력이 실효 한도의 85%를 넘으면 앞선 대화를 요약해 보통 75% 아래로 줄여요. 최근 두 원문을 우선 유지하고, 그것만으로도 너무 크면 더 앞선 원문부터 순서대로 요약해요. 현재 사용자 입력과 고정 지침은 삭제하지 않아요.
4. 요약은 명시한 기억 모델을 사용하고, 없으면 해당 실행의 모델을 사용해요. 기존 요약과 새 대화를 합쳐 갱신해요. 큰 원문은 UTF-16 조각을 모두 처리한 뒤에만 요약 완료로 표시해요.
5. 최종 요약과 유지할 원문 목록을 고정한 뒤 메인 호출을 시작해요. 압축된 원문도 `story.search/read`에서 같은 출처·해시 범위로 조회할 수 있어요.

요약은 파생 기억이며 작가 정사나 상태 판정의 증거를 대신하지 않아요. 저장 원문·사용자 지시의 귀속·과거 Run은 그대로 남아요. 진행 화면, 원문, 작업 상세에서 입력 추정치와 한도, 요약한 원문 수, 이번 실행의 요약 호출 수를 볼 수 있어요.

공통 자료에서 직접 작성한 시작문은 `authored-start` 출처로 고정해 assistant 단독으로 요약해요. 없던 사용자 요청을 만들지 않으며, 일반 대화의 사용자 메시지가 유실된 경우에는 계속 오류로 처리해요. 보관 검증은 원래 Run의 시작 모드와 원문 해시를 대조해요.

이전 대화를 제외해도 고정 입력이 85%를 넘으면 유지 중인 조회 로어를 오래 사용하지 않은 순서로 통째 정리해 75%를 목표로 줄여요. 고정 자료는 제거하지 않아요. 이때 남은 조회 구간과 정리 이유를 Run에 저장하고 다음 턴은 그 결과만 상속해요. 단순히 대화가 길다는 이유로 작은 조회 자료부터 모두 지우지 않아요. 요약 모델에는 실제 대화만 보내며 조회 로어 본문은 섞지 않아요. 요약으로 원래 위치가 빠진 참고 자료는 요약 뒤·최근 대화 앞에 별도 메시지로 제공해요.

## 재사용과 실패

- 다음 요청은 같은 자료·정사·원문 구간 정책과 원문 해시를 갖는 완료된 조상 Run의 요약을 재사용할 수 있어요. 구간의 시간별 제외 범위도 `viewHash`로 비교해요. 제외된 리포트가 요약으로 되살아나지 않아요.
- 원문 수정이나 retcon으로 의존성이 달라지면 다음 요청에서 기존 요약을 재사용하지 않아요. 보관 검증은 과거 snapshot 당시의 의존성을 확인하며 최신 원문으로 과거 기록을 덮어 판정하지 않아요.
- 요약 호출도 실행의 전체 `maxCalls`에 포함하고 메인 호출 한 번을 남겨요. 평가 도구의 라운드 한도는 실제 해당 역할의 호출에 따로 적용해요.
- 전송 전 attempt를 기록해요. 거절·빈 응답·잘림·전송 오류·취소는 자동 재시도하지 않으며, 불확실 실행을 재시작 후 재생하지 않아요. 관측된 usage와 미확인 `null`을 보존해요.
- 현재 입력과 고정 자료 자체가 너무 크거나 호출 한도가 모자라면 이유를 표시하고 멈춰요. 도구 결과·opaque continuation이 진행 중 한도를 넘으면 그 요청을 보내지 않으며 도중에 대화를 재작성하지 않아요.

상태·기억 보조 작업도 같은 요약 엔진으로 이전 대화를 줄여요. 판정할 현재 원문은 한 번, 온전히 보내고 전체 출처 이력은 결과 검증과 원문 조회에 유지해요. 현재 원문·정사·스키마 등 필수 입력만으로 한도를 넘으면 요청 전에 실패해요. 번역은 현재 원문 전체와 원문시점 자료를 보내며 모든 역할의 실제 전송 body에는 최종 입력 한도 검사가 적용돼요.

## 추정 방식과 검증 범위

`tiktoken@1.0.22`의 로컬 WASM `o200k_base`를 사용해요. 큰 단일 문자열의 비선형 처리 비용을 피하도록 최대 4,096 UTF-16 단위로 나누고 동일 요청의 같은 조각은 계산을 재사용해요. 합계에 10% 여유를 더해요. 문자열·키·토큰은 외부 계산 서비스로 보내지 않아요.

이 값은 **o200k 기반 입력 토큰 추정치**예요. 다른 모델의 tokenizer, 공급자의 내부 포맷, 조각 경계에 따른 차이가 있어 실제 청구 입력 토큰이나 상한 보장으로 해석하면 안 돼요. 실제 usage는 별도 공급자 응답으로 기록해요. 설치·Node 실행 방식과 MIT 라이선스는 [tiktoken 공식 저장소](https://github.com/dqbd/tiktoken)에서 확인했어요.

구현 위치는 `core/context-budget.ts`, `core/context-plan.ts`, `core/context-projection.ts`, `server/context-planning.ts`, `server/context-compaction.ts`예요. 로컬 합성 검증은 흐름·귀속·취소·보관 계약을 확인하며 실제 모델의 요약 품질·청구액·계정별 최대 문맥을 증명하지 않아요.

## 전체 원문 번역

번역 구간 기준과 분할 계획은 제거했어요. 현재 장면 원문 전체를 일반 텍스트로 번역하며 모델 입력·출력 한도, timeout, 작업별 maxCalls는 유지해요. 한도 초과나 부분 응답 때문에 자동으로 다시 나누거나 재생하지 않아요.

예약 시 현재 번역 모델·전역 프롬프트·정책을 고정해요. 응답 앞 1,000자에 대한 별도 모델의 거절 판정과 자동 재요청도 같은 전체 호출 한도에 포함해요. 수동 재번역은 현재 설정으로 새 작업을 만들고 이전 성공본은 새 작업의 실패·취소에도 표시해요. 원문과 과거 Run snapshot은 바뀌지 않아요. 세부 계약은 [RUNTIME-SIMPLIFICATION.md](RUNTIME-SIMPLIFICATION.md)를 봐요.

진단은 전체 작업과 attempt의 호출 수·입출력 토큰·공급자 보고 비용을 기록해요. 공급자가 보고하지 않은 비용은 미확인이며 추정하거나 0으로 바꾸지 않아요. archive/fork는 원문·결과 귀속을 검증하며 번역문 안의 구간 마커나 앵커를 검사하지 않아요.

# 입력 문맥·요약·메모

원문 전체 이력은 보존하고, 실제 전송에는 **유효한 요약 + 아직 요약하지 않은 원문 + 사용자 메모·정정**을 사용해요. 모델이 매 장면 기억 항목을 추출하는 기능과 색인 watermark는 제거했어요. 오래된 원문은 해당 채팅의 원문 이력 범위에서 `story.search/read`로 다시 읽어요. `story.search`는 query를 생략하면 순서대로 목록을 반환하고 query를 주면 검색해요. 명시적 사용자 메모는 별도 조회 도구로 숨기지 않고 유효한 전체 메모를 host context에 직접 제공해요.

문맥 수명과 압축 시점은 host가 관리해요. 저장할 대화 요약은 전역 문맥 정리 모델로 만들고, 사용자는 기존 요약 화면에서 조회·편집·수동 압축할 수 있어요. 본문 실행 중 읽기 결과를 정리하는 임시 요약과 도우미 대화 요약은 각각 별도 수명과 범위를 유지해요.

## 입력 한도와 자동 정리

모델 편집의 **입력 컨텍스트 한도**는 요청 준비에 쓰는 토큰 추정 한도예요. 기본값은 **272,000**, 직접 지정 범위는 **8,192–1,000,000**이에요. 출력 토큰 한도는 별개예요. 확인된 native 모델은 전체 문맥에서 선택한 출력 예약량을 뺀 값도 실효 입력 한도에 적용해요. Codex 실행기·Vercel 경로·미등록 모델에 API 모델의 전체 문맥 크기를 추정 적용하지 않아요.

**채팅 설정 → 자동 후속 작업 → 작업당 모델 호출 한도**는 정수 1~32회이며 새 채팅의 기본값은 8회예요. `PATCH /api/chats/:id/settings`도 같은 범위를 허용해요. 본문 요청의 조회 후속 호출·문맥 요약은 이 한도를 함께 사용하고, 설정 변경은 이후 예약에 반영돼요. 번역은 별도 정책의 2~64회, 도우미는 전체 2~100회 안에서 판단 호출을 1~전체 한도로 정하므로 도우미의 전체·판단 한도 32/32도 허용돼요. 호출 횟수는 입력 토큰 한도·출력 한도와 다른 제한이에요.

1. 예약할 때 전체 원문과 실제 user/assistant 쌍, 모델·프로바이더·자료·메모·원문 구간 정책, 활성 checkpoint의 정확한 ID/revision/hash를 고정해요.
2. 최종 요청 body의 system·메시지·도구·카탈로그·출력 스키마를 모두 세어요. 캐시 읽기 토큰도 입력 문맥에 포함해요.
3. 입력이 실효 한도의 85%를 넘으면 이전 대화를 요약해 보통 75% 아래로 줄여요. 최근 두 원문을 우선 유지하되 필요하면 더 오래된 순서부터 추가 요약해요. 현재 사용자 입력과 고정 지침을 삭제하지 않아요.
4. **전역 문맥 정리 모델 `contextModel`**만 사용해요. 모델이 미지정이면 실제 압축이 필요한 작업만 중단해요. 다른 모델로 대체하지 않으며 예약된 모델·프로바이더를 호출 도중 교체하지 않아요.
5. 기존 요약과 모든 새 대화 조각을 병합해요. 조각의 분량은 글자 수가 아니라 기존 요약·사용자 메모·지침을 포함한 실제 요청의 추정 토큰이 문맥 정리 모델 입력 한도의 85% 안에 드는지로 정해요. 한 번에 들어가는 긴 원문을 글자 수만으로 쪼개 추가 호출하지 않아요. 나눠야 하는 원문은 UTF-16 문자 쌍을 유지하며 모든 조각을 처리한 뒤에만 요약 완료로 표시해요. 사용자 메모·정정은 별도 입력으로 보내고 파생 요약과 충돌하는 명시적 정정을 우선하도록 지시해요.
6. 최종 요약과 미압축 원문 목록을 고정한 뒤 본문 호출을 시작해요. 압축한 원문도 출처·해시·구간 정책을 유지한 검색으로 다시 읽을 수 있어요.

요약은 파생 문맥이며 사실 판정이나 도구 실행 권한을 만들지 않아요. 사용자 요청, 인물의 믿음과 불확실성, 본문에서 실제로 일어난 일을 구분해요. 공통 자료에서 작성한 시작문은 `authored-start` 출처의 assistant 단독 이력으로 보내고 존재하지 않았던 사용자 요청을 만들지 않아요.

저장된 `summary`는 문자열로 유지해요. 모델에게는 `derived-conversation-summary`와 기존 checkpoint 참조(해당 투영에 있을 때), 채팅, 압축한 원문 수와 마지막 revision/hash/viewHash를 함께 전달해요. 전체 원문 ID 목록이나 별도 기억 DB를 추가하지 않아요. 도우미 작업 요약은 `derived-helper-summary`와 도우미 대화 ID·세그먼트로 구분하며 본편 요약을 대신하지 않아요. 요약이나 압축 범위를 바꾼 투영은 이전 checkpoint의 ID를 자기 출처로 재사용하지 않아요.

자신의 이전 요약과 다른 보조의 의견 모두 작성자와 불확실성을 보존해요. 재전달·재요약만으로 해석을 사실로, 제안을 지시로, 계획을 완료 사건으로 올리지 않도록 공통 지침을 적용해요. 확실성을 높이려면 새로운 근거가 필요해요. 실제 사용자 요청·설정·유효한 작가 메모는 원래 입력에서 전달하며 요약 속 작업 계획으로 대체하지 않아요. 미채택 전개는 현재 작업의 제안이지 본편에서 일어난 사건이 아니에요.

요약은 장별 줄거리를 끝없이 누적하지 않고 다음 턴에 필요한 작업 기억으로 다시 써요. 현재 상황·인물 관계와 동기·조건부 약속·미해결 사건·명시적 사용자 정정을 우선 보존하며, 오래된 해결 사건은 현재에 남은 결과로 묶어요. 세부 원문은 삭제하지 않고 `story.*`로 다시 읽어요. 전체 요약의 목표는 소비 모델 입력 한도의 12.5%, 최대 2,048 토큰이고 고정 입력을 제외한 85%까지의 여유와 요약 모델 출력 한도의 절반으로 더 줄여요. 이 값은 모델 지침이며 실제 전송 결과를 다시 측정해요. 고정 입력만으로 이미 85% 이상이면 불가능한 요약을 유료 요청하지 않고 중단해요. 출력의 강제 자르기나 부분 응답 자동 재시도는 하지 않아요.

대화를 제외해도 고정 입력이 85%를 넘으면 유지 중인 조회 로어를 오래 사용하지 않은 순서로 통째 정리해 75%를 목표로 줄여요. 고정 자료는 제거하지 않아요. 남은 조회 구간과 정리 이유를 Run에 저장하고 다음 턴은 그 결과만 상속해요. 원문 대화 요약에 조회 로어 본문을 섞지 않으며, 요약 때문에 원래 위치가 빠진 참고 자료는 요약 뒤·최근 대화 앞에 별도 메시지로 제공해요.

## 본문 실행 중 조회 결과 정리

사전 정리가 끝난 뒤에도 같은 요청 안에서 `story.read` 등을 반복하면 조회 결과가 입력을 채울 수 있어요. `server/model-runner.ts`는 다음 모델 호출 직전에 반환된 결과를 포함한 실제 전송 body를 다시 추정해요. 입력이 85%를 넘고 정리할 성공한 읽기 결과가 있으면 `server/context-tool-compaction.ts`가 예약 당시 문맥 정리 모델로 그 결과를 요약해요. 이 경로는 평가 도구 실행을 제외한 본문 실행기에 자동으로 적용해요.

정리 대상은 **이미 완료된 성공한 읽기 도구 교환**이에요. `story.*`, `knowledge.*`, `skills.*`의 등록된 조회 결과만 대상으로 삼아요. 거절된 호출, 카드 스크립트 실행 영수증과 작문 보조 응답은 원래 호출·결과를 그대로 남겨요. 요청·고정 지침·원문 ancestry를 이 경로에서 지우거나 다시 쓰지 않아요.

큰 조회 결과는 문맥 모델의 입력 한도에 맞게 모든 조각을 차례로 처리하고 이전 요약과 병합해요. 출처·장면 번호·식별자, 누가 누구에게 한 말인지, 약속별 당사자와 조건, 불확실성·명시적 정정을 유지하도록 지시해요. 한 인물의 행동 시점과 다른 인물의 약속 조건을 합치지 않도록 구분하며, 원래 읽기 도구 이름과 인자는 모델 요약과 별도로 보존해 다시 조회할 수 있게 해요. 이는 요약 지침이며 의미 정확성을 보장하는 검증은 아니에요.

회수 참조에는 읽기 도구가 실제 반환한 source revision/hash·장면 범위·문자 범위·부분/필터 여부도 보존해요. 같은 조회 인자여도 반환한 원문 hash나 범위가 다르면 합치지 않아요. 읽기 완료와 질문에 대한 확인 완료는 구분하며, 검색 발췌나 부분 범위를 전체 원문의 검증으로 취급하지 않도록 지시해요. 충분한 근거를 얻으면 답변을 마무리하되 정확한 인용·정정·빠진 범위를 위한 재조회는 허용해요.

완료된 조회 교환은 현재 실행의 전송 입력에서 `host-compacted-reads` 요약과 회수 참조로 바꿔요. 후보가 원래 요청보다 작고 실제 입력 한도 이내이면 채택하고 공급자 opaque 연속을 해제해 새 요청을 구성해요. 이때 완료된 읽기 요약과 원래 수정 영수증은 `input.source.completedToolHistory`의 일반 참고 데이터로 전달하며, 새 요청의 미처리 도구 결과나 서명 없는 native 함수 호출로 만들지 않아요. 반복 정리에서도 이전 조회 인자와 완료 영수증을 유지해요.

구조화 요청은 완료된 도구 기록까지 구성한 뒤 `withNativeHostContext`로 참고 메시지를 확정해요. 본문·번역의 동적 참고 자료는 `system`/`instructions`가 아닌 별도 사용자 역할의 참고 메시지에 두며, 사용자가 작성한 프리셋의 역할과 순서는 보존해요. 인코더는 참고 문맥 불일치를 지침 문자열에 덧붙여 보정하지 않아요. Codex는 같은 자료를 JSON `input`으로 이미 전달하므로 내용이 동일한 호스트 참고 메시지만 생략해 중복을 피하고, 현재 요청·원래 프롬프트·완료 영수증은 유지해요.

새 창과 읽기 압축 뒤에는 같은 요청을 계속 진행 중이라는 host 기록을 전달해요. 구조화 프롬프트에서는 기존 메시지 순서를 유지하고 마지막에 완료한 교환의 ID·이름·거절 여부를 참고 데이터로 덧붙여요. 원래 요청을 처음부터 다시 수행하지 않고 남은 작업을 이어가며, 오래된 요약의 다음 단계보다 실제 완료 영수증을 우선하도록 안내해요. 이 기록은 새 권한이나 전체 작업의 성공 판정이 아니에요.

85%는 정리를 시도하는 기준이며 별도의 전송 상한이 아니에요. 요약이 도움이 되지 않아도 원래 요청이 실제 입력 한도 이내이면 원래 결과와 공급자 연속을 유지해요. 같은 읽기 결과를 다시 요약해 비용을 쓰지 않고 새로 성공한 읽기 결과가 추가될 때만 다시 판단해요. 원래 요청이 한도를 넘었는데 요약도 충분히 줄이지 못하면 `CONTEXT_TOOL_COMPACTION_NO_PROGRESS`로 끝나요. 요약 호출 자체의 EOF·권한 오류·취소를 무시하고 진행하지 않으며, 어느 경로든 최종 전송의 실제 입력 한도 검사를 유지해요.

이 요약은 **현재 실행용 파생 참고 문맥**이에요. 정사나 다음 턴의 활성 checkpoint로 저장하지 않으며 실행 중 예약 입력과 도구 기록은 유지해요. 원문·현재 요약·변수는 영구 자료이며 성공한 실행의 큰 진단 입력은 완료 후 정리해요. 정리 전후 추정 토큰 수와 후보 채택 여부 `applied`는 `context.compact` 이벤트에 남아요. 사용하지 않은 요약 호출도 attempt와 사용량에서 빼지 않아요. 원문 대화는 다음 집필 요청을 준비하는 기존 사전 정리 경로에서 다뤄요.

문맥 모델이 없거나 비활성이면 `MODEL_REQUIRED:context`로 멈춰요. 요약 호출은 전체 `maxCalls`에 포함하고 다음 본문 호출 한 번을 남겨야 해요. 전송 전 attempt, 취소, 매 호출 연결 권한 검사를 유지하며 요약 실패를 자동으로 재전송하지 않아요. 강제 글자 자르기나 저장 작업 재실행으로 공간을 만들지 않아요.

## 공통 요약 지침과 출력 여유

`core/context-summary-policy.ts`는 자동 대화 요약, 실행 중 읽기 요약, 도우미 요약에 공통 정보 보존 지침을 제공해요. 주체·상대·행동·해당 행동의 조건, 관찰·계획·믿음·전언, 이행 여부 미확인, 명시적 사용자 정정과 정확한 식별자·알려진 출처를 구분해요. 이행 확인이 없다는 사실을 실패나 미이행 확정으로 바꾸지 않도록 지시해요. 지침 공유가 실행기나 저장 범위를 합치는 것은 아니에요.

별도 요약 모델을 호출하는 세 경로는 소비 모델 입력 한도의 12.5%·최대 2,048 토큰을 작업 요약의 목표로 삼아요. 요약 호출의 출력 상한은 저장 모델 설정과 4,096 중 작은 값이에요. 목표는 출력 상한의 절반과 고정 입력을 제외한 여유로 더 줄여요. 자동 대화 요약은 기존 85%까지의 여유를 쓰고, 실행 중 읽기·도우미 요약은 실제 입력 상한까지의 여유를 써요. 숫자 사고 예산이 있으면 목표 본문과 합쳐 출력 상한을 넘지 않도록 함께 조절하며, 숫자 없는 사고 강도는 유지해요. 저장 모델이나 과거 snapshot을 수정하지 않고 해당 요약 요청에만 적용해요.

숫자 사고 예산 보정은 내부 요청의 방어 경계예요. 현재 정상 모델 설정은 `thinkingBudgetTokens`를 허용하지 않고 실제 공급자 인코더도 전송하지 않아요. 따라서 이 숫자 예산 검사는 합성 입력에 대한 증거이며 실제 공급자 지원을 뜻하지 않아요. Gemini 실비교는 기존 `thinkingLevel: LOW`를 유지해요.

실행 중 읽기 요약의 고정 입력은 빈 요약뿐 아니라 보존할 실제 참조 metadata·안내·변경 영수증을 포함한 최종 요청 형태로 계산해요. 모델이 생성한 뒤에는 완성된 요청 본문을 다시 재서 채택 여부를 판단해요.

목표 길이는 모델 지침이고 실제 결과의 길이나 의미 정확성을 보장하지 않아요. 최종 후보의 전송 body는 다시 측정하고 각 경로의 채택·저장 조건을 적용해요.

## 요약에서 원문 장면 찾기

`story.search/read`는 원문의 `sceneNumber`와 현재 `sceneScope`를 반환해요. `story.search`는 query가 없거나 빈 문자열이면 목록 탐색으로 동작해요. 번호는 **예약 시 고정한 해당 채팅의 전체 원문 ancestry에서 1부터 시작하는 위치**예요. 작성된 시작문이 있으면 1번이며 소설 본문에 적힌 회차 번호와는 별개예요. 요약으로 압축하거나 검색 결과를 거르거나 페이지를 넘겨도 번호를 다시 매기지 않아요. 범위에는 채팅 ID, 마지막 원문 revision/hash가 있고 각 결과는 해당 원문의 revision/hash를 유지해요. 선택 지점에서 독립 복사한 채팅도 같은 앞부분은 같은 번호를 갖지만 원문 ID는 새로 부여되므로 다른 채팅의 식별자로 사용하지 않아요.

요약의 중요한 약속·정정·미해결 사실에는 출처를 아는 경우 `[scene 12]`처럼 짧은 위치를 남기도록 지시해요. 자동 요약은 모든 분할 조각에 `sourceSceneNumber`를 보내고, 원문 조회 결과는 번호·revision/hash와 범위를 알려줘요. 번호를 모르는 오래된 사실에 출처를 지어내거나 원문마다 요약 항목을 만들도록 요구하지 않아요. 위치 표기는 기존 전체 요약 목표 안에 포함하며 의미상 정확성은 모델 출력에 달려 있어요.

번호가 있으면 `story.read {sceneNumber: 12}`로 바로 읽어요. 모델-facing 계약은 `sceneNumber` 하나만 식별자로 사용하며 내부 revision ID는 provenance로 반환할 뿐 조회 인자로 받지 않아요. 범위 밖 번호는 수정 가능한 `RESOURCE_UNAVAILABLE`, 잘못된 문자 위치는 `INVALID_ARGUMENTS`로 반환하고 원문 hash 검증·UTF-16 offset·24,000바이트 결과 한도는 그대로 적용해요. 원문 무결성 오류는 수정 가능한 입력 실수로 취급하지 않아요. 위치 표기는 조회를 돕는 정보이고 저장 원문·정정 권한·checkpoint 유효성을 바꾸지 않아요.

## 수동 정리와 요약 편집

**채팅 설정 → 기억과 메모**에서 현재 요약, 요약한 원문 범위, 최근 정리 작업과 메모를 확인해요. **지금 압축**은 자동 임계값 아래에서도 최근 두 원문 이전의 이력을 압축해요. 남은 정리 대상이 없고 입력이 한도 안이면 공급자를 호출하지 않는 no-op으로 완료해요. 본문 Run이나 새 장면을 만들지 않아요.

요약 직접 편집은 현재 요약을 교체해요. 이전 요약 목록과 복원 UI는 제공하지 않아요. 편집 요청은 활성 revision과 원문 head를 확인하고 재전송 시 변경을 중복 적용하지 않은 채 현재 상태를 반환해요. 작은 요청 해시만 저장하며 전체 조회 결과를 영수증으로 복사하지 않아요.

요약의 저장·편집·모델 도구는 원문과 같은 200만 자 자원 상한을 사용해요. 실제 사용 가능 여부는 전체 작문 입력의 추정 토큰으로 판단하며, 자동 요약의 길이는 위의 요약 목표 토큰과 출력 토큰 설정으로 안내해요. 글자 수를 토큰 한도로 취급하거나 이미 저장된 요약을 잘라 바꾸지 않아요.

네이티브 Risu 자료와 RISUP를 사용하는 수동 압축·요약 편집은 작업 입력의 사본에서 CBS·정규식을 먼저 평가해요. 도우미의 같은 문맥 도구도 이 경계를 사용해요. 평가 결과를 작업에 고정하며 Lua/V2 콜백·지속 VM·추가 모델 호출·채팅 변수 쓰기는 실행하지 않아요. 수동 압축에 필요한 요약 모델 호출과 checkpoint 저장은 기존 예산·CAS 계약을 유지해요.

자동 정리를 기다리는 동안 사용자가 요약이나 메모를 고치면 늦은 결과는 비활성 후보로 남아요. 다음 요청의 활성 요약을 되돌리지 않으며, 현재 진행 중인 실행은 자신이 포착한 checkpoint를 계속 사용해요. 완료 뒤 활성 상태나 재시도 입력이 참조하지 않는 후보는 정리해요. 원문이 추가되더라도 기존 prefix가 동일해야 활성화할 수 있고, 편집으로 prefix가 달라지면 활성화하지 않아요.

`GET /api/chats/:id/context`, `PUT /context/summary`, `POST /context/compact`와 `/context/jobs/:jobId`의 조회·취소가 이 계약을 사용해요. 각 짧은 경로 앞에는 `/api/chats/:id`가 붙어요. 자동·수동 결과는 `context_checkpoints`, 활성 포인터는 `context_heads`, 수동 실행과 전송 영수증은 `context_jobs/context_job_attempts`에 보존해요.

도우미의 `context.read`와 화면 상세는 같은 현재 요약·원문 출처·유효한 메모·사용 가능 여부를 읽어요. 화면만 최근 10개 정리 작업의 작은 상태를 더 제공해요. 완료 작업의 전체 입력이나 과거 checkpoint 본문을 조회해서 버리는 경로는 없어요. 요약이 현재 자료와 맞지 않으면 `usable: false`와 이유를 반환해요.

`server/context-dependency.ts`는 실제 작문 program과 적용값·자료·정정·네이티브 이력에 따라 재사용을 판단해요. 전역 설정 번호나 도우미/번역 모델만 바뀐 것은 본문 요약 무효화 사유가 아니에요. `tests/context-checkpoint-storage.test.ts`와 `tests/helper-context-read.test.ts`가 저장 수명과 조회 경계를 검사해요.

## 사용자 메모·정정

메모는 사용자가 명시한 내용과 작성자, 적용을 시작한 원문 ID/hash를 보존해요. 원문이 없는 새 채팅에서도 작성할 수 있어요. 저장은 메모 revision과 채팅의 원문 head를 CAS로 보호하며, 수정·삭제는 해당 채팅에 새 대체/종료 기록을 남겨요. 독립 복사한 채팅의 메모는 별도로 관리해요.

유효한 메모는 Run에 고정하며 `notes` 프롬프트 슬롯에 제공해요. 슬롯이 없으면 host가 별도로 넣어요. 메모는 이미 현재 응답에 필요한 명시적 사용자 지시·정정이므로 `notes.list/read` 같은 중복 모델 도구는 제공하지 않아요. 원문 anchor의 hash가 바뀐 메모는 다음 입력에서 제외하고 과거 snapshot의 내용은 유지해요. `StoryConfig.memory`, `memory` 슬롯, `memory.search/read`, 기억 추출 job과 재색인 API는 지원하지 않아요. 사용자 메모를 본문에서 추출한 사실이나 상태 변경 결과로 바꾸지 않아요.

## 문맥 관리의 책임과 이전 설정

본문 모델에는 `context.read/write/new`를 등록하지 않아요. 입력량 계산·요약·창 전환은 host가 맡고, 정확한 과거 내용은 `story.search/read`, 참고 자료는 `knowledge.*`로 회수해요. 평가 도구의 기존 판단·제출 흐름은 유지해요. 문맥 정리 모델이 없으면 실제 압축이 필요한 작업만 기존처럼 `MODEL_REQUIRED:context`로 멈추며, 본문 모델을 자동 대체 요약기로 사용하지 않아요.

이전 프리셋·백업에 있는 `contextTools` 설정은 더 이상 동작하지 않아요. 저장된 원문이나 요약을 지우는 마이그레이션은 없어요. 기존 `origin: 'model'` checkpoint는 출처 표시와 의존성 검사를 유지하며 조회·편집·재사용할 수 있어요. 명시적 사용자 메모와 요약 편집의 우선권도 그대로예요.

도우미가 사용자 요청에 따라 실행하는 `context.read`, 요약 편집·압축 앱 작업은 본문 모델의 자동 창 전환 도구와 별개예요. 해당 사용자 기능은 기존 dispatcher와 저장 계약을 사용해요.

진행 중인 구버전 Anthropic Batch 작업은 업데이트 전에 완료해 주세요. 도구 목록·지침이 달라진 요청을 이전 요청 hash에 맞춰 강제로 재생하거나 새 유료 요청으로 자동 재전송하지 않아요.

## 재사용·실패·복원

- 다음 요청은 예약 때 캡처한 활성 checkpoint를 원문 prefix/hash, 자료·메모 의존성, 구간 `viewHash`로 검증해요. 현재 활성 포인터를 다시 읽어 과거 Run의 입력을 재해석하지 않아요. 모델을 바꾸면 새 모델 예산으로 재측정해요.
- 원문·메모·자료·구간 정책이 달라진 요약은 다음 입력에 재사용하지 않아요. 화면에는 보존된 요약과 재사용 불가 이유를 표시해요. 숨기거나 제외한 구간이 요약으로 되살아나지 않아요.
- 요약 호출도 상위 작업의 전체 `maxCalls`에 포함해요. 본문/상태 작업은 다음 역할 호출을 위해 한 번을 남기고, 독립 수동 정리 작업은 자신의 예산을 전부 사용할 수 있어요.
- [JEV 선별](LORE-CONTEXT.md#jev-사전-선별) 호출도 같은 `maxCalls`를 쓰고 본문·거절 판정에 필요한 호출 예산을 남겨요. 남은 예산이 부족하면 선별을 건너뛰며, 이미 쓴 선별 호출은 이어지는 자동 정리의 남은 예산 계산에 포함해요.
- 전송 전에 attempt를 기록해요. 거절·빈 응답·잘림·오류·취소는 자동 재시도하지 않으며 재시작 후 불확실 실행도 재생하지 않아요. 취소 후 늦은 결과는 checkpoint를 활성화하거나 terminal 상태를 바꾸지 않아요. 받은 usage와 미확인 `null`을 보존해요.
- 고정 입력이 너무 크거나 호출 예산이 모자라면 이전 정상 checkpoint를 유지하고 중단해요. 상태 작업도 같은 요약 엔진을 사용하며 판정할 현재 원문을 온전히 한 번 보내요. 번역은 현재 원문 전체와 원문시점 자료를 보내고, 모든 역할의 실제 body에 입력 한도 검사를 적용해요.
- 선택 지점에서 독립 채팅을 복사하면 그 시점까지의 원문·메모를 새 ID로 연결해요. 선택 지점 이후의 메모와 내부 문맥 checkpoint·요약은 복사하지 않아요. 새 채팅에서 요약이 필요하면 복사한 원문과 메모로 다시 만들어요.
- DB와 교환 형식은 [현재 지원 버전](DATA-MIGRATIONS.md)을 사용해요. 전체 DB 스냅샷은 내부 checkpoint와 활성 참조도 보존해요. 개별 채팅 백업·독립 복사는 사용자 자료를 새 채팅으로 가져오되 내부 요약·작업·전송 기록을 재생하지 않아요. 구형 DB/archive의 자동 이관은 지원하지 않아요.

도우미 대화도 같은 checkpoint 형식을 사용하지만 본편과 별도 scope에 저장해요. 도우미의 대화·작업 방식은 [사용 안내](USAGE.md#도우미와-독립-가정-장면)를 봐요.

도우미는 85%를 압축 시도 기준으로 사용하며, 후보가 원래 요청보다 작고 실제 입력 상한 이내이면 채택해요. 정상 완료한 후보가 도움이 되지 않아도 원래 요청이 한도 안이면 원래 이력·결과·공급자 연속 정보를 유지해요. 둘 다 보낼 수 없으면 `HELPER_COMPACTION_NO_PROGRESS`로 중단해요. 정리할 내용이 없는 고정 입력은 실제 상한을 넘을 때 `HELPER_FIXED_CONTEXT_TOO_LARGE`로 중단해요.

채택 때만 checkpoint를 게시하고 세그먼트를 전환해요. 완료된 수정·거절·알 수 없는 도구 교환은 원형 그대로 `input.source.completedToolHistory`의 일반 참고로 유지하고 미처리 native 호출로 재구성하지 않아요. 같은 읽기 입력·결과만 반복되거나 수정 영수증만 늘었다는 이유로 다시 요약하지 않으며, 새 읽기 데이터나 실제 상한 초과에서 재판정해요. 원래 권한·operation ID·CAS·누적 사용량·취소는 유지해요. `context.compaction` 이벤트의 `applied`와 정리 전후 추정량으로 채택과 보류를 구분해요.

압축 후 `input.source.continuation`에는 같은 도우미 작업의 세그먼트와 성공한 읽기의 인자·실제 반환 위치를 남겨요. 큰 본문은 요약으로 전달하되 source/hash/revision·부분 범위·필터 정보는 회수 참조에 보존해요. 거절·실패한 읽기를 완료 목록에 넣지 않으며, 읽기 완료를 전체 답변의 정확성으로 간주하지 않아요. 이 metadata와 정확한 변경 영수증의 크기도 압축 후보의 실제 입력에 포함해요.

### 응답 EOF의 발생 단계

EOF는 공급자 스트림이 정상 완료 신호 없이 끝났다는 뜻이에요. 입력 문맥 초과나 출력 토큰 부족과 같은 원인으로 단정하지 않아요. 원래 attempt에는 공급자의 `UNEXPECTED_EOF`를 남기고 상위 작업은 다음 코드로 실패 단계를 구분해요.

| 실패한 호출 | 작업 오류 코드 |
| --- | --- |
| 일반 본문·도우미 답변 등 공급자 호출 | `UNEXPECTED_EOF` |
| 본문 실행 전·수동 원문 대화 요약 | `CONTEXT_COMPACTION_EOF` |
| 본문 실행 중 완료된 조회 결과 요약 | `CONTEXT_TOOL_COMPACTION_EOF` |
| 도우미 대화·작업 문맥 요약 | `HELPER_COMPACTION_EOF` |

부분 요약을 성공한 checkpoint로 저장하거나 원문을 요약 완료로 표시하지 않아요. 이전 활성 요약·원문·완료된 변경 영수증은 유지하며 불확실한 호출은 자동 재생하지 않아요. 특히 도우미의 변경이 저장된 뒤 최종 답변만 끊긴 경우는 [사용 안내의 도우미](USAGE.md#도우미와-독립-가정-장면)처럼 저장된 변경과 미완료 응답을 따로 표시해요.

## 추정과 검증 범위

### 다음 요청 미리보기

채팅 입력창의 **다음 요청 미리보기**는 현재 초안과 저장된 원문 head·설정·작문 모델·프롬프트·페르소나로 다음 첫 본문 요청을 투영해요. `POST /api/chats/:id/request-preview`는 `request`와 선택적인 `loreContextReset`만 받으며, 실제 요청과 같은 초안 길이·빈 입력 검사를 적용해요. 응답에는 선택 항목과 revision, 로컬 토크나이저·실효 입력 예산·요청 추정량, 로어 보존·고정 항목 수, 기존 요약의 재사용 여부만 포함해요. 원문·프롬프트 본문·연결 주소·인증 정보는 돌려주지 않아요.

기존 요청 빌더와 공급자 encoder body를 로컬에서 측정하고 10% 여유를 더해요. 입력 예산은 기존 모델 예산 계산 결과를 그대로 쓰며 출력 예약량을 다시 빼지 않아요. 의미별 토큰 분해 합계나 정확한 청구 비용은 제공하지 않아요. 유효한 활성 checkpoint만 현재 대화에 투영하며 요약 생성·문맥 정리·JEV 선별·모델 호출·Run/작업 생성·DB 저장은 수행하지 않아요. 실제 인코딩된 요청에서 기존 요약을 확인한 경우에만 사용 중으로 표시해요. 프롬프트의 대화 범위 등으로 포함 여부를 확인할 수 없으면 재사용 가능 여부와 구분하여 미확인으로 표시해요. 85%를 넘는 추정은 문맥 정리가 필요한 상태로 표시하되, 실행 시 정리 가능 여부와 최종 입력량은 아직 확정되지 않아요.

네이티브 Risu 미리보기는 복사한 CBS 필드와 정규식을 평가하지만 `input`·`editInput`·`start` 콜백과 `editRequest` 변환을 실행하지 않아요. JEV 로어 선별도 대기 상태로 표시하므로 실제 실행 입력과 달라질 수 있어요. 로드 실패 시 토크나이저 대체 정보를 표시하고 계산할 수 없는 값은 `null`로 반환해요. 조회 중 head·설정·프로필·전역 설정·선택 모델·연결·첨부 자료·활성 문맥 revision이나 원문 hash가 바뀌면 `snapshot.stale`로 이전 투영임을 표시해요. 화면에서도 초안이나 채팅 상태가 바뀌면 이전 응답을 현재값으로 재사용하지 않으며 다시 조회할 수 있어요.

`tests/request-preview.test.ts`는 실제 API와 임시 SQLite, 네이티브 미리보기 경로에서 조회 전후 DB 변경 수·공급자/콜백 미실행·초안 및 현재 설정 반영·유효 요약 재사용·조회 중 revision 변경을 확인해요. 이 검사는 실제 공급자 청구량이나 모델 요약의 의미 품질을 보장하지 않아요.

완료된 조회 결과를 요약할 때 전체 입력이 요약 모델 예산에 들어가면 한 번에 전달하고, 초과할 때만 분할 위치를 탐색해요. 입력량 측정은 실제 encoder body를 사용하며 요약 결과를 채택하기 전 최종 입력 한도를 다시 확인해요.

새 실행은 모델에 맞춰 자동 선택하거나 고급 설정에서 지정한 로컬 토크나이저를 snapshot에 고정해요. 본문·도우미와 각 요약 요청은 각각 자기 모델의 토크나이저로 실제 encoder body를 측정하고 10% 여유를 더해요. 문자열·키·토큰을 외부 계산 서비스로 보내지 않으며, 필요한 토크나이저만 처음 사용할 때 불러와 제한된 캐시에 재사용해요. 지원하지 않는 모델이나 로드할 수 없는 토크나이저는 일반 로컬 추정치로 계산해요. 선택한 토크나이저 로드에 실패한 경우 장면 상세에도 이 사실을 표시해요.

토크나이저 선택이 없는 기존 snapshot은 저장 당시 `o200k_base-v1` 요청 계산을 유지해요. 로어 보존과 일반 발췌의 `o200k_base-text-v1` 예산도 유지하며, 최종 전송 요청은 해당 실행에 고정된 모델 토크나이저로 다시 검사해요. 모델 설정을 바꿔도 진행 중인 실행·공급자 continuation·과거 장면의 계산을 새 설정으로 바꾸지 않아요.

로컬 텍스트 분절이 맞더라도 JSON 계수는 공급자의 실제 입력 포맷이나 청구 토큰과 같지 않아요. 토크나이저 세대·공급자 내부 포맷·조각 경계 차이 때문에 이 수치는 여전히 추정이며 상한 보장도 아니에요. 같은 내용의 body라도 실행마다 새로 만드는 Run·메시지 ID와 해시 때문에 추정값이 조금씩 달라져요. 기존 `o200k_base-v1`에서 관측한 예로 직렬화 길이가 15,887 UTF-16 단위로 동일한 body가 6,943–7,011 토큰(약 1%) 범위로 움직였어요. 85%·75% 판정은 이 편차보다 큰 여유가 있을 때만 결정적이므로, 합성 검사도 픽스처를 경계 1% 안쪽에 두지 않아요.

구현은 `core/context-budget.ts`, `core/context-plan.ts`, `core/context-projection.ts`, `core/notes.ts`, `core/story-context.ts`, `server/context-planning.ts`, `server/context-compaction.ts`, `server/context-tool-compaction.ts`, `server/model-runner.ts`, `server/context-store.ts`, `server/story-notes.ts`에 있어요. `tests/context-integration.test.ts`와 관련 context/story 검사는 실제 앱 경로와 fresh SQLite, 합성 provider body로 경합·취소·입력 귀속·보관을 확인해요. 기존 모델 작성 checkpoint 보존과 실행 중 조회 결과 정리는 해당 context 저장·도구 검사로 확인해요. 단계별 EOF는 `tests/context-compaction.test.ts`와 `tests/helper-compaction.test.ts`에 회귀가 있어요. 실제 요약의 의미 품질·공급자 인증·계정별 문맥 상한·물리적 휴대폰 검증은 별도예요.

### 파생 문맥 검증

`tests/context-provenance.test.ts`는 조건부 약속, 인물의 전언, 보조의 해석, 작가 정정, 미채택 전개를 여러 번 투영해도 호스트가 본문이나 출처를 바꾸지 않는지 검사해요. 이는 모델이 여러 번 요약해도 의미를 보존한다는 증거는 아니에요. `tests/context-tools.test.ts`는 실제 요청 빌더를 통해 다섯 전송 경로의 지침 영역과 참고 자료를 구분하고, `tests/agent-collaboration-context.test.ts`는 실제 도구 루프에서 캐시·전달·원문 범위를 확인해요.

실제 모델을 평가할 때는 같은 사례를 1회·3회·5회 요약한 뒤 조건·주체·불확실성·정정·제안 구분이 남는지 비교해요. 정보가 이미 충분한 경우의 불필요한 재조회도 함께 세요. 자동 감독 모델, 문장별 확신 점수, 매번 원문 재검증하는 단계는 추가하지 않아요. 이 변경에는 실모델 의미 품질 측정 결과가 포함되지 않아요.

## 전체 원문 번역

번역은 현재 장면 원문 전체와 원문 시점의 문맥을 사용해요. 구간 분할·자동 재분할은 없으며 입력·출력·시간·전체 호출 한도를 적용해요. 입력 구성·거절 판정·재번역의 보존 계약은 [본문 생성과 번역](GENERATION.md#번역)을 봐요.

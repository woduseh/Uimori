# 독립 자료 교환

봇·페르소나·모듈·프리셋의 **개별 백업**은 Uimori 설정과 연결 자료·이미지를 함께 옮기는 기능이에요. Risu 파일 내보내기와는 별도예요. 원본 파일 컨테이너나 실행 영수증을 보존하지 않고 현재 저장된 자료를 내보내요.

공통 `uimori-native-transfer` 형식에 선택한 자료, 필요한 연결 모듈, 프리셋 옵션 조합과 이미지가 들어가요. 서버 DB 테이블을 그대로 노출하지 않아요. 가져올 때는 검토 후 항상 새 ID의 사본으로 추가하고 내부 참조를 새 자료에 연결해요. 같은 이름의 기존 자료를 덮어쓰거나 자동 병합하지 않아요.

화면에서 만드는 백업은 `.uimori` 파일이에요. `uimori-archive` 버전 1의 무압축 ZIP 안에 `manifest.json`과 `images/<SHA-256>.bin`을 넣으며, 이미 압축된 이미지 바이트를 다시 압축하거나 base64로 전체 조립하지 않아요. 전체 파일은 512MiB, 메타데이터는 32MiB, 묶음의 서로 다른 이미지 바이트는 최대 65,534개예요. 개별 카드의 논리 에셋은 12,288개까지 보존하며, 이름이 다른 동일 이미지도 이름·역할은 각각 유지해요. 기존 `.json` 파일 가져오기와 JSON API는 유지하며 JSON 요청 한도는 256MiB예요.

가져오기 화면에서는 프리셋 조언자가 지정한 외부 모델을 자동으로 주 모델 따르기로 바꿔요. 모델 지정이 있는 파일은 가져오기 요약에 이를 안내해요. 프로바이더 키는 포함하지 않아요. 이미지 이름·설명·Risu 참조 이름은 함께 보존하지만 이미지 바이트는 공통 WebP 처리 경계를 거쳐요. 이미 WebP인 이미지는 다시 손실 압축하지 않아요.

`server/resource-bundle.ts`가 사용자 자료 묶음을 만들고 적용해요. `server/transfer-images.ts`는 묶음의 이미지 변환과 참조 치환만 맡아요. 전체 실행 이력의 재현·복구·신뢰 증명을 위한 receipt 체계는 없어요.

가져오기 요청은 원본 파일과 검토한 digest를 확인한 뒤 이미지를 변환하고, 변환된 자료의 구조·이미지 해시·참조를 한 번 확인해요. 이 검증 결과와 요약을 내부 적용 단계에서 재사용해 같은 파일을 반복 검증·복사하지 않아요. 새 자료와 중복 요청 방지 영수증은 하나의 트랜잭션으로 저장해요.

`.uimori` 가져오기는 업로드 파일의 목차·CRC·이미지 SHA-256을 검사하고 이미지를 하나씩 준비한 뒤 검토 결과를 보여줘요. 적용 단계는 준비된 바이너리 파일을 한 번에 하나씩 등록하며 검토 이후 재변환하지 않아요. 적용 성공 후 준비 파일은 바로 정리하고, 미완료 준비 결과는 최대 24시간 동안 유지해요. 만료된 미완료 요청은 파일을 다시 선택해야 해요. 완료된 요청은 임시 파일이 없어도 같은 요청 영수증으로 중복 없이 확인해요. 내보내기는 읽기 전용 DB 스냅샷에서 이미지를 하나씩 스트리밍하므로 다운로드 도중 자료 변경·이미지 정리가 바이트를 바꾸지 않아요.

Risu 파일과 `.uimori` 백업의 준비 작업은 프로세스 전체에서 한 건씩 실행해요. 다른 준비 작업이 진행 중이면 대기열을 만들지 않고 완료 후 다시 시도하도록 알려줘요. 연결이 끊기면 준비를 취소하고 임시 산출물을 정리해요. 이미 시작한 이미지 변환은 완료되는 즉시 결과를 버리고 다음 이미지로 진행하지 않아요.

일반 자료 가져오기 영수증은 최근 256개를 보관해요. 채팅 transcript와 재시도 영수증은 이 정리에서 제외해, 이후 자료를 많이 가져와도 같은 요청이 새 채팅·생성을 만들지 않아요.

# 프로바이더와 모델

Uimori에서 사용하는 AI 프로바이더 연결, 모델 프리셋 등록, 역할별 배정 및 관련 세부 옵션을 설정하는 안내예요.

검사용 로컬 fixture 등록과 기존 fixture 연결의 복제는 `UIMORI_TEST_MODE=1` 환경변수가 설정된 검사 환경에서만 표시돼요. 일반 화면에서는 실제 프로바이더를 등록하며, 기존에 저장된 검사용 연결의 조회·편집·관리 기능은 그대로 유지해요. 연결 안내에는 인증 및 목록 조회 방식, 지원 제약 사항을 함께 표시해요.

---

## 프로바이더와 모델 등록

### 연결 추가 및 키 관리

1. **설정 → 프로바이더와 모델 → 프로바이더 관리**로 이동해요.
2. **프로바이더 추가**를 눌러 원하는 프로바이더 유형을 선택해요.
3. API 기본 주소와 인증 정보를 입력하고 저장해요.
   - **일반 API 연결**: 발급받은 API 키를 앱에 직접 저장해요.
   - **Google Cloud Vertex AI**: 서비스 계정 JSON 파일을 업로드해요.
   - **Codex (ChatGPT)**: [Codex 안내](CODEX.md)에 따라 전용 실행기 로그인 상태를 연동해요.
4. 연결을 수정한 때 키 입력란을 비워 두면 기존 키를 유지하고, 명시적인 키 삭제 동작을 수행해야 저장된 연결에서 키가 해제돼요.

#### 지원 프로토콜 및 접속 주소 안내
- **프로토콜 구분**: OpenAI Responses 호환, OpenAI Chat 호환, Anthropic Messages 등 프로토콜과 주소를 명확히 구분해요.
- **사용자 지정 주소 및 LAN 연결**: 일반 연결은 사용자 지정 호환 주소나 사내망 LAN HTTP 주소도 지정할 수 있어요.
- **Docker 컨테이너 주의사항**: 컨테이너 안에서 `localhost`는 컨테이너 자신을 가리켜요. 호스트 PC나 다른 PC의 서비스를 바라보려면 실제 LAN IP나 호스트 네트워크 주소를 입력해야 해요.
- **Google AI Studio**: 공식 Gemini API 주소만 사용하며, 임의의 프록시 주소로 우회하지 않아요.

### 모델 프리셋 등록

1. 프로바이더 등록 후, 해당 프로바이더 하위에 **모델 프리셋**을 추가해요.
2. 프로바이더가 제공하는 모델 ID와 출력 한도, 사고(Thinking) 수준, 생성 옵션을 설정해요.
3. **모델 ID 수동 입력**: 목록에 없는 최신 모델이나 파인튜닝 모델도 모델 ID를 직접 입력해 등록할 수 있어요.
4. 모델 프리셋을 저장하는 것만으로는 외부 API에 요청을 보내지 않아요.

### 프로바이더 및 모델 순서 정렬

모델 프리셋 목록은 프로바이더별로 묶여 표시되며 각 묶음을 접고 펼칠 수 있어요.

- **마우스 드래그**: 프로바이더 행이나 묶음 제목을 끌어 프로바이더 간 순서를 바꾸고, 모델 행을 끌어 같은 프로바이더 내 모델 순서를 변경해요. 항목 위쪽에 놓으면 앞, 아래쪽에 놓으면 뒤에 배치돼요.
- **키보드 단축키**: 항목에 포커스한 후 **Alt + ↑ / ↓**를 눌러 이동해요.
- **터치 기기**: 항목 보조 메뉴의 **순서 조정**을 사용해요.
- **적용 범위**: 설정한 순서는 역할별 모델, 채팅, 삽화, 협업의 모델 선택 드롭다운에 즉시 반영돼요. 일반 프로바이더와 모델 순서는 서버 DB에 저장되며, 별도 판단용 연결인 TypeSafe AI의 목록 위치는 브라우저 로컬에 저장돼요.
- **안내 사항**: 순서를 변경해도 이미 선택된 모델이나 생성 설정은 영향을 받지 않아요. 검색어를 입력 중일 때는 일치하는 항목을 보여주기 위해 모든 묶음이 자동으로 펼쳐지며 순서 변경은 잠시 비활성화돼요.
- **자동 갱신**: 프로바이더와 모델 목록은 저장하거나 다른 창에서 돌아오면 자동으로 갱신돼요. TypeSafe AI 등록 상태를 읽지 못하면 오류 옆에서 바로 다시 조회할 수 있어요.

## 역할별 모델 배정과 생성 설정

### 역할별 모델 선택

**설정 → 역할별 모델**에서 각 작업에 사용할 모델 프리셋을 지정해요.

| 역할 | 설명 |
| --- | --- |
| **작문** | 본문 생성 및 스토리 이어쓰기를 담당하는 메인 모델이에요. |
| **번역** | 원문 자동/수동 번역을 담당하는 모델이에요. |
| **도우미** | 자료 제작, 설정 질의, 퇴고 제안을 수행하는 보조 모델이에요. |
| **거절 감지** | 본문 생성 후 안전성 거절 여부를 판단하는 선택 모델이에요 (TypeSafe JEV 사용). |

- **빠른 프리셋 편집**: 선택 항목 옆의 **선택 모델 편집** 버튼을 누르면 해당 모델 프리셋 화면으로 바로 이동해 수정할 수 있어요.
- **초안 보존**: 화면을 전환하더라도 저장하지 않은 역할 선택 상태는 유지돼요. 다른 모델 초안으로 교체할 때는 저장·계속 편집·버리기 확인 과정을 거쳐요. 프로바이더와 모델의 미저장 초안은 각각 유지되며, 한쪽을 저장하거나 화면을 옮겨도 다른 쪽 초안이 지워지지 않아요.
- **새 모델 등록 시 주의사항**: 새 모델을 등록하더라도 기존 역할 배정이 자동으로 바뀌지 않아요. 반드시 **설정 → 역할별 모델**에서 직접 선택하고 저장해야 새 모델이 적용돼요.

### 채팅별 생성 설정과 전역 설정 연계
- 채팅 설정의 **생성 설정** 화면에서 본문 모델 선택란 아래의 **전역 모델 설정** 링크를 누르면 전체 모델 설정 화면으로 바로 이동할 수 있어요.
- 모델이 아직 지정되지 않았거나 사용할 수 없게 된 상태에서도 같은 자리에서 전체 설정을 열 수 있어요.
- 채팅 설정에 저장하지 않은 변경사항이 있다면 저장·계속 편집·버리기 확인 창이 먼저 나타나요.

### Vercel AI Gateway 모델 계열 선택
- 직접 연결은 해당 API 고유의 생성 옵션을 사용하지만, Vercel 연결에서는 **모델 계열**을 통해 제조사별 옵션 세트를 선택해요.
- 자동 추정과 수동 선택 모두 지원하며, 알 수 없는 계열이어도 공통 옵션으로 저장할 수 있어요.
- 계열 선택은 옵션 UI를 결정할 뿐이며, 프로바이더의 실제 지원 여부를 보장하거나 새 전송 프로토콜을 추가하지는 않아요. 자세한 내용은 [모델 생성 설정](MODEL-PARAMETERS.md)을 참고해요.

## 지원 프로바이더별 세부 안내

### Google AI Studio (Gemini API)

**프로바이더 추가 → Google AI Studio · Gemini**에서 공식 발급받은 API 키를 등록해요.

- **엔드포인트**: 공식 주소 `https://generativelanguage.googleapis.com/v1beta`를 사용해요 (`google-gemini-v1`). 별도의 서비스 계정이나 프로젝트 ID는 필요하지 않아요.
- **환경변수**: 서버 환경변수로 지정할 때는 `GEMINI_API_KEY`를 사용해요.
- **서비스 티어 (Service Tier)**: 모델 프리셋에서 Standard, Flex, Priority 중 선택할 수 있어요 (실제 지원은 모델과 계정 설정을 따름).
  - Standard 및 모델 기본값: API 요청 시 필드를 생략해요.
  - Flex 및 Priority: Gemini API의 `service_tier` 매개변수로 전달해요.
  - 참고 링크: [Gemini API 키 안내](https://ai.google.dev/gemini-api/docs/api-key), [Flex 추론](https://ai.google.dev/gemini-api/docs/generate-content/flex-inference), [Priority 추론](https://ai.google.dev/gemini-api/docs/generate-content/priority-inference).
- **단가 설정**: Gemini API 단가는 자동으로 추정되지 않으므로 모델 프리셋에서 직접 입력해야 해요.

### Google Agent Platform (Vertex AI)

Gemini용 `vertex-gemini-v1` 연결은 Google Cloud의 기업용 엔드포인트를 사용해요.

- **서비스 계정 등록**: 앱 화면에서 서비스 계정 JSON 파일을 업로드하면 프로젝트 ID가 global endpoint에 반영돼요.
- **검증 및 저장**: 파일 선택 시 형식만 검사하고, 프로바이더를 저장할 때 서비스 계정도 함께 안전하게 DB에 저장돼요. 저장하지 않거나 저장이 실패한 초안의 인증 정보는 DB에 남지 않아요.
- **오류 410 대처**: 서버 업데이트 전에 열어 둔 구버전 화면에서 등록을 시도하면 410 오류가 발생할 수 있어요. 이 경우 페이지를 새로고침한 뒤 JSON 파일을 다시 선택해 저장해 주세요.
- **인증 재사용**: 등록된 Vertex 인증은 본문 생성뿐만 아니라 Google Model Garden 모델 목록 조회에도 함께 사용돼요. 교체하거나 삭제한 이전 서비스 계정은 실행 중인 작업의 참조 보호를 위해 안전하게 보존돼요.

### TypeSafe AI / JEV

**프로바이더 추가 → TypeSafe AI**에서 API 키를 등록해요. 로어북 관련성 선별, 본문 삽화 이미지 선택, 그리고 선택적인 본문 거절 감지에 활용돼요.

- **거절 감지**: 기본적으로 꺼져 있으며, **역할별 모델 → 거절 감지**에서 켤 수 있어요. 켜두면 본문 생성 후 JEV가 안전성 거절 여부를 판정해요 (다른 JEV 기능을 끄지는 않아요).
- **키 관리와 모델 테스트**: 프로바이더 화면에서 키를 관리하고, **모델 프리셋 → TypeSafe AI → JEV**에서 모델 ID 지정 및 판단 응답 테스트를 실행해요. 화면 전환 시에도 입력 초안과 진행 중인 테스트가 유지돼요.
- **이미지를 보고 선택 (실험 기능)**:
  - 기본적으로는 에셋 ID, 이름, 설명 등 텍스트 메타데이터를 비교해 문단별로 삽입 후보를 선별해요. 여러 문단에서 같은 에셋이 선택되면 중복을 자동 제거해요.
  - 이 옵션을 켜면 로컬 검색으로 좁힌 최대 16개의 실제 이미지 후보를 TypeSafe에 전송해요. 전송용 이미지는 회전 방향을 바로잡고 512×512 JPEG로 맞추며 원본 파일은 손상되지 않아요.
  - 적합한 이미지가 없으면 삽입하지 않으며, 최종 본문 삽입은 기존과 동일하게 최대 4장이에요. 변환이나 판단 실패를 텍스트만의 선택으로 숨기거나 자동 재시도하지 않아요.
- **긴 컨텍스트 (실험 기능)**:
  - 기본 컨텍스트 한도는 요청 전체 64,000토큰, 질문별 32,000토큰이에요.
  - 이 설정을 켜면 둘 다 최대 262,000토큰까지 허용해요. 로어의 별도 입력 상한과 본문에 전달할 로어 예산은 유지돼요.
  - 이미지 토큰은 응답 사용량에 포함되지만 로컬 텍스트 추정에는 포함되지 않으므로 제공사의 입력 초과 응답이 최종 기준이에요. 긴 입력과 이미지는 토큰 사용량과 응답 지연을 증가시킬 수 있어요.
- **참고 문서**: 지원 모델과 형식 제약은 [TypeSafe 모델 문서](https://docs.typesafe.ai/models)와 [TypeSafe 이미지 문서](https://docs.typesafe.ai/images)를 따라요. 환경변수 fallback이나 별도 `.jev-credentials` 파일은 일반 실행에서 사용하지 않아요.

### Anthropic 실시간 및 Batch 실행

직접 `Anthropic · Messages` 연결을 사용하는 모델 프리셋은 **실행 방식**을 선택할 수 있어요.

- **실행 옵션**:
  - `실시간`: 기존과 동일하게 즉시 스트리밍 또는 완성형 응답을 받아요 (기본값).
  - `Batch · 비동기 · 50% 할인`: 50% 할인된 요금으로 비동기 Batch API를 통해 실행해요.
- **적용 범위**: 본문을 생성하는 메인 Run에 적용돼요. 번역, 도우미, 제목 생성 등의 보조 작업은 빠른 응답을 위해 기존 실시간 실행을 유지해요. Batch 응답은 스트리밍처럼 꾸미지 않고 완료되면 한 번에 표시해요.
- **취소 동작**: 사용자가 작업 생성을 취소하면 로컬 Run이 즉시 취소되며, 생성된 Anthropic Batch가 있으면 조회 응답을 읽는 중에도 원격 취소를 best-effort로 요청해요. 서버 종료는 사용자 취소가 아니므로 원격 Batch를 취소하지 않아요. 취소 뒤 늦게 도착한 결과는 source로 commit하지 않아요.
- **비용 계산**: Anthropic Batch 추정 비용은 모델 프리셋에 별도로 입력한 Batch 단가를 기준으로 계산해요. Batch 단가가 없으면 비용 미확인으로 표시되며 기본 단가에 임의로 자동 할인을 적용하지 않아요. 업데이트 전에 예약된 작업의 가격 snapshot은 당시 계산을 유지해요. 실제 청구 금액은 Anthropic 대시보드가 기준이에요.

### Codex (ChatGPT 구독 연동)

Codex는 일반 API 키가 아니라 서버에 설치된 전용 실행기의 로그인 상태를 사용해요.
자세한 설정 방법, Docker 환경 구성 및 CLI 요구사항은 [Codex 안내](CODEX.md)를 참고해 주세요.

## 모델 목록 조회와 응답 테스트

### 모델 목록 조회
- **목록에서 선택**: 모델 ID란 아래의 **모델 목록에서 선택**을 펼치면 프로바이더에서 조회한 지원 모델 목록을 검색하고 고를 수 있어요.
- **모델 목록 새로고침**: 사용자가 직접 버튼을 눌렀을 때만 외부 API에 목록 갱신을 요청해요.
  - HTTP 프로바이더: 각 프로바이더의 모델 목록 API를 호출해요.
  - Codex: 로그인된 로컬 실행기의 모델 목록을 조회해요.
  - Vertex AI: 등록된 서비스 계정 인증으로 Google Model Garden을 조회해요.
- 조회가 실패하더라도 마지막으로 저장된 목록을 유지하며, 모델 ID를 직접 텍스트로 입력하는 것은 언제든 가능해요.

### 응답 테스트
- 모델 프리셋 화면의 **응답 테스트** 버튼을 눌러 실제 API 호출이 정상 작동하는지 확인해요.
- 프로바이더가 등록되어 있거나 모델 목록에 이름이 보인다고 해서 실제 호출 성공을 보장하지 않으므로, 새 모델을 등록한 후에는 테스트 호출로 검증하는 것을 권장해요.

### 작업 현황과 사용량 표시
- **작업 현황**의 **전체 역할의 호출과 비용**에서 요청별 입력·출력 토큰을 목록을 펼치기 전에도 확인할 수 있어요.
- 상세 화면에는 프로바이더 보고 캐시 사용량과 로어 이름·출처·전달 방식(전체 본문, 읽은 구간, 요약만)을 표시해요.
- 원시 요청·응답 JSON은 별도로 펼칠 때만 화면에 생성되고, 닫으면 메모리에서 해제해요. 토큰이 보고되지 않은 경우는 숫자 0과 구분해 `미확인`으로 표시해요.

## Gemini 안전 필터 설정

Google AI Studio 및 Google Cloud Vertex AI 직접 연결 모델은 **고급 → Gemini 안전 필터**에서 안전성 차단 수위를 조정할 수 있어요.

### 설정 범주
- 괴롭힘 (Harassment)
- 증오 표현 (Hate Speech)
- 성적 콘텐츠 (Sexually Explicit)
- 위험 콘텐츠 (Dangerous Content)
- 탈옥 시도 (Jailbreak)

### 차단 단계 옵션
- **모델 기본값**: API 요청 시 해당 범주 설정을 생략해요 (모든 범주가 기본값이면 `safetySettings` 전체를 전송하지 않음).
- **OFF**: 조정 가능한 안전 필터를 완전히 비활성화해요.
- **BLOCK_NONE**: 자동 차단 없이 안전성 평가만 요청해요.
- **차단 수위 지정**: 높음만 차단, 중간 이상 차단, 낮음 이상 차단 중에서 선택해요.

> [!NOTE]
> 이 설정은 제공사의 조정 가능한 필터 매개변수를 제어하는 것이며, 모델 자체에 내장된 원천적인 보호 기능까지 해제하는 것은 아니에요. 상세 규격은 [Gemini generateContent REST](https://ai.google.dev/api/generate-content#SafetySetting) 및 [Google Cloud 안전 필터 가이드](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/configure-safety-filters)를 따라요.
> 현재 연결은 generateContent 계열의 `safetySettings`, `category`, `threshold` 형식을 사용하며 Interactions 형식과 섞지 않아요. 탈옥 시도는 `HARM_CATEGORY_JAILBREAK`로 전달하고 Jailbreak 차단 응답은 거절로 처리해요. 모델 ID로 설정을 숨기거나 자동 치환하지 않으며 실제 사용 가능 여부는 제공사의 응답을 따라요. 평가 방식 `method`는 생략해 기존 API 기본 동작을 유지하고, 폐기된 Civic integrity 범주는 추가하지 않아요.

## 키 관리와 전체 백업 주의사항

- **DB 내 단일 저장**: 일반 API 키와 JEV 키는 앱 SQLite DB의 안전한 테이블에 저장돼요. 별도의 암호화 키 파일이 필요한 이중 저장소 구조는 아니에요.
- **내보내기 보호**: 일반 설정 조회, 개별 자료 내보내기, 개별 채팅 백업 파일에는 키 원문이 절대 포함되지 않아요.
- **전체 백업 시 주의**: **전체 SQLite 백업 파일(`.sqlite`)에는 API 키와 업로드된 이미지가 원본 그대로 포함**돼요. 따라서 전체 DB 백업 파일은 외부에 공유하거나 공개 저장소에 올리지 마세요.

## 구현 참고

이 섹션은 프로바이더 연동과 관련된 내부 아키텍처, 전송 인코딩, 동시성 및 진단 규약을 설명하는 개발자/에이전트 계약이에요.

### 요청 변환 및 소유권 경계
- `core/model-request-fields.ts`: 실행 스냅샷에서 모델 ID, 프로바이더 옵션, 확정된 가격 스냅샷만 추출해 요청 객체로 변환해요. 생성 옵션, 컨텍스트 예산, 도구 정의, 저장 및 실행 정책은 각 호출 주체가 독자적으로 결정해요.
- `server/provider-connections.ts` 및 `server/credentials.ts`: 연결 입력값 검증과 키 저장(DB 읽기/쓰기)을 담당해요. 연결 저장 시 최종 URL 검증과 새로 선택하거나 기존에 저장한 Vertex 서비스 계정 프로젝트 검증은 동일 트랜잭션에서 원자적으로 수행돼요. 자료 편집과 과거 백업 검증이 프로바이더 전송 경로에 개입하지 않아요.
- `server/main-request.ts`: 공통 컨텍스트 측정 경로로, 프로바이더별 요청과 모델별 토크나이저 예산을 통합 처리해요. 컨텍스트 계획, 자동 압축, 다음 요청 분량 미리보기가 이 경로를 사용하며, 실제 전송할 요청을 기준으로 측정하고 요약 포함 여부를 확인해요. Gemini 대화는 역할과 순서를 유지한 네이티브 텍스트로 전송하며, Codex의 두 실행 형식 측정과 도우미 전용 입력 형식도 유지해요.
- 프롬프트 형상 검증은 원본 데이터를 복사하거나 수정하지 않으며, 수정이 필요한 입력과 프로바이더 연속 상태는 소유 경계에서 복사해요. 공개 스트림을 소비하지 않는 호출에서는 중간 표시용 본문을 조립하지 않으며 최종 결과·사용량·취소 처리는 유지해요.

### 프로토콜별 이미지 및 메시지 인코딩
- **본문 참고 이미지 전달 규격**:
  - OpenAI Responses: `input_image`
  - OpenAI Chat / Vercel: `image_url`
  - Anthropic Messages: `image`
  - Google Gemini / Vertex AI: `inlineData`
  - Codex: 전용 이미지 입력 객체 (Codex의 이미지 생성 도구는 켜지 않음)
- **이미지 제약**: DeepSeek 직접 연결 및 명시적으로 확인된 텍스트 전용 모델은 이미지 입력을 거절해요. 지원 여부가 확인되지 않은 사용자 지정 모델은 지원 미확인 상태로 전송을 허용해요. 현재 이미지 입력은 본문 사용자 요청 범위이며 입력 번역, JEV 선별, 도우미 패널에는 이미지 첨부 UI가 노출되지 않아요.
- **Vercel Chat 변환**: 이전 assistant 메시지의 텍스트 조각들을 순서대로 합쳐 하나의 문자열로 전송해요.
- **OpenAI Responses 변환**: 수동 대화 이력을 assistant를 포함하여 `input_text` 조각들로 구성하고 조각별 캐시 기준점을 유지해요. 도구 후속 요청에서는 프로바이더가 실제로 반환한 메시지·사고·도구 호출 항목을 원래 형식과 식별자로 이어 보내요.
- **Gemini 대화 및 도구 처리**: 도구 호출 후 이어지는 요청은 모델의 원본 응답과 사고 서명을 보존하고, 동일한 사용자 턴 안의 추가 제어 텍스트를 도구 결과(`functionResponse`) 앞에 배치해 Vertex 엔드포인트 거절 문제를 방지해요 (Claude·OpenAI·Codex 요청 형식은 변경하지 않음).
- **Anthropic 메시지 보정**: `user → 연속 system → user` 형태의 프롬프트 전송 시, system 블록 끝에 짧은 가상 completed assistant 응답을 전송용으로 한 번 추가해요. 원래 프롬프트 및 실행 스냅샷의 역할·순서·본문·캐시 기준점은 옮기지 않으며 요청 미리보기 진단에만 기록돼요. 도구 후속 요청은 저장된 메시지를 그대로 재생하므로 보조 응답을 중복 추가하지 않아요.
- **DeepSeek 오류 처리**: `insufficient_system_resource` 또는 `aborted`로 응답이 종료된 경우 수신된 본문과 최종 사용량을 보존하고 미완료로 기록해요. 불완전한 도구 호출은 실행하지 않으며 자동 재요청하지 않아요. 원격 중단 사유는 지원하지 않는 응답 형식과 구분해 실행 기록에 남겨요.

### Anthropic Batch 아키텍처
- 자체 배치 스케줄러를 두지 않고, 단일 모델 호출마다 Anthropic Batch API에 요청 하나를 넣고 기존 `runMain` 도구 루프를 그대로 사용해요.
- Claude가 도구를 요청하면 로컬에서 도구를 실행한 후 다음 턴을 새 Batch로 전송해요. `story.submit` 도구가 호출되면 추가 호출 없이 작업을 종료해요.
- SQLite에 `runId`, `attemptId`, `batchId`, `customId`와 요청 해시를 저장해 서버 재기동 시에도 동일 Run과 Batch를 다시 조회해 복구해요. 저장된 Batch 결과와 도구 영수증도 재사용해 중복 실행을 방지해요.
- `batchId` 저장이 누락된 모호한 생성 실패 상태에서는 중복 과금을 막기 위해 자동 재전송하지 않고 실패로 확정해요.
- JEV와 Responses를 포함한 프로바이더 응답 본문 읽기는 작업 취소와 시간 제한에 따라 중단돼요. 완료나 오류가 확정된 뒤에는 응답 스트림 정리를 요청하되 원격 정리 확인을 기다리지 않아 지연에 막히지 않아요.

### 캐시 기준점 진단과 도구 규약 (`cacheBoundaries`)
- OpenAI Responses 및 Anthropic 실행 요청 기록에는 명시적 캐시 기준점 진단 정보인 `cacheBoundaries`가 포함돼요.
- 각 항목은 기준점 위치, 직전 입력과 도구·생성 설정을 포함한 해시, 진단 JSON 바이트 수를 담아요. 로어 뒤 내용이 바뀌어도 앞 기준점 해시는 유지되지만 도구 schema·순서·기준점 앞 사전 도구 이력이 바뀌면 달라져요.
- 기존 `stablePrefixSha256`은 공통 계약·도구만의 해시로 유지하며 전체 프롬프트의 캐시 재사용 근거로 쓰지 않아요. 암묵적 캐시만 있는 요청에는 기준점을 추정해서 추가하지 않아요. 이 진단은 실시간·Batch 모두 로컬 요청 기록에만 추가되고 프로바이더 본문에는 들어가지 않아요.
- Anthropic Messages는 `anthropic-version: 2023-06-01` 헤더를 사용해요. Uimori 도구 이름은 프로바이더 호환용 별칭으로 전송되며, 저장된 도구 이름·인수·결과와 호출 ID는 유지해요. 현재 도구 목록에서 제외한 사전 평가 이력은 원래의 유효한 이름으로 남겨요. 도구 정의 규격은 [공식 도구 정의 계약](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)을 따라요.

### 로어 포함 기록 메타데이터
- 본문·번역 요청을 전송할 때 호스트가 기존 요청 JSON에 작은 메타데이터로 로어 포함 기록을 저장해요.
- 자료 목록에 이름만 있거나 JEV에서 선별됐다는 사실만으로 실제 본문 포함을 확정하지 않으며, 프롬프트 가공 등으로 확인하지 못한 후보는 별도로 표시하고 기록이 없는 과거 요청은 미포함으로 추정하지 않아요.
- 로어 본문을 중복 저장하거나 이 기록을 모델에 전송하지 않으며, 기존 요청 기록 보관 범위를 그대로 따라요.

### 동시 수정 및 스트리밍 본문 조립
- 프로바이더와 모델 활성/비활성 상태는 자료를 삭제하지 않고 저장 즉시 다음 호출부터 적용돼요.
- 편집 화면 전환 시 미저장 입력은 보호되며, 다른 곳에서 먼저 저장된 경우 현재 초안을 유지한 채 최신 설정을 불러오도록 안내해요. 설정 조회 API는 편집 가능한 설정만 반환하고 API 키 원문은 일체 반환하지 않아요. 미저장 초안의 키 입력은 브라우저 메모리에만 존재하며 로컬 복구 저장소에 기록되지 않아요.
- 실시간 스트리밍은 디코더가 검증한 추가 청크와 UTF-16 끝 인덱스를 전달해 매 청크마다 전체 문자열을 재비교하지 않아요. 전체 본문 스냅샷이나 앞선 내용 변경 경계에서는 접두사 검증을 유지하고, 종료 시 누적 청크의 합과 최종 본문의 일치 여부를 검증해요. 사고 과정, 도구 인수, 최종 제출 envelope, 구조화 번역은 공개 조각에 포함되지 않아요.

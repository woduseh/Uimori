# 전역 역할 모델과 현재 프롬프트

모든 봇·채팅의 **이후 시작하는 작업**은 같은 전역 역할 모델과 현재 작문·번역 프롬프트를 사용해요. 채팅을 만들거나 기존 채팅을 열 때 모델·프롬프트를 다시 저장하지 않아요. 채팅별 모델 선택은 없으며, 채팅의 자료·로어·옵션 변경은 전역 모델 선택과 별도예요.

## 사용 흐름

1. 설정의 프로바이더와 모델에서 프로바이더·모델 프리셋을 등록해요. 등록은 역할 선택과 별개예요.
2. 설정 → 현재 모델에서 본문·번역·번역 거절 판정·표시 상태·이미지 배치와 선택 기능인 도우미·문맥 정리·제목 모델을 지정해요. 모델이 하나여도 자동 선택하지 않아요.
3. 같은 화면의 번역 영역에서 자동 재요청 횟수와 전체 호출 한도를 설정해요.
4. 설정 → 현재 프롬프트에서 현재 작문·번역 프롬프트와 옵션을 편집하거나 프롬프트 목록의 저장된 프리셋을 복사해 적용해요.
5. 봇을 선택해 새 채팅을 만들거나 기존 채팅을 열어 대화해요. 채팅에서는 적용 설정을 확인하고 전역 설정으로 이동해요.

미지정·삭제·비활성 모델이나 사용 불가 프로바이더는 해당 작업을 차단해요. 임의의 다른 모델로 대체하지 않아요. 과거 snapshot에 프로바이더 정보가 있어도 실제 전송 권한은 매 호출 최신 프로바이더의 활성 상태·endpoint·credential 참조와 서버 origin 정책으로 확인해요.

## 저장과 실행 경계

`GET /api/model-workspace`는 `{revision, routes, translationPolicy, titleModel, helperModel, contextModel}`을 반환하고, `PUT`은 `expectedRevision`으로 동시 편집을 보호해요. 세 선택 기능 모델은 `{id}` 참조 또는 `null`이며 PUT에서 생략하면 기존 값을 유지해요. 현재 프롬프트와 같은 `prompt_workspace` JSON 행에 저장하므로 모델·프롬프트의 동시 저장 충돌도 CAS로 처리해요. 프리셋을 적용하면 현재 작업본으로 복사하며, 프리셋 후속 수정·삭제가 현재 작업본이나 과거 실행을 바꾸지 않아요.

현재는 fresh v15 DB와 v15 archive만 지원해요. 새 DB의 역할 모델은 미지정으로 시작하고 채팅 body의 모델 값을 전역 기본값으로 채택하지 않아요. API의 채팅 `profile.routes`는 현재 전역 설정을 보여 주는 읽기 전용 projection이며 채팅별 선택 저장 경로가 아니에요. 보관된 Run의 `snapshot.profile.routes/models`는 과거 실행의 고정 정보예요. 구버전 DB/archive를 자동 이관하지 않아요.

| 작업 | 모델·프롬프트를 읽는 시점 |
| --- | --- |
| 새 본문 실행 | 예약 시 현재 전역 설정을 Run에 고정 |
| 새 번역·수동 재번역 | 예약 시 현재 번역 모델·프롬프트·거절 판정 모델·정책을 job에 고정 |
| 새 도우미 작업 | 작업 예약 시 현재 `helperModel`과 문맥 모델을 고정 |
| 자동·수동 문맥 정리 | 상위 Run 또는 독립 context job 예약 시 `contextModel`을 고정 |
| 진행 중 작업 | 예약 때 고정한 값 유지. 설정 변경으로 교체하지 않음 |
| 본문 ‘현재 설정으로 재시도’ | 원래 요청 직전 위치의 새 분기에서 현재 설정으로 새 Run 생성 |
| 번역 job 재시도 | 기존 계약대로 현재 모델·번역 프롬프트·정책으로 새 번역 job 예약 |
| 표시 상태·이미지 job 재시도 | 원래 job의 고정 입력·모델·snapshot 유지. 표시 상태의 명시적 새 요청은 현재 모델 사용 |
| 같은 입력 후보 실험 | 원래 고정 snapshot 계약 유지 |
| 채팅 포크 | 복사된 과거 원문·Run·결과 snapshot 보존. 이후 새 작업은 전역 설정 사용 |

source/hash·revision/CAS·idempotency·worker 소유권·취소·중복 방지 계약은 유지해요. 번역 응답 앞 1,000자만 별도 모델로 거절 판정하고 명확한 거절만 제한된 자동 재요청을 해요. 번역·조회·판정은 같은 전체 호출 한도를 사용해요. HTTP 오류나 불확실한 공급자 실행은 자동 재생하지 않아요.

## 별도 기능 모델

- 채팅 제목 모델은 설정 → 현재 모델의 선택 항목 `titleModel`이에요. 기본은 미지정이며 자동 제목 생성을 끄고, 본문 모델로 대체하지 않아요. 지정하면 새 채팅의 첫 성공 응답 뒤 제목을 한 번 생성하며 사용자가 직접 바꾼 제목은 덮어쓰지 않아요. 본문·번역·표시 상태·이미지의 `TaskRole`이나 채팅 `profile.routes`에는 추가하지 않아요.
  - 새 채팅에서 제목을 직접 입력한 경우와 기존 채팅·포크는 자동 생성 대상이 아니에요. 생성 시작 시 모델·프로바이더와 첫 응답을 고정하고 최대 1회·25초·출력 256토큰으로 실행해요. 전송 전 attempt를 기록하며 실패·재시작 후 자동 재호출하지 않아요. 수동 제목 저장·원문 변경·채팅 삭제가 발생하면 늦은 결과를 적용하지 않아요.
  - 채팅 메뉴에서 제목을 200자까지 반복 수정할 수 있어요. `PATCH /api/chats/:id/title`의 `expectedTitleRevision`은 제목 이벤트 revision을 사용해 같은 문자열로 저장한 수동 의사와 ABA 충돌도 보호해요. 제목 변경은 원문·설정·폴더 revision을 바꾸지 않아요.
- 도우미 모델은 `helperModel`이에요. 기본은 미지정이며 본문 모델로 대체하지 않아요. 도우미 대화·도구 실행에 사용하고 본문 원고를 저장하는 역할과 구분해요. 도우미가 요청한 독립 가정 장면은 고정한 작문 모델·작문 프롬프트를 사용해요.
- 문맥 정리 모델은 `contextModel`이에요. 기본은 미지정이며 실제 압축이 필요할 때만 작업을 차단해요. 단문 본문 실행·요약 직접 편집·정리 대상 없는 no-op은 문맥 모델을 호출하지 않아요. 본문·도우미·상태의 요약도 이 역할을 사용하고 다른 모델로 대체하지 않아요. 본문 프리셋의 선택형 문맥 도구를 켜면 본문 모델이 요약을 직접 저장·전환하므로 그 checkpoint가 유효한 동안은 문맥 모델을 호출하지 않지만, 85% 자동 정리는 여전히 `contextModel`을 사용해요. 상세 계약은 [CONTEXT-LIMITS.md](CONTEXT-LIMITS.md)를 봐요.
- 표시 상태 역할과 작품 상태 추적은 서로 다른 기능이에요. `StoryConfig.stateModel`은 작품의 상태 모듈·활성화 기준·원문 근거를 함께 관리해요. 기억 추출 설정과 모델은 제거했어요. 일반 본문·번역을 쓰기 위해 작품 상태를 다시 설정할 필요는 없어요.
- 작문 보조의 전용 모델은 전역 현재 작문 프롬프트의 `collaboration.agents[].model`에 있어요. 전용 모델이 없으면 해당 Run의 본문 모델을 사용해요. 보조 지침·모델·공유 권한은 Run에 고정하고 메인만 원문을 저장해요.
- 전역 설정을 호출 도중 다시 읽지 않아요. 모델 프리셋의 평가 도구도 독립 설정이며 역할 선택으로 권한이나 호출 한도를 확장하지 않아요. 기록·미리보기는 저장된 모델을 읽을 수 있지만 실제 전송 시점에는 최신 프로바이더 권한을 반드시 확인해요.

실제 검증 결과는 [CURRENT](../project-plan/CURRENT.md)에 기록해요. 로컬 합성 검사는 실제 공급자의 인증·품질·거절 판정 정확도나 물리적 휴대폰 검증을 대신하지 않아요.

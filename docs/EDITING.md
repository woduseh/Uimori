# 일반 자료 편집과 저장

Uimori의 봇·페르소나·모듈·프리셋 자료와 원고를 편집기에서 수정하고 저장할 수 있어요. 미저장 입력은 각 기기에 복구용으로 보관하며, 서버의 초안 ID나 제안, 미저장 입력의 기기 간 자동 동기화는 제공하지 않아요.

## 자료 편집과 저장 흐름

### 편집 상태 표시와 저장
- **상태 구분**: 편집기 헤더 상단에 자료의 현재 상태가 명확히 표시돼요.
  - **등록 전**: 아직 서버에 등록되지 않은 새 자료예요.
  - **변경 N건**: 저장본과 비교해 새로 입력하거나 바꾼 내용이 있는 상태예요. N은 바뀐 편집 영역의 수이고, 아직 편집기에 적용하지 않은 원문 JSON·정규식·트리거·토글 입력이 있는 영역도 셈해요. 좁은 화면에서는 연필 아이콘과 숫자로 줄여 보여요.
  - **저장됨**: 서버에 성공적으로 반영된 최신 상태예요.
- **변경 검토**: **변경 N건**을 누르면 화면 가운데에 큰 검토 창이 열려요. 왼쪽 목록에는 바뀐 편집 영역과 그 안에서 바뀐 항목이 늘어놓이고, 항목마다 늘어난 양과 줄어든 양(**+N −M**)이나 **추가됨**, **삭제됨**, **순서 바뀜**, **적용 전 입력**이 붙어요. 목록에서 항목을 누르면 오른쪽 내용이 그 항목으로 스크롤되고, 스크롤하는 동안에는 지금 보고 있는 항목이 목록에 표시돼요. 목록 안에서는 위아래 화살표와 Home·End 키로도 옮겨 다녀요.
  - **바뀐 내용**: 오른쪽에는 바뀐 항목마다 카드가 처음부터 펼쳐져 있어요. 항목은 로어·정규식·프롬프트 블록 같은 항목 이름과 필드 이름으로 나오고, 글은 추가된 부분과 삭제된 부분을 표시해 보여 줘요. 거의 다시 쓴 부분은 단어마다 번갈아 표시하지 않고 삭제된 글 전체 뒤에 추가된 글 전체를 이어 보여 줘요. 켬·끔이나 숫자 같은 값은 이전 값과 새 값을, 이미지와 에셋 목록은 개수만 보여 줘요. 목록 중간에 항목을 넣거나 순서를 바꿔도 그 항목만 **추가됨**이나 **순서 바뀜**으로 나오고 뒤 항목은 바뀐 것으로 보이지 않아요. 글이 너무 길거나 비교가 오래 걸리면 비교를 생략했다고 알려 줘요. 바뀐 부분이 아주 많은 글은 앞부분만 보여 주고 **바뀐 부분 더 보기**로 이어 봐요.
  - **나란히 보기와 통합 보기**: 넓은 화면에서는 저장본(왼쪽)과 지금 내용(오른쪽)을 **나란히 보기**로 보여 주고, 머리글의 전환 버튼으로 **통합 보기**로 바꿀 수 있어요. 고른 방식은 이 브라우저에 기억돼요. 좁은 화면에서는 늘 통합 보기예요.
  - **스크립트와 설정 줄**: 정규식·트리거·CSS·배경 HTML·변수와 토글처럼 줄 단위로 비교하는 내용은 줄 번호를 함께 보여 주고, 한 줄 안에서 일부만 바뀌었으면 그 줄을 통째로 칠한 위에 바뀐 단어만 더 진하게 표시해요. 바뀐 부분 사이에 접어 둔 같은 줄은 **숨긴 줄 N개 펼치기**로 펼쳐요.
  - **이동**: 카드의 **이동**을 누르면 검토 창이 닫히고 그 항목이 있는 영역으로 가요. 로어·첫 메시지·정규식·트리거·프롬프트 블록은 해당 항목을 골라 열고, 본문처럼 코드 입력란이 있는 필드는 바뀐 곳에 커서를 둬요. 삭제된 항목과 그 밖의 항목은 영역까지만 이동해요.
  - **이 항목만 되돌리기**: 카드 하나의 변경만 저장본 값으로 되돌려요. 추가한 항목은 빠지고, 삭제한 항목은 원래 자리에 돌아오고, 순서를 바꾼 항목은 원래 순서로 돌아가요. 되돌린 카드는 목록에서 사라지고, 바로 나오는 알림의 **되돌리기 취소**로 한 번 되살릴 수 있어요. 적용 전 입력이 있는 영역, 이미지·에셋 목록과 대표 이미지는 저장한 파일과 이어져 있어서 되돌리기를 제공하지 않아요.
  - **아래 줄**: 바뀐 영역 수, 항목 수와 전체 증감 옆에 **모든 편집 취소**, **닫기**, **변경사항 저장**이 있어요. 여기서 저장하는 것은 헤더의 저장과 같아서, 이름이 비어 있으면 검토 창 안에 그 오류를 보여 주고 창을 닫지 않아요. 저장에 성공하면 창이 닫혀요.
  - **좁은 화면**: 검토 창이 화면 전체를 채우고, 바뀐 항목 목록은 맨 위의 **변경 목록 N개** 버튼을 눌러 펼쳐요.
- **편집 중 표시**: 저장하지 않은 변경이 있는 편집 영역에는 왼쪽 영역 목록(좁은 화면에서는 영역 선택 목록)에 작은 점이 붙어요. 코드 입력란에서는 저장본과 달라진 줄의 왼쪽 가장자리에 가는 표시가 붙어요. 새로 생긴 줄과 고친 줄은 색이 다르고, 줄이 지워진 자리에는 짧은 표시가 남아요. 저장하면 점과 표시가 모두 사라져요. 아주 긴 입력란에는 이 줄 표시를 붙이지 않아요.
- **저장과 취소**:
  - **변경사항 저장**: 화면의 변경 내용을 실제 서버 자료에 반영해요.
  - **편집 취소**: 현재 저장되어 있는 서버 저장본을 다시 불러와 화면을 되돌려요. 넓은 화면에서는 헤더에도 있고, 좁은 화면에서는 변경 검토 창 아래의 **모든 편집 취소**로만 해요.
- **이전 저장본과 비교**: 저장한 자료와 프롬프트 프리셋의 ⋯ 메뉴에서 열어요. 변경 검토와 같은 창에서 지금 저장본과 바로 전 저장본의 차이를 보여 줘요. 이 창에는 항목별 이동과 되돌리기가 없고, 아래 줄에 **이전 저장본으로 복원**이 있어요. **이전 저장본으로 복원**을 누르면 이전 저장본을 새 저장으로 다시 저장해요. 복원한 뒤 나오는 알림의 **복원 취소**나, 비교를 다시 열어 한 번 더 복원하면 복원 전 저장본으로 돌아와요. 이전 저장본은 자료마다 하나만 남고 다음 저장이 그 자리를 대신해요. 미저장 변경이 있는 동안에는 열 수 없고, 한 번만 저장한 자료는 이전 저장본이 없다고 알려 줘요.
- **필수 항목**: 프롬프트 이름은 필수 항목이며 편집기 상단에 항상 표시돼요.
- **복구 상태 알림**: 브라우저 로컬 복구 저장소에 입력을 보관하지 못하면 헤더에 경고를 표시해요. 정상 보관은 따로 표시하지 않아요.

### 원문 JSON과 정규식 입력
- **저장 시 검증**: 원문 JSON, 정규식, 트리거 입력은 **변경사항 저장**을 누를 때 함께 파싱하고 검증해요.
- **편집기에 적용**: 편집기 안의 **편집기에 적용** 버튼은 계속해서 GUI 폼으로 편집을 이어가기 위한 선택 동작일 뿐이며, 저장을 위한 필수 단계가 아니에요.
- **문법 오류 보호**: 문법 오류가 발견되면 작성한 입력을 지우지 않고 유지한 채 오류 위치와 사유를 표시해요.
- **저장 용량 한도**: 자료 본문·로어북 및 채팅 전용 로어의 수정은 공통 원문 저장 한도인 2,000,000자(UTF-16 코드 단위)를 지원해요. HTTP 요청은 한글과 JSON 이스케이프를 포함한 전송 크기를 온전히 받아들이며, 채팅 전용 로어의 변경 개수만으로 저장을 막지 않아요.

### Risu 템플릿(CBS) 입력 칸
- **적용 칸**: 첫 메시지와 대체 첫 메시지, 카드·모듈 설명, 글로벌 노트, 대화 예시, 로어 본문, 정규식 바꿀 내용(찾을 표현식은 CBS 처리를 켠 규칙만), 프리셋 프롬프트 본문·감싸는 문구·작가 노트 기본값, 배경 HTML / CSS 칸은 코드 편집 칸으로 열려요. Lua 트리거 소스는 Lua 문법만 색으로 구분하고 CBS는 따로 보지 않아요. 변수 초기값, 토글 정의, 원문 JSON처럼 CBS가 아닌 칸은 일반 입력 칸 그대로예요.
- **색 구분과 짝 표시**: `{{`와 `}}`, 함수 이름, `::` 구분자, `#when` 같은 블록 이름, `{{// 주석}}`을 테마 색으로 구분하고, 겹친 호출은 괄호 색을 번갈아 써요. 커서를 블록 여는 칸에 두면 닫는 칸이 함께 강조되고, 짝이 없으면 오류 색으로 표시해요.
- **자동 완성**: `{{`를 입력하면 Risu 함수 이름 목록이 열려요. 다른 이름(별칭)과 설명 첫 줄을 함께 보여 줘요. `{{getvar::`, `{{setvar::`처럼 변수 이름을 받는 자리와 `{{#when::toggle::` 뒤에서는 지금 편집 중인 자료(봇·모듈이나 프리셋)에 나오는 변수와 토글 이름을 제안해요.
- **문제 표시**: 닫히지 않은 `{{`나 블록, 짝 없는 닫는 칸, `#when` 밖의 `{{:else}}`, Risu에 없는 함수 이름에 물결 밑줄을 그어요. 밑줄에 마우스를 올리거나 커서를 두면(휴대폰에서는 눌러서) 이유가 보여요. 표시는 안내일 뿐이며 저장을 막지 않고, 실행 결과도 바꾸지 않아요. 설명 아래의 **도우미에게 고쳐 달라고 하기**는 [편집기에서 도우미에게 묻기](#편집기에서-도우미에게-묻기)를 봐요. 조건값이 실행 중에 정해지는 블록처럼 미리 판단할 수 없는 경우에는 표시하지 않아요.
- **변수와 토글 사용처**: 봇·모듈의 **변수와 토글 초기값**과 프리셋의 **변수와 토글**에서 변수와 토글마다 읽는 곳과 쓰는 곳의 수를 보여 줘요. 줄을 펼치면 사용처가 나오고, 사용처를 누르면 그 영역과 항목으로 이동해 해당 이름을 선택해요. 위의 CBS 칸, 정규식, 블록 트리거의 변수 조건과 변수 설정, 초기값, 토글 정의, Lua 소스 안의 `getChatVar`·`setChatVar`·`getState`·`setState`·`getGlobalVar` 호출 가운데 이름이 따옴표로 바로 적힌 것을 셈해요. 사용처가 없으면 **사용처를 찾지 못함**이라고 보여 줘요.
  - **안내 표시**: 기본값 없이 읽는 변수, 읽는 곳 없는 변수, 쓰지 않는 토글, 이 자료에 정의되지 않은 토글을 줄 옆에 표시해요. 기본값 없이 읽는 변수는 위쪽에 따로 모으고 **기본값 추가**로 `이름=` 줄을 초기값 끝에 붙여요. Risu는 값이 빈 초기값 줄을 건너뛰므로 값을 채워야 안내가 사라져요.
  - **판단 범위**: 이 자료 안만 봐요. 함께 쓰는 모듈이나 프리셋이 읽거나 정의하는 이름은 셈하지 않으므로 안내는 참고용이에요. 변수 이름을 CBS나 Lua 코드로 계산하는 곳이 있으면 "읽는 곳 없음" 같은 판단을 "없을 수 있음"으로 낮춰 보여 줘요.
- **원문 보존**: 칸은 입력한 글자를 그대로 저장해요. 다른 프로그램에서 가져온 CRLF 줄바꿈은 손대지 않으면 그대로 남고, 고쳐도 같은 줄바꿈을 이어 써요. 한 글에 줄바꿈 방식이 섞여 있으면 그 칸만 일반 입력 칸으로 열어요. 코드 편집기를 불러오는 동안이나 불러오지 못했을 때도 일반 입력 칸으로 계속 편집할 수 있어요.

### 첫 메시지 미리보기
- **저장 전 미리보기**: 한 번이라도 저장한 자료의 **첫 메시지** 영역에서 편집 중인 첫 메시지를 저장하지 않은 채로 미리 볼 수 있어요. 채팅 시작 화면과 같은 방식으로 CBS, 정규식, Lua의 표시 단계를 실행하고, 이름(`{{char}}`), 초기값, 정규식, 트리거도 편집 중인 내용을 써요. 이 자료에 정의한 토글은 새 채팅을 시작할 때처럼 기본값(켜고 끄는 토글은 꺼짐, 고르는 토글은 첫 항목)으로 계산해요. 실제 채팅에서 고른 프롬프트 프리셋이나 함께 쓰는 모듈이 정의하는 토글과, 채팅에서 바꾼 토글 값은 미리보기가 알 수 없어서 반영하지 않아요. 이미지는 마지막 저장본에 있는 이미지만 보여요. 미리보기는 아무것도 저장하지 않아요.
- **갱신**: 입력을 멈추고 0.5초쯤 지나면 다시 그려요. 새로 그리는 동안에는 이전 결과를 그대로 두고 **갱신 중**만 표시해요. 실행이 실패하면 이유를 미리보기 위에 보여 주고 마지막으로 성공한 결과를 흐리게 남겨 둬요. 확인이 필요한 항목(찾지 못한 에셋 이름, 적용하지 못한 정규식 번호, 미리보기에서 지원하지 않는 함수)은 미리보기 아래에 문장으로 모아 보여 줘요. 처음 그리기부터 실패하면 **다시 불러오기**로 다시 시도해요.
- **표시 방식**: 넓은 화면에서는 입력 칸 아래에 나오고, 항목 제목 옆의 미리보기 버튼으로 숨기거나 다시 열어요. 이 선택은 앱을 다시 열 때까지 기억해요. 휴대폰에서는 **편집**과 **미리보기**를 바꿔 가며 봐요.

## 원문 저장본 비교

원문 편집기의 **저장본 비교** 기능을 통해 편집 중인 내용과 이전 판본을 나란히 비교할 수 있어요.

- **비교 대상**: 현재 저장본, 직전 저장본, 최초 원문의 세 가지 판본을 편집 중인 초안과 비교해요.
- **초안 불러오기**:
  - **선택한 저장본 불러오기**: 선택한 판본의 내용을 편집 중인 초안으로 가져와요 (이 동작은 화면의 초안만 바꾸며 즉시 본문으로 확정되지 않아요).
  - **불러오기 전 초안으로 돌아가기**: 판본을 불러온 뒤에도 편집 중 마음이 바뀌면 원래 작성하던 초안으로 되돌아갈 수 있어요.
- **저장 확정**: 불러온 판본을 실제 본문과 후속 작업에 반영하려면 최종적으로 **원문 저장**을 눌러야 해요.
- **보존 범위**: 성능과 안정성을 위해 앱은 최초 원문 1개와 최근 수정본 2개만 보존하며, 무제한 편집 이력을 늘리지는 않아요.

## 선택 구절 퇴고

원문 편집기에서 다듬고 싶은 구절을 마우스나 키보드로 선택한 뒤 **선택 구절 퇴고**를 열어 도우미 모델에 맞춤 수정을 요청할 수 있어요.

- **진행 단계**:
  1. **구절 선택 및 요청**: 원문에서 구절을 드래그해 선택하고 **선택 구절 퇴고**를 열어 원하는 퇴고 방향을 입력해요.
  2. **제안 받기**: **제안 받기**를 누르면 설정된 도우미 모델을 1회 호출하며, 기존 원문과 모델의 제안을 좌우로 나란히 비교해 보여줘요.
  3. **초안 반영**: 제안이 마음에 들면 **초안에 반영**을 눌러 편집 중인 초안에 적용해요 (이 단계는 화면의 편집 초안만 바꾸며 서버에 바로 저장되지 않아요).
  4. **원문 저장**: 최종적으로 **원문 저장**을 눌러야 본문과 다음 생성에 확정 반영돼요.
- **재요청 및 취소**:
  - 제안을 확인한 후 마음에 들지 않으면 **다시 제안 받기** 아이콘을 눌러 새로운 제안을 요청할 수 있어요.
  - 위쪽의 닫기 아이콘이나 패널 안의 `Esc`는 퇴고 패널만 닫고 기존 편집으로 돌아가요. 요청 중이면 요청도 취소하고, 장면 초안은 그대로 둬요.
- **컨텍스트 전달과 비용**:
  - 모델에는 선택한 구절과 해당 장면의 편집 중인 원문 전체가 문맥으로 함께 전달돼요.
  - **앞뒤 문단만 문맥으로 보내기**를 켜면 선택한 구절 앞뒤로 각각 3,000자 안쪽의 문단만 보내요. 긴 장면에서 요청이 작아지는 대신 모델은 장면의 나머지를 보지 못해요. 이 선택은 사용 중인 브라우저에 기억되고 읽기 화면의 다듬기에도 똑같이 적용돼요.
  - 퇴고 요청과 제안 내용은 서버 원고나 도우미 대화 기록에 영구 보존되지 않으며, 모델 호출 횟수와 토큰 사용량만 도우미 사용량으로 집계돼요.
  - 컨텍스트 크기를 벗어나는 긴 입력이나 불완전한 결과가 나오더라도 모델 출력을 임의로 자르거나 자동으로 재요청하지 않아요.
- **상태 변경 보호**:
  - 퇴고를 요청하는 도중에 편집 초안이나 선택 구간, 이미 저장된 원문이 바뀌면 이전 제안을 초안에 반영할 수 없게 차단하여 텍스트 꼬임을 방지해요 (작성 중이던 기존 초안은 유지돼요).
  - 요청 취소나 편집기 닫기는 대기 중인 네트워크 호출을 즉시 중단하지만, 제공사 서버에서 이미 진행된 모델 이용 비용까지 취소되는 것은 아니에요.

## 읽는 중에 다듬기

본문을 읽다가 마우스나 키보드로 글을 선택하면 선택한 글 위나 아래에 작은 막대가 떠요. 막대에는 **다듬기**, **도우미에게 묻기**, **책갈피**, **복사**가 있어요. 도우미에게 묻기는 선택한 글을 붙여 도우미 사이드 패널을 열고, 책갈피는 선택한 글을 인용으로 넣어 장면 책갈피를 만들어요.

- **다듬기가 나오는 조건**: 선택한 글이 지금 보이는 표시(원문 또는 번역)의 저장본과 글자 그대로, 그리고 한 곳에서만 일치할 때만 나와요. 장면을 어떤 방식으로 그렸는지는 따지지 않으므로 봇 채팅에서도 서식 없는 문장은 다듬을 수 있어요. 줄바꿈 문자 차이(CRLF와 LF)만 같게 보고, 따옴표나 공백 같은 다른 차이는 맞춰 주지 않아요. 그래서 표시용 정규식이 바꾼 글, 강조나 루비처럼 서식이 걸친 선택, 이야기 UI 블록과 생성된 HTML, 장면 안에 같은 글이 두 번 이상 있는 선택에서는 다듬기가 빠지고 나머지 버튼만 남아요. 이럴 때는 도우미에게 묻거나 장면 메뉴에서 편집기를 열어 고쳐요.
- **진행**: 다듬기를 누르면 선택한 글 옆에 작은 창이 열려요. 다듬을 방향을 쓰고 **제안 받기**를 누르면 도우미 모델을 한 번 호출하고, 제안을 선택한 글과 단어 단위로 비교해 보여 줘요(지운 말은 취소선, 더한 말은 밑줄). 거의 다시 쓴 부분은 단어가 뒤섞이지 않게 지운 글 전체 뒤에 새 글 전체를 이어서 보여 줘요. **적용**은 그 자리에서 바로 저장해요. 다시 제안 받기 아이콘은 새로 요청하고, **닫기**는 아무것도 저장하지 않아요.
- **저장 전 확인**: 원문은 원문 해시와 수정 번호로, 번역은 최신 번역의 수정 번호, 원문 해시, 보고 있는 번역 본문의 해시로 제안을 요청할 때와 저장할 때 확인해요. 그사이 무엇이 바뀌었으면 저장하지 않고 원문과 번역 중 무엇이 바뀌었는지 알려 주며, 제안은 창에 남아요. 바뀐 뒤에는 그 제안을 적용할 수 없으니 닫고 다시 선택해요.
- **번역에 적용할 때**: 창에서 한 번 알려요. 번역을 저장하면 진행 중인 재번역이 취소되고 번역에 맞춘 삽화 배치가 무효가 돼요.
- **적용 뒤**: 저장한 글을 바로 보여 주고, 읽던 위치를 지키며 포커스를 장면 본문으로 돌려요.
- **선택 막대와 복사**: 여러 문단에 걸친 긴 선택도 화면 안에 막대를 표시해요. 복사에 실패하면 선택과 막대를 유지하고 오류를 보여 줘 다시 시도할 수 있어요. Risu 표시가 갱신되어 선택한 본문이 사라지면 예전 선택 막대는 닫혀요.
- **키보드와 닫기**: 막대가 떠 있을 때 `Tab`을 누르면 막대의 첫 버튼으로 가고, 좌우 화살표로 버튼 사이를 옮겨요. `Esc`는 열린 다듬기 창을 먼저 닫고(요청 중이면 요청도 취소해요) 선택과 막대로 돌아가며, 한 번 더 누르면 막대를 닫아요. 적용한 내용을 저장하는 동안에는 `Esc`가 창을 닫지 않아서, 저장 결과나 충돌 안내가 창에 남아요. 다듬기 창이 열려 있는 동안에는 다른 대화상자처럼 전역 단축키가 동작하지 않아요. 선택이 풀리거나 선택한 글이 화면 밖으로 나가면 막대도 사라져요.
- **터치로 고른 글**: 휴대폰에서 길게 눌러 고른 글에도 막대가 떠요. 브라우저의 선택 메뉴와 선택 손잡이가 선택한 글 바로 위아래에 뜨기 때문에, 막대는 선택 옆이 아니라 읽기 영역의 아래쪽 가장자리에 붙고, 선택이 그 자리를 가리면 위쪽 가장자리로 옮겨요. 손잡이를 끄는 동안에는 기다렸다가 선택이 멈추면 보여 줘요. 버튼을 누르는 순간 브라우저가 선택을 풀어도 누르기 직전의 선택으로 동작해요.
- **막대가 없는 곳**: 편집기와 입력란, 이야기 UI 컨트롤, 도우미 안에서 고른 글에는 막대가 뜨지 않아요.
- 모델 호출은 요청마다 한 번이고, Codex 콘텐츠 경고 확인, 취소 시 요청 중단, 사용량만 남기고 요청과 제안은 저장하지 않는 점, 자동으로 다시 요청하지 않는 점은 편집기의 선택 구절 퇴고와 같아요.

## 과거 사용자 입력과 장면의 문맥 제어

이야기를 진행하면서 과거에 보냈던 사용자 요청을 다듬거나, 특정 장면을 이후 생성 컨텍스트에서 제외할 수 있어요.

### 문맥용 요청 수정 및 포함/제외
- **입력 수정**: 요청 아래 **요청 및 컨텍스트 메뉴 → 요청 수정**에서 **입력 저장**을 누르면, 이전 사용자 입력을 고쳐서 이후 이어지는 생성 컨텍스트에 반영해요.
  - 수정된 입력을 볼 때도 당시 실제로 보냈던 원래 요청을 펼쳐서 언제든 확인할 수 있어요.
  - Risu에서 한 장면을 여러 개의 연속된 사용자 메시지로 구성했던 경우에도, 수정된 입력을 하나의 통합 요청으로 반영하면서 첨부 이미지를 보존해요.
  - 요청 편집기(도우미 대화와 취소된 요청의 편집 포함)에서 `Esc`를 누르면 원문 편집기와 같이 바뀐 입력이 있을 때 버릴지 먼저 물어요. **요청 편집 취소** 버튼은 묻지 않고 닫아요.
- **문맥 제외와 복원**:
  - 같은 메뉴에서 사용자 입력만 제외하거나, 해당 장면의 입력과 본문을 모두 **장면을 컨텍스트에서 제외/포함**할 수 있어요.
  - 제외된 장면이라도 화면에서 완전히 사라지지 않고 비활성화 상태로 유지되며, 언제든지 다시 문맥에 포함하도록 복원할 수 있어요 (영구 삭제가 아니에요).

### 다시 쓰기 (새 채팅 / 기존 응답 교체)
요청 아래 또는 **장면 작업 메뉴 → 다시 쓰기**에서는 생성에 실제로 보낼 문구를 확인하고 수정해요.

- **초안 불러오기**: 처음 창을 열면 현재 문맥용 요청을 가져오며, 이전에 작성 중이던 실행 초안이 있으면 복원해요. 화면 표시용 변환 문구는 사용하지 않아요.
- **다시 쓰기 옵션**:
  - **새 채팅에서 다시 요청**: 해당 시점까지의 맥락을 바탕으로 독립된 새 채팅 사본을 만들어 응답을 생성해요.
  - **기존 응답 교체**: 마지막으로 완료된 장면에 한해 선택할 수 있어요. 생성이 완전히 성공한 뒤에만 기존 응답을 교체해요.
- **교체 안전장치**:
  - 생성 도중 실패하거나 취소하면 기존 응답과 원래 요청 기록을 그대로 유지해요.
  - 다시 쓰기 실행 문구를 수정하는 것만으로는 문맥용 요청이 저장되지 않아요.
  - 요청 수락 여부가 불확실하면 문구를 잠그고 동일한 요청 키로 **이전 요청 확인**을 진행해요.
  - 문맥 수정 초안, 다시 쓰기 초안, 다음 장면 입력 초안은 서로 간섭하지 않고 독립적으로 유지돼요.
- **문맥 제어의 기본 성격**:
  - 이 기능은 기존 실행 결과를 과거로 거슬러 올라가 소급 변경하는 것이 아니라, **앞으로 모델에게 전달할 문맥을 사용자가 직접 제어**하는 기능이에요.
  - 다른 장면의 번호와 본문, 이전 모델 요청 기록, 비용, 첨부 이미지, 번역, Lua/CBS 변수 및 완료된 부수효과는 그대로 보존돼요.
  - 별도로 작성된 개요나 작가 노트에서 같은 사건을 다룬 내용도 자동으로 지우지 않아요.
  - 새로운 장면이 생성되는 도중에는 과거 입력이나 문맥 활성 상태의 변경을 막아 동시 실행 충돌을 방지해요.

## 도우미를 통한 본문과 자료 편집

### 도우미 본문 편집
- **본문 수정 요청**: 채팅 도우미에게 원문이나 완료된 번역의 수정을 요청할 수 있어요.
- **안전한 저장 검증**: 도우미는 최신 저장본을 읽은 뒤, 읽었을 때의 수정 번호와 원문 해시가 일치할 때만 수정을 저장해요. 화면 표시용 HTML이 아닌 실제 저장 본문을 수정해요.
- **번역 무효화**: 원문이 변경되면 이전 원문을 바탕으로 작성되었던 번역은 더 이상 유효한 현재 번역으로 취급되지 않아요.
- **이력 제한**: 도우미는 보존되어 있는 원문 저장본을 새 판본으로 복원할 수는 있지만, 번역 판본 복원이나 무제한 이력 관리는 지원하지 않아요.
- **초안 충돌 방지**: 도우미가 본문을 저장하더라도 사용자가 열어 둔 편집기의 미저장 초안을 강제로 덮어쓰지 않아요. 저장 기준본이 달라지면 저장 충돌 대화상자에서 초안과 서버 저장본을 확인하고 병합할 수 있어요. 도우미가 사용자의 미저장 초안을 몰래 읽거나 가로채지 않아요.

### 편집기에서 도우미에게 묻기
- **부르는 곳**: 봇·페르소나·모듈과 프롬프트 프리셋 편집기에서 로어 항목, 첫 메시지와 추가 인사말, 정규식, 트리거, 프롬프트 블록의 제목 줄에 있는 도우미 버튼(**{항목} 도우미에게 묻기**)을 누르거나, 토글 줄의 메뉴에서 **도우미에게 묻기**를 골라요. 설명, 로어 본문, 배경 HTML, Lua 같은 코드 편집 칸은 오른쪽 위 모서리에 같은 버튼이 있어요. 데스크톱에서는 칸에 마우스를 올리거나 칸에 포커스가 있을 때 보이고, 휴대폰과 좁은 화면에서는 늘 보여요. 칸 안에서 글을 선택하면 이 버튼이 **선택한 부분 도우미에게 묻기**로 바뀌어 선택한 글만 붙여요. 편집기 안에 포커스가 있을 때 `Alt+I`(Apple 기기는 `Option+I`)를 눌러도 돼요.
- **오류 고쳐 달라고 하기**: CBS 문제 표시에 커서를 두면 뜨는 설명 아래에 **도우미에게 고쳐 달라고 하기**가 있어요. 커서가 칸 안에 있을 때 Tab으로 갈 수 있어요. 누르면 그 오류의 종류와 줄·칸 위치를 붙여 도우미를 열어요.
- **도우미가 받는 위치**: 도우미는 데스크톱에서는 편집기 옆 사이드 패널로, 휴대폰에서는 아래에서 올라오는 창으로 열려요. 입력창 위의 칩에 도우미가 볼 위치(영역, 항목 이름, 칸 이름, 선택한 글자 수나 오류 위치)가 보이고, ×로 빼면 그 위치 없이 자료 전체만 붙여 보내요. 따로 부르지 않아도 편집기를 열어 둔 채 도우미에게 요청하면 지금 보고 있는 영역과 항목, 포커스가 있던 칸이 함께 가요. 선택한 글은 2000자까지, 오류는 10개까지 보내고 나머지는 개수만 알려요.
- **추천 요청**: 부르면 그 항목에 맞는 요청이 몇 개 떠요. 오류가 있으면 오류 고치기, 정규식·트리거·Lua·HTML은 설명과 점검, 글은 다듬기·줄이기·이어 쓰기, 로어 항목은 키워드와 내용 맞추기를 먼저 보여 줘요. 누르면 입력창에 들어가기만 하고 보내지는 않아요.
- **저장하지 않은 입력이 있을 때**: 도우미는 편집기에 보이는 그대로(저장하지 않은 입력 포함) 읽고 설명하거나 점검할 수 있어요. 하지만 그 자료를 고치는 저장은 하지 않고 먼저 저장해 달라고 해요. 그래서 도우미의 저장이 입력 중인 글을 덮어쓰거나, 입력 중인 글이 도우미의 저장을 모르게 덮어쓰는 일이 없어요. 칩에는 **저장 전**과 **저장** 버튼이 보이고, 저장은 편집기의 저장 버튼과 같은 확인과 충돌 검토를 거쳐요.
- **도우미가 고친 뒤**: 열어 둔 편집기에 저장하지 않은 입력이 없으면 도우미가 저장한 내용이 바로 편집기에 들어오고, 변경 표시나 저장하지 않은 변경으로 남지 않아요. 도우미가 작업하는 동안 그 자료를 고치기 시작했다면 저장할 때 저장 충돌 검토가 열려 두 내용을 비교해 고를 수 있어요. 변경 카드의 열기 버튼은 열린 편집기에서 바뀐 항목으로 바로 이동해요.

### 도우미가 바꾼 내용 확인
- **변경 카드**: 도우미 답변 아래에는 그 작업이 바꾼 대상마다 한 줄씩 카드가 붙어요. 카드에는 대상 종류 아이콘, 제목, 바뀐 위치, 추가·삭제 수가 보이고, 누르면 그 자리에서 바뀐 부분을 펼쳐요. 원문, 번역, 로어 본문, 개요 같은 글은 문단 안에서 바뀐 단어만 표시하고(지운 말은 취소선, 더한 말은 밑줄), JSON, 정규식, 스크립트는 줄 단위로 보여 줘요. 긴 비교는 카드 안에서 스크롤해요.
- **비교가 없는 카드**: 바뀐 내용이 너무 크거나 비교에 시간이 오래 걸리면 비교를 생략했다고 알려요. 대상을 삭제했거나 보관 기간이 지나 바뀐 글을 지운 경우에도 그 사실만 남아요. 작업이 삭제한 대상은 목록에 남지만 열 수 없어요.
- **카드 한 장은 작업 전체의 순변경이에요**: 한 작업이 같은 대상을 여러 번 고쳐도 처음 상태와 마지막 상태의 차이 하나만 보여요. 그 뒤에 사용자가 고친 내용은 카드에 반영되지 않아요. 변경 기록이 없는 설정 변경과 삽화·장면 요청 예약은 예전처럼 결과 줄로 보여요.
- **카드에서 열기**: 카드의 열기 버튼은 바뀐 자리로 이동하고 잠깐 테두리로 표시해요. 장면은 바뀐 문단으로, 봇·페르소나·모듈은 편집기의 해당 영역(로어북 항목은 그 항목)으로, 프롬프트 프리셋은 해당 블록으로 가요. 봇 화면처럼 Risu 표시로 그리는 장면은 문단 단위 위치가 없어서 비슷한 높이로 이동하고 본문 전체를 표시해요. 개요는 플롯 작업 공간의 해당 항목으로, 작가 노트와 채팅 전용 로어는 채팅 설정의 해당 영역으로 열어요. 데스크톱에서는 도우미가 닫히지 않아요. 사이드 패널에서 열면 그대로 두고, 크게 보기에서 열면 대상 옆의 사이드 패널로 돌아가요. 이미 열려 있는 편집기는 다시 불러오지 않으므로 저장하지 않은 입력이 그대로 남고, 다른 자료에 저장하지 않은 입력이 있으면 이동 전에 확인해요.
- **필요할 때만 읽기**: 대화를 열면 마지막 작업의 결과만 바로 읽고, 이전 답변의 결과는 그 답변이 화면에 가까워질 때 읽어요.

### 도우미 변경 되돌리기
- **저장 후 검토**: 도우미는 요청한 변경을 바로 저장해요. 대화의 마지막 작업이 끝나고 되돌릴 수 있는 변경이 있으면 결과 맨 위에 **변경 N개를 저장했어요** 줄이 붙고, 되돌릴 대상이 둘 이상이면 같은 줄에 **모두 되돌리기**가 있어요. 각 카드에는 글자로 된 **되돌리기** 버튼이 있고, 바뀐 대상이 하나뿐이면 바뀐 부분이 펼쳐진 채로 보여요. 그대로 두려면 아무것도 하지 않으면 돼요. 다음 요청을 보내면 이 줄은 사라지고, 이전 작업의 카드에는 아이콘 되돌리기 버튼만 남아요.
- **되돌릴 수 있는 대상**: 서재 자료, 장면 원문과 번역, 플롯, 작가 노트예요. 마지막 작업이 아닌 이전 작업에서는 되돌릴 대상이 둘 이상이면 카드 목록 아래에 **이 작업의 변경 되돌리기**가 있어요. 한 장면의 원문과 번역은 함께 되돌려요. 설정, 채팅 전용 로어, 장면 이름은 되돌리기 대상이 아니라는 안내가 목록 아래에 한 번 나와요.
- **도우미에게 알리기**: 되돌린 변경과 확인 카드에서 **거절**한 작업은 다음 요청 하나에 함께 전달돼요. 도우미는 다시 해 달라고 하지 않는 한 같은 변경을 다시 하지 않아요.
- **되돌리기 전 확인**: 누르면 지금 상태를 다시 확인해서 되돌릴 대상과 그대로 둘 대상을 사유와 함께 보여 주고, 확인 버튼 하나로 진행해요. 작업 뒤에 다시 고친 대상, 작업 도중 다른 곳에서 저장된 대상, 삭제나 보관 기간 때문에 바뀐 글이 지워진 대상, 작업이 만들거나 지운 자료는 그대로 둬요. 번역을 되돌리는 장면은 번역 삽화 배치가 돌아오지 않는다고 미리 알려요.
- **열린 편집기의 미저장 입력**: 이 브라우저에 열린 편집기(자료 편집기, 원문과 번역 편집기, 플롯 항목 편집, 작가 노트 편집)에 저장하지 않은 입력이 있으면 그 대상은 되돌리지 않고 이유를 알려요. 입력은 그대로 남고, 다른 대상은 되돌릴 수 있어요. 저장하거나 취소하면 다시 되돌릴 수 있어요. 다른 기기에 열린 입력은 수정 번호 검사로만 지켜요.
- **결과**: 되돌린 카드에는 **되돌렸어요**가, 되돌리지 못한 카드에는 사유가 남아요. 되돌린 상태는 대화를 다시 열어도 유지돼요. 열려 있는 깨끗한 편집기와 읽기 화면은 되돌린 내용으로 새로 불러와요. 되돌린 저장도 일반 저장이라 편집기의 **이전 저장본과 비교**에서 다시 복원할 수 있어요.
- **진행 중인 작업**: 이 대화에 진행 중이거나 대기 중인 도우미 작업이 있거나 요청을 보내는 중이면 되돌리기 버튼을 쓸 수 없고 그 이유가 보여요.
- **결과를 모를 때**: 요청을 보낸 뒤 연결이 끊기면 자동으로 다시 보내지 않고 **결과 확인**을 보여 줘요. 누르면 무엇이 되돌려졌는지 다시 읽어 카드에 표시해요.

### 도우미 서재 자료 편집과 일괄 처리
- **서재 복제**: 서재 목록 복제와 도우미의 `resource.clone`은 동일한 서버 복제 기능을 사용해요.
- **일괄 수정**: 도우미를 통해 여러 자료를 한 번에 수정할 때는 모든 자료의 수정이 성공해야만 원자적으로 저장돼요.
- **프리셋 진단**: 프리셋 진단 기능은 토글 정의와 선택값, 직전 저장 이후 선택지 이름과 번호의 변화를 분석해 줘요. CBS는 직접 실행하지 않으며, 진단 결과는 저장을 차단하지 않아요.

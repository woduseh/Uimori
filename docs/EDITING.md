# 일반 자료 편집과 저장

봇·페르소나·모듈·프리셋은 화면에서 편집하고 **변경사항 저장**으로 실제 자료를 갱신해요. **편집 취소**는 현재 저장본을 다시 불러와요. 서버의 초안 ID, 제안, 작업 영수증, 미저장 입력의 기기 간 동기화는 없어요.

프롬프트 이름은 필수 항목으로 편집기 상단에 항상 표시해요. 기본 저장 상태는 편집기 헤더에 모아 표시하며, 아직 등록하지 않은 새 자료는 **등록 전**, 입력을 바꾸면 **미저장 변경**, 실제 저장된 자료는 **저장됨**으로 구분해요. 복구 보관 상태와 오류는 계속 별도로 알려줘요.

원문 JSON·정규식·트리거 입력은 저장할 때 함께 파싱해요. `폼에 반영`은 계속 폼으로 편집하기 위한 선택 동작이지 저장의 필수 단계가 아니에요. 문법 오류가 있으면 입력을 남기고 오류를 표시해요.

이 기기의 최신 미저장 입력만 IndexedDB에 비동기로 덮어써요. 타이핑마다 전체 자료를 localStorage에 동기 저장하지 않아요. 성공적으로 보관된 경우에만 복구 보관 상태를 표시하며 실패를 성공처럼 표시하지 않아요. 저장·취소·원래 값으로 되돌리기는 이 편집 세션이 읽었거나 성공적으로 쓴 복구 입력만 정리해요. 각 저장의 식별자를 IndexedDB의 한 트랜잭션에서 비교해, 다른 탭이 나중에 남긴 미저장 입력을 지우지 않아요.

일반 폼 입력은 바뀐 필드의 경로만 새로 만들고, 변경 여부 비교에서 그대로인 자료 부분은 건너뛰어요. 큰 카드·프리셋 전체를 타이핑마다 복제하거나 JSON으로 만들지 않아요. 카드 입력을 저장본과 같게 되돌리면 목록 이동을 막지 않으며, 원문 JSON 표시·적용과 실제 저장 경계의 검증은 유지해요.

도우미에게 요청할 때 저장된 자료는 ID와 수정 번호만 보내고, 서버가 접수 시점의 해당 저장본을 확보해요. 미저장 자료는 전송 시점의 편집 입력을 분석용으로 보내요. 같은 자료를 도우미가 수정하려면 먼저 편집기에서 저장해야 하며, 다른 자료의 작업까지 막지는 않아요. 도우미 입력과 전송 대기 요청도 기존 IndexedDB 복구 저장소를 사용해요. 복구 보관에 실패하면 입력을 남기고 재시도 또는 보관 없이 보내기를 선택할 수 있어요. 보관 없이 보낸 요청은 새로고침 뒤 복구를 보장하지 않아요.

사용자와 보조 에이전트는 같은 `saveResource`를 사용해요. 현재 자료 수정 번호 하나를 비교해 다른 변경을 덮어쓰지 않도록 하고, 충돌 시 재조회·재적용해요. 에이전트의 권한 승인 절차는 아니에요. 일반 저장의 직전본 한 개만 되돌릴 수 있어요.

자료 본문·로어와 채팅 전용 로어 수정은 공통 원문 저장 한도인 2,000,000자를 사용해요. HTTP 요청은 한글과 JSON 이스케이프를 포함한 전송 크기를 받아들이며, 채팅 전용 로어의 변경 개수만으로 저장을 막지 않아요.

목록 갱신과 저장 후 폴더 배치는 저장 완료와 분리해요. 프리셋·프로바이더·모델이 저장된 뒤 이 후속 작업이 실패해도 저장본은 유지하고, 별도 경고와 함께 저장 후 이동을 마쳐요. 실제 저장 실패나 수정 번호 충돌은 입력을 남긴 채 이동을 막으며, 후속 작업 실패로 쓰기를 자동 반복하지 않아요. 자료 변경 이벤트는 해당 자료 또는 그 연결 모듈에 의존하는 채팅만 갱신해요. 실제 입력 소유자는 `web/resource-editor-session.ts`, API와 에이전트의 공통 저장 기능은 `server/resource-service.ts`에 있어요.

## 입력 상태의 소유자

각 자료의 `ResourceEditorSession` 하나가 폼 모델·원문 입력·저장 기준본·변경 여부·저장 진행을 소유해요. 화면은 세션의 모델을 직접 읽고 함수형 갱신으로 바꿔요. 복원된 모델을 부모 상태로 옮겼다가 다시 세션에 전달하는 동기화 과정은 없어요. 프롬프트의 역할·프리셋 전환은 세션을 보관하고 선택할 뿐, 모델이나 변경 여부를 따로 복제하지 않아요.

현재 프롬프트 옵션의 자동 저장은 새 입력에만 예약해요. 복구한 입력과 실패한 저장은 명시적으로 다시 저장하며, 저장 응답은 전송 이후의 입력을 지우지 않아요. 새 자료·사본을 저장하면 복구 입력의 키도 실제 자료 ID로 옮겨요. 복구 저장의 순서, 수정 번호 비교, 이전 조회 응답 무시, 도우미 요청 시점의 입력 확보는 데이터 보존을 위해 유지해요. 다른 창의 저장 알림은 깨끗한 편집기를 갱신하고, 미저장 입력이 있으면 보존한 채 충돌을 알려줘요.

원문·번역 편집을 열 때는 Reader와 명시된 테마 본문만 스크롤해요. 저장·취소 뒤에는 읽던 대목과 시작 버튼의 포커스를 복원하며, 앱의 헤더나 입력창을 스크롤하지 않아요.

좁은 화면에서는 원문·번역·요청 편집 중 아래에 떠 있는 장면 탐색 버튼을 잠시 숨겨 편집 버튼을 가리지 않도록 해요. 장면 목록과 책갈피 편집은 유지하며, 편집을 마치면 탐색 버튼이 기존 표시 설정에 따라 다시 나타나요.

## 선택 구절 퇴고

원문 편집기에서 구절을 선택한 뒤 **선택 구절 퇴고**를 열고 요청을 입력해요. **퇴고 제안 받기**는 설정된 도우미 모델을 한 번 호출하며, 원문과 제안을 나란히 확인할 수 있어요. **선택 구간에 반영**은 편집 중인 초안만 바꿔요. 기존 **원문 저장**을 눌러야 본문에 저장돼요.

모델에는 선택 구절과 같은 장면의 편집 중 원문을 문맥으로 보내요. 요청과 제안은 서버 원고나 도우미 대화에 저장하지 않고 숫자 사용량만 도우미 호출로 집계해요. 문맥에 맞지 않는 긴 입력이나 불완전한 결과는 자동으로 자르거나 재요청하지 않아요. 요청 중 초안·선택 구간·저장된 원문이 바뀌면 이전 제안을 반영할 수 없으며, 기존 초안은 유지해요. 요청 취소나 편집기 닫기는 대기 중인 호출을 중단하지만 이미 진행한 모델 이용 비용까지 취소되는 것은 아니에요.

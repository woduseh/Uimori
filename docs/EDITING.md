# 일반 자료 편집과 저장

Uimori의 봇·페르소나·모듈·프리셋 자료와 원고를 편집기에서 수정하고 저장할 수 있어요. 미저장 입력은 각 기기에 복구용으로 보관하며, 서버의 초안 ID나 제안, 미저장 입력의 기기 간 자동 동기화는 제공하지 않아요.

## 자료 편집과 저장 흐름

### 편집 상태 표시와 저장
- **상태 구분**: 편집기 헤더 상단에 자료의 현재 상태가 명확히 표시돼요.
  - **등록 전**: 아직 서버에 등록되지 않은 새 자료예요.
  - **미저장 변경**: 저장본과 비교해 새로 입력하거나 바꾼 내용이 있는 상태예요.
  - **저장됨**: 서버에 성공적으로 반영된 최신 상태예요.
- **저장과 취소**:
  - **변경사항 저장**: 화면의 변경 내용을 실제 서버 자료에 반영해요.
  - **편집 취소**: 현재 저장되어 있는 서버 저장본을 다시 불러와 화면을 되돌려요.
  - **직전본 되돌리기**: 일반 저장 후 직전 저장본 1회에 한해 되돌리기를 지원해요.
- **필수 항목**: 프롬프트 이름은 필수 항목이며 편집기 상단에 항상 표시돼요.
- **복구 상태 알림**: 브라우저 로컬 복구 저장소의 보관 성공 여부와 오류는 헤더와 별도로 명확히 안내해요.

### 원문 JSON과 정규식 입력
- **저장 시 검증**: 원문 JSON, 정규식, 트리거 입력은 **변경사항 저장**을 누를 때 함께 파싱하고 검증해요.
- **폼에 반영**: 편집기 안의 `폼에 반영` 버튼은 계속해서 GUI 폼으로 편집을 이어가기 위한 선택 동작일 뿐이며, 저장을 위한 필수 단계가 아니에요.
- **문법 오류 보호**: 문법 오류가 발견되면 작성한 입력을 지우지 않고 유지한 채 오류 위치와 사유를 표시해요.
- **저장 용량 한도**: 자료 본문·로어북 및 채팅 전용 로어의 수정은 공통 원문 저장 한도인 2,000,000자(UTF-16 코드 단위)를 지원해요. HTTP 요청은 한글과 JSON 이스케이프를 포함한 전송 크기를 온전히 받아들이며, 채팅 전용 로어의 변경 개수만으로 저장을 막지 않아요.

## 원문 저장본 비교

원문 편집기의 **저장본 비교** 기능을 통해 편집 중인 내용과 이전 판본을 나란히 비교할 수 있어요.

- **비교 대상**: 현재 저장본, 직전 저장본, 최초 원문의 세 가지 판본을 편집 중인 초안과 비교해요.
- **초안 불러오기**:
  - **선택본을 초안에 불러오기**: 선택한 판본의 내용을 편집 중인 초안으로 가져와요 (이 동작은 화면의 초안만 바꾸며 즉시 본문으로 확정되지 않아요).
  - **불러오기 전 초안으로 돌아가기**: 판본을 불러온 뒤에도 편집 중 마음이 바뀌면 원래 작성하던 초안으로 되돌아갈 수 있어요.
- **저장 확정**: 불러온 판본을 실제 본문과 후속 작업에 반영하려면 최종적으로 **원문 저장**을 눌러야 해요.
- **보존 범위**: 성능과 안정성을 위해 앱은 최초 원문 1개와 최근 수정본 2개만 보존하며, 무제한 편집 이력을 늘리지는 않아요.

## 선택 구절 퇴고

원문 편집기에서 다듬고 싶은 구절을 마우스나 키보드로 선택한 뒤 **선택 구절 퇴고**를 열어 도우미 모델에 맞춤 수정을 요청할 수 있어요.

- **진행 단계**:
  1. **구절 선택 및 요청**: 원문에서 구절을 드래그해 선택하고 **선택 구절 퇴고**를 열어 원하는 퇴고 방향을 입력해요.
  2. **제안 받기**: **제안 받기**를 누르면 설정된 도우미 모델을 1회 호출하며, 기존 원문과 모델의 제안을 좌우로 나란히 비교해 보여줘요.
  3. **초안 반영**: 제안이 마음에 들면 **초안에 반영**을 눌러 편집 중인 초안에 적용해요 (이 단계는 화면의 편집 초안만 바꾸며 서버에 바로 저장되지 않아요).
  4. **원문 저장**: 최종적으로 **원문 저장**을 눌러야 본문과 다음 생성에 확정 반영돼요.
- **재요청 및 취소**:
  - 제안을 확인한 후 마음에 들지 않으면 **다시 제안 받기** 아이콘을 눌러 새로운 제안을 요청할 수 있어요.
  - 위쪽의 닫기 아이콘을 누르면 퇴고 패널을 닫고 기존 편집으로 돌아가요.
- **컨텍스트 전달과 비용**:
  - 모델에는 선택한 구절과 해당 장면의 편집 중인 원문 전체가 문맥으로 함께 전달돼요.
  - 퇴고 요청과 제안 내용은 서버 원고나 도우미 대화 기록에 영구 보존되지 않으며, 모델 호출 횟수와 토큰 사용량만 도우미 사용량으로 집계돼요.
  - 컨텍스트 크기를 벗어나는 긴 입력이나 불완전한 결과가 나오더라도 모델 출력을 임의로 자르거나 자동으로 재요청하지 않아요.
- **상태 변경 보호**:
  - 퇴고를 요청하는 도중에 편집 초안이나 선택 구간, 이미 저장된 원문이 바뀌면 이전 제안을 초안에 반영할 수 없게 차단하여 텍스트 꼬임을 방지해요 (작성 중이던 기존 초안은 유지돼요).
  - 요청 취소나 편집기 닫기는 대기 중인 네트워크 호출을 즉시 중단하지만, 제공사 서버에서 이미 진행된 모델 이용 비용까지 취소되는 것은 아니에요.

## 과거 사용자 입력과 장면의 문맥 제어

이야기를 진행하면서 과거에 보냈던 사용자 요청을 다듬거나, 특정 장면을 이후 생성 문맥에서 제외할 수 있어요.

### 문맥용 요청 수정 및 포함/제외
- **입력 수정**: 요청 아래 **요청과 문맥 메뉴 → 문맥용 요청 수정**에서 **입력 저장**을 누르면, 이전 사용자 입력을 고쳐서 이후 이어지는 생성 문맥에 반영해요.
  - 수정된 입력을 볼 때도 당시 실제로 보냈던 원래 요청을 펼쳐서 언제든 확인할 수 있어요.
  - Risu에서 한 장면을 여러 개의 연속된 사용자 메시지로 구성했던 경우에도, 수정된 입력을 하나의 통합 요청으로 반영하면서 첨부 이미지를 보존해요.
- **문맥 제외와 복원**:
  - 같은 메뉴에서 사용자 입력만 제외하거나, 해당 장면의 입력과 본문을 모두 **문맥에서 제외/포함**할 수 있어요.
  - 제외된 장면이라도 화면에서 완전히 사라지지 않고 비활성화 상태로 유지되며, 언제든지 다시 문맥에 포함하도록 복원할 수 있어요 (영구 삭제가 아니에요).

### 다시 쓰기 (새 채팅 / 기존 응답 교체)
요청 아래 또는 **장면 작업 메뉴 → 다시 쓰기**에서는 생성에 실제로 보낼 문구를 확인하고 수정해요.

- **초안 불러오기**: 처음 창을 열면 현재 문맥용 요청을 가져오며, 이전에 작성 중이던 실행 초안이 있으면 복원해요. 화면 표시용 변환 문구는 사용하지 않아요.
- **다시 쓰기 옵션**:
  - **새 채팅에서 다시 요청**: 해당 시점까지의 맥락을 바탕으로 독립된 새 채팅 사본을 만들어 응답을 생성해요.
  - **기존 응답 교체**: 마지막으로 완료된 장면에 한해 선택할 수 있어요. 생성이 완전히 성공한 뒤에만 기존 응답을 교체해요.
- **교체 안전장치**:
  - 생성 도중 실패하거나 취소하면 기존 응답과 원래 요청 기록을 그대로 유지해요.
  - 다시 쓰기 실행 문구를 수정하는 것만으로는 문맥용 요청이 저장되지 않아요.
  - 요청 수락 여부가 불확실하면 문구를 잠그고 동일한 요청 키로 **이전 요청 확인**을 진행해요.
  - 문맥 수정 초안, 다시 쓰기 초안, 다음 장면 입력 초안은 서로 간섭하지 않고 독립적으로 유지돼요.
- **문맥 제어의 기본 성격**:
  - 이 기능은 기존 실행 결과를 과거로 거슬러 올라가 소급 변경하는 것이 아니라, **앞으로 모델에게 전달할 문맥을 사용자가 직접 제어**하는 기능이에요.
  - 다른 장면의 번호와 본문, 이전 모델 요청 기록, 비용, 첨부 이미지, 번역, Lua/CBS 변수 및 완료된 부수효과는 그대로 보존돼요.
  - 별도로 작성된 개요나 작가 노트에서 같은 사건을 다룬 내용도 자동으로 지우지 않아요.
  - 새로운 장면이 생성되는 도중에는 과거 입력이나 문맥 활성 상태의 변경을 막아 동시 실행 충돌을 방지해요.

## 도우미를 통한 본문과 자료 편집

### 도우미 본문 편집
- **본문 수정 요청**: 채팅 도우미에게 원문이나 완료된 번역의 수정을 요청할 수 있어요.
- **안전한 저장 검증**: 도우미는 최신 저장본을 읽은 뒤, 읽었을 때의 수정 번호와 원문 해시가 일치할 때만 수정을 저장해요. 화면 표시용 HTML이 아닌 실제 저장 본문을 수정해요.
- **번역 무효화**: 원문이 변경되면 이전 원문을 바탕으로 작성되었던 번역은 더 이상 유효한 현재 번역으로 취급되지 않아요.
- **이력 제한**: 도우미는 보존되어 있는 원문 저장본을 새 판본으로 복원할 수는 있지만, 번역 판본 복원이나 무제한 이력 관리는 지원하지 않아요.
- **초안 충돌 방지**: 도우미가 본문을 저장하더라도 사용자가 열어 둔 편집기의 미저장 초안을 강제로 덮어쓰지 않아요. 저장 기준본이 달라지면 저장 충돌 대화상자에서 초안과 서버 저장본을 확인하고 병합할 수 있어요. 도우미가 사용자의 미저장 초안을 몰래 읽거나 가로채지 않아요.

### 도우미 서재 자료 편집과 일괄 처리
- **서재 복제**: 서재 목록 복제와 도우미의 `resource.clone`은 동일한 서버 복제 기능을 사용해요.
- **일괄 수정**: 도우미를 통해 여러 자료를 한 번에 수정할 때는 모든 자료의 수정이 성공해야만 원자적으로 저장돼요.
- **묶음 되돌리기**: 도우미의 **마지막 자료 수정 되돌리기**는 함께 변경되었던 자료들을 한 묶음으로 되돌려요. 만약 어느 한 자료라도 이후에 다시 수정되었거나 현재 편집기에 미저장 입력이 남아 있다면 묶음 되돌리기가 차단돼요.
- **프리셋 진단**: 프리셋 진단 기능은 토글 정의와 선택값, 직전 저장 이후 선택지 이름과 번호의 변화를 분석해 줘요. CBS는 직접 실행하지 않으며, 진단 결과는 저장을 차단하지 않아요.

## 에이전트 및 구현 참고

### 입력 상태와 세션 소유권 (`ResourceEditorSession`)
- **단일 소유자**: 각 자료 편집기는 `web/resource-editor-session.ts`의 `ResourceEditorSession` 인스턴스 하나가 폼 모델, 원문 텍스트 입력, 저장 기준본, 변경 여부, 저장 진행 상태를 단독 소유해요. 화면 UI는 세션 모델을 직접 참조하며 함수형 갱신으로 상태를 바꿔요. 복원된 모델을 부모 상태로 옮겼다가 다시 세션에 전달하는 동기화 과정은 없어요.
- **역할 및 프리셋 전환**: 프롬프트의 역할·프리셋 전환은 세션을 보관하고 선택할 뿐, 모델이나 변경 여부를 따로 복제하지 않아요.
- **조회 수명주기 보호**: 프롬프트를 불러오는 동안 새 프롬프트 작성을 시작하거나 목록으로 돌아가면 이전 조회를 취소해요. 늦게 도착한 응답이 새 초안이나 현재 화면을 덮지 않으며, 목록에서 열기와 외부에서 지정한 프리셋 열기는 같은 조회 수명주기를 사용해요.
- **자동 저장 예약**: 현재 프롬프트 옵션의 자동 저장은 새 입력에만 예약해요. 복구한 입력과 실패한 저장은 명시적으로 다시 저장하며, 저장 응답은 전송 이후의 입력을 지우지 않아요. 새 자료·사본을 저장하면 복구 입력의 키도 실제 자료 ID로 옮겨요. 복구 저장의 순서, 수정 번호 비교, 이전 조회 응답 무시, 도우미 요청 시점의 입력 확보는 데이터 보존을 위해 유지해요. 다른 창의 저장 알림은 깨끗한 편집기를 갱신하고, 미저장 입력이 있으면 보존한 채 충돌을 알려줘요.
- **스크롤 및 포커스 복원**:
  - 원문·번역 편집을 열 때는 Reader와 명시된 테마 본문만 스크롤해요. 저장·취소 뒤에는 읽던 대목과 시작 버튼의 포커스를 복원하며, 앱의 헤더나 입력창을 스크롤하지 않아요.
  - 좁은 화면의 맨 아래 이동 버튼은 입력창 도구 영역에 있어요. 원문·번역·요청을 편집하는 동안에는 숨기고, 편집을 마치면 탐색기 표시 설정과 현재 읽기 위치에 따라 다시 나타나요. 상단 제목의 장면 목록과 책갈피 편집은 계속 사용할 수 있어요.

### 로컬 복구 저장소 (IndexedDB)
- **비동기 격리 저장**: 타이핑마다 전체 자료를 `localStorage`에 동기 저장하지 않아요. 이 기기의 최신 미저장 입력만 IndexedDB에 비동기로 덮어써요. 성공적으로 보관된 경우에만 복구 보관 상태를 표시하며 실패를 성공처럼 표시하지 않아요.
- **트랜잭션 충돌 방지**: 저장·취소·원래 값으로 되돌리기는 이 편집 세션이 읽었거나 성공적으로 쓴 복구 입력만 정리해요. 각 저장의 식별자를 IndexedDB의 한 트랜잭션에서 비교해, 다른 탭이 나중에 남긴 미저장 입력을 지우지 않아요.
- **부분 경로 갱신**: 일반 폼 입력은 바뀐 필드의 경로만 새로 만들고, 변경 여부 비교에서 그대로인 자료 부분은 건너뛰어요. 큰 카드·프리셋 전체를 타이핑마다 복제하거나 JSON으로 만들지 않아요. 카드 입력을 저장본과 같게 되돌리면 목록 이동을 막지 않으며, 원문 JSON 표시·적용과 실제 저장 경계의 검증은 유지해요.
- **도우미 및 생성 대기 큐**: 도우미에게 요청할 때 저장된 자료는 ID와 수정 번호만 보내고, 서버가 접수 시점의 해당 저장본을 확보해요. 미저장 자료는 전송 시점의 편집 입력을 분석용으로 보내요. 같은 자료를 도우미가 수정하려면 먼저 편집기에서 저장해야 하며, 다른 자료의 작업까지 막지는 않아요. 도우미 입력과 전송 대기 요청도 기존 IndexedDB 복구 저장소를 사용해요. 복구 보관에 실패하면 입력을 남기고 재시도 또는 보관 없이 보내기를 선택할 수 있어요. 보관 없이 보낸 요청은 새로고침 뒤 복구되지 않을 수 있어요.

### 동시성 제어와 멱등성 보장
- **CAS 수정 번호 (`expectedRevision`)**: 사용자와 보조 에이전트는 같은 `saveResource`를 사용해요. 현재 자료 수정 번호 하나를 비교해 다른 변경을 덮어쓰지 않도록 하고, 충돌 시 재조회·재적용해요. 저장이 실패하더라도 기존 수정 번호 충돌 경고는 유지하며, 실제 사본 저장 성공이나 명시적 재조회 뒤에만 해제해요. 에이전트의 권한 승인 절차는 아니에요.
- **멱등성 키와 영수증**:
  - 브라우저의 새 자료 저장과 목록 복제는 요청별 멱등성 키를 기록하며, 결과가 불분명한 요청을 다시 실행할 때 원래 입력과 키를 재사용해 중복 사본을 만들지 않아요.
  - 서버는 작은 생성 ID 영수증만 영구 보존하며 별도의 DB 형식 변경은 없어요. 새 자료 편집기의 미확정 요청은 일반 미저장 입력과 구분된 탭별 IndexedDB 기록에 보관해요. 새 입력에 오류가 생겨도 원래 생성 요청은 이미 고정된 입력만으로 재확인하며, 확인 이후에 새 입력을 그대로 남겨요.
  - 서버가 명확히 거절한 요청은 새 요청으로 수정할 수 있어요. 구형 API 클라이언트나 수동 생성 요청에서 키를 생략하면 기존 비멱등 동작을 유지해요. 원본 수정 번호를 확인하고 저장된 전체 내용을 새 ID로 복사해요. 편집 중인 미저장 입력은 포함하지 않으며 원본과 현재 적용 상태는 유지해요. 도우미는 반환된 사본 ID에 표시 이름·본문·블록 추가·삭제·이동을 한 번에 적용할 수 있어요. 프롬프트의 서재 표시 이름과 native 내부 이름은 독립적이에요. 구조 편집도 수정 번호 확인과 직전본 되돌리기를 사용해요.
  - 생성 또는 복제 결과가 불분명해진 뒤에는 재확인 요청이 인증 만료 같은 오류를 받아도 원래 요청 키를 유지해요. 편집기에서 새 입력이 미완성이어도 **이전 요청 확인**으로 고정된 생성 요청을 확인할 수 있으며 새 입력은 그대로 남아요. 확인 전 다른 창에서 생성된 자료를 수정했다면 이후 입력을 충돌 상태로 보존하고, 저장본 확인이나 명시적인 다시 불러오기를 기다려요. 생성 영수증의 대상이 이미 삭제됐다고 서버가 확인하면 입력을 유지하고 새 저장을 선택할 수 있어요.
- **폴더 배치 및 후속 작업 분리**:
  - 생성한 자료의 폴더 배치는 생성 직후의 서재 정리 수정 번호를 확인해요. 확인 전 다른 창에서 정리가 바뀌었거나 구형 영수증에 수정 번호가 없으면 자동 이동을 건너뛰고 알려요. 이렇게 하면 다른 창에서 지정한 폴더나 미분류를 덮어쓰지 않아요.
  - 목록 갱신과 저장 후 폴더 배치는 저장 완료와 분리해요. 프리셋·프로바이더와 모델이 저장된 뒤 이 후속 작업이 실패해도 저장본은 유지하고, 별도 경고와 함께 저장 후 이동을 마쳐요. 실제 저장 실패나 수정 번호 충돌은 입력을 남긴 채 이동을 막으며, 후속 작업 실패로 쓰기를 자동 반복하지 않아요. 자료 변경 이벤트는 해당 자료 또는 그 연결 모듈에 의존하는 채팅만 갱신해요. 실제 입력 소유자는 `web/resource-editor-session.ts`, API와 에이전트의 공통 저장 기능은 `server/resource-service.ts`에 있어요.

### 문맥 제어의 내부 데이터 구조 (`scene_context`)
- **독립 테이블 저장**: 변경 사항은 원본 Run/Source와 별도의 `scene_context`에 수정 번호를 두고 저장해요. 이후 모델의 일반 문맥·압축 요약·검색 및 도우미의 현재 채팅 조회는 그 상태를 반영해요.
- **컨텍스트 유효성 판정**: 입력 수정만으로 원문 해시가 달라지지 않으므로 문맥 압축 유효성에는 장면 문맥 수정 번호도 반영해요.
- **사본 및 백업 연동**: 채팅 사본/백업과 transcript v2의 선택적 `sceneContext` 필드에서도 이 상태를 보존해요. 기존 transcript v2에는 해당 필드가 없어도 모두 활성 상태로 읽어요. 원본 실행 기록이나 명시적으로 요청한 보존 장면의 편집/조회는 별개의 기능이에요.

### 도우미 부분 수정 및 문자열 치환 알고리즘
- **블록 참조 추적**: 도우미의 부분 수정은 읽었던 블록을 참조해 앞 항목 삭제·이동 뒤에도 같은 대상을 수정할 수 있어요.
- **CRLF/LF 허용 검색**: 문구 치환은 정확한 일치를 먼저 찾고, 없을 때만 CRLF/LF 줄바꿈 차이를 허용해 유일한 문구를 찾아요. 실패하면 변경 위치와 원인을 반환하며 아무것도 저장하지 않아요.
- **토글 정의 정합성**: 토글 정의 변경 시 더 이상 유효하지 않은 기존 선택값을 정리하고 제거·초기화된 키를 알려줘요. 새로 지정한 잘못된 값은 자동으로 고치지 않고 저장을 거절해요.
- **직전본 비교**: 직전 저장본은 저장하지 않고 읽어 비교할 수도 있어요. 여러 단계의 자료 이력이나 복제한 프리셋 사이의 지속적인 동기화는 제공하지 않아요.

# 일반 자료 편집과 저장

Uimori의 봇·페르소나·모듈·프리셋 자료와 원고를 편집기에서 수정하고 저장할 수 있어요. 미저장 입력은 각 기기에 복구용으로 보관하며, 서버의 초안 ID나 제안, 미저장 입력의 기기 간 자동 동기화는 제공하지 않아요.

## 자료 편집과 저장 흐름

### 편집 상태 표시와 저장
- **상태 구분**: 편집기 헤더 상단에 자료의 현재 상태가 명확히 표시돼요.
  - **등록 전**: 아직 서버에 등록되지 않은 새 자료예요.
  - **미저장 변경**: 저장본과 비교해 새로 입력하거나 바꾼 내용이 있는 상태예요.
  - **저장됨**: 서버에 성공적으로 반영된 최신 상태예요.
- **저장과 취소**:
  - **변경사항 저장**: 화면의 변경 내용을 실제 서버 자료에 반영해요.
  - **편집 취소**: 현재 저장되어 있는 서버 저장본을 다시 불러와 화면을 되돌려요.
  - **직전 저장 되돌리기**: 일반 저장 후 직전 저장본 1회에 한해 되돌리기를 지원해요.
- **필수 항목**: 프롬프트 이름은 필수 항목이며 편집기 상단에 항상 표시돼요.
- **복구 상태 알림**: 브라우저 로컬 복구 저장소에 입력을 보관하지 못하면 헤더에 경고를 표시해요. 정상 보관은 따로 표시하지 않아요.

### 원문 JSON과 정규식 입력
- **저장 시 검증**: 원문 JSON, 정규식, 트리거 입력은 **변경사항 저장**을 누를 때 함께 파싱하고 검증해요.
- **편집기에 적용**: 편집기 안의 **편집기에 적용** 버튼은 계속해서 GUI 폼으로 편집을 이어가기 위한 선택 동작일 뿐이며, 저장을 위한 필수 단계가 아니에요.
- **문법 오류 보호**: 문법 오류가 발견되면 작성한 입력을 지우지 않고 유지한 채 오류 위치와 사유를 표시해요.
- **저장 용량 한도**: 자료 본문·로어북 및 채팅 전용 로어의 수정은 공통 원문 저장 한도인 2,000,000자(UTF-16 코드 단위)를 지원해요. HTTP 요청은 한글과 JSON 이스케이프를 포함한 전송 크기를 온전히 받아들이며, 채팅 전용 로어의 변경 개수만으로 저장을 막지 않아요.

## 원문 저장본 비교

원문 편집기의 **저장본 비교** 기능을 통해 편집 중인 내용과 이전 판본을 나란히 비교할 수 있어요.

- **비교 대상**: 현재 저장본, 직전 저장본, 최초 원문의 세 가지 판본을 편집 중인 초안과 비교해요.
- **초안 불러오기**:
  - **선택한 저장본 불러오기**: 선택한 판본의 내용을 편집 중인 초안으로 가져와요 (이 동작은 화면의 초안만 바꾸며 즉시 본문으로 확정되지 않아요).
  - **불러오기 전 초안으로 돌아가기**: 판본을 불러온 뒤에도 편집 중 마음이 바뀌면 원래 작성하던 초안으로 되돌아갈 수 있어요.
- **저장 확정**: 불러온 판본을 실제 본문과 후속 작업에 반영하려면 최종적으로 **원문 저장**을 눌러야 해요.
- **보존 범위**: 성능과 안정성을 위해 앱은 최초 원문 1개와 최근 수정본 2개만 보존하며, 무제한 편집 이력을 늘리지는 않아요.

## 선택 구절 퇴고

원문 편집기에서 다듬고 싶은 구절을 마우스나 키보드로 선택한 뒤 **선택 구절 퇴고**를 열어 도우미 모델에 맞춤 수정을 요청할 수 있어요.

- **진행 단계**:
  1. **구절 선택 및 요청**: 원문에서 구절을 드래그해 선택하고 **선택 구절 퇴고**를 열어 원하는 퇴고 방향을 입력해요.
  2. **제안 받기**: **제안 받기**를 누르면 설정된 도우미 모델을 1회 호출하며, 기존 원문과 모델의 제안을 좌우로 나란히 비교해 보여줘요.
  3. **초안 반영**: 제안이 마음에 들면 **초안에 반영**을 눌러 편집 중인 초안에 적용해요 (이 단계는 화면의 편집 초안만 바꾸며 서버에 바로 저장되지 않아요).
  4. **원문 저장**: 최종적으로 **원문 저장**을 눌러야 본문과 다음 생성에 확정 반영돼요.
- **재요청 및 취소**:
  - 제안을 확인한 후 마음에 들지 않으면 **다시 제안 받기** 아이콘을 눌러 새로운 제안을 요청할 수 있어요.
  - 위쪽의 닫기 아이콘이나 패널 안의 `Esc`는 퇴고 패널만 닫고 기존 편집으로 돌아가요. 요청 중이면 요청도 취소하고, 장면 초안은 그대로 둬요.
- **컨텍스트 전달과 비용**:
  - 모델에는 선택한 구절과 해당 장면의 편집 중인 원문 전체가 문맥으로 함께 전달돼요.
  - **앞뒤 문단만 문맥으로 보내기**를 켜면 선택한 구절 앞뒤로 각각 3,000자 안쪽의 문단만 보내요. 긴 장면에서 요청이 작아지는 대신 모델은 장면의 나머지를 보지 못해요. 이 선택은 사용 중인 브라우저에 기억되고 읽기 화면의 다듬기에도 똑같이 적용돼요.
  - 퇴고 요청과 제안 내용은 서버 원고나 도우미 대화 기록에 영구 보존되지 않으며, 모델 호출 횟수와 토큰 사용량만 도우미 사용량으로 집계돼요.
  - 컨텍스트 크기를 벗어나는 긴 입력이나 불완전한 결과가 나오더라도 모델 출력을 임의로 자르거나 자동으로 재요청하지 않아요.
- **상태 변경 보호**:
  - 퇴고를 요청하는 도중에 편집 초안이나 선택 구간, 이미 저장된 원문이 바뀌면 이전 제안을 초안에 반영할 수 없게 차단하여 텍스트 꼬임을 방지해요 (작성 중이던 기존 초안은 유지돼요).
  - 요청 취소나 편집기 닫기는 대기 중인 네트워크 호출을 즉시 중단하지만, 제공사 서버에서 이미 진행된 모델 이용 비용까지 취소되는 것은 아니에요.

## 읽는 중에 다듬기

본문을 읽다가 마우스나 키보드로 글을 선택하면 선택한 글 위나 아래에 작은 막대가 떠요. 막대에는 **다듬기**, **도우미에게 묻기**, **책갈피**, **복사**가 있어요. 도우미에게 묻기는 선택한 글을 붙여 도우미 사이드 패널을 열고, 책갈피는 선택한 글을 인용으로 넣어 장면 책갈피를 만들어요.

- **다듬기가 나오는 조건**: 선택한 글이 지금 보이는 표시(원문 또는 번역)의 저장본과 글자 그대로, 그리고 한 곳에서만 일치할 때만 나와요. 장면을 어떤 방식으로 그렸는지는 따지지 않으므로 봇 채팅에서도 서식 없는 문장은 다듬을 수 있어요. 줄바꿈 문자 차이(CRLF와 LF)만 같게 보고, 따옴표나 공백 같은 다른 차이는 맞춰 주지 않아요. 그래서 표시용 정규식이 바꾼 글, 강조나 루비처럼 서식이 걸친 선택, 이야기 UI 블록과 생성된 HTML, 장면 안에 같은 글이 두 번 이상 있는 선택에서는 다듬기가 빠지고 나머지 버튼만 남아요. 이럴 때는 도우미에게 묻거나 장면 메뉴에서 편집기를 열어 고쳐요.
- **진행**: 다듬기를 누르면 선택한 글 옆에 작은 창이 열려요. 다듬을 방향을 쓰고 **제안 받기**를 누르면 도우미 모델을 한 번 호출하고, 제안을 선택한 글과 단어 단위로 비교해 보여 줘요(지운 말은 취소선, 더한 말은 밑줄). **적용**은 그 자리에서 바로 저장해요. 다시 제안 받기 아이콘은 새로 요청하고, **닫기**는 아무것도 저장하지 않아요.
- **저장 전 확인**: 원문은 원문 해시와 수정 번호로, 번역은 최신 번역의 수정 번호, 원문 해시, 보고 있는 번역 본문의 해시로 제안을 요청할 때와 저장할 때 확인해요. 그사이 무엇이 바뀌었으면 저장하지 않고 원문과 번역 중 무엇이 바뀌었는지 알려 주며, 제안은 창에 남아요. 바뀐 뒤에는 그 제안을 적용할 수 없으니 닫고 다시 선택해요.
- **번역에 적용할 때**: 창에서 한 번 알려요. 번역을 저장하면 진행 중인 재번역이 취소되고 번역에 맞춘 삽화 배치가 무효가 돼요.
- **적용 뒤**: 저장한 글을 바로 보여 주고, 읽던 위치를 지키며 포커스를 장면 본문으로 돌려요.
- **선택 막대와 복사**: 여러 문단에 걸친 긴 선택도 화면 안에 막대를 표시해요. 복사에 실패하면 선택과 막대를 유지하고 오류를 보여 줘 다시 시도할 수 있어요. Risu 표시가 갱신되어 선택한 본문이 사라지면 예전 선택 막대는 닫혀요.
- **키보드와 닫기**: 막대가 떠 있을 때 `Tab`을 누르면 막대의 첫 버튼으로 가고, 좌우 화살표로 버튼 사이를 옮겨요. `Esc`는 열린 다듬기 창을 먼저 닫고(요청 중이면 요청도 취소해요) 선택과 막대로 돌아가며, 한 번 더 누르면 막대를 닫아요. 적용한 내용을 저장하는 동안에는 `Esc`가 창을 닫지 않아서, 저장 결과나 충돌 안내가 창에 남아요. 다듬기 창이 열려 있는 동안에는 다른 대화상자처럼 전역 단축키가 동작하지 않아요. 선택이 풀리거나 선택한 글이 화면 밖으로 나가면 막대도 사라져요.
- **터치로 고른 글**: 휴대폰에서 길게 눌러 고른 글에도 막대가 떠요. 브라우저의 선택 메뉴와 선택 손잡이가 선택한 글 바로 위아래에 뜨기 때문에, 막대는 선택 옆이 아니라 읽기 영역의 아래쪽 가장자리에 붙고, 선택이 그 자리를 가리면 위쪽 가장자리로 옮겨요(`web/reader-selection.ts`의 `placeDocked`). 손잡이를 끄는 동안에는 기다렸다가 선택이 멈추면 보여 줘요. 버튼을 누르는 순간 브라우저가 선택을 풀어도 누르기 직전의 선택으로 동작해요. `tests/reader-selection-browser.spec.ts`의 `RSEL22`가 합성 터치 입력으로 확인해요.
- **막대가 없는 곳**: 편집기와 입력란, 이야기 UI 컨트롤, 도우미 안에서 고른 글에는 막대가 뜨지 않아요.
- 모델 호출은 요청마다 한 번이고, Codex 콘텐츠 경고 확인, 취소 시 요청 중단, 사용량만 남기고 요청과 제안은 저장하지 않는 점, 자동으로 다시 요청하지 않는 점은 편집기의 선택 구절 퇴고와 같아요.

## 과거 사용자 입력과 장면의 문맥 제어

이야기를 진행하면서 과거에 보냈던 사용자 요청을 다듬거나, 특정 장면을 이후 생성 컨텍스트에서 제외할 수 있어요.

### 문맥용 요청 수정 및 포함/제외
- **입력 수정**: 요청 아래 **요청 및 컨텍스트 메뉴 → 요청 수정**에서 **입력 저장**을 누르면, 이전 사용자 입력을 고쳐서 이후 이어지는 생성 컨텍스트에 반영해요.
  - 수정된 입력을 볼 때도 당시 실제로 보냈던 원래 요청을 펼쳐서 언제든 확인할 수 있어요.
  - Risu에서 한 장면을 여러 개의 연속된 사용자 메시지로 구성했던 경우에도, 수정된 입력을 하나의 통합 요청으로 반영하면서 첨부 이미지를 보존해요.
  - 요청 편집기(도우미 대화와 취소된 요청의 편집 포함)에서 `Esc`를 누르면 원문 편집기와 같이 바뀐 입력이 있을 때 버릴지 먼저 물어요. **요청 편집 취소** 버튼은 묻지 않고 닫아요.
- **문맥 제외와 복원**:
  - 같은 메뉴에서 사용자 입력만 제외하거나, 해당 장면의 입력과 본문을 모두 **장면을 컨텍스트에서 제외/포함**할 수 있어요.
  - 제외된 장면이라도 화면에서 완전히 사라지지 않고 비활성화 상태로 유지되며, 언제든지 다시 문맥에 포함하도록 복원할 수 있어요 (영구 삭제가 아니에요).

### 다시 쓰기 (새 채팅 / 기존 응답 교체)
요청 아래 또는 **장면 작업 메뉴 → 다시 쓰기**에서는 생성에 실제로 보낼 문구를 확인하고 수정해요.

- **초안 불러오기**: 처음 창을 열면 현재 문맥용 요청을 가져오며, 이전에 작성 중이던 실행 초안이 있으면 복원해요. 화면 표시용 변환 문구는 사용하지 않아요.
- **다시 쓰기 옵션**:
  - **새 채팅에서 다시 요청**: 해당 시점까지의 맥락을 바탕으로 독립된 새 채팅 사본을 만들어 응답을 생성해요.
  - **기존 응답 교체**: 마지막으로 완료된 장면에 한해 선택할 수 있어요. 생성이 완전히 성공한 뒤에만 기존 응답을 교체해요.
- **교체 안전장치**:
  - 생성 도중 실패하거나 취소하면 기존 응답과 원래 요청 기록을 그대로 유지해요.
  - 다시 쓰기 실행 문구를 수정하는 것만으로는 문맥용 요청이 저장되지 않아요.
  - 요청 수락 여부가 불확실하면 문구를 잠그고 동일한 요청 키로 **이전 요청 확인**을 진행해요.
  - 문맥 수정 초안, 다시 쓰기 초안, 다음 장면 입력 초안은 서로 간섭하지 않고 독립적으로 유지돼요.
- **문맥 제어의 기본 성격**:
  - 이 기능은 기존 실행 결과를 과거로 거슬러 올라가 소급 변경하는 것이 아니라, **앞으로 모델에게 전달할 문맥을 사용자가 직접 제어**하는 기능이에요.
  - 다른 장면의 번호와 본문, 이전 모델 요청 기록, 비용, 첨부 이미지, 번역, Lua/CBS 변수 및 완료된 부수효과는 그대로 보존돼요.
  - 별도로 작성된 개요나 작가 노트에서 같은 사건을 다룬 내용도 자동으로 지우지 않아요.
  - 새로운 장면이 생성되는 도중에는 과거 입력이나 문맥 활성 상태의 변경을 막아 동시 실행 충돌을 방지해요.

## 도우미를 통한 본문과 자료 편집

### 도우미 본문 편집
- **본문 수정 요청**: 채팅 도우미에게 원문이나 완료된 번역의 수정을 요청할 수 있어요.
- **안전한 저장 검증**: 도우미는 최신 저장본을 읽은 뒤, 읽었을 때의 수정 번호와 원문 해시가 일치할 때만 수정을 저장해요. 화면 표시용 HTML이 아닌 실제 저장 본문을 수정해요.
- **번역 무효화**: 원문이 변경되면 이전 원문을 바탕으로 작성되었던 번역은 더 이상 유효한 현재 번역으로 취급되지 않아요.
- **이력 제한**: 도우미는 보존되어 있는 원문 저장본을 새 판본으로 복원할 수는 있지만, 번역 판본 복원이나 무제한 이력 관리는 지원하지 않아요.
- **초안 충돌 방지**: 도우미가 본문을 저장하더라도 사용자가 열어 둔 편집기의 미저장 초안을 강제로 덮어쓰지 않아요. 저장 기준본이 달라지면 저장 충돌 대화상자에서 초안과 서버 저장본을 확인하고 병합할 수 있어요. 도우미가 사용자의 미저장 초안을 몰래 읽거나 가로채지 않아요.

### 도우미가 바꾼 내용 확인
- **변경 카드**: 도우미 답변 아래에는 그 작업이 바꾼 대상마다 한 줄씩 카드가 붙어요. 카드에는 대상 종류 아이콘, 제목, 바뀐 위치, 추가·삭제 수가 보이고, 누르면 그 자리에서 바뀐 부분을 펼쳐요. 원문, 번역, 로어 본문, 개요 같은 글은 문단 안에서 바뀐 단어만 표시하고(지운 말은 취소선, 더한 말은 밑줄), JSON, 정규식, 스크립트는 줄 단위로 보여 줘요. 긴 비교는 카드 안에서 스크롤해요.
- **비교가 없는 카드**: 바뀐 내용이 너무 크거나 비교에 시간이 오래 걸리면 비교를 생략했다고 알려요. 대상을 삭제했거나 보관 기간이 지나 바뀐 글을 지운 경우에도 그 사실만 남아요. 작업이 삭제한 대상은 목록에 남지만 열 수 없어요.
- **카드 한 장은 작업 전체의 순변경이에요**: 한 작업이 같은 대상을 여러 번 고쳐도 처음 상태와 마지막 상태의 차이 하나만 보여요. 그 뒤에 사용자가 고친 내용은 카드에 반영되지 않아요. 변경 기록이 없는 설정 변경과 삽화·장면 요청 예약은 예전처럼 결과 줄로 보여요.
- **카드에서 열기**: 카드의 열기 버튼은 바뀐 자리로 이동하고 잠깐 테두리로 표시해요. 장면은 바뀐 문단으로, 봇·페르소나·모듈은 편집기의 해당 영역(로어북 항목은 그 항목)으로, 프롬프트 프리셋은 해당 블록으로 가요. 봇 화면처럼 Risu 표시로 그리는 장면은 문단 단위 위치가 없어서 비슷한 높이로 이동하고 본문 전체를 표시해요. 개요는 플롯 작업 공간의 해당 항목으로, 작가 노트와 채팅 전용 로어는 채팅 설정의 해당 영역으로 열어요. 데스크톱에서는 도우미가 닫히지 않아요. 사이드 패널에서 열면 그대로 두고, 크게 보기에서 열면 대상 옆의 사이드 패널로 돌아가요. 이미 열려 있는 편집기는 다시 불러오지 않으므로 저장하지 않은 입력이 그대로 남고, 다른 자료에 저장하지 않은 입력이 있으면 이동 전에 확인해요.
- **필요할 때만 읽기**: 대화를 열면 마지막 작업의 결과만 바로 읽고, 이전 답변의 결과는 그 답변이 화면에 가까워질 때 읽어요.

### 도우미 변경 되돌리기
- **되돌릴 수 있는 대상**: 서재 자료, 장면 원문과 번역, 플롯, 작가 노트예요. 되돌릴 수 있는 카드에는 되돌리기 버튼이 있고, 되돌릴 대상이 둘 이상이면 카드 목록 아래에 **이 작업의 변경 되돌리기**가 있어요. 한 장면의 원문과 번역은 함께 되돌려요. 설정, 채팅 전용 로어, 장면 이름은 되돌리기 대상이 아니라는 안내가 목록 아래에 한 번 나와요.
- **되돌리기 전 확인**: 누르면 지금 상태를 다시 확인해서 되돌릴 대상과 그대로 둘 대상을 사유와 함께 보여 주고, 확인 버튼 하나로 진행해요. 작업 뒤에 다시 고친 대상, 작업 도중 다른 곳에서 저장된 대상, 삭제나 보관 기간 때문에 바뀐 글이 지워진 대상, 작업이 만들거나 지운 자료는 그대로 둬요. 번역을 되돌리는 장면은 번역 삽화 배치가 돌아오지 않는다고 미리 알려요.
- **열린 편집기의 미저장 입력**: 이 브라우저에 열린 편집기(자료 편집기, 원문과 번역 편집기, 플롯 항목 편집, 작가 노트 편집)에 저장하지 않은 입력이 있으면 그 대상은 되돌리지 않고 이유를 알려요. 입력은 그대로 남고, 다른 대상은 되돌릴 수 있어요. 저장하거나 취소하면 다시 되돌릴 수 있어요. 다른 기기에 열린 입력은 수정 번호 검사로만 지켜요.
- **결과**: 되돌린 카드에는 **되돌렸어요**가, 되돌리지 못한 카드에는 사유가 남아요. 되돌린 상태는 대화를 다시 열어도 유지돼요. 열려 있는 깨끗한 편집기와 읽기 화면은 되돌린 내용으로 새로 불러와요. 되돌린 저장도 일반 저장이라 편집기의 직전 저장 되돌리기로 다시 되돌릴 수 있어요.
- **진행 중인 작업**: 이 대화에 진행 중이거나 대기 중인 도우미 작업이 있으면 되돌리기 버튼을 쓸 수 없고 그 이유가 보여요.
- **결과를 모를 때**: 요청을 보낸 뒤 연결이 끊기면 자동으로 다시 보내지 않고 **결과 확인**을 보여 줘요. 누르면 무엇이 되돌려졌는지 다시 읽어 카드에 표시해요.

### 도우미 서재 자료 편집과 일괄 처리
- **서재 복제**: 서재 목록 복제와 도우미의 `resource.clone`은 동일한 서버 복제 기능을 사용해요.
- **일괄 수정**: 도우미를 통해 여러 자료를 한 번에 수정할 때는 모든 자료의 수정이 성공해야만 원자적으로 저장돼요.
- **프리셋 진단**: 프리셋 진단 기능은 토글 정의와 선택값, 직전 저장 이후 선택지 이름과 번호의 변화를 분석해 줘요. CBS는 직접 실행하지 않으며, 진단 결과는 저장을 차단하지 않아요.

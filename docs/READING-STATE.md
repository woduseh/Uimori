# 읽기 위치와 책갈피

## 이어 읽기

원고는 같은 기기의 정밀한 sessionStorage 복원을 유지하면서 서버에 브라우저·채팅별 최근 읽기 위치 **한 건**을 보관해요. 서버에는 채팅·장면·원문/번역·문단 기준과 문단 내 상대 위치를 저장하고, 화면 픽셀과 읽기 이력은 보내지 않아요. 브라우저의 무작위 식별자는 인증 수단이 아니며 기존 작업실 로그인이 필요해요.

새 브라우저에 자기 위치가 없으면 마지막 유효한 서버 위치에서 열어요. 기존 기기의 위치가 있으면 그 위치가 우선이고, 다른 기기의 더 새로운 위치는 `다른 기기에서 이어 읽기` 안내만 보여요. **열린 화면을 다른 기기의 저장이 강제로 움직이지 않아요.** 검색 결과·책갈피·장면 URL로 지정한 위치는 자동 복원보다 우선해요.

실제 휠·키보드·터치 읽기로 위치가 바뀌면 최대 10초마다 최근 위치를 저장하고, 다른 채팅으로 이동하거나 탭을 숨길 때도 저장을 시도해요. 초기 레이아웃·본문 생성·프로그램 스크롤을 읽기 진행으로 간주하지 않아요. 종료 직전 요청 하나만 신뢰하지 않으며, 연결이 끊겨도 이 기기의 sessionStorage 복원은 유지돼요. 오래된 오프라인 위치들을 큐로 재생하지 않고 다음 실제 읽기 위치 한 건을 저장해요.

같은 기기의 여러 탭은 `expectedRevision`으로 충돌을 확인해요. 충돌한 예전 위치를 재시도해 최신 위치를 덮지 않고 서버 개정만 다시 확인해요. 원고를 뒤로 읽는 것도 정상 위치로 저장하며 최대 진행도를 강제하지 않아요. 서버 위치 조회가 실패해도 원고 열기는 막지 않아요.

원문 수정·재번역으로 hash가 바뀌면 잘못된 문단 대신 장면 시작으로 이동해요. 동적 Risu HTML처럼 안정적인 문단 anchor가 없으면 장면 단위로 복원해요. 모델 호출이나 번역 재실행으로 위치를 복구하지 않아요.

## 책갈피

장면 아래 **책갈피 추가**에서 이름과 짧은 메모를 저장해요. 선택한 텍스트가 있으면 짧은 인용 미리보기로, 없으면 해당 원문/번역의 앞부분으로 남겨요. **장면 목록 → 책갈피**에서 이동·이름/메모 편집·삭제가 가능해요. 삭제는 책갈피만 지우며 원고는 유지해요. 원고 수정으로 위치가 달라져도 사용자가 남긴 이름·메모·인용은 임의로 삭제하지 않아요.

책갈피는 사용자 자료이며 자동 만료나 조회 이력이 없어요. 채팅 삭제 시 해당 채팅의 위치·책갈피만 함께 삭제하고 독립 사본은 유지해요. `이 장면까지 새 채팅으로 복사`는 선택 범위 안의 책갈피만 새 장면 ID에 연결해요. 원문 내용과 문단이 유지되면 새 source의 anchor로 옮기며, 안전하게 재연결할 수 없는 번역 문단은 장면 시작으로 옮겨요. 기기별 읽기 위치는 독립 채팅에 복사하지 않아요.

개별 채팅 백업에도 책갈피가 포함돼요. 가져오기는 새 ID로 연결하며 책갈피가 없는 과거 백업도 허용해요. 전체 DB 백업은 위치와 책갈피 모두를 포함해요.

## API와 검증

`GET/PUT /api/chats/:id/reading-position`은 브라우저 ID·현재 개정·ReaderTarget을 사용해요. `GET/POST /api/chats/:id/bookmarks`, `PATCH/DELETE /api/bookmarks/:id`는 기존 인증과 CAS를 재사용해요. 서버는 장면이 현재 채팅 경로에 실제 속하는지 ID로 확인하고, 빈번한 위치 저장 때 긴 본문을 읽거나 토큰화하지 않아요. clientId는 신뢰 경계나 계정이 아니에요.

`tests/reading-state.test.ts`는 기기별 상태·뒤로 읽기·충돌·채팅 경계, 책갈피 생성 재전송·수정·삭제, 복사 범위/ID/문단 재연결, 개인 백업/구형 입력/원자적 실패를 검사해요. `npm run verify:personal-features`는 새 기기의 시작 위치, 원격 변경 안내, 책갈피 편집과 작은 화면을 실제 브라우저에서 확인해요. 물리적인 휴대폰 OS가 종료 순간의 네트워크 전송을 보장한다는 뜻은 아니에요.

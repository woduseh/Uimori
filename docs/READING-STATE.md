# 읽기 위치와 책갈피

Uimori에서 긴 원고를 기기별로 이어서 읽는 방식, 장면 이름 지정과 목차 관리, 책갈피 기능 및 백업 동작에 관한 안내예요.

---

## 기기별 이어 읽기와 위치 복원

### 화면 즉시 열기와 이어 읽기 제안
원고 화면을 열면 브라우저 로컬 저장소(`localStorage`)에 보관된 위치로 본문을 지체 없이 즉시 표시하고, 서버에 저장된 최근 위치 조회를 백그라운드에서 병렬로 진행해요.

- **다른 기기에서 이어 읽기**: 다른 기기나 다른 브라우저에서 더 최근에 읽은 위치가 확인되면, 화면에 `다른 기기에서 이어 읽기` 제안 카드를 띄워요.
- **저장된 위치에서 이어 읽기**: 서버에 현재 기기에서 저장했던 위치만 남아 있는 상태라면 `저장된 위치에서 이어 읽기` 카드를 안내해요.
- **화면 강제 이동 금지**: **다른 기기에서 저장한 위치 때문에 현재 열려 있는 화면이 강제로 스크롤되거나 움직이지 않아요.** 사용자가 제안 카드를 직접 눌러야 해당 위치로 이동해요.
- **명시적 탐색 우선**: 검색 결과, 책갈피 클릭, 또는 특정 장면 URL을 통해 진입한 경우에는 자동 복원 위치보다 사용자가 지정한 이동 대상이 항상 우선해요.
- **제안 카드 닫기**: 제안 카드를 닫거나 이어 읽기를 적용하면 해당 탭에서는 동일한 위치를 다시 제안하지 않아요 (실제 장면·문단 위치가 변경된 경우에만 새 제안이 나타남). 일시적인 위치 조회 통신 오류는 화면에 경고를 띄우지 않고 자연스럽게 무시해요.

### 위치 저장 시점과 주기
- **직접 이동 시**: 장면 목록, 검색 결과, 책갈피를 눌러 직접 이동한 위치는 화면 레이아웃이 적용된 직후 즉시 서버에 저장을 시도해요.
- **스크롤 및 일반 읽기 시**: 마우스 휠, 키보드 방향키, 터치 드래그로 본문을 읽어 나갈 때는 **최대 10초마다** 가장 최근 위치를 주기적으로 서버에 저장해요.
- **탭 전환 및 이탈 시**: 다른 채팅으로 이동하거나 브라우저 탭을 백그라운드로 숨길 때도 최신 읽기 위치를 즉시 저장해요.
- **읽기 진행 판정**: 초기 레이아웃 계산, 새 본문 생성 중 스크롤, 프로그램 스크립트에 의한 화면 이동은 사용자의 읽기 진행으로 간주하지 않아요.
- **뒤로 읽기 지원**: 원고의 앞부분으로 되돌아가 읽는 것도 정상적인 읽기 위치로 저장하며, 최대 진행도만을 강제하지 않아요.
- **오프라인 동작**: 네트워크가 끊기더라도 현재 기기의 `localStorage` 복원은 안정적으로 유지되며, 다시 연결되었을 때 가장 최근의 실제 위치 한 건을 서버에 저장해요.

### 본문 수정 시의 위치 보정
- 원문을 직접 편집하거나 번역을 다시 실행하여 텍스트 내용의 해시(hash)가 변경된 경우, 엉뚱한 문단으로 튀는 것을 방지하기 위해 해당 장면의 시작 지점으로 안전하게 이동해요.
- 동적 Risu 카드 HTML처럼 안정적인 문단 앵커가 없는 콘텐츠는 문단 대신 장면 단위로 복원해요. 모델을 다시 호출하거나 번역을 재실행하여 위치를 억지로 계산하지 않아요.

## 장면 이름과 목차 관리

### 장면에 이름 붙이기
장면 목록(목차)을 열고 각 장면의 이름 편집 버튼을 눌러 원하는 이름을 직접 지정할 수 있어요.

- **표시 우선순위**: 장면 목록과 화면 상단 눈금(네비게이터)에는 다음 순서에 따라 장면 이름이 표시돼요.
  1. 사용자가 직접 입력한 **장면 이름**
  2. 연결된 스토리 구성(아웃라인)의 **구성 제목**
  3. 해당 장면의 **요청문 미리보기**
- **세부 구성 항목 반영**: 여러 구성 항목이 동일한 장면에 연결된 경우, 작은 사건 단위의 가장 구체적인 항목을 우선 표시하며 단계가 같다면 먼저 연결된 항목을 사용해요.
- **이름 초기화**: 입력란을 비워 두고 저장하면 구성 제목이나 요청문 미리보기 표시로 되돌아가요.
- **첫 메시지**: 대화의 가장 첫 번째 메시지는 기본적으로 **첫 메시지**로 표시돼요.

### 목차 검색과 모델 비용
- 장면 목록에서는 번호, 지정한 이름, 요청문 미리보기 텍스트로 장면을 빠르게 검색할 수 있어요.
- 장면 이름을 변경하더라도 원고 본문과 모델 입력 프롬프트는 그대로 유지되며, 추가적인 AI 모델 호출이나 요금은 일체 발생하지 않아요.
- 다른 브라우저 창에서 이름이 먼저 변경된 경우, 현재 작성 중인 미저장 입력을 안전하게 보존한 채 충돌 사실을 알려줘요.

## 책갈피 추가와 관리

### 빠른 책갈피 추가
- 원고 읽기 중 장면 하단의 **책갈피 추가** 버튼을 한 번 누르면 현재 읽고 있는 위치가 즉시 저장돼요.
- 저장된 버튼을 다시 누르거나 장면 목록의 편집 버튼을 눌러 책갈피 이름과 메모를 수정할 수 있어요.
- **인용구 자동 추출**: 본문에서 특정 텍스트를 마우스나 터치로 선택한 상태에서 추가하면 해당 구절이 짧은 인용구 미리보기로 저장되고, 선택 영역이 없으면 해당 문단의 첫머리가 인용구로 저장돼요.

### 책갈피 탐색, 수정 및 삭제
- **장면 목록 → 책갈피** 탭에서 등록된 모든 책갈피 목록을 확인하고, 원하는 위치로 즉시 이동하거나 이름·메모를 수정하고 삭제할 수 있어요.
- **확인 창 기반 삭제**: 책갈피 삭제 시 공통 확인 대화상자를 거치며, 확인된 책갈피만 안전하게 삭제되고 원고 본문은 전혀 영향을 받지 않아요.
- **편집 이탈 방지**: 책갈피 이름이나 메모를 수정하던 중 대화상자를 닫으려고 하면 **계속 편집 / 초안 버리고 닫기 / 저장하고 닫기** 선택창이 나타나요. ESC 키를 누르거나 바깥 영역을 클릭해도 작성 중인 내용이 사라지지 않아요.
- **실패 시 복구**: 네트워크 오류 등으로 저장이나 삭제 요청이 실패하면, 대화상자를 닫은 뒤 **책갈피 다시 불러오기** 버튼이 나타나 최신 서버 목록을 다시 확인할 수 있어요.

## 독립 채팅 복사와 백업 동작

### 특정 장면까지 새 채팅으로 복사
원고 메뉴에서 **이 장면까지 새 채팅으로 복사**를 실행하면:
- 선택한 장면 범위 내에 포함된 책갈피들만 새 채팅의 고유 장면 ID로 안전하게 재연결되어 함께 복사돼요.
- 원문 내용과 문단 구조가 그대로 유지된 경우 실제 텍스트 블록을 찾아 새 소스의 앵커와 문단 내 상대 위치까지 정확하게 옮겨줘요 (구조가 달라진 번역 문단은 해당 장면의 시작 지점으로 연결).
- **읽기 위치 복사 제외**: 기기별 스크롤 읽기 위치는 복사본 채팅으로 이전되지 않으며, 새 채팅에서는 처음부터 읽기를 시작해요.

### 백업 파일과의 관계
- **개별 채팅 백업 (`.json`)**: 사용자가 작성한 책갈피(이름, 메모, 인용구, 연결 장면)가 모두 백업 파일에 포함돼요. 가져올 때는 새 고유 ID로 다시 매핑되며, 책갈피가 없는 과거 버전 백업 파일도 문제없이 가져올 수 있어요.
- **전체 SQLite DB 백업**: 모든 채팅의 기기별 읽기 위치 레코드와 전체 책갈피 데이터가 온전히 포함돼요.

## 구현 참고

이 섹션은 읽기 위치 및 책갈피의 저장 계층, CAS 동시성 제어, API 사양 및 검증 규약을 설명하는 개발자/에이전트 계약이에요.

### 읽기 위치 데이터 스키마 및 저장소 계층
- **서버 저장 단위**: 브라우저·채팅별로 최근 위치 **단 1건**을 보관해요 (`app_metadata` 또는 전용 위치 테이블).
  - 저장 필드: `chatId`, `sceneId`, `representation`(`original | translation`), `paragraphIndex`(문단 기준), `offsetRatio`(문단 내 상대 위치).
  - 화면 픽셀 좌표나 전체 스크롤 이력 로그는 서버로 전송하지 않아요.
- **클라이언트 스토리지 분담**:
  - `localStorage`: 현재 기기의 정밀한 스크롤 읽기 위치 캐시를 보관해요.
  - `sessionStorage`: 입력창 커서 위치 및 탭별 임시 상태를 보관해요 (조회 시 기존 세션스토리지 위치를 로컬스토리지로 마이그레이션).
  - 브라우저의 무작위 클라이언트 식별자(`clientId`)는 인증 수단이 아니며 기존 세션 로그인을 반드시 거쳐요.

### 동시성 및 CAS(`expectedRevision`) 충돌 제어
- 동일 기기 내 다중 탭이나 다중 창 간의 경합은 `expectedRevision`을 활용한 CAS(Compare-And-Swap) 방식으로 제어해요.
- 서버 수정 번호가 일치하지 않는 예전 위치는 무리하게 재전송하지 않으며, 다음 채팅 진입이나 화면 복귀 시 최신 서버 수정 번호를 다시 확인해요.
- 저장 요청이 전송 중인 상태에서 새로운 스크롤 위치가 발생한 채 사용자가 탭을 닫거나 이동하면, 앞선 저장이 완료된 후 새 위치를 연속해서 안전하게 저장해요.

### 책갈피 데이터 모델 및 원자적 관리
- 책갈피는 사용자 창작 자산으로 분류되며 임의의 자동 만료나 만료일자가 없어요.
- 원고 본문 텍스트가 수정되어 문단 위치가 어긋나더라도 사용자가 작성한 이름, 메모, 인용구는 임의로 삭제되지 않고 보존돼요.
- 채팅을 완전히 삭제할 때만 해당 채팅에 종속된 읽기 위치와 책갈피 레코드가 함께 정리돼요.

### 관련 API 엔드포인트
- `GET /api/chats/:id/reading-position`: 현재 브라우저의 최근 읽기 위치 및 서버 수정 번호를 조회해요.
- `PUT /api/chats/:id/reading-position`: `clientId`, `expectedRevision`, `ReaderTarget` 객체를 전달하여 읽기 위치를 원자적으로 갱신해요. 긴 본문 토큰화나 본문 재파싱을 유발하지 않아요.
- `GET /api/chats/:id/bookmarks`: 해당 채팅의 책갈피 목록을 조회해요.
- `POST /api/chats/:id/bookmarks`: 현재 장면에 새 책갈피를 생성해요.
- `PATCH /api/bookmarks/:id`: 책갈피의 이름 및 메모를 수정해요 (CAS 적용).
- `DELETE /api/bookmarks/:id`: 확인된 수정 번호의 책갈피를 삭제해요.
- 서버는 요청된 장면이 현재 채팅 경로에 실제로 속하는지 ID 소유권을 반드시 검증해요.

### 검증 도구와 테스트 명령어

```sh
# 읽기 위치, 책갈피 생성/수정/삭제, CAS 충돌 및 백업 복원 단위 테스트
npx vitest run tests/reading-state.test.ts

# 개인 기능 브라우저 종합 검증 (기기 간 이어 읽기 흐름, 확인 대화상자, 초안 보호)
npm run verify:personal-features
```

- `tests/reading-state.test.ts`: 기기별 독립 상태, 뒤로 읽기 정상 저장, 동시 탭 충돌 방지, 책갈피 중복 생성 방지, 복사 시 문단 앵커 재연결, 과거 백업 호환성 등을 검증해요.
- `npm run verify:personal-features`: 실제 브라우저 환경에서 장면 목록 이동 후 별도 브라우저에서 이어 읽기 제안이 표시되는 흐름, 지연된 네트워크 환경에서도 원고가 즉시 로딩되는 동작, 모바일/데스크톱 확인창의 취소·삭제·충돌 보호 동작을 종합적으로 검증해요 (물리적인 모바일 OS가 전원 종료 순간의 소켓 전송을 보장한다는 의미는 아님).

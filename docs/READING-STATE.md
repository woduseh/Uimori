# 읽기 위치와 책갈피

## 이어 읽기

원고는 같은 기기의 정밀한 sessionStorage 복원을 유지하면서 서버에 브라우저·채팅별 최근 읽기 위치 **한 건**을 보관해요. 서버에는 채팅·장면·원문/번역·문단 기준과 문단 내 상대 위치를 저장하고, 화면 픽셀과 읽기 이력은 보내지 않아요. 브라우저의 무작위 식별자는 인증 수단이 아니며 기존 작업실 로그인이 필요해요.

읽기 위치와 입력창 커서 위치는 선택적인 화면 캐시예요. 저장 공간 부족 등으로 이 캐시를 읽거나 쓰지 못해도 서재·채팅 이동을 계속해요. 원고 초안과 미확정 요청의 복구 저장은 별도 정책을 유지해요. 로컬 스크롤 위치는 Reader에서 한 번 저장하고, 서버 동기화는 아래의 사용자 읽기 조건을 따로 적용해요.

원고와 이 기기의 로컬 위치는 바로 열고, 서버 위치 조회는 병렬로 진행해요. 새 기기에서도 조회 결과로 화면을 자동 이동하지 않고 `다른 기기에서 이어 읽기`를 선택해요. 서버에 이 기기의 위치만 남아 있으면 `저장된 위치에서 이어 읽기`를 안내해요. **열린 화면을 다른 기기의 저장이 강제로 움직이지 않아요.** 검색 결과·책갈피·장면 URL로 지정한 위치는 자동 복원보다 우선해요.

장면 목록·검색·책갈피로 직접 이동한 위치는 레이아웃이 적용된 뒤 즉시 서버 저장을 시도해요. 자동 복원·초기 레이아웃과 명시적 이동을 구분하며, 휠·키보드·터치 읽기로 위치가 바뀌면 최대 10초마다 최근 위치를 저장하고, 다른 채팅으로 이동하거나 탭을 숨길 때도 저장을 시도해요. 초기 레이아웃·본문 생성·프로그램 스크롤을 읽기 진행으로 간주하지 않아요. 종료 직전 요청 하나만 신뢰하지 않으며, 연결이 끊겨도 이 기기의 sessionStorage 복원은 유지돼요. 오래된 오프라인 위치들을 큐로 재생하지 않고 다음 실제 읽기 위치 한 건을 저장해요.

같은 기기의 여러 탭은 `expectedRevision`으로 충돌을 확인해요. 충돌한 예전 위치를 재시도해 최신 위치를 덮지 않고 서버 개정만 다시 확인해요. 원고를 뒤로 읽는 것도 정상 위치로 저장하며 최대 진행도를 강제하지 않아요. 서버 위치 조회가 실패해도 원고 열기는 막지 않아요.

원문 수정·재번역으로 hash가 바뀌면 잘못된 문단 대신 장면 시작으로 이동해요. 동적 Risu HTML처럼 안정적인 문단 anchor가 없으면 장면 단위로 복원해요. 모델 호출이나 번역 재실행으로 위치를 복구하지 않아요.

## 책갈피

장면 아래 **책갈피 추가**를 한 번 누르면 현재 위치를 바로 저장해요. 저장된 버튼을 다시 누르거나 장면 목록의 편집 버튼으로 이름·메모를 수정해요. 선택한 텍스트가 있으면 짧은 인용 미리보기로, 없으면 해당 원문/번역의 앞부분으로 남겨요. **장면 목록 → 책갈피**에서 이동·이름/메모 편집·삭제가 가능해요. 삭제는 공통 확인창에서 확인한 책갈피 개정만 지우며 원고는 유지해요. 미저장 편집을 닫을 때는 앱 확인창에서 계속 편집·수정 버리고 닫기·저장하고 닫기를 선택해요. Escape나 바깥 클릭은 편집을 유지하며, 저장 충돌이나 실패가 나면 입력을 보존해요. 원고 수정으로 위치가 달라져도 사용자가 남긴 이름·메모·인용은 임의로 삭제하지 않아요.

미저장 메모와 저장 중인 요청은 기존 편집 이탈 방지에 연결해 알림이 와도 창을 강제로 없애지 않아요.

책갈피는 사용자 자료이며 자동 만료나 조회 이력이 없어요. 채팅 삭제 시 해당 채팅의 위치·책갈피만 함께 삭제하고 독립 사본은 유지해요. `이 장면까지 새 채팅으로 복사`는 선택 범위 안의 책갈피만 새 장면 ID에 연결해요. 원문 내용과 문단이 유지되면 실제 블록을 찾아 새 source의 anchor와 문단 내 상대 위치로 옮기며, 안전하게 재연결할 수 없는 번역 문단은 장면 시작으로 옮겨요. 기기별 읽기 위치는 독립 채팅에 복사하지 않아요.

개별 채팅 백업에도 책갈피가 포함돼요. 가져오기는 새 ID로 연결하며 책갈피가 없는 과거 백업도 허용해요. 전체 DB 백업은 위치와 책갈피 모두를 포함해요.

## API와 검증

`GET/PUT /api/chats/:id/reading-position`은 브라우저 ID·현재 개정·ReaderTarget을 사용해요. `GET/POST /api/chats/:id/bookmarks`, `PATCH/DELETE /api/bookmarks/:id`는 기존 인증과 CAS를 재사용해요. 서버는 장면이 현재 채팅 경로에 실제 속하는지 ID로 확인하고, 빈번한 위치 저장 때 긴 본문을 읽거나 토큰화하지 않아요. clientId는 신뢰 경계나 계정이 아니에요.

`tests/reading-state.test.ts`는 기기별 상태·뒤로 읽기·충돌·채팅 경계, 책갈피 생성 재전송·수정·삭제, 복사 범위/ID/문단 재연결, 개인 백업/구형 입력/원자적 실패를 검사해요. `npm run verify:personal-features`는 실제 장면 목록 이동으로 저장한 위치를 별도 브라우저에서 이어 읽는 흐름, 지연된 위치 API와 독립적인 원고 로딩, 책갈피 즉시 저장·편집과 데스크톱/모바일 확인창의 취소·삭제·충돌·진행 중 보호를 실제 브라우저에서 확인해요. 물리적인 휴대폰 OS가 종료 순간의 네트워크 전송을 보장한다는 뜻은 아니에요.

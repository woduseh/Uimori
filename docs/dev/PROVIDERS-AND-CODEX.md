# Providers, Codex, execution, context and illustrations

Developer and agent contract for provider transport encoding, Codex App Server isolation, model parameters and pricing, prompt and model workspace semantics, execution snapshots and response streams, queued requests and refusal retries, context measurement and compaction, custom agent collaboration, evaluation tools, scene illustrations, and input translation. Feature entry points live in [CODE-MAP](CODE-MAP.md).

## Providers and transport encoding

### Request conversion and ownership boundaries

- `modelRequestFields` extracts only `modelId`, `providerOptions`, and frozen `pricingSnapshot` from a `ModelSnapshot`; callers independently own generation options, context budgets, tool definitions, and storage or execution policy.
- `saveConnection` runs `validateProviderEndpoint` and `validateVertexCredential` (for a newly supplied or previously stored Vertex service account) atomically in the same SQLite transaction as credential writes; resource editing and legacy backup checks do not enter the transport path.
- `measureProviderRequest` unifies outgoing request-body measurement and per-model tokenizer budgets across context planning, automatic compaction, and next-request previews, checking summary inclusion against the actual outgoing request while keeping native Gemini roles and ordering and measuring Codex native and helper formats.
- Prompt-shape validation neither copies nor mutates caller data; inputs requiring mutation and provider continuation state copy at ownership boundaries.
- Calls with no public stream subscriber skip assembling intermediate display prose while preserving final results, usage, and cancellation handling (`createPublicTextProgress`).

### Per-protocol image and message encoding

- `imageInputSupported` allows images on a direct DeepSeek connection only for `deepseek-flash`, the one ID the DeepSeek pricing page marks with vision, and rejects every other direct DeepSeek ID (`deepseek-v4-pro` is listed there as not supporting vision) and confirmed text-only models, while returning `null` so custom models with unconfirmed support may still attempt transmission.
- **DeepSeek message content (`encodeChat`)**: system and assistant content is sent as one string because the Chat Completion reference types it as a string; user content is one string too unless it carries an image, in which case it keeps its text and `image_url` parts.
- Codex's image generation tool stays disabled on main-story and text turns (`CODEX_RUNTIME_CONFIG` sets `'features.image_generation': false`); user image attachment UI applies to main-story requests, whereas image-placement judgment candidates are configured separately under judgment provider options.
- **Vercel Chat (`encodeChat`)**: concatenates text parts from prior assistant messages in order into one string before sending.
- **OpenAI Responses (`encodeResponses`)**: builds manual conversation history (including assistant turns) from `input_text` parts preserving per-part cache breakpoints, and replays provider-returned message, reasoning, and tool-call items with their original format and IDs on follow-up tool rounds.
- **Gemini conversation and tool handling (`encodeVertex`)**: follow-up requests after tool calls preserve the model's original response and `thoughtSignature`, placing additional control text inside the same user turn before `functionResponse` parts to avoid Vertex endpoint rejections (Claude, OpenAI, and Codex request formats remain unchanged).
- **Gemini mid-conversation system conversion (`acceptsMidConversationSystem`, `planNativeMessages`)**: for Gemini model IDs (including gateway IDs such as `gemini-…` and `google/gemini-…`), non-leading `system` messages convert to `user` at send time only and emit `GEMINI_MID_SYSTEM_TO_USER` without mutating the source prompt. Direct connections require this because Gemini API and Vertex AI allow only `user` and `model` roles in `contents`, and gateways apply it conservatively where support is unconfirmed.
- **Anthropic message normalization (`planNativeMessages`)**: for prompts shaped `user → 연속 system → user` (`user` → consecutive `system` → `user`), appends one short synthetic completed assistant reply at the end of the system block for transmission only (`ANTHROPIC_SYSTEM_BOUNDARY_ASSISTANT_INSERTED`), leaving original roles, ordering, prose, and cache breakpoints untouched and avoiding duplication on follow-up tool rounds.
- **DeepSeek error handling (`encodeChat`)**: when a stream ends with `insufficient_system_resource` or `aborted`, preserves received prose and final usage, marks the run incomplete, neither executes nor auto-retries incomplete tool calls, and distinguishes remote abort reasons from unsupported response formats.

### Anthropic Batch architecture

- `AnthropicBatchRun` runs no custom batch scheduler: it submits one Anthropic Batch per model turn inside the existing `runMain` tool loop, executes requested tools locally, and submits the next turn as a new Batch until `story.submit` ends the run.
- `anthropic_batches` persists `runId`, `attemptId`, `batchId`, `customId`, and `request_sha256` so server restarts re-query and recover the same Run and Batch, reusing stored results and tool receipts to prevent duplicate execution.
- Ambiguous creation failures where `batchId` was never persisted finalize the run as failed rather than auto-resubmitting, preventing double billing.
- Provider response body reads—including JEV and Responses—abort on cancellation and timeouts; once completion or failure finalizes, stream cleanup is requested without awaiting remote cleanup confirmation so remote latency cannot block finalization.

### Cache-breakpoint diagnostics and tool contracts (`cacheBoundaries`)

- `providerCacheBoundaries` records explicit cache-breakpoint diagnostics under `cacheBoundaries` on local OpenAI Responses and Anthropic request records (live and Batch), never in provider payloads.
- Each entry stores breakpoint position, a hash covering preceding input plus tool and generation settings, and diagnostic JSON byte count: changes after lore leave earlier hashes intact, whereas changes to tool schemas, tool order, or earlier tool history change the hash.
- `stablePrefixSha256` hashes shared contracts and tools only and is not proof of whole-prompt cache reuse; breakpoints are never inferred or fabricated for implicit-cache-only requests.
- Anthropic Messages sends `anthropic-version: 2023-06-01`, maps Uimori tool names to provider-compatible aliases while preserving canonical stored names, arguments, results, and call IDs, keeps original valid names in prior evaluation history excluded from the current tool list, and follows the [official tool definition contract](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools).

### Lore-inclusion record metadata

- `requestLore` embeds compact lore-inclusion metadata inside local main-story and translation request JSON; it never duplicates lore bodies, is never sent to models, and follows existing request-record retention.
- Interpretation rules: appearing by name in a catalog or being selected by the judgment model does not prove actual prose inclusion; candidates whose inclusion could not be verified (for example after prompt transformations) are marked separately, and legacy requests without `requestLore` are never assumed to have excluded lore.

### Concurrent edits and streaming prose assembly

- Enabling or disabling providers and models deletes no stored data and takes effect on the next call.
- Unsaved provider/model drafts stay isolated across editor view switches; if settings were saved elsewhere first, the UI preserves the current draft and prompts to reload.
- Settings read APIs never return raw API keys; unsaved key inputs reside only in browser memory and are never written to local recovery storage.
- `createPublicTextProgress` delivers decoder-validated append chunks with UTF-16 end offsets instead of re-diffing full prose on every chunk, keeps prefix validation across full snapshots or text-change boundaries, verifies accumulated chunks match final text on completion, and excludes reasoning traces, tool arguments, final submission envelopes (`story.submit`, `eval_submit_artifact`), and structured translations from public chunks.

## Codex App Server protocol and isolation

### App Server communication and turn lifecycle

- Uimori drives official Codex App Server RPC methods (`initialize`, `account/*`, `model/list`, `thread/start`, `turn/start`); main-story writers, advisors, and helpers each execute **one task in one thread/turn** and answer host tool callbacks in-turn.
- Translation and context compaction stay ephemeral per-request; separate helper hypothetical-scene execution is intentionally omitted.
- During main-story evaluation, only the first `preloaded` + `economized` step uses the low-cost transport before switching to native writing at configured effort; cross-task native thread resume metadata and opaque continuation state are never persisted in SQLite.
- Text roles replace default coding instructions via `thread/start.baseInstructions` with concise writing, translation, or summary instructions; the helper uses dedicated instructions for resource lookup, editing, and post-save verification.
- The initial request delivers the task, history, resource scope, and registered tools (running pre-start compaction for the helper if initial history exceeds budget); once started, Uimori does not re-bundle history or start a new turn per tool result—in-turn progression and compaction are owned by Codex.
- `buildCodexNativeRequest` and `buildCodexDescriptor` serialize RisuPrompt logical roles, ordering, and empty messages as JSON, preserving message IDs, provenance kinds, and source revisions/hashes while excluding internal host block/run IDs and redundant completion flags on always-completed messages. Separate `input.task` is omitted only when a single current user message matches verbatim, and assistant prefill or `require` cache directives reject pre-send because Codex injects its own instructions.
- `reasoningEffort` and timeout are forwarded while temperature is disallowed; general roles pass `maxOutputTokens` as soft `outputTokenBudget` rather than a provider cap (never padded—explicit prompt length directives take precedence). Structured output and per-role validation stay on general roles, while the native helper enforces no final JSON envelope or `outputSchema`.
- `CodexRuntime` records an RPC attempt before sending with concurrency capped at 2 active text turns and 32 queued (all cancellable), and never auto-replays after restarts, send failures, or uncertain outcomes.
- Official CLI 0.153 rejects overriding retry settings, so internal CLI retries or duplicate calls can occur; explicit harness retries and bounded retries on cleanly completed results record as separate judgment requests.
- One attempt represents one host-initiated Codex turn rather than internal model calls: native helper tool/model loops log as one attempt while pre-start compaction logs separately. Actual cost and internal model-call counts remain `null`, turn-wide timeout, cancellation, and host tool permissions still apply, and Vertex USD budgets never interpret as Codex subscription budgets.
- Raw usage retains only numeric input, cached, output, and reasoning tokens from `tokenUsage.total` and `last`, updating totals from the latest `total` snapshot without double-counting updates, re-adding cached tokens, or zero-filling omitted fields; illustration raw usage also records `itemCounts` and `tokenUsageUpdates` while excluding image bytes and tool contents.

### Native execution for main writing and advice

- Activates automatically whenever a Codex writer or advisor is selected in a real main-story Run, including a Codex advisor paired with a non-Codex main model.
- **Context and tool delivery**: main writers preserve exact roles, ordering, source text, lore, plot/outline, and prior results from `buildMainProviderRequest` and `editRequest` (registering tool schemas as native tools only); advisors use dedicated requests, models, instructions, and explicit drafts/evidence under `agents.consult` (no sub-advisors or prose writes), preserving pre-writing consultation order.
- **Submission detection and early termination**: on observing `story.submit` or a valid `eval_submit_artifact`, the host skips a normal tool response, immediately invokes `turn/interrupt`, and cleans up the process. Only that host-confirmed submission succeeds—cancellation, timeout, connection changes, or write failures never promote to success.
- Source persistence still runs judgment-model verdict, post-processing, and atomic commit without follow-up confirmation prose; main runs with evaluation off still accept normal final text, whereas evaluation-enabled `model-selected` and `preloaded` runs both require `eval_submit_artifact` (streaming is not added for main-writer or advisor turns).
- Usage on host-submission termination records `completion: 'host-submission'` and `usageComplete: false` so it is not mistaken for final billed usage.
- **Context planning and evidence tracking**: native execution neither rebuilds prompts per tool call nor runs duplicate compaction (`editRequest` runs only when the real host request begins). Initial planning uses the larger estimate between legacy and native inputs for economized first-step reuse, then re-checks the actual native descriptor pre-send; `requestLore`, `tool_events`, and advisor `agents.read` stay separate evidence records so later reads never retroactively attribute to initial input.
- **Host callbacks and call limits**: call limits count host-initiated requests and native executions (not internal reasoning steps or individual read tools); advice cache hits are not re-billed, while judgment calls and separate advisor executions count individually. An active native writer continues in-turn after consultation without reserving a next writer call, whereas pre-writing consultation and the legacy HTTP loop reserve 1 writer call plus post-processing.
- Evaluation enforces fixed `EVALUATION_TOOL_ROUND_LIMIT` (10 non-terminal host tool callbacks including failed submissions) with valid terminal submission accepted separately on native main runs, and at most 11 provider requests plus overall call and time limits on HTTP main and translation runs.
- Synthetic stdio regression coverage lives in `tests/codex-writing.test.ts` (writing, consultation, cache reuse, child-slot allocation, cancellation propagation, submission detection, and economized transition).

### Built-in tools and isolation boundaries

- **Disabled tools (`CODEX_RUNTIME_CONFIG`)**: disables shell/unified execution, filesystem writes, `js_repl`, `view_image`, browser/computer use, external apps/MCP, skills, persistent memory, built-in subagents/collab, and interactive permission prompts (`approval_policy: 'never'`, `sandbox_mode: 'read-only'`) to preserve host file, credential, storage, collaboration, and context boundaries.
- **Code Mode (`code_mode`)**: isolated V8 JavaScript executor distinct from Node REPL—can call only registered tools and exposes no Node, filesystem, or network APIs and no module imports.
- **Namespace isolation**: excludes the default `functions` namespace (`code_mode.excluded_tool_namespaces`) so shell/file tools cannot resurface via nested execution; Uimori tools register exclusively under experimental `dynamicTools` (`type: "function"`) in the `uimori` namespace with an `uimori_...` wire prefix restored on the host, accepting calls only when active thread/turn and `uimori` namespace match and rejecting duplicate call IDs.
- **Tool results and streaming**: ephemeral legacy roles return final JSON envelopes while native main/advisor/helper turns answer `item/tool/call` with `contentItems`/`success`. Helper replies stream `final_answer` plain text live while commentary logs as separate progress events, built-in search/compute intermediates never save as prose, and phase-less legacy replies fall back to the last message only when no follow-up work remains.

### Explicit server-internal multi-turn sessions

- `CodexRuntime.createSession(connection)` creates an in-memory caller-owned session closed via `close()` in a `finally` block: sequential `execute`, `executeAgent`, and `generateImage` calls reuse the first turn's isolated process and ephemeral thread (single-turn methods close the process after each request).
- Sessions pin connection, model, base/developer instructions, and tool permissions, reject concurrent turns, never share across users or independent tasks, never persist resume metadata in SQLite, enforce per-turn cancellation/timeout/connection checks, and close permanently after any failed or uncertain turn.
- **Consecutive illustration cuts**: cuts sharing the same source hash and storyboard plan reuse one session while keeping **a separate turn, job, attempt, and result per cut**; successful cuts commit immediately, only failed cuts retry, incompatible plans/chats/connections/regenerations/budgets run independently, and variants of one cut never cross-assign.
- **Cumulative token checks**: local session history includes host tool arguments and text responses; when Codex reports cumulative input/output tokens, the next turn must fit that cumulative total plus the new request estimate within the model's input budget. If tool, image, or reasoning items occurred without usable token reporting, the session rejects the next turn so illustrations run independently (cumulative usage may exceed actual active context).

### Local verification and official contracts

- For installed-CLI preflight (`UIMORI_CODEX_PREFLIGHT=1` and `output/codex-preflight/summary.json`), see [DEVELOPMENT](DEVELOPMENT.md#builds-and-evidence).
- Non-1:1 test suites: `tests/codex-image.test.ts`, `tests/codex-integration.test.ts`, and `npm run verify:providers` (390px Codex settings, mocked login, cancellation, and disconnect).

## Model parameters, cache quirks and connection tests

Authoritative option definitions live in `modelCapability` and `validateModelOptions` alongside the model family and protocol definitions in [CODE-MAP](CODE-MAP.md). Showing a family's option list does not confirm that a specific model supports every option; only values verified against provider catalogs or review tables appear as confirmed hints.

- **Claude Opus 5.5 (`claude-opus-5-5`)**: cache support is confirmed for the exact model ID (authored breakpoints transmit even when cache settings are unspecified); adaptive thinking is always enabled (default effort `medium`), forced tool calling is unsupported, and saved generation settings are not rewritten automatically.
- **Claude Fable 5.2 (`claude-fable-5-2`)**: exact-ID cache support; adaptive thinking is always enabled (default effort `high`) and forced tool calling is unsupported. The model rejects with HTTP 400 any request whose `system`, `tools`, or prior messages preceding a thinking block changed, so `encodeAnthropic` replays initial `system`, `tools`, messages, and response blocks verbatim across tool rounds and rejects mutated follow-ups pre-send (`ANTHROPIC_CONTINUATION_MISMATCH`).
- **GPT-5.6+ Responses**: confirmed TTL is `30m` only; `planProviderCache` passes mode via `prompt_cache_options.mode` and breakpoints via `prompt_cache_breakpoint`.
- **GPT-6.2 Responses (`encodeResponses`)**: `gpt-6.2-astra` and `gpt-6.2-sol` append top-level `instructions` after `input`, so for model IDs matching `gpt-6.2` or `gpt-6.2-…` (including `provider/` prefixes) shared instructions move into the first `developer` message in `input` and top-level `instructions` is omitted without shifting breakpoints or `prompt_cache_options`; earlier models are unaffected and reasoning effort `none` is rejected.
- `validateModelOptions` rejects saving a cache TTL while cache mode is disabled or unspecified.
- **Gemini 4 (`gemini-4-carbon`, `gemini-4-neon`, `gemini-4-hydrogen`)**: explicit `cachedContents` is unsupported; implicit caching applies on shared prefixes around 4,096 tokens for Carbon and Hydrogen (hits are not guaranteed). Carbon supports `LOW`/`MEDIUM`/`HIGH` (default `MEDIUM`) while Neon and Hydrogen add `XHIGH` (default `HIGH`). `encodeVertex` matches these IDs and `gemini-4-argon` by exact ID, independent of the capability table: it omits `temperature` and `top_p` (ignored by the models), rejects `MINIMAL` pre-send, and caps direct REST streaming output at 65,536 tokens (`continuation_token` automatic re-invocation is not yet supported).
- **IDs removed from the capability table**: a saved preset whose model ID is no longer in `modelCapability` takes the unlisted-model path. `validateModelOptions` checks options per protocol, never per model, so stored options still load, save, and send unchanged. What the table supplied stops: picker suggestions, confirmed-value hints, the context-window clamp in `contextBudgetForModel`, `forcedTools` pre-send rejection, and the exact-ID cache support in `planProviderCache` and `helperGenerationFromModel` (authored breakpoints and the helper's automatic cache are sent only once the preset sets a cache mode; a `require` breakpoint fails with `PROMPT_CACHE_UNSUPPORTED` until then). `tests/model-capabilities.test.ts` covers removed IDs end to end.
- **Deliberate cache omissions**: no Gemini cache OFF or TTL controls are exposed (the app implements neither `cachedContents` CRUD nor project-wide implicit cache controls), and cache support is never inferred for Chat, Vercel, or OpenAI-compatible providers.
- **Connection tests (`ProviderConnectionTestStore`, `createConnectionTestRunner`)**: log a local diagnostic pre-send, never replay identical idempotency keys, cap concurrent tests per model at 1, finalize restart-interrupted tests as interrupted without replay, and include `provider_connection_tests` in full SQLite backups only (excluded from portable per-resource/chat backups).

### Storage and execution boundary

- Model revisions persist generation options and Run/job snapshots freeze them so main prose, translation, compaction, helper, and script assistance forward identical fields through `modelRequestFields`.
- Enabled state and credentials re-verify at call time; evaluation economized mode lowers output caps and effort only on explicit opt-in without mutating other bindings.

## Model pricing and cost estimation

### Execution and storage contract

- `validateModelPricing` and `resolveModelPricing` save model `pricing` under revision CAS and freeze unit rates, source, verification date, and context tiers into `ModelSnapshot.pricingSnapshot` at queue time so later edits never reprice historical runs.
- Pricing metadata is host-only (never sent in provider HTTP/RPC payloads), logs on attempts with start time pre-send, and server-forced Vertex Flex selects the Flex rates frozen at queue time.
- `estimateCost` writes calculation results and line items into `response.estimatedCost`; `cost_usd` remains exclusively for provider-reported actual cost (never turning `null` into an estimate or `0`), requiring no DB schema migration.
- Input/cache accounting (`providerCacheUsage`, `estimateCost`): Anthropic normalized input already includes cache tokens so raw `input_tokens`/cache split is used; reasoning/thinking tokens already counted in output are not re-added; Vercel cache writes prefer top-level `cache_creation_input_tokens` and fall back to `prompt_tokens_details.cache_write_tokens` only when absent; unpriced write tokens stay in partial sums and raw usage `cost` is never auto-treated as provider-reported cost.
- Missing usage or rates leave overall estimated cost unknown while surfacing confirmed items in `subtotalUsd`, and explicitly `0` usage prices at `0` even with unknown rate. For Vertex/Gemini, omitted `cachedContentTokenCount` alongside a valid `promptTokenCount` reads as proto3 default `0`, whereas missing usage overall or explicit `null` remains unknown.
- **HTTP 429 zero-usage (`rateLimitedCallUsage`)**: rate-limited calls arrive before any response body starts so they record `0` input and `0` output tokens (computing cache-read, cache-write, and estimated cost as `0`), preventing helper retries after 429s from turning a task's usage total unknown; other HTTP errors and dropped connections stay unknown because provider execution is uncertain (`tests/vertex-transport.test.ts`).
- Actual-vs-frozen service-tier mismatches suppress estimation (`standard_only` normalizes to `standard`). New Anthropic Batch reservations freeze explicitly entered Batch rates without extra discounting, whereas legacy pre-update Batch snapshots retain their 50% discount (`ANTHROPIC_BATCH_50_PERCENT`), and historical unknown calls are not retroactively repriced.
- Main views aggregate writing and writing-assistance estimates while task activity separates follow-ups (translation, title generation), detail views separate actual from estimated cost, and usage from retired helper hypothetical-scene generation remains attributed under `helper-artifact` (and its summaries under `summary`).
- **Judgment pricing (`judgmentPricing`, `judgmentPriceTarget`, `validateJudgmentPricing`, `judgmentPricingSnapshot`)**: judgment prices live in the model workspace's `judgmentPricing` list, not on a `ModelPreset`, because the TypeSafe default has no connection and Decisions model IDs (`gpt-6-luna`, `gemini-decision-1`) are not chat models a user registers, so no existing model price entry can describe them. Each entry is keyed by what is billed: provider and model, plus the connection only for the compatible formats, since two gateways can bill one model ID differently while the official OpenAI and Gemini endpoints bill the same model the same way whichever saved connection carries the key. Switching providers therefore keeps every price. The earlier single `judgment.pricing` shape is still read and carried into the list for its target, and every save writes the list. Entries whose connection was deleted are dropped on the next save of the role settings, and `MAX_JUDGMENT_PRICES` caps the list because compatible model IDs are free text. `judgmentRuntime` freezes the snapshot of the target it resolves, so the price on a call is the one for the target that actually ran, and a changed price never reprices past attempts. `backfillUnpricedCalls` skips `usage_kind='judgment'` rows so a chat model with the same ID cannot price them; `backfillUnpricedJudgmentCalls` prices them only on request, matching the recorded format, model and (for compatible formats) connection. Content-free judgment records that dropped their format can only be matched when they ran on TypeSafe, whose `typesafe-judgment` connection ID is unique. Only input, cached input (OpenAI Decisions formats, which report `input_tokens_details.cached_tokens`) and output rates are accepted, because those are the only usage counts judgment responses carry; TypeSafe bills input tokens only and states output tokens are free ([TypeSafe models](https://docs.typesafe.ai/models), checked 2026-11-25), so an explicit output rate of `0` is the expected entry. No published rate is prefilled: the app keeps no built-in price table.
- Full SQLite backups preserve pricing snapshots and estimates while portable per-resource/chat backups omit provider/model settings and call records; pricing never gates execution or acts as a cumulative spend cap.
- Non-1:1 verification: `tests/pricing-store.test.ts`, `tests/pricing-transport.test.ts`, and `tests/model-pricing-browser.spec.ts`.

## Global models and prompt workspace

- `updateModelWorkspace` (`PUT` `/api/model-workspace`) guards concurrent edits with `expectedRevision` CAS; optional role models (`titleModel`, `helperModel`, `contextModel`, `scriptModel`), `helperTaskTimeoutMinutes`, `helperConfirmPaidGeneration` (default `false`; see [Helper tools](../HELPER-TOOLS.md#confirmation-before-deletion-or-paid-generation)), and `judgment` preserve stored values when omitted from `PUT` (legacy DBs default `judgment` to JEV / `'typesafe'`).
- `summaryLength` (see [summary length](../CONTEXT-LIMITS.md#공통-요약-지침과-출력-여유)) shares the single `prompt_workspace` JSON row with prompt selection, so concurrent model-workspace and prompt-workspace saves share CAS handling.
- Writing and translation prompts store only preset IDs and explicit default overrides, reading bodies and defaults from the latest saved preset while historical runs preserve queue-time snapshots (`freezeCurrentPrompts`).
- New DBs initialize with unassigned role models rather than adopting models from chat bodies; unsupported legacy DBs and archives are not auto-converted (see [data migrations](../DATA-MIGRATIONS.md)).
- Chat API `profile.routes` is a read-only projection of effective settings (including pinned main model), while overrides store in `profile.pinned.mainPromptPresetId` and `profile.pinned.mainModel`. In profile updates, omitting `pinned` keeps pins, `{}` clears all pins, `expectedRevision` guards conflicts, and archived Runs' `snapshot.profile.routes/models` remain frozen.

### Reading defaults in the UI

- `usePromptWorkspace()` shares one tab-wide read state and invalidation subscription across views; if a save, cross-tab change, or focus-return notification arrives mid-read, the stale response is discarded and a fresh read follows immediately. When the last view unsubscribes, in-flight reads abort and the cache clears without touching editor drafts or queued snapshots.
- `CurrentPrompt.defaultValues` holds the preset's latest saved defaults, `optionValues` holds explicit user overrides, and `values` is their merged result (selecting a preset default clears the override); `freezeCurrentPrompts` freezes only effective `values`, omitting `defaultValues` and `optionValues`.
- Legacy standalone or unnamed current prompts migrate on boot as separate presets, retaining options that differed from legacy defaults as explicit overrides.
- **Auto-title generation (`ChatTitleService`)**: `titleModel` (**설정 → 역할별 모델**, default unassigned, never falling back to main model, excluded from `TaskRole` and `profile.routes`) runs at most once after a new chat's first successful non-authored response; manual titles, existing chats, and forks are excluded.
- At title-generation start, model, provider, and first response freeze in the chat-creation UI language under the model's normal output budget (no separate title length cap) and timeout (default 300s). Models with capability reasoning/effort lists in `modelCapability` send the lowest option for title requests only; unlisted models send their preset value unchanged.
- Title generation logs an attempt pre-send with zero auto-retry after failure or restart and discards late results on manual rename, source edit, or chat deletion; manual renames (`PATCH /api/chats/:id/title`, `Store.renameChat`) enforce `expectedTitleRevision` backed by title event revisions for ABA protection even on identical strings without bumping source, settings, or folder revisions.

## Execution input lifetime, Batch recovery and response streams

- **Reference image storage and normalization (`prepareRequestImages`, `REQUEST_IMAGE_MAX_COUNT`)**: persist in `RunSnapshot.requestImages` deduplicated by hash in `image_blobs`; preserved originals normalize still pixels to lossless WebP while transmission copies freeze separately within 2048px long edge and 2MiB (64MiB input and preserved cap). Conversion runs outside DB transactions under shared image-processing concurrency, committing bytes and request attribution atomically and checking existing receipts before reading consumed or expired uploads.
- **Unsent draft persistence and tab isolation**: unsent draft prose writes to `sessionStorage` immediately; IndexedDB writes prose and attachment list in one transaction, modifying stored image files only on attachment add/remove. `sessionStorage` generation counters and acceptance tokens stop stale recovery overwrites, and Web Locks own the active tab's draft namespace (cloned tabs fork a namespace; browsers without Web Locks isolate normal new tabs but may not isolate duplicated-`sessionStorage` tabs).
- **Image attachment identity through prompts and re-saves**: original message IDs persist through prompt compilation (only user messages in the selected `chat` range forward attachments, never guessed onto CBS-copied ChatML). Lua `editRequest` must preserve message `id` (losing/duplicating an ID or changing role on an image-bearing message aborts; empty-text image turns stay distinct from deleted turns), and native buttons/manual triggers preserve per-user-message bindings on re-save, aborting before commit if merging into one scene exceeds `REQUEST_IMAGE_MAX_COUNT` (8).
- **Deferred image resolution and token allowances (`materializeProviderImages`, `PROVIDER_REQUEST_MAX_BYTES`, `estimateContextInput`)**: requests, continuations, and diagnostics hold only immutable `uimori-image://` references resolved right before transmission after verifying pinned attachments and SHA-256 hashes (Anthropic Batch recovery computes the same request hash from frozen transmission copies). Base64 bytes are not text-tokenized: `conservative-dimensions-v1` adds a resolution-based allowance (not a model-specific formula or billed count) while wire byte limits check independently.
- **History reuse and hash caching**: main history reuses fresh validated items without redundant full-history clones while keeping request items isolated from original snapshots; `validatedHashes` (`WeakMap`) reuses hashes while a source object's text is unchanged and recomputes on change (still verifying supplied hashes), needing no expiry or invalidation service.
- **Lore selection and local candidate search (`createCandidateSearch`)**: small lists fitting the input budget judge in full; large lists search selectable lore across all run-pinned resources by term rarity/frequency and CJK 2-character cues (no extra APIs, embeddings, or persistent indexes) without folder or attachment-order bias, continuing past over-budget entries.
- **Pruning unfinished runs and minimal receipts (`releaseEndedSnapshot`, `runResponse`)**: unfinished main runs (failed, cancelled, interrupted, refused, partial) strip frozen history, resource, and prompt copies on termination, keeping only display/retry fields (only runs eligible to re-run judgment verdict on preserved prose keep full frozen input). `Prefer: return=minimal` on intake, retry, candidate, re-judgment, or cancel returns a compact receipt while full inputs and diagnostics remain on `GET /api/runs/:id`.
- **Compact snapshots and lore inheritance (`settleSnapshot`, `readRunSnapshot`)**: completed state compacts so ordinary Run queries return lightweight metadata while `readRunSnapshot` reconstructs context on demand. Lore inheritance validates source, ancestor, and note provenance on `chat_lore_state` without reviving completed parent Runs (no auto-expanding `DatabaseSync` subclasses or text-sharing triggers).
- **Streaming chunk retention and startup pruning (`pruneUnreachableResponseChunks`)**: completed runs switch reads to terminal status and stored final messages instead of duplicating chunks; on server startup, `pruneUnreachableResponseChunks` removes chunks for main runs the UI can no longer render (committed scenes or finished runs retried in the same chat) while retaining chunks for cancelled runs without `partial_text` even if retried because activity renders partial output from them.
- **Lightweight projections and reader loading**: status checks use `readRunStatus` and `readRunState`; Reader loads current page, latest failure, and active jobs before full history and renders prose only after saved reading position resolves. Logical conversation assembly checks integrity without constructing Reader blocks or translation storage rows, display transforms react to source/variable/resource/image changes rather than a global cursor, mid-story rewrites fork an [independent chat copy](../CHAT-BACKUP.md), and last-response retries copy or replace on commit without deterministic replay.
- **Live interruption vs. Anthropic Batch recovery (`recoverableAnthropicBatchRun`)**: live provider requests transition to `interrupted` on disconnect without auto-resubmitting; Anthropic Batch runs requeue to `queued` only when durable `anthropic_batches` state covers every external call. Mixing live summary, judgment, or script-model calls intentionally blocks auto-reentry because a crash between remote completion and local replay receipt persistence is indistinguishable.
- **Batch replay mechanics and reservation states (`AnthropicBatchRun`)**: recovery re-enters `runMain` matching round order and `request_sha256`, polling existing `batchId` or re-decoding stored JSONL; `tool_events` act as replay receipts (rejected tool records never replay as mutations), and Lua `editRequest` reuses matching request index, input hash, and modified prompt without extra invocations during sizing. New Batches persist locally as `reserved` (safe to create after restart) before flipping to `creating` right before remote creation (`creating` without `batchId` never auto-resubmits to prevent duplicate billing); raw Batch result bodies purge after source commit.
- **Deterministic evaluation replay and upgrade boundary**: evaluation sessions derive from Run ID and queued timestamp and case/receipt IDs derive deterministically from session and call ID so restarts under the same contract reconstruct preloaded requests and receipts identically. Queued or in-progress evaluation Batches under pre-simplification contracts (alongside random-session or removed-context-tool Batches) must finish before upgrading—mandatory `eval_submit_artifact`, `EVALUATION_TOOL_ROUND_LIMIT`, and removal of `source-bound` and find-and-replace never reinterpret old receipts or ignore cross-contract hashes (see [Evaluation tools](../EVALUATION-TOOLS.md)).
- **Response stream batching, sequencing, and handoff (`ResponseStreamStore`)**: approved resumed Batch runs hand off their existing response stream to the new writer (preventing duplicate streams, revoking prior writers, and distinguishing user `cancelled` from shutdown `interrupted`). Incoming text batches at 50ms or 1,024 chars (`DELIVERY_INTERVAL_MS`/`DELIVERY_CHARS`) for immediate in-memory subscribers and flushes to SQLite in one transaction on whichever comes first: 750ms, 4,096 chars (`PERSIST_INTERVAL_MS`/`PERSIST_CHARS`), attempt/segment transition, or termination. Sequence numbers assign pre-delivery so `read()` merges stored rows and the unflushed tail identically across tabs and reconnects, pre-reserving `sqlite_sequence` in blocks of 1,024 (`SEQUENCE_BLOCK`) so pre-flush crashes never reuse delivered numbers; run validity checks on flush while `AbortSignal` guards cancellation and shutdown.
- **Translation streams**: keyed by job ID (`taskKind: 'translation'`) strictly for progress display while `job_results` commits only in the verdict phase, using distinct segments and attempt IDs on post-refusal retries and purging chunks on completion, failure, cancellation, or restart (re-runs open a fresh stream).
- **Thought summaries and HTTP 400 fallback (`ProviderRequest.thoughtSummary`, `ProviderExecutionOptions.onThought`, `VertexDecoder`)**: unsigned thought-summary parts strip from continuation state (display text only; resending bloats input) while signed parts replay verbatim; HTTP 400 on a thought-summary call retries once without summaries and disables them for remaining calls in that task (unrelated 400s fail identically). Main-story runs and non-Gemini providers never set `thoughtSummary`, and live summaries stream through `ResponseStreamStore`'s `thought` field (`tests/vertex-transport.test.ts`, `tests/chat-event-stream.test.ts`, and `tests/helper-workspace.test.ts`).
- **Helper activity tracking and retention (`readHelperActivity`, `helperActivityTarget`, `helperActivitySummary`)**: `tool.started` resolves target titles at query time from structured metadata without ever showing argument previews (deleted scenes or hidden resources show tool kind only); helper activity grouping (React-free) pairs by call ID and folds consecutive read/list/search/check calls while keeping mutating calls and failed reads separate. Running copy comes from `helperActivitySummary`, `helperCalls` counts across the whole task separately from the 80-record query window (`activityLimit`), and `provider.retry` emits pre-wait without error fields and turns historical on the next record (`tests/helper-workspace.test.ts`). Successful helper tasks compact large tool results/receipts while failed tasks keep retry payloads and retired hypothetical scenes remain read/copy-only; refresh queries only event kinds and sequence numbers without tool bodies, and summary checkpoints keep stored message provenance without cleared tool-payload hash lists.
- **Stream vs. final-message ordering**: stream completion and final-message fetch may arrive out of order; the browser retains displayed streamed output until the final message loads rather than permanently storing server chunks.

### Execution and browser boundaries

- The run executor owns prose preparation, model invocation, judgment, atomic commit, and termination while the app router wires HTTP routes and follow-up jobs; illustration and auxiliary job queues remain separate.
- Queued inputs stay separated from in-flight execution inputs, and native preparation, lore selection, context preparation, and prompt compilation sequentially update the same execution input.
- When a subscriber's send buffer fills, only that subscriber pauses until `drain`, advancing cursors for already-accepted pages so chunks never resend without blocking other subscribers or model execution.
- `evictHelperViews` retains the active helper conversation and the 4 most recent in memory without truncating expanded messages in the active conversation, re-fetching evicted ones on demand, cleaning cursors and request IDs together, and discarding late responses.

## Generation, queued next request and automatic refusal retry

- **Tab-local next-request queueing (`queueRequest`, `sendQueuedRequest`, `generate`)**:
  - Enforces `one_active_run_per_chat` via a single tab-local reservation rather than a server queue, never pre-claiming or reordering server runs or one-shot `chat_option_pending` reservations.
  - Auto-dispatch uses the normal `generate` send path and idempotency key so uncertain intakes hand off to **이전 요청 확인** (Check previous request), Reader follows new prose, and refreshes or other tabs never double-send.
  - User-visible auto-dispatch preconditions, compared revisions, hidden-tab deferral, Codex check failure fallback, navigation/reload cancellation, lore-reset travel, and text-only/no-reference-image rules live in [실행 중 다음 요청 예약](../GENERATION.md#실행-중-다음-요청-예약) (`tests/composer-next-request-browser.spec.ts`).
- **Automatic refusal retry (`finishRefusalWithAutomaticRetry`, `automaticRefusalRetryDepth`, `retryRun`)**:
  - Reuses the manual **다시 시도** (Retry) `retryRun` path creating a normal run whose `retryOf` points to the prior run, preserving `one_active_run_per_chat`, idempotency keys, revision checks, independent `maxCalls`/usage per attempt, and immutability of the refused run.
  - `automaticRefusalRetryDepth` walks `retryOf` counting `auto-refusal-retry:<거절된 실행 ID>` keys so manual retries reset depth to `0`; at `autoRefusalRetryLimit`, the last refused run remains terminal awaiting manual retry.
  - Never triggers on user cancellation, server shutdown/maintenance, auth/connection failures, unknown-outcome errors, call-limit or context-limit exhaustion, judgment failures, refusal of a judgment-only retry, or when the story progressed or scenes were deleted.
  - `finishRefusalWithAutomaticRetry` commits the refusal record and follow-up run intake in one SQLite transaction (unique key per refused run prevents duplicate intake; shutdown before start ends the follow-up as `interrupted`) and suppresses failure push notifications while a retry queues, emitting them only on terminal refusal (`tests/run-auto-refusal-retry.test.ts`).

## Context limits, compaction and request measurement

- **Call limits, token bounds, and defaults**:
  - Input token bounds are governed by `DEFAULT_INPUT_TOKEN_LIMIT`, `MIN_INPUT_TOKEN_LIMIT`, and `MAX_INPUT_TOKEN_LIMIT`; per-chat call limits (**채팅 설정 → 생성 설정 → 고급 실행 설정 → 작업당 모델 호출 한도**) enforce `MAX_MAIN_MODEL_CALLS` (1–128) shared across lookups and context summaries, while helper tasks enforce fixed internal `HELPER_TASK_LIMITS` and `HELPER_TOOL_CALL_LIMIT` with no per-conversation editing.
  - On the last allowed call, `finalCall` instructs the model to summarize completed, saved, uncertain, and remaining work without tools; requesting a tool on `finalCall` skips execution and fails the task for budget exhaustion.
  - Already-queued tasks keep frozen call limits; because native Codex internal model calls are unobservable, call limits are not cost caps and stay distinct from token limits.
  - `saveChatGenerationDefaults` (`PUT` `/api/chat-generation-defaults`) stores defaults in `app_metadata`, preserves `autoRefusalRetryEnabled` and `autoRefusalMaxRetries` when omitted from `PUT`, and returns 409 on `expectedRevision` CAS mismatch.
- **In-run tool compaction and reference placement**:
  - Right before each follow-up model call after reads such as `story.read`, `runMain` re-estimates the actual outgoing body via `measureProviderRequest`; when input exceeds `CONTEXT_COMPACTION_TRIGGER_RATIO` (0.85) with compactable successful reads (`compactableRead`), `compactToolReads` summarizes them with the queue-time context model (automatic for main runs except evaluation-tool runs).
  - Structured requests assemble completed tool records first and finalize dynamic references via `withNativeHostContext` into a separate `user`-role message (`native.host-context`) rather than `system`/`instructions`, preserving authored preset roles and order without encoder patching. The text is regenerated from the frozen snapshot for every request, so the copy a compiled snapshot stores marks only the message's position: `attachMainHostContext` accepts a stored copy written by an earlier build, and a run frozen before an upgrade sends the running build's host context with that build's tool list. A message under the reserved id with another block, origin, role or shape is a collision (`NATIVE_HOST_CONTEXT_COLLISION`). Anthropic Batch recovery is stricter: it compares the whole transmitted body (`ANTHROPIC_BATCH_RECOVERY_MISMATCH`), so a Batch run resumed after any change to request building still fails. Codex omits only identical host reference messages already sent in JSON `input` while keeping the current request, original prompt, and completion receipts.
  - `CONTEXT_SUMMARY_SEMANTICS` and `contextSummaryPolicy` share preservation rules across automatic conversation summaries, in-run read summaries, and helper summaries—never turning lack of confirmation into confirmed failure or non-fulfillment—without merging executors or storage scopes.
- **Context projections and dependency tracking**:
  - Helper `context.read` and UI context details share the same current summary, source provenance, valid notes, and usability projection (`usable: false` with reason on mismatch); only the UI adds compact status for the 10 most recent compaction jobs, and no path fetches and discards full completed inputs or historical checkpoint bodies.
  - `contextDependencyKey` computes reuse from the actual writing program, effective values, resources, corrections, and native history—changes solely to defaults revisions or helper/translation models never invalidate main summaries (`tests/context-checkpoint-storage.test.ts`, `tests/helper-context-read.test.ts`).
- **Next request preview (`inspectNextRequest`)**:
  - **다음 요청 미리보기** (`POST /api/chats/:id/request-preview`) runs a read-only projection through `buildMainProviderRequest` and `measureProviderRequest` with zero DB mutations and zero provider/callback calls, accepting image metadata (`name`, `width`, `height`) without uploading bytes and never exposing source text, prompt bodies, connection URLs, or credentials.
  - If chat head, settings, profile, workspace, notes, active context revision, story-UI themes, source hashes, attached content revisions, or selected model/connection/pinned-prompt revisions change during lookup, `inspectNextRequest` sets `snapshot.stale` to `true` and appends the `SNAPSHOT_CHANGED` caveat.
- **Estimation variance and Gemini signature exclusion**:
  - Local JSON token counts (`CONTEXT_ESTIMATOR` / `o200k_base-v1`, `MODEL_CONTEXT_ESTIMATOR`) remain estimates rather than upper-bound guarantees due to tokenizer generations, internal provider formats, chunk-boundary differences, and fresh per-run IDs/hashes. In an observed `o200k_base-v1` case, identical 15,887 UTF-16 code-unit bodies spanned 6,943–7,011 tokens (~1%); synthetic tests keep fixtures outside 1% of the 85% (`CONTEXT_COMPACTION_TRIGGER_RATIO`) and 75% boundaries.
  - Gemini-family echoed `thoughtSignature` values and reasoning bodies are excluded from input estimation because providers do not tokenize opaque signatures character-by-character and tokenizing them inflates estimates across tool calls, causing unnecessary compaction. In production logs, an estimate including signatures reached 258,852 when provider-reported input was 92,495, whereas excluding signatures yielded 0.88–1.22x of actual input (medians by call-order bucket) across 1,146 Vertex helper calls.
  - Compaction checks (`measureProviderRequest`), Vertex pre-send limit checks, and attempt-recorded estimates all share this rule (`tests/helper-compaction.test.ts`, `tests/vertex-transport.test.ts`).
- Cross-cutting regression coverage: `tests/context-integration.test.ts` (races, cancellation, attribution, retention) and `tests/helper-compaction.test.ts` (staged EOF).

## Custom agent collaboration

### Call and storage contract

- **Validation and disabled drafts (`validateRisuPrompt`, `validateAgentCollaboration`)**: `RisuPrompt.collaboration` saves inside prompt presets under `expectedRevision` CAS. Schema shape and duplicate-ID checks always run; while `enabled` is `false`, empty titles, empty instructions, unset call limits, and deleted `sharedControls` remain saveable so other prompt edits succeed, re-enabling validates required fields, controls, and limits, and stale prose undo never erases separate collaboration edits.
- **Snapshotting and attempt attribution**: queue-time snapshots freeze collaborator models in `ProfileSnapshot.collaborationModels` so mid-run edits apply on the next Run. Each invocation verifies the live connection at start, logs an attempt pre-send, and reuses `role: 'main'` transport tagged with host-only `agentId` (never sent to providers or read from model output).
- **Shared call budgets**: all collaborator calls count toward `settings.maxCalls` alongside summaries and main calls; overall and per-agent caps sum host requests across pre-writing, follow-up, and lookup rounds while reserving 1 call for the main writer's next call—except consultations from an active Codex native writer, which return in-turn without reserving a next call. New questions never reset limits, recoverable lookup errors may correct within the same budget/timeout, and enabling collaboration always adds tool descriptions and `sharedInstructions` to main input.
- **Output, timeout, and legacy fields**: per-model `maxOutputTokens`, input limits, and shared-per-consultation timeouts apply without a separate opinion character limit; legacy `maxOutputChars` in old presets or backups is ignored and stripped on save (`validateAgentCollaboration`), while historical `truncated` flags on past consultation receipts remain readable.
- **Failure, cancellation, and sequential pre-writing**: failures, refusals, partial responses, and uncertain disconnects return as `unavailable` without auto-retry (retaining spent calls, usage, and `null` actual cost), cancellation stops collaborators and main together, and restarts or restores never auto-replay uncertain executions. Pre-writing consultations stay sequential in registration order because collaborators share a call budget and log attempts/usage right before sending—parallel execution is not added without a separate budget-reservation contract.
- **Trace records and boundaries**: `agents.consult`, `agents.read`, `agentId`-tagged inputs, and `consultationContext` are in-run records not permanently archived; independent chat backups exclude collaborator traces, only main commits prose, and collaborator reads never auto-promote to retained lore.
- **Persistence, restore, and deletion**: stored in existing JSON fields with no dedicated collaboration DB table (see [data formats](../DATA-MIGRATIONS.md)); restore checks attribution, strips credential references, and disables providers, and deleting a dedicated collaborator model in the active workspace disables collaboration and clears its binding while keeping historical snapshots (see [item deletion](../DELETION.md)).

## Scene illustrations

### Job queue and concurrency control

- **Job pump structure**: `pumpIllustrations` runs 1 `text` job and 1 `render` job concurrently without locking main-writing slots or composer state; renders proceed sequentially starting with a plan's representative cut.
- **Deduplication locks and limits**: only 1 planning job may run per response (`ILLUSTRATION_PLAN_ACTIVE`), while distinct cuts queue independently and same-cut duplicates reject (`ILLUSTRATION_ACTIVE`); per-source cut counts and automatic retries cap at `ILLUSTRATION_MAX_PER_SOURCE` and `ILLUSTRATION_MAX_AUTO_RETRIES`.
- **State machine**: `queued → running → completed | failed | cancelled | interrupted`. User cancellation bumps `generation` so late results discard; restarts mark running jobs `interrupted` without auto-retrying while `queued` jobs resume, and `illustration_jobs.input.task` partitions into `plan`, `render`, and `placement`.

### Database schema and metadata

- **Preset persistence**: preset entities live as `illustration-preset` rows in shared `versions` (bounded by `ILLUSTRATION_WORKFLOW_MAX_CHARS` and `ILLUSTRATION_PRESET_FILE_MAX_BYTES`), and scoped selection state lives in `app_metadata` under `illustration-preset-preferences` (see [Data formats](../DATA-MIGRATIONS.md)).
- **Presentation ownership**: `illustration-presentation:<sourceId>` (`illustrationPresentationKey`) in `app_metadata` owns the representative target, per-cut latest requested/displayed job IDs, translation text hash, and placement mapping, strictly separating execution inputs from UI display selections so late older completions never overwrite newer selections.
- **Source revision attribution**: jobs bind to `source_revision` and queue-time `source_hash` and re-fetch via `sourceAtHash` at execution time so later source edits leave completed cuts bound as **수정 전 원문의 삽화** (Illustration for pre-edit source).
- **Reader communication**: `GET /api/chats/:id/reader` returns current-scene `illustrations`, SSE events `illustration.*` and `illustration-layout.updated` scope to that scene only, and `reader.activity` tags them `kind: 'illustration'` isolated from main `activeJobs`.

### Tool and context contracts

- **Prompt-model read tools (`ILLUSTRATION_RESEARCH_TOOLS`)**: exposes read-only `illustration.sources.search` and `illustration.sources.read` across pinned character cards, personas, CHARX descriptions/lorebooks, and captions/prompts of earlier successful illustrations; no write tools exist and placement jobs omit these tools. The catalog carries the full bot and persona descriptions inline when they fit `KNOWLEDGE_ITEM_TOKENS`, the size of one default `knowledge.read` page, so the usual appearance check needs no read round; longer fields and modules list their paths and lengths so one read can fetch them without a field-listing round. A prompt request makes at most the chat's `settings.maxCalls` model calls, the per-task budget auxiliary jobs already use; a model still calling tools at that point fails with `ILLUSTRATION_PROMPT_CALL_BUDGET_EXHAUSTED` before the pending reads run.
- **Consistency guide (`visualCanon`)**: planning optionally emits `visualCanon: [{name, appearance}]`, which deterministically appends into non-NovelAI cut prompts so cuts for the same response share character identity.
- **Input token budgets**: planning inspects the full response and fails immediately on context-budget overflow; per-cut rendering and placement combine pinned focus/brief with tail excerpts capped by `ILLUSTRATION_EXCERPT_TOKENS` (2,000 estimated tokens for `target`).

### Image processing and storage

- All generated outputs validate through a real image decoder within `ILLUSTRATION_MAX_IMAGE_BYTES` (64MiB), convert to WebP in shared `image_blobs`, and serve from `/api/illustration-images/:id`.
- `resizeIllustrationReference` downscales Codex reference images to at most 1536px on the long edge without upscaling or cropping while leaving stored originals immutable.
- Independent chat copies and backups restore only currently displayed successful results, same-cut variant groups, representative designations, and verifiable source/translation anchors (mismatches move to the auxiliary area; unfinished jobs and failure logs are excluded).

### Codex path technical contract

- **Turn separation**: planning, placement, and ComfyUI prompt-authoring turns use `CODEX_ILLUSTRATION_TEXT_CONFIG` (web search, code mode, and `features.image_generation=false`), whereas Codex image turns use `CODEX_ILLUSTRATION_CONFIG` (`features.image_generation=true`, web search and code mode disabled).
- **Prompt refinement**: `refinePrompt` freezes at queue time and reuses on retries, refining instructions and caption inside the image turn (falling back to draft caption if omitted).
- **Session and slot boundaries**: consecutive cuts from one plan reuse one `CodexRuntime.createSession` process and ephemeral thread with a separate `turn/start` per cut (see [Codex execution boundaries](../CODEX.md)); image turns use isolated `imageSlots` (1 concurrent, 8 queued) and log under `role: 'illustration'`.
- **Result ingestion and failure codes**: reads `item/completed` `imageGeneration` base64 `result` first and falls back to reading and deleting `savedPath` inside the dedicated directory; `CODEX_IMAGE_USAGE_LIMIT` and `CODEX_IMAGE_UNAVAILABLE` never auto-retry, while `CODEX_IMAGE_NOT_GENERATED` is retryable.

### Using the judgment model for translation placement

- `judgeIllustrationPlacement` tries the [judgment provider](../PROVIDERS.md#판단-프로바이더) first, supplying all translated paragraphs once with one multiple-choice question per cut (`none` stores no placement) and attributing usage to `illustration-placement`.
- **Pre-dispatch fallback vs. post-dispatch failure**: missing judgment key/connection, token-limit overflow, or translated paragraphs exceeding `limits.maxOptions` (255 including `none`) fall back before dispatch to the prompt model or Codex text turn. HTTP, timeout, or format errors after dispatch fail the job without falling back (retryable via **번역 위치 다시 연결**); real judgment accuracy is outside synthetic test scope.

### Pre-judgment for Codex image requests

- `checkCodexIllustrationContent` pre-checks the exact text sent to the Codex image turn (prompt-model prompt plus reference labels, even with `refinePrompt` enabled) via the judgment provider using the `noul` metric at `CODEX_CONTENT_WARNING_THRESHOLD` (0.9).
- Scores ≥ 0.9 block dispatch as `ILLUSTRATION_CODEX_CONTENT_BLOCKED`, preventing both automatic retry and identical-input manual retry without affecting other cuts, main/translation jobs, or existing images.
- Missing judgment key, response errors, 8-second timeout, or input token overflow record `unavailable` and proceed (leaving moderation to the provider); judgment calls attribute to `illustration-content`.

### ComfyUI path technical contract

- Planning → single-pass substitution of `{{prompt}}`, `{{negative}}`, and `{{seed}}` inside `inputs` strings (API format `노드 ID → {class_type, inputs}` only; UI format `nodes`/`links` rejects with `COMFYUI_WORKFLOW_UI_FORMAT`) → `POST /prompt` → poll `GET /history/{prompt_id}` → `GET /view`.
- `validateComfyBaseUrl` permits only `http://` and `https://` URLs with no embedded credentials or query strings; optional **인증 헤더 환경변수** (Auth header environment variable) is read server-side into `Authorization` so browsers never contact ComfyUI directly.
- Request timeouts (`COMFYUI_TIMEOUT`) preserve `prompt_id` without aborting remote rendering so **결과 확인** (Check result) (`reconcileIllustrationJob`) can fetch completed remote outputs later.
- `cancelComfyUIPrompt` calls `POST /api/jobs/{prompt_id}/cancel` only on explicit user cancellation, falling back only to `POST /queue` `{delete: [id]}`—global `/interrupt` is never called.
- Diagnostic codes: `COMFYUI_PROMPT_REJECTED`, `COMFYUI_EXECUTION_FAILED`, `COMFYUI_SUBMISSION_UNCERTAIN` (no auto-resubmission), and `COMFYUI_RESULT_UNAVAILABLE`.

### NovelAI path technical contract

- **V4.5 character-reference gate**: `novelAISupportsCharacterReference` is the single-source V4.5-only Precise Reference support gate (`NOVELAI_REFERENCE_ANLAS` = 5 Anlas per reference) shared between settings UI and runtime.
- **Request (`novelAIImageRequest`)**: one `POST https://image.novelai.net/ai/generate-image` per cut with scene prompt in `v4_prompt.caption.base_caption` and negative prompt in both `negative_prompt` and `v4_negative_prompt.caption.base_caption`; authenticates via `Authorization: Bearer <Persistent API 토큰>` (Persistent API token) and refuses redirects.
- **Character references (`novelAIReferenceImage`)**: each selected reference letterboxes with black padding onto whichever PNG canvas of 1024×1536, 1536×1024, or 1472×1472 best matches its aspect ratio in `director_reference_images` (caption `character`, info extraction 1, strength 0.6, secondary strength 0—matching Asset Made defaults, non-editable in UI); unselected or out-of-range indices are omitted and sent count logs under `novelai.references`.
- **Per-character captions and 5×5 grid**: `characters` map in order to `char_captions` of `v4_prompt` and `v4_negative_prompt`, capped at `NOVELAI_MAX_CHARACTERS` (6, V4/V4.5 limit, dropping overflow from the end); `use_coords` enables only when all characters have positions (partial positions clear all for auto-placement). Coordinates clamp to 0.1–0.9, snapping to the 5×5 grid (0.1, 0.3, 0.5, 0.7, 0.9) on V4/V4.5 models and 0.01 increments on V5.
- **`visualCanon` omission reason**: unlike other generators, the illustration runner supplies `visualCanon` only as prompt-model input and never appends it to the NovelAI scene prompt, preventing per-character traits from bleeding onto other characters.
- **Response and failure codes**: validates the first image inside the ZIP (or raw image body) by real image signature into shared WebP storage, logging `novelai.seed`, and stores only HTTP status plus ≤300 chars of NovelAI's message across `NOVELAI_TOKEN_MISSING`, `NOVELAI_UNAUTHORIZED`, `NOVELAI_ANLAS_INSUFFICIENT`, `NOVELAI_BUSY`, `NOVELAI_REQUEST_REJECTED`, `NOVELAI_UNREACHABLE`, `NOVELAI_RESULT_UNCERTAIN`, `NOVELAI_RESPONSE_INVALID`, and `NOVELAI_IMAGE_INVALID`.
- **Uncertain results and pre-judgment**: NovelAI returns no job ID so remote reconciliation is unavailable; manual **다시 요청** (Request again) is permitted after uncertain failures reusing the saved prompt, cancellation drops the HTTP connection while remote generation may finish, and Codex explicit-content pre-judgment does not apply.

## Input translation

### Implementation boundaries

- `inputTranslationRoutes` (`POST /api/chats/:id/input-translation`, context cap `INPUT_TRANSLATION_CONTEXT_TOKENS`) executes a single provider call via shared adapters and auth without creating prose, sources, or jobs and without writing drafts or input-translation payloads to SQLite.
- Temporary original text stores in `sessionStorage` under `input-translation:<기존 draft 키>` (existing draft key), and target language persists in `localStorage` under `uimori:input-translation-language`; when browser storage is restricted, original text exists only in active editor memory, and provider-side retention is independent of app temporary storage.
- Composer view/draft revision checks guard against stale results and coordinate with send-acceptance boundaries without changing request record schemas; saved-request clipboard copying stays decoupled from display strings.

### Verification

- `npm run verify:input-translation` plus cross-cutting suites `tests/request-edit.test.ts` and `tests/api-errors.test.ts` cover model/preset isolation, zero DB mutation on success or failure, truncated-output rejection, shutdown cancellation, temporary-original recovery, stale results, send uncertainty, final-only text retention, and clipboard copy using a temporary DB, synthetic responses, and local browser.

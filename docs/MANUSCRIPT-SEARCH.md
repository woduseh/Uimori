# 원고 검색

사이드바 **채팅 검색**, 봇의 채팅 검색, **장면 목록 → 본문·번역 검색**에서 같은 검색기를 사용해요. 전체 작업실·봇·현재 채팅 범위를 고르고 원문·번역·요청을 선택해요. 제목 결과도 유지하며 본문 결과는 장면 단위로 묶어요. 제목 일치 건수는 전체를 표시하고 30개씩 더 볼 수 있어요. 봇 범위의 제목 결과에는 채팅 폴더를, 전체 범위에는 봇 이름을 표시해요. 각 결과의 `원문/번역 장면 열기`는 해당 저장된 장면과 보기 모드로 이동하고 새 번역이나 모델 요청을 만들지 않아요.

공백으로 구분한 단어는 같은 문서 안에서 모두 찾고 `"붉은 우산"`은 연속 문구로 찾아요. NFC 정규화와 소문자 비교를 사용해요. `%`, `_`, SQL·FTS 연산자처럼 보이는 문구도 일반 문자열이에요. 한국어·일본어 1~2글자 이름도 지원해요. 한글 조합 중에는 검색하지 않고 짧은 입력은 Enter/검색으로 실행해요. 나머지 입력은 300ms 후 조회하며 이전 요청은 취소해요.

현재 수정본 원문, 현재 원문 hash에 맞는 완료된 번역(재번역 중·실패 시 직전 성공본), 저장된 요청만 대상으로 해요. 과거 수정본·미완성 생성·요약·모델 로그는 제외해요. 봇 Lua·JavaScript·표시 정규식을 실행해서 색인하지 않아요. 저장된 Markdown/HTML의 정적인 평문을 사용하며 script/style과 코드형 프로그램 블록은 제외해요. 동적 Risu UI가 만든 문구까지 찾는 기능은 아니에요.

`search_documents`와 FTS5 trigram은 파생 데이터예요. 원문·번역 수정 트랜잭션은 `search_dirty_sources`에 변경을 함께 기록해요. 읽기 Worker가 작은 묶음을 정규화하고 서버가 변경 수정 번호를 비교한 뒤 색인을 반영해요. 한 번의 쓰기는 기존·새 텍스트 합계 약 256KiB 또는 최대 8장면으로 제한해요. 한 장면 자체가 큰 경우 그 한 장면은 처리하되 다른 큰 장면과 합치지 않아요. 전체 색인 완료 시간보다 다른 작업의 응답성을 우선하는 경계예요. **검색은 변경 대기 중인 문서를 같은 SQLite 읽기 트랜잭션의 최신 본문으로 대체**하므로 색인이 늦어도 저장된 수정·삭제가 반영돼요. 재시작 때 전량 재구축하지 않아요.

3글자 이상 용어는 색인으로 후보를 좁혀 문자열을 다시 검사하고, 짧은 용어만 있으면 200장면 이하의 구간을 읽어요. `계속 찾기`는 다음 구간을 검사해요. 미완료 검색을 결과 없음으로 표시하지 않으며 색인 구축 중에는 별도 안내를 보여요. 커서는 검색 조건과 마지막 장면의 순서만 보관해요. 다른 채팅이나 이미 지난 결과의 수정으로 다음 페이지를 무효화하지 않아요. 현재 읽는 페이지는 최신 원고를 검색하고, 이미 지난 범위의 새 일치는 처음부터 다시 검색해 확인해요. 작업실 전체의 단일 시점 스냅샷을 여러 페이지 동안 유지하는 검색은 아니에요.

API: `POST /api/search`의 `{query,scope,chatId?,botId?,kinds,cursor?,limit?}`. 기본 20개, 최대 50개 결과. 응답의 `nextCursor`, `coverage`를 확인해요. 요청은 읽기 전용이며 유지보수 중에도 동작해요. 서버가 정한 DB만 Worker에서 읽고 API는 SQL·파일 경로를 받지 않아요. Worker의 전체 실행 제한과 동시 실행 한도가 있어요. 시간 제한을 넘으면 원고 쓰기는 막지 않고 검색 범위를 줄이도록 안내해요.

`ReaderTarget`은 채팅·장면·원문/번역·hash·선택 문단을 함께 이동시키는 공통 계약이에요. 본문 hash가 바뀌면 잘못된 문단 대신 해당 장면 시작으로 이동해요. 검색문이나 원문 인용은 URL에 넣지 않아요.

검증: `tests/manuscript-search.test.ts`(한/일 짧은 문자열·FTS·문구/기호·수정/번역/삭제·범위·페이지·취소·유지보수), `tests/personal-features-browser.spec.ts`(실제 검색과 장면 이동·작은 화면). 동적 스크립트 표시와 형태소·의미 검색은 지원 범위가 아니에요.

# 원고 검색

사이드바 **채팅 검색**, 봇의 채팅 검색, 원고 읽기 화면의 **장면 목록 → 본문**에서 같은 검색기를 사용해요. 저장된 대화 제목과 본문을 빠르게 찾고, 원하는 장면으로 바로 이동할 수 있어요.

## 검색하기

### 검색 열기와 범위
- **사이드바 채팅 검색**: 사이드바의 **채팅 검색**(또는 **전체 채팅 검색**)은 작업실 전체의 대화와 원고를 검색해요. 검색 범위가 **전체 작업실**로 고정되어 범위 선택창이 생략돼요.
- **봇 메뉴의 채팅 검색**: 봇 목록이나 메뉴의 **이 봇의 채팅 검색**에서는 해당 봇의 대화와 원고를 검색해요. **전체 작업실**이나 **이 봇** 범위를 선택할 수 있어요.
- **장면 목록의 본문 검색**: 원고 읽기 화면의 **장면 목록**에서 **본문** 탭을 선택해 검색해요. 하나의 검색어로 **장면 목록**과 **본문** 대상을 전환하며 검색어를 유지할 수 있어요.
  - **장면 목록** 검색: 장면 번호, 장면 이름, 요청 요약을 찾아요.
  - **본문** 검색: 저장된 원문, 번역, 요청의 본문 내용을 장면별로 찾아요.
- **검색 범위와 대상 선택**:
  - **검색 범위**: **전체 작업실**, **이 봇**, **현재 채팅** 중 하나를 고를 수 있어요 (봇·장면 검색에서 선택 가능).
  - **검색 대상**: **원문**, **번역**, **요청** 중 원하는 대상을 하나 이상 선택해요.

### 검색 결과 확인과 장면 이동
- **채팅 제목 일치 결과**:
  - 검색어와 일치하는 채팅 제목을 상단 별도 영역에 표시해요.
  - 일치하는 제목 건수는 전체를 표시해요.
  - 검색어를 입력한 상태에서는 일치하는 채팅 제목을 처음 5개 표시하고, 이후 5개씩 더 볼 수 있어요.
  - 검색어 없이 제목을 둘러볼 때는 30개씩 표시해요.
  - 봇 범위에서는 채팅이 속한 폴더 이름을 표시하고, 전체 범위에서는 소속 봇 이름을 표시해요.
- **본문 검색 결과**:
  - 본문 검색 결과는 장면 단위로 묶어서 별도 영역에 표시해요.
  - 채팅 제목, 장면 번호와 함께 일치한 본문의 앞뒤 문맥(스니펫)과 강조 표시를 보여줘요.
- **장면으로 바로 이동**:
  - 결과 항목의 **원문 장면 열기**, **번역 장면 열기**, **요청 장면 열기**를 누르면 해당 저장된 장면과 보기 모드로 이동해요.
  - 이동 시 새로운 번역이나 모델 요청을 만들지 않고, 이미 저장된 본문과 보기 모드를 그대로 열어줘요.

### 검색 대상과 제외 범위
- **검색 대상**:
  - 현재 수정본 원문
  - 현재 원문 해시(hash)에 맞는 완료된 번역 (재번역 중이거나 실패한 경우 직전 성공본)
  - 저장된 요청
- **검색 제외 대상**:
  - 과거 수정본, 미완성 생성물, 요약, 모델 로그
  - 봇의 Lua, JavaScript, 표시 정규식 실행 결과
  - `<script>`, `<style>` 태그 및 프로그램 코드 블록(`javascript`, `lua`, `css`, `html` 등)
  - 동적 Risu UI가 만든 문구 (저장된 Markdown/HTML의 정적인 평문만 사용해요)

## 검색 규칙
- **단어 조합 (AND 검색)**: 공백으로 구분한 단어는 같은 문서 안에서 모두 찾아요.
- **연속 문구 검색**: `"붉은 우산"`처럼 큰따옴표로 감싸면 연속 문구로 찾아요.
- **대소문자와 정규화**: NFC 정규화와 소문자 비교를 사용해요.
- **특수문자와 기호**: `%`, `_` 같은 기호나 SQL·FTS 연산자처럼 보이는 문구도 일반 문자열로 검색해요.
- **짧은 이름 지원**: 한국어와 일본어의 1~2글자 이름도 검색할 수 있어요.
- **입력과 자동 검색**:
  - 한글 조합 중에는 검색을 실행하지 않아요.
  - 1~2글자의 짧은 입력은 Enter 키를 누르거나 **검색** 버튼을 눌러 직접 실행해요.
  - 3글자 이상의 일반 입력은 입력을 멈추고 300ms 뒤에 자동으로 조회하며, 이전 요청은 취소해요.

## 구현 참고

### 색인 구조와 변경 추적 (FTS5 trigram)
- **파생 데이터**: `search_documents` 테이블과 SQLite FTS5 trigram 가상 테이블(`search_fts`)은 원본 데이터에서 파생된 데이터예요. 앱 재시작 때 전량을 재구축하지 않아요.
- **변경 추적과 정규화**: 원문·번역 수정 트랜잭션은 `search_dirty_sources` 테이블에 변경 사항(장면 ID 및 revision)만 함께 기록해요.
- **Worker 배치 처리**: 읽기 Worker가 작은 묶음을 정규화하고, 메인 서버가 수정 번호를 비교한 뒤 색인에 반영해요.
- **쓰기 제한**: 한 번의 색인 쓰기는 기존·새 텍스트 합계 약 256KiB 또는 최대 8장면으로 제한해요. 한 장면 자체가 큰 경우 그 한 장면은 단독으로 처리하되 다른 큰 장면과 합치지 않아요. 전체 색인 완료 시간보다 다른 작업의 응답성을 우선하는 경계예요.
- **최신 본문 대체 (Overlay)**: **검색은 변경 대기 중인 문서를 같은 SQLite 읽기 트랜잭션의 최신 본문으로 대체**해요. 색인이 늦어져도 방금 저장된 수정과 삭제가 즉시 검색에 반영돼요.

### 검색 쿼리와 구간 탐색
- **후보 추출과 검사**: 3글자 이상 용어는 색인으로 후보를 좁혀 문자열을 다시 검사하고, 짧은 용어만 있으면 200장면 이하의 구간을 순차적으로 읽어요.
- **남은 원고 검색**: 한 구간에서 완료되지 않은 검색은 결과 하단의 **남은 원고 검색**(`계속 찾기`)으로 다음 구간을 검사해요.
- **상태 안내**: 미완료 검색을 결과 없음으로 표시하지 않으며, 백그라운드 색인 구축 중에는 안내 문구(`coverage: 'building'`)를 보여줘요.
- **커서(Cursor) 안정성**: 커서는 검색 조건과 마지막 장면의 순서 번호만 보관해요. 다른 채팅이나 이미 지난 결과의 수정으로 다음 페이지 조회를 무효화하지 않아요.
- **스냅샷 범위**: 현재 읽는 페이지는 최신 원고를 검색해요. 이미 지난 범위의 새 일치는 처음부터 다시 검색해 확인해야 해요. 작업실 전체의 단일 시점 스냅샷을 여러 페이지 동안 유지하는 검색은 아니에요.

### API 규약과 ReaderTarget 계약
- **API 규약**:
  - `POST /api/search`
  - 요청 페이로드: `{ query, scope, chatId?, botId?, kinds, cursor?, limit? }`
    - 기본 20개, 최대 50개 결과.
  - 응답 페이로드: `{ items, nextCursor, coverage }`
  - 요청은 읽기 전용(`PRAGMA query_only=ON`)이며 유지보수 중에도 동작해요. 서버가 정한 DB만 Worker에서 읽고 API는 SQL이나 파일 경로를 받지 않아요.
  - Worker의 전체 실행 제한(8초 타임아웃)과 동시 실행 한도(최대 4개)가 있어요. 시간 제한을 넘으면 원고 쓰기는 막지 않고 검색 범위를 줄이도록 안내해요.
- **위치 이동 계약 (`ReaderTarget`)**:
  - `ReaderTarget`은 채팅·장면·원문/번역·hash·선택 문단을 함께 이동시키는 공통 계약이에요.
  - 본문 hash가 바뀌면 잘못된 문단 대신 해당 장면 시작으로 이동해요.
  - 검색문이나 원문 인용은 URL에 넣지 않아요.
- **검증 테스트**:
  - `tests/manuscript-search.test.ts`: 한국어·일본어 짧은 문자열, FTS, 문구·기호, 수정·번역·삭제 즉시 반영, 범위 격리, 페이지네이션, 검색 취소, 유지보수 모드.
  - `tests/personal-features-browser.spec.ts`: 실제 검색과 장면 이동, 작은 화면 레이아웃.
  - 동적 스크립트 표시와 형태소·의미 검색은 지원 범위가 아니에요.

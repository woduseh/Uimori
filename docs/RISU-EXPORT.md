# Risu 자료 내보내기

서재에 저장된 봇, 페르소나, 모듈, 프리셋을 RisuAI 호환 규격으로 내보내는 방법과 지원 범위, 주의사항을 안내해요.

## 내보내기 형식과 기본 원칙

- **자료별 파일 형식**:
  - **봇·페르소나**: `.charx` 파일로 내보내요.
  - **독립 모듈**: `.risum` 파일로 내보내요.
  - **프롬프트 프리셋**: `.risup` 파일로 내보내요.
- **최신 저장본 기준 내보내기**: 내보내기는 현재 Uimori에 저장되어 있는 Risu 원문과 이미지 연결 상태를 읽어서 새로 패키징해요. 최초 가져오기 당시의 원본 파일을 그대로 내려주는 기능이 아니므로, 편집 중인 변경사항이 있다면 먼저 저장해 주세요.
- **모듈 분류 카드**: 카드를 모듈 단위로 분류해 사용하고 있다면 카드 설정을 온전히 보존할 수 있도록 CHARX 형식으로 내보내요. 독립 Risu 모듈을 RISUM으로 내보낼 때는 원본의 네임스페이스, 토글, 권한 설정과 이미지를 유지해요.
- **단일 자료 내보내기 원칙**: Risu 내보내기는 **선택한 자료 하나만** 내보내요. 자료 자체에 내장된 원본 카드나 내장 모듈(`module.risum`)은 유지하지만, Uimori에서 별도로 연결한 모듈이나 그 의존 자료를 하나의 카드로 합치지는 않아요. 연결 모듈이 있는 자료는 내보내기 버튼 옆에 해당 범위가 표시되며, 연결 자료는 각각 따로 내보내거나 연결 관계와 이미지를 통째로 보존하는 [개별 백업](NATIVE-TRANSFER.md)을 사용해 주세요. 저장된 원본과 연결 모듈 데이터는 내보내기로 인해 바뀌지 않아요.

## 포함 및 제외 범위

### 파일에 포함되는 내용
- **CHARX**: 현재 카드 설정, 첫 메시지와 대체 첫 메시지, 예시 대화, 글로벌노트, 로어, CBS, 정규식, Lua 스크립트·트리거, 배경 HTML, 기본 변수 및 알 수 없는 카드 확장 필드를 보존해요. 가져온 내장 모듈은 `module.risum`으로 다시 기록해요.
- **에셋 이미지**: 이미지의 현재 blob을 넣고 기존 에셋 이름과 URI를 유지해요. 새로 추가한 이미지에는 이식 가능한 ZIP 경로를 부여하고, 대표 이미지 선택을 `icon/main`에 반영해요. 이미지 내용이나 스크립트를 임의로 실행하지 않으며 외부 URL을 내려받지 않아요.
- **RISUP**: 현재 저장된 `promptTemplate`, 지원하는 `promptSettings`, 토글 정의, 기본 변수, 정규식을 기록해요. 카드의 `post_history_instructions` 글로벌노트와 `promptTemplate`의 활성 블록도 유지해요.

### 제외되는 Uimori 전용 설정
- Uimori의 채팅 대화, 사용자 메모, JEV 설정, 이미지 위임 설정, 협업 설정, 현재 토글 선택 상태는 Risu 자료 형식에 포함되지 않아요.
- 프리셋을 가져올 때 제외되었던 모델, 연결 정보, 인증정보, 생성 설정도 복원하지 않아요.
- 작업실 전체 데이터는 **설정 → 데이터 관리**의 SQLite 백업으로 보존해요. 개별 자료와 채팅 파일은 새 사본으로 가져오며, 구형 전체 JSON 아카이브 복원은 지원하지 않아요.

## 에셋 이미지 편집과 관리

- **이미지 추가**: 에셋 편집에서 이미지를 추가하면 Risu 원문의 에셋 목록과 파일 연결도 함께 갱신해요.
- **이미지 교체**: 기존 파일을 교체하면 에셋 이름, URI, 확장자 별칭, 이미지 식별자를 유지하고 이미지 바이트만 교체해요.
- **이미지 제거**: 제거를 확정하면 해당 이미지와 원문 에셋 목록의 연결을 함께 삭제해요. 단, 본문·로어·HTML·Lua 내부의 참조 문자열까지 자동으로 바꾸지는 않으므로 그 참조는 작가가 직접 확인해야 해요.
- **비이미지 에셋 보존**: 아직 Uimori에서 지원하지 않는 비이미지 에셋은 원문에서 안전하게 유지되며, 이미지 편집 작업으로 인해 삭제되지 않아요.
- **내보내기 차단 조건**: 가져오기 단계에서 지원되지 않아 저장하지 못한 embedded 자산이 있으면 내보내기를 차단해요. 원래 있던 외부 HTTP(S)나 data URI는 그대로 보존하지만 네트워크 요청이나 가용성 확인을 수행하지 않아요. 원본 컨테이너에 있던 임의의 첨부 파일까지 복사하는 범용 백업 기능은 아니에요.

## 구현 참고

- **RISUP 인코딩 규약**: MessagePack → Risu 고정 키 AES-GCM → gzip → RPack 형식으로 기록해요. 이때 사용하는 고정 키는 개인정보 보호용 암호화가 아니에요.
- **필드 폐기 정책**: RisuToki와 동일한 폐기 정책(`core/risu-deprecated-fields.ts`)을 적용해요. 카드 성격·상황·시스템 프롬프트 등 폐기 필드, 모듈 `cjs`, 프리셋의 구형 최상위 프롬프트 필드는 출력하지 않아요.
- **내보내기 API 엔드포인트**:
  - `GET /api/content/:id/risu-export?expectedRevision=N`
  - `GET /api/prompt-presets/:id/risu-export?expectedRevision=N`
  - attachment 응답을 반환하며, UTF-8 파일명, `Cache-Control: no-store`, `X-Uimori-Revision` 헤더를 제공해요.
  - `expectedRevision`이 최신 수정 번호와 다르면 409로 거절하며 숨긴 자료는 404를 반환해요. 예상 수정 번호를 생략한 API 호출은 최신 저장본을 읽어요.
- **용량 및 압축 예산**:
  - CHARX·RISUM 최대 출력: 512 MiB (가져오기와 동일)
  - 카드 및 모듈 JSON 크기: 최대 8 MiB
  - 에셋 개수 한도: 최대 12,288개
  - ZIP 개별 항목 크기: 64 MiB (전체 확장 크기도 가져오기 예산을 준수)
  - 이미지 무압축 로직: 파일 한도에 여유가 있는 자료는 PNG, JPEG, WebP, AVIF, GIF 확장자의 이미지를 재압축하지 않고 원래 바이트 그대로 넣고, JSON과 텍스트는 압축해요. 더 큰 자료는 이미지도 압축해 파일 한도에 맞출 수 있는지 확인해요. 압축률이 너무 높으면 일부 항목만 무압축으로 기록해 다시 가져올 수 있는 크기를 맞춰요. 최종 파일과 확장 예산을 함께 지킬 수 없으면 내보내기를 거절해요.
  - RISUP 처리 예산: 프리셋 가져오기와 동일한 24 MiB 파일 및 원문 처리 예산을 사용해요.
  - 안전성 검사: ZIP 경로 탈출(path traversal), 중복 경로에 다른 데이터가 존재하는 경우, 누락된 이미지 연결이 있는 파일은 내보내기를 거절해요. 내보내기 도중 저장 상태나 가져오기 원본 사본은 수정하지 않아요.
- **관련 코드 및 테스트**:
  - 구현 코드: `server/risu-export.ts`, `server/risu-export-codec.ts`, `core/risu-deprecated-fields.ts`, `core/risu-native-assets.ts`, `web/NativeRisuAssetsEditor.tsx`
  - 테스트 스위트:
    - `tests/risu-export.test.ts`: 저장 후 수정한 자료를 실제 카드·프리셋 importer에 다시 넣어 첫 메시지, 내장 모듈, 이미지, CBS·Lua 원문, 폐기 정책 및 수정 번호 충돌을 검증해요.
    - `tests/risu-native-assets.test.ts`: 에셋 추가·교체·제거 시 식별자와 원문 보존을 검증해요.

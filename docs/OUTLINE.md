# 플롯과 집필

작품 전체의 큰 줄기나 이번 회차의 사건 흐름을 계층형 플롯(Outline)으로 미리 정리하고, 원하는 단위를 골라 본문을 집필하거나 이어 쓰는 작업 공간이에요.

플롯을 사용하지 않는 기존의 자유로운 이어쓰기 방식도 그대로 유지돼요. 계획이 작성되어 있다는 이유만으로 원문을 임의로 자동 생성하거나, 아직 쓰지 않은 미래 사건을 이미 일어난 사실로 기록하지 않아요.

## 화면 구성과 시작하기

### 진입과 작업 환경

- **진입 경로**: 채팅 메뉴의 **계층형 플롯**에서 **플롯과 집필** 화면을 열어요. 데스크톱에서는 채팅 머리글의 **플롯** 버튼이 본문 옆 우측 패널의 플롯 탭을 열고, 탭의 **플롯 크게 보기**가 이 전체 화면으로 넓혀요.
- **시작하기**: 빈 화면에서 **도우미와 플롯 시작**을 누르면 도우미에게 보낼 기본 요청문과 작업 대상을 준비해 줘요. 사용자가 직접 전송하기 전까지는 모델을 호출하지 않아요. 또는 **직접 추가**를 눌러 필요한 회차나 사건을 직접 등록할 수도 있어요.
- **반응형 화면**:
  - **데스크톱**: 플롯 목록, 선택한 항목의 본문, 도우미 대화창을 나란히 열어 두고 작업해요. 본문을 읽으면서 플롯을 보려면 우측 패널의 플롯 탭을 써요. 같은 화면을 한 줄로 좁힌 보기로, 현재 플롯 선택기로 항목을 골라 읽고 편집하며, 본문은 그대로 보이고 스크롤돼요. 플롯 탭에서 집필을 시작하거나 연결된 원문을 열어도 탭은 닫히지 않아요. 크게 본 화면을 닫으면 그 화면을 연 플롯 탭으로 돌아가요.
  - **좁은 화면**: 상단의 현재 플롯 선택기로 작업할 단위를 골라요.
  - **모바일**: 플롯 화면과 도우미 화면을 탭으로 전환하며 이용해요.
  - 화면을 전환하거나 다른 메뉴를 다녀와도 선택한 항목, 펼쳐 둔 목록 상태, 작성 중이던 편집 초안과 본문 읽기 위치를 유지해요.

### 항목 관리와 동기화

- **주요 조작**: 선택한 항목에 대해 **상세화**, **집필하기/이어 쓰기**, **원문과 점검**을 실행할 수 있어요.
- **관리 메뉴**: 이름과 내용 수정, 하위 항목 추가, 유지 조건 설정, 진행 중 지정, 순서 이동, 항목 삭제를 제공해요. 삭제는 확인 창에서 함께 지워질 하위 항목 수를 보여 준 뒤에만 실행되고, 되돌릴 수 없어요.
- **목록의 진행 표시**: 각 항목 옆에 진행 중, 유지 조건, 집필 중, 마지막 집필 실패, 현재 분기의 원문 연결을 표시해요. 주제, 메인 스토리, 큰 사건처럼 직접 집필하지 않는 항목은 바로 아래 회차나 작은 사건 중 현재 분기에 원문이 연결된 수를 `2/5`처럼 보여 줘요.
- **다음 항목**: 선택한 회차나 작은 사건에 원문이 있으면, 같은 수준에서 아직 원문이 없는 다음 항목으로 이동하는 버튼이 나타나요. 이동만 하고 집필을 시작하지는 않아요.
- **동시 편집 충돌 방지**: 다른 화면이나 도우미가 저장한 변경 사항은 작업 상태 갱신, 화면 재진입, 새로고침 시 다시 읽어오며, 편집 중인 사용자의 초안을 덮어쓰지 않아요. 오래된 수정 번호로 저장을 시도하면 충돌 안내와 함께 현재 저장된 내용을 보여줘요.

## 플롯 수준과 작성 방법

다섯 가지 플롯 수준은 `core/outline.ts`의 `OUTLINE_LEVELS`를 사용해요.

| 코드 | 화면 표시 | 작성 내용 안내 | 한 번의 집필 대상 |
| --- | --- | --- | --- |
| `theme` | 작품 방향과 주제 | 작품의 정서와 방향 | 아니요 |
| `mainStory` | 메인 스토리 | 이야기 전체의 흐름 | 아니요 |
| `arc` | 큰 사건 | 주요 전환과 결과 | 아니요 |
| `episode` | 회차 | 이번 회차의 사건과 목적 | 예 |
| `beat` | 작은 사건 | 이어질 행동과 반응 | 예 |

### 계층 구조 규칙

- **자유로운 계층 구성**: 중간 단계를 생략하고 필요한 수준만으로 만들 수 있어요. 예를 들어 `theme → episode → beat`, `episode → beat`, 또는 독립된 `beat`만 등록해도 유효해요.
- **부모-자식 관계**: 부모 항목은 반드시 자식 항목보다 상위 수준이어야 해요. 동일 수준의 중첩, 역순 계층, 자기 참조, 다른 채팅의 항목을 부모로 지정하는 것은 허용되지 않아요. 상위 항목을 강제로 자동 생성하지도 않아요.
- **수준과 상위 변경**: 편집기에서 기존 항목의 수준과 상위 항목도 바꿀 수 있어요. 새 수준은 상위보다 작고 하위보다 커야 하며, 집필 예약이 있는 항목은 집필 단위가 아닌 수준으로 바꿀 수 없어요. 자기 자신이나 자신의 하위 항목은 상위로 고를 수 없어요.

## 편집과 유지할 조건

- **상세화할 때 유지하도록 요청 (`fixed`)**: 도우미에게 상세화나 재구성을 맡길 때 반드시 보존해야 할 창작상의 핵심 조건을 지정해요. 이는 절대적인 편집 잠금이 아니며, 사용자가 명시적으로 수정을 요청하면 도우미나 직접 편집을 통해 언제든 변경할 수 있어요.
- **저장과 삭제 규칙**: 직접 편집과 도우미를 통한 편집은 동일한 저장 규칙을 사용해요. 현재 집필이 진행 중인 단위의 수정이나 중복 실행은 방지되며, 실제 작성된 원문이 연결된 항목이나 그 상위 항목의 삭제는 거절돼요. 계획을 수정하더라도 이미 저장된 원문 텍스트는 바뀌지 않아요.

## 함께 참고할 플롯과 이번 입력 컨텍스트

- **함께 참고할 플롯**: 편집기의 접힌 **함께 참고할 플롯**에서 같은 채팅의 다른 플롯을 이름으로 검색해 최대 40개까지 연결할 수 있어요. 한 회차에서 던진 복선이 먼 회차에서 회수되는 등 유기적인 연결이 필요할 때 활용해요.
- **연결 제한**: 자기 자신, 존재하지 않는 항목, 다른 채팅의 항목, 중복 연결은 거절돼요. 상호 참조는 지원하지만 순환 참조를 재귀적으로 추적하지는 않아요.
- **앞뒤 단위**: 집필 입력에는 같은 상위 아래에서 같은 수준인 직전과 직후 항목(`neighbors`)이 제목과 600자 이내의 내용 발췌로 함께 들어가요. 모델은 직전 항목에서 이어 쓰고, 직후 항목에 계획된 사건이 시작되기 전에 멈춰요. 앞뒤 항목은 집필 대상이 아니에요. 앞뒤 항목을 고쳐도 대기 중인 예약은 취소되지 않고, 실제 Run은 접수 시점의 앞뒤 항목을 고정해요.
- **정보 공개 시점 준수**: 선택된 단위를 집필할 때 모델이 허용된 정보 공개 시점을 따르도록 안내해요. 뒤에서 밝혀져야 할 핵심 반전을 미리 누설하지 않으면서도, 이번 단위에서 공개할 차례가 된 사건은 자연스럽게 드러내도록 유도해요. 함께 참고할 플롯(`related`)은 추가 집필 대상이나 이미 일어난 과거 사실로 취급하지 않아요.

## 진행 중 플롯과 일반 이어쓰기

플롯 화면에서 집필하지 않고 입력창에서 이어 쓰거나 RP를 할 때도 지금 이야기가 플롯의 어디쯤인지 반영할 수 있어요.

- **진행 중 지정**: 채팅마다 항목 하나를 **진행 중**으로 지정해요. 관리 메뉴에서 지정하거나 해제하고, 플롯 화면에서 어떤 단위를 집필하면 그 단위가 자동으로 진행 중이 돼요. 지정된 동안 입력창 위의 다음 요청 상태 줄에 진행 중인 플롯이 표시되며, 눌러서 플롯 화면을 열거나 닫기 버튼으로 해제할 수 있어요.
- **일반 요청에 반영**: 진행 중인 항목이 있으면 일반 본문 요청과 다시 쓰기, 요청 미리보기에 그 항목의 상위 경로, 직계 하위, 관련 계획, 앞뒤 단위가 `outline.focus: true`로 들어가요. 이 항목은 집필 대상이 아니에요. 무엇을 쓸지는 현재 요청이 정하고, 플롯은 속도와 연속성, 계획된 방향을 잡는 데만 쓰여요. 남은 하위 사건을 서둘러 처리하거나 다음 단위로 넘어가지 않도록 안내해요.
- **원문 연결**: 진행 중일 때 완성된 일반 원문은 그 항목에 `focus` 연결로 붙어요. 진척 표시, 원문과 점검, 이후 집필의 이미 쓴 단위 목록에 반영되지만, 장면 이름표는 플롯 이름으로 바뀌지 않고 요청 이름을 유지해요. 원문이 연결된 항목은 다른 원문처럼 삭제할 수 없어요.
- **해제**: 진행 중을 해제하면 일반 요청은 플롯 없이 자유롭게 이어 써요. 진행 중 항목을 삭제해도 함께 해제돼요.

## 집필과 이어 쓰기

### 집필 절차

1. **집필하기/이어 쓰기**: 작성할 단위를 선택하고 버튼을 누르면 플롯 내용 아래에 이번 집필에 반영할 추가 지시나 멈출 지점을 적는 별도 입력창이 열려요. 추가 지시는 비워 두어도 무방해요.
2. **집필 시작**: 버튼을 누르면 실제 본문 생성이 시작돼요. 플롯 선택이나 미리보기만으로는 모델이 실행되지 않아요.
3. **이전 초안 복구**: 이전 방식으로 브라우저에 보관된 요청 초안이 있다면 접힌 **이전 집필 요청**에서 전문을 확인하고 복사할 수 있어요. 새 입력에 임의로 뒤섞지 않아요.

### 다중 원문과 진행 상태

- **여러 원문 연결**: 한 플롯에 여러 원문을 연결할 수 있어요. 이미 작성된 원문이 있는 경우 새로운 요청은 **이어 쓰기**로 준비되며 기존 원문을 참고해요. 자동 연속 집필은 하지 않으며 각 회차의 진행은 사용자가 직접 조절해요.
- **완료 판단 분리**: 원문이 연결되었다고 해서 하위 사건이 자동으로 완료 처리되거나 상위 목표가 모두 달성되었다고 단정하지 않아요. 화면에서는 실제 연결된 원문 수와 하위 항목의 구조적 연결 현황을 분리해서 보여줘요.
- **현재 분기 기준**: 다시 쓰기로 생긴 다른 분기의 원문도 연결은 유지하지만, 원문 수, **집필하기/이어 쓰기** 표시, 연결된 원문 목록, 점검 가능 여부는 현재 읽는 분기의 원문만 기준으로 해요. 다른 분기에만 있는 원문은 수만 따로 표시해요.
- **실패와 취소 표시**: 마지막 집필이 실패했거나 예약이 취소되면, 이미 연결된 원문이 있어도 상태 줄에 따로 표시해요.

## 원문과 점검

- **원문과 점검**: 현재 작성된 플롯과 실제 연결된 원문을 비교하여 설정 불일치, 복선 누락, 캐릭터 행동 일관성을 확인하는 명시적인 읽기 전용 기능이에요.
- **결과 확인과 반영**: 점검 결과와 모델이 실제로 검토한 원문 근거는 도우미 대화와 작업 기록에서 투명하게 확인할 수 있어요. 제안된 내용을 실제로 플롯에 반영하려면 사용자가 새로운 편집 요청으로 지시해요.

## 구현 참고

### 집필 컨텍스트 조립과 파이프라인

- **브리핑 조립 API**: `GET /api/outline-nodes/:id/brief`에서 프로그램이 영속 데이터를 직접 조립해요 (별도 모델 호출 없음).
  - `path`: 존재하는 루트부터 현재 단위까지의 상위 경로
  - `children`: 현재 단위의 직계 하위 플롯 목록
  - `related`: 명시적으로 연결된 관련 플롯 (중복 배제)
  - `neighbors`: 같은 상위 아래 같은 수준의 직전·직후 항목
  - `sources`: 현재 단위 및 그 하위에 연결된 현재 분기 원문의 ID·현재 hash·귀속 항목·연결 종류(`planned`/`focus`), 최근 40개
  - 실제 Run 실행 시에는 Run 계보에 원문이 있는 다른 항목도 `written`으로 최대 40개까지 포함해요.
- **컨텍스트 주입 경로**: `RunSnapshot.outline → MainInput.outline → main-host-context`. 기존 본문 입력 경로를 재사용하며, 이 컨텍스트는 현재 사용자 요청, 실제 원문, 메모, 로어를 대체하지 않고 최종 입력 토큰 예산 검사를 통과해야 해요. 전체 계획을 무조건 삽입하거나 예산을 초과하는 중요 조건을 조용히 누락하지 않아요.
- **장면 예약과 접수**:
  1. `POST /api/outline-nodes/:id/scene-command`로 플롯에 연결된 장면 요청을 생성해요. 별도의 `additionalInstruction`, 대상 수정 번호, 계획 hash를 전달해 변경된 계획에 옛 요청이 잘못 연결되는 것을 막아요.
  2. 기존 `POST /api/scene-commands/:id/run`으로 본문을 예약해요. 별도의 작문 전용 실행기를 두거나 도우미 산출물을 본편으로 자동 승격하지 않아요.
  3. 현재 플롯과 추가 지시는 실제 Run 접수 시 함께 고정되며, 단일 writer, 취소 처리, 원문 저장 경계를 유지해요.
  - 플롯과 별개인 독립 장면 예약의 생성·취소·삭제 API 및 별도 대기열 화면은 제공하지 않아요.

### 예약 취소, 멱등성, 변경 감지

- **미실행 예약 취소**: 아직 실행되지 않은 예약에 포함된 상위 경로, 직계 하위, 명시적 관련 계획이 실질적으로 변경되면 동일 저장 트랜잭션에서 해당 예약을 즉시 취소해요. (단순 형제 노드 변경, 수정 번호만 바뀐 경우, 롤백된 변경은 취소하지 않아요. 이미 접수된 Run은 당시 입력을 유지해요.)
- **진행 중 API**: `GET /api/chats/:id/outline/focus`는 진행 중 항목을 돌려주고, `PUT`에 `{ "nodeId": "..." }` 또는 `{ "nodeId": null }`을 보내 지정하거나 해제해요. 값을 그대로 덮어쓰므로 같은 요청을 반복해도 결과가 같아요. 일반 Run 접수(`run`, `preview-main`)에서 장면 예약이 아닐 때 `freezeOutlineFocus`가 진행 중 항목을 고정하고, 원문 커밋 트랜잭션에서 `linkFocusSource`가 `focus` 연결을 남겨요.
- **멱등키와 복구**: 브라우저는 플롯 저장과 집필의 요청 본문 및 키를 전송 전에 로컬에 보존해요. 통신 응답이 유실되면 **요청 결과 확인**을 통해 동일한 요청의 처리 상태를 조회하며 중복 실행으로 대체하지 않아요. 원래 키는 원래 플롯 및 장면 요청에만 유효하며 다른 대상이나 내용으로 키를 재사용하면 충돌로 처리해요.

### 도우미 도구 계약 (`outline.read`, `outline.write`)

- **`outline.read`**:
  - **모드**: 기본 `overview`, 특정 `nodeId`의 `subtree`, 단일 항목의 `detail`. `overview`는 진행 중 항목의 `focusId`도 알려 줘요.
  - **하위 트리 깊이**: `depth` (0=선택 항목, 1=직계 자식, 생략=전체 자손).
  - **상세 섹션**: `detail`의 `section`은 `intent`, `related`, `writings` (선택 단위와 자손의 실제 본문 참조 목록).
  - **단위와 한도**: 모든 모드는 `offset/limit`을 사용해요. `intent` 조회 시 `limit` 생략 시 로컬 추정 3,000토큰을 반환하고, 명시된 `limit`은 최대 10,000 UTF-16 단위 수로 해석해요. 본문 offset과 반환 좌표는 항상 UTF-16 단위예요. 개요의 `intentCodePoints`는 SQLite Unicode 코드 포인트 수예요.
  - **일관성 검증**: 모든 페이지는 조회 범위의 `version`, 정확한 반환 범위, 재호출용 `nextRead`를 제공해요. 이어 읽기는 `expectedVersion`을 전달하며 플롯이 변경되면 `OUTLINE_CHANGED`와 재조회 경로를 돌려줘요.
  - **적용 범위 지표**: `coverage.wholeField`는 이번 한 응답이 필드 전체를 포함하는지 여부만 나타내요 (예: 전체 841자 중 마지막 600–841 구간은 `wholeField: false`, `nextOffset: null`). `coverage.excludedByDepth`로 깊이 제한에 따라 제외된 항목을 표시해요.
  - **응답 크기 상한**: JSON 메타데이터를 포함해 로컬 추정 12,000토큰 이내로 조립해요.
- **`outline.write`**:
  - 단일 호출에서 `create`, `update`, `move`, `remove`를 최대 200개까지 원자적으로 적용해요. `update`는 `level`도 바꿀 수 있어요. 새 항목의 `ref`/`parentRef`로 계층 구조를 한 번에 생성할 수 있어요.
  - 모델 반환값: 전체 detail 대신 `operationId`, `applied`, `atomic`, `created`, `changes`, `revisionAfterOperation`을 반환해요.
  - 확정 확인: 기존 `task.inspect(kind:"helper")`의 `committedEffects`에서 확정 영수증 ID·시각·도구/호출 ID를 확인할 수 있어요.

### 점검 기술 계약

- **읽기 전용 제한**: **원문과 점검** 요청 시 앱 도구는 `outline.read` 및 기존 본문·로어 읽기로 제한되며 쓰기 도구 실행은 엄격히 거절돼요. 별도의 승인 체계나 전용 점검 에이전트는 두지 않아요.
- **초기 컨텍스트 예산**: 선택한 플롯의 작은 개요, 이어 읽기 경로, 현재 분기에서 가장 최근에 연결된 최대 3개 원문의 짧은 발췌문으로 구성돼요. 현재 분기에 연결된 원문이 없으면 점검을 시작하지 않아요. 초기 원문 발췌에는 입력 예산의 1/8 이내이면서 최대 1,500 추정 토큰을 사용해요. 불완전 제공 시 `partial` 플래그를 표기해요.
- **데이터 보존**: 별도의 영구 점검 테이블을 유지하지 않으며, 점검 결과와 근거는 도우미 대화 이력과 작업 기록에 남아요.

### 데이터베이스 스키마와 데이터 보존

- **테이블 구조**: 플롯과 편집 영수증은 `outline_nodes`와 `outline_batches`에, 관련 플롯 및 원문 연결은 `outline_links`와 `outline_writings`에, 채팅별 진행 중 항목은 `outline_focus`에 저장해요. `outline_writings.origin`은 계획 집필(`planned`)과 진행 중 일반 요청(`focus`)을 구분해요. 기존 `outline_reviews`와 내부 장면 명령 데이터는 보존해요. [데이터 정책](DATA-MIGRATIONS.md)
- **단일 원본 유지**: 플롯과 원문 자체는 단 한 벌만 유지해요. 성공한 실행의 큰 입력 데이터는 수명 정책에 따라 정리하고 필수 메타데이터(수정 번호, hash, source 참조)만 남겨요.
- **복사와 백업**: 독립 사본 및 휴대용 채팅 백업은 플롯 내용, 계층, 순서, 유지 조건, 관련 참조와 진행 중 항목을 새 ID로 재생성해요. 복사 시점 이전의 실제 원문 연결만 연결 종류와 순서를 유지한 채 새 source ID로 매핑하며, 완료된 Run/예약/영수증 및 도우미 점검 작업은 복제하지 않아요.

### 검증과 범위

- **검증 파일**: `tests/outline.test.ts`, `tests/helper-outline.test.ts`, `tests/helper-workspace.test.ts`, `tests/database-schema.test.ts`, 우측 패널의 플롯 탭은 `tests/side-panel-browser.spec.ts`

- **범위 외 사항**: 자동 재계획, 다중 회차 자동 집필, 공유 플롯 템플릿, 그래프 편집기, 신규 기억 추출 시스템은 본 작업실 범위에 포함되지 않아요.

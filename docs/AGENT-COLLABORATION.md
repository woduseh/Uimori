# 메인 작문과 커스텀 에이전트 협업

작문 프롬프트 편집기의 **에이전트 협업**에서 인물·설정과 기억·직접 만들기 템플릿을 추가해요. 이름, 메인이 참고할 역할 설명, 지침, 모델, 참여 시점, 추가 조회 도구와 호출 한도를 편집할 수 있어요. 템플릿은 편집 가능한 시작점이며 특정 프롬프트나 작품을 전제로 하지 않아요.

기본은 꺼짐이에요. 협업을 끄면 저장한 정의는 보관하고 기존 메인 요청 경로를 사용해요. 작문 프리셋을 적용하면 협업 구성도 현재 작문 작업본으로 복사해요. 프리셋의 후속 수정·삭제는 작업본을 바꾸지 않아요. 정의는 작문 프로그램에 속하며 함께 저장·복제·JSON 내보내기를 해요. 독립된 에이전트 등록부는 만들지 않아요.

기존 에이전트는 접힌 행으로 표시하고 새로 추가한 행은 바로 펼쳐요. **전달할 창작 옵션 → 선택 변경**에서는 이름·키 검색, 원본 그룹, 선택된 항목으로 목록을 좁힐 수 있어요. 선택은 초안에 즉시 반영하고 프리셋 저장으로 확정해요. 최대 64개까지 선택하며 더 이상 존재하지 않는 옵션도 목록에서 해제할 수 있어요.

## 참여 방식과 문맥

- **작성 전**: 등록한 순서대로 한 번 의견을 받고 메인에 전달해요. 각 보조는 독립적으로 판단하며 앞 보조의 의견을 자동으로 받지 않아요.
- **메인이 필요할 때**: 메인이 `agents.consult({agentId, question, contextRefs?, draft?})`로 질문해요. 다른 관점이나 근거 확인이 필요하면 후속 상담할 수 있고, 같은 보조의 앞선 질문·의견이 참고 자료로 전달돼요. 메인은 다른 보조의 의견·자신의 조회 결과를 명시적으로 선택하거나 검토할 초안을 함께 보낼 수 있어요. 같은 에이전트·질문(앞뒤 공백 제외)·명시 전달 문맥은 기존 성공·실패 결과를 재사용하고, 선택 문맥이나 초안이 달라지면 새 상담으로 처리해요. 의미가 비슷한 질문을 임의로 같은 요청으로 묶지는 않아요.
- **함께 따를 지침**은 메인과 보조의 명시 지시로, 선택한 **프롬프트 옵션의 현재 값**은 데이터로 전달해요. 메인 프롬프트 전체를 자동으로 복사하거나 특정 옵션 ID를 추정하지 않아요. 공유 지침은 선택한 작문 프롬프트와 함께 적용하며, 보조의 의견은 그 프롬프트의 문체·인물 저작 범위·출력 형식을 대체하지 않아요.
- 보조는 예약된 Run의 사용자 요청, 작문용 원문 projection, 고정 자료, 메모·요약·적용 구성(`outline`)을 받아요. 구성은 작가의 계획이며 이미 일어난 사건이나 인물 지식이 아니라는 계약도 전달해요. 추가 조회는 선택한 `knowledge`, `skills`, `notes`, `story` 도구와 기존 메인 조회 권한의 교집합이에요. 체크박스는 기본 문맥이나 메인이 명시 공유한 근거를 제거하는 필터가 아니라 추가 조회 도구 선택이에요.

보조는 맡은 질문에 유효한 해석·선택지·짧은 예시를 제안하고, 기존 사실과 인물의 믿음·추론·새 창작 제안을 구분해요. 답변 형식과 깊이는 설정된 지침과 질문에 맞춰 정하며, 고정 체크리스트나 사건의 크기를 하네스가 강제하지 않아요. 메인이 의견을 채택·수정·무시하며 최종 창작 결정을 맡아요. 자동 후처리나 원문 재작성은 없으며 보조는 원문·정사·상태를 저장하거나 추첨을 실행하지 않아요. 다른 보조를 부르거나 `story.submit`·평가 도구를 호출할 수 없어요. 모델 프리셋의 `evaluationTools` 설정도 보조의 읽기 권한을 늘리지 않아요.

보조의 응답은 자연어 의견과 호스트가 붙이는 `AgentAdvice`로 전달해요. 같은 Run 안의 원래 `consultationId`, `agentId`, 상태·잘림 여부, 실제 읽기 근거와 분기·원문 시점을 후속 상담에도 그대로 유지해요. 캐시 응답은 새 전달 `callId`를 받더라도 원래 상담 ID가 같아요. 다른 보조의 의견을 검토한 결과에는 선택한 의견들의 원래 작성자·상담 ID를 평탄한 `basedOn`으로 남겨요. 전달을 거듭해도 같은 의견이 독립적으로 확인된 증거로 늘어나지 않아요. 상담 ID는 Run 범위이며 전역 에이전트 등록부나 영구 상담 기록을 추가하지 않아요.

메인과 보조는 자신의 이전 해석도 파생 주장으로 취급해요. 중요한 사실 판단이 요약·의견에만 의존하거나 근거가 충돌하면 해당 원문을 확인하되, 충분한 원문이 이미 전달됐으면 다시 읽지 않아요. 실제 출처 ID·hash·조회 성공은 자료 귀속 정보이지 해석의 정확성을 보증하지 않아요. 의견 본문을 문장별 Claim 객체나 고정 형식으로 만들지 않으며, 새 창작 제안은 자유롭게 채택할 수 있지만 미집필 제안을 과거 사건으로 바꾸지는 않아요.

## 선택한 의견·근거·초안 전달

`contextRefs`는 같은 Run에서 이미 완료된 상담 또는 메인의 `knowledge.*`, `skills.*`, `notes.*`, `story.*` 읽기 도구의 `callId`를 최대 8개 선택해요. 메인이 두 독립 의견을 얻은 뒤 전개 담당에게 함께 검토하도록 맡기는 식으로 사용할 수 있어요. 보조를 선택했다고 다른 모든 의견이나 메인의 작업 내용을 자동으로 공유하지 않아요.

하네스는 실제 완료 영수증을 찾아 도구명·인수·결과·출처·실패 상태를 그대로 전달해요. 상담 결과의 질문·담당자·잘림 상태도 유지해요. 실패한 읽기나 사용할 수 없는 상담은 실패를 설명하는 자료이며 성공 근거가 아니에요. 다른 Run, 아직 완료하지 않은 호출, 상태 변경·평가 도구, 보조 내부의 `agents.read`는 선택할 수 없어요. 참조 대상은 원래 완료한 영수증이며 메인의 전송용 읽기 요약과 별도로 보존하므로 `context.new` 뒤에도 같은 참조를 사용할 수 있어요.

`draft`는 미확정 초안이에요. 모델 내부의 미공개 사고나 초안을 하네스가 추출하지 않으며, 메인이 명시한 글만 `uncommitted`로 전달해요. 의견 여러 개가 일치해도 독립적인 원문 증거가 늘어나지는 않아요. 보조는 근거와 이견을 검토하고, 최종 반영·본문 저장은 메인이 맡아요.

질문·참조 영수증·초안에는 별도 글자 수 제한을 두지 않아요. 지침과 기존 문맥까지 포함한 실제 요청이 선택한 보조 모델의 입력 토큰 한도를 넘으면 원문을 잘라 보내지 않고 수정 가능한 `ADVISOR_CONTEXT_TOO_LARGE` 오류를 반환해요. 요청 JSON에 `o200k_base` 추정치와 여유분을 적용하는 기존 입력 검사를 사용하며, 공급자가 청구하는 정확한 토큰 수는 아니에요. 잘못된 인수·참조와 입력 초과는 추가 모델 전송 전에 반환하므로 메인이 범위를 줄이거나 올바른 ID로 고칠 수 있어요. 공유 자체가 도구 실행이나 새 읽기 권한을 만들지는 않아요.

선택한 원본 영수증과 초안의 내용 해시를 상담 캐시에 포함해요. 같은 질문이라도 새 근거·다른 초안을 명시하면 다시 검토할 수 있고, 동일한 문맥의 성공·실패는 재사용해요. 자기 상담 이력이 하나 더 쌓였다는 이유만으로 동일 요청의 캐시를 무효화하지 않아요. 모든 추가 상담은 기존 개별·전체 호출 예산을 계속 나눠 써요.

## 호출과 저장 계약

`RisuPrompt.collaboration`은 아래 데이터를 보관해요. `validateRisuPrompt`과 `validateAgentCollaboration`이 알 수 없는 필드·ID 중복·공유 옵션 참조·수치 한도를 검사해요.

```ts
type AgentCollaboration = {
  enabled: boolean;
  sharedInstructions: string;
  sharedControls: string[];
  maxCalls: number; // 모든 보조가 나눠 쓰는 1~12회
  agents: {
    id: string;
    title: string;
    description: string;
    instructions: string;
    model: { id: string } | null; // null이면 메인 모델 상속
    trigger: 'before' | 'on-demand';
    tools: ('knowledge' | 'skills' | 'notes' | 'story')[];
    maxCalls: number; // 한 에이전트의 전체 조회 왕복 포함 1~6회
  }[]; // 최대 6명
};
```

API는 기존 `POST/PUT /api/prompt-presets`의 `program`을 사용하며 수정은 `expectedRevision` CAS로 보호해요. 협업을 끈 상태에서는 빈 이름·지침·미입력 호출값과 삭제된 공유 옵션 참조도 보관하므로 다른 프롬프트 편집을 저장할 수 있어요. 다시 켤 때 필수값·공유 옵션과 실행 한도를 검증해요. 데이터 형식과 중복 ID 검사는 저장할 때도 유지해요. 별도 협업 편집 후 오래된 본문 undo가 협업 설정을 지우지 않아요.

현재 프롬프트와 모델을 Run 예약 시 고정해요. `ProfileSnapshot.collaborationModels`에 에이전트 ID별 모델·프로바이더·파라미터를 보관하므로 진행 중 설정 수정은 다음 Run부터 적용돼요. 매 호출에 최신 프로바이더 권한을 다시 검사하고 전송 전에 attempt를 기록해요. 기존 `role: main` 전송을 사용하되 attempt의 host 전용 `agentId`로 보조 호출을 구분해요. 이 ID는 공급자에게 보내거나 모델 출력에서 받지 않아요.

모든 보조 호출은 요약·메인과 같은 `settings.maxCalls`에 포함돼요. 보조 전체 한도와 각 에이전트 한도는 작성 전 상담·후속 질문·조회 왕복을 합산하며 메인의 다음 호출 1회분을 남겨요. 새 질문으로 한도가 초기화되지 않아요. 수정 가능한 조회 오류는 같은 예산과 timeout 안에서 교정할 수 있어요. 기본 전체 추가 호출 한도는 3회, 템플릿별 한도는 2회예요. 최종 작문이 더 많은 도구 왕복을 요구하면 기존 전체 한도에서 끝날 수 있어요. 켜진 협업은 호출 여부와 별개로 도구 설명·공유 지침만큼 메인 입력이 늘어나요.

모델별 `maxOutputTokens`·입력 토큰 한도와 timeout을 사용해요. 보조의 timeout은 한 상담의 여러 호출이 나눠 써요. 완료된 의견은 별도 글자 수로 자르지 않고 메인에게 전달해요. 과거 프리셋·백업의 `maxOutputChars`는 읽을 수 있고 실행에는 적용하지 않으며 새 저장 시 제거해요. 과거 숫자를 임의로 토큰 값으로 변환하거나 모델 설정을 바꾸지 않아요. 과거 상담 영수증의 `truncated` 표시는 보존해요. 이름·역할 설명·지침에도 협업 전용 글자 수 제한을 두지 않으며 프롬프트 파일·API의 공통 저장 크기 경계를 따라요.

보조 실패·거절·부분 응답·불확실 연결 종료는 사용 불가 결과로 전달하고 자동 재호출하지 않아요. 이미 소비한 호출과 usage는 유지하며 실제 비용 미제공 값 `null`을 0으로 바꾸지 않아요. 취소하면 보조와 메인을 함께 멈추고 늦은 결과를 원문으로 저장하지 않아요. 서버 재시작·보관 복원도 불확실 실행을 자동 재생하지 않아요.

작성 전 상담은 등록 순서를 유지해요. 보조들이 공유 호출 예산을 사용하고 전송 직전에 attempt와 사용량을 기록하므로, 병렬 실행은 별도의 예산 예약 계약 없이 추가하지 않아요.

## 진단과 보관

Run의 `agents.consult` tool event에 의견·상태·호출량·질문·출처·명시 문맥 해시를 남겨요. `agents.read`에는 실제 읽기 결과를 남기고, 모델 입력은 `agentId`로 구분하며 `consultationContext`에 실제 전달한 의견·근거·초안을 기록해요. 이 정보는 실행 중 상담에 사용하고 완료 후 영구 아카이브로 보존하지 않아요. 독립 채팅 백업에는 최종 원문과 이어쓰기 자료만 담아요. 원문에는 메인의 최종 응답만 저장해요. 보조가 읽은 본문을 다음 Run의 유지 로어로 자동 승격하지 않아요.

협업 설정은 기존 JSON 필드에 보관하고 협업 전용 DB 테이블은 없어요. DB 버전·지원 이관은 [데이터 형식](DATA-MIGRATIONS.md)을 따라요. 복원은 에이전트 모델 귀속을 검사하고 메인·보조 snapshot의 인증 참조를 제거하며 프로바이더를 비활성화해요. 모델·프로바이더 삭제는 새 선택과 전송 권한에 적용하며 과거 실행 snapshot은 보존해요. 현재 작업본의 전용 보조 모델이 삭제되면 협업을 끄고 모델 선택을 해제해요. 자세한 처리는 [항목 삭제](DELETION.md)를 참고해요.

## 검증 범위

설정·보관 검사는 `tests/agent-collaboration-config.test.ts`, `tests/agent-collaboration-store.test.ts`예요. `tests/agent-collaboration-runtime.test.ts`는 실제 loopback Responses 서버와 새 SQLite DB로 순서·추가 조회·권한·호출량·중복·취소·설정 변경을 검사해요. `tests/agent-collaboration-context.test.ts`는 선택 문맥·초안·구성·문맥별 캐시와 호출 예산, 새 문맥 창 뒤 참조, 수정 가능한 오류를 확인하고 실행 입력은 테스트에서 실행 시점에 관찰하며, 실제 DB의 완료 후 정리도 별도로 검사해요. 브라우저는 `tests/agent-collaboration-browser.spec.ts`의 AGENTUI01/02에서 모바일·데스크톱 편집과 실제 저장/미리보기 API를 확인해요.

합성 검사는 구현 계약의 증거예요. 실제 모델의 창작 품질 향상, 비용 대비 효과, 실제 공급자 응답 지연은 평가하지 않았어요.

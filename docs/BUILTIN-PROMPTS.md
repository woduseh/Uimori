# 기본 제공 프롬프트

Phēmē v5.4.1의 RP·소설 프리셋과 Hermēneía v1.1.0 번역 프리셋을 제공해요. 새 작업실은 **Phēmē · RP**와 **Hermēneía**로 시작해요. 이미 저장한 프롬프트·선택 옵션·과거 실행 기록은 교체하지 않아요.

## 선택과 편집

프롬프트 관리의 **기본 프롬프트**에서 원하는 항목을 추가해요. 추가하면 새 ID의 일반 프리셋으로 저장하고 편집할 수 있어요. 현재 프롬프트 설정에서 그 프리셋을 선택하면 다음 요청부터 적용돼요. 프리셋 추가만으로 현재 작업본을 바꾸지 않아요. 삭제하거나 편집한 사본을 시작할 때마다 복구하거나 덮어쓰지 않으며, 기본 제공 목록에서 다시 추가할 수 있어요.

| ID | 제목 | 용도·구성 |
| --- | --- | --- |
| `pheme` | Phēmē · RP | 대화형 역할극. 옵션 44개, 기본 꺼짐 협업자 3명 |
| `pheme-novel` | Phēmē · 소설 | 요청한 장면·회차의 집필. 옵션 45개, 기본 꺼짐 시뮬레이션 협업자 4명 |
| `hermeneia` | Hermēneía | 한국어 문학 번역 |

RP와 소설은 별도 프리셋이에요. 예전 작업 모드 선택으로 전환하지 않아요. 별도 OOC·협업·시뮬레이션 항목은 기본 목록에서 제공하지 않으며, 기존에 저장한 사본은 계속 사용할 수 있어요.

Phēmē의 초기 선택은 배포된 Uimori r2 파일을 따라요. 한국어 응답·사용자 캐릭터 공동 서술·선언대로 행동 결과 확정으로 시작하며 옵션에서 바꿀 수 있어요. 자기 캐릭터의 내면·대사·행동을 직접 쓰려면 **유저 캐릭터 서술권 → 사용자 전담**을 선택해 주세요. 새 시점 키 `pheme_viewpoint`와 RP 분량 키 `pheme_rp_length_preset`을 사용하며, 기존 프리셋의 선택값을 새 키로 자동 변환하지 않아요.

## 선택형 협업

협업은 기본으로 꺼져 있어요. 프리셋의 협업 설정을 켜면 RP에서는 인물·관계, 설정·연속성, 전개를 검토하는 3명이 참여할 수 있어요. 소설에는 장면 밖 인물과 사건을 검토하는 협업자 1명을 더해요. 별도 프리셋을 추가하지 않고 같은 프리셋에서 켜거나 끌 수 있어요.

모든 협업자는 필요할 때 호출하는 `on-demand` 방식이며, 모델을 지정하지 않으면 본문 모델을 따라요. 전체 보조 호출 상한은 8회이고, 보조의 자료 조회 왕복도 전체 호출 예산에서 차감돼요. 협업을 켜면 추가 모델 호출과 대기 시간이 발생할 수 있어요. 프리셋 추가·적용으로 모델이나 전체 호출 예산을 변경하지 않아요. 의견과 조회 근거의 전달, 불확실 실행 처리는 [작문 협업](AGENT-COLLABORATION.md)을 따라요.

## 제공과 출처

`server/builtin-prompts.ts`가 목록과 독립 사본 생성을 담당해요. `GET /api/prompt-templates`는 제목·역할·설명만, `GET /api/prompt-templates/:id`는 선택한 프로그램과 기본 옵션을 반환해요. 두 API는 읽기 전용이에요. 추가·편집·적용에는 기존 프리셋 및 현재 작업본 API의 검증·수정 번호·초안 보호를 사용해요.

Phēmē는 RisuToki의 `risu/prompts/phēmē/dist/uimori/pheme-roleplay.uimori.json`과 `pheme-novel.uimori.json`의 V5.4.1 r2 프로그램·기본 선택값을 사용해요. 이 프로그램은 같은 버전의 `.risup`을 직접 가져온 결과와 같아요. 원본의 CBS·토글 선언·정규식·캐시 지점을 보존하고, 선택형 협업 설정만 별도로 붙여요.

Hermēneía는 릴리즈 인스턴스에 저장된 **Hermēneía Prompt v1.1.0**의 프로그램과 선택값을 가져왔어요. 원본 프리셋의 이름은 `Hermēneía v1.1.0`이에요. `server/builtin-prompts/`에 두 작문 본문·번역 본문·각 기본 선택값·협업 정의 두 개를 보관해요. 실행 중인 릴리즈 인스턴스에서 자동으로 동기화하지 않아요.

Phēmē의 캐시 지점 네 개는 Responses·Anthropic 연결의 **명시적 캐시**와 **자동 캐시** 모두에서 유지돼요. 자동 모드도 네 지점이 모두 사용되면 추가 자동 지점만 생략하고 미리보기 진단에 남겨요. 프리셋 선택은 모델의 캐시·출력 토큰 설정을 바꾸지 않아요.

## 검증 범위

`tests/builtin-prompts.test.ts`는 새 환경의 초기 선택, 기존 DB 재시작 시 저장본 보존, 목록 조회의 비변경성, 독립 사본, 고정 RP·소설 모드와 협업 설정을 확인해요. `tests/risu-native-prompt-composition.test.ts`는 두 프리셋의 CBS 조립을 검사해요. 기본 목록의 추가·편집 흐름은 `npm run verify:browser -- --grep BPTUI`로 확인해요. 실제 모델의 창작·번역 품질과 비용·지연은 별도 평가 대상이에요.

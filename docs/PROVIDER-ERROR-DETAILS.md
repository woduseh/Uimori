# 공급자 오류 상세

HTTP 오류의 원인을 소유자가 확인할 수 있도록 공급자의 짧은 설명을 보존해요.

- 응답 본문은 최대 16,384바이트까지 읽어요. 초과한 응답의 일부를 진단으로 채택하지 않아요.
- `ProviderHttpDiagnostic.message`에는 최대 4,000자의 설명을 보관해요. 현재 요청에 사용한 인증 문자열을 먼저 마스킹하고, 그 다음 표시 길이를 제한해요.
- 알 수 없는 공급자 오류 코드·상태·명시적 필드 경로는 문자 형식·길이·개수 제한을 통과하면 남겨요. 앱 옵션 이름으로 매핑하는 것은 알려진 필드만이에요.
- 비-JSON 프록시 오류의 본문도 진단 기록에 제한된 텍스트로 남겨요. HTML로 실행하지 않아요. 현재 상세 UI는 일반 4xx 요청 거절에 연결돼요.
- 일반 4xx 요청 거절 안내의 **공급자 오류 상세**를 펼치면 설명을 볼 수 있어요. 401·403·429 및 서버 오류를 생성 옵션 오류라고 단정하는 기존 동작은 바꾸지 않아요.

## 내부 열람과 공유 보고서는 달라요

공급자는 요청 원문을 오류에 되돌려줄 수 있어요. 따라서 이 설명은 키를 마스킹해도 **공유해도 안전한 정보가 아니에요.** 복사하거나 공개하기 전에 확인해요.

공유용 진단 보고서는 `server/diagnostic-report.ts`의 명시적 필드 투영을 계속 사용해요. 새 `message`나 공급자 원문을 공유 보고서에 추가하지 않아요. 이번 변경은 서버 인증, iframe, Lua 실행 권한, 도우미 권한 모델을 변경하지 않아요.

## 검증

```sh
npm run check
npx --no-install vitest run tests/provider-http-error.test.ts tests/provider-rejection.test.ts
```

HTTP 진단 단위 테스트는 마스킹·길이 제한·새 필드·비-JSON 응답·취소·중단된 스트림을 다뤄요. 공급자 옵션 거절 테스트는 기존 옵션 매핑과 오류 설명 전달을 다뤄요. 실제 공급자 호출이나 전체 내보내기 경로의 통합 검증을 대신하지 않아요.

# 본문만 내보내기와 가져오기

본문 교환(Transcript)은 대화의 요청 문구, 완료된 원문, 유효한 번역, 작성자 메모만을 추출하여 가볍게 새 채팅으로 옮길 수 있는 JSON 형식이에요. 봇·페르소나·모듈의 본문 자료, 첨부 이미지 파일, 변수 상태나 Lua 메시지 수정 내역까지 통째로 옮기려면 [독립 채팅 백업](CHAT-BACKUP.md)을 사용해요.

## 본문 교환 형식과 가져오기

### 본문 가져오기 방법
- **접근 경로**: 봇 메뉴의 **이 봇으로 본문 가져오기** (또는 **본문 가져오기**)에서 본문 JSON 파일을 선택해요.
  - **주의**: **설정 → 데이터 관리 → 백업 파일 가져오기**는 자료 및 채팅 백업 전용 입구이므로 본문 transcript 파일을 받지 않아요.
- **가져오기 검토**:
  1. 파일을 선택하면 대화 제목, 전체 장면 수, 대상 봇을 화면에서 확인해요.
  2. 대상 봇은 반드시 선택해야 해요 (봇 자료 자체가 없으면 이어 쓸 채팅을 생성할 수 없으며, 제목이나 역할 문자열만으로 임의 추측하지 않아요).
  3. 다른 연결 자료는 대상 작업실에 이미 존재하는 동일 ID 자료의 최신 수정본을 사용하며, 대상 작업실에 없는 자료는 제외된 항목을 결과에서 알려줘요.
- **등록 결과**:
  - 새 채팅, 메시지, 메모 ID를 발급하고 내부 순서를 연결해요. 기존 채팅이나 원본 파일은 변경하지 않아요.
  - 확정된 원문은 `source`로 저장되고 가져온 본문이라는 작은 표시만 남겨요 (이전 모델 요청이나 도구 호출 기록을 인위적으로 꾸며내지 않아요).
  - 이미지를 외부에서 자동 다운로드하지 않으며 모델 생성이나 Lua 스크립트를 실행하지 않아요.
  - 가져온 텍스트를 읽거나 이후 장면을 생성할 때는 목적지 작업실의 현재 자료와 모델 설정을 사용해요.
- **멱등성과 중복 방지**:
  - 동일한 통신 요청을 재전송하면 같은 가져오기 결과를 반환해 중복 사본 생성을 방지해요.
  - 사용자가 새 가져오기를 시작하면 새 독립 사본을 생성해요 (목적지의 요청 키를 과거 원본의 이벤트 이력으로 대체하지 않아요).

## 형식 규약과 한도

### 지원 버전과 구조
- **지원 버전**: `uimori-chat-transcript` **버전 2**만 지원해요 (예전 v1 메모 형식을 추측해 변환하는 호환 경로는 지원하지 않아요).
- **기본 필드 구성**:
  - `title`: 대화 제목
  - `packageAttachments`: 연결된 패키지 자료 목록
  - `notes`: 작성자 메모 목록 (`text`, `author`, `atIndex`, `kind`를 명시하며, 가져온 메모 종류에는 출처 정보도 담겨요)
  - `entries`: 각 장면 항목 배열 (각 항목은 `request`, `text`, `translation`을 포함하며 번역이 없으면 `null`이에요)
- **선택적 확장 필드**:
  - `sceneContext`: 각 장면의 다음 집필용 요청 및 본문 문맥 포함/제외 설정을 보존해요.
  - `requestImages`: 요청 참고 이미지의 참조 정보를 포함하지만 이미지 바이트 자체는 담지 않아요. 가져올 작업실에 원본 보존본과 모델 전송본 이미지가 둘 다 존재해야 하며, 하나라도 없으면 가져오기를 거절해요 (이미지까지 함께 옮기려면 독립 채팅 백업을 사용해 주세요).

### 패키지 연결 규칙과 한도
- **역할 분리 연결**: 같은 패키지라도 봇과 페르소나처럼 서로 다른 역할로 각각 연결할 수 있으며, 가져오기·분기·독립 백업 복원 시 이 역할들이 보존돼요. 단, 같은 패키지 ID와 역할을 두 번 지정하면 revision 값이 다르더라도 중복 연결로 거절해요.
- **용량 및 글자 수 한도**:
  - 화면 선택 파일 크기: 최대 60MiB
  - API JSON 요청 본문 크기: 최대 64MiB
  - 텍스트 크기: 요청(`request`), 원문(`text`), 번역(`translation`)은 각각 최대 2,000,000개 UTF-16 코드 단위
  - 메모 본문(`notes`): 최대 32,000개 UTF-16 코드 단위
  - 연결 자료: 최대 300개
  - 장면과 메모 개수 자체에는 별도 제한이 없지만 전체 파일 및 요청 크기 한도를 지켜야 해요.

## 에이전트 및 구현 참고

### 내부 모듈과 트랜잭션 보장
- **구현 파일**: 형식 정의와 검증은 `core/chat-transcript.ts`, 데이터베이스 저장과 영속화 처리는 `server/chat-transcript.ts`에 분리되어 있어요.
- **원자적 실패 처리**: 파일 포맷, 메모가 가리키는 대상 장면, 텍스트 크기 한도, 연결 봇 존재 여부를 사전에 철저히 검증해요. 검증에 실패하면 불완전한 중간 채팅이나 레코드를 남기지 않고 즉시 롤백해요.
- **전체 작업실 복원**: 작업실 전체 복원은 이 형식이 아니라 [SQLite 백업](DATA-MIGRATIONS.md)을 사용해요.

### 테스트 및 검증 명령어
```sh
npm test -- tests/chat-transcript.test.ts tests/personal-workspace-flow.test.ts
```

- `tests/chat-transcript.test.ts`: 원문, 번역, 메모, 중복 재전송 요청 및 잘못된 파일 형식에 대한 거절 동작을 검증해요.
- `tests/personal-workspace-flow.test.ts`: 독립 백업과 연계된 대화 이어쓰기 및 전반적인 작업실 대화 흐름을 검증해요.

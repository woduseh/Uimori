# 문제 확인과 실행 상세

**작업 현황**에서 진행 상태·선택한 모델·사용량·오류와 제공되는 복구 동작을 확인해요. 원고의 **이번 생성**과 작업의 **실행 확인**은 해당 실행에 남아 있는 입력·모델·컨텍스트 정보를 보여줘요. 도우미 작업은 활동 내역과 작업 상세에서 읽기·변경·오류 및 저장 결과를 확인할 수 있어요.

별도의 익명 공유 진단 보고서 생성·미리보기·다운로드 UI와 API는 제공하지 않아요. 실제 작업의 상태·오류·실행 상세는 계속 사용할 수 있어요.

## 저장되는 기록

실행 중에는 요청 입력과 도구 결과가 필요해요. 본문·보조·도우미 작업이 성공하면 해당 경로의 큰 모델 입력과 누적 기록을 정리하고 상태·역할·모델·사용량 등의 요약을 남겨요. 원문·메모·변수·Lua 메시지 변경과 현재 로어 상태는 이어쓰기에 필요한 자료로 별도 보관해요. [실행 데이터 수명](EXECUTION.md)

모델 호출은 공통 attempt 기록에 시작·종료 시각, 관측한 경과 시간, 역할·모델·사용량·오류를 남겨요. 본문, 조언자, 번역, 컨텍스트 요약, 원작 참고, 삽화의 계획·이미지·배치, 입력 번역·선택 수정, 제목과 네이티브 Risu 모델 호출이 이 경계를 사용해요. Codex 사전 내용 판정도 `codex-content-preflight`로 구분한 실제 판단 호출로 집계하며, 입력 번역·선택 수정과 마찬가지로 원문·미저장 초안은 보관하지 않아요. 시작 후 예외로 끝난 시도는 확인 불가 결과로 마감하고 재호출하지 않아요.

호스트 도구는 실행 전에 호출 식별자·종류·제한된 인자 미리보기와 해시를 기록하고, 끝나면 관측한 상태·시간·오류·결과 크기로 갱신해요. 셸은 종료 코드·타임아웃·출력 바이트와 잘림 여부를 구분해요. 본문·조언자·원작 참고·번역·삽화의 기록은 `execution_tool_diagnostics`, 도우미는 기존 `helper_events`에 남아요. 성공 후 큰 재실행용 입력·도구 결과를 정리해도 작은 진단은 남아요. 호출 시작만 있으면 관측이 중단된 것으로 읽고, 변경이 없었다고 판단하지 않아요. 완료 영수증과 진단 기록은 별개예요.

네이티브 Codex의 검색·계획·대기·이미지 활동은 종류·ID·상태·시각을 최대 64개, 문맥 압축은 별도로 최대 16개 기록하고 초과 개수를 남겨요. 비공개 추론·검색 내용·결과 본문과 앱에서 이미 기록한 동적 도구는 중복 보관하지 않아요. 내부 모델 호출 수가 보고되지 않으면 여전히 미확인이에요. 프로세스가 기록을 전달하기 전에 종료되면 그 내부 활동은 복원할 수 없어요.

도우미의 `task.inspect`에 `includeDiagnostics:true`를 지정하면 본문·보조 작업·삽화·도우미의 호출과 도구 진단을 각 20개씩 조회해요. `attemptsOffset`, `toolsOffset`으로 다음 페이지를 열어요. 캐시·추론 토큰과 Codex 내부 활동의 종류·상태별 개수도 보고된 범위에서 보여줘요. Codex의 개별 내부 활동은 DB의 attempt raw usage에 보존돼요. 수동 컨텍스트 요약의 attempt는 `context_job_attempts`로 연결되며, 기존 `task.inspect`의 작업 종류에는 별도 수동 요약이 포함되지 않아요. 기본 조회는 계속 작은 요약을 반환해요.

진단은 모델 입력에 자동으로 추가하지 않아요. 인자 미리보기는 제한·가림 처리되어 원본을 재구성할 수 없으며, 자격증명 패턴을 가렸더라도 개인 자료의 일부가 포함될 수 있어요. 부모 작업·채팅 삭제와 자료 삭제 정리를 따르고 전체 작업실 DB 백업에 포함돼요. 장면을 삭제하면 해당 채팅의 도우미 인자 미리보기도 정리해요. 완료 작업의 입력은 이미 비워져 어느 장면을 참조했는지 확정할 수 없으므로 채팅 단위로 정리하되 호출 식별자·해시·시간·결과·사용량은 보존해요. 이전 실행에 없는 시각·인자·도구 기록은 만들어 넣지 않아요.

실패하거나 중단된 요청의 부분 출력은 완료된 원문과 구분해요. 프로바이더 내부 응답 시간이나 기록에 없는 요청 내용을 추정해서 표시하지 않아요. 완료 후의 입력·도구 기록 개수는 남아 있는 기록의 개수이며, 실행 전체에서 실제 사용한 도구 수와 다를 수 있어요. 호출량은 저장된 사용량을 함께 확인해요. [사용량과 미확인 금액](USAGE-REPORT.md)

도우미의 접힌 사용량에는 마지막 요청 입력과 이번 작업 출력을 간결한 K/M 표기로 보여줘요. 펼치면 정확한 누적 입력·출력과 캐시·추론 부분집합을 확인할 수 있어요. 누적 입력에는 같은 문맥을 후속 요청에서 다시 보낸 양도 포함되므로 현재 문맥 크기와 다를 수 있어요. 미보고 사용량은 미확인으로, 로컬 측정 입력은 추정으로 표시해요.

## 프로바이더 오류 상세

HTTP 오류에는 프로바이더가 보낸 짧은 설명이 있을 수 있어요. 응답은 최대 16,384바이트까지 읽고, 해당 요청의 인증 문자열과 Bearer·Basic 인증 패턴을 마스킹한 뒤 최대 4,000자의 설명을 보관해요. 비 JSON 프록시 오류도 텍스트로 표시하며 HTML로 실행하지 않아요. 401·403·429와 서버 오류를 모두 생성 옵션 문제라고 해석하지 않아요.

프로바이더가 요청 내용을 오류에 되돌려 줄 수 있으므로, 인증 문자열을 가린 오류 상세에도 원문이나 다른 개인 정보가 남을 수 있어요. 오류 내용을 다른 사람에게 전달할 때는 본문을 직접 확인해요. 기록되지 않은 외부 처리 상태나 미보고 비용을 이 화면만으로 확정할 수는 없어요.

## 작업 제어와 확인 범위

취소·재시도는 해당 작업의 현재 상태와 제공되는 동작을 따라요. 저장 결과가 불명확한 변경이나 외부 실행은 자동으로 되풀이하지 않아요. 도우미는 기존 `task.list`, `task.inspect`, `task.cancel`, `task.retry`를 통해 요청 범위의 작업을 확인하고 제어할 수 있어요. 저장된 변경은 작업의 응답 실패와 별개일 수 있으므로 먼저 완료된 변경을 확인해요. [도우미 작업 도구](HELPER-TOOLS.md#settings-diagnostics-and-task-control)

`tests/provider-http-error.test.ts`와 `tests/provider-rejection.test.ts`는 제한된 HTTP 오류 읽기·인증 문자열 가림·오류 전달을 다뤄요. 이 합성 검사는 실제 프로바이더 장애의 원인이나 계정 상태를 입증하지 않아요. 환경 실행 문제를 확인하는 절차는 [개발과 검증](DEVELOPMENT.md)을 참고해요.

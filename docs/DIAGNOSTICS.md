# 문제 확인과 진단 보고서

작업 현황은 실행 상태·모델·사용량·오류를 확인하는 곳이에요. **설정 → 데이터 관리**의 시스템/채팅 진단과 실행 상세의 **문제 보고용 진단 만들기**는 이 중 공유 가능한 필드만 JSON으로 추려요. 내용을 먼저 보고 파일을 내려받으며 자동 업로드는 하지 않아요.

## 저장되는 기록

실행 중에는 요청 입력과 도구 결과가 필요해요. 본문·보조·도우미 작업이 성공하면 해당 경로의 큰 모델 입력과 누적 진단을 정리하고 상태·역할·모델·사용량 등의 요약을 남겨요. 원문·메모·변수·Lua 메시지 변경과 현재 로어 상태는 진단 로그가 아니라 이어쓰기에 필요한 자료로 별도 보관해요. [실행 데이터 수명](EXECUTION.md)

실패하거나 중단된 요청의 부분 출력은 완료된 원문과 구분해요. 공급자 내부 응답 시간이나 기록에 없는 요청 내용을 추정해서 표시하지 않아요. 완료 후의 입력/도구 기록 개수는 남아 있는 기록의 개수이며, 전체 실행 중 실제 사용한 도구 수를 뜻하지 않을 수 있어요. 호출량은 저장된 사용량을 함께 확인해요.

## 공급자 오류 상세

HTTP 오류에는 공급자가 보낸 짧은 설명이 있을 수 있어요. 응답은 최대 16,384바이트까지 읽고, 등록된 인증 문자열을 마스킹한 뒤 최대 4,000자의 설명을 보관해요. 비-JSON 프록시 오류도 텍스트로 표시하며 HTML로 실행하지 않아요. 401·403·429와 서버 오류를 모두 생성 옵션 문제라고 해석하지 않아요.

공급자가 요청 내용을 오류에 되돌려 줄 수 있으므로 **키가 가려졌다고 공유해도 안전한 자료는 아니에요.** 내부 오류 상세를 공개하기 전에는 본문을 확인해요. 아래 공유 진단에는 공급자 원문 설명을 넣지 않아요.

## 공유 진단의 범위

`uimori-diagnostic-report` v1에는 빌드·DB 스키마·Node·OS·아키텍처와 제한된 실행/attempt 요약이 들어가요. 원문·프롬프트·로어·메모·이미지·요청/응답 본문·도구 인자·API 키·환경변수·서버 주소·개인 파일 경로·원래 자료 ID는 포함하지 않아요.

알려진 오류 코드·HTTP 상태·상태 전환·사용량만 명시적으로 추리고 알 수 없는 값은 `unknown` 또는 `null`로 표시해요. 시스템/채팅/선택 실행 범위를 구분하며 아직 지원하지 않는 보조·도우미 전체 수명주기나 제외된 오래된 기록은 coverage 정보로 알려줘요. 보고서는 원문 의미나 공급자 내부 실패 원인을 증명하지 않아요.

한 번에 실행 50개, attempt 100개, JSON 256KiB 범위로 제한해요. 상대 시간은 기록된 시점 간 차이이며 실제 외부 처리 시간과 같지 않아요. 이 상한은 과거 자료를 보관하는 기간 정책이 아니에요.

## 구현과 검사

`core/diagnostic-report.ts`가 형식을, `server/diagnostic-report.ts`가 제한된 DB 조회를, `web/DiagnosticReport.tsx`가 미리보기와 파일 저장을 맡아요. 출력에 DB 객체 전체를 spread한 뒤 지우는 방식 대신 필요한 필드를 선택해요.

`tests/diagnostic-report.test.ts`, `tests/provider-http-error.test.ts`, `tests/provider-rejection.test.ts`는 범위·마스킹·오류 전달을 확인해요. `npm run verify:diagnostics`는 합성 화면 검사예요. 사용자 DB·실제 API 키·외부 모델 호출을 테스트에 사용하지 않아요.

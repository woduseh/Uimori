# 본문 생성과 번역

모델·프롬프트를 선택하고 예약 시 고정하는 계약은 [전역 설정](GLOBAL-MODELS.md), Risu 원본 평가와 메시지 구성은 [프롬프트 실행](PROMPT-RUNTIME.md), 예약·복원은 [실행 snapshot](RESERVATION-SNAPSHOTS.md)에 있어요.

## 본문 응답 판정

본문 서비스 거절 감지가 켜져 있으면 생성 전에 TypeSafe AI의 JEV 연결과 최소 호출 예산을 확인해요. 실제 생성 응답을 받은 뒤 Lua 출력 후처리 전에 명시적 서비스 거절 하나만 판정해요. 장르·문체·허구 여부·품질을 심사하지 않으며 작품 속 인물의 거절이나 인용을 서비스 거절로 취급하지 않도록 지시해요.

생성문 전체를 `state.response`로 보내며 `explicitRefusal >= mainJudgmentThreshold`이면 거절, 미만이면 채택해요. 기준은 기본 0.9, 설정 범위는 0.5 초과~1이에요. 채택한 결과만 카드의 Lua 출력 콜백을 거쳐 확정 원문이 돼요. 거절·판정 실패는 원래 출력과 호출 기록을 보존하고 본문·이야기 기억에 채택하거나 자동 재생성하지 않아요. 원본 Lua의 모델 호출은 이 판정과 별개예요.

판정 1회는 Run 전체 `maxCalls` 안에서 예약해요. 같은 입력 후보도 자신의 생성 결과를 새로 판정해요. JEV 입력 지문과 전체 생성문을 `main-refusal-jev-v2` snapshot 영수증에 저장하며 archive 검증에서 해당 요청과 일치하는지 확인해요.

본문·번역 거절 감지는 **역할별 모델 → 작업 동작**에서 각각 설정하며 기본은 켜짐이에요. `mainJudgmentEnabled`·`mainJudgmentThreshold`는 Run snapshot에, `translationPolicy.judgment`는 번역 작업 입력에 예약 시 고정해요. 끈 역할은 거절 검사의 키 확인·판정 예산·호출을 건너뛰지만 생성 오류·취소·소유권·저장 검증은 유지해요. 로어·이미지 JEV에는 영향을 주지 않아요. 연결과 입력 예산은 [프로바이더 안내](PROVIDERS.md)를 봐요.

## 번역 입력과 결과

전체 원문을 한 번의 번역 입력으로 보내요. 구간 분할·자동 재분할은 없으며 원문 ID/hash와 작업 소유권·세대·CAS를 검사해요. 기본 응답은 일반 텍스트이고, 선택형 **번역 구조화 출력**은 [프로바이더 계약](PROVIDERS.md)에 따라 검증한 `text`만 저장해요.

예약 시 현재 번역 프롬프트와 원문 시점의 봇·페르소나·로어·번역 지침, 허용된 요약·메모·자료 조회를 고정해요. 다른 채팅이나 나중에 수정된 자료를 섞지 않아요. 네이티브 `chat` 블록에는 번역할 원문과 참고 문맥을 담은 현재 user 메시지가 들어가며, 원문을 CBS로 평가하지 않아요. `server/product-auxiliary.ts`는 컴파일된 입력에 전체 값이 전달된 경우에만 같은 데이터의 호스트 전달을 생략해요. 프리셋이 메시지나 일부 내용을 제외하면 전체 데이터를 별도로 전달해요.

메인과 번역의 `story.list/search/read`·`notes.list/read` 정의는 `core/story-read-tools.ts`를 공유해요. 검색어 없이 찾을 때는 `story.list`, 알려진 회차는 `story.read`의 `sceneNumber`를 사용해요. 빈 검색어는 수정 가능한 인수 오류이고, 출처 무결성 오류는 실행을 종료해요.

번역 거절 감지가 켜져 있으면 JEV에 후보 전체와 질문 `explicitRefusal` 하나만 보내요. 원문·자료·도구·대화 기록은 판정 입력에 넣지 않아요. `explicitRefusal >= translationPolicy.judgment.threshold`인 명시적 거절만 전체 번역을 자동 재요청해요. 기준은 기본 0.9, 범위는 0.5 초과~1이고 추가 요청은 기본 1회, 0~5회예요. 번역·조회 후속 요청·판정은 한 작업의 전체 호출 한도(기본 16, 2~64)를 공유해요. 생성형 판단 모델이나 실패 시 대체 호출은 없어요.

전체 입력과 질문·본문 해시를 `translation-refusal-jev-v2` 입력 지문으로 검증해요. 요청·응답·실제 또는 미상 사용량은 attempt에 남기며 인증키는 제외해요. 입력 한도 초과에서도 생성문을 잘라 보내지 않아요. [JEV 입력 검증](JEV-INPUT-VERIFICATION.md)은 실제 전송과 합성 실행 검사의 범위를 구분해요.

빈 응답·부분 응답·판정 실패·HTTP 오류·취소·한도 초과는 자동 재생하지 않아요. 판정 실패의 후보 텍스트는 기록에 보존하지만 성공 번역으로 표시하지 않아요. 이전 성공본이 있으면 같은 원문 hash에 속한 결과를 계속 표시해요.

수동 재번역은 현재 모델·프롬프트·정책으로 새 작업을 만들며 진행 중인 중복 요청은 기존 작업을 반환해요. 직접 번역 수정은 새 완료본으로 저장하고 모델을 호출하지 않아요. 원문이 바뀌면 이전 hash의 번역을 최신 결과로 재사용하지 않아요.

## 재요청과 도구 오류

`POST /api/runs/:id/retry`는 원래 요청 직전 위치에서 새 분기를 만들고 현재 설정으로 생성해요. 이전 성공 원문·실패 기록을 수정하지 않으며 같은 idempotency key는 같은 새 실행을 반환해요. 별도의 같은 입력 후보 실험은 원래 고정 snapshot을 사용해요.

잘못된 입력처럼 명시적으로 `recoverable`인 도구 오류는 모델에 돌려줘 실행기의 호출·시간·문맥 예산 안에서 수정할 수 있어요. 권한 거절과 분류되지 않은 실패는 종료하며, 불확실한 외부 공급자 요청의 자동 재실행을 허용하지 않아요.

관련 구현은 `server/model-runner.ts`, `server/main-judgment.ts`, `server/translation-judgment.ts`, `server/product-auxiliary.ts`, `server/source-editing.ts`, `core/tool-outcome.ts`예요. 합성 검사는 실행·저장 계약을 확인하며 실제 거절 분류나 창작·번역 품질을 판정하지 않아요.

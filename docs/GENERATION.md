# 본문 생성과 번역

모델과 프롬프트의 선택은 [역할별 모델과 현재 프롬프트](GLOBAL-MODELS.md), Risu 평가 순서는 [프롬프트 실행](PROMPT-RUNTIME.md), 저장되는 데이터의 수명은 [실행 입력](EXECUTION.md)을 참고해요.

## 요청과 완료

요청을 접수할 때 현재 자료·모델·프롬프트·채팅 상태를 읽어 해당 실행의 입력을 구성해요. 실행 도중 다른 창에서 자료를 수정해도 이미 시작한 요청에 섞지 않아요. 잘못된 도구 인수는 수정 가능한 오류로 모델에 반환하고, 취소·통신 실패·호출 한도는 실행을 중단해요. 부분 출력과 실패한 출력을 완료된 원문으로 저장하지 않아요.

성공한 요청은 원문·카드 변수·Lua 메시지 변경·사용량을 저장해요. 전체 모델 입력과 도구 교환은 작업 중에 사용하지만 완료 후 영구 보존하지 않아요. **이번 생성**과 **실행 확인**은 남아 있는 기록을 보여주며 과거 전체 요청을 재생하는 기능이 아니에요. 별도 익명 진단 보고서 생성은 제공하지 않아요.

## 실행 중 다음 요청 예약

채팅당 실행 중인 생성은 하나(`one_active_run_per_chat`)라서, 집필 중에 보낸 다음 요청은 서버 대기열이 아니라 그 탭에만 있는 한 건으로 예약해요. 예약은 서버의 실행과 1회 옵션 예약(`chat_option_pending`)을 미리 차지하거나 순서를 바꾸지 않아요. 보낼 때는 일반 전송과 같은 경로와 멱등 키를 지나가므로, 접수가 불확실한 요청은 기존의 **이전 요청 확인**이 이어받고 새로고침이나 다른 탭에서도 두 번 나가지 않아요.

자동 전송은 앞선 실행이 `completed`로 끝났고, 이 탭이 같은 채팅을 보고 있고, 요청이 함께 보낼 설정의 수정 번호가 예약 때와 같고, 확인 대화상자(Codex 내용 경고 등)나 다른 전송 조건이 막고 있지 않을 때만 해요. 비교하는 수정 번호는 채팅 설정, 채팅 프로필(입력창의 모델, 페르소나, 모듈과 작가 노트, 로어 정책, 고정 프롬프트), 창작 옵션, 전역 모델과 프롬프트 설정 네 가지예요. 서재 자료, 로어 항목, 플롯의 진행 중 항목, 이야기 가이드는 비교하지 않고 직접 보낼 때처럼 보내는 순간의 내용을 써요. 조건은 실행이 끝난 것을 탭이 본 순간에 확인해요. 숨은 탭은 화면을 갱신하지 않으므로, 다시 보일 때 확인하고 보내요. 하나라도 어긋나면 보내지 않고 예약 내용을 입력창 초안으로 되돌린 뒤 이유를 알려요. Codex 내용 확인 요청 자체가 실패해도 확인이 필요한 것으로 보고 되돌려요. 직접 보낼 때는 같은 실패에서 그대로 보내지만, 자동 전송에는 결과를 지켜보는 사람이 없기 때문이에요. 채팅을 떠나면 그 자리에서 예약을 끝내요. 보내기 직전의 확인 중에 떠났다가 돌아와도 그 예약은 보내지 않아요. 새로고침 뒤에는 예약을 보내지 않고 초안으로 되돌려요. 실행이 끝났는지 확인할 수 없는 상태에서 자동으로 보내지 않기 위해서예요. 자동으로 보낸 요청도 직접 보낸 요청과 같은 전송 함수(`web/main.tsx`의 `generate`)를 거치므로, 리더가 새 글을 따라 내려가요.

로어 초기화 표시는 예약에 함께 담겨 그 요청에만 적용되고, 입력 번역의 원문 되돌리기는 예약하는 순간 전송할 때처럼 끝나요. 예약은 새로고침에 대비해 텍스트만 세션 저장소에 두므로, 참고 이미지가 있는 요청은 예약하지 않아요. 동작은 `web/useStory.ts`의 `queueRequest`, `sendQueuedRequest`가 맡고 `tests/composer-next-request-browser.spec.ts`가 확인해요.

## 거절 판정

본문 서비스 거절 감지는 **기본 꺼짐**이에요. **설정 → 역할별 모델**에서 켜면 본문 생성 후 Lua 출력 후처리 전에 [판단 프로바이더](PROVIDERS.md#판단-프로바이더)(기본 TypeSafe AI / JEV)로 명시적 서비스 거절 여부를 확인해요. 응답을 작성한 모델이 사용자 요청을 거절하고 대안을 제시한 경우도 거절로 보며, 이야기 속 인물의 대사나 인용과 구분해요.

판정 기준은 기본 0.9이고 설정 범위는 0.5 초과~1이에요. 켠 경우에만 판단 프로바이더의 키와 판정 호출 예산을 요구해요. 판단 프로바이더의 키는 **프로바이더와 모델** 설정에서 앱에 등록하며 일반 API 키와 같은 DB에 보관해요. 이 옵션은 같은 판단 프로바이더를 쓰는 로어 관련성·이미지 선택과 별개로 켜고 꺼요.

본문 생성은 끝났지만 판정 호출이 실패했다면 보존된 응답에서 **판정만 다시 시도**할 수 있어요. 생성 모델을 다시 호출하지 않고 판정과 필요한 출력 처리를 수행해요. 원래 요청 이후 이야기가 진행됐다면 오래된 위치에 몰래 삽입하지 않아요. 서버가 판정을 기다리다 종료된 경우도 완성 후보와 판정 대기 기록이 있으면 명시적으로 판정만 다시 시도할 수 있어요. 판정상 거절, 부분 생성, 이미 확정된 결과, 판정 후 출력 스크립트 처리 중 중단은 이 복구 대상이 아니에요.

## 거절 뒤 자동 다시 생성

본문 실행이 거절 판정(`MAIN_RESPONSE_REFUSED`), 프로바이더의 거절·안전 차단(`refused`), 또는 프로바이더가 정상 종료했지만 글과 도구 호출이 모두 비어 있는 응답(`EMPTY_COMPLETION`)으로 끝나면 서버가 같은 요청을 새 실행으로 다시 보내요. 기본값은 켜짐·최대 2회이고, **앱 설정 → 새 채팅 기본값**에서 바꾸며 채팅의 **고급 실행 설정**에서 그 채팅만 켜거나 끌 수 있어요. 채팅에서 정하지 않으면 전역 값을 따르므로 기존 채팅에도 적용돼요. 판단은 실행이 끝나는 시점의 채팅 설정으로 해요.

다시 생성은 수동 **다시 시도**와 같은 `retryRun` 경로로 `retryOf`가 앞 실행을 가리키는 일반 실행을 만들어요. 그래서 채팅당 실행 하나, 멱등 키, 수정 번호 확인이 그대로 적용되고, 각 시도는 자기 호출 한도(`maxCalls`)와 사용량을 따로 가져요. 거절된 실행의 글·오류·사용량·attempt는 바뀌지 않아요. 횟수는 `retryOf` 사슬에서 자동 재시도 키(`auto-refusal-retry:<거절된 실행 ID>`)를 가진 실행을 거슬러 세므로, 사용자가 직접 다시 시도하면 새로 0부터 세요. 한도에 닿으면 마지막 거절 실행이 그대로 남아 수동 다시 시도를 기다려요.

사용자 취소, 서버 종료·점검, 인증·연결 실패, 결과를 알 수 없는 오류, 호출 한도·컨텍스트 한도 초과, 판정 실패, 판정만 다시 시도한 실행의 거절, 실행 뒤 이야기가 진행됐거나 장면이 삭제된 경우는 다시 보내지 않아요. 거절 기록과 다음 실행 접수는 한 트랜잭션이라 둘 다 남거나 둘 다 남지 않아요. 접수 뒤 시작 전에 서버가 멈추면 다음 실행은 다른 실행처럼 `interrupted`로 끝나요. 같은 거절 실행의 키는 하나뿐이라 두 번 접수되지 않아요. 다음 실행이 접수된 거절에는 실패 푸시 알림을 보내지 않고, 다시 보내지 않아 거절이 최종 결과가 될 때만 보내요. 구현은 `server/run-retry.ts`의 `finishRefusalWithAutomaticRetry`, `server/run-executor.ts`이고 `tests/run-auto-refusal-retry.test.ts`, `tests/main-judgment.test.ts`가 확인해요.

번역의 거절 재시도는 별도 정책(번역 정책의 `maxRetries`, 기본 1회)으로 같은 번역 작업 안에서 반복하며 이 설정과 독립적이에요.

## 번역

번역은 원문 전체를 한 번에 대상으로 삼아요. 새 작업은 현재 번역 모델·프롬프트·정책과 해당 원문 및 필요한 컨텍스트를 사용해요. 실행 중인 번역은 예약한 입력을 유지하며, 늦게 끝난 작업이 더 최신 원문이나 사용자가 수정한 번역을 덮어쓰지 않도록 확인해요.

**설정 → 역할별 모델 → 번역 참고 범위**에서 입력 범위를 고를 수 있어요. 기본값인 **관련 자료 포함(기존)**은 봇·페르소나·로어·직전 두 원문·이야기 메모와 필요한 자료 조회를 유지해요. 자동 요약을 여기에 추가로 붙이지는 않아요. **본문과 번역 지침만**은 선택한 번역 프롬프트, 현재 봇의 번역 지침·표기 목록과 현재 원문 전체를 보내요. 배경 자료·이전 장면·메모·자료 목록을 제외하고 이를 다시 읽는 도구도 제공하지 않아요. 배경에 의존하는 프롬프트의 슬롯과 카드 변수는 비워지지만, 선택한 프롬프트의 자체 기본값과 조작값은 유지해요. 원문 식별·결과 검증용 메타데이터와 선택한 모델의 평가 도구 계약은 유지해요.

참고 범위는 작업 접수 시 고정돼요. 진행 중인 작업과 판정만 재시도하는 작업은 당시 설정을 유지하고, 현재 설정으로 새 번역·재번역하면 새 범위를 사용해요. 설정이 없던 과거 작업은 기존 범위로 처리해요. 본문만 보내면 입력량을 줄일 수 있지만 이전 장면에만 있는 호칭·화자 관계는 참고하지 못하므로, 필요한 작품별 선택은 번역 지침에 적어 주세요.

기존 범위에서도 메모 본문과 이미 전달한 고정 자료의 목록 메타데이터를 중복해서 보내지 않아요. 추가 자료 목록은 항목별 80토큰 이내의 짧은 설명과 전체 6,000토큰(로컬 추정) 예산으로 제한하고, 나머지는 기존 검색·읽기 도구로 접근해요. 원문과 직전 두 원문은 이 정리로 잘라내지 않아요.

과거 번역을 표현 참고로 준비할 때는 현재 원문의 식별자·해시와 완료된 번역 결과를 조회해요. 사용하지 않는 원문 표시 블록과 과거 번역 작업의 실행 입력은 불러오지 않아요. 예약된 대화 이력·원문 해시와 일치하는 유효한 완료 번역만 선택하며, 원문 수정·다른 채팅·잘못된 결과를 제외하는 검증은 유지해요.

번역 거절 감지는 본문과 독립적으로 설정하며 기본 켜짐이에요. 판단 프로바이더에는 번역 후보 전체를 보내요. 후보가 원문과 정확히 같을 때만 그 사실을 덧붙이고 원문은 별도로 보내지 않아요. 원문 속 화자의 거절과 모델 자신의 번역 거절을 구분해 달라고 요청하며, 명시적 거절에 한해 정책에서 지정한 횟수만 다시 번역해요. 빈 응답·부분 출력·HTTP 오류·취소는 자동으로 새 번역을 반복하지 않아요. 이전 성공본이 현재 원문에 유효하면 재번역 실패 후에도 계속 보여줘요.

번역 생성 후 판정만 실패한 경우에는 **번역 판정만 다시 시도**로 후보를 재사용해요. 완성된 번역 후보는 판단 모델을 호출하기 전에 저장하므로 판정 대기 중 서버가 종료되어도 유지해요. 재시작만으로 번역이나 판정을 자동 재호출하지 않아요. 원문이 달라졌거나 더 최신 번역이 있으면 복구 대상에서 제외해요. 직접 번역 수정과 저장된 원문/번역 보기 전환은 모델을 호출하지 않아요.

## 다시 쓰기와 독립 사본

**다시 쓰기**에서 실제 생성에 사용할 요청을 확인하고 **새 채팅에서 다시 요청 / 기존 응답 교체**를 골라요. 중간 장면은 해당 위치까지 새 채팅 사본을 만들고, 마지막 완료 응답은 교체도 선택할 수 있어요. 교체는 새 생성이 성공한 뒤에만 적용하며 실패·취소하면 기존 응답을 유지해요. 실행 문구 수정만으로 과거 문맥용 요청을 저장하지 않아요. 이후 요청에는 현재 자료와 설정을 사용해요. 원본의 미래 메시지와 사본은 독립적이며, 과거 입력 snapshot을 공유하는 후보 분기 그래프는 사용하지 않아요.

같은 통신 요청을 재전송하면 같은 결과를 반환해 중복 생성을 막아요. 새 재작성 요청은 새로운 실행이며, 외부 프로바이더에게 이미 전송한 불확실한 요청을 서버 재시작만으로 다시 보내지 않아요.

구현 진입점은 `server/model-runner.ts`, `server/run-retry.ts`, `server/main-judgment.ts`, `server/product-auxiliary.ts`, `server/source-editing.ts`예요. 합성 테스트로 데이터 흐름과 저장 동작을 확인해요.

번역 요청 시 [봇별 번역 지침](TRANSLATION-GUIDES.md)을 현재 저장본에서 읽어 해당 작업에 고정해요. 기존 번역은 자동 교정하지 않으며, 새 번역·재번역에만 새 지침을 사용해요. 판정만 재시도할 때는 기존 후보와 지침을 유지해요.

번역의 선택적 자료 조회는 누적 96KB 바이트 상한 대신 실제 모델 요청의 토큰 예산으로 판단해요. 다음 요청에 들어가지 않는 조회 결과는 더 좁게 읽거나 확보한 근거로 원문 전체 번역을 마칠 수 있는 복구 가능한 결과로 돌려줘요. 원문을 잘라 공간을 만들거나 새 요약 모델을 자동 호출하지 않아요.

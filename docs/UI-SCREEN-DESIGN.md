# 공통 UI 화면 설계 · 설정과 서재

> 2026-09-08 후속: 채팅 리더·입력창·탐색과 서재 목록·상세의 배치는 [UI 설계 v2](UI-DESIGN-V2.md)가 대체 제안해요. 이 문서의 설정 탐색·연결과 모델·데이터 관리 절은 그대로 유효하고, 서재 절이 v2와 다르면 v2를 우선해요(데스크톱 폴더 패널 → 폴더 드롭다운, 상세의 역할 카드 → 주 행동 하나와 메뉴). v2는 제안이며 구현·검증 전이에요.

2026-09-08 [UI·아이콘 원칙](UI-PRINCIPLES.md)을 실제 화면으로 구체화한 검토용 설계예요. 범위는 데스크톱·모바일의 서재, 설정 탐색, 연결·모델, 데이터 관리와 관련 메뉴·상태예요. 합성 자료를 사용한 시안이며 제품 코드의 구현·동작 검증이나 운영 화면의 완료 증거는 아니에요.

## 사용 흐름과 화면 책임

| 흐름 | 시작 | 다음 화면 | 완료 후 |
| --- | --- | --- | --- |
| 자료로 대화 시작 | 서재에서 분류·폴더·검색으로 찾기 | 자료 상세 또는 해당 자료의 채팅 시작 | 기존 새 채팅 흐름에서 봇·모델 확인 |
| 자료 수정 | 자료의 편집 또는 항목 메뉴 | 이름·본문 중심 편집, 선택 설정은 접기 | 저장 후 같은 자료로 복귀, 취소·오류는 초안 보호 |
| 자료 정리 | 목록 관리 또는 폴더 관리 | 정렬·보기·선택·이동 등 해당 작업 | 기존 검색·폴더·선택을 작업 결과에 맞춰 유지 |
| 모델 관리 | 설정 → 연결과 모델 | 모델 목록 → 해당 모델 편집 | 저장 후 모델 목록과 선택 위치로 복귀 |
| 첫 연결 준비 | 연결이 없는 상태의 연결 시작 | 기존 제공자 선택 → 연결 → 모델 등록 흐름 | 모델 목록에서 다음 설정을 확인 |
| 백업과 복원 | 설정 → 데이터 관리 | 형식을 골라 받기 또는 파일을 골라 복원 | 성공·거부·실패를 구분하고 현재 조건 표시 |

자료 행을 여는 행동은 **상세 보기**, `새 채팅`은 **기존 새 채팅 흐름 시작**이에요. 상세를 읽으려고 눌렀는데 채팅이나 모델 호출이 시작되지 않아요. 연결·모델 목록 조회와 설정 변경도 응답 테스트·모델 호출을 자동으로 시작하지 않아요.

## 비교할 세 배치

공통 색상·기능 이름·아이콘 규칙·저장 동작을 고정하고 화면 구성만 비교해요. 명칭은 설계 방향 식별자이며, 채팅에 표시되는 시안 번호와의 연결은 실제 이미지 표시 순서를 따라요.

| 방향 | 데스크톱 서재 | 모바일 서재 | 적합성과 비용 |
| --- | --- | --- | --- |
| 본문 우선 목록 | 이름이 있는 탐색과 편안한 폭의 한 열 목록 | 같은 목록과 간단한 조작부 | 기본 추천. 기존 흐름의 변화가 작고 긴 이름·설명에 유리. 상세는 열어서 확인 |
| 목록과 미리보기 | 좁은 자료 목록과 선택 자료 상세를 병치 | 목록→자료 상세 단계 전환 | 여러 자료를 비교할 때 유리. 선택·상세·복귀 상태의 관리가 더 필요 |
| 가벼운 컬렉션 | 자료를 두 열의 가벼운 항목으로 표시 | 한 열의 짧은 가로 항목 | 자료를 시각적으로 훑는 데 유리. 긴 설명과 많은 자료에서는 목록보다 정보 밀도가 낮아질 수 있음 |

각 시안은 데스크톱 서재·모바일 서재·데스크톱 연결과 모델·모바일 연결과 모델을 같은 언어로 보여줘요. 목록과 미리보기 방향의 모바일 서재는 자료를 연 **상세 단계**를 보여줘요. 이미지의 합성 자료·연결 이름은 실제 저장 자료나 실행 결과가 아니에요.

## 서재 · 기본 추천 배치

### 데스크톱

- 왼쪽 탐색은 약 224px에서 시작하고 `서재`, `프롬프트`, `설정`을 아이콘과 이름으로 표시해요. 현재 위치를 하나만 강조해요.
- 본문은 제목·만들기, 분류 탭, 찾기 도구, 자료 목록 순서예요. 제목은 한 번만 보여주고 반복 소개 문구는 제거해요.
- 분류는 `봇`, `페르소나`, `모듈`의 짧은 탭이에요. 역할 설명은 빈 화면이나 필요한 도움말에서 제공해요.
- 찾기 도구는 현재 폴더, 유연한 폭의 검색, 목록 관리 순서로 같은 줄에 배치해요. 줄이 부족하면 좁은 화면의 그룹 구성으로 전환해요.
- 한 열 목록은 약 760~860px에서 시작해 읽기 쉬운 폭을 비교해요. 아바타, 자료 이름, 짧은 설명, 채팅 시작, 항목 메뉴를 일정한 열에 맞춰요. 각 행에 큰 초록색 버튼을 반복하지 않아요.
- 목록과 미리보기 방향은 이 본문을 목록과 상세로 나누고, 컬렉션 방향은 항목을 두 열로 바꿔요. 기능과 메뉴의 이름은 같아요.

### 모바일

- 첫 줄은 56px 안팎의 헤더예요. 왼쪽 탐색, `서재`, 오른쪽 만들기를 두고 별도의 `봇` 상단 제목이나 두 번째 `서재` 제목을 쌓지 않아요.
- 본문 조작부는 **분류 탭 → 폴더 선택 → 검색과 목록 관리**로 구성해요. 폴더 선택 아래에 선택된 폴더를 다시 칩으로 표시하지 않아요.
- 기본 글자 크기에서 첫 자료 행이 헤더 포함 약 220~240px 안에서 시작하는 것을 설계 목표로 해요. 글자 확대나 오류 표시 때는 자연스럽게 늘어나며 이 목표를 맞추기 위해 내용을 잘라내지 않아요.
- 항목은 전체 폭을 사용해요. 이름은 필요하면 두 줄까지, 요약은 짧게 보여주고 전체 설명은 상세에서 읽어요. 아바타가 텍스트 폭을 밀어내지 않아요.
- 자료 이름·본문 영역은 상세를 열고, 별도 채팅 행동은 새 채팅 흐름을 열어요. 항목 메뉴는 그 자료에 귀속돼요.
- 모바일 상세는 `서재로 뒤로가기`, 현재 자료, 항목 메뉴를 보여줘요. 이름·설명·주된 `새 채팅` 행동을 먼저 두고 편집·관리와 구분해요.

### 서재의 메뉴와 상태

| 위치 | 내용 | 동작 기준 |
| --- | --- | --- |
| 목록 관리 | 정렬, 목록/컬렉션 보기, 여러 자료 선택 | 메뉴 안에서 현재 선택을 표시. 사용자 보기 선호를 유지 |
| 폴더 관리 | 새 폴더, 현재 폴더 이름 변경·삭제 등 기존 가능한 행동 | 전체/미분류에서는 불가능한 이름 변경·삭제를 제공하지 않기 |
| 자료 메뉴 | 편집, 이동, 삭제 등 현재 지원하는 행동 | 자료 이름을 대상으로 삼고 기존 참조·삭제 보호 유지 |
| 선택 모드 | 선택 개수, 이동 등 유효한 작업, 선택 종료 | 일반 도구를 모두 추가로 쌓지 않고 같은 도구 영역을 선택 작업으로 전환 |
| 전체 자료가 없음 | 짧은 안내와 만들기 | 검색·정렬·선택 숨김. 만들기 행동을 헤더와 중앙에서 중복 강조하지 않기 |
| 폴더만 비어 있음 | 현재 폴더, 전환, 만들기·이동 안내 | 전체 자료가 없는 것으로 설명하지 않기 |
| 검색 결과가 없음 | 검색어, 활성 조건, 지우기 | 검색창과 복구 경로 유지 |
| 로딩·오류 | 로딩 또는 오류 문구, 필요할 때 다시 읽기 | 기존 목록·검색을 보존하고 실패를 빈 목록으로 바꾸지 않기 |

## 설정 · 탐색과 상세

데스크톱은 왼쪽 설정 항목과 오른쪽 상세를 나란히 보여줘요. 설정 안에서는 앱의 전역 탐색까지 중복해서 배치하지 않아요. 모바일은 먼저 설정 항목 목록을 보여주고 선택하면 상세로 이동해요.

항목과 순서는 `일반`, `연결과 모델`, `에이전트`, `데이터 관리`, `접근 보안`이에요. 한 항목에는 아이콘과 이름을 함께 두고 선택 상태·초점 상태를 구별해요. 모바일 상세 헤더는 **뒤로가기 · 현재 항목 이름 · 닫기**로 구성하며 전체 항목 메뉴를 상단에 남기지 않아요.

`뒤로가기`는 설정 항목 목록으로, `닫기`는 설정 진입 전 화면으로 돌아가요. 미저장 편집이 있으면 기존 초안 보호 절차를 적용해요. 데스크톱에서 다른 설정 항목을 선택할 때도 같은 보호 규칙을 적용해요. 화면 크기가 바뀌어도 현재 항목과 편집 상태를 유지해요.

미저장의 범위는 편집 중인 초안과 아직 응답이 오지 않은 저장 요청이에요. 저장이 인정되어 "저장했어요"를 표시한 뒤 이어지는 화면 새로고침은 미저장으로 보지 않으므로, 그 사이에 닫아도 초안 보호 확인을 묻지 않아요(2026-09-08 채팅 설정의 프로필·상태와 기억·자동 후속 작업 패널에 적용). 브라우저 검사에서 저장 뒤 닫기를 확인할 때는 서버 상태가 아니라 패널의 저장 인정 문구를 기다려요.

## 연결과 모델

- 현재 항목 제목 아래에 얇은 `모델`·`연결` 탭을 놓고 목록 새로고침 아이콘을 같은 줄 오른쪽에 배치해요. 0개의 탭 개수는 필요하지 않으면 생략하며 개수를 여러 위치에 반복하지 않아요.
- 목록이 있을 때 검색과 해당 목록의 추가 행동을 제공해요. 모바일에서는 검색과 추가를 명시적으로 배치하고 새로고침만 혼자 다음 줄로 보내지 않아요.
- 모델 항목은 프리셋 이름과 연결 이름을 실제 텍스트로 보여줘요. 상태가 필요하면 짧은 문구로 표시해요. 복제·비활성화·삭제 등은 항목 메뉴에서 열어요.
- 연결이 전혀 없으면 `연결 시작`을 주된 행동으로 두고 기존 제공자 선택 흐름으로 연결해요. 모델 추가·빠른 연결·제공자 선택 버튼을 같은 빈 화면에서 경쟁시키지 않아요.
- 연결은 있지만 모델이 없으면 모델 추가를 주된 행동으로 보여줘요. 검색 결과만 없을 때는 검색과 해제 경로를 유지해요.
- 편집 화면은 필수 이름·연결·모델 선택부터 보여주고 고급 옵션을 필요할 때 열어요. 필수 입력 오류는 필드 가까이에 표시하고, 접힌 영역에 오류가 있으면 해당 영역을 찾을 수 있게 요약해요.
- 저장·취소는 편집 대상과 가까운 하나의 행동 영역을 사용해요. 긴 모바일 폼에서는 입력 중에도 도달할 수 있게 하되 키보드와 겹치는 이중 고정 막대를 만들지 않아요. 저장 중 중복 실행을 막고 실패한 초안을 유지해요.

## 데이터 관리

`백업 받기`와 `가져오기` 두 구역으로 나눠요. JSON과 SQLite는 각 형식의 짧은 용도를 선택하는 위치에 보여주고, 상세 보관 범위·서버 경로·종료 절차는 도움말로 제공해요.

가져오기는 파일 선택, 선택한 파일 이름, 복원 가능 조건, 실행 행동의 순서예요. 빈 DB 복원 조건은 접지 않아요. 파일이 없거나 현재 DB로 복원할 수 없는 경우 이유를 가까이 표시하고 실행을 차단해요. 복원 거부나 실패를 성공처럼 처리하지 않아요. OS 파일 선택 UI는 기본 기능을 유지하면서 주변 라벨과 간격을 정리해요.

## 아이콘 명세

현재 `lucide-react` 계열을 이어가는 후보예요. 실제 적용 때 설치된 export와 화면의 구별 가능성을 확인해요. 이 표는 새 아이콘 라이브러리나 별도 그림 자산을 요구하지 않아요.

| 의미 | 후보 아이콘 | 기본 문구 정책 |

| 편집 / 새 채팅 | Pencil / MessageSquarePlus | 원문 직접 저장·새 생성의 구별이 필요하면 이름 유지 |
| 목록 / 컬렉션 | List / LayoutGrid | 목록 관리 안에서 선택 상태와 이름 표시 |
| 백업 받기 / 가져오기 | Download / Upload | 형식·방향이 중요한 선택 위치에서 이름 유지 |

기본 그림 크기는 18~20px, 터치·클릭 영역은 최소 44×44 CSS px에서 시작해요. 아이콘의 실제 의미는 접근 가능한 이름으로 제공해요. 색상·hover·툴팁만으로 의미나 필수 상태를 전달하지 않아요. 더보기를 열면 메뉴 안에는 아이콘과 행동 이름을 함께 보여줘요.

## 설계의 확인 상태

이 절은 시안 작성 당시의 확인 상태예요. 이후 실제 구현과 검증은 [공통 UI 결과](../project-plan/UI-COMPACT-IMPLEMENTATION.md)와 [상세 화면 결과](../project-plan/UI-DETAIL-IMPLEMENTATION.md)에서 확인해요.

- 근거는 이번 대화의 사용자 사진, 현재 소스의 UI·색상 규칙, 이전 UI 개선에서 보관한 합성 화면이에요. 보관 화면은 참고 자료이며 이번 실행의 재현 결과는 아니에요.
- 이미지 시안은 정보 배치와 시각적 위계를 비교하는 자료예요. 생성 이미지에서 글자·아이콘·간격이 일부 다르면 이 문서와 원칙의 동작·접근성 계약을 우선해 실제 구현에서 맞춰요.
- 빈 화면·메뉴·오류·편집 복귀는 위 명세로 정의했으며 아직 동작을 구현하거나 검증하지 않았어요. 이미지에 보이는 합성 연결을 실제 공급자 성공으로 해석하지 않아요.
- 시안 선택 뒤에는 해당 배치를 기준으로 기존 제품 컴포넌트에 적용하고, 변경된 대표 흐름의 모바일·중간 폭·데스크톱 검사와 실제 S25U 확인을 분리해 기록해요.

이미지와 생성 프롬프트는 이 작업의 로컬 `output/design/uimori-ui-2026-09-08/`에 보관해요. 해당 경로는 Git 제외 산출물이며 다른 환경에서는 없을 수 있어요. 이 문서와 [공통 원칙](UI-PRINCIPLES.md)이 텍스트 설계 계약이에요.

### 시안 검토와 보정 항목

실제 채팅 표시 순서는 [시안 1](../output/design/uimori-ui-2026-09-08/01-reading-list.png), [시안 2](../output/design/uimori-ui-2026-09-08/02-master-detail.png), [시안 3](../output/design/uimori-ui-2026-09-08/03-light-collection.png)이에요. 내장 Image Gen으로 생성했으며 정확한 프롬프트·참고 이미지 목록은 [prompts.json](../output/design/uimori-ui-2026-09-08/prompts.json), 이미지 크기와 SHA-256은 [artifacts.json](../output/design/uimori-ui-2026-09-08/artifacts.json)에 있어요.

- 세 이미지에서 서재의 목록/미리보기/컬렉션 구조, 데스크톱 설정의 항목 목록, 모바일 설정 상세의 한 줄 탐색을 확인했어요. 실제 클릭·반응형·초점 동작의 검증은 아니에요.
- 이미지 안의 `1440×1024`, `390×844` 표시는 요청한 목표 화면 크기예요. 생성된 화면 비율·픽셀 치수와 일치하는 실측 캡처가 아니므로 여백·글자·터치 영역을 이미지에서 측정해 합격 판정하지 않아요.
- 시안 1의 임시 테스트 식별자와 반복 개수, 시안 2의 자료 상세 위 중복 헤더·설명·임의 모델 설명/날짜, 시안 3의 반복 개수는 최종 적용 대상에서 제외해요. 합성 자료의 개수·이름도 일관되게 맞춰야 해요.
- 각 이미지에서 목록 새로고침의 위치, 채팅 시작 문구, 개념별 아이콘 일부가 공통 명세와 달라요. 선택된 방향을 구현할 때 이 문서의 같은 줄 배치·명확한 행동 이름·아이콘 의미 기준으로 보정해요.
- 이번 선택은 정보 배치의 방향을 고르는 단계예요. 세 이미지의 모든 문구와 세부 배치를 확정한 것으로 취급하지 않아요.

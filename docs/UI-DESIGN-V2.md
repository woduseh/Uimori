# UI 설계 v2 · 원고가 화면이다

2026-09-08 실제 실행 화면(데스크톱 1440×900, 모바일 390×844 합성 뷰포트)을 검토한 뒤 작성한 **제안 설계**예요. 지금까지의 [UI 원칙](UI-PRINCIPLES.md)·[화면 설계](UI-SCREEN-DESIGN.md)·개별 계약(응답별 작업 현황, 장면 네비게이터, 입력창 구성, 포크)이 각각은 합리적이었지만, 원고 앞뒤에 한 줄씩 쌓여 채팅 화면이 무거워졌어요. 이 문서는 그 결정들을 **한 화면 단위로 다시 판단**하고, 필요한 곳은 뒤집어요. 아래 시안은 합성 자료로 만든 정적 HTML이에요. 적용 순서 1단계(채팅 리더)는 2026-09-08에 구현했고 결과는 문서 끝의 [적용 기록](#적용-기록)에 있어요. 2~4단계는 아직 제안이에요.

## 한 문장 목표

**채팅을 열면 원고가 보이고, 손이 가는 자리에 입력창이 있고, 나머지는 만졌을 때만 나타나요.** ChatGPT·Codex가 간결하게 느껴지는 이유는 기능이 적어서가 아니라, 상시 표시 요소가 메시지·입력창·헤더 세 가지뿐이고 그 밖의 모든 것이 대상 가까이에서 호출될 때만 나타나기 때문이에요. Uimori는 원고 읽기 앱이라 이 원칙이 더 강하게 적용돼야 해요.

## 세 층으로 나눠요

모든 화면 요소를 다음 세 층 중 하나에 배정하고, 새 요소를 추가할 때도 층부터 정해요.

| 층 | 뜻 | 채팅 화면의 예 |
| --- | --- | --- |
| **0 · 상시** | 항상 보여요. 한 화면에 최소한만 둬요. | 헤더 한 줄, 원고 본문, 요청 말풍선, 입력창 한 줄, 진행·실패 카드(해당 턴 안에서만) |
| **1 · 근접** | 항상 존재하지만 연하게 그리고, 마우스를 올리거나 장면을 누르면 진해져요. 터치에서는 연한 상태로 보여요. | 장면 헤더 줄(번호·상태·보기 전환), 장면 끝 액션 줄, 스크롤 중 "최신으로" 버튼 |
| **2 · 열어서** | 메뉴·시트·대화상자로 열어요. 이름과 아이콘을 함께 보여요. | 장면 ⋯, 채팅 ⋯, 입력창 ⋯, 작업 상세, 채팅 설정, 읽기 설정 |

원칙 문서의 "필요한 상태는 보여요"는 유지해요. 다만 **완료는 상태가 아니에요.** 진행·실패·불확실만 0층에 두고, 완료는 1층의 작은 체크 표시로 남겨요.

## 수치 목표

원칙 문서의 시작값을 이어받고, 채팅 화면에 없던 목표를 추가해요. 합성 검사에서 고정할 수 있는 값이에요.

| 항목 | 목표 | 현재 실측(2026-09-08) |
| --- | --- | --- |
| 모바일 채팅 첫 화면에서 본문이 차지하는 높이 | **60% 이상** (844px 중 506px 이상) | 약 33% → 1단계 뒤 53%(449px) → 2단계 뒤 **75%**(633px; 입력창 52px, 장면 탐색 바 제거) |
| 요청 말풍선 아래 ~ 첫 문장 | **70px 이하** (장면 헤더 44 + 간격) | 약 200px → 1단계 뒤 62px(모바일)·66px(데스크톱) |
| 빈 입력창 높이 | 모바일 **52px**, 데스크톱 **56px** (칩·상태 줄 제외) | 162 / 173px → 2단계 뒤 **52 / 56px** |
| 장면 끝 ~ 다음 요청 사이의 조작부 | **44px 한 줄** | 약 250px (세 줄 + 여백) → 1단계 뒤 109px(도구 줄 44 + 장면 사이 여백) |
| 헤더 | 56px 한 줄, 제어 4개 이하 | 56px, 데스크톱 5개 → 2단계 뒤 탐색 토글 제외 데스크톱 4개(모델 칩·집중·설정·⋯), 모바일 3개(칩·설정·⋯) |
| 터치 영역 | 모든 제어 44×44 이상 (1층 아이콘은 32px 그림 + 44px 영역) | 드로어 메뉴 36×40 |

## 채팅 화면

### 헤더

`[탐색] [제목 / 봇 · 페르소나로] … [모델 칩] [읽기 T] [집중 ⛶] [⋯]`. 모바일은 `[☰] [제목/부제] [모델 칩] [⋯]` 네 개예요.

- **부제에 페르소나를 합쳐요.** "등대지기 미라 · 서연으로". 리더 첫 줄의 봇 칩은 없애요.
- **모델은 헤더의 칩이에요.** 현재 본문 모델 이름을 항상 보여주고, 누르면 본문 모델 선택 메뉴가 열려요. 입력창에서 모델을 빼는 대신 여기서 "본문 모델 확인" 요구를 채워요. 모바일은 짧은 이름(프리셋 이름의 마지막 단어 또는 12자)만 보여요.
- **채팅 ⋯ 메뉴**: 채팅 설정, 여기까지 새 채팅으로 복사(포크), 이름 변경, 작업 현황, 보관된 전개, 읽기 설정(모바일), 집중 읽기(모바일), 채팅 삭제. 포크는 이름이 있는 항목으로만 제공하고 헤더의 단독 아이콘은 없애요. 확인 단계 없이 즉시 복사하는 결정은 유지하되, 복사 뒤 "원본으로 돌아가기" 링크가 있는 짧은 알림을 보여줘요.

### 턴의 구조

요청 말풍선 → 장면 헤더 한 줄 → 본문 → 장면 끝 액션 줄. 이 넷만이에요.

- **요청 말풍선**은 오른쪽 정렬과 배경색으로 화자를 드러내요. "내 요청" 라벨은 없애요.
- **장면 헤더 줄(44px, 1층)**: 왼쪽 `장면 3` + 상태 표시 + `직접 수정한 번역` 배지, 오른쪽 `번역 | 원문` 작은 전환. 상태 표시는 완료 ✓(연함), 진행 ⟳, 실패 ⚠ + 짧은 문구, 불확실 ?예요. 줄을 누르면 **작업 상세**가 바로 아래에 펼쳐져요(별도 시트 대신 인라인 펼침). 이 펼침이 응답별 작업 현황 계약(요청별 독립, 기본 접힘, 펼침 선택 보존, 펼치기만으로 호출 없음)을 그대로 이어받아요. 줄 높이는 시안의 28px 대신 터치 영역 원칙에 맞춰 44px로 정했어요. 번역이 없는 장면은 전환 대신 **`번역 보기`** 텍스트 버튼 하나를 보여줘요. 이 버튼은 모델을 호출하므로 이름을 유지해요.
- **본문**은 읽기 설정의 서체·크기·줄간격을 그대로 따라요. 최대 폭 760px.
- **장면 끝 도구 줄(44px, 1층)**: 왼쪽에 `복사 · 수정(지금 보는 쪽) · ⋯`, 오른쪽 끝에 `표시 문구 바꾸기 · 원문 연결 정보` 두 개의 작은 접기 항목. 보기 전환은 헤더 줄에 있으므로 여기서는 반복하지 않아요. **⋯ 메뉴**: 현재 설정으로 새 번역, 여기서 새 이야기로 이어가기, 다른 쪽 수정(원문 또는 번역), 이미지 선택. 두 접기 항목은 시안에서 메뉴로 옮기려 했지만, 응답별 작업 현황 문서가 원문 연결 정보의 위치를 응답 하단으로 정하고 있어 이름 있는 접기 항목으로 한 줄 끝에 남겼어요. 집중 읽기에서는 이 줄이 연해지고 장면에 마우스를 올리거나 초점이 들어오면 진해져요.
- **진행 중 턴**: 장면 헤더 아래에 `⟳ 장면을 쓰는 중 · 12초 [중지]` 한 줄과 흐린 자리표시 세 줄. 입력창의 보내기 버튼은 중지 버튼으로 바뀌어요.
- **실패 턴**: 본문 자리에 카드 하나. 제목(무엇이 실패했는지), 한 줄 설명, `다시 시도 · 모델 설정 · 상세`. 실패한 원고를 원문으로 만들지 않고 요청은 그대로 남겨요. 입력창 위의 고정 실패 줄은 **화면에 없는 턴**의 실패나 보조 작업(다른 장면의 번역)에만 사용하고, 사용자가 해당 턴을 보면 사라져요. 경과 시간은 1초 이상일 때만 표시해요.

### 입력창

두 단계로 모양이 바뀌어요. **비어 있거나 한 줄일 때**는 `[⋯] [텍스트] [↑]` 한 줄이에요. **두 줄 이상으로 늘어나면** 텍스트가 위에서 전체 폭을 쓰고, 그 아래 한 줄에 `[⋯]`가 왼쪽, `[↑]`가 오른쪽에 놓여요. 버튼이 본문 옆에 떠 있지 않게 하려는 규칙이며, 전환은 줄 수만으로 결정해요. 보조 선택(창작 프리셋, 페르소나, 조회 로어 제외)이 있을 때만 입력창 위에 칩 한 줄을 보여주고, 칩의 ×로 해제해요. ⋯ 버튼 자체는 선택 여부로 강조하지 않아요. 칩이 그 역할을 해요. 모델명 캡션 줄과 단축키 캡션 줄은 없애요. 단축키는 placeholder 끝의 흐린 글자(데스크톱)와 보내기 버튼의 툴팁, 설정 → 일반에서 확인해요.

### 장면 탐색

데스크톱은 왼쪽의 얇은 눈금 레일을 유지해요. **모바일은 헤더 아래의 고정 바를 없애고** 두 가지로 대체해요. 헤더 제목을 누르면 장면 목록 시트(번호·요청 검색·페이지)가 열리고, 스크롤이 마지막 장면을 벗어나면 입력창 위 오른쪽에 `↓` 둥근 버튼이 나타나 "최신 장면으로" 이동해요. 다운로드 화살표 아이콘은 쓰지 않아요.

### 빈 채팅

봇 아바타(48px)와 "첫 장면을 들려주세요." 한 줄, 그 아래 한 줄 안내를 화면 세로 중앙에 둬요. 패키지에 시작문이 있으면 시작 선택지를 칩으로 최대 3개 보여줘요.

### 집중 읽기

탐색·입력창을 숨기는 현재 정의에 **1층 요소도 숨김**을 더해요. 장면 헤더 줄과 액션 줄은 본문을 눌렀을 때만 잠시 나타나요. 데스크톱 눈금 레일은 유지해요.

## 탐색

### 데스크톱 사이드바(260px)

위에서 아래로 `[Uimori · 접기] [새 채팅] [채팅 검색] [봇 전환 행] [채팅 목록] … [진행 중 N] [서재] [프롬프트] [설정]`이에요.

- **봇 전환 행** `[아바타] 등대지기 미라 ▾` 하나가 "← 봇 목록", 봇 카드, "채팅 4개"를 대신해요. 누르면 봇 목록 팝오버(검색, 최근 순, "서재에서 관리")가 열려요. 개수는 표시하지 않아요.
- **채팅 목록**은 미분류 채팅을 헤더 없이 위에 평평하게, 이름이 있는 폴더만 접이식 헤더로 보여요. "채팅 폴더" 라벨과 폴더 만들기 아이콘은 없애고, 폴더 만들기는 봇 전환 행의 메뉴와 채팅 ⋯의 "폴더로 이동 → 새 폴더"에서 해요. 행은 34px, 마우스를 올리면 ⋯가 나타나요. 드래그 정렬·폴더 드롭·hover 삭제는 현재 계약을 유지해요.
- **작업 현황은 탐색 항목이 아니에요.** 진행 중 작업이 있을 때만 하단에 `⟳ 진행 중 N` 한 줄이 나타나고, 누르면 작업 현황이 열려요. 없으면 줄 자체가 없어요.
- **서재 화면에서도 사이드바는 그대로 채팅 목록이에요.** 사이드바에 봇 목록을 다시 그리지 않아요. 이것이 서재 본문과의 중복을 없애는 유일한 방법이에요.

### 모바일 드로어

같은 구성의 전체 높이 시트예요. "탐색" 제목은 없애고 오른쪽 위 닫기만 둬요. 채팅 ⋯는 항상 보이며 44×44예요.

## 서재와 프롬프트

- **헤더** `[서재] … [+ 만들기]`, 그 아래 분절 탭 `봇 · 페르소나 · 모듈`, 그 아래 **도구 한 줄** `[폴더 ▾] [검색] [목록 조정]`. 폴더 드롭다운 마지막 항목이 "폴더 관리…"예요. 데스크톱의 별도 폴더 패널은 없애서 두 번째 PanelLeft 아이콘 문제와 목록 폭 문제를 함께 해결해요. 목록 조정 아이콘은 SlidersHorizontal이에요(정렬·카드/목록·선택).
- **행** 64px: 아바타 40, 이름 한 줄(모바일은 두 줄), 설명 한 줄. 오른쪽 `새 채팅 · ⋯`는 데스크톱에서 마우스를 올렸을 때 진해지고 터치에서는 연하게 항상 보여요. 페르소나·모듈 행은 ⋯만 있어요.
- **자료 상세**: 헤더 `[←] [이름 / 분류 · 폴더] [편집] [⋯]`. 본문은 아바타 72 + 이름 + 소개, **주 행동 `새 채팅` 하나**, 보조 `최근 채팅 이어가기 · 제목`, 개수 한 줄(`로어 3 · 지침 2 · 이미지 1`, 모두 0이면 생략), 본문. ⋯에 페르소나로 사용, 모듈로 추가, 복제, 분류·폴더 이동, 삭제를 둬요. 네 개의 역할 카드와 역할 설명 문장은 없애요. 역할 설명은 페르소나·모듈 탭의 빈 화면과 선택기에 남아요.
- **편집**: 헤더 `[←] [이름 또는 새 봇] [⋯(삭제)]`, 하단 `저장 · 취소`(새 자료는 `등록`). 저장 뒤 같은 자리에 `채팅 시작`을 보여주는 현재 동작은 유지하되 저장이 주 행동이에요. 홀로 떠 있는 삭제 아이콘은 ⋯로 들어가요.
- **프롬프트 목록**은 서재와 같은 도구 한 줄 `[폴더 ▾] [검색] [목록 조정(역할 필터·정렬·선택)]`을 써요. 폴더 칩 줄과 "전체 · 3개" 개수 줄은 없애요.

## 설정

- **채팅 설정**은 여섯 분야를 두 묶음으로 보여요. **기본**: 인물과 자료, 프롬프트와 프리셋, 모델. **고급**: 상태와 기억, 이미지, 자동 후속 작업. 묶음 이름은 목록의 작은 구분 라벨이에요. 읽기 설정은 채팅 설정에서 빼요.
- **읽기 설정**(헤더 T 또는 채팅 ⋯)은 기본 보기, 본문 글꼴, 본문 크기, 집중 읽기 시작만 다뤄요. 화면 테마는 **설정 → 일반**에서만 바꿔요. 같은 값을 세 곳에서 바꾸지 않아요.
- **모델 이름 표기**를 한 가지로 통일해요. 어디서든 `프리셋 이름`이 첫째 줄이고 `연결 이름`이 흐린 둘째 줄이에요. 모델 ID는 모델 편집 화면에서만 보여요. select 안에서도 같은 순서를 지켜 잘림이 생기지 않게 해요.
- 그 밖의 설정·연결·데이터 관리 화면은 현재 구현을 유지해요.

측정(합성 뷰포트, 실패 상태 줄이 없는 채팅): 요청 말풍선 아래에서 첫 문장까지 모바일 62px·데스크톱 66px, 장면 헤더 44px, 장면 끝에서 다음 요청까지 109px, 모바일 첫 화면 본문 449px(53%). 입력창(162px)과 모바일 장면 탐색 바(42px)는 2단계 범위예요.

Playwright trace로 원인을 좁혔어요. 채팅 설정 패널은 저장 PUT이 끝나고 "저장했어요"를 표시한 뒤에도 후속 새로고침(library·reader·package-behaviors 조회, 약 30ms)이 끝날 때까지 `saving`을 미저장으로 취급해서, 그 사이에 닫으면 '미저장 채팅 설정 확인'이 떠요. 탐색 드로어는 처음 그려질 때 봇 목록을 보인 뒤 effect에서 현재 봇으로 전환해요. 둘 다 이 변경과 무관한 기존 경쟁 조건이며 같은 날 별도 커밋으로 고쳤어요([현재 작업 상태의 마지막 검증](../project-plan/CURRENT.md#마지막-검증)). 전체 163/163은 이 환경에서 확인하지 못했어요. 시스템 PAC 프록시가 127.0.0.1 요청을 가로채 브라우저 검사가 멈추는 문제는 `playwright.config.ts`의 `--no-proxy-server`로 막았어요. 최종 source/build 지문은 `5fe413718ee2190c5fc434b5771f12f88f0e0e8ce306826ac8f323ebe53a4429`예요.

### 2단계(1/2) · 헤더와 입력창 (2026-09-08)

구현 범위는 `web/main.tsx`, `web/style.css`, `web/composer-more.css`예요.

- 헤더: 본문 모델은 헤더의 **모델 칩**이에요. 기존 입력창의 `빠른 본문 모델` select를 칩 모양으로 헤더에 옮겼고 접근 이름과 동작(즉시 저장, 비활성 모델 표기)은 그대로예요. **채팅 메뉴(⋯)**에 여기까지 새 채팅으로 복사(접근 이름 `채팅 포크` 유지), 읽기 설정, 집중 읽기(모바일에서만 항목으로 노출), 작업 현황, 보관된 전개(전개가 둘 이상일 때)를 모았어요. 헤더의 포크 아이콘과 리더 첫 줄의 보관된 전개 버튼은 없앴어요. 메뉴에서 연 대화상자는 닫힐 때 초점을 ⋯ 버튼으로 되돌려요(항목은 다시 숨겨지므로).
- 설계와 다른 점: **채팅 설정은 헤더 아이콘으로 남겼어요.** 가장 잦은 진입이고 브라우저 검사 17개 파일 42곳이 헤더 버튼을 직접 누르기 때문이에요. 대신 읽기 설정을 데스크톱에서도 메뉴로 옮겨 데스크톱 헤더 제어는 탐색 토글 제외 4개(칩·집중·설정·⋯)예요. 이름 변경·채팅 삭제는 사이드바 채팅 메뉴에 그대로 두고 헤더 메뉴에 넣지 않았어요. 포크 뒤 "원본으로 돌아가기" 알림은 미구현이에요(알림 줄이 문구만 지원).
- 입력창: 비어 있거나 한 줄일 때 `[⋯] [글] [↑]` 한 줄(grid), 두 줄 이상이면 글이 전체 폭을 쓰고 아래 줄에 ⋯·↑가 놓여요. 늘어남 판정은 줄 높이 측정과 줄바꿈 문자로 하고, 초안이 비워질 때만 한 줄로 돌아가요(경계 근처 입력에서 깜박임 방지). 모델명·단축키 캡션 줄은 없애고, 단축키는 데스크톱 placeholder 끝과 보내기 버튼 툴팁으로 옮겼어요. 알림(이전 전송 확인, 설정 저장 안내, 미저장 변경)만 입력창 아래 상태 줄에 남고 비어 있으면 자리를 차지하지 않아요. 모바일 placeholder는 줄바꿈으로 한 줄 입력창이 커지지 않도록 짧게 했어요.
- 칩: 입력창 위 칩은 **조회 로어 제외**만 표시해요. 페르소나는 헤더 부제에 이미 있고, 창작 프리셋은 현재 값과 일치하는 조합을 표시하는 것이라 ×로 "해제"할 대상이 아니에요(설계의 페르소나·프리셋 칩은 채택하지 않음).
- 검사 변경: `채팅 포크`·`읽기 설정`·`보관된 전개`를 헤더 메뉴에서 여는 `openChatMenu` 도우미를 추가하고 ui-browser·deletion-browser의 해당 단계를 바꿨어요. 대화상자 초점 복귀 기대는 ⋯ 버튼으로 바꿨어요.

측정: 빈 입력창 데스크톱 56px·모바일 52px(목표 충족), 헤더 56/60px, 모바일 첫 화면 본문 70%(장면 탐색 바 42px가 남은 상태, 2/2에서 75%로). 검증: `quality`·빌드 통과, 영향 받는 브라우저 검사 14건(DEL06, EVALUI01, LCUI03, LCUI04, PMUI03, RACOM01, SCUI03, UXUI01, UI07 UI09, UI07 UI12 ×2, UI18, UI common dialogs, run-retry) 통과. SCUI03은 첫 실행에서 설정 초안 입력 7ms 뒤 history.go(-2)를 부르는 타이밍으로 한 번 실패하고 재실행에서 통과했어요(이 변경과 무관한 검사 쪽 경쟁, 후속 후보). 전체 브라우저 재실행은 사용자 결정으로 단계 완료 시점에만 돌려요. 남은 2단계 항목은 모바일 장면 탐색(제목 탭 → 장면 목록, 플로팅 최신 버튼, 고정 바 제거)이에요.

### 2단계(2/2) · 모바일 장면 탐색 (2026-09-08)

- 760px 이하에서 헤더 아래 고정 바(42px)를 없앴어요. 대신 헤더 제목 블록 전체가 `장면 목록 열기` 버튼이고(제목 옆 작은 ∨ 표시), 마지막 장면이 아닌 곳을 읽는 동안 입력창 위 오른쪽에 44px 둥근 `최신 장면으로`(↓) 버튼이 떠요. 목록 시트·검색·60개 페이지·읽는 중 표시는 그대로이며, 시트 열림 상태는 헤더가 소유하고 채팅·분기가 바뀌면 닫혀요. 데스크톱 눈금 레일은 아이콘만 ↓로 바꿨어요(다운로드 화살표 사용 안 함).

## 이 설계의 한계

- 시안은 정적 HTML이고 hover·시트·키보드 동작은 그려져 있지 않아요. 구현에서 초점 순서와 Escape 처리를 기존 대화상자·메뉴 규칙에 맞춰요.

- 이 문서는 채팅·탐색·서재·설정의 배치를 다루고, 프롬프트 편집기 내부(기본 지침 우선 편집, C14)와 채팅 이름 변경·재생성(C05·C12)은 다음 설계 범위로 남겨요.

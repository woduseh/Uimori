# Risu 자료와 native JSON 가져오기

앱은 `.charx`·Character Card JSON·독립 `.risum`·Risu 모듈 JSON/프로젝트 ZIP을 읽어요. 새로 가져온 카드는 `ContentPackage.nativeRisu`의 원래 카드·모듈 문서를 실행·편집 기준으로 삼아요. CBS·정규식·트리거·Lua를 별도의 Uimori DSL로 번역하지 않아요. 프리셋 `.risup`·`.risupreset`은 아래 프리셋 경로를 사용하고, 플러그인 `.js`는 기존 격리 행동 어댑터를 유지해요. [라이선스와 원본 고지](../THIRD_PARTY_NOTICES.md)도 보존해요.

## Risu 캐릭터 카드

서재의 봇·모듈 탭에서 **Risu 자료 가져오기**를 열고 파일을 선택해요. 24 MiB를 넘는 파일은 [대용량 경로](#대용량-자료)로 먼저 올리고, 파일 자체는 최대 256 MiB까지 받아요. 봇을 가져오면 새 채팅을 만들고, 비어 있지 않은 기본 `first_mes`가 있으면 그 작성된 시작문을 즉시 열어요. 시작문이 없는 카드나 모듈은 자동 응답을 만들지 않아요. 가져오기 중 모델을 호출하거나 스크립트를 실행하지 않아요.

- **원래 자료:** `nativeRisu.card`는 카드 `data` 객체의 원문 JSON, `nativeRisu.module`은 내장 또는 독립 모듈 객체예요. 알려지지 않은 필드, 비활성 로어, 원래 에셋 역할도 보존해요. `sourceHash`는 입력 파일의 SHA-256이고, `assets`는 자료 이름·URI를 저장한 이미지 ID에 연결해요.
- **저장용 표시:** 기존 서재와 채팅 저장소가 읽는 본문·시작문·지침·로어는 원문에서 읽은 표시 필드예요. 원문 CBS를 그대로 두며 새 `bodyTemplate`, `compat.risuCbs`, `transforms`, `behavior` 프로그램을 함께 만들지 않아요. 설명·성격·시나리오·예시·시스템 지침·글로벌 노트는 원문에 보존하고 적용 시 앱의 전역 프롬프트나 모델 연결을 바꾸지 않아요.
- **로어:** 항상 활성인 항목은 고정 자료로, 나머지 활성 항목은 기본적으로 Uimori 모델 선택을 사용해요. 원래 키·보조 키·정규식·로어북 설정은 보존하므로 키워드 선택으로 바꿀 수 있어요. 현재 모델 문맥에 반영하지 않는 위치·삽입 지시문은 가져오기에서 알려요. 비활성 항목도 원문에 남지만 모델 입력 표시에서는 제외해요. 보존 자체가 모든 Risu 로어 지시문의 실행 지원을 뜻하지 않아요.
- **진행 기억:** 기본은 로어북을 그대로 두는 것이에요. 필요할 때만 **로어북에서 과거 진행 기억 분리하기 (선택)**에서 항목을 골라 출처가 있는 `imported-memory` 메모로 옮겨요. 선택한 항목은 모델 입력 로어 목록에서 빠지고, 원래 카드 문서는 유지해요.
- **이미지:** 컨테이너의 PNG·JPEG·WebP·AVIF·GIF를 실제 바이트 헤더와 2 MB 한도에 맞춰 저장해요. 파일 확장자만으로 형식을 판단하지 않아요. 외부 URL은 다운로드하지 않고, 미지원·누락·너무 큰 에셋은 알려요. 이미지 이름·URI와 원래 역할은 네이티브 문서에서 확인할 수 있어요.
- **원본 파일:** 24 MiB 이하 원본은 영수증 `sourceFiles`에 보존해 재내보내기와 전체 archive에도 포함해요. 큰 staged 컨테이너는 사본을 보관하지 않지만 원래 카드·모듈 JSON과 읽은 이미지 바이트는 자료에 보존해요. 어느 경우에도 원본 파일 base64를 모델 입력으로 보내지 않아요.
- **재시도:** 검토 digest가 바뀌면 다시 검토해야 해요. 저장 결과가 불확실하면 같은 파일·선택·요청 키로 확인해요. 이미 성공한 요청은 봇·채팅·시작문을 중복 생성하지 않아요. 기존 자료와 운영 데이터는 이 가져오기로 덮어쓰지 않아요.

이 경로는 [네이티브 importer](../server/risu-native-import.ts), [원문 계약](../core/risu-native.ts), [카드 파일 읽기](../server/character-card-file.ts)에 있어요. 원문 저장, 실제 스크립트 실행, 실제 화면 동작 검증은 서로 다른 증거예요. 원문을 읽었다는 사실만으로 모든 봇의 동작이나 UI가 Risu와 동일하다고 주장하지 않아요.

### CharX 내부 자료의 우선순위

`module.risum`은 별도 장착 모듈이 아니라 같은 카드의 직렬화된 자료로 읽어요. 카드와 모듈 원문은 둘 다 남기고 실행 시 다음 우선순위를 적용해요.

- 내장 모듈이 있으면 `regex ?? []`와 `trigger ?? []`가 카드의 인라인 스크립트를 대체해요.
- 내장 `lorebook`은 빈 배열도 카드 로어를 대체해요. 누락/null일 때만 카드 로어를 사용하고 두 목록을 합치지 않아요.
- 이름·설명·시작문은 카드 소유예요. 내부 모듈의 이미지 바이트도 메타데이터 순서대로 읽어 카드 이미지와 함께 저장하되 원문 문서를 덮어쓰지 않아요.
- 손상된 내부 모듈을 조용히 무시하고 인라인 자료로 대체하지 않아요. RPack·컨테이너 버전·UTF-8·CRC·에셋 수·ZIP 경로와 확장 크기 한도를 계속 검사해요. 파일 시스템으로 압축을 풀지 않아요.

## 네이티브 자료 편집과 새 채팅

서재의 Risu 편집기는 이름·설정·성격·상황·기본 시작문·대화 예시·제작자 코멘트를 원문 필드에 저장해요. 카드 프롬프트·배경 HTML/CSS·기본 변수를 직접 수정하고, 대체 시작문·로어·정규식·트리거/Lua는 JSON 편집에서 적용해요. 카드 또는 모듈 전체 JSON도 편집할 수 있어요. 알 수 없는 확장 필드는 그대로 남아요. 기존 독자 패키지의 DSL 편집 화면은 네이티브 자료에 표시하지 않아요.

가져오기와 저장 API가 같은 projection 함수를 사용해 원문에서 본문·시작문·로어·지침·기본 변수를 다시 만들어요. 일반 본문만 바꾼 요청이 네이티브 원문과 다른 실행 내용을 만들 수 없어요. 적용하지 않은 JSON은 공유 초안으로 보존하며 적용 전에는 저장을 막아요. 네이티브 패키지는 12 MiB, 원문은 8 MiB 한도를 유지하고 자료 저장 요청은 16 MiB, 네이티브 초안 모델은 16 MiB를 받아요. 원문 편집 버퍼와 모델을 함께 보내는 초안 요청은 48 MiB까지 허용해요. 기존 일반 초안 모델의 5 MB 한도는 유지해요. 저장하지 않은 네이티브 변경은 먼저 저장한 뒤 내보내요.

가져올 때 선택한 대화 기억은 canonical 로어 항목의 `enabled`를 `false`로 기록해 원문을 보존하면서 로어와 기억에 중복 포함되지 않게 해요. 로어 선택 방식은 Uimori 모델 선택·키워드 규칙·필요할 때 읽기 중 선택해요.

새 채팅은 네이티브 기본 `first_mes`가 있으면 기본 시작문을 선택해요. 선택 화면의 미리보기는 저장된 정확한 자료 리비전으로 일회성 Lua `editDisplay`, CBS, 정규식을 적용한 뒤 격리된 메시지 프레임에 표시해요. 미리보기는 채팅·변수를 저장하거나 모델을 호출하지 않고 선택 버튼도 비활성화해요. 페르소나 이름은 반영하지만 별도로 붙인 모듈과 채팅 중 변수는 이 미리보기에 포함하지 않아요.

채팅 백업·복원·포크는 네이티브 실행 결과와 작성된 버튼 응답을 보존해요. 메시지의 host 식별자만 새 채팅으로 매핑하고 본문·변수·실제 전송 프롬프트 영수증은 그대로 두며 스크립트나 모델을 다시 호출하지 않아요. 응답 후보는 준비된 입력을 공유하지만 `editRequest`·출력 후처리와 최종 변수는 후보마다 새로 실행해요. 버튼이 직접 작성한 응답은 작문 모델 재요청·후보 생성 대상으로 삼지 않아요.

네이티브 Lua는 채팅·분기·자료 개정별 격리 worker에서 초기 코드를 한 번 실행하고, 이후 콜백에서도 같은 local/global 값을 유지해요. 저장 변수와 대화는 매 호출 최신 고정값으로 갱신해요. worker 재시작·시간 초과·실행 실패·자료 변경은 그 VM을 폐기하며 영속 상태는 `getState`·채팅 변수로 보존해요. 각 authored script는 내부 RPC와 다른 스크립트의 권한을 볼 수 없는 실행 환경을 사용해요. 함수·`listenEdit` 콜백·동적 `load`는 원래 스크립트 권한을 유지하고, 서로 호출할 때 권한을 합치지 않아요. `LLM`·`axLLM`·`simpleLLM`은 허용된 원본 호출만 Uimori 호스트에 전달하며 화면 표시 콜백에서는 모델 호출을 허용하지 않아요. 미지원 API는 명시적 오류로 남아요.

지속 VM은 채팅 실행과 버튼 동작에 사용해요. Reader의 `editDisplay`와 시작문 미리보기는 저장 상태를 복사한 일회성 VM으로 실행하므로 화면을 열거나 새로고침하는 행위가 카드 상태를 저장하거나 모델을 호출하지 않아요. 표시 콜백이 이전 실행의 Lua local/global 값 자체에 의존하는 카드는 이 차이를 확인해야 해요. 프롬프트 미리보기·도우미·수동 문맥 정리도 상태를 변경하는 입력 콜백을 재실행하지 않고 고정된 자료의 CBS와 정규식 사본을 사용해요.

메시지 본문의 스타일 선택자는 Risu처럼 메시지 안쪽에만 적용해요. 카드에 `html, body` 레이아웃 규칙이 있어도 iframe 문서 전체의 높이·배치를 바꾸지 않아요. 별도 배경 임베딩은 같은 격리 프레임 안에서 표시하며 앱의 서재·설정 화면에는 영향을 주지 않아요.

카드의 고정 툴바와 접이식 패널도 메시지 프레임 안에서 동작해요. 보이는 고정 컨트롤이 잘리지 않도록 프레임 높이를 잡으며, 화면 밖에 닫혀 있는 패널은 높이를 늘리지 않아요. 고정 위치의 기준은 앱 전체 화면이 아닌 프레임이고, 외부 URL의 글꼴은 불러오지 않으므로 Risu와 글꼴·절대 위치가 다를 수 있어요. 같은 선택·설정·상태 표시를 사용할 수 있는지가 호환 기준이며 Risu 앱 전체의 외형이나 내부 렌더링 순서를 복제하지 않아요.

출력 스크립트가 한 응답에 메시지를 추가하면 각 메시지의 대화 순번으로 표시 콜백과 정규식을 적용해 함께 보여줘요. 이미 표시한 사용자 요청은 반복하지 않아요. 번역과 자동 이미지의 원문 위치는 저장된 본문에 연결하며, 스크립트가 추가한 메시지는 번역 보기에서도 원문으로 유지해요.

표시 에셋은 정확한 이름·URI·확장자 별칭을 먼저 찾아요. 없으면 Risu 기본 규칙처럼 소문자화, 알려진 미디어 확장자와 구분자 제거 후 Levenshtein 거리 4 이내에서 가장 가까운 이름을 선택하며, 동률이면 원래 에셋 순서를 유지해요. 저장된 로컬 에셋만 후보가 되고 외부 URL은 사용하지 않아요. 자동 이미지 배치도 이 표시 규칙을 적용한 결과가 선택한 이미지와 정확히 같은지 확인해요.

독립 가정 장면과 수동 문맥 작업은 고정 입력의 사본에서 CBS·정규식·RISUP 필드를 평가해요. 본편의 지속 Lua VM, 입력·요청·출력 콜백, 추가 모델 호출을 사용하지 않고 채팅 변수나 본편 응답을 바꾸지 않아요. 생략한 콜백은 실행 영수증에 표시하며 가정 장면을 수정하면 새 요청으로 다시 평가해요. 가정 장면의 작문과 문맥 압축에 필요한 모델 호출은 기존 작업 예산과 전송 영수증을 사용해요.

`editRequest`가 마지막 assistant 메시지의 역할과 위치를 유지하면 RISUP의 prefill도 유지해요. 콜백이 그 본문을 편집하면 편집된 본문을 이어 쓰며, 마지막 위치나 역할을 바꾸면 일반 완료 메시지로 취급해요.

카드와 내장 모듈의 트리거 권한은 카드 `extensions.risuai.lowLevelAccess`를 따르며 누락하면 꺼져요. 독립 `.risum`은 모듈의 `lowLevelAccess`를 따르고, 장착한 자료들을 모아 실행해도 각 원본의 권한을 유지해요. 원문 트리거의 개별 필드는 보존하지만 이 상위 권한을 우회하지 않아요.

### 네이티브 로어 위치

새 네이티브 카드의 `@@depth`, `@@end`, `@@reverse_depth`, `@@role`은 활성화된 로어의 역할·위치로 보존해요. `@@depth 0`과 `@@end`는 최종 지시에, 양수 `@@depth`는 실제 전송 대화의 앞쪽 인덱스에, `@@reverse_depth`는 전송 대화의 뒤쪽을 기준으로 넣어요. 일반적인 다른 앱의 depth 이름만 보고 방향을 바꾸지 않고 Risu의 삽입 계산을 따라요. 원래 삽입 순서를 유지하고 조건부 항목은 이번 실행의 고정된 로어 선택 결과에 있을 때만 배치해요. 기존 assistant prefill은 마지막 위치를 유지해요.

`@@depth 0`·`@@end`는 프리셋에서 `postEverything` 슬롯을 중간으로 옮겨 놓았어도 최종 지시 위치를 사용해요. 그 특수한 슬롯 이동이나 슬롯의 래퍼를 로어 메시지 전체에 적용하는 동작까지 동일하게 재현하지는 않아요.

위치를 지정한 항목은 일반 로어·참고 자료 슬롯과 자동 배경 참고 메시지에서 빠져 중복 전달되지 않아요. 고정 로어 문자 예산과 검색·읽기 도구의 원문·참조 범위는 그대로 유지해요. 앱의 기억이나 사용자 메모를 가짜 대화로 바꾸지 않아요. `@@position`·`@@inject_*`와 음수/한도 밖 depth 등 지원하지 않는 지시는 계속 가져오기 안내로 남겨요. 이 계약은 서재의 원래 카드 문서를 바꾸지 않으며 `nativeRisuPosition`은 저장·실행용 투영 정보예요.

### 이미지 선택 지시 옮기기

가져오기 검토와 네이티브 편집기의 **이미지 선택 지시**에서 원문 필드·로어 항목과 이동 범위를 확인해요. `<img...>`를 소비하는 표시 정규식이 있고 이미지 태그 규칙임이 명시된 로어 또는 제목 구간만 자동 후보로 찾아요. CBS 블록 경계가 맞지 않는 구간은 기본 선택하지 않으므로 미리보기를 보고 직접 선택해야 해요. 원문이 바뀌면 이전의 선택을 다른 내용에 자동으로 이어 붙이지 않아요.

채팅의 **이미지 자동 배치**가 켜졌을 때만 선택한 범위를 작문 입력에서 제외하고 이미지 선택 모델의 참고 지침으로 넘겨요. 태그 문법·복장·감정·위치 조건을 포함한 범위 원문을 그대로 보존하며 `imageHandoff`에는 원래 필드, 시작·끝 위치, 선택 여부를 기록해요. 이 정책을 꺼두면 원래 작문 지침을 유지해요. 설정을 바꿔도 카드·모듈 원문이나 저장된 응답을 삭제하지 않아요.

이미지 지시를 감싼 바깥 CBS 조건도 원래 필드에서 평가한 뒤 해당 범위만 추출해요. 예를 들어 서로 다른 연령·복장 분기 안의 이미지 지침을 조건 없이 함께 넘기지 않아요. 평가는 복사한 변수에만 적용하고 주변의 작문 지침은 이미지 모델로 옮기지 않아요. 비활성 로어와 폴더는 이미지 지시로 옮기지 않아요.

선택 모델이 반환한 에셋과 문단 참조는 기존 hash·리비전 검증을 거쳐 표시 사본에만 적용해요. 원래 정규식으로 정확히 같은 로컬 에셋이 나오는 태그만 역으로 찾아 삽입하므로 카드의 이미지 상자를 사용할 수 있어요. 현재 `<img="이름">`와 `<img src=이름>` 계열을 검사하고 복장 변수에 따라 다른 이미지가 나오거나 대응 에셋이 없으면 삽입하지 않아요. 외부 모듈의 이미지를 다운로드하거나 없는 이미지를 다른 이미지로 대체하지 않아요. 이는 임의의 태그·정규식·Lua 이미지 생성 규칙 전체를 재현하는 기능이 아니에요.

새 삽화 생성은 기존 Uimori 삽화 설정과 독립 큐를 사용해요. 일반 네이티브 작문 응답도 자동 생성 예약과 Reader 삽화 표시 대상이며, 카드 첫 화면이나 버튼이 직접 작성한 문장은 자동 예약하지 않아요. 별도 Lightboard 모듈을 내장하지 않아요. 테스트에서는 로컬 표본의 태그·정규식·에셋 연결과 합성 생성 완료를 검증하며 실제 이미지 생성 제공자의 결과나 창작 품질을 보증하지 않아요.

## 이전 변환 패키지의 실행 계약

아래 CBS·선언형 트리거·Lua 설명은 이미 가져온 구형 패키지에 저장된 AST·wrapper 프로그램의 계약이에요. 새 네이티브 카드 가져오기는 이 변환 경로를 사용하지 않으며 기존 저장 자료를 자동 변환하거나 삭제하지 않아요.
### 기본 변수와 읽기 CBS

`extensions.risuai.defaultVariables`와 프리셋의 `templateDefaultVariables`는 [공통 템플릿 변수](PROMPT-RUNTIME.md#템플릿-기본-변수) 선언으로 가져와요. 고정 Risu의 `getChatVar`처럼 봇 기본값이 프리셋 기본값보다 우선해요. 기본값은 저장된 채팅 상태의 초기 복사본이 아니며, 토글 값이나 패키지 행동 state로 바꾸지 않아요. 카드 선언은 **봇 역할일 때만** 적용하고 모듈은 선택한 봇·프리셋의 같은 값을 읽어요. 같은 카드가 모듈·페르소나로 장착됐다고 봇 기본값을 덮어쓰지 않아요.

어댑터는 고정 Risu `parseKeyValue` 의미대로 줄마다 첫 `key=value` 쌍만 읽고 공백을 정리하지 않아요. 빈 key/value는 무시하며 첫 중복이 우선해요. 따라서 `a=b=c`는 `a → b`예요. 문자열에 들어 있는 CBS를 다시 실행하지 않아요. 허용하지 않는 이름·형식·한도 초과는 부분 가져오기 대상으로 안내하고 원본에 보존해요.

이전 가져오기에서 만든 이름·변수·조건 CBS AST는 저장된 프로그램으로 계속 실행해요. 이 AST를 만들던 별도의 CBS·정규식·트리거 변환기는 신규 가져오기 경로에서 제거했어요. 이미 저장한 `compat.risuCbs` 필드는 기존 `server/compat/risu/cbs.ts` 평가기로 한 번 평가하고 Run 영수증에 고정하는 계약을 유지해요. 결과·쓰기 기록·원본 입력 hash는 복원과 포크에서 검증하며, 저장된 자료를 새 네이티브 자료로 자동 변경하지 않아요.

사용자가 [분기 공유 변수](PROMPT-RUNTIME.md#분기-공유-변수)를 직접 저장하면 그 값이 기본값보다 우선하며 지원하는 읽기 CBS에도 적용돼요. Lua의 공유 쓰기는 아래 이벤트와 Host API 범위로 연결해요. `compat.risuCbs`로 선언한 필드 안의 `setvar`·`addvar`·`setdefaultvar`는 영수증에 기록해 두었다가 그 Run의 원문을 저장할 때 분기 공유 변수에 반영해요. 채팅에서 해당 자료 개정에 **공유 변수 변경**을 허용해야 반영하며, 허용이 없거나 예약 이후 분기 변수가 바뀌었으면 원문 저장을 실패시키지 않고 쓰기만 건너뛴 뒤 이벤트로 남겨요. 같은 턴에 그 자료의 행동 코드가 공유 변수를 바꿨을 때도 분기가 예약 시점과 달라지므로 CBS 쓰기는 건너뛰어요. 한 턴 안에서 두 쓰기 주체의 결과를 합치지 않아요. 같은 Run의 다른 선언 필드는 예약 시점 값을 계속 읽으므로 본문의 쓰기가 로어 평가에 보이지 않아요. 쓰기 한도는 항목마다 200개이고, 이름·값·전체 크기는 분기 공유 변수와 같은 한도를 적용해요. 해당 코드가 있는 자료는 부분 가져오기이며 동적인 게임 상태나 상태창 전체가 재현됐다고 볼 수 없어요. 기존 가져온 자료·과거 Run에 새 변환을 자동 적용하지 않아요.

### 선언형 트리거 효과

스크립트 없이 `setvar`만 사용하는 트리거는 공통 행동 하나로 연결해요. Risu와 같이 트리거의 `type`이 실행 시점을 정하며 `start`는 생성 전, `input`은 입력 단계, `output`은 완성 응답 후, `manual`은 트리거 이름을 단 사용자 버튼이 돼요. `display`·`request` 시점은 Risu도 v1 효과와 `triggerlua`를 실행하지 않아요(그 허용 목록에는 v2 opcode만 있어요). 이 시점의 트리거는 연결할 대상이 없어 원본 선언만 보존해요. 조건은 Lua 콜백과 같은 변환을 사용하고, 변환할 수 없는 조건·효과 종류·실행 시점에 정해지는 변수 이름이 있으면 그 트리거를 연결하지 않고 원본 선언만 보존해요.

값 계산은 Risu의 고정 구현과 같은 JavaScript 숫자·문자열 의미를 사용해요. `=`는 CBS를 해석한 문자열을 그대로 저장하고 `+= -= *= /=`는 현재 값을 숫자로 읽어(숫자가 아니면 0) 계산한 결과를 문자열로 저장해요. 값 안의 `{{getvar::이름}}`은 같은 분기 공유 변수를 읽고 없는 변수는 `null` 문자열이에요. 이 행동은 분기 공유 변수를 바꾸므로 채팅에서 해당 자료 개정에 **공유 변수 변경**을 허용해야 실행해요.

스크립트와 효과가 섞인 트리거는 **스크립트가 첫 효과가 아닐 때** 선언 순서를 유지해 연결해요. 효과 → 스크립트 콜백 → 효과를 그 트리거의 실행 시점 하나에서 차례로 실행하고, 이때 스크립트 콜백은 Risu와 같이 그 시점의 콜백만 호출해요. 스크립트가 첫 효과면 Risu가 모든 시점에서 트리거를 실행하므로 아직 연결하지 않아요. 수동 트리거의 효과와 스크립트를 한 번의 클릭으로 묶는 경로도 아직 없어요. Risu는 조건을 효과보다 먼저 한 번만 판정하므로, 트리거가 자신의 조건이 읽는 변수를 바꾸면 같은 의미로 옮길 수 없어 연결하지 않고 원본을 보존해요.

카드가 저수준 접근을 선언한 경우 `runLLM`과 `extractRegex`도 연결해요. `runLLM`은 해석한 값을 하나의 요청으로 보내 결과를 지정한 변수에 저장하고, 실패는 Risu와 같이 `Error: …` 문자열로 남겨요. 설정의 **확장 호출 모델**과 채팅의 **추가 모델 호출 허용**이 필요하며, `<|im_start|>`로 시작하는 ChatML 형식 프롬프트는 한 메시지로 바꿔 보내지 않고 오류로 표시해요. `extractRegex`는 같은 정규식·플래그로 한 번 매칭해 `$1`·`$&`·`$$` 치환 결과를 변수에 저장하고, 매칭이 없으면 오류로 표시해요. 카드가 저수준 접근을 선언하지 않으면 Risu와 같이 두 효과를 실행하지 않고 나머지 효과만 실행해요.

`cutchat`·`modifychat`·`systemprompt`·`impersonate`·`command`·`runImgGen` 같은 나머지 효과 종류는 아직 연결하지 않고 안내와 원본 보존으로 남겨요.

### Lua 콜백 가져오기

독립 `triggerlua` 효과의 원본 코드를 Lua 프로그램으로 보존해 `onInput`은 입력 단계, `listenEdit("editInput")`은 입력 편집 단계, `onStart`는 생성 전, `listenEdit("editRequest")`는 전송문 편집 단계, `listenEdit("editOutput")`·`onOutput`·`listenEdit("editDisplay")`는 완성 응답 후, `onButtonClick`은 문자열 입력을 받는 사용자 행동으로 연결해요. `onInput`은 공통 자동 준비의 `hook: 'input'` 단계로 구분해 모든 시작 행동보다 먼저 실행하며, 대화 읽기에는 이번 입력을 덧붙이지 않아요. `onStart`부터 이번 입력을 포함해요. 원래 요청과 예약 snapshot은 보존하고 계산한 상태·변수는 기존 준비 영수증과 본문 성공 시 채택 경계를 사용해요. 실패·건너뛰기·취소도 기존 자동 준비 규칙을 따라요. `trigger.type`만으로 콜백을 추정하지 않으며 실제 호출 때 등록된 함수를 찾아요. 가져오기·일반 미리보기·복원에서는 실행하지 않아요. 공유 변수 쓰기·대화 읽기·모델 호출은 정확한 자료 개정에 대해 채팅별로 각각 허용해야 해요.

`getChatVar/setChatVar/setChatVarChanged`, `getState/setState/setStateChanged`, JSON 모듈·`async`와 `simpleLLM`은 공통 Host API를 사용해요. 없는 변수의 문자열 `"null"`, 빈 값, 저장된 override와 기본값의 차이, Risu JSON의 nil/빈 테이블 의미를 어댑터에서 처리해요. 호출별 Lua 전역은 새로 초기화되므로 영속 상태는 공유 변수/`getState`에 저장해야 해요.

`getChat/getChatMain/getChatData/getChatRole/getChatLength`, `getRecentChats/getRecentChatsMain`, `getFullChat/getFullChatMain`, `getUserLastMessage/getCharacterLastMessage`는 [현재 분기 대화 Host](EXTENSION-PROGRAMS.md#host-api로-현재-분기-대화-읽기)를 사용해요. 모델 문맥 절삭과 무관하게 현재 분기에서 사용자가 볼 수 있는 저장 대화를 읽고, 입력 단계는 현재 요청을 제외하고, 생성 전·모델 행동은 현재 요청, 응답 후 행동은 현재 요청과 완성 응답을 덧붙여요. 다른 채팅·분기·삭제·대체된 기록과 앱 설정·연결 설정의 API 키는 제공하지 않아요. 사용자가 대화 본문에 직접 쓴 문자열은 원문으로 취급해요. 원본에 없는 시각은 `0`이고 저장되지 않은 첫 인사 대체값은 만들지 않아요. 전체 조회가 실행 한도를 넘으면 일부 결과를 성공으로 반환하지 않아요.

`getName`·`getPersonaName`·`getDescription`은 [자기 자료 Host](EXTENSION-PROGRAMS.md#host-api로-자기-자료-읽기)를 사용해요. 앞의 두 함수는 본문·로어 템플릿이 넣는 것과 같은 봇·페르소나 이름을 읽고, `getDescription`은 같은 패키지의 본문 자료를 조각 읽기로 이어 붙여 돌려주며 본문 자료가 없으면 빈 문자열이에요. 고정 Risu가 저장 원문 `desc`를 그대로 주는 것과 달리 이름·옵션·공유 변수 템플릿을 적용한 투영 본문을 읽는 의도적 차이가 있어요. 다른 Host 함수와 같이 호출자가 넘긴 id로 대상을 바꾸지 않고 이번 호출에 고정된 자료만 읽어요. `getPersonaDescription`은 페르소나 본문을 읽는 경로가 없고 `setName`·`setDescription`·`setCharacterFirstMessage`는 자료를 바꾸는 경로가 없어 계속 미지원 오류로 남겨요.

Risu의 `var`·`value` 트리거 조건과 지원하는 비교/CBS 값은 공통 `when` 식으로 변환해 `onInput`·`onStart`·`onOutput` 자동 행동에 적용해요. 변수값 자체에 실행할 CBS가 남아 있거나 조건 종류·연산·CBS 블록을 안전하게 변환할 수 없으면 조건을 버리지 않고 해당 자동 콜백 실행을 보류해요. 다른 효과와 섞인 `triggerlua`도 원래 순서를 바꾸지 않고 소스만 보존해요.

`listenEdit("editInput")`은 입력 단계 다음, 생성 전 단계보다 먼저 실행해 **이번 요청의 전송 사본**에 적용해요. 저장한 요청 원문·hash·편집 기준은 그대로 두므로 Risu가 편집 결과를 대화에 저장하는 것과 다른 의도적 차이예요. Reader의 요청 항목에서 원문과 전송문을 비교할 수 있어요. Risu의 편집 경로와 같이 트리거 조건을 적용하지 않고, 등록 순서대로 값을 이어 넘기며 콜백이 `nil`을 반환하면 직전 값을 유지해요. 여러 자료가 선언하면 자료 장착 순서로 이어져요. `meta.index`는 Risu와 같이 `-1`이고 대화 읽기에는 이번 입력을 덧붙이지 않아요. 문자열이 아니거나 100,000자를 넘는 반환은 자동 준비 묶음의 실패로 처리해 원래 요청으로 계속해요. 이어지는 프리셋 전송 정규식은 편집된 사본을 입력으로 받지만, 같은 요청의 `onStart`·대화 읽기 Host는 저장된 원문을 그대로 읽어요.

`listenEdit("editRequest")`는 생성 전 단계 다음에 실행하고 **전송용 원문 대화와 이번 요청만** `{role, content}` 목록으로 받아요. Risu가 시스템 프롬프트·로어·다른 자료의 지침까지 합친 최종 배열을 넘기는 것과 달라요. 메시지 수와 역할은 바꿀 수 없고 본문 텍스트만 바꿀 수 있으며, 다른 모양을 반환하면 자동 준비 묶음의 실패로 처리해 원문 대화를 그대로 보내요. 이 채팅에서 해당 자료 개정에 **대화 읽기를 허용**해야 실행하고, 허용이 없거나 대화가 실행 한도(메시지 1,000개·메시지당 100,000자·합계 100,000자)를 넘으면 편집을 건너뛰고 Reader에 안내해요. 편집 결과는 이번 전송 사본에만 적용하고 저장한 원문·hash·이후 대화 읽기는 바꾸지 않아요.

`listenEdit("editOutput")`과 `listenEdit("editDisplay")`는 완성 응답을 저장한 뒤 응답 후 단계에서 **한 번 계산**해 이 응답의 표시 사본을 만들어요. Risu는 `editOutput` 결과를 대화에 저장하지만 Uimori는 저장 원문을 바꾸지 않고, 다음 턴의 문맥·대화 읽기·`onOutput`도 원문을 읽어요. 전송에서 빼야 하는 내용은 [본문 구간](SOURCE-SEGMENTS.md)을 사용해요. 실행 순서는 `editOutput` → `onOutput` → `editDisplay`이고, 결과는 프리셋 표시 정규식보다 먼저 적용해요. 새로고침·분기·복원은 저장한 결과를 읽고 코드를 다시 실행하지 않으며, 원문을 편집하면 이 표시 사본은 사라져요. 문자열이 아니거나 100,000자를 넘는 결과는 그 자료의 응답 후 묶음 실패로 처리해 원문을 그대로 표시해요. 구간 경계가 있는 응답에는 적용하지 않고 안내해요. 여러 자료가 함께 선언하면 자료별로 `editOutput → onOutput → editDisplay`를 묶어 순서대로 실행해요. Risu처럼 모든 자료의 `editOutput`을 먼저 모으지 않아요.

대화 변경·나머지 자료/UI API와 동적 화면은 아직 연결하지 않아요. 해당 부분을 가져오기 안내에 남기고 미지원 API는 성공한 것처럼 처리하지 않아요. Lua 외 트리거의 나머지 효과 종류와 커스텀 표시 역시 후속 범위예요. 이 연결은 동적인 상태창·선택기나 전체 표본 기능의 완료를 뜻하지 않아요.

## Risu 플러그인 파일

같은 **Risu 자료 가져오기**에서 플러그인 `.js`를 고르면 지원 범위 보고와 함께 **모듈로 가져오기**를 누를 수 있어요. 플러그인은 항상 모듈이며 봇·채팅·진행 기억을 만들지 않아요. **가져오는 동안에는 코드를 실행하지 않아요.** 파일이 선언한 `//@name`·`//@display-name`·`//@api`·`//@arg`·`//@link`·`//@version`·`//@update-url`·`//@allowed-ipc`를 읽고, 본문이 언급한 `risuai.*` 이름을 현재 계약과 대조해 **대응 가능·미구현·제공하지 않음**으로 나눠 보여 줘요. 등록한 뒤 기존 채팅의 봇·페르소나·모듈 설정에서 장착하면, 그때부터 이 코드가 [격리된 자료 행동](EXTENSION-PROGRAMS.md)으로만 실행돼요.

가져오기는 훅·인자·저장소 세 축을 현재 실행 모델 위에 연결해요. 상주 플러그인 인스턴스·iframe·앱 전역 저장소·일반 HTTP·제공자/MCP/음성 합성은 이 범위가 아니에요.

- **훅**: `addRisuScriptHandler`의 `input`·`output`·`display`는 각각 입력 편집·출력 편집·표시 편집 단계로, `addRisuReplacer`의 `beforeRequest`·`afterRequest`는 전송문 편집·출력 편집 단계로, `addRisuChatListener('output')`은 응답 후 자동 행동으로 연결해요. 등록 모드를 문자열 리터럴로 적은 파일은 그 단계만 연결하고, 실행 중에 정해지는 모드는 세 단계를 모두 연결해요.
- **인자**: `//@arg <key> <int|string> <설명>` 한 줄이 자료 옵션 하나가 되고 `getArgument`·`getArg`는 채팅에서 사용자가 고른 값을 읽어요. `int`는 기본값 0인 숫자 옵션, `string`은 기본값이 빈 문자열인 글 옵션이에요. `hidden_`으로 시작하는 키도 감추지 않고 옵션으로 만들어요. 자료 옵션 이름 규칙(영숫자와 `_ . : -`)에 맞지 않거나 중복된 키는 옵션을 만들지 않고 안내로 남겨요.
- **저장소**: 세 저장소 모두 **이 채팅 분기의 공유 변수**를 쓰고, Risu가 서로 다른 저장소를 두는 것과 같이 각각 자기 접두사를 가져요. `pluginStorage`는 `risu.plugin.storage:`로 JSON 값을, `getLocalPluginStorage()`는 `risu.plugin.local:`로 JSON 값을, `safeLocalStorage`는 `risu.plugin.localstorage:`로 문자열 값을 저장해요.

의도적으로 다른 점은 다음과 같아요.

- **호출마다 새 실행**: 상주 인스턴스가 없으므로 플러그인 파일은 이벤트마다 처음부터 다시 실행하고, 그 실행에서 등록한 콜백만 그 이벤트에서 불러요. 최상위에 둔 값은 이벤트 사이에 남지 않으니 유지할 값은 저장소에 넣어야 해요. `onUnload`는 해제 시점이 없어 콜백을 받아 두기만 하고 부르지 않아요.
- **저장소 범위와 허용**: 앱 전역·기기 로컬이 아니라 채팅 분기 범위예요. Risu처럼 플러그인 사이에 키를 공유하지만, Risu가 localforage와 localStorage를 따로 두는 것처럼 세 저장소는 각자 접두사로 분리해요. 같은 키 이름을 `safeLocalStorage`와 `getLocalPluginStorage()`로 써도 서로 덮어쓰거나 섞이지 않아요. 쓰려면 채팅에서 그 자료 개정에 **공유 변수 변경**을 허용해야 하고, 허용이 없으면 그 묶음이 실패해 이번 턴에는 이 자료의 행동을 적용하지 않아요.
- **요청 모양**: `beforeRequest`는 전송용 원문 대화와 이번 요청만 `{role, content}` 목록으로 받아요. Risu가 시스템 프롬프트·로어까지 합친 최종 배열을 넘기는 것과 달라요. 메시지 수와 역할은 바꿀 수 없고 채팅에서 **대화 읽기**를 허용해야 실행해요. `addRisuChatListener('output')`도 같은 허용이 없으면 빈 대화를 받아요.
- **표시 사본**: `output`·`display` 처리와 `afterRequest`는 저장 원문을 바꾸지 않고 이 응답의 표시 사본만 만들어요. 다음 턴의 문맥·대화 읽기는 원문을 읽어요. 입력 편집도 저장한 요청 원문 대신 이번 전송 사본에만 적용해요.
- **`process` 미지원**: `addRisuScriptHandler('process')`는 같은 실행 시점의 공통 훅이 없어 연결하지 않아요. 등록은 받지만 어떤 이벤트에서도 부르지 않고 미지원으로 안내해요.
- **인자 쓰기 미지원**: `setArgument`·`setArg`는 부르면 오류를 표시해요. 값은 자료 옵션에서 사용자가 바꾸고 플러그인은 읽기만 해요. `getArg`는 이 플러그인 자신의 이름만 읽고 다른 플러그인 이름은 거절해요.
- **나머지 API**: 위에 없는 이름과 알려진 목록에 없는 이름은 부르면 `RISU_PLUGIN_API_UNSUPPORTED:<이름>` 오류를 표시하고, 성공한 것처럼 처리하지 않아요. `runLLMModel`은 메시지를 한 줄씩 이어 붙인 하나의 프롬프트로 [확장 호출 모델](EXTENSION-PROGRAMS.md)에 보내고 `{type, result}`를 돌려줘요. `getRuntimeInfo`는 `apiVersion '3.0'`과 `platform`·`saveMethod` `'uimori'`라는 고정값이에요. `log`는 받아서 무시해요.

목록에 없는 이름은 판정하지 않고 그대로 보고해요. 사용 API는 글자만 대조해서 찾기 때문에 `const r = risuai` 같은 별칭, 계산된 접근, 이름을 바꾼 구조 분해는 놓칠 수 있어요. 보고서가 그 사실과 발견한 별칭 이름을 함께 알려 주므로 "미구현" 목록이 비어 있어도 쓰지 않는다는 증거로 읽지 않아요. 별칭을 쓰는 파일은 등록 시점을 정적으로 알 수 없으므로 행동이 하나도 없는 자료를 만드는 대신 다섯 단계에 모두 연결하고, 등록되지 않은 단계는 아무것도 바꾸지 않아요. API 2.0/2.1을 선언한 파일도 읽지만 판정은 3.0 기준이라는 점을 함께 알려요. 파일은 4 MiB까지 읽고, 원본 `.js`는 자료 이동 영수증에 그대로 보존해요. 코드가 공통 프로그램 소스 한도를 넘으면 행동을 연결하지 않고 안내로 남겨요.

## 대용량 자료

24 MiB가 넘는 카드·모듈 파일은 요청 본문 대신 **먼저 서버에 올린 뒤** 검토해요. 화면에서 파일을 고르면 자동으로 이 경로를 사용하고, 올린 파일은 DB 옆의 `uploads` 디렉터리에 두었다가 등록이 끝나면 지워요. 검토를 끝내지 않은 파일은 24시간 뒤 정리하며, 정리된 뒤 등록을 누르면 파일을 다시 선택하라고 안내해요. 한도는 256 MiB예요.

이 경로에서는 **원본 파일의 사본을 앱에 보관하지 않아요.** 24 MiB 이하 파일은 지금처럼 원본을 자료 이동 영수증에 보존하지만, 그보다 큰 파일은 원래 카드·모듈 JSON과 가져온 에셋을 저장하고 가져오기 안내에 파일 이름과 SHA-256 지문을 남겨요. 원본 파일은 사용자가 직접 보관해야 다시 내보낼 수 있어요.

컨테이너 안에서 읽는 양은 파일 크기에 비례해 허용하되 한 항목은 64 MiB를 넘을 수 없어요. 실제 크기보다 훨씬 크게 부풀리는 압축 파일은 크기와 상관없이 거절해요. 첨부 자료의 한도(이미지 2 MB, PNG·JPEG·WebP·AVIF·GIF)는 그대로이므로 큰 오디오·영상·고해상도 이미지는 계속 가져오지 않고 안내로 남겨요.

## 봇·페르소나·모듈

### 구조화된 Risu 모듈 JSON

RisuToki의 **파일 → 파일을 프로젝트 폴더로 추출…**에서 `.risum`을 새 폴더로 내보내면 `{ "type": "risuModule", "module": {...} }` 형식의 `module.json`이 생성돼요. 서재 봇/모듈 탭의 **Risu 자료 가져오기**에서 이 파일을 선택하고 **모듈 가져오기**를 눌러요. 모듈로 등록하며 봇·채팅·진행 기억을 자동 생성하지 않아요. 등록 후 기존 채팅의 봇·페르소나·모듈 설정에서 장착할 수 있어요.

독립 `.risum`도 같은 화면에서 직접 읽을 수 있어요. 모듈 객체 전체를 `nativeRisu.module`로 보존하고 활성 로어·이름·설명은 서재 표시용으로 읽어요. 모듈 설명은 작문 본문에 복사하지 않아요. 바이너리 에셋과 JSON의 PNG/JPEG/WebP/AVIF/GIF data URL 이미지는 같은 이미지 저장 경로를 사용해요. 정규식·Lua·트리거·CSS·토글·namespace/MCP 등은 원문으로 남으며 실행 지원 범위와는 구분해요.

추출 폴더의 이미지도 옮기려면 **`module.json`과 `.risutoki` 폴더를 함께 ZIP으로 압축**하고 그 ZIP을 선택해요. 하나의 상위 폴더로 감싸져 있어도 읽어요. `.risutoki/workspace.json`의 `risumAssetFiles` 순서로 원래 모듈 에셋과 연결하며, 목록이 없는 경우 `.risutoki/risum-assets/*.bin`의 파일명 순서를 사용해요. 실제 이미지 바이트로 형식을 확인하며 누락된 파일은 미지원으로 표시해요. ZIP 안에서만 읽고 외부 경로나 로컬 파일 시스템으로 추출하지 않아요. 여러 모듈 정의나 카드·모듈 정의가 함께 있는 모호한 프로젝트 ZIP은 거절해요.

이 경로에서는 별도 설치된 RisuToki가 바이너리 해석을 맡고 Uimori는 일반 JSON과 ZIP만 읽어요. RisuToki 추출의 정규화·숨김 필드 제거가 적용되므로 그 결과를 원본 `.risum` 전체와 동일하다고 간주하지 않아요. Uimori는 선택한 JSON/ZIP 바이트를 원본 영수증에 보존해요.

### native 패키지 JSON

서재에서 해당 종류의 자료를 만들거나 편집하고 **패키지 가져오기·내보내기와 역할 사본 → 패키지 JSON 가져오기**를 선택해요.

1. `ContentPackage` 자체, `{ "package": ... }` wrapper 또는 이미지를 포함한 `uimori-package-bundle` JSON을 선택해요. 파일은 64 MiB 이하여야 하며 [native 패키지 스키마](PACKAGES.md) 검증도 통과해야 해요. 이미지 bundle은 서버에서 이미지 hash와 참조를 검사해요.
2. 제목·로어·지침 수를 확인하고 **가져온 패키지로 초안 바꾸기**를 눌러요. 패키지의 제목·설명·본문·내부 자료가 편집 초안에 반영돼요. **가져오기 취소**로 검토를 끝낼 수도 있어요.
3. 내용과 선택한 자료 종류를 확인한 뒤 **자료 등록** 또는 **새 revision 저장**을 눌러요. JSON 선택이나 초안 교체만으로 저장하지 않아요.

wrapper 바깥의 콘텐츠 ID·revision·종류·기타 metadata를 복원하는 기능은 아니에요. 자료 종류는 현재 편집기 선택을 따르고, 저장 시 서버가 콘텐츠 ID/revision과 패키지를 정규화해요. 연결한 공통 모듈은 단일 패키지 파일에 포함하지 않으므로 대상 서재에도 같은 ID·개정이 있어야 해요. 채팅 장착은 저장된 참조로 따로 진행해요. 역할을 바꾸어도 원문의 인물 관점이나 지침을 자동 각색하지 않아요.

## Risu 프리셋

프롬프트 관리의 **Risu 프리셋 가져오기**에서 `.risup`·구형 `.risupreset` 바이너리, 프리셋 JSON 또는 RisuToki 프로젝트 ZIP을 선택해요. **작문 프롬프트로 저장**하면 `PromptProgram.nativeRisuPreset`에 프롬프트 관련 원본을 보존해요. **가져온 프롬프트 편집**에서는 Risu의 메시지 구성·CBS 원문·토글·기본 변수·정규식을 직접 편집해요. 실행용 블록은 원본에서 만들며 별도의 수동 이식본으로 관리하지 않아요. `.risup`의 RPack·압축·MessagePack 해독과 가져오기 검토는 코드를 실행하지 않으며 원본 파일도 native transfer에 보존해요.

Risu의 `memory` 슬롯은 사용자 메모로 치환하지 않아요. Uimori는 과거 요약을 전송 대화 문맥에 포함하고 사용자 메모·정정을 별도 참고 정보로 전달해요. 실제 전달은 선택한 프롬프트와 문맥 구성에 따르며, 가져오기 안내에 Risu 슬롯의 위치·래퍼는 직접 적용하지 않는 차이를 설명해요. 슬롯을 추가해 같은 요약을 중복 삽입하지 않아요. 모델·파라미터·도구는 Uimori가 별도로 관리하므로 가져오기 대상이나 미지원 손실로 계산하지 않아요.

실행 시 CBS는 시간·출력 제한이 있는 worker에서 원본 그대로 평가하고, 필드 간 변수 변경도 같은 평가 문맥을 사용해요. 평가 결과는 Run에 고정해 재접속·복원 때 다시 실행하지 않아요. 프리셋 정규식은 네이티브 `editinput`·`editoutput`·`editprocess`·`editdisplay` 단계에 연결하며 캡처 치환 뒤 CBS를 평가해요. 예전 32개 규칙 변환 제한을 적용하지 않지만 worker 실행·메모리·출력 한도는 유지해요. `@@inject`·`@@repeat_back`·`@@emo` 같은 host 특수 명령과 일부 Risu 확장 동작은 아직 실행하지 않고 문제로 보고해요. 기존에 저장한 일반 PromptProgram·공통 텍스트 변환 프리셋은 그대로 동작해요.

모델·프로바이더·인증·생성 파라미터·도구 권한은 Uimori가 소유해요. RISUP를 가져오거나 적용해도 이를 덮어쓰지 않으며 네이티브 프롬프트 편집기에도 노출하지 않아요. 원본 파일의 해당 값은 보관용 바이트에만 남아요. 실제 봇과 개인 프리셋 조합의 창작 품질은 별도 확인이 필요해요.

## 프롬프트

프롬프트 편집의 메시지 구성에서 **JSON 불러오기**를 선택해요. `PromptProgram` 자체 또는 `program`과 선택적인 `title`·`role`·`values`를 담은 native 파일을 받아요. 파일은 1,500,000 bytes 이하이며 [프롬프트 스키마와 실행 한도](PROMPT-AUTHORING.md)를 검사해요.

성공하면 이름·역할·구성과 옵션 값이 편집 초안에 반영되고 상위 편집기에서 명시적으로 저장해야 해요. 기존 프리셋을 편집 중일 때 다른 역할의 파일은 거절하고 새 프롬프트에서 불러오도록 안내해요. 원본의 ID·revision이나 저장된 옵션 조합 목록을 통째로 복원하지 않아요. `values`가 없는 예전 wrapper의 `suggestedCombination.values`는 기본 옵션 값으로 읽어요. 정의는 `program.controls`, 값은 `values`로 검증하며 내보내기에도 이름·역할·AST·현재 옵션 값을 담아요. 실제 계약은 [prompt-file](../core/prompt-file.ts)을 봐요.

파일 형식이나 스키마 검증이 실패하면 적용된 자료·프롬프트는 유지해요. JSON 가져오기·검증·저장에는 모델 호출이나 원본 스크립트 실행이 없어요. 스키마 통과는 Risu 원본과의 동작 동등성을 뜻하지 않으므로 이식 보고와 대표 동작 검증을 함께 확인해요.

현재 화면 구현은 [LibraryPanel](../web/LibraryPanel.tsx), [PackageTransfer](../web/PackageTransfer.tsx)와 [PromptComposer](../web/PromptComposer.tsx)에 있어요. 전체 DB의 v15 archive 복원은 이 파일 가져오기와 별개이며 [사용 안내](USAGE.md)를 확인해요.

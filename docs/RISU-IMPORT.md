# Risu 자료와 native JSON 가져오기

앱은 `.charx`·Character Card JSON·독립 `.risum`·Risu 모듈 JSON/프로젝트 ZIP을 읽어요. 새로 가져온 카드는 `RisuContent.nativeRisu`의 원래 카드·모듈 문서를 실행·편집 기준으로 삼아요. CBS·정규식·트리거·Lua를 별도의 Uimori DSL로 번역하지 않아요. 프리셋 `.risup`·`.risupreset`은 아래 프리셋 경로를 사용하고, 독립 플러그인 `.js` 변환은 제공하지 않아요. [라이선스와 원본 고지](../THIRD_PARTY_NOTICES.md)도 보존해요.

## Risu 캐릭터 카드

서재의 봇·페르소나·모듈 탭에서 **자료 가져오기**를 열고 파일을 선택해요. 봇 탭의 자동 판별은 카드 파일을 봇으로 보고 모듈 파일을 모듈로 봐요. 페르소나와 모듈 탭은 해당 종류를 기본으로 선택하며 창에서 바꿀 수 있어요. 24 MiB를 넘는 파일은 [대용량 경로](#대용량-자료)로 먼저 올리고, 파일 자체는 최대 256 MiB까지 받아요. 봇을 가져오면 새 채팅을 만들고, 비어 있지 않은 기본 `first_mes`가 있으면 그 작성된 시작문을 즉시 열어요. 페르소나와 모듈은 서재에만 등록하며 채팅이나 자동 응답을 만들지 않아요. 가져오기 중 모델을 호출하거나 스크립트를 실행하지 않아요.

- **원래 자료:** `nativeRisu.card`는 카드 `data` 객체, `nativeRisu.module`은 내장 또는 독립 모듈 객체예요. 아래 폐기 필드 정책을 적용하고 알려지지 않은 활성 확장 필드, 비활성 로어, 원래 에셋 역할은 보존해요. `sourceHash`는 입력 파일의 SHA-256이고, `assets`는 자료 이름·URI를 저장한 이미지 ID에 연결해요.
- **저장용 표시:** 기존 서재와 채팅 저장소가 읽는 본문·시작문·로어는 원문에서 읽은 표시 필드예요. 원문 CBS를 그대로 두며 새 `bodyTemplate`, `compat.risuCbs`, `transforms`, `behavior` 프로그램을 함께 만들지 않아요. 본문은 카드 설명이며 대화 예시와 글로벌 노트는 네이티브 프리셋이 정한 대화·블록 위치에서 소비해요. 가져오기는 앱의 전역 프롬프트나 모델 연결을 바꾸지 않아요.
- **원문과 시작문 크기:** 카드·모듈 원문은 합계 8 MiB의 JSON 예산을 사용해요. HTML/CSS 선택 화면을 포함한 개별 시작문·본문·로어는 저장 메시지와 같은 2,000,000자까지 받아요. 시작문 개수나 목록 합계에 별도 상한을 두거나 표시용 복사본을 다시 합산해 원문을 거절하지 않아요. 원문을 잘라 가져오지 않으며 저장 메시지 한도를 넘으면 화면에 알려줘요.
- **로어:** 항상 활성인 항목은 고정 자료로, 나머지 활성 항목은 기본적으로 Uimori 모델 선택을 사용해요. 원래 키·보조 키·정규식·로어북 설정은 원본에 보존하지만 관련성 판단은 JEV가 담당해요. 현재 모델 문맥에 반영하지 않는 위치·삽입 지시문은 가져오기에서 알려요. 비활성 항목도 원문에 남지만 모델 입력 표시에서는 제외해요. 보존 자체가 모든 Risu 로어 지시문의 실행 지원을 뜻하지 않아요.
- **진행 기억:** 로어 항목을 채팅 메모로 옮기거나 가져오기 때문에 비활성화하지 않아요. `memoryIds` 선택 API와 분리 화면은 제공하지 않아요. 과거에 저장한 `imported-memory` 메모·출처·백업은 계속 읽으며 기존 자료나 채팅을 자동 삭제하거나 재분류하지 않아요.
- **이미지:** PNG·JPEG·WebP·AVIF·GIF를 실제로 판독해 공통 이미지 처리 경계에서 고품질 WebP로 저장해요. 원해상도·투명도·지원 애니메이션을 유지하며 이미 WebP인 파일은 재압축하지 않아요. 파일당 64MiB와 픽셀·프레임 처리 한도를 사용하고, 원본을 이중 보관하지 않아요. 이름·설명은 화면과 JEV 선택에, 기존 에셋 참조 이름은 Risu 스크립트에 사용해요. 외부 URL의 파일을 자동 다운로드하지 않아요.
- **원본 파일:** 카드·모듈·프리셋의 현재 원문과 변환된 이미지를 보관해요. 입력 컨테이너 전체를 별도 sourceFiles 영수증으로 영구 저장하지 않아요. 바이트 단위의 원본이 필요하면 가져오기 전 파일을 직접 보관해요. 내보내기는 현재 자료로 새 파일을 만드는 기능이에요.
- **재시도:** 검토 digest가 바뀌면 다시 검토해야 해요. 저장 결과가 불확실하면 같은 파일·선택·요청 키로 확인해요. 이미 성공한 최근 요청은 임시 업로드가 삭제된 뒤에도 작은 처리 결과를 먼저 확인해 봇·채팅·시작문을 중복 생성하지 않아요. 원본 파일이나 전체 변환본을 재시도용으로 영구 보관하지는 않아요. 기존 자료와 운영 데이터는 이 가져오기로 덮어쓰지 않아요.

이 경로는 [네이티브 importer](../server/risu-native-import.ts), [원문 계약](../core/risu-native.ts), [카드 파일 읽기](../server/character-card-file.ts)에 있어요. 원문 저장, 실제 스크립트 실행, 실제 화면 동작 검증은 서로 다른 증거예요. 원문을 읽었다는 사실만으로 모든 봇의 동작이나 UI가 Risu와 동일하다고 주장하지 않아요.

### CharX 내부 자료의 우선순위

`module.risum`은 별도 장착 모듈이 아니라 같은 카드의 직렬화된 자료로 읽어요. 카드와 모듈 원문은 둘 다 남기고 실행 시 다음 우선순위를 적용해요.

- 내장 모듈이 있으면 `regex ?? []`와 `trigger ?? []`가 카드의 인라인 스크립트를 대체해요.
- 내장 `lorebook`은 빈 배열도 카드 로어를 대체해요. 누락/null일 때만 카드 로어를 사용하고 두 목록을 합치지 않아요.
- 이름·설명·시작문은 카드 소유예요. 내부 모듈의 이미지 바이트도 메타데이터 순서대로 읽어 카드 이미지와 함께 저장하되 원문 문서를 덮어쓰지 않아요.
- 손상된 내부 모듈을 조용히 무시하고 인라인 자료로 대체하지 않아요. RPack·컨테이너 버전·UTF-8·CRC·에셋 수·ZIP 경로와 확장 크기 한도를 계속 검사해요. 파일 시스템으로 압축을 풀지 않아요.

## 네이티브 자료 편집과 새 채팅

서재의 Risu 편집기는 이름·설정·기본 시작문·대화 예시·제작자 코멘트를 원문 필드에 저장해요. 글로벌 노트·배경 HTML/CSS·기본 변수를 직접 수정하고, 대체 시작문·로어·정규식·트리거/Lua는 JSON 편집에서 적용해요. 카드 또는 모듈 전체 JSON도 편집할 수 있어요. 알 수 없는 활성 확장 필드는 그대로 남아요. 콘텐츠 편집과 실행의 기준은 이 원문 하나예요.

RisuToki `deprecated-save-policy.ts`에 맞춰 카드의 `personality`, `scenario`, `system_prompt`, `nickname`, `source`, `group_only_greetings`, 카드 `extensions.risuai`의 `additionalText`, `license`, `virtualscript`, 모듈의 `cjs`를 신규 가져오기·저장에서 제외해요. 프리셋에서는 `mainPrompt`, `jailbreak`, `globalNote`, `useInstructPrompt`, `instructChatTemplate`, `JinjaTemplate`을 제외해요.

Uimori는 추가로 프리셋의 `jailbreakToggle`, `chainOfThought`, `promptSettings`의 `sendName`, `sendChatAsSystem`, `postEndInnerFormat`, `assistantPrefill`과 `promptTemplate`의 `jailbreak`·`cot` 블록, 종속 설정 `chatAsOriginalOnSystem`을 제외해요. 일반 블록으로 바꾸거나 별도 경고·알림을 표시하지 않아요. 다른 활성 블록·카드 `post_history_instructions`·사용자 토글·스크립트는 유지해요. 공통 정책은 `core/risu-deprecated-fields.ts`에 있어요.

저장과 가져오기는 같은 원문 투영 함수를 사용해요. 현재 자료 수정에는 새 revision을 붙이지만 모든 과거 개정과 폐기 필드를 영구 보관하지 않아요. 진행 중 요청은 시작한 입력을 유지하며, 새 실행에는 현재 원문과 정책을 적용해요.

새 번역·보조 작업은 현재 설정과 필요한 원문·기억을 읽어 입력을 구성해요. 실행 중 작업을 나중 설정으로 바꾸지는 않아요. 재작성은 현재 설정을 사용하는 독립 채팅 사본이고, 예전 실행 환경을 그대로 복제하는 후보 replay는 제공하지 않아요.

가져오기와 저장 API는 원문에서 본문·시작문·로어·지침·기본 변수를 다시 만들어요. 자료 편집은 일반 저장/취소 방식이고 원문 JSON도 저장할 때 함께 파싱해요. 미완성 입력은 이 기기의 복구 버퍼에 남기되 서버 초안이나 이력으로 동기화하지 않아요. 잘못된 문법은 입력을 지우지 않고 알려줘요. 저장하지 않은 내용은 먼저 저장한 뒤 내보내요. [자료 편집](EDITING.md)

로어 선택은 JEV의 사전 선별 또는 필요할 때 읽기를 사용해요. 봇으로 새 채팅을 시작해도 같은 활성 로어를 사용할 수 있으며, 가져오기 시 최초 채팅만 갖는 별도 기억을 만들지 않아요.

새 채팅은 네이티브 기본 `first_mes`가 있으면 기본 시작문을 선택해요. 선택 화면의 미리보기는 저장된 정확한 자료 리비전으로 일회성 Lua `editDisplay`, CBS, 정규식을 적용한 뒤 읽기 화면과 같은 Shadow DOM 메시지 표면에 표시해요. 미리보기는 채팅·변수를 저장하거나 모델을 호출하지 않고 선택 버튼도 비활성화해요. 페르소나 이름은 반영하지만 별도로 붙인 모듈과 채팅 중 변수는 이 미리보기에 포함하지 않아요.

채팅 백업과 독립 사본은 작성된 메시지·카드 변수 및 Lua가 남긴 메시지 변경분을 보존해요. 식별자를 새 채팅에 연결하지만 전체 모델 전송 입력이나 호출 영수증을 복제하지 않아요. 가져오기 중 스크립트나 모델을 다시 실행하지 않아요. 카드 버튼이 직접 작성한 응답은 작문 모델 재요청 대상으로 삼지 않아요.

네이티브 Lua는 채팅·분기·자료 개정별 격리 worker에서 초기 코드를 한 번 실행하고, 이후 콜백에서도 같은 local/global 값을 유지해요. 저장 변수와 대화는 매 호출 최신 고정값으로 갱신해요. worker 재시작·시간 초과·실행 실패·자료 변경은 그 VM을 폐기하며 영속 상태는 `getState`·채팅 변수로 보존해요. 각 authored script는 내부 RPC와 다른 스크립트의 권한을 볼 수 없는 실행 환경을 사용해요. 함수·`listenEdit` 콜백·동적 `load`는 원래 스크립트 권한을 유지하고, 서로 호출할 때 권한을 합치지 않아요. `LLM`·`axLLM`·`simpleLLM`은 허용된 원본 호출만 Uimori 호스트에 전달하며 화면 표시 콜백에서는 모델 호출을 허용하지 않아요. 미지원 API는 명시적 오류로 남아요.

지속 VM은 채팅 실행과 버튼 동작에 사용해요. Reader의 `editDisplay`와 시작문 미리보기는 저장 상태를 복사한 일회성 VM으로 실행하므로 화면을 열거나 새로고침하는 행위가 카드 상태를 저장하거나 모델을 호출하지 않아요. 표시 콜백이 이전 실행의 Lua local/global 값 자체에 의존하는 카드는 이 차이를 확인해야 해요. 프롬프트 미리보기·도우미·수동 문맥 정리도 상태를 변경하는 입력 콜백을 재실행하지 않고 고정된 자료의 CBS와 정규식 사본을 사용해요.

메시지는 하나의 열린 Shadow Root 안에 HTML 구조와 ID 관계를 보존해 표시해요. 메시지 내부 CSS 선택자는 다른 메시지나 앱의 서재·설정 화면에 일반 선택자로 적용되지 않아요. `html`, `body` 선택자는 Shadow Root의 별도 문서 요소로 재해석하지 않으며, `rem`, 뷰포트 단위와 미디어 쿼리는 앱 문서 기준이에요. 별도 iframe이나 메시지 간 통신 브리지는 사용하지 않아요.

보통 콘텐츠는 문서 흐름으로 높이가 정해져요. 일반 링크·버튼만 있는 메시지에는 레이아웃 관찰이나 이벤트 리스너를 설치하지 않아요. 고정 배치 또는 position 변수 선언이 있는 메시지만 보정을 준비해 미디어/컨테이너 쿼리와 체크박스 전환을 처리해요. 공유 조상은 한 번만 검사하고 실제 고정 요소만 높이 관찰 대상으로 추가하며, 일반 배치로 돌아오면 그 관찰을 해제해요. 가로 화면 밖의 닫힌 패널은 높이에 포함하지 않아요. 고정 배치는 메시지 호스트의 layout containment를 기준으로 해요. 봇 자체의 고정 폭·위치 화면을 모바일용으로 자동 재설계하지 않으므로 실제 카드 확인이 필요해요.

이 표면은 사용자가 신뢰하는 개인용 카드 자료를 전제로 해요. DOMPurify로 작성자 script·이벤트 속성·iframe 등은 계속 제거하지만, 별도 CSP나 CSS 네트워크 차단기는 제공하지 않아요. 외부 자원 참조는 문서와 브라우저 정책을 따르며 Risu 에셋 태그의 로컬 가져오기 규칙은 그대로예요. 임의 JavaScript 실행 지원을 새로 추가하지 않아요. 기존 트리거·Lua와 서버의 리비전/실행 검증도 유지해요.

읽기 설정은 앱이 표시용 Markdown에서 식별한 일반 서술문에 적용하고, 작성자 UI와 DOM 관계를 재구성하지 않아요. `risu-trigger`와 `risu-btn`은 앱의 액션 함수에 직접 연결하며, 실행 성공 뒤에는 다음 서버 리비전까지 중복 실행을 막아요. 실패 시 재시도할 수 있고 오래된 실패가 새 메시지의 실행 상태를 변경하지 않아요.

출력 스크립트가 한 응답에 메시지를 추가하면 각 메시지의 대화 순번으로 표시 콜백과 정규식을 적용해 함께 보여줘요. 이미 표시한 사용자 요청은 반복하지 않아요. 번역과 자동 이미지의 원문 위치는 저장된 본문에 연결하며, 스크립트가 추가한 메시지는 번역 보기에서도 원문으로 유지해요.

표시 에셋은 정확한 이름·URI·확장자 별칭을 먼저 찾아요. 없으면 Risu 기본 규칙처럼 소문자화, 알려진 미디어 확장자와 구분자 제거 후 Levenshtein 거리 4 이내에서 가장 가까운 이름을 선택하며, 동률이면 원래 에셋 순서를 유지해요. 저장된 로컬 에셋만 후보가 되고 외부 URL은 사용하지 않아요. 자동 이미지 배치도 이 표시 규칙을 적용한 결과가 선택한 이미지와 정확히 같은지 확인해요.

독립 가정 장면과 수동 문맥 작업은 고정 입력의 사본에서 CBS·정규식·RISUP 필드를 평가해요. 본편의 지속 Lua VM, 입력·요청·출력 콜백, 추가 모델 호출을 사용하지 않고 채팅 변수나 본편 응답을 바꾸지 않아요. 생략한 콜백은 실행 영수증에 표시하며 가정 장면을 수정하면 새 요청으로 다시 평가해요. 가정 장면의 작문과 문맥 압축에 필요한 모델 호출은 기존 작업 예산과 전송 영수증을 사용해요.

`editRequest`가 마지막 assistant 메시지의 역할과 위치를 유지하면 RISUP의 prefill도 유지해요. 콜백이 그 본문을 편집하면 편집된 본문을 이어 쓰며, 마지막 위치나 역할을 바꾸면 일반 완료 메시지로 취급해요.

카드와 내장 모듈의 트리거 권한은 카드 `extensions.risuai.lowLevelAccess`를 따르며 누락하면 꺼져요. 독립 `.risum`은 모듈의 `lowLevelAccess`를 따르고, 장착한 자료들을 모아 실행해도 각 원본의 권한을 유지해요. 원문 트리거의 개별 필드는 보존하지만 이 상위 권한을 우회하지 않아요.

### 네이티브 로어 위치

새 네이티브 카드의 `@@depth`, `@@end`, `@@reverse_depth`, `@@role`은 활성화된 로어의 역할·위치로 보존해요. `@@depth 0`과 `@@end`는 최종 지시에, 양수 `@@depth`는 실제 전송 대화의 앞쪽 인덱스에, `@@reverse_depth`는 전송 대화의 뒤쪽을 기준으로 넣어요. 일반적인 다른 앱의 depth 이름만 보고 방향을 바꾸지 않고 Risu의 삽입 계산을 따라요. 원래 삽입 순서를 유지하고 조건부 항목은 이번 실행의 고정된 로어 선택 결과에 있을 때만 배치해요. 기존 assistant prefill은 마지막 위치를 유지해요.

`@@depth 0`·`@@end`는 프리셋에서 `postEverything` 슬롯을 중간으로 옮겨 놓았어도 최종 지시 위치를 사용해요. 그 특수한 슬롯 이동이나 슬롯의 래퍼를 로어 메시지 전체에 적용하는 동작까지 동일하게 재현하지는 않아요.

위치를 지정한 항목은 일반 로어·참고 자료 슬롯과 자동 배경 참고 메시지에서 빠져 중복 전달되지 않아요. 고정 로어 문자 예산과 검색·읽기 도구의 원문·참조 범위는 그대로 유지해요. 앱의 기억이나 사용자 메모를 가짜 대화로 바꾸지 않아요. `@@position`·`@@inject_*`와 음수/한도 밖 depth 등 지원하지 않는 지시는 계속 가져오기 안내로 남겨요. 이 계약은 서재의 원래 카드 문서를 바꾸지 않으며 `nativeRisuPosition`은 저장·실행용 투영 정보예요.

### 이미지 선택 지시 옮기기

가져오기 검토와 네이티브 편집기의 **이미지 선택 지시**에서 원문 필드·로어 항목과 이동 범위를 확인해요. `<img...>`를 소비하는 표시 정규식이 있고 이미지 태그 규칙임이 명시된 로어 또는 제목 구간만 자동 후보로 찾아요. CBS 블록 경계가 맞지 않는 구간은 기본 선택하지 않으므로 미리보기를 보고 직접 선택해야 해요. 원문이 바뀌면 이전의 선택을 다른 내용에 자동으로 이어 붙이지 않아요.

채팅의 **이미지 자동 배치**가 켜졌을 때만 선택한 범위를 작문 입력에서 제외하고 이미지 선택 모델의 참고 지침으로 넘겨요. 태그 문법·복장·감정·위치 조건을 포함한 범위 원문을 그대로 보존하며 `imageHandoff`에는 원래 필드, 시작·끝 위치, 선택 여부를 기록해요. 이 정책을 꺼두면 원래 작문 지침을 유지해요. 설정을 바꿔도 카드·모듈 원문이나 저장된 응답을 삭제하지 않아요.

이미지 지시를 감싼 바깥 CBS 조건도 원래 필드에서 평가한 뒤 해당 범위만 추출해요. 예를 들어 서로 다른 연령·복장 분기 안의 이미지 지침을 조건 없이 함께 넘기지 않아요. 평가는 복사한 변수에만 적용하고 주변의 작문 지침은 이미지 모델로 옮기지 않아요. 비활성 로어와 폴더는 이미지 지시로 옮기지 않아요.

선택 모델이 반환한 에셋과 문단 참조는 기존 hash·리비전 검증을 거쳐 표시 사본에만 적용해요. 원래 정규식으로 정확히 같은 로컬 에셋이 나오는 태그만 역으로 찾아 삽입하므로 카드의 이미지 상자를 사용할 수 있어요. 현재 `<img="이름">`와 `<img src=이름>` 계열을 검사하고 복장 변수에 따라 다른 이미지가 나오거나 대응 에셋이 없으면 삽입하지 않아요. 외부 모듈의 이미지를 다운로드하거나 없는 이미지를 다른 이미지로 대체하지 않아요. 이는 임의의 태그·정규식·Lua 이미지 생성 규칙 전체를 재현하는 기능이 아니에요.

새 삽화 생성은 기존 Uimori 삽화 설정과 독립 큐를 사용해요. 일반 네이티브 작문 응답도 자동 생성 예약과 Reader 삽화 표시 대상이며, 카드 첫 화면이나 버튼이 직접 작성한 문장은 자동 예약하지 않아요. 별도 Lightboard 모듈을 내장하지 않아요. 테스트에서는 로컬 표본의 태그·정규식·에셋 연결과 합성 생성 완료를 검증하며 실제 이미지 생성 제공자의 결과나 창작 품질을 보증하지 않아요.

## 대용량 자료

24 MiB가 넘는 카드·모듈 파일은 요청 본문 대신 **먼저 서버에 올린 뒤** 검토해요. 화면에서 파일을 고르면 자동으로 이 경로를 사용하고, 올린 파일은 DB 옆의 `uploads` 디렉터리에 두었다가 등록이 끝나면 지워요. 검토를 끝내지 않은 파일은 24시간 뒤 정리하며, 정리된 뒤 등록을 누르면 파일을 다시 선택하라고 안내해요. 한도는 256 MiB예요.

파일 크기와 무관하게 원래 카드·모듈 JSON과 지원 이미지를 앱 자료로 저장하고, 입력 컨테이너 전체의 별도 사본은 보관하지 않아요. 최초 파일이 필요하면 직접 보관해요. 현재 자료를 새 CHARX로 만드는 기능은 [Risu 내보내기](RISU-EXPORT.md)를 참고해요.

ZIP의 개별 항목은 64 MiB, 압축을 푼 전체 크기는 64 MiB와 입력 파일의 4배 중 큰 값까지 받아요. 독립 RISUM은 파일당 256 MiB이며 각 이미지와 JSON의 처리 예산은 그대로 적용해요. 내보내기도 같은 파일·확장 예산을 사용하므로 64 MiB를 넘는 이미지 묶음이라는 이유만으로 거절하지 않아요. 이미지는 별도의 픽셀·프레임 작업량 한도로 처리하고, 오디오·영상 등 현재 이미지 저장소가 지원하지 않는 에셋은 안내로 남겨요.

## 봇·페르소나·모듈

### 구조화된 Risu 모듈 JSON

RisuToki의 **파일 → 파일을 프로젝트 폴더로 추출…**에서 `.risum`을 새 폴더로 내보내면 `{ "type": "risuModule", "module": {...} }` 형식의 `module.json`이 생성돼요. 서재 모듈 탭의 **자료 가져오기**에서 이 파일을 선택하고 **모듈 가져오기**를 눌러요. 모듈로 등록하며 봇·채팅·진행 기억을 자동 생성하지 않아요. 등록 후 기존 채팅의 봇·페르소나·모듈 설정에서 장착할 수 있어요.

독립 `.risum`도 같은 화면에서 직접 읽을 수 있어요. 모듈 객체 전체를 `nativeRisu.module`로 보존하고 활성 로어·이름·설명은 서재 표시용으로 읽어요. 모듈 설명은 작문 본문에 복사하지 않아요. 바이너리 에셋과 JSON의 PNG/JPEG/WebP/AVIF/GIF data URL 이미지는 같은 이미지 저장 경로를 사용해요. 정규식·Lua·트리거·CSS·토글·namespace/MCP 등은 원문으로 남으며 실행 지원 범위와는 구분해요.

추출 폴더의 이미지도 옮기려면 **`module.json`과 `.risutoki` 폴더를 함께 ZIP으로 압축**하고 그 ZIP을 선택해요. 하나의 상위 폴더로 감싸져 있어도 읽어요. `.risutoki/workspace.json`의 `risumAssetFiles` 순서로 원래 모듈 에셋과 연결하며, 목록이 없는 경우 `.risutoki/risum-assets/*.bin`의 파일명 순서를 사용해요. 실제 이미지 바이트로 형식을 확인하며 누락된 파일은 미지원으로 표시해요. ZIP 안에서만 읽고 외부 경로나 로컬 파일 시스템으로 추출하지 않아요. 여러 모듈 정의나 카드·모듈 정의가 함께 있는 모호한 프로젝트 ZIP은 거절해요.

RisuToki에서 추출한 JSON/ZIP과 원래 RISUM을 모두 가져올 수 있어요. 추출 도구가 적용한 정규화·폐기 필드 제거 때문에 두 파일이 동일하다고 간주하지 않아요. 앱은 실제 읽은 현재 원문과 지원 이미지를 저장해요.

## Risu 프리셋

프롬프트 관리의 **프롬프트 가져오기**에서 `.risup`·구형 `.risupreset` 바이너리, 프리셋 JSON 또는 RisuToki 프로젝트 ZIP을 선택해요. **작문 프롬프트로 저장**하면 `RisuPrompt.nativeRisuPreset`에 프롬프트 관련 원본을 보존해요. **가져온 프롬프트 편집**에서는 Risu의 메시지 구성·CBS 원문·토글·기본 변수·정규식을 직접 편집해요. 실행용 블록은 원본에서 만들며 별도의 수동 이식본으로 관리하지 않아요. `.risup`의 RPack·압축·MessagePack 해독과 가져오기 검토는 코드를 실행하지 않으며 현재 프리셋 원문을 독립 자료 백업에 담아요.

프리셋의 블록 수나 원문 750,000자에 별도 상한을 두지 않아요. 파일 처리와 프롬프트 실행의 메모리 예산, 실제 모델에 보내는 토큰 예산은 각 경계에서 확인해요.

Risu의 `memory` 슬롯은 사용자 메모로 치환하지 않아요. Uimori는 과거 요약을 전송 대화 문맥에 포함하고 사용자 메모·정정을 별도 참고 정보로 전달해요. 실제 전달은 선택한 프롬프트와 문맥 구성에 따르며, 가져오기 안내에 Risu 슬롯의 위치·래퍼는 직접 적용하지 않는 차이를 설명해요. 슬롯을 추가해 같은 요약을 중복 삽입하지 않아요. 모델·파라미터·도구는 Uimori가 별도로 관리하므로 가져오기 대상이나 미지원 손실로 계산하지 않아요.

실행 시 CBS는 시간·출력 제한이 있는 worker에서 원본 그대로 평가하고, 필드 간 변수 변경도 같은 평가 문맥을 사용해요. 평가 결과는 해당 실행 동안 고정해요. 완료 후에는 이어쓰기 결과만 남기고, 재접속이나 백업 복원으로 실행을 반복하지 않아요. 프리셋 정규식은 네이티브 `editinput`·`editoutput`·`editprocess`·`editdisplay` 단계에 연결하며 캡처 치환 뒤 CBS를 평가해요. 예전 32개 규칙 변환 제한을 적용하지 않지만 worker 실행·메모리·출력 한도는 유지해요. `@@inject`·`@@repeat_back`·`@@emo` 같은 host 특수 명령과 일부 Risu 확장 동작은 아직 실행하지 않고 문제로 보고해요. 구형 Uimori AST와 공통 텍스트 변환 형식은 지원하지 않아요.

모델·프로바이더·인증·생성 파라미터·도구 권한은 Uimori가 소유해요. RISUP를 가져오거나 적용해도 이를 덮어쓰지 않으며 네이티브 프롬프트 편집기에도 노출하지 않아요. 가져오지 않는 연결 정보가 필요하면 원본 파일을 별도로 보관해요. 실제 봇과 개인 프리셋 조합의 창작 품질은 별도 확인이 필요해요.

## 프롬프트 편집

현재 프롬프트와 저장 프리셋 모두 RISUP의 메시지 구성·CBS·토글·기본 변수·정규식 원문을 편집해요. 모델과 연결 설정은 별도로 관리해요. 형식과 저장 계약은 [프롬프트 실행](PROMPT-RUNTIME.md), 원문 및 이미지의 이동은 [Risu 내보내기](RISU-EXPORT.md)를 확인해요.
## 저장 정보의 책임

Risu 원문은 편집·실행 기준이며 본문·로어·시작문 투영은 이를 읽기 위한 표현이에요. 요청 컨텍스트에는 자료 ID·역할·이름과 로어 항목 ID를 함께 전달해 같은 이름을 가진 자료를 구분해요. 이 출처 메타데이터를 카드의 원래 문자열에 덧붙이지 않아요. 공통 모듈은 현재 저장본을 따라가고, 별도로 보관할 판본은 명시적인 사본이나 백업으로 관리해요. [입력 수명](EXECUTION.md)과 [독립 채팅 복원](CHAT-BACKUP.md)을 참고해요.

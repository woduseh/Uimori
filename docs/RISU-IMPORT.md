# Risu 자료와 native JSON 가져오기

> 현재 구현의 사용 안내예요. [베타 결정](DECISIONS-2026-09-12-BETA.md)에 따라 Risu 가져오기·표현 변환·선택적 호환 실행을 준비하며 구현/검증 상태는 [베타 계획](../project-plan/BETA-PLAN.md)에 기록해요.

앱은 `.charx`·Character Card JSON과 구조화된 Risu 모듈 JSON/프로젝트 ZIP의 기본 자료를 가져오며, Uimori의 `ContentPackage`·`PromptProgram` JSON도 읽어요. 프리셋 `.risup`·`.risupreset` 바이너리와 JSON/프로젝트 ZIP은 아래 프리셋 범위에서 읽어요. 독립 `.risum` 파일은 지원 대상에서 제외해요. CharX 내부 모듈의 자료와 아래 범위의 Lua 콜백을 읽고, 아직 연결하지 않은 동적 스크립트·표시 기능은 원본과 안내로 보존해요. `.risup` 해독에는 RPack 치환표를 사용하며 [라이선스와 원본 고지](../THIRD_PARTY_NOTICES.md)를 보존해요.

## Risu 캐릭터 카드

서재의 봇·모듈 탭에서 **Risu 자료 가져오기**를 열고 `.charx` 또는 카드 JSON(최대 256 MiB, 24 MiB를 넘으면 [대용량 경로](#대용량-자료))을 선택해요. 설명·시작문·로어·첨부 이미지와 지원하지 않는 부분을 확인한 뒤 **가져오고 새 채팅 열기**를 누르면 새 봇과 채팅을 함께 만들어요. 기존 자료를 덮어쓰거나 모델을 호출하지 않아요.

**가져올 자료 종류**에서 봇·모듈을 선택해요. 자동은 카드/CharX를 봇으로, 명시적인 모듈 JSON·프로젝트 ZIP을 모듈로 읽어요. 모듈 탭에서 새로 시작하면 모듈이 기본이며, 이전에 검토한 파일과 종류는 탭 이동에도 유지해요. 모듈은 서재에만 등록하고 새 채팅·진행 기억을 만들지 않아요. CharX 파일명이나 아이콘으로 용도를 확정하지 않아요. 종류를 바꾸면 같은 파일을 다시 검토하고, 실패하면 이전 검토를 유지해요. 저장 응답이 불확실한 동안에는 종류를 바꾸지 않고 같은 요청으로 확인해요.

- 로어북은 기본적으로 봇 자료로 유지해요. 대부분의 봇에는 이전 플레이 기억이 없으므로 기억 분류는 필수 단계가 아니에요. 필요한 경우에만 접힌 **로어북에서 과거 진행 기억 분리하기 (선택)**를 열어요. 자동 선택은 없고, 선택한 활성 항목만 출처가 있는 `imported-memory` 메모로 옮겨요. 이는 실제 채팅 원문이나 사용자 지시가 아니에요.
- 기본/대체 시작문은 사용자가 고를 수 있는 authored 시작문으로 보존해요. 디스크립션과 대화 예시를 가져오고, 성격·시나리오 필드와 메인 프롬프트 덮어쓰기는 제외 사실을 안내한 뒤 원본 파일에만 보존해요.
- 글로벌 노트(`post_history_instructions`)는 봇의 추가 작문 지침으로 가져와 기존 프롬프트와 함께 전달해요. 전역 설정이나 선택한 프롬프트를 덮어쓰지 않으며 Risu 삽입 위치를 재현하지 않아요. `{{original}}` 참조는 비워서 기존 프롬프트가 중복 전달되지 않게 하고 이 차이를 안내해요. 내용이 이 참조뿐이면 빈 추가 지침을 만들지 않아요.
- 로어는 먼저 Risu 스냅샷의 `convertCharbook`을 거쳐요. 다른 프론트엔드가 CCv3 `extensions`(position·depth·role·selectiveLogic·probability)로 적은 설정도 Risu가 쓰는 `@@` 지시문 줄로 바뀌어 같은 규칙을 받아요. 맨 앞의 `@@` 지시문은 Risu와 같은 파서(대소문자 구분)로 본문에서 떼어내 읽어요. `@@dont_activate`는 Risu가 한 번도 활성화하지 않는 항목이라 **모델에 보내지 않고** 자료가 스스로 쓰는 자료·코드로 보고 원본 파일에만 보존해요. `@@activate`는 항상 활성으로 읽어요. 활성화를 정하는 지시문(`activate_only_after`·`activate_only_every`·`scan_depth`·`additional_keys`·`exclude_keys`·`match_*`·`probability`·`priority`·`ignore_on_max_context`·재귀 관련)은 규칙으로 보존해 아래 키워드 활성화가 그대로 적용하고, 위치·삽입 지시문(`depth`·`reverse_depth`·`end`·`role`·`position`·`inject_*`)은 아직 적용하지 않아 이름별로 안내해요. `keep_activate_after_match`·`dont_activate_after_match`가 남기는 활성 상태 기억은 저장하지 않아 이번 생성 안에서만 반영되고, `is_greeting`은 선택한 시작문 순번을 알 수 없어 0번으로 봐요. 모르는 이름은 목록으로 알려요. 본문은 Risu처럼 앞뒤 공백을 정리하고, 본문 중간의 `@@` 줄은 해석하지 않고 그대로 남기고 차이를 안내해요.
- 항상 활성인 로어는 고정 자료로, 키워드 로어는 **키워드 활성화** 규칙(키·보조 키·selective·정규식·`@@` 줄)을 [패키지의 `activation`](PACKAGES.md)에 보존한 채 가져오고 패키지를 `loreActivation.mode = 'keyword'`로 만들어요. 로어북의 `scan_depth`·`recursive_scanning`·`risu_fullWordMatching`은 패키지 설정으로 옮기고, `token_budget`은 [채팅 설정의 조회 로어 문자 한도](LORE-CONTEXT.md#키워드-활성화)가 대신하므로 버려요. 생성마다 최근 대화·요청에서 Risu와 같은 규칙으로 켜진 로어만 모델에 들어가고, 패키지 편집에서 모델 조회 방식으로 바꿀 수 있어요. PNG·JPEG·WebP 첨부는 실제 바이트 형식과 기존 2 MB 이미지 한도를 확인해요. 외부 URL은 다운로드하지 않아요.
- 제작자 코멘트(`creator_notes`)는 자료 설명으로 가져오고, 4,000자를 넘으면 뒤를 줄임표로 줄인 뒤 그 사실을 안내해요. 코멘트가 없는 카드만 파일 이름을 담은 기본 문구를 써요. 태그·제작자·카드 버전·별칭은 자료 필드로 옮기지 않고 원본 파일에만 남겨요.
- 감정 화면·이미지 생성 화면(`viewScreen`·`inlayViewScreen`)과 확장 설정의 감정·추가 에셋 목록은 미지원으로 안내해요. 카드 첨부의 감정·배경 이미지는 역할 없이 일반 이미지로만 들어오며, 유틸리티 봇·라이선스·출처·이미지 생성 설정과 RisuAI 자신도 가져오기에서 지우는 `depth_prompt`는 각각 안내로 표시해요.
- 설명·로어·지시·시작문의 `{{char}}`·`{{user}}`는 공통 템플릿으로 변환해요. 새 요청이나 시작을 확정할 때 선택한 봇·페르소나 이름을 적용하고 원래 표기와 AST는 패키지에 보존해요. 분리한 진행 기억은 별도 외부 기록이므로 원문을 그대로 보관해요. 지원하는 CBS 읽기·조건도 공통 AST로 변환하며 범위는 아래를 봐요. 독립 Lua 트리거의 일부 콜백은 아래 범위로 연결하며 커스텀 UI·미지원 CBS·나머지 트리거는 보존·안내해요. 보고된 미지원 기능은 명시적으로 부분 가져오기를 선택해야 진행해요.
- 카드의 `extensions.risuai.customScripts`에 있는 정적 `editdisplay` 정규식은 기존 응답 본문 표시 기능으로 가져와요. 기본/사용자 flags·캡처·`$n` 개행·`<order N>` 순서를 보존하며 저장 원문·사용자 메시지·번역은 바꾸지 않아요. CBS 재평가·HTML 패널·주입/이동 등 특수 동작·다른 처리 단계는 미지원으로 표시해요. 실제 source segment 경계가 있는 원문에서는 기존 구간 표시 규칙이 우선해요. 정규식 문법·실행은 기존 제한된 worker가 처리하며 오류는 원문을 보존한 채 표시해요.
- 원본 파일은 자료 이동 영수증의 `sourceFiles`에 보존하며 모델 입력에 복사하지 않아요. 자료 파일 재내보내기와 전체 archive에도 포함돼요. 전송 결과가 불확실하면 파일·선택·요청 키를 유지해 같은 요청으로 확인하고 중복 생성하지 않아요.

구현은 [RisuImport](../web/RisuImport.tsx), [단방향 변환](../server/risu-import.ts), [카드 파일 읽기](../server/character-card-file.ts)에 있어요. 특정 봇 이름에 따른 처리는 없으며 Risu 실행기에 의존하지 않아요. 프리셋과 CharX 내부 모듈은 같은 RPack 해독 함수를 사용하며 각 컨테이너의 구조는 별도로 검사해요. 파일을 읽었다는 결과는 표본 전체의 기능 수용 완료와 구분해요.

### CharX 내부 자료의 우선순위

고정 Risu 내보내기는 로어·정규식·트리거를 `module.risum`에도 저장해요. 이 파일은 별도 장착 모듈로 추가 등록하지 않고 **같은 카드의 자료**로 읽어요. `server/risu-module-file.ts`가 경계·버전·UTF-8·에셋 수를 검사해 해독하고, `character-card-file.ts`가 다음 순서로 정규화해요.

- 내장 모듈이 있으면 `regex ?? []`와 `trigger ?? []`가 카드의 인라인 스크립트를 대체해요.
- 내장 `lorebook`이 있으면 빈 배열도 카드 로어를 대체해요. 누락/null일 때만 카드 로어를 사용해요. 두 목록을 합치지 않아요.
- 이름·디스크립션·제작자 코멘트·시작문·카드 에셋은 카드 소유예요. 내장 모듈의 이름이나 설명으로 덮어쓰지 않아요. 카드 첨부와 별개인 내부 모듈 에셋은 자동 연결하지 않고 미지원으로 안내해요.
- 손상된 내부 모듈을 무시하고 인라인 자료로 조용히 대신 가져오지 않아요. 원본 CharX 한 개는 native transfer 영수증에 보존해요.

모듈 JSON과 내부 모듈의 로어는 같은 `moduleLoreEntries` 변환을 사용해요. 검토 digest는 원본을 포함한 native 변환 결과·종류·안내·로어 목록에 결합하므로 파일이나 해석 결과가 달라진 요청은 재검토해야 해요.

현재 파일 24 MiB, ZIP 전체 해제 크기 64 MiB·멤버 4,096개, 자료 에셋 2,000개 한도를 유지해요. Merry처럼 이 한도를 넘는 제공 표본은 대용량 가져오기 경로가 필요한 후속 범위예요. 한도 내 파일의 부분 가져오기를 전체 표본 기능 인수로 간주하지 않아요.

### 기본 변수와 읽기 CBS

`extensions.risuai.defaultVariables`와 프리셋의 `templateDefaultVariables`는 [공통 템플릿 변수](PROMPT-RUNTIME.md#템플릿-기본-변수) 선언으로 가져와요. 고정 Risu의 `getChatVar`처럼 봇 기본값이 프리셋 기본값보다 우선해요. 기본값은 저장된 채팅 상태의 초기 복사본이 아니며, 토글 값이나 패키지 행동 state로 바꾸지 않아요. 카드 선언은 **봇 역할일 때만** 적용하고 모듈은 선택한 봇·프리셋의 같은 값을 읽어요. 같은 카드가 모듈·페르소나로 장착됐다고 봇 기본값을 덮어쓰지 않아요.

어댑터는 고정 Risu `parseKeyValue` 의미대로 줄마다 첫 `key=value` 쌍만 읽고 공백을 정리하지 않아요. 빈 key/value는 무시하며 첫 중복이 우선해요. 따라서 `a=b=c`는 `a → b`예요. 문자열에 들어 있는 CBS를 다시 실행하지 않아요. 허용하지 않는 이름·형식·한도 초과는 부분 가져오기 대상으로 안내하고 원본에 보존해요.

`server/risu-cbs.ts`의 파서를 카드 텍스트·프리셋·프리셋 정규식이 공유해요. 이름, `getvar`, 기존 토글 읽기·비교·문자열 계산, `#when`의 `var`·`vis`·`visnot`, `#if`·`#if_pure`를 기존 AST로 표현해요. 조건의 참은 Risu처럼 문자열 `1`/`true`이고 없는 변수는 문자열 `null`이에요. `{{// …}}`와 `{{comment::…}}` 주석은 Risu처럼 빈 출력으로 다뤄 같은 항목의 나머지 문법을 그대로 변환해요. 모든 CBS 명령이나 조합을 지원한다는 의미는 아니에요. 카드 항목은 두 갈래로 갈라져요. 변환할 수 있는 CBS는 공통 AST로 옮기고, AST로 표현할 수 없는 항목은 패키지의 `compat.risuCbs`에 필드로 선언한 뒤 원문을 그대로 보존해요. 선언한 필드는 Run 예약 시점에 고정 Risu 스냅샷 평가기로 한 번 평가해요. 평가가 읽는 입력은 예약이 고른 이름, 공유 변수와 기본값, 현재 분기 대화와 이번 요청, 예약 시각, run과 필드로 만든 seed뿐이에요. 결과는 Run 스냅샷 영수증으로 고정하므로 복원과 미리보기는 다시 평가하지 않아요. 원문 안의 `setvar`류 쓰기는 그 한 번의 평가 안에서만 보이고 채팅에 저장하지 않아요(후속 범위). 화면·에셋·모듈 함수는 빈 문자열로 평가하고 가져오기 안내에 그 이름을 나열해요. 프리셋의 미지원 블록/정규식은 비활성화·제외와 안내를 유지해요. 미지원 블록의 원문은 꺼진 블록 안에 텍스트로 남겨 편집기에서 고칠 수 있게 해요.

사용자가 [분기 공유 변수](PROMPT-RUNTIME.md#분기-공유-변수)를 직접 저장하면 그 값이 기본값보다 우선하며 지원하는 읽기 CBS에도 적용돼요. Lua의 공유 쓰기는 아래 이벤트와 Host API 범위로 연결해요. `compat.risuCbs`로 선언한 필드 안의 `setvar`·`addvar`·`setdefaultvar`는 예약 시점 평가에만 적용하고 분기 공유 변수에는 쓰지 않아요. 쓰기 반영과 나머지 실행 시점은 후속 범위예요. 해당 코드가 있는 자료는 부분 가져오기이며 동적인 게임 상태나 상태창 전체가 재현됐다고 볼 수 없어요. 기존 가져온 자료·과거 Run에 새 변환을 자동 적용하지 않아요.

### 선언형 트리거 효과

스크립트 없이 `setvar`만 사용하는 트리거는 공통 행동 하나로 연결해요. Risu와 같이 트리거의 `type`이 실행 시점을 정하며 `start`는 생성 전, `input`은 입력 단계, `output`은 완성 응답 후, `manual`은 트리거 이름을 단 사용자 버튼이 돼요. `display`·`request` 시점은 Risu도 v1 효과와 `triggerlua`를 실행하지 않아요(그 허용 목록에는 v2 opcode만 있어요). 이 시점의 트리거는 연결할 대상이 없어 원본 선언만 보존해요. 조건은 Lua 콜백과 같은 변환을 사용하고, 변환할 수 없는 조건·효과 종류·실행 시점에 정해지는 변수 이름이 있으면 그 트리거를 연결하지 않고 원본 선언만 보존해요.

값 계산은 Risu의 고정 구현과 같은 JavaScript 숫자·문자열 의미를 사용해요. `=`는 CBS를 해석한 문자열을 그대로 저장하고 `+= -= *= /=`는 현재 값을 숫자로 읽어(숫자가 아니면 0) 계산한 결과를 문자열로 저장해요. 값 안의 `{{getvar::이름}}`은 같은 분기 공유 변수를 읽고 없는 변수는 `null` 문자열이에요. 이 행동은 분기 공유 변수를 바꾸므로 채팅에서 해당 자료 개정에 **공유 변수 변경**을 허용해야 실행해요.

스크립트와 효과가 섞인 트리거는 **스크립트가 첫 효과가 아닐 때** 선언 순서를 유지해 연결해요. 효과 → 스크립트 콜백 → 효과를 그 트리거의 실행 시점 하나에서 차례로 실행하고, 이때 스크립트 콜백은 Risu와 같이 그 시점의 콜백만 호출해요. 스크립트가 첫 효과면 Risu가 모든 시점에서 트리거를 실행하므로 아직 연결하지 않아요. 수동 트리거의 효과와 스크립트를 한 번의 클릭으로 묶는 경로도 아직 없어요. Risu는 조건을 효과보다 먼저 한 번만 판정하므로, 트리거가 자신의 조건이 읽는 변수를 바꾸면 같은 의미로 옮길 수 없어 연결하지 않고 원본을 보존해요.

카드가 저수준 접근을 선언한 경우 `runLLM`과 `extractRegex`도 연결해요. `runLLM`은 해석한 값을 하나의 요청으로 보내 결과를 지정한 변수에 저장하고, 실패는 Risu와 같이 `Error: …` 문자열로 남겨요. 설정의 **확장 호출 모델**과 채팅의 **추가 모델 호출 허용**이 필요하며, `<|im_start|>`로 시작하는 ChatML 형식 프롬프트는 한 메시지로 바꿔 보내지 않고 오류로 표시해요. `extractRegex`는 같은 정규식·플래그로 한 번 매칭해 `$1`·`$&`·`$$` 치환 결과를 변수에 저장하고, 매칭이 없으면 오류로 표시해요. 카드가 저수준 접근을 선언하지 않으면 Risu와 같이 두 효과를 실행하지 않고 나머지 효과만 실행해요.

`cutchat`·`modifychat`·`systemprompt`·`impersonate`·`command`·`runImgGen` 같은 나머지 효과 종류는 아직 연결하지 않고 안내와 원본 보존으로 남겨요.

### Lua 콜백 가져오기

독립 `triggerlua` 효과의 원본 코드를 Lua 프로그램으로 보존해 `onInput`은 입력 단계, `listenEdit("editInput")`은 입력 편집 단계, `onStart`는 생성 전, `listenEdit("editRequest")`는 전송문 편집 단계, `listenEdit("editOutput")`·`onOutput`·`listenEdit("editDisplay")`는 완성 응답 후, `onButtonClick`은 문자열 입력을 받는 사용자 행동으로 연결해요. `onInput`은 공통 자동 준비의 `hook: 'input'` 단계로 구분해 모든 시작 행동보다 먼저 실행하며, 대화 읽기에는 이번 입력을 덧붙이지 않아요. `onStart`부터 이번 입력을 포함해요. 원래 요청과 예약 snapshot은 보존하고 계산한 상태·변수는 기존 준비 영수증과 본문 성공 시 채택 경계를 사용해요. 실패·건너뛰기·취소도 기존 자동 준비 규칙을 따라요. `trigger.type`만으로 콜백을 추정하지 않으며 실제 호출 때 등록된 함수를 찾아요. 가져오기·일반 미리보기·복원에서는 실행하지 않아요. 공유 변수 쓰기·대화 읽기·모델 호출은 정확한 자료 개정에 대해 채팅별로 각각 허용해야 해요.

`getChatVar/setChatVar/setChatVarChanged`, `getState/setState/setStateChanged`, JSON 모듈·`async`와 `simpleLLM`은 공통 Host API를 사용해요. 없는 변수의 문자열 `"null"`, 빈 값, 저장된 override와 기본값의 차이, Risu JSON의 nil/빈 테이블 의미를 어댑터에서 처리해요. 호출별 Lua 전역은 새로 초기화되므로 영속 상태는 공유 변수/`getState`에 저장해야 해요.

`getChat/getChatMain/getChatData/getChatRole/getChatLength`, `getRecentChats/getRecentChatsMain`, `getFullChat/getFullChatMain`, `getUserLastMessage/getCharacterLastMessage`는 [현재 분기 대화 Host](EXTENSION-PROGRAMS.md#host-api로-현재-분기-대화-읽기)를 사용해요. 모델 문맥 절삭과 무관하게 현재 분기에서 사용자가 볼 수 있는 저장 대화를 읽고, 입력 단계는 현재 요청을 제외하고, 생성 전·모델 행동은 현재 요청, 응답 후 행동은 현재 요청과 완성 응답을 덧붙여요. 다른 채팅·분기·삭제·대체된 기록과 앱 설정·연결 설정의 API 키는 제공하지 않아요. 사용자가 대화 본문에 직접 쓴 문자열은 원문으로 취급해요. 원본에 없는 시각은 `0`이고 저장되지 않은 첫 인사 대체값은 만들지 않아요. 전체 조회가 실행 한도를 넘으면 일부 결과를 성공으로 반환하지 않아요.

`getName`·`getPersonaName`·`getDescription`은 [자기 자료 Host](EXTENSION-PROGRAMS.md#host-api로-자기-자료-읽기)를 사용해요. 앞의 두 함수는 본문·로어 템플릿이 넣는 것과 같은 봇·페르소나 이름을 읽고, `getDescription`은 같은 패키지의 본문 자료를 조각 읽기로 이어 붙여 돌려주며 본문 자료가 없으면 빈 문자열이에요. 고정 Risu가 저장 원문 `desc`를 그대로 주는 것과 달리 이름·옵션·공유 변수 템플릿을 적용한 투영 본문을 읽는 의도적 차이가 있어요. 다른 Host 함수와 같이 호출자가 넘긴 id로 대상을 바꾸지 않고 이번 호출에 고정된 자료만 읽어요. `getPersonaDescription`은 페르소나 본문을 읽는 경로가 없고 `setName`·`setDescription`·`setCharacterFirstMessage`는 자료를 바꾸는 경로가 없어 계속 미지원 오류로 남겨요.

Risu의 `var`·`value` 트리거 조건과 지원하는 비교/CBS 값은 공통 `when` 식으로 변환해 `onInput`·`onStart`·`onOutput` 자동 행동에 적용해요. 변수값 자체에 실행할 CBS가 남아 있거나 조건 종류·연산·CBS 블록을 안전하게 변환할 수 없으면 조건을 버리지 않고 해당 자동 콜백 실행을 보류해요. 다른 효과와 섞인 `triggerlua`도 원래 순서를 바꾸지 않고 소스만 보존해요.

`listenEdit("editInput")`은 입력 단계 다음, 생성 전 단계보다 먼저 실행해 **이번 요청의 전송 사본**에 적용해요. 저장한 요청 원문·hash·편집 기준은 그대로 두므로 Risu가 편집 결과를 대화에 저장하는 것과 다른 의도적 차이예요. Reader의 요청 항목에서 원문과 전송문을 비교할 수 있어요. Risu의 편집 경로와 같이 트리거 조건을 적용하지 않고, 등록 순서대로 값을 이어 넘기며 콜백이 `nil`을 반환하면 직전 값을 유지해요. 여러 자료가 선언하면 자료 장착 순서로 이어져요. `meta.index`는 Risu와 같이 `-1`이고 대화 읽기에는 이번 입력을 덧붙이지 않아요. 문자열이 아니거나 100,000자를 넘는 반환은 자동 준비 묶음의 실패로 처리해 원래 요청으로 계속해요. 이어지는 프리셋 전송 정규식은 편집된 사본을 입력으로 받지만, 같은 요청의 `onStart`·대화 읽기 Host는 저장된 원문을 그대로 읽어요.

`listenEdit("editRequest")`는 생성 전 단계 다음에 실행하고 **전송용 원문 대화와 이번 요청만** `{role, content}` 목록으로 받아요. Risu가 시스템 프롬프트·로어·다른 자료의 지침까지 합친 최종 배열을 넘기는 것과 달라요. 메시지 수와 역할은 바꿀 수 없고 본문 텍스트만 바꿀 수 있으며, 다른 모양을 반환하면 자동 준비 묶음의 실패로 처리해 원문 대화를 그대로 보내요. 이 채팅에서 해당 자료 개정에 **대화 읽기를 허용**해야 실행하고, 허용이 없거나 대화가 실행 한도(메시지 1,000개·메시지당 100,000자·합계 100,000자)를 넘으면 편집을 건너뛰고 Reader에 안내해요. 편집 결과는 이번 전송 사본에만 적용하고 저장한 원문·hash·이후 대화 읽기는 바꾸지 않아요.

`listenEdit("editOutput")`과 `listenEdit("editDisplay")`는 완성 응답을 저장한 뒤 응답 후 단계에서 **한 번 계산**해 이 응답의 표시 사본을 만들어요. Risu는 `editOutput` 결과를 대화에 저장하지만 Uimori는 저장 원문을 바꾸지 않고, 다음 턴의 문맥·대화 읽기·`onOutput`도 원문을 읽어요. 전송에서 빼야 하는 내용은 [본문 구간](SOURCE-SEGMENTS.md)을 사용해요. 실행 순서는 `editOutput` → `onOutput` → `editDisplay`이고, 결과는 프리셋 표시 정규식보다 먼저 적용해요. 새로고침·분기·복원은 저장한 결과를 읽고 코드를 다시 실행하지 않으며, 원문을 편집하면 이 표시 사본은 사라져요. 문자열이 아니거나 100,000자를 넘는 결과는 그 자료의 응답 후 묶음 실패로 처리해 원문을 그대로 표시해요. 구간 경계가 있는 응답에는 적용하지 않고 안내해요. 여러 자료가 함께 선언하면 자료별로 `editOutput → onOutput → editDisplay`를 묶어 순서대로 실행해요. Risu처럼 모든 자료의 `editOutput`을 먼저 모으지 않아요.

대화 변경·나머지 자료/UI API와 동적 화면은 아직 연결하지 않아요. 해당 부분을 가져오기 안내에 남기고 미지원 API는 성공한 것처럼 처리하지 않아요. Lua 외 트리거·커스텀 표시와 CBS 쓰기 역시 후속 범위예요. 이 연결은 동적인 상태창·선택기나 전체 표본 기능의 완료를 뜻하지 않아요.

## Risu 플러그인 파일

같은 **Risu 자료 가져오기**에서 플러그인 `.js`를 선택하면 지원 범위 보고를 보여 줘요. **코드는 실행하지 않고 자료로 등록하지도 않아요.** 파일이 선언한 `//@name`·`//@display-name`·`//@api`·`//@arg`·`//@link`·`//@version`·`//@update-url`·`//@allowed-ipc`를 읽고, 본문이 언급한 `risuai.*` 이름을 현재 계약과 대조해 세 가지로 나눠요.

- **대응 가능**: 지금의 공통 API로 옮길 수 있는 이름이에요. 플러그인 인자 읽기, 입력·출력·표시 텍스트 처리와 편집 훅(메시지 수와 역할은 유지해야 해요), 대화 이벤트, 현재 봇·채팅 읽기, 자기 자료 읽기, 추가 모델 호출, 실행 환경·버전 정보가 여기에 들어가요. 옮기는 작업 자체는 아직 하지 않아요.
- **미구현**: 일반 HTTP·비밀 헤더(`risuFetch`는 원문에서도 대체된 옛 이름), 제공자·MCP 어댑터와 요청 본문 가로채기, 음성 합성, 에셋 읽기/저장, 번역 캐시, 플러그인 설치·상호 통신·`//@allowed-ipc` 채널, 플러그인 인자 쓰기, 앱 전역 플러그인 저장소(채팅 분기의 공유 변수와 범위·형식·허용 조건이 달라요), 런타임 CBS 파싱, `onUnload`(상주 인스턴스가 없어요), `log`처럼 아직 만들지 않은 경로예요.
- **제공하지 않음**: 번호로 다른 채팅·다른 캐릭터를 고르는 조회(Uimori는 현재 대화와 자기 자료만 노출해요), 앱 설정 전체를 읽는 `getDatabase`(원문에서도 읽기 전용 프록시지만 다른 자료까지 드러나요), 저장 대화 직접 변경, 주 앱 DOM 접근, 주 앱 화면·대화상자 등록, 테마 변경처럼 [확장 경계](EXTENSIONS.md)와 원문 보존 결정으로 제외한 범위예요. 화면은 [격리 패널](PACKAGE-PANELS.md)을 사용해요.

목록에 없는 이름은 판정하지 않고 그대로 보고해요. 사용 API는 글자만 대조해서 찾기 때문에 `const r = risuai` 같은 별칭, 계산된 접근, 이름을 바꾼 구조 분해는 놓칠 수 있어요. 보고서가 그 사실과 발견한 별칭 이름을 함께 알려 주므로 "미구현" 목록이 비어 있어도 쓰지 않는다는 증거로 읽지 않아요. API 2.0/2.1을 선언한 파일도 읽지만 판정은 3.0 기준이라는 점을 함께 알려요. 파일은 4 MiB까지 읽고 보고에는 이름과 SHA-256 지문을 남겨요.

## 대용량 자료

24 MiB가 넘는 카드·모듈 파일은 요청 본문 대신 **먼저 서버에 올린 뒤** 검토해요. 화면에서 파일을 고르면 자동으로 이 경로를 사용하고, 올린 파일은 DB 옆의 `uploads` 디렉터리에 두었다가 등록이 끝나면 지워요. 검토를 끝내지 않은 파일은 24시간 뒤 정리하며, 정리된 뒤 등록을 누르면 파일을 다시 선택하라고 안내해요. 한도는 256 MiB예요.

이 경로에서는 **원본 파일의 사본을 앱에 보관하지 않아요.** 24 MiB 이하 파일은 지금처럼 원본을 자료 이동 영수증에 보존하지만, 그보다 큰 파일은 가져온 자료만 저장하고 가져오기 안내에 파일 이름과 SHA-256 지문을 남겨요. 원본 파일은 사용자가 직접 보관해야 다시 내보낼 수 있어요.

컨테이너 안에서 읽는 양은 파일 크기에 비례해 허용하되 한 항목은 64 MiB를 넘을 수 없어요. 실제 크기보다 훨씬 크게 부풀리는 압축 파일은 크기와 상관없이 거절해요. 첨부 자료의 기존 한도(이미지 2 MB, PNG·JPEG·WebP)는 그대로이므로 큰 오디오·영상·고해상도 이미지는 계속 가져오지 않고 안내로 남겨요.

## 봇·페르소나·모듈

### 구조화된 Risu 모듈 JSON

RisuToki의 **파일 → 파일을 프로젝트 폴더로 추출…**에서 `.risum`을 새 폴더로 내보내면 `{ "type": "risuModule", "module": {...} }` 형식의 `module.json`이 생성돼요. 서재 봇/모듈 탭의 **Risu 자료 가져오기**에서 이 파일을 선택하고 **모듈 가져오기**를 눌러요. 모듈로 등록하며 봇·채팅·진행 기억을 자동 생성하지 않아요. 등록 후 기존 채팅의 봇·페르소나·모듈 설정에서 장착할 수 있어요.

이름·설명, 활성 로어의 내용·이름 템플릿·정렬 순서, 지원하는 정적 표시 정규식을 가져와요. 모듈 설명은 사용자용 metadata로 유지하고 작문 본문에 복사하지 않아요. JSON에 직접 들어 있는 PNG/JPEG/WebP data URL 이미지는 기존 이미지 저장 경로를 사용해요. Lua 콜백은 카드와 같은 어댑터로 처리하며 미지원 트리거·CSS·토글·namespace/MCP 등 나머지 설정도 검토 대상이에요.

추출 폴더의 이미지도 옮기려면 **`module.json`과 `.risutoki` 폴더를 함께 ZIP으로 압축**하고 그 ZIP을 선택해요. 하나의 상위 폴더로 감싸져 있어도 읽어요. `.risutoki/workspace.json`의 `risumAssetFiles` 순서로 원래 모듈 에셋과 연결하며, 목록이 없는 경우 `.risutoki/risum-assets/*.bin`의 파일명 순서를 사용해요. 실제 이미지 바이트로 형식을 확인하며 누락된 파일은 미지원으로 표시해요. ZIP 안에서만 읽고 외부 경로나 로컬 파일 시스템으로 추출하지 않아요. 여러 모듈 정의나 카드·모듈 정의가 함께 있는 모호한 프로젝트 ZIP은 거절해요.

이 경로에서는 별도 설치된 RisuToki가 바이너리 해석을 맡고 Uimori는 일반 JSON과 ZIP만 읽어요. RisuToki 추출의 정규화·숨김 필드 제거가 적용되므로 그 결과를 원본 `.risum` 전체와 동일하다고 간주하지 않아요. Uimori는 선택한 JSON/ZIP 바이트를 원본 영수증에 보존해요.

### native 패키지 JSON

서재에서 해당 종류의 자료를 만들거나 편집하고 **패키지 가져오기·내보내기와 역할 사본 → 패키지 JSON 가져오기**를 선택해요.

1. `ContentPackage` 자체, `{ "package": ... }` wrapper 또는 이미지를 포함한 `uimori-package-bundle` JSON을 선택해요. 파일은 64 MiB 이하여야 하며 [native 패키지 스키마](PACKAGES.md) 검증도 통과해야 해요. 이미지 bundle은 서버에서 이미지 hash와 참조를 검사해요.
2. 제목·로어·지침 수를 확인하고 **가져온 패키지로 초안 바꾸기**를 눌러요. 패키지의 제목·설명·본문·내부 자료가 편집 초안에 반영돼요. **가져오기 취소**로 검토를 끝낼 수도 있어요.
3. 내용과 선택한 자료 종류를 확인한 뒤 **자료 등록** 또는 **새 revision 저장**을 눌러요. JSON 선택이나 초안 교체만으로 저장하지 않아요.

wrapper 바깥의 콘텐츠 ID·revision·종류·기타 metadata를 복원하는 기능은 아니에요. 자료 종류는 현재 편집기 선택을 따르고, 저장 시 서버가 콘텐츠 ID/revision과 패키지를 정규화해요. 연결한 공통 모듈은 단일 패키지 파일에 포함하지 않으므로 대상 서재에도 같은 ID·개정이 있어야 해요. 채팅 장착은 저장된 참조로 따로 진행해요. 역할을 바꾸어도 원문의 인물 관점이나 지침을 자동 각색하지 않아요.

## Risu 프리셋

프롬프트 관리의 **Risu 프리셋 가져오기**에서 `.risup`·구형 `.risupreset` 바이너리, 프리셋 JSON 또는 RisuToki 프로젝트 ZIP을 선택해요. 프롬프트·템플릿·커스텀 토글·지원 정규식의 변환 결과와 차이를 검토하고 **작문 프롬프트로 저장**하면 기존 native transfer로 새 프롬프트를 등록해요. **가져온 프롬프트 편집**에서 옵션을 편집하고 기존 작문 프롬프트 적용 기능으로 채팅에 사용해요. `.risup`은 RPack 해독 뒤 압축·MessagePack과 preset payload를 읽어요. Risu 내부 DB나 실행기를 설치하지 않아도 읽으며 원본 스크립트를 실행하지 않아요.

Risu의 `memory` 슬롯은 사용자 메모로 치환하지 않아요. Uimori는 과거 요약을 전송 대화 문맥에 포함하고 사용자 메모·정정을 별도 참고 정보로 전달해요. 실제 전달은 선택한 프롬프트와 문맥 구성에 따르며, 가져오기 안내에 Risu 슬롯의 위치·래퍼는 직접 적용하지 않는 차이를 설명해요. 슬롯을 추가해 같은 요약을 중복 삽입하지 않아요. 모델·파라미터·도구는 Uimori가 별도로 관리하므로 가져오기 대상이나 미지원 손실로 계산하지 않아요.

초안 검토와 명시 저장을 거쳐 기존 작문 프롬프트 적용 경로를 사용해요. 프리셋 `editprocess`·`editdisplay`는 [공통 텍스트 변환](PROMPT-TRANSFORMS.md)으로 연결해 전송 전 원문 대화와 Reader 요청·응답 표시에 적용해요. 순서·캡처·지원 CBS 치환을 가져오고 프롬프트 편집기의 **텍스트 변환**에서 수정·비활성화할 수 있어요. 원문은 유지하며 Reader에서 실제 전송문과 비교해요. `editoutput`·`editinput`, 임의 특수 플래그·상태 변경·전체 본문 CBS 재평가 등은 미지원으로 안내해요. 기억 슬롯의 차이와 남은 실행 차이가 있으므로 Phēmē 전체 기능·창작 품질 인수가 완료됐다고 보지 않아요. 변환 결과에 표시한 차이와 미지원 내용을 확인해요. 모델·프로바이더·모델 파라미터·도구 설정은 가져오기 목표나 미지원 손실에 포함하지 않아요.

## 프롬프트

프롬프트 편집의 메시지 구성에서 **JSON 불러오기**를 선택해요. `PromptProgram` 자체 또는 `program`과 선택적인 `title`·`role`·`values`를 담은 native 파일을 받아요. 파일은 1,500,000 bytes 이하이며 [프롬프트 스키마와 실행 한도](PROMPT-AUTHORING.md)를 검사해요.

성공하면 이름·역할·구성과 옵션 값이 편집 초안에 반영되고 상위 편집기에서 명시적으로 저장해야 해요. 기존 프리셋을 편집 중일 때 다른 역할의 파일은 거절하고 새 프롬프트에서 불러오도록 안내해요. 원본의 ID·revision이나 저장된 옵션 조합 목록을 통째로 복원하지 않아요. `values`가 없는 예전 wrapper의 `suggestedCombination.values`는 기본 옵션 값으로 읽어요. 정의는 `program.controls`, 값은 `values`로 검증하며 내보내기에도 이름·역할·AST·현재 옵션 값을 담아요. 실제 계약은 [prompt-file](../core/prompt-file.ts)을 봐요.

파일 형식이나 스키마 검증이 실패하면 적용된 자료·프롬프트는 유지해요. JSON 가져오기·검증·저장에는 모델 호출이나 원본 스크립트 실행이 없어요. 스키마 통과는 Risu 원본과의 동작 동등성을 뜻하지 않으므로 이식 보고와 대표 동작 검증을 함께 확인해요.

현재 화면 구현은 [LibraryPanel](../web/LibraryPanel.tsx), [PackageTransfer](../web/PackageTransfer.tsx)와 [PromptComposer](../web/PromptComposer.tsx)에 있어요. 전체 DB의 v15 archive 복원은 이 파일 가져오기와 별개이며 [사용 안내](USAGE.md)를 확인해요.

# 항목 삭제

서재·설정·채팅 화면에서 저장한 항목을 삭제할 수 있어요. 삭제 확인창에서 대상 이름과 설명을 확인한 뒤 **영구 삭제**를 눌러요. 취소하면 서버 데이터는 바뀌지 않아요. 삭제는 숨김 처리나 휴지통 이동이 아니며 되돌릴 수 없어요.

## 탐색한 대상과 위치

| 대상 | 삭제 위치·처리 |
| --- | --- |
| 봇·페르소나·모듈 | 서재 카드와 자료 상세의 삭제 버튼. 모든 개정을 삭제해요. |
| 독립 로어·작가 설정·창작 스킬·명칭집 | 서재의 **기타 자료**에서 조회·편집·삭제해요. |
| 작문·번역 프롬프트 | 서재 → 프롬프트에서 저장한 프롬프트를 선택하고 **프롬프트 삭제**를 눌러요. |
| 전역 창작 조합·기본 창작 프리셋 | 프롬프트의 **저장된 창작 조합·프리셋 관리**에서 삭제해요. |
| 연결·모델 프리셋 | 설정 → 연결과 모델에서 목록 또는 편집 양식의 삭제 버튼을 사용해요. 연결을 참조하는 모델부터 삭제해요. |
| 채팅 | 탐색 메뉴의 채팅 카드에서 **채팅 삭제**를 눌러요. 봇 없이 만든 채팅도 **봇 없는 채팅** 목록에서 찾을 수 있어요. |
| 보관된 분기 | 채팅의 **보관된 전개**에서 **분기 삭제**를 눌러요. 기본 분기는 채팅 전체 삭제를 사용해요. |
| 채팅에 업로드한 이미지 | 채팅 설정의 **이 이야기의 이미지**에서 삭제해요. 저장된 파일 데이터도 함께 삭제해요. |
| 가져온 네이티브 봇·히든 모듈 | 해당 설정 패널에서 선택한 패키지·모듈을 삭제해요. |
| 미사용 작가 선언 | 상태·기억 패널에서 **선언 삭제**를 눌러요. |
| 미실행 장면 예약 | 상태·기억 패널에서 **예약 삭제**를 눌러요. |
| 채팅 폴더 | 기존 **폴더 해제 · 채팅 유지**를 사용해요. 채팅은 미분류로 이동해요. |
| 패키지 내부 로어·폴더·지침·옵션·이미지·시작문·표시 변환·상태 표시 필드·공유 모듈 참조 | 기존 편집기의 삭제·참조 해제를 사용하고 자료를 저장해요. 이전 저장 개정은 바뀌지 않아요. |
| 프롬프트 블록·제어 정의·이야기별 조합 | 기존 편집기에서 삭제하고 저장해요. |

## 연결된 데이터와 실행 보호

- 다른 자료·폴더·채팅·보관된 실행이 참조하는 항목은 삭제를 거절하고 참조 종류와 건수를 표시해요. 현재 연결을 해제해도 과거 개정에 참조가 남아 있다면, 그 개정의 소유 자료·채팅을 삭제해야 해요. 임의로 다른 항목을 연쇄 삭제하지 않아요.
- 자료·프롬프트·설정 삭제는 확인한 최신 revision이 일치해야 해요. 채팅 전체 삭제는 설정·프로필·소속·분기 목록 및 마지막 이벤트를 다시 확인해요. 확인 이후 변경되었다면 취소하고 최신 목록에서 다시 시작해 주세요.
- 진행 중인 생성·보조 작업·공급자 요청이 있으면 채팅 삭제를 거절해요. 불확실한 공급자 실행을 재요청하지 않아요.
- 채팅 전체 삭제는 원문·수정본·번역·이미지·상태·기억·분기·진단 기록을 같은 트랜잭션에서 정리해요. 공통 서재 자료와 별도로 포크한 채팅은 유지해요.
- 분기는 자신에게 속한 원문과 기록만 삭제해요. 다른 분기의 원문·상태·기억이 의존하면 삭제를 거절해요.
- 완료한 모델·연결 snapshot은 자체 내용을 유지해요. 현재 채팅이나 상태 설정 이력에서 해당 모델을 조회하는 경우에는 모델 삭제를 거절해요.
- 채팅·분기를 삭제하면 해당 내용을 열어 둔 다른 탭도 삭제 알림을 받아 현재 선택을 정리해요.

## 개별 삭제하지 않는 기록

원문과 파생 번역·생성 상태·자동 기억·실행된 장면 예약·정사 수정 이력은 귀속된 분기 또는 채팅과 함께 삭제해요. 생성 당시 snapshot과 중복 실행 방지 영수증을 부분적으로 지워 재실행이나 보관 파일 손상을 일으키지 않아요. 공급자 등록 요청·응답 테스트 같은 내부 실행 영수증에는 독립 삭제 UI를 추가하지 않아요.

앱 기본 프롬프트·내장 이미지·기본 설정은 사용자 저장 항목이 아니에요. 패키지 소유 이미지는 패키지 편집기에서 관리해요. 연결 삭제는 서버의 인증 환경변수, 업로드한 인증 파일 또는 Codex 로그인 자체를 삭제하지 않아요.

서로를 참조하는 과거 `relatedIds` 기록은 단건 삭제만으로 해소할 수 없어요. 이런 경우에도 무결성 검사를 우회하거나 자동 연쇄 삭제하지 않아요.

## 검증 명령

`npm run check`, `npm run build`, `npm test -- tests/library-deletion.test.ts tests/chat-deletion.test.ts tests/asset-deletion.test.ts`, `node scripts/verify-deletion.mjs`를 사용해요. 브라우저 검증은 새 포트와 합성 SQLite DB를 만들고 `output/playwright/deletion-<run-id>/summary.json`에 결과·화면·정리 증거를 남겨요. 사용자 DB와 실제 공급자를 사용하지 않아요.

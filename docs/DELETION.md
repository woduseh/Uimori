# 항목 삭제

자료 삭제는 현재 목록과 새 선택에서 제외하고, **아무 자료도 사용하지 않는 본문과 이미지는 실제로 정리**해요. 휴지통이나 영구 진단 아카이브를 만들지 않아요. 보관할 자료는 먼저 [개별 백업](NATIVE-TRANSFER.md)으로 남겨요.

## 자료와 이미지

현재 채팅이 쓰는 봇·프리셋, 저장된 메시지·독립 사본이 쓰는 이미지, 직전 저장 되돌리기에 필요한 참조는 유지해요. 이런 참조가 있는 자료는 목록에서는 사라져도 계속 쓰기에 필요한 본문이 남아요. 마지막 참조를 없앤 후의 삭제·저장 정리에서 회수해요. 과거 진단 snapshot만의 참조는 영구 보관 이유가 아니에요.

삭제·저장 트랜잭션에서 `server/unused-data.ts`가 실제 자료 참조를 따라가며 고아 이미지 BLOB과 사용하지 않는 숨김 항목을 정리해요. Reader 조회나 모델의 매 출력 조각마다 전체 자료를 스캔하지 않아요. 진행 중인 모델/이미지 작업이 있으면 물리 회수는 미뤄요. 일반 삭제는 제거되는 자료가 참조하던 이미지에만 회수를 적용하므로 다른 편집창에서 방금 올린 미저장 이미지까지 지우지 않아요. 기존 고아 이미지 전체 정리는 DB 전환 때 수행해요. 패키지 이미지 제거 직후에는 직전본 되돌리기에 남을 수 있으며, 그 되돌리기 사본까지 대체되고 다른 참조가 없으면 회수해요.

모델·프로바이더 삭제는 새로운 선택/호출을 중지해요. 진행 중인 작업이 참조하는 연결은 작업 종료까지 필요한 만큼 유지해요. 이미 공급자에게 보낸 요청의 처리 비용이나 외부 Codex 로그인 해제를 되돌리는 기능은 아니에요.

## 채팅과 폴더

채팅 삭제는 해당 메시지·번역·메모·변수·도우미·작업 기록을 함께 정리해요. 다른 독립 채팅 사본과 공통 자료는 지우지 않아요. 실행 중인 생성·공급자 요청이 있으면 먼저 중지하거나 끝날 때까지 기다려요. 단순 진단 이벤트가 추가됐다는 이유로 삭제 확인을 다시 요구하지 않아요.

채팅 폴더나 서재 폴더 해제는 자료를 미분류로 옮기며 자료 자체를 삭제하지 않아요. 공유 분기 삭제 기능은 제거했으며, 구형 분기는 [DB 전환](DATA-MIGRATIONS.md)에서 독립 채팅으로 옮겨요.

## 복원

개별 백업은 새 사본으로 가져오고 전체 작업실 복구는 [SQLite 스냅샷](DATA-MIGRATIONS.md)을 사용해요. 원문·이미지·API 키를 포함하므로 백업은 개인적으로 보관해요.

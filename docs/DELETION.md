# 항목 삭제

서재·프롬프트·설정의 삭제 버튼은 현재 목록과 새 선택에서 항목을 제외해요. 기존에 작성한 메시지를 지우는 동작과 별개예요. 자료의 모든 과거 개정을 보존하는 시스템은 아니며, 보관할 자료는 삭제 전에 [개별 백업](NATIVE-TRANSFER.md)으로 남겨요.

## 자료와 이미지

봇·페르소나·모듈은 서재 상세·목록에서, 프리셋은 프롬프트 목록·편집기에서 삭제해요. 원본 로어·Lua·정규식·이미지는 자료 편집기에서 제거하고 저장해요. 저장 전 취소하면 기존 자료가 유지돼요. 원본 Risu 참조 이름과 이미지 표시 이름은 구분해요.

채팅 이미지의 삭제는 해당 채팅의 선택 목록에서 제외해요. 불변 이미지 바이트는 메시지와 독립 사본이 참조할 수 있으므로 이미지 이름 변경·목록 삭제만으로 지우지 않아요. 패키지 소유 이미지는 해당 자료 편집기에서 관리해요.

모델·프로바이더 삭제는 현재 선택을 정리하고 새로운 호출을 중지해요. 이미 공급자에게 보낸 요청의 취소나 외부 Codex 로그인 해제와 같은 동작은 아니에요. 키의 등록·변경·해제는 프로바이더 설정이 맡아요.

## 채팅과 폴더

채팅 삭제는 그 채팅의 메시지·번역·메모·변수·작업 기록을 함께 정리해요. 서재 자료나 별도로 복사한 채팅은 지우지 않아요. 공유 분기 그래프가 아니라 독립 채팅 사본이므로, 원본 채팅 삭제가 사본의 계속 쓰기를 막지 않아요.

실행 중인 작업이 있다면 먼저 중지하거나 끝날 때까지 기다려요. 삭제 확인 이후 변경이 생기면 최신 상태에서 다시 확인해요. 이는 오래된 화면이 새로운 작업을 삭제하지 않도록 하는 변경 충돌 확인이에요.

채팅 폴더 해제는 채팅을 미분류로 옮기며 채팅을 삭제하지 않아요. 서재 폴더 삭제도 같은 분류의 미분류 목록으로 항목을 옮겨요.

## 복원

삭제한 항목 전체의 휴지통이나 모든 과거 저장 이력은 제공하지 않아요. 개별 백업은 새 사본으로 가져오고, 작업실 전체 복구에는 [SQLite 스냅샷](DATA-MIGRATIONS.md)을 사용해요. 스냅샷에는 API 키와 이미지가 포함되므로 개인적으로 보관해요.

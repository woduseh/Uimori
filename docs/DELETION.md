# 항목 삭제

자료 삭제는 현재 목록과 새 선택에서 제외하고, **아무 자료도 사용하지 않는 본문과 이미지는 실제로 정리**해요. 휴지통이나 영구 진단 아카이브를 만들지 않아요. 보관할 자료는 먼저 [개별 백업](NATIVE-TRANSFER.md)으로 남겨요.

서재 자료는 별도 삭제 가능 여부 조회 없이 확인한 revision으로 삭제해요. 실제 삭제 요청에서 변경 충돌과 참조 보존을 처리해요. 진행 중인 작업을 확인해야 하는 채팅·도우미 대화의 삭제 사전조회는 별도로 유지해요.

## 자료와 이미지

현재 채팅이 쓰는 봇·프리셋, 저장된 메시지·독립 사본이 쓰는 이미지, 직전 저장 되돌리기에 필요한 참조는 유지해요. 이런 참조가 있는 자료는 목록에서는 사라져도 계속 쓰기에 필요한 본문이 남아요. 마지막 참조를 없앤 후의 삭제·저장 정리에서 회수해요. 과거 진단 snapshot만의 참조는 영구 보관 이유가 아니에요.

삭제·저장 트랜잭션에서 `server/unused-data.ts`가 실제 자료 참조를 따라가며 고아 이미지 BLOB과 사용하지 않는 숨김 항목을 정리해요. Reader 조회나 모델의 매 출력 조각마다 전체 자료를 스캔하지 않아요. 진행 중인 모델/이미지 작업이 있으면 물리 회수는 미루되 후보 해시는 DB에 남겨요. 작업 종료와 서버 재시작 때 후보를 다시 처리하며, 후보와 숨김 자료가 없으면 원고 전문을 훑지 않아요. 일반 삭제는 제거되는 자료가 참조하던 이미지에만 회수를 적용하므로 다른 편집창에서 방금 올린 미저장 이미지까지 지우지 않아요. 패키지 이미지 제거 직후에는 직전본 되돌리기에 남을 수 있으며, 그 되돌리기 사본까지 대체되고 다른 참조가 없으면 회수해요.

모델·프로바이더 삭제는 새로운 선택/호출을 중지해요. 진행 중인 작업이 참조하는 연결은 작업 종료까지 필요한 만큼 유지해요. 이미 프로바이더에게 보낸 요청의 처리 비용이나 외부 Codex 로그인 해제를 되돌리는 기능은 아니에요.

## 채팅과 폴더

채팅 삭제는 해당 메시지·번역·메모·변수·도우미·작업 기록을 함께 정리해요. 다른 독립 채팅 사본과 공통 자료는 지우지 않아요. 실행 중인 생성·프로바이더 요청이 있으면 먼저 중지하거나 끝날 때까지 기다려요. 단순 진단 이벤트가 추가됐다는 이유로 삭제 확인을 다시 요구하지 않아요.

채팅 폴더나 서재 폴더 해제는 자료를 미분류로 옮기며 자료 자체를 삭제하지 않아요. 새 전개는 선택한 장면까지 [독립 채팅으로 복사](CHAT-BACKUP.md)해 만들어요. 구형 공유 분기와 구형 DB의 자동 변환은 지원하지 않으므로, 이전 DB는 [해당 형식에 맞는 앱 버전](DATA-MIGRATIONS.md)과 함께 보관해요.

## 복원

개별 백업은 새 사본으로 가져오고 전체 작업실 복구는 [SQLite 스냅샷](DATA-MIGRATIONS.md)을 사용해요. 원문·이미지·API 키를 포함하므로 백업은 개인적으로 보관해요.

## 사용량 숫자 보존

채팅·도우미 대화·삽화를 삭제해도 전체 사용량 합계는 유지해요. 실행의 본문·프롬프트·원시 응답·오류 상세·콘텐츠 연결은 제거하고 시각·모델·용도·토큰·금액만 보관해요. 개인 채팅 복사는 사용량을 복사하거나 중복 청구하지 않아요. [사용량](USAGE-REPORT.md)

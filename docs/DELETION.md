# 항목 삭제

Uimori에서 자료를 삭제할 때의 동작 방식, 사용자 화면에서의 조작 방법, 데이터 보존 및 복원 원칙을 안내해요.

## 기본 원칙과 안전 안내

- **휴지통 없는 즉시 정리**: 자료를 삭제하면 현재 목록과 새로운 선택에서 즉시 제외되고, 삭제 대상의 본문과 회수 대상으로 지정된 미사용 이미지를 정리해요. 휴지통이나 영구 진단 아카이브를 별도로 만들지 않으므로, 보관할 자료는 삭제하기 전에 미리 [개별 백업](NATIVE-TRANSFER.md)으로 남겨두세요.
- **수정 번호(Revision) 기반 확인**: 서재 자료는 별도의 삭제 가능 여부 사전 조회 없이, 화면에서 확인한 최신 revision으로 삭제를 요청해요. 변경 충돌과 다른 자료에서의 참조 보존은 실제 삭제 요청 트랜잭션에서 안전하게 처리해요.
- **진행 중인 작업 확인**: 실행 중인 생성이나 프로바이더 요청이 있는 채팅 및 도우미 대화는 먼저 작업을 중지하거나 끝날 때까지 기다려야 삭제할 수 있어요.

## 항목별 삭제 동작

### 서재 자료와 프리셋
- **참조 중인 자료의 본문 보존**: 현재 채팅이 사용 중인 봇·프리셋, 저장된 메시지나 독립 사본이 사용하는 이미지, 그리고 직전 저장 되돌리기에 필요한 참조는 그대로 유지해요. 이런 참조가 남아 있는 자료는 목록에서는 사라지더라도 계속 사용하는 데 필요한 본문 데이터가 유지돼요.
- **기본 프리셋 보호**: 기본 프롬프트로 사용 중인 프리셋은 먼저 다른 프리셋을 기본값으로 지정해야 삭제할 수 있어요.
- **패키지 이미지 정리**: 패키지 이미지를 제거한 직후에는 직전본 되돌리기 사본에 남을 수 있으며, 그 되돌리기 사본까지 다른 내용으로 대체되고 다른 참조가 모두 사라지면 안전하게 회수해요.

### 모델과 프로바이더
- **모델 삭제**: 삭제한 모델은 새로운 선택 목록에서 제외되고, 기본 모델 지정도 함께 해제돼요.
- **프로바이더 삭제**: 프로바이더 연결을 비활성화하고 소속 모델을 숨겨요. 이미 준비된 작업의 추가 전송도 차단해요.
- **협업 조언자 모델**: 전용 조언자 모델을 삭제하면 에이전트 협업 기능이 꺼져요. 진행 중인 작업이 참조하는 연결은 작업 종료 시까지 필요한 만큼 유지돼요.
- **외부 비용 및 세션**: 이미 프로바이더에 전송되어 처리 중인 요청의 비용이나 외부 Codex 로그인 해제를 되돌리는 기능은 아니에요.

### 채팅과 폴더
- **채팅 삭제**: 해당 채팅의 메시지, 번역, 메모, 변수, 도우미 대화, 작업 기록을 모두 함께 정리해요. 다른 독립 채팅 사본과 서재의 공통 자료는 지우지 않아요. 단순한 진단 이벤트가 추가되었다는 이유로 삭제 확인을 다시 요구하지 않아요.
- **폴더 해제**: 채팅 폴더나 서재 폴더를 해제하면 자료가 미분류로 이동하며, 자료 자체가 삭제되지는 않아요.
- **새로운 이야기 분기**: 특정 지점부터 새로운 이야기를 이어가려면 원하는 장면까지 [독립 채팅으로 복사](CHAT-BACKUP.md)해서 작업해요. 구형 공유 분기와 구형 DB의 자동 변환은 지원하지 않으므로, 이전 DB는 [해당 형식에 맞는 앱 버전](DATA-MIGRATIONS.md)과 함께 보관해 주세요.

## 장면 삭제와 기억 정리

### 장면 삭제 (`… → 장면 삭제`)
- **삭제 범위 선택**: 장면 메뉴의 **… → 장면 삭제**에서 **이 장면만** 또는 **이 장면부터 이후까지**를 선택하고 삭제 개수를 확인해요.
- **정리 범위**: 장면은 연결된 사용자 요청과 응답을 묶은 단위예요. 삭제를 확정하면 원문, 번역, 삽화, 해당 실행 기록을 실제로 정리해요. 다른 독립 채팅 사본은 유지돼요.
- **되돌리기 불가**: 남은 장면의 ID와 본문은 그대로 유지되고 전후 연결만 다시 이어붙어요. 되돌리기를 제공하지 않으므로 필요한 채팅은 먼저 복사하거나 백업해 두세요.
- **안전 조건**: 진행 중인 생성, 도우미, 보조 작업이 있으면 삭제할 수 없어요. 삭제 확인 이후 원문, 요청, 현재 변수 또는 채팅 설정이 바뀌면 삭제 범위를 다시 확인해야 해요.
- **네트워크 오류 대응**: 응답을 확인하지 못한 삭제는 같은 요청으로 결과를 다시 확인하며, 확인 중 오류가 나더라도 새로운 삭제를 자동으로 반복하지 않아요. 삭제된 문맥을 보존한 실패 작업의 재시도는 차단되므로 새 요청을 작성해야 해요.
- **변수 및 요약 처리**:
  - 중간 장면 하나만 삭제하면 이후 장면과 현재 카드 변수는 유지돼요.
  - 마지막 장면을 포함해 지우면 마지막으로 남은 장면의 변수 체크포인트로 돌아가요.
  - 모든 장면을 지우면 사용자 변수 값을 비워요.
  - 삭제된 장면을 포함하는 기존 요약은 화면에서 확인할 수 있지만, 새 생성에는 재사용하지 않아요.

### 연결이 끊긴 기억 관리
- **확인 위치**: **기억과 메모 → 연결이 끊긴 기억**은 해당 항목이 있을 때만 건수를 표시해요.
- **대상 항목**: 삭제·수정되었거나 현재 이야기 흐름 밖에 있는 장면에 연결된 사용자 메모, 가져온 기억, 채팅 전용 로어를 모아서 보여줘요.
- **보관 및 활용**: 기본값은 안전한 보관 상태이며, 새 생성에서는 자동으로 제외돼요. 항목별로 현재 장면에 다시 연결하거나 사용 중지 이력을 남길 수 있고, 내용, 작성자, 가져온 출처는 유지돼요.
- **AI 검토**: 선택한 항목을 최대 6,000자까지 도우미 요청 초안에 넣어줘요. 사용자가 직접 전송해야 실행되며, 자동 AI 호출이나 자동 기억 삭제는 하지 않아요.

## 복원과 사용량 보존 규칙

- **자료 복원**: 개별 백업은 새 사본으로 가져오고, 작업실 전체 복구는 [SQLite 스냅샷](DATA-MIGRATIONS.md)을 사용해요. 백업에는 원문, 이미지, API 키가 포함되므로 개인적으로 안전하게 보관하세요.
- **사용량 숫자 보존**: 채팅, 도우미 대화, 삽화를 삭제하더라도 작업실 전체 사용량 합계는 유지돼요. 실행의 본문, 프롬프트, 원시 응답, 오류 상세, 콘텐츠 연결은 제거하지만 호출 시각, 모델, 용도, 토큰 수, 금액은 보관해요. 개인 채팅 복사는 사용량을 복사하거나 중복 청구하지 않아요. [사용량](USAGE-REPORT.md)

## 구현 참고

- **고아 이미지 회수 큐**: 삭제 및 저장 트랜잭션에서 `server/unused-data.ts`가 실제 자료 참조를 따라가며 회수 후보인 고아 이미지 BLOB과 사용하지 않는 숨김 항목을 정리해요. Reader 조회나 모델의 매 출력 조각마다 전체 자료를 스캔하지 않아요.
- **지연 물리 회수 및 DB 후보 해시**: 진행 중인 모델/이미지 작업이 있으면 물리적 회수는 미루되 회수 후보 해시를 DB(`image_cleanup_candidates`)에 남겨요. 작업 종료와 서버 재시작 때 후보를 다시 처리하며, 후보와 숨김 자료가 없으면 원고 전문을 훑지 않아요.
- **초안 보호와 이미지 회수 예외**: 일반 삭제는 제거되는 자료가 참조하던 이미지에만 회수 후보를 추가해요. 도우미 대화 텍스트에만 있던 이미지나 개별 삽화 삭제는 별도 이미지 회수 후보를 추가하지 않는데, 다른 편집창의 미저장 초안이 같은 이미지를 참조할 수 있기 때문이에요. 단, 도우미가 직접 첨부한 이미지와 다른 자료의 기존 삭제 정리는 유지하며, 다른 작업에서 회수 후보로 지정된 이미지는 참조 검사 후 정리될 수 있어요.
- **스냅샷 참조 처리**: 과거 진단 snapshot만의 참조는 영구 보관 이유가 아니며, 마지막 참조를 없앤 후 회수 대상으로 지정된 자료는 삭제·저장 정리에서 회수해요.
- **관련 파일**: `server/scene-deletion.ts`, `server/orphan-memory.ts`, `server/unused-data.ts`

# 항목 삭제

서재·설정·채팅 화면에서 저장한 항목을 삭제할 수 있어요. 취소하면 서버 데이터는 바뀌지 않아요. 서재 자료·프롬프트·옵션 조합·모델·프로바이더를 삭제하면 목록과 새 선택에서 제외해요. 기존 채팅과 생성 기록이 사용하는 내용·개정·파일은 내부에 보존하며, 복원 UI는 제공하지 않아요. 채팅·분기 삭제는 아래 범위의 실제 데이터 삭제예요.

## 탐색한 대상과 위치

| 대상 | 삭제 위치·처리 |
| --- | --- |
| 봇·페르소나·모듈 | 서재 카드와 자료 상세의 삭제 버튼. 목록에서 제외하고 기존 개정은 사용 중인 기록을 위해 보존해요. |
| 작문·번역 프롬프트 | 탐색의 **프롬프트**에서 항목 메뉴의 삭제 버튼 또는 편집기의 **프롬프트 삭제**를 눌러요. |
| 전역 프롬프트 옵션 조합 | 프롬프트의 저장된 조합 관리에서 삭제해요. |
| 프로바이더·모델 프리셋 | 설정 → 프로바이더·모델 등록에서 목록 또는 편집 양식의 삭제 버튼을 사용해요. 프로바이더 삭제 시 그 프로바이더를 쓰는 모델도 새 선택에서 제외하고, 프로바이더를 비활성화해 이후 전송을 차단해요. |
| 채팅 | 소속 봇의 채팅 목록에서 삭제 아이콘 또는 메뉴의 **채팅 삭제**를 눌러요. |
| 보관된 분기 | 채팅의 **보관된 전개**에서 **분기 삭제**를 눌러요. 기본 분기는 채팅 전체 삭제를 사용해요. |
| 채팅에 업로드한 이미지 | 채팅 설정의 **이 이야기의 이미지**에서 삭제해요. 새 이미지 목록에서 제외하며 과거 표시와 작업에 필요한 파일은 보존해요. |
| 사용자 메모·정정 | **상태와 문맥**에서 메모를 삭제해요. 현재 분기에 종료 기록을 남기며 과거 Run과 다른 분기의 메모는 유지해요. |
| 미실행 장면 예약 | **상태와 문맥**에서 **예약 삭제**를 눌러요. |
| 채팅 폴더 | 기존 **폴더 해제 · 채팅 유지**를 사용해요. 채팅은 미분류로 이동해요. |
| 서재·프롬프트 폴더 | **폴더 관리**에서 폴더를 삭제해요. 항목은 같은 분류의 미분류로 이동해요. |
| 패키지 내부 로어·폴더·지침·옵션·이미지·시작문·표시 변환·상태 표시 필드·공유 모듈 참조 | 기존 편집기의 삭제·참조 해제를 사용하고 자료를 저장해요. 이전 저장 개정은 바뀌지 않아요. |
| 프롬프트 블록·제어 정의·현재 옵션 | 기존 편집기에서 삭제하고 저장해요. |

독립 로어·작가 설정·창작 스킬·명칭집과 **기타 자료** 분류는 제거했어요. 세계관·지침은 공통 패키지 내부에서 관리하며, 현재 자료 종류와 분류 계약은 [서재 안내](LIBRARY.md)를 따라요.

## 연결된 데이터와 실행 보호

- 다른 자료·폴더·채팅·보관된 실행의 참조는 서재 항목 삭제를 막지 않아요. 봇을 삭제해도 기존 채팅의 소속·폴더·첨부·사용 내용은 보존해요. 삭제 영향 조회는 최신 revision과 삭제 가능 여부만 확인하며 참조 차단 목록은 비어 있어요. 내부의 특정 개정 조회는 과거 실행과 보관 파일 검증에 계속 사용해요.
- 자료·프롬프트·설정 삭제는 확인한 최신 revision이 일치해야 해요. 채팅 전체 삭제는 설정·프로필·소속·분기 목록 및 마지막 이벤트를 다시 확인해요. 확인 이후 변경되었다면 취소하고 최신 목록에서 다시 시작해 주세요.
- 진행 중인 생성·보조 작업·공급자 요청이 있으면 채팅 삭제를 거절해요. 불확실한 공급자 실행을 재요청하지 않아요.
- 채팅 전체 삭제는 원문·수정본·번역·이미지·상태·메모·요약·도우미·분기·진단 기록을 같은 트랜잭션에서 정리해요. 공통 서재 자료와 서재 소속 도우미 작업, 별도로 포크한 채팅은 유지해요.
- 분기는 자신에게 속한 원문과 기록만 삭제해요. 다른 분기의 원문·상태·메모·요약이 의존하면 삭제를 거절해요.
- 모델·프로바이더 삭제는 실행 snapshot이나 진행 중인 작업·진단 기록을 지우지 않아요. 현재 선택은 정리하고 새 선택은 차단해요. 프로바이더 삭제는 최신 프로바이더를 비활성화해 다음 전송의 권한을 회수해요. 이미 전송한 공급자 요청이 취소되었다거나 외부 계정 인증이 해제되었다는 뜻은 아니에요.
- 채팅·분기를 삭제하면 해당 내용을 열어 둔 다른 탭도 삭제 알림을 받아 현재 선택을 정리해요.

## 개별 삭제하지 않는 기록

원문과 파생 번역·생성 상태·요약 checkpoint·실행된 장면 예약·메모의 대체 이력은 귀속된 분기 또는 채팅과 함께 삭제해요. 생성 당시 snapshot과 중복 실행 방지 영수증을 부분적으로 지워 재실행이나 보관 파일 손상을 일으키지 않아요. 응답 테스트 같은 내부 실행 영수증에는 독립 삭제 UI를 추가하지 않아요.

앱 기본 프롬프트·기본 설정은 사용자 저장 항목이 아니에요. 패키지 소유 이미지는 패키지 편집기에서 관리해요. 프로바이더 삭제는 서버의 인증 환경변수, 업로드한 인증 파일 또는 Codex 로그인 자체를 삭제하지 않아요.

서로 참조하는 과거 `relatedIds`가 있어도 서재 목록에서 각각 삭제할 수 있어요. 참조 대상 개정은 내부에 보존하므로 다른 자료나 채팅을 함께 지울 필요가 없어요.

## 검증 명령

`npm run check`, `npm run build`, `npm test -- tests/library-deletion.test.ts tests/chat-deletion.test.ts tests/asset-deletion.test.ts`, `node scripts/verify-deletion.mjs`를 사용해요. 브라우저 검증은 새 포트와 합성 SQLite DB를 만들고 `output/playwright/deletion-<run-id>/summary.json`에 결과·화면·정리 증거를 남겨요. 사용자 DB와 실제 공급자를 사용하지 않아요.

# Uimori v0.7.0

원고를 직접 다듬고 생성 요청을 확인하는 도구를 확장하고, 도우미의 진행 상태·후속 지시·편집 복구를 강화한 릴리스예요. 모델별 로컬 토큰 추정도 추가해 장문 집필의 컨텍스트 사용량을 더 정확하게 확인할 수 있어요.

## 주요 변경

- **이전 장면 컨텍스트 보존:** 이전 장면의 본문이 다음 생성 요청에서 누락될 수 있던 문제를 수정했어요. Vercel Chat의 assistant 메시지와 OpenAI Responses의 수동 이력이 이전 본문을 유지하고, Risu CBS의 `{{role}}`도 이전 장면의 실제 메시지 역할로 평가해요.
- **채팅별 작가 노트:** 채팅 설정에 저장한 작가 노트를 본문용 Risu `authornote` 슬롯과 `{{authornote}}`에 제공해요. 비워 두면 프리셋 기본값을 사용하고 번역에는 주입하지 않아요. 독립 채팅 사본과 개별 백업에도 보존해요.
- **새 채팅과 자료 가져오기:** 봇별 기본 페르소나를 지정하거나 채팅 폴더 기본값을 따를 수 있고, 새 채팅에서 명시한 페르소나 또는 사용 안 함을 우선해요. 채팅 없는 봇도 탐색 목록에 표시해요. 채팅 가져오기·복원·사본에는 새 채팅 기본값을 덮어쓰지 않고 기존 페르소나 선택을 보존해요. Risu 봇 가져오기는 기본으로 서재에만 추가하며 채팅을 함께 만들지는 가져올 때 직접 선택해요.

- **원고 편집 도구:** 원문 편집기에서 현재·직전·최초 저장본을 비교하고 선택한 저장본을 초안으로 불러올 수 있어요. 구절을 선택해 도우미 모델에 **선택 구절 퇴고**를 요청하고 원문과 제안을 비교한 뒤 필요한 부분만 초안에 반영할 수 있어요. 실제 본문은 기존처럼 **원문 저장**을 눌러야 바뀌어요.
- **원고 내보내기와 장면 이름:** 채팅의 전체 원고나 지정한 장면 범위를 읽기용 Markdown으로 내보낼 수 있고, 장면에 선택적인 이름을 붙여 목차와 백업·사본에서 유지할 수 있어요. 장면 이름은 기존 메타데이터 저장소를 사용하므로 별도 DB 마이그레이션은 없어요.
- **마지막 응답 다시 요청:** 마지막 완료 응답은 **기존 응답 교체**와 **새 채팅에서 다시 요청** 중 선택해요. 교체는 새 본문이 성공적으로 저장될 때만 적용하고 실패·취소·거절·원문 동시 수정 때는 기존 본문을 보존해요. 중간 장면은 독립 사본에서 다시 요청해요. 현재 설정과 이전 응답 직전의 대화·변수 체크포인트를 사용하며, 교체된 원문은 이력으로 남아요.
- **사본 이름과 서재 정리:** 자동 사본 이름을 `원래 제목 · 사본 1`, `· 사본 2`처럼 일관되게 붙이고 사본을 다시 복사해도 접미사를 겹쳐 붙이지 않아요. 사이드바에서 봇을 폴더로 끌어 분류하거나 봇 사이로 끌어 순서를 바꾸고, 사이드바·서재에서 폴더 순서를 드래그로 정리할 수 있어요.
- **다음 요청 미리보기:** 입력창에서 실제 모델을 호출하기 전에 현재 요청, 선택된 모델·프롬프트·페르소나, 로어·요약 상태와 로컬 입력 토큰 추정을 확인할 수 있어요. 로어 선별·컨텍스트 압축·Risu 스크립트처럼 실행 시점에 달라지는 요소는 실제 전송과 차이가 날 수 있음을 함께 표시해요. 입력창의 컨텍스트 메뉴에서 수동 정리를 열고 이번 요약 작업에만 적용할 보존 우선사항을 전달할 수 있어요.
- **생성 기록과 사용량:** 장면 제목을 펼친 작업 박스에서 **이번 생성**과 **실행과 실제 입력 확인**을 열어 마지막 본문 호출의 모델·프롬프트·페르소나 선택, 요약 포함 여부, 입력 한도·사용량과 가능한 캐시·로어 정보를 확인해요. 상시 포함 로어의 **고정 자료**와 **자동 선택**을 구분하고 읽은 구간·요약·미확인 범위를 표시해요. 전체 본문 전달에는 별도 꼬리표를 생략하고, 이전에 읽어 유지한 로어는 **이전 요청 포함**으로 표시해요. 로컬 추정값은 **약**, 추정 방식은 접힌 **사용량 안내**에서 확인해요. 과거 실행에 없던 정보를 현재 설정으로 추정해 채우지 않아요.
- **모델별 로컬 토크나이저:** Claude 계열의 레거시 토크나이저와 DeepSeek, GLM, Kimi, Gemini/Gemma 계열 등 여러 모델군의 로컬 추정기를 추가했어요. 지원되는 경우 모델에 맞는 추정기를 사용하고, 그렇지 않으면 기존 fallback 정책을 기록해 표시해요. 이를 위해 `@huggingface/tokenizers` 의존성과 출처·라이선스가 포함된 tokenizer 자료가 추가됐어요.
- **도우미 진행과 후속 지시:** 실행 중인 도우미 작업의 활동과 입력 사용량을 더 자세히 표시하고, 진행 중 작업에 **현재 작업에 추가**로 후속 지시를 전달할 수 있어요. 확인된 추가 지시는 같은 대화의 후속 컨텍스트에도 남고, 전달 여부가 불확실한 입력을 자동으로 재전송하지 않아요.
- **도우미 편집 복구:** 도우미가 저장한 최근 자료 변경은 영수증과 최신 revision을 다시 확인한 뒤 **마지막 자료 수정 되돌리기**로 직전 저장본을 복구할 수 있어요. 새 저장이나 삭제, 미저장 편집, 진행 중 작업 등 충돌 가능성이 있으면 되돌리기를 막아 사용자 입력을 보존해요.
- **도우미 컨텍스트와 검증 도구:** 완료된 대화의 선택 원문과 필요한 이전 대화를 더 안정적으로 이어 읽고, 장문 도우미 입력의 압축·토큰 추정을 보완했어요. 선택적인 helper behavior evaluation runner도 추가해 실제 모델 평가와 합성 검증의 경계를 분리했어요.
- **설정·편집 UI 정리:** 역할별 선택 모델을 직접 편집하며 미저장 역할 선택을 유지해요. 번역 실패·중단 뒤 **번역 다시 시도**와 **원문부터 읽기**, 생성 재시도 전 **이전 요청 확인**을 제공해요. 설정·자료 가져오기 설명, 에디터 작업 버튼과 장면 사용량 표시도 정리했어요. 정적인 UI 설명이 지나치게 길어지는 부분을 찾는 경고성 copy 검사도 개발 도구에 추가했어요.
- **설정 화면 통일:** 앱·채팅·도우미 설정의 제목·그룹·입력·작업 버튼을 통일하고 좁은 화면에서는 쌓아 표시해요. 배경 이미지 선택과 효과 슬라이더도 구분했어요.
- **프로바이더와 Codex 상태:** Codex 연결 화면에서 공식 응답으로 확인된 사용 가능한 크레딧을 표시해요. 제공되지 않은 정보는 생략해요. TypeSafe AI 키 관리와 JEV 모델 ID·판단 테스트 화면을 분리하고 화면을 바꿔도 키 초안과 진행 중 테스트를 유지해요.

- **삽화 설정 입력 복구:** 최대 삽화 개수를 잠시 비우거나 잘못 입력한 뒤 정상 값으로 고쳤을 때, 숨겨진 자동 선택 한도 때문에 저장이 계속 막히던 문제를 수정했어요. 잘못된 입력은 연관 설정을 바꾸지 않으며 기존 초안·저장 충돌 보호는 유지해요.

- **화면 용어 통일:** 프로바이더·컨텍스트·채팅 제목·새 채팅 표기를 통일하고, 수정 번호와 저장본을 구분해 화면과 안내 문서에서 같은 용어를 사용해요.

## 데이터 호환성

앱 버전은 **0.7.0**, 개인 작업실 DB는 계속 **스키마 15**예요. **v0.6.1과 데이터 스키마가 같으므로 기존 스키마 15 작업실은 데이터를 유지해 업데이트할 수 있어요.** 선택적인 장면 이름은 기존 `app_metadata`에 저장하므로 기존 데이터 변환이 필요하지 않아요.

런타임 의존성에는 `@huggingface/tokenizers`가 새로 추가됐고, 모델별 로컬 토큰 추정을 위한 third-party tokenizer 자료와 관련 라이선스·출처 정보가 포함돼요. 업데이트 전에는 앱의 일관된 SQLite 백업과 실행 중인 앱/이미지 정보를 함께 보관하고, 진행 중인 생성·Batch·도우미 작업과 편집을 마쳐요.

v0.3.1의 스키마 12 DB를 직접 변환하는 기능은 포함하지 않아요. 구형 DB와 백업은 해당 형식을 지원하는 앱 버전과 함께 보관하고 DB 버전 숫자를 수동으로 바꾸지 않아요. 자세한 범위는 [데이터 안내](../DATA-MIGRATIONS.md)와 [업데이트 안내](../UPDATES.md)에 있어요.

## 설치와 업데이트

아래 태그 기반 설치는 `v0.7.0` 태그 발행 후 사용할 수 있어요. 릴리스 준비와 GitHub Release 발행은 별개예요.

```sh
git clone --branch v0.7.0 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x를 사용해요. 기존 설치는 [업데이트 안내](../UPDATES.md)를 따르고, 업데이트 뒤 **설정 → 앱 정보·라이선스**에서 0.7.0을 확인해요. Oracle 운영 설치는 [전용 배포 절차](../ORACLE-RELEASE.md)를 사용해요. GitHub Release 발행만으로 설치된 앱이 업데이트되지는 않아요.

## 검증 범위와 알려진 제한

릴리스 후보의 로컬 검증은 정적 검사·타입 검사·빌드·전체 Vitest·도구 검증과 전체 합성 브라우저 회귀를 포함해요. 공개 전에는 후보 커밋을 push하고 GitHub CI의 Linux core/self-host/tooling, Windows Vitest shard와 최종 quality 결과를 같은 SHA 기준으로 별도로 확인해야 해요.

이 검증은 합성 모델·CLI 응답과 격리된 DB/브라우저 환경을 사용하며 실제 유료 모델의 집필 품질·지침 준수, 물리 모바일 기기, 실제 운영 Docker 업그레이드 자체를 증명하지 않아요. 로컬 토큰 수는 선택된 tokenizer와 fallback 정책에 따른 추정이며 프로바이더의 실제 청구 토큰과 다를 수 있어요. Claude 3 이후는 구형 공개 토크나이저 기반 근사값이며, Grok와 미지원 모델은 `o200k_base`로 추정해요.

# Uimori v0.6.1

채팅 자료의 역할 보존과 도우미의 편집 보호를 보완하고, 선택형 평가 도구의 작성 방식과 메타데이터 설정을 확장한 릴리스예요.

## 주요 변경

- **채팅 가져오기·복사·복원:** 같은 자료를 봇과 페르소나로 함께 사용하는 채팅을 중복 자료로 잘못 거절하던 문제를 수정했어요. 채팅 가져오기, 독립 채팅 복사, 채팅 백업 복원에서 두 역할을 유지해요. CHARX 카드 가져오기 자체의 변경은 아니에요.
- **도우미의 프롬프트 편집 보호:** 전역 프롬프트의 미저장 초안을 도우미에 전달한 경우, 같은 프롬프트의 직접 저장을 막아 초안을 보호해요. 편집·쓰기 대상과 저장 영수증이 실제 작업실의 같은 대상을 가리키도록 정리했어요.
- **원본 기반 직접 작성:** 모델 프리셋의 선택형 평가 도구에 `source-bound` 모드를 추가했어요. 평가용 문맥·리뷰어·케이스 생성 단계 없이 원본과 기존 집필 설정으로 작성하고, 유효한 결과물 제출을 요구해요. 기존 프리셋의 기본 모드는 유지돼요.
- **프로바이더별 평가 메타데이터:** Responses·Anthropic·Vertex 프로토콜은 해당 프로필을 자동 선택하고, 다른 프로토콜은 OpenAI·Anthropic·Google DeepMind·중립 프로필을 직접 고를 수 있어요. 수동 선택은 프로바이더를 바꿨다가 돌아와도 유지돼요. 이 설정은 평가 도구가 보내는 메타데이터이며, 모델 제공자의 승인이나 성능을 증명하지 않아요.
- **거절 판정의 일관성:** 평가 도구의 거절 문구에 따른 별도 검사와 자동 재요청을 제거하고 기존 본문·번역 JEV 설정을 따르도록 했어요. JEV를 끈 상태에서는 평가 도구가 대체 거절 판정을 하지 않아요. 공급자의 구조화된 거절 신호 처리는 유지돼요. 이전 `outputRecovery` 설정은 더 이상 런타임 동작을 제어하지 않아요.

평가 도구는 계속 기본으로 꺼져 있어요. 지원 프로토콜과 제출 조건, 기존 Batch 복구 범위는 [평가 도구 안내](../EVALUATION-TOOLS.md)를 참고해요.

## 데이터 호환성

앱 버전은 **0.6.1**, 개인 작업실 DB는 계속 **스키마 15**예요. **v0.6.0과 데이터 스키마가 같으므로 기존 스키마 15 작업실은 데이터를 유지해 업데이트할 수 있어요.** 의존성 변경은 없어요. 업데이트 전에는 앱의 일관된 SQLite 백업과 실행 중인 앱/이미지 정보를 함께 보관하고, 진행 중인 생성·Batch 작업과 편집을 마쳐요.

v0.3.1의 스키마 12 DB를 직접 변환하는 기능은 포함하지 않아요. 구형 DB와 백업은 해당 형식을 지원하는 앱 버전과 함께 보관하고 DB 버전 숫자를 수동으로 바꾸지 않아요. 자세한 범위는 [데이터 안내](../DATA-MIGRATIONS.md)와 [업데이트 안내](../UPDATES.md)에 있어요.

## 설치와 업데이트

```sh
git clone --branch v0.6.1 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x를 사용해요. 기존 설치는 [업데이트 안내](../UPDATES.md)를 따르고, 업데이트 뒤 **설정 → 앱 정보·라이선스**에서 0.6.1을 확인해요. Oracle 운영 설치는 [전용 배포 절차](../ORACLE-RELEASE.md)를 사용해요. GitHub Release 발행만으로 설치된 앱이 업데이트되지는 않아요.

## 검증 범위와 알려진 제한

자동 검사는 합성 모델·CLI 응답과 격리된 DB로 채팅 자료 이동, 도우미 편집 보호, 평가 설정·실행과 버전·재시작·백업 동작을 확인해요. 실제 유료 모델의 집필 품질·거절률·지침 준수나 실제 Docker 업그레이드를 검증한 결과는 아니에요. 전체 브라우저 회귀와 물리 모바일 기기 검증은 이번 릴리스 검증에 포함하지 않아요.

# v0.15.3

도우미가 멈춘 자리에서 이어 가고, 지금 무엇을 기다리는지 말하고, 거절된 호출을 다시 보내요. Gemini 모델을 쓰면 응답을 기다리는 동안 생각 요약이 보여요.

- **멈춘 도우미 작업을 이어서 해요.** 실패했거나 멈춘 작업이 그 전에 자료를 읽었거나 변경을 저장했으면 **이어서 하기**가 보여요. 누르면 같은 요청을 새 작업으로 시작하면서 앞 작업이 읽은 내용과 저장한 변경의 기록을 넘겨줘서, 이미 저장한 변경을 다시 하지 않고 남은 일만 해요. 변경을 저장한 뒤 실패한 작업은 전에는 다시 요청할 방법이 없었는데, 이제 이어서 할 수 있어요. 요청 한도 초과가 몇 분씩 이어져 실패했을 때도 잠시 뒤에 이어서 하면 돼요. Codex 실행기로 돌린 작업과 삭제한 장면이 든 작업은 이어서 할 수 없어요. [읽기](../READING.md)
- **도우미가 지금 무엇을 기다리는지 보여요.** 상태 줄이 모델의 응답이면 몇 번째 호출인지, 도구면 종류와 대상, 다시 시도 대기면 몇 초 뒤 몇 번째 시도인지를 말해요. 펼친 활동 목록은 내부 이름 대신 읽을 수 있는 말로 적고, 새 단계를 따라 내려가요.
- **Gemini 모델은 생각 요약을 보여 줘요.** 도우미 호출이 응답을 만드는 동안 모델의 생각 요약이 응답 자리에 흐린 글씨로 보이고, 그 호출이 끝나면 사라져요. 요약은 저장하지 않고, 프로바이더 요금은 요약을 받든 안 받든 같아요. 모델이 이 요청을 받지 않으면 요약 없이 다시 보내요. 이 기능은 실제 프로바이더로 확인하지 못한 채 넣었어요. [생각 요약](../EXECUTION.md#생각-요약)
- **도우미도 거절된 호출을 다시 보내요.** 프로바이더가 응답을 거절하면 같은 호출을 바로 다시 보내요. 횟수는 본문과 같은 설정을 따라요. **앱 설정 → 새 채팅 기본값**의 **거절되면 자동으로 다시 생성**이고, 기본값은 켜짐과 최대 2회, 범위는 0~5회예요. 채팅마다 따로 정한 값은 도우미에 적용하지 않아요. 횟수를 다 쓰고도 거절되면 작업이 거절로 끝났다고 알려 주고, **다시 시도**나 **이어서 하기**를 할 수 있어요. [거절 뒤 자동 다시 생성](../GENERATION.md#거절-뒤-자동-다시-생성)
- **도우미 대화 목록을 정리했어요.** 도우미를 열어 보기만 한 채팅의 빈 대화는 전체 목록과 다른 채팅의 목록에 나오지 않아요. 대화를 지우지는 않아서, 그 채팅에서 도우미를 열면 같은 대화가 다시 열려요. 마지막 작업이 실패했거나 중단, 취소된 대화는 목록에 그 상태가 표시돼요.
- **요청 한도 초과로 거절된 호출은 사용량 0으로 기록해요.** 전에는 "미확인"으로 남아서, 도우미가 다시 보낸 호출이 하나만 있어도 작업의 사용량 합계가 "일부 미확인"으로 보였어요. 본문과 번역의 호출에도 같은 규칙이 적용돼요. 그 밖의 오류로 끝난 호출은 그대로 미확인이에요. [모델 요금](../MODEL-PRICING.md)
- **그 밖에**
  - 도우미가 작업 공간 명령의 출력을 한 번에 64KB까지 받아요(전에는 16KB). 잘린 출력을 다시 읽으려는 호출이 줄어요.
  - 멈춘 작업에 표시하는 "저장한 변경" 수를 실제로 바뀐 대상 수로 세요. 여러 대상을 한 번에 저장한 호출을 1건으로 세던 것을 고쳤어요.
  - 작업 중 입력창의 전송 방식 단축키 안내를 고정 문구에서 버튼 설명으로 옮겼어요.

기존 **SQLite 스키마 15**를 유지하고, 업데이트할 때 바뀌는 데이터가 없어요. 이전에 기록된 요청 한도 초과 호출의 사용량은 미확인 그대로예요. [데이터 호환성](../DATA-MIGRATIONS.md) · [업데이트 안내](../UPDATES.md)

**알려진 문제:** 생각 요약은 Gemini 모델의 도우미 호출에만 있고, 본문 생성과 다른 프로바이더에는 없어요. 도우미 입력창의 초안은 브라우저에만 저장돼서, 다른 채팅의 빈 대화에 초안을 써 두고 탭을 새로 고치면 그 대화는 그 채팅에서 도우미를 열어야 다시 보여요. 실패한 도우미 작업에 내용이 없는 "일부 응답 보기"가 나올 수 있어요. 그 밖은 v0.15.2와 같아요. 봇이 있는 채팅에서는 장면이 완성되는 순간 본문이 위아래로 조금 움직일 수 있고, 봇의 화면 형식으로 그린 장면에서는 변경 카드가 바뀐 자리의 근처까지만 열어요. 채팅 로어를 바꾼 변경 카드는 그 변경을 보여 줄 화면이 아직 없어요.

<summary>구현·검증 범위 — 에이전트 작성 (Claude Fable 5.2)</summary>

변경 커밋은 `v0.15.2..v0.15.3` 범위의 11개예요. 모두 도우미 실행과 그 화면에 관한 것이고, 운영 DB의 도우미 작업 기록을 읽기 전용으로 집계한 결과를 근거로 했어요.

- **이어서 하기(`ac285d70`, `b1f964f0`, `9a63defd`):** `server/helper-resume.ts`가 멈춘 작업이 이미 남긴 기록에서 도구 교환을 되살려요. 결과는 `tool.finished` 이벤트에서, 정확한 인자는 호출 기록의 응답에서 읽어요. 새 저장 위치와 스키마 변경이 없어서, 기존 삭제와 보관 경로가 그 기록을 지우면 이어서 할 수 없게 돼요. 되살린 교환은 프로바이더 연속 상태가 아니라 참고 자료로 넘기므로 이어 가는 작업은 다른 모델을 쓸 수 있어요. 이어 간 작업이 다시 멈춰도 저장 건수와 "처음부터 다시 시도" 금지는 앞 작업까지 합쳐 적용해요.
- **상태 줄(`14759df3`, `c18b0d26`):** 다시 시도 대기는 `provider.retry` 이벤트로 기록해요. 운영 기록에서 완료된 작업 시간의 96%가 모델 호출 대기였어요.
- **거절(`183637aa`, `3dd59307`):** 프로바이더 거절은 `HELPER_RESPONSE_REFUSED`로 끝나요. 다시 보내는 횟수는 거절이 도착한 시점의 전역 설정으로 정하고, 거절된 호출마다 새로 세요. 다시 보낸 호출은 도우미 호출 한도를 쓰지 않지만 전체 호출 한도에는 들어가요. Codex 네이티브 실행은 도구가 이미 실행된 뒤라 다시 보내지 않아요.
- **사용량(`835b8b21`):** HTTP 429는 응답 본문이 시작되기 전에 오는 상태 코드라 모델이 실행되지 않았어요. 세 전송 경로가 입력과 출력 토큰을 0으로 기록하고, 비용 추정은 전체 입력이 0이면 캐시 항목도 0으로 계산해요. 프로바이더가 보고하는 비용 칸은 보고가 없으므로 비워 둬요.
- **대화 목록(`84d53ae4`):** 운영의 빈 대화 17개 중 14개가 도우미를 열 때 만들어진 기본 대화였어요. 서버 목록은 모든 대화를 돌려주면서 쓰지 않은 기본 대화를 표시하고, 숨기는 일은 화면이 해요. 대화를 첫 요청 때 만드는 방식은 넣지 않았어요. 패널이 화면, 초안, 말투를 대화 ID로 묶고 있어서 바꿀 범위가 넓고, 숨긴 뒤에는 남은 빈 행이 화면에 보이지 않아요.
- **생각 요약(`237f5203`):** 요청에 `thinkingConfig.includeThoughts`를 넣고, 도착한 요약을 응답 스트림의 메모리에만 둬요. 서명이 없는 요약 부분은 다음 호출에 돌려보내는 모델 응답에서 빼서 연속 요청과 그 크기 추정이 전과 같아요. HTTP 400이면 그 작업은 요약 없이 한 번 다시 보내고 더 요청하지 않아요.
- **셸 출력(`b1acc94a`):** 운영 기록의 셸 호출 256번 중 73번이 출력이 잘렸고, 그중 54번은 전체 출력이 64KB 이하였어요.
- **v0.15.2 노트에 남겨 둔 질문의 답:** 셸 도구가 들어간 뒤 도우미 완료율이 84.2%에서 64.4%로 낮아진 원인은 셸이 아니었어요. 그 이전 76건 중 53건은 도우미 호출 한도가 12회였고, 한도에 닿으면 "완료"로 끝났어요. 한도가 64회로 오른 뒤 완료 작업의 호출 중앙값이 7회에서 14회가 됐고, 늘어난 실패는 HTTP 429(4건에서 7건)와 20분 시간 초과(1건에서 6건)였어요.
- **로컬 검증:** 릴리스 후보에서 `quality`, 전체 Vitest 3,177개(건너뜀 42개), 문서 검사, 문구 검사를 통과했어요. 브라우저 테스트는 `verify:chat-unification` 31개와 도우미 대화, 작업 공간, 활동 목록, 응답 스트림 42개를 통과했어요. 생각 요약과 목록의 실패 표시는 합성 데이터로 띄운 화면에서 확인했어요. Windows에서 실행했어요. 전체 브라우저 회귀는 이 후보에서 실행하지 않았어요.
- **CI 검증:** 릴리스 커밋의 GitHub `Quality` 워크플로 통과를 확인한 뒤 태그와 릴리스를 발행해요.
- **검증하지 않은 것:** 생각 요약을 실제 Gemini 응답으로 확인하지 못했어요. 요청 필드와 응답 모양은 2026-11-23에 읽은 Gemini API 문서를 따랐고, 테스트는 합성 스트림을 써요. 실제 프로바이더에서의 거절 다시 보내기와 이어서 하기, 좁은 화면과 실제 휴대폰에서의 렌더링도 확인하지 않았어요. 셸 출력 한도를 올린 효과는 배포 뒤의 운영 기록(잘린 출력의 비율, 작업당 셸 호출 수)으로 재야 해요.

# Uimori v0.2.0

`v0.1.1` 이후 모델 실행과 설정, 도구 계약, 운영 배포 경로를 크게 정리한 초기 개발 릴리스예요. 화면의 작은 불일치와 내부 유지보수 비용을 줄이면서, 긴 창작 작업에서 실제로 사용할 수 있는 Anthropic Batch 실행과 더 안전한 Oracle 릴리스 흐름을 추가했어요.

## 주요 변경

- **Anthropic Messages에 Batch 실행 방식**을 추가했어요. 모델 프리셋에서 본문 Run을 `실시간` 또는 `Batch · 비동기 · 50% 할인`으로 선택할 수 있어요. Batch는 완료 뒤 한 번에 표시되고, 번역·상태·도우미·제목 같은 보조 작업은 기존 실시간 실행을 유지해요.
- **Batch 실행을 재시작 뒤 이어 받을 수 있게 했어요.** 공급자의 Batch ID와 요청 해시, 실행 상태를 SQLite에 저장하고 같은 요청을 중복 제출하지 않아요. 이미 완료한 도구 영수증도 재사용하며 사용자 취소는 로컬 Run을 즉시 끝내고 원격 Batch 취소를 best-effort로 요청해요.
- **프로바이더·모델 설정을 단순화했어요.** 프로바이더별 모델 묶음과 독립적인 편집 초안을 사용하고, 중복된 준비 상태 UI와 계열별 제한을 줄였어요. Vertex 모델 목록은 생성과 같은 서비스 계정 인증으로 조회해요.
- **모델 도구 계약을 정리했어요.** 불필요한 단·복수 입력 형태와 과도한 계약을 줄이고 Anthropic을 포함한 프로바이더에서 더 단순한 스키마를 사용해요. 실패 시에는 민감한 원문 대신 안전한 도구 인자 진단을 남겨 원인을 찾기 쉽게 했어요.
- **읽기·설정 UI를 다듬었어요.** 읽기 레이아웃과 모델 설정의 시각적 구조를 통일하고 로어 삭제 확인창, 사이드바 설정 행 등 작은 불일치를 정리했어요.
- **런타임 유지보수와 실행 비용을 줄였어요.** Run 실행 오케스트레이션과 프로바이더 편집 상태를 분리하고 죽은 설정·코드·낡은 벤치마크를 제거했어요. 도우미 화면 보존량을 제한하고 SSE 구독자별 backpressure를 적용해 느린 클라이언트가 불필요한 메모리를 쌓지 않게 했어요.
- **Oracle 릴리스 검증을 강화했어요.** CI를 격리된 shard로 나누고 정확한 branch/SHA의 전체 성공을 배포 관문으로 사용해요. 운영 전환은 쓰기를 닫은 상태에서 백업·이미지·DB·HTTPS smoke를 확인하고, 전환 전후 실패 지점에 맞는 복구 규칙과 보존 정책을 사용해요.
- **개발용 브라우저 검증 경로를 정리했어요.** 시스템 고정 경로뿐 아니라 `PATH`의 Chrome/Chromium도 찾을 수 있어 공용 Playwright 런타임 같은 환경을 그대로 사용할 수 있어요.

## 버전과 데이터

앱 버전은 **`0.2.0`**이며 **설정 → 앱 정보·라이선스**와 Codex 실행기 식별에 같은 패키지 버전을 사용해요. 빌드 식별자는 소스 변경을 구분하기 위해 별도로 유지해요.

개인 작업실 DB는 **schema 6**이에요. schema 1~5의 `uimori-personal-v1` DB는 시작 시 한 번의 트랜잭션으로 현재 형식으로 전환해요. 이번 schema 6 변경은 Anthropic Batch 복구 메타데이터를 위한 것이며 사용자 원고 형식을 새로 만들지는 않아요. 업데이트 전에는 SQLite 스냅샷을 보관하고, 갱신한 DB를 구버전 앱으로 다시 여는 다운그레이드는 하지 않아요. 정확한 범위는 [데이터 안내](../DATA-MIGRATIONS.md#현재-버전)를 확인해요.

## 설치와 업데이트

새 소스 설치:

```sh
git clone --branch v0.2.0 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

기존 사용자는 업데이트 전에 SQLite 백업과 현재 실행 이미지/커밋 정보를 보관하고 [업데이트 안내](../UPDATES.md)의 절차로 코드와 앱을 함께 바꿔요. Oracle 설치는 [Oracle 릴리스 안내](../ORACLE-RELEASE.md)를 사용해요. 태그나 GitHub Release 발행만으로 실행 중인 서버가 자동 업데이트되지는 않아요.

## 알려진 제한

앱 내 업데이트 확인·설치와 무인 자동 업데이트는 아직 제공하지 않아요. Anthropic Batch는 현재 main 본문 Run에만 적용하며 여러 요청을 한꺼번에 모으는 자체 batching scheduler는 없어요. 모든 Risu 자료·스크립트의 완전한 호환성도 보장하지 않으며 지원 범위는 [Risu 가져오기 안내](../RISU-IMPORT.md)를 따라요.

자동 검증의 모델 호출은 합성 fixture를 사용해요. 실제 모델의 품질·요금·서비스 제약은 사용하는 프로바이더가 기준이에요.

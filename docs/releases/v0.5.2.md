# Uimori v0.5.2

v0.5.1의 요청·복구 최적화 기반 위에서, 실제 본문 작성과 조언 흐름의 Codex 네이티브 실행을 확장하고 응답 표시·편집 초안·탐색 UI를 단순화한 패치 릴리스예요. 별도 인프라나 영구 에이전트 계층을 늘리기보다 기존 Run과 저장 경계를 유지하면서 한 작업 안의 도구 왕복을 자연스럽게 이어 가도록 정리했어요.

## 주요 변경

- **Codex 본문·조언자 native tool loop:** 실제 본문 Run에서 Codex 작가와 Codex 조언자가 각각 하나의 native thread/turn 안에서 자료 조회·조언·최종 제출까지 이어갈 수 있어요. 메인 작가가 다른 공급자여도 Codex 조언자는 같은 native 실행 방식을 사용해요.
- **기존 Run·저장 경계 유지:** `story.submit`과 유효한 평가 제출은 기존 JEV 판정·후처리·원자적 저장 흐름으로 넘겨요. native 실행 중 도구마다 프롬프트를 다시 만들거나 문맥 정리를 중복 수행하지 않고, 내부 추론 횟수를 호스트 요청 횟수로 잘못 집계하지 않아요.
- **응답 표시 방식 선택:** 기본 **실시간 표시**와 **완료 후 한 번에 표시**를 고를 수 있어요. 완료 후 표시는 검증·후처리가 끝난 답변만 공개하며, 진행 상태·취소는 그대로 유지하고 중단·실패한 경우 일부 응답을 따로 확인할 수 있어요.
- **스트리밍·provider hot path 정리:** 검증된 텍스트 조각을 증분으로 전달하고, 진단 JSON과 요청 직렬화의 반복 작업을 줄였어요. 구조화 번역·도구 인수·최종 제출 envelope 같은 내부 데이터는 공개 본문 조각에 섞이지 않아요.
- **편집 초안 상태 단순화:** 자료 편집은 하나의 `ResourceEditorSession`이 폼·원문·저장 기준본·변경 여부를 소유하도록 정리했어요. 복구 초안, 저장 실패, 늦게 도착한 조회, 다른 창의 저장 알림에서도 미저장 입력을 덜 흔들리게 보존해요.
- **탐색 UI 다듬기:** 서재·프롬프트 편집의 중복 상태를 줄이고 compact navigation을 정리했어요. 데스크톱에서는 좌측 사이드바 폭을 **보통 / 넓게 / 매우 넓게** 중에서 선택할 수 있어요.
- **유지보수 정리:** 중복 native 검사와 더 이상 쓰지 않는 JEV 검사 스크립트·오래된 테스트 fixture를 제거하고, 새 실행 경계에 맞춰 문서와 회귀 검사를 갱신했어요.

## 데이터 호환성

앱 버전은 **0.5.2**, 개인 작업실 DB는 계속 **스키마 15**예요. **v0.5.1과 데이터 스키마가 같으므로 기존 스키마 15 작업실은 데이터 볼륨을 유지해 업데이트할 수 있어요.** 업데이트 전에는 평소처럼 앱의 일관된 SQLite 백업과 실행 중인 앱/이미지 정보를 함께 보관해요.

v0.3.1의 스키마 12 DB를 직접 변환하는 기능은 포함하지 않아요. 구형 DB와 백업은 해당 형식을 지원하는 앱 버전과 함께 보관하고, DB 버전 숫자를 수동으로 바꾸지 않아요. 자세한 범위는 [데이터 안내](../DATA-MIGRATIONS.md)와 [업데이트 안내](../UPDATES.md)를 확인해요.

## 설치와 업데이트

```sh
git clone --branch v0.5.2 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x를 사용해요. 기존 설치는 [업데이트 안내](../UPDATES.md)를 따라 앱과 DB 백업을 함께 보관해요. Oracle 운영 설치는 [전용 배포 절차](../ORACLE-RELEASE.md)로 검증한 정확한 main 커밋을 배포해요. GitHub Release 발행만으로 서버가 업데이트되지는 않아요.

## 검증 범위와 알려진 제한

Codex 본문·조언의 native 실행은 합성 stdio 통합 검사에서 작성·조언·캐시·자식 슬롯·취소·제출·절약형 전환을 확인해요. 응답 표시, 스트리밍 진행 상태, 편집 초안 복구와 탐색 UI는 단위·브라우저 회귀 검사로 확인해요.

실제 유료 모델의 후속 생성 방식·응답 품질·내부 모델 호출 수·최종 청구 사용량까지 자동 검사로 보장하지는 않아요. native 제출로 호스트가 작업을 종료한 경우에는 불완전한 usage를 최종 공급자 청구량처럼 표시하지 않아요.

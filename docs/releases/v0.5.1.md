# Uimori v0.5.1

v0.5.0의 도우미·네이티브 실행 기능을 유지하면서, 실제 요청과 화면 갱신에서 반복되는 작업을 줄이고 복구·번역·진단 경로를 다듬은 패치 릴리스예요. 새 인프라를 늘리기보다 기존 흐름을 단순화하고 필요한 정보만 만들고 읽도록 정리하는 데 집중했어요.

## 주요 변경

- **요청 오버헤드 감소:** provider 요청 준비, 캐시 진단, 프롬프트·컨텍스트 구성에서 사용하지 않는 계산과 복사를 늦추거나 제거했어요. 요청 단위 worker와 이미 검증한 중간 결과를 재사용하고, 이미지·원문 준비의 반복 작업도 줄였어요.
- **네이티브 복구 안정화:** Codex·Risu 네이티브 실행에서 처리 가능한 오류 뒤의 복구와 늦게 도착한 응답 처리를 정리했어요. 실패한 호출을 잘못 재생하지 않고, 다음 입력 초안과 탐색 상태를 보존하며 복구할 수 있도록 했어요.
- **번역 입력 간소화:** 번역이 필요한 원문만 보내는 source-only 경로를 추가하고, 번역 가이드·작성 메모·참조 자료가 중복 전달되지 않도록 요청 구성을 정리했어요.
- **요청 진단 개선:** 실행 상세에서 요청별 토큰 사용량과 실제로 붙은 로어를 확인할 수 있어요. 사용자가 열지 않는 진단 정보는 필요할 때까지 계산을 미뤄 평상시 요청 비용을 늘리지 않아요.
- **도우미·리더 UI 효율화:** 보이지 않는 패널의 작업과 느린 idle polling을 멈추고, Reader와 도우미가 필요하지 않은 데이터를 미리 만들거나 다시 읽는 경로를 줄였어요. 기존 초안·revision·저장 영수증 경계는 유지해요.
- **유지보수 정리:** 사용하지 않는 generic updater와 죽은 코드·중복 검증·오래된 문서 경로를 제거하고, 문서 링크 검사를 더 작은 전용 검사로 바꿨어요. Oracle 배포의 기존 백업·호환성·HTTPS smoke 경계는 그대로 유지해요.

## 데이터 호환성

앱 버전은 **0.5.1**, 개인 작업실 DB는 계속 **스키마 15**예요. **v0.5.0과 데이터 스키마가 같으므로 기존 스키마 15 작업실은 데이터 볼륨을 유지해 업데이트할 수 있어요.** 업데이트 전에는 평소처럼 앱의 일관된 SQLite 백업과 실행 중인 앱/이미지 정보를 함께 보관해요.

v0.3.1의 스키마 12 DB를 직접 변환하는 기능은 포함하지 않아요. 구형 DB와 백업은 해당 형식을 지원하는 앱 버전과 함께 보관하고, DB 버전 숫자를 수동으로 바꾸지 않아요. 자세한 범위는 [데이터 안내](../DATA-MIGRATIONS.md)와 [업데이트 안내](../UPDATES.md)를 확인해요.

## 설치와 업데이트

```sh
git clone --branch v0.5.1 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x를 사용해요. 기존 설치는 [업데이트 안내](../UPDATES.md)를 따라 앱과 DB 백업을 함께 보관해요. Oracle 운영 설치는 [전용 배포 절차](../ORACLE-RELEASE.md)로 검증한 정확한 main 커밋을 배포해요. GitHub Release 발행만으로 서버가 업데이트되지는 않아요.

## 검증 범위와 알려진 제한

provider·Codex 요청 구성, source-only 번역, 요청 로어·토큰 진단, 네이티브 복구, Reader·도우미 상태 보존은 합성 provider와 단위·브라우저 회귀 검사로 확인해요. 배포 도구 변경은 Oracle 호스트 제어·HTTPS smoke 상태 머신 검사와 실제 ARM64 운영 배포에서 함께 확인했어요.

실제 유료 모델의 응답 품질이나 프로바이더 내부 토큰 계산 방식까지 자동 검사로 보장하지는 않아요. 요청 진단은 Uimori가 알고 있는 wire usage와 첨부 자료를 보여주며, 프로바이더가 공개하지 않는 내부 처리량이나 비용을 추정해 채우지 않아요.

# Uimori v0.8.0

v0.7.2 이후 모델 연결과 장문 창작 자료 선별 범위를 확장하고, 자주 사용하는 서재·설정 화면의 정렬과 실패 복구를 개선한 기능 릴리스예요.

## 주요 변경

- **Google AI Studio · Gemini 연결:** Google AI Studio API 키로 Gemini API에 직접 연결해 모델 목록을 조회하고 모델 프리셋을 등록할 수 있어요. Google Cloud 서비스 계정이나 Vertex 프로젝트 ID는 필요하지 않아요. 생성 옵션과 Standard/Flex/Priority 서비스 등급을 설정할 수 있지만 실제 지원 범위·과금은 계정과 모델에 따라 달라요.
- **Gemini PDF 입력 옵션:** Vertex Gemini와 Google AI Studio 연결에서 초기 텍스트 대화를 하나의 PDF로 묶어 전송하는 선택 기능을 추가했어요. 기본값은 꺼짐이며 시스템 지침·도구 결과·후속 대화는 기존 형식을 유지해요. 원문 기준 컨텍스트 예산 측정과 전송 전 용량 제한을 적용해요. PDF 전환으로 인한 응답 품질·비용·토큰 절약을 보장하지 않으며 전송 표현이 바뀌어 응답이 달라질 수 있어요.
- **대규모 로어 선별:** 로어북이 JEV 입력 예산을 초과하면 폴더와 첨부 순서에 구애받지 않고 전체 고정 로어에서 제목·설명·본문의 관련 후보를 로컬 검색해 JEV에 전달해요. 공유 로어의 실제 포함 분량과 수정된 채팅별 값을 확인하고, 판단하지 못한 로어를 불필요로 기록하지 않아요. 검색에는 추가 API 호출·임베딩·영구 색인이 필요하지 않아요.
- **대규모 이미지 후보 선별:** 최대 10,000개 작업 카탈로그의 메타데이터를 로컬 검색해 선택된 문단별 이미지 후보를 구성해요. 한 문단이 예산을 독점하지 않도록 문단별 초기 몫과 남은 예산을 배분하며, 기존 JEV 호출·선택 및 삽입 상한을 유지해요. 이미지 자체의 표정·구도 해석이나 표현이 다른 모든 의미 관계의 검색을 보장하지 않아요.
- **드래그 정렬 확대:** 프로바이더와 모델 프리셋 순서를 직접 끌어 바꾸고, 주요 모델 선택 메뉴에서도 그 순서를 따르도록 했어요. 프롬프트의 수동 순서 변경과 폴더 이동도 지원하고, 키보드·메뉴 기반 대체 수단과 기존 설정 보존을 유지해요.
- **로딩 및 오류 복구 통일:** 서재·프롬프트·설정·원고 작업실 등에서 지연된 조회의 로딩 표시와 실패 시 오류·재시도 경로를 공통 방식으로 정리했어요. 이전 응답이 새 화면의 데이터나 미저장 작업을 덮지 않도록 기존 복구 경계를 유지해요.

## 데이터 호환성

앱 버전은 **0.8.0**, SQLite 데이터베이스는 계속 **스키마 15**예요. v0.7.2에서 사용하던 스키마 15 작업실은 기존 데이터·설정으로 업데이트할 수 있으며 별도 DB 마이그레이션은 없어요. Google AI Studio 연결과 PDF 입력은 선택 사항이며 기존 연결을 자동 전환하지 않아요. 업데이트 전 일관된 SQLite 백업을 보관하고, 실행 중인 생성·도우미 작업과 저장을 완료해 주세요. 이전 스키마 DB의 직접 변환은 제공하지 않아요.

## 설치와 업데이트

GitHub 릴리스가 발행되면 `v0.8.0` 태그로 설치할 수 있어요.

```sh
git clone --branch v0.8.0 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x가 필요해요. 기존 설치는 [수동 업데이트](../UPDATES.md)를, Oracle 운영 환경은 [전용 배포 안내](../ORACLE-RELEASE.md)를 따라요. 설치 후 **설정 → 앱 정보·라이선스**에서 앱 버전 `0.8.0`과 빌드 식별자를 확인해요. 릴리스 게시만으로 운영 인스턴스는 업데이트되지 않아요.

## 검증 범위와 제한

릴리스 후보는 문서·타입·빌드 및 기능별 합성 테스트와 정확한 커밋의 GitHub Quality CI로 검증해요. Google AI Studio와 PDF 입력은 실제 계정의 모든 모델·서비스 등급에서 호환성과 품질을 보장하지 않아요. 로컬 후보 검색은 메타데이터와 단어 단서를 기반으로 하므로 단어가 전혀 겹치지 않는 의역·연상 관계는 누락될 수 있어요. 운영 이미지·기존 DB 복제본·HTTPS와 쓰기 재개는 별도 Oracle 배포 절차에서 확인해요.

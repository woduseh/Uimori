# v0.15.1

v0.15.0에서 새로 넣은 도우미 되돌리기, 확인, 다음 요청 예약의 결함을 고치고 성능을 손봤어요.

- **도우미 확인과 되돌리기가 빠뜨리던 경우를 고쳤어요.**
  - 전에 승인한 것과 같은 요청이 다시 보류되면 승인 버튼이 뜨지 않던 문제를 고쳤어요.
  - 가져온 기억 메모를 바꾼 작업, 플롯의 단계나 관련 항목만 바꾼 작업, 봇의 초상 이미지나 연결 모듈 같은 설정만 바꾼 작업도 변경 카드가 생기고 되돌릴 수 있어요.
  - 작업 뒤에 봇 설정을 직접 고쳤으면 되돌리기가 그 수정을 덮어쓰지 않고 멈춰요.
  - 계획 모드에서는 보류된 작업을 승인할 수 없어요. 승인하면 실행 모드로 바뀌어요.
- **지운 내용이 도우미 기록에 남지 않아요.** 보류된 작업이 담고 있던 요청 원문은 더는 승인할 수 없게 되거나 대상을 지우면 함께 지워요. 변경 기록이 만료되거나 지워질 때 거기서만 쓰이던 이미지와 테마 자산도 정리해요. [삭제](../DELETION.md)
- **다음 요청 예약이 더 조심스러워졌어요.** 예약해 둔 뒤에 모델, 페르소나, 모듈이나 전역 프롬프트 설정을 바꾸면 자동으로 보내지 않고 초안으로 돌려놓아요. 전송 직전에 다른 화면에 다녀온 경우와 사전 확인을 하지 못한 경우에도 보내지 않아요. 예약으로 보낸 요청도 직접 보낸 요청처럼 본문 끝을 따라가요. [실행 중 다음 요청 예약](../GENERATION.md#실행-중-다음-요청-예약)
- **읽는 중에 화면이 바뀌거나 닫히던 문제를 고쳤어요.**
  - 편집기를 열어 두었거나 글을 선택하고 있으면 번역이 도착해도 화면이 바뀌지 않아요. 봇의 화면 형식으로 그린 장면에서도 같아요.
  - 장면 메뉴에서 번역 보기를 누른 직후 메뉴가 닫히던 문제를 고쳤어요.
  - 선택 구절 다듬기 창은 저장하는 동안 `Esc`로 닫히지 않고, 열려 있는 동안 전역 단축키가 동작하지 않아요. 제안이 도착해도 키보드 포커스가 창 안에 남아요.
- **선택 구절을 다듬을 때 앞뒤 문단만 보낼 수 있어요.** 긴 장면에서 요청이 작아지는 대신 모델은 장면의 나머지를 보지 못해요. [선택 구절 퇴고](../EDITING.md#선택-구절-퇴고)
- **더 빨라졌어요.** 활동 피드 확인이 실행 기록이 많은 작업실에서 느리던 문제를 고쳤어요. 이미지가 많은 카드는 본문 모델에 보내는 이미지 목록이 작아졌어요. [Risu 가져오기](../RISU-IMPORT.md)
- **화면 정리**
  - 도우미를 옆에 붙여 둔 채 채팅을 옮긴 뒤 브라우저 뒤로가기를 누르면 이전 채팅으로 돌아가요.
  - 옵션 프리셋을 편집하다 나갈 때 저장하지 않은 입력이 있으면 먼저 확인해요.
  - 좁은 화면의 설정 편집 화면에는 뒤로가기가 하나만 보여요. 한 번 누르면 편집 화면에서 나오고, 한 번 더 누르면 설정 목록으로 가요.
  - 좁은 도우미 패널에서 입력창 도구가 겹치던 문제와, 넓게 저장한 오른쪽 패널이 좁은 창에서 잘리던 문제를 고쳤어요.
  - 변경 카드의 한국어 비교에서 지운 낱말과 넣은 낱말이 붙어 보이던 것, 접힌 계획 카드의 마지막 줄이 잘려 보이던 것, 도우미 실행 중 문구가 두 곳에 보이던 것을 고쳤어요.
  - 중국어의 토큰 표기와 영어의 단수·복수 표기를 바로잡았어요.

기존 **SQLite 스키마 15**를 유지해요. 업데이트 뒤 처음 시작할 때 도우미 기록에 남아 있던 보류 작업의 요청 원문을 지우고 읽기 인덱스 하나를 추가해요. 그 밖의 자료는 바꾸지 않아요. [데이터 호환성](../DATA-MIGRATIONS.md) · [업데이트 안내](../UPDATES.md)

Oracle 배포 도구는 백업을 확인한 뒤 DB의 빈 공간이 20% 이상이고 64MiB 이상일 때만 DB를 압축해요. 평소 배포에서는 이 단계가 아무 일도 하지 않아요. [Oracle 배포 안내](../ORACLE-RELEASE.md)

**알려진 문제:** v0.15.0과 같아요. 봇이 있는 채팅에서는 장면이 완성되는 순간 본문이 위아래로 조금 움직일 수 있고, 봇의 화면 형식으로 그린 장면에서는 변경 카드가 바뀐 자리의 근처까지만 열어요. 채팅 로어를 바꾼 변경 카드는 그 변경을 보여 줄 화면이 아직 없어요.

변경 커밋은 `v0.15.0..v0.15.1` 범위에 있어요. gemini-4-neon이 v0.15.0 구현을 감사해 지적한 결함을, 실패하는 테스트로 먼저 재현한 것만 고쳤어요. 구현은 Claude Opus 5.5 서브에이전트가 맡았고, 성능 변경은 별도 브랜치(`perf/verified-fixes`)를 병합했어요. 릴리스 전에 gemini-4-neon이 전체 범위와 v0.14.0 이후의 문구를 다시 검토했어요.

- **확인:** 승인은 보류한 작업보다 나중 작업의 것만 인정해요(`d3b9754f`). 보류된 호출의 인자는 `server/helper-argument-retention.ts`가 나중 작업이 생기거나 승인한 작업이 끝나거나 대상을 지울 때 지우고, 인자가 없는 확인은 `CONFIRMATION_UNAVAILABLE`로 끝나요(`e00f87ac`, `08aa9437`). 계획 모드와 승인을 함께 보낸 요청은 서버가 거절해요(`337aac51`).
- **되돌리기:** 가져온 기억 메모의 `origin`을 저장된 메모에서 읽어 복원해요(`e7f4bc82`). 플롯 변경 기록이 단계, 관련 항목, 위치를 비교하고, 복원은 모양이 바뀐 노드를 최상위로 떼어 낸 뒤 다시 만들고 옮기는 세 번의 저장으로 해요(`059d3df1`). 봇 설정은 되돌리기 해시와 변경 항목에 모두 들어가요(`922a8d7f`, `907f3059`). 속성 검사 생성기에 단계 변경, 부모를 넘는 이동, 관련 항목 변경을 넣었고 시드 1,500개로 통과했어요.
- **자산 정리:** 변경 기록의 기준 상태를 지우는 모든 경로가 그 안의 이미지 해시를 정리 대기열에 넣고 테마 자산을 바로 정리해요(`ea7961ac`).
- **예약:** 예약할 때 프로필, 옵션, 프롬프트 작업공간의 수정 번호를 기록하고 보내기 전에 다시 읽어요. 예약 전송은 `web/main.tsx`의 전송 경로 하나를 써요(`5e134640`).
- **리더:** 작업 메뉴는 기준 버튼의 내용 기준 위치가 바뀐 스크롤을 배치 변화로 보고 기준만 다시 잡아요(`9150cf18`). 번역 도착 시 선택 감지는 섀도 DOM 안까지 봐요(`e03235c3`, `2ce993a3`). 다듬기 창은 모달이 아니라서 `aria-modal` 대신 `data-keyboard-overlay`로 단축키를 멈춰요(`0cf87c34`).
- **화면:** 도우미의 히스토리 항목은 옆에 붙어 있지 않을 때만 만들어요(`9ae0456a`). 포커스 유지는 `web/useFocusFallback.ts`예요(`736e6aab`). 시각 마감은 `28fda323`, `c2e391f3`, `a1333539`, `f4ca41d2`, `15dd8204`, `edfcecd7`이에요.
- **성능:** 활동 피드의 실행별 조회가 실행 인덱스를 쓰도록 지정했어요. 실행 905개와 시도 5,149개가 있는 DB에서 폴링 한 번이 2,070ms에서 6.7ms로 줄었어요(`e5910285`). 도우미 작업의 재시도 조회용 인덱스(`ef8c763c`), 중복 읽기 제거(`6da9c215`), Risu 자산 이름 탐색(`0508d838`), 토큰 캐시(`0e58497f`), 이미지 목록 축소(`f0348ff3`, `4e0541b6`), 배포 때 DB 압축(`d4f7ec9d`)이 들어갔어요.
- **재현되지 않아 고치지 않은 지적:** 작업 메뉴의 한글 조합 중 `Esc`(메뉴 안에 입력란이 없음), 플롯 복원이 예약된 장면 명령을 잘못 취소한다는 추정(테스트로 고정, `7d5220f0`)이에요.
- **로컬 검증:** 문구 보정 전 커밋 `f4f50ab8`에서 `quality`, `build`, 전체 Vitest 3,025개(건너뜀 42개), 전체 브라우저 회귀 629개, UI 회귀 62개, 번역 키와 문구 검사, 문서 검사를 통과했어요. Windows에서 실행했어요.
- **CI 검증:** 릴리스 커밋의 GitHub `Quality` 워크플로 통과를 확인한 뒤 태그와 릴리스를 발행해요.
- **검증하지 않은 것:** 실제 모델 프로바이더 호출, 배포 때 DB 압축의 실제 실행(이번 배포가 새 배포 스크립트의 첫 사용이에요), 실제 휴대폰에서의 렌더링이에요. 예약 전송의 사전 확인은 서버 쪽 판정이 실패하거나 판정용 자격 증명이 없으면 통과해요.

# Uimori v0.5.0

큰 구성과 로어를 필요한 범위만 따라 읽고, 무엇을 실제로 읽었고 어떤 저장이 확정됐는지 더 명확하게 확인하는 도우미 중심 기능 릴리스예요. Codex 네이티브 도구 실행을 안정화하고 반복 읽기 비용을 줄였으며, 도우미 응답의 복사와 마크다운 표시도 함께 다듬었어요.

## 주요 변경

- **큰 구성의 부분 조회:** `outline.read`가 전체 개요, 특정 하위 트리, 한 항목 상세를 작은 페이지로 읽어요. 깊이 제한으로 제외된 항목과 실제 반환 범위, 이어 읽기 위치와 조회한 수정 번호를 구분해 큰 작품도 필요한 만큼 검토할 수 있어요. 긴 의도문은 UTF-16 범위로 이어 읽고, `wholeField`는 한 응답이 필드 전체를 담았는지만 뜻해요.
- **구성과 실제 원문 연결:** 구성의 작성 참조에서 정확한 원문 ID·hash와 기존 `data.read` 호출로 이어져요. 작업 시작 시 고정된 원문과 이후 편집된 현재 원문을 구별하며, 계획을 읽은 것과 실제 본문을 읽은 것을 같은 근거로 취급하지 않아요.
- **로어 계층 탐색:** 기존 `knowledge.search`에 현재 실행의 package → folder → lore 구조를 따라가는 탐색 모드를 추가했어요. 기존 문자열 검색·JEV 선별·고정 로어 배치는 그대로 두고, 별도 벡터 DB·embedding·검색 모델 없이 같은 네이티브 tool loop에서 필요한 설정만 찾아 읽어요.
- **확정 저장 효과 확인:** `task.inspect(kind:"helper")`가 기존 helper operation 영수증을 이용해 확정된 저장 효과를 작은 페이지로 보여줘요. 응답이 끊겨도 기록된 commit을 확인할 수 있지만, 과거 저장 결과를 재생하거나 현재 데이터가 그대로라고 추정하지는 않아요. 기존 원자적 저장·수정 번호 충돌·중복 실행 방지는 유지해요.
- **Codex 도우미 안정화:** Uimori 도구를 별도 namespace로 격리하고 Code Mode의 기본 `functions` 경로와 충돌하지 않게 했어요. 도구 읽기·캐시·병렬 refill·source hash 재사용을 정리해 불필요한 host-side 반복 작업을 줄였어요.
- **도우미 응답 UX:** 도우미 응답에도 복사 동작을 제공하고, 표를 포함한 일반 Markdown 표시를 메인 응답과 더 일관되게 렌더링해요.
- **명시적 Codex 요청 안내:** Codex를 메인/번역 모델로 사용할 때 명시적인 성인 콘텐츠 요청은 전송 전에 안내해 사용자가 직접 계속할지 결정할 수 있어요.

## 데이터 호환성

앱 버전은 **0.5.0**, 개인 작업실 DB는 계속 **스키마 15**예요. **v0.4.0과 데이터 스키마가 같으므로 스키마 15를 사용 중인 v0.4.0 설치는 기존 데이터 볼륨을 유지해 업데이트할 수 있어요.** 업데이트 전에는 평소처럼 앱의 일관된 SQLite 백업과 실행 중인 앱/이미지 정보를 함께 보관해요.

v0.3.1의 스키마 12 DB를 직접 변환하는 기능은 여전히 포함하지 않아요. 구형 DB와 백업은 해당 형식을 지원하는 앱 버전과 함께 보관하고, DB 버전 숫자를 수동으로 바꾸지 않아요. 자세한 범위는 [데이터 안내](../DATA-MIGRATIONS.md)와 [업데이트 안내](../UPDATES.md)를 확인해요.

## 설치와 업데이트

```sh
git clone --branch v0.5.0 --single-branch https://github.com/woduseh/Uimori.git
cd Uimori
npm ci
npm run dev
```

Node 24.14 이상 24.x를 사용해요. 기존 설치는 [업데이트 안내](../UPDATES.md)를 따라 앱과 DB 백업을 함께 보관해요. Oracle 운영 설치는 [전용 배포 절차](../ORACLE-RELEASE.md)로 검증한 정확한 main 커밋을 배포해요. GitHub Release 발행만으로 서버가 업데이트되지는 않아요.

## 검증 범위와 알려진 제한

도우미의 부분 조회·이어 읽기·저장 영수증, Codex App Server 도구 연결, 로어 계층 탐색, 응답 마크다운과 복사 동작은 합성 모델·App Server와 브라우저/스토리지 회귀 검사로 확인해요. Oracle 릴리스 절차는 정확한 커밋의 전체 GitHub Actions와 ARM64 후보 이미지, 빈 DB·운영 DB 복제본, HTTPS smoke를 별도로 검증해요.

실제 구독 모델이 어떤 순서로 도구를 선택하는지, 장편 분석 품질이 얼마나 좋아졌는지, 프로바이더 내부 모델 호출 수나 토큰 절감량은 자동 검사만으로 보장하지 않아요. 폴더 탐색은 기존 작성 구조를 이용하는 보조 경로이며 자동 AI 분류·vector RAG·별도 PageIndex 서비스는 포함하지 않아요. 구성 점검 결과와 도우미 해석도 원문·사용자 설정과 별도의 근거로 취급해요.

# v0.12.4

Risu Lua 호환성을 넓히고 카드 선택·폼 제출의 결과 재확인을 보완했어요. 기존 원고·자료·대화·이미지를 보존하며 **SQLite 스키마는 15로 유지**해요.

- 카드의 `risu-form` 제출을 `onFormSubmit`에 연결했어요. 같은 이름의 여러 필드와 제출 버튼 값을 보존하고, 키보드 제출·필수 입력 검증을 유지해요. 선택된 파일과 외부 폼 전송은 차단해요.
- `editDisplay`는 문자열이 아닌 반환값을 무시하고 직전 문자열로 계속해요. 수동 트리거의 `risu-id`를 해당 실행의 CBS에 전달하며, 같은 이름의 체크박스도 다시 표시할 때 선택을 유지해요.
- 선택 응답이 유실되면 원래 요청으로 결과를 확인해요. 지연 중인 요청에 새 화면이 합류해도 잠금이 남지 않으며, 같은 본문의 서로 다른 장면은 독립적인 선택으로 처리해요. 확정 실패 뒤에는 다음 수동 클릭으로 새 시도를 할 수 있어요.
- `axLLM`의 `otherAx`·`memory`·`translate`를 기존 스크립트·컨텍스트 정리·번역 모델에 연결했어요. 새 액션은 현재 설정을 고정하고, 설정된 모델이 삭제되거나 사용할 수 없으면 다른 모델로 조용히 대체하지 않아요. 무관한 작문과 로컬 카드 동작은 계속 사용할 수 있어요.
- 멀티모달 Lua 요청은 현재 실행에 속한 카드·채팅 이미지의 저장된 바이트를 전송해요. 스트림 중간 실패는 부분 응답·사용량을 호출 기록에 보존하고 Lua에는 명시적 오류를 반환해요.
- `hash`, `getTokens`, `getAuthorsNote`, `getPersonaDescription`, `getLoreBooks`를 추가했어요. 조회는 고정된 실행 자료를 사용하고 원본 자료나 로어 선택 상태를 변경하지 않아요.
- `npm run check:risu-lua -- --risu <경로>`로 원본 Lua API·래퍼·이벤트 변경과 Uimori의 이름 노출 현황을 비교할 수 있어요. 자동 런타임 갱신이나 완전 호환 판정은 아니에요.

`emotion`·`submodel`, 명시적인 `streaming=false`, system·assistant 이미지 전송, Risu의 별도 UUID 인레이 저장소는 지원하지 않아요. 캐릭터 수정·이미지 생성·외부 요청·임베딩·로어 수정 API도 계속 미지원이에요. 자세한 계약은 [Risu 가져오기와 Lua 실행](../RISU-IMPORT.md#lua-조회와-모델-옵션)을 참고해요.

업데이트 절차는 [업데이트 안내](../UPDATES.md)를 참고해요. 검증은 합성 제공자·로컬 브라우저를 중심으로 했어요.

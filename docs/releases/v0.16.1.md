# v0.16.1

도우미가 읽는 앱 사용 설명서에서 개발용 내용을 덜어내고 사용법만 남겼어요. 화면과 생성 동작은 바뀌지 않아요.

- **설명서에서 개발용 내용을 뺐어요.** 소스 파일 경로, 테스트 이름, 내부 API 주소와 "구현 참고" 섹션을 설명서에서 걷어냈어요. 설명서 44개의 전체 분량이 약 30% 줄어서(452,304자 → 315,823자), 도우미가 설명서를 검색하고 읽을 때 구현 설명이 섞여 나오지 않아요.
- **구현 참고 안에 있던 사용법은 본문으로 옮겼어요.** Risu 카드의 Lua 조회 API와 폼 제출, 대용량 자료 한도, ComfyUI·NovelAI 오류 코드, 푸시 알림의 재시도와 만료처럼 사용자와 카드 제작자가 알아야 하는 설명은 지우지 않고 각 설명서의 본문 섹션에 뒀어요.
- **CHARX 내장 모듈의 우선순위를 설명서에 적었어요.** CHARX 안에 내장 모듈이 있으면 정규식·트리거·로어는 카드에 직접 적힌 것 대신 내장 모듈의 것을 써요. 카드의 로어나 스크립트가 적용되지 않을 때 확인할 내용이에요. [Risu 자료 가져오기](../RISU-IMPORT.md#자주-겪는-문제와-대처-방법)
- **개발 문서는 `docs/dev/`로 옮겼어요.** 코드 지도, 도구 계약, 개발·배포 안내와 기능별 구현 제약이 이 폴더에 있어요. 이 폴더의 문서는 도우미가 읽지 않고 Docker 이미지에도 넣지 않아요. `docs/CODE-MAP.md`, `docs/DEVELOPMENT.md` 같은 예전 주소로 걸어 둔 링크는 `docs/dev/` 아래로 바꿔 주세요.

**데이터 호환성:** SQLite 스키마 15를 유지하고 저장된 원고·번역·설정은 변경하지 않아요. 새 데이터 마이그레이션은 없어요. [업데이트 안내](../UPDATES.md)

**검증:** 전체 품질 검사와 단위 테스트(3,207건), 빌드와 도구 테스트가 통과했어요. 문서 검사는 링크·앵커·경로와 함께, 설명서에 개발 섹션 제목·내부 경로·내부 API 주소가 다시 들어오면 실패하도록 넓혔어요. 옮기고 줄이는 과정에서 내용이 사라지지 않았는지는 아래 변경 근거의 방법으로 확인했어요. 영어로 옮긴 개발 문서를 원문과 문장 단위로 전부 대조하지는 않았어요. 정리한 설명서로 도우미의 답이 달라지는지는 실제 모델 호출로 확인하지 않았어요.

## 결정

### 1. 채팅별 고정 층을 도입해요

전역 작문 프롬프트와 전역 본문 모델을 기본값으로 두고, 채팅이 원하면 **작문 프롬프트 프리셋과 본문 모델**을 그 채팅에 고정해요. 번역 프롬프트·번역 모델·거절 판정·표시 상태·이미지·도우미·문맥·제목 모델은 전역으로 유지해요.

- 고정은 프리셋 **ID**를 가리키고 최신 저장본을 따라가요. "같은 ID의 최신 내용을 다음 실행에 사용"하는 현재 원칙과 같아요.
- 고정한 프리셋·모델이 삭제·비활성이면 임의 대체 없이 그 채팅의 새 실행을 막고 다시 고르게 해요. 전역 모델 삭제 처리와 같은 규칙이에요.
- 채팅 설정에서 고정 대상 변경과 전역 복귀를 제공해요. 변경은 과거 Run을 바꾸지 않아요. 고정 변경으로 옵션 소속(`OptionBinding`)이 달라지면 기존 "예약 전 프롬프트 변경" 충돌 검사가 대기 중 옵션을 무효 처리해요.
- 채팅 헤더·설정에 고정 상태를 항상 표시해요.
- 근거: 전역 작업본은 공유 가변 상태라, 기기 A의 프리셋 적용이 기기 B에서 진행 중인 채팅의 다음 요청에 조용히 적용돼요. 최초 구상 7·8번을 동시에 만족시키는 방법이에요.
- 구현 자리: 모델 참조 해석을 한 곳(`ModelRole` + 단일 해석 함수)으로 모으는 결정 6의 작업과 같은 자리에서 해요. 관련 계약: [GLOBAL-MODELS.md](GLOBAL-MODELS.md), [RUNTIME-SIMPLIFICATION.md](RUNTIME-SIMPLIFICATION.md).

### 2. Q04 실모델 평가를 실사용 장기 세션으로 대체해요

Q04는 "150k~200k 누적 토큰 규모에서 수동 요약·새 채팅 없이 같은 작품을 이어갈 수 있는지, 근거 없는 정보가 자기강화되지 않는지"를 실모델로 평가하는 인수 항목이에요. 기억 추출이 제거됐으므로 대상은 자동 압축·`context.*` 도구·사용자 메모·원문 재조회예요.

- 기존 297회 호출 프로토콜([MEMORY-EVALUATION-RESULTS](../project-plan/MEMORY-EVALUATION-RESULTS.md))은 추출 경로를 전제하므로 사용하지 않아요.
- 대체: 검증용 모델 프리셋의 입력 한도를 낮게 두어 압축을 빨리 유도하고, 작품 하나를 압축이 두세 번 지나도록 누적해요. 2026-09-10 추가 지시에 따라 퍼블릭 도메인 작품의 원문을 사용할 수 있어요. 기존 작품 지식으로 답하는 것을 구분할 별도 수정 사실과 원문 근거를 확인하고, 압축 뒤 도우미에게 요약 내용의 적절성을 조회시켜요.
- 관찰 기준: 압축 전 약속·관계 기억, 사용자 정정의 우선, 필요 시 자발적 원문 조회. 도우미는 로어 수정 저장과 옵션 위임을 각 한 번 실제로 실행해요.
- 2026-09-10 사용자가 로컬에 연결된 **Gemini 3.8 Flash**, 총비용 **$100 이내**, 평가 전체 호출 횟수 제한 없음을 승인했어요. 작업별 호출·출력·취소 한도는 유지해요. 결과는 원문과 대조해 판정하고 로컬 계약 검사 PASS로 대신하지 않으며, 에이전트 대조와 사용자의 문학적 품질 판정을 구분해요.
- L01(공급자별)·L02(실기기)는 3일 사용 결과를 CURRENT에 기록하는 것으로 정리해요.

### 4. 프롬프트는 저장된 AST 하나가 원본이고, 에이전트가 편집하고 사람이 손봐요

- 원본은 저장된 `PromptProgram` AST예요. 사람은 블록 편집기로, 에이전트(도우미)는 초안 도구로 같은 AST를 고쳐요.
- TypeScript 제작 API(`core/prompt-authoring.ts`)는 처음 만들 때 한 번 AST를 생성하는 입력 경로예요. 생성 뒤 TS 원본을 원본으로 보지 않아요.
- 선택형 템플릿 문법(`core/prompt-language.ts`)은 실험 기능으로 표시하고 새 기능 반영 의무를 빼요. 제거는 하지 않아요.
- 코드 확인 결과: 도우미는 이미 `draft.create`(kind `content` · `prompt-preset`), `draft.patch`, `draft.save`를 갖고 있고, 공통 초안(`server/edit-drafts.ts`)은 `content` · `prompt-preset` · `prompt-workspace` 세 종류를 다뤄요. 새 도구 추가보다 결정 2의 실사용에서 실제 모델이 이 도구로 프롬프트를 고치는지 확인하는 것이 남은 일이에요.
- 관련 계약: [PROMPT-AUTHORING.md](PROMPT-AUTHORING.md), [PROMPT-RUNTIME.md](PROMPT-RUNTIME.md).

### 5. 확장성은 선언형으로 확정하고 런타임 코드 실행은 미지원이에요

- 패키지 behavior·PromptProgram AST·정규식 transforms·앱 밖 에이전트 이식이 확장 수단이에요. Lua·임의 JavaScript·플러그인 로더·MCP 클라이언트는 미지원으로 고정해요.
- 재검토 조건: 2026-09-10 사용자가 지정한 **Merry Sisters! - Final.charx 한 개**를 [RISU-PORTING.md](RISU-PORTING.md) 절차로 **정적 검토**해 미지원 동작 보고를 만들어요. 표현 불가능한 동작이 있으면 그때 확장성을 다시 논의해요. 이 검토는 다른 작업과 독립이라 먼저 해도 돼요.
- 외부 도구 연결이 필요해지면 본문 모델이 아니라 도우미 한정으로 검토해요.

### 6. 구조 정리는 4건을 두 단계로 해요

설계 지도에서 짚은 7건 중 4건을 채택해요.

| 단계 | 항목 | 이유 |
| --- | --- | --- |
| 지금 | 값 import 순환 제거(`product-store` ↔ `story-archive`·`helper-archive`·`package-start`, `main-request` ↔ `prompt-snapshot`, `transport` → `vertex` → `vertex-auth` → `transport`) | 검증·키 함수를 core 또는 별도 모듈로 빼는 기계적 작업 |
| 지금 | 옵션 소속 규칙 통합(`freezeCurrentPrompts`와 `optionBinding`의 owner+hash 계산을 한 함수로) | 한쪽만 바뀌면 모든 예약이 충돌로 막혀요 |
| 결정 1과 함께 | 모델 역할 통일(`ModelRole` + 단일 해석 함수) | 고정 층의 구현 자리 |
| 실검증 뒤 | 예약 고정 체인 통합(`store.ts` · `helper-runtime.ts` · `prompt-routes.ts` · `story-store.ts` · `package-start.ts`의 사본을 purpose 옵션 하나로) | 실검증에서 기억·도우미 경로를 고칠 때 한 번에 해요 |

구형 `Content`/`Resource`/`Settings` 정리, `MainInput`과 `PromptCompilation` 이중 표현 정리, `prompt_workspace` 행 분리는 계약 변경이 따라와 이번 범위가 아니에요.

### 7. 실검증 전에 채팅 본문 추출 형식과 기능을 먼저 만들어요

- 정식 배포 전 하위 호환을 요구하지 않는 원칙은 유지해요. 2026-09-10 사용자 확인으로 **Oracle 운영 서버에는 이미 v15가 배포됐어요.** 이번 작업은 배포나 초기화를 수행하지 않으며 이관은 만들지 않아요.
- 대신 채팅 하나의 **본문 기록만** 담는 작은 형식을 정의하고 추출·가져오기를 만들어요. 담는 것은 원문 텍스트·요청·최신 번역·사용자 메모·장착 자료 참조(ID)예요. Run·snapshot·상태·추첨·attempt는 담지 않아요.
- 가져오기는 새 채팅의 authored 이력으로 읽어요. 스키마가 바뀌어도 이 형식은 유지해 개발 단계의 DB 리셋에서 작품 본문을 살려요. 전체 archive(v15)는 그대로 스키마와 함께 바뀌어요.
- 순서: 이 기능을 먼저 만들고 형식을 확정한 뒤 결정 2의 실검증 작품을 시작해요. 그 작품의 DB는 그 시점부터 보존 대상이에요.

### 8. 계획 문서를 현재 계약과 이력으로 분리해요

- `project-plan/CURRENT.md`를 현재 유효한 계약·남은 범위만 담은 짧은 문서로 다시 쓰고, 시간순 기록은 `project-plan/history/`로 옮겨요.
- 계약에 영향 있는 모순 셋은 기존 관례대로 머리말 정정을 붙여요. REDESIGN.md 본문의 "채팅 설정에서 모델·프롬프트 선택", CURRENT.md M3 행의 삭제된 등록 보조, 문서마다 다른 schema 버전(v10·v12·v13·v15)이에요.
- 과거 결과 문서의 다른 어긋남(용어 변경 전 "연결과 모델", 본문 모델 칩 위치 변경, 선행 실패 목록)은 당시 기록으로 두어요.

## 실행 순서

1. 결정 3·8: 게이트 문구 변경과 문서 분리.

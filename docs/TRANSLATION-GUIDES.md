# 봇별 번역 지침

봇별 번역 지침은 작품 특유의 인물 말투, 호칭, 문체와 고유명사 표기를 일관되게 번역하도록 돕는 기능이에요. 공통 번역 원칙을 담는 번역 프리셋과 달리, 각 봇 자료에 귀속되어 작품별 고유 설정을 관리해요.

## 번역 지침 작성과 관리

### 설정 위치와 기본 편집
- **접근 경로**: **서재 → 자료 → 편집 → 번역 지침**에서 설정해요.
- **자유 지침**: 인물의 말투, 호칭, 문체 등을 자연스러운 문장으로 자유롭게 작성해요.
- **용어 표기 목록**: 원문 표기, 사용할 번역 표기, 선택적인 조건·설명을 행 단위로 관리해요.
- **초안 및 복구**: 기존 **변경사항 저장**, **편집 취소**, **직전 저장 되돌리기**와 기기별 미저장 입력 복구 기능을 그대로 지원해요. 입력 중인 표기 행은 비어 있어도 초안에 유지되지만, 저장할 때는 원문과 번역 표기가 모두 채워져 있어야 해요.
- **적용 대상**: 서재 자료의 종류나 분류와 무관하게 지침을 편집할 수 있지만, 실제 적용은 해당 자료를 **봇**으로 사용하는 채팅에서만 이루어져요. 페르소나나 모듈 역할로 장착한 자료의 지침은 합치지 않아요.
- **지침 해제**: 지침과 표기 목록을 모두 비우고 저장하면 명시적인 봇 지침을 모델에 전달하지 않으며, 지침이 없는 봇은 기존 기본 번역 경로를 사용해요.

### 참고 범위 선택
번역 실행 시 참고할 배경 문맥의 범위를 선택할 수 있어요.

- **관련 자료 포함 (기존 기본값)**: 봇 설명, 페르소나, 로어북과 이전 원문·번역을 기존 경로대로 함께 참고해요.
- **본문과 번역 지침만**: 배경 자료와 이야기 메모를 모두 제외하고, 선택한 프롬프트·번역 지침·표기 목록·현재 원문 전체만 모델에 전달해요. 배경 자료를 조회하는 도구 호출도 제외돼요.

### 표기 목록과 지침의 성격
- **권장 기준**: 표기 목록은 번역 모델에 제공하는 가이드라인이며, 정규식이나 강제 문자열 치환(search & replace)이 아니에요.
- **조건 명시**: `Rose → 로즈 / 인물 이름일 때만. 꽃은 장미.`처럼 상황별 조건을 덧붙일 수 있어요. 조사 결합, 어미 활용, 고유명사와 일반명사의 구분은 문맥에 맞춰 자연스럽게 번역돼요.
- **원문 맥락 존중**: 원문에서 의도적으로 비튼 말투, 극적인 사건, 화자의 심경 변화나 불확실한 묘사를 기계적인 기본 지침으로 덮어쓰지 않아요.
- **입력 번역과의 분리**: [전송 전 입력 번역](INPUT-TRANSLATION.md)은 사용자 입력창을 위한 별도 도구예요. 입력 번역 시에는 이 표기 목록의 관련 어휘만 참고하며 한국어 번역용 자유 지침은 적용하지 않아요.
- **범위 외 기능**: `edittrans`, 자동 용어 누적, 번역문 일괄 교정은 포함하지 않으며, 지침을 전달하더라도 외부 모델이 모든 항목을 100% 엄격하게 준수한다고 보장하지는 않아요.

## 적용 시점과 미리보기

### 적용 및 고정 규칙
- **작업 시점 스냅샷**: 새 번역 요청이 서버에 접수되는 순간, **현재 봇의 최신 지침**을 복사해 해당 번역 작업에 고정해요. 지침이 없다는 상태(`null`)도 함께 고정되므로, 번역이 대기 중이거나 실행되는 도중에 다른 창에서 지침을 수정해도 진행 중인 작업에 섞이지 않아요.
- **이후 생성 반영**: 저장된 새 지침은 이후 접수되는 새 번역과 명시적인 재번역 요청부터 반영돼요.
- **저장 자체의 영향**: 지침을 저장하더라도 이미 완료된 기존 번역이나 원문이 소급 변경되지 않으며 모델이 호출되지도 않아요. 저장된 완료 번역을 다시 열어보는 동작 역시 재번역을 유발하지 않아요.
- **기존 번역 갱신**: 이미 작성된 번역에 새 지침을 적용하려면 **현재 설정으로 새 번역**을 실행하세요. 실패한 판정만 다시 시도하는 작업은 보존된 번역 후보와 당시의 고정 지침을 그대로 사용해요.
- **텍스트 취급**: 번역용 메타데이터를 작문 프롬프트, 이야기 메모, 장기 기억에 자동으로 편입하지 않아요. `{{...}}`나 HTML 태그처럼 보이는 문자열도 지침 입력란에서는 일반 텍스트로 취급되며 CBS나 Lua로 실행되지 않아요.

### 지침 미리보기
- **편집기 미리보기**: 편집기 안의 **번역에 전달할 지침 미리보기**는 **현재 편집 중인 미저장 내용**을 즉시 보여줘요 (저장하지 않은 내용은 실제 번역 요청에 들어가지 않아요).
- **프롬프트 미리보기 API**: `POST /api/chats/:id/prompt-preview`의 translation 모드는 **현재 서버에 저장된 봇 지침과 번역 참고 범위**를 반영하며, 응답의 `translationGuide` 필드로도 지침 내용을 반환해요. 프리셋이 context 슬롯을 생략하면 그 지침은 실제 요청에서 호스트의 보충 컨텍스트로 전달되므로, compilation만 보고 누락으로 판단하지 않아요. 기존 provider 미리보기의 `mapping-only` 의미는 유지하며 전체 실행 도구 호출을 재현한다고 주장하지 않아요. main 모드에는 이 필드를 전달하지 않아요.

## 저장 구조와 자료 교환 규약

### 네이티브 카드 확장 위치
번역 지침은 별도의 DB 테이블이나 채팅 설정이 아니라, 봇 자료의 네이티브 카드 확장에 단일 원본으로 보관돼요.

```text
content.package.nativeRisu.card.extensions.uimori.translationGuide
```

카드가 비어 있는 독립 Risu 모듈을 봇으로 사용하는 경우에는 해당 모듈의 확장에 저장돼요. 이는 다른 장착 모듈의 지침을 합치는 기능이 아니며 빈 카드는 그대로 둬요.

```text
content.package.nativeRisu.module.extensions.uimori.translationGuide
```

### JSON 구조와 입력 한도
```json
{
  "instructions": "미라는 평소 담담하게 말한다. 원문에서 드러나는 말투 변화는 보존한다.",
  "terms": [
    { "source": "Mira", "target": "미라" },
    { "source": "Rose", "target": "로즈", "note": "인물 이름일 때만. 꽃은 장미." }
  ]
}
```

- **입력 크기 제한**:
  - 자유 지침(`instructions`): 최대 20,000자
  - 표기 목록(`terms`): 최대 500개
  - 원문/번역 표기(`source`, `target`): 각각 최대 300자
  - 조건·설명(`note`): 최대 2,000자
- 서버의 네이티브 자료 검증 경계에서 이 형식과 한도를 엄격히 검사하며, 한도를 초과한 내용을 조용히 자르거나 누락하지 않아요. 실제 요청의 전체 컨텍스트 제한은 기존 번역 실행 경로를 따라요.
- **자료 교환과 보존**: 카드 전체 JSON 편집과 GUI 편집은 같은 필드를 수정해요. 다른 Risu·Uimori 확장은 보존해요. 자료 복제, Uimori 개별 자료 백업, 채팅 백업 및 CHARX 내보내기/재가져오기 시 이 확장이 온전히 함께 옮겨져요. 단, 이는 Uimori 전용 확장이므로 외부 편집기나 원본 RisuAI가 이 지침을 해석하거나 확장을 보존한다고 보장하지는 않아요. Risu의 `translatorNote`를 별도의 2차 원본으로 생성하거나 자동으로 덧붙이지 않아요.

## 에이전트 및 구현 참고

### 도우미와 외부 에이전트 작업 계약
- **요청 처리**: 사용자로부터 '이 봇의 설명과 로어를 참고해 번역 지침 초안을 만들어줘' 또는 'Rose의 표기를 로즈로 지정해서 저장해줘' 같은 요청을 받으면 도우미가 직접 작업을 수행해요. 별도의 번역 에이전트·승인 모드·자동 작성 작업은 없어요.
- **초안과 저장 분리**: 검토나 초안 요청은 저장하지 않고 대화로 제안하며, 명시적인 작성·수정 요청은 기존 도우미의 자료 저장 동작을 사용해요.
- **도구 호출 순서**:
  1. `resource.read {kind:"content", id}`로 봇 개요, 현재 수정 번호, `source.translationGuidePath`를 확인해요.
  2. 반환된 경로로 기존 지침을 읽고 관련 로어를 필요한 만큼 검토한 뒤, 명시된 설정과 제안한 번역 선택을 명확히 구분해 설명해요.
  3. 기존 용어를 보존한 `{instructions, terms}` 객체를 생성하고, 해당 경로에 대한 `set` 변경으로 만들어요.
  4. `resource.patch`의 최신 `expectedRevision`과 함께 저장해요. 다른 확장은 유지하고 카드 전체를 다시 구성하지 않아요. 번역 규칙을 일반 이야기 메모로 저장하거나 테마 등 다른 자료형과 결합할 필요도 없어요.

### 서버 실행 파이프라인
- **지침 로드와 캡슐화**: `server/translation-guide.ts`가 채팅의 고정 소속 봇에서 현재 지침을 읽어요. `server/source-editing.ts`의 번역 접수 시 `job.input.translationGuide`에 봇 ID·자료 수정 번호·이름과 지침을 담고, `resolveJobPrompt`는 이 작은 메타데이터를 해당 번역용 snapshot에만 연결해요. 실행 도중 DB를 재조회해서 지침을 바꾸지 않아요. 모든 과거 자료 저장본이나 전체 프롬프트를 재현하는 새 이력 시스템은 없어요.
- **컨텍스트 주입**: `translationInput`은 `context.translationGuide`에 지침을 넣어요. 기존 context 슬롯과 누락 시의 호스트 보충 전달을 재사용하므로 기본 프롬프트, Hermēneía와 context 슬롯을 생략한 사용자 프리셋에서도 지침을 전달해요. 별도 glossary 슬롯에 같은 표기를 다시 넣지 않아요. 번역 원칙 설명은 기존 번역 역할의 참조 정책에 연결해요.
- **참고 범위 분리 (`contextMode`)**: 참고 범위는 전역 번역 정책의 `contextMode`로 저장하고 새 작업에 고정해요 (값이 없는 과거 정책·작업은 `full`로 해석). `source-only`에서는 CBS 평가 전에 배경 자료·카드 변수·이전 대화·메모를 제외한 번역용 입력을 만들므로, 배경 슬롯을 쓰는 프리셋도 제외한 자료를 다시 가져오지 않아요. 원문 ID·해시 등 결과 연결에 필요한 메타데이터는 유지해요. 선택한 프리셋 내용 자체나 저장된 원문·자료는 수정하지 않아요.

### 테스트 및 검증 명령어
```sh
npm run quality
npm test -- tests/translation-guides.test.ts tests/translation-prompt-delivery.test.ts tests/translation-continuity.test.ts tests/source-translation.test.ts
npm run build
npm run verify:translation-guides
```

- `tests/translation-guides.test.ts`: 저장·검증·되돌리기·자료 교환·요청 시점 고정·판정 복구·미리보기/작문 분리를 확인해요.
- `tests/translation-prompt-delivery.test.ts`: 일곱 프로바이더 프로토콜의 실제 직렬화 결과에서 두 참고 범위와 기본/Hermēneía/context 생략 프리셋의 지침·표기·원문이 누락되거나 중복되지 않고 CBS 문자도 그대로 남는지 확인해요. 별도 네이티브 CBS 사례는 배경 자료 제외와 프리셋 자체 기본값·조작값 유지를 확인해요. 로컬 프로바이더 대역을 사용하며 실제 유료 모델을 호출하지 않아요.
- `verify:translation-guides`: 데스크톱·모바일 너비의 실제 앱에서 편집·저장·JSON 편집·미저장 입력 복구·취소·표기 삭제·잘못된 입력 보존과 모든 자료의 편집 노출과 원본 종류 보존을 확인해요. 합성 전송·브라우저 검사는 실제 작품의 번역 품질이나 물리 기기 동작을 보증하지 않아요.

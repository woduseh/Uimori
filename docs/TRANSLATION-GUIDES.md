# 봇별 번역 지침

**서재 → 봇 → 편집 → 번역 지침**에서 말투·호칭·문체를 자유롭게 적고 원문 표기 / 사용할 표기 / 선택적인 조건·설명 목록을 관리해요. 기존 ‘변경사항 저장’, 편집 취소, 직전 저장 되돌리기와 이 기기의 미저장 입력 복구를 사용해요. 입력 중인 표기 행은 비어 있어도 편집·복구할 수 있지만, 저장할 때는 원문과 번역 표기가 모두 있어야 해요.

번역 프리셋은 공통 원칙을, 봇 지침은 작품별 선택을 맡아요. 같은 봇의 모든 채팅에서 사용하며 채팅별 예외·전역 지침·공유 지침 목록은 없어요. 지침을 설정하지 않은 봇은 기존 번역 경로를 그대로 사용해요. 지침과 표기를 모두 비우고 저장하면 명시적인 봇 지침을 전달하지 않아요.

## 의미와 적용 시점

- 봇 설명·페르소나·로어와 이전 원문·번역의 기존 참고 경로는 유지해요. 같은 내용을 번역 지침에 다시 옮겨 적을 필요는 없어요. 새 사실이나 말투를 추측해 지침에 자동 저장하지 않아요.
- 표기 목록은 번역 모델에 전달하는 기준이지 정규식이나 강제 문자열 치환이 아니에요. `Rose → 로즈 / 인물 이름일 때`처럼 조건을 적을 수 있어요. 조사·활용과 고유명사/일반명사 구분은 문맥에 맞게 번역해요. 원문에서 의도적으로 바뀐 말투와 실제 사건·화자·불확실성을 기본 지침으로 덮어쓰지 않아요.
- 새 번역 요청을 접수할 때 **현재 봇의 최신 지침**을 복사해 해당 작업에 고정해요. 지침이 없다는 사실도 `null`로 고정하므로, 대기·실행 중 다른 창에서 지침을 추가해도 그 작업에는 섞이지 않아요. 이후 새 번역·명시적인 재번역은 새 지침을 사용해요.
- 지침 저장 자체는 원문이나 기존 번역을 변경하거나 모델을 호출하지 않아요. 완료된 번역을 다시 보는 것도 재번역하지 않아요. 기존 번역에 새 지침을 적용하려면 ‘현재 설정으로 새 번역’을 사용해요. 실패한 판정만 재시도하는 작업은 보존된 번역 후보와 당시 지침을 사용해요.
- 번역용 메타데이터를 작문 프롬프트·이야기 메모·기억에 자동으로 편입하지 않아요. `{{...}}`, HTML처럼 보이는 내용도 지침 필드에서는 일반 텍스트이며 CBS/Lua로 실행하지 않아요.

`edittrans`, 자동 용어 누적, 번역문 일괄 교정은 이 기능에 포함하지 않아요. [전송 전 입력 번역](INPUT-TRANSLATION.md)은 별도의 입력창 도구이며, 여기의 관련 표기 목록만 참고하고 한국어 번역용 자유 지침은 적용하지 않아요. 지침을 전달해도 실제 모델이 모든 선택을 완벽히 따른다고 보장하지는 않아요.

## 저장과 자료 교환

단일 저장 위치는 봇 자료의 아래 네이티브 카드 확장이에요. 별도 DB 테이블·채팅 설정·투영 사본을 만들지 않아요.

```text
content.package.nativeRisu.card.extensions.uimori.translationGuide
```

```json
{
  "instructions": "미라는 평소 담담하게 말한다. 원문에서 드러나는 말투 변화는 보존한다.",
  "terms": [
    { "source": "Mira", "target": "미라" },
    { "source": "Rose", "target": "로즈", "note": "인물 이름일 때만. 꽃은 장미." }
  ]
}
```

카드가 비어 있는 독립 Risu 모듈을 봇으로 등록한 경우에는 그 봇의 `nativeRisu.module.extensions.uimori.translationGuide`를 사용하고 빈 카드는 그대로 둬요. 이는 다른 장착 모듈의 지침을 합치는 기능이 아니에요.

GUI와 카드 전체 JSON 편집은 같은 필드를 수정해요. 다른 Risu·Uimori 확장은 보존해요. 복제, Uimori 개별 자료/채팅 백업과 CHARX 내보내기·재가져오기는 이 확장을 함께 옮겨요. 이는 Uimori 전용 확장이며, RisuAI가 이 지침을 실행하거나 외부 편집기가 확장을 반드시 보존한다는 뜻은 아니에요. Risu의 `translatorNote`를 별도의 두 번째 저장 원본으로 만들거나 자동으로 덧붙이지 않아요.

서버의 네이티브 자료 검증 경계에서 지침 형식과 입력 한도를 확인해요. 자유 지침은 20,000자, 표기는 500개, 원문/번역 표기는 각각 300자, 조건·설명은 2,000자까지예요. 한도를 넘는 내용을 조용히 자르거나 덜 전달하지 않아요. 실제 요청의 전체 문맥 제한은 기존 번역 실행 경로를 따라요.

## 도우미와 외부 에이전트

도우미에게 ‘이 봇의 설명과 로어를 참고해 번역 지침 초안을 만들어줘’ 또는 ‘Rose의 표기를 로즈로 지정해서 저장해줘’라고 요청할 수 있어요. 별도의 번역 에이전트·승인 모드·자동 작성 작업은 없어요. 초안·검토 요청은 저장하지 않고, 명시적인 작성·수정 요청은 기존 도우미의 자료 저장 동작을 사용해요.

작업 시 `resource.read {kind:"content", id}`로 봇을 먼저 읽어요. 관련 로어를 필요한 만큼 확인하고, 명시된 설정과 제안한 번역 선택을 구분해 설명해요. 기존 용어를 보존하면서 위 확장 필드만 편집하고, `resource.save`의 최신 `expectedRevision`과 기존 콘텐츠 편집 모델을 사용해 저장해요. 다른 확장을 덮어쓰거나 번역 규칙을 일반 이야기 메모로 저장하지 않아요. 테마 등 다른 작업의 자료형과 결합할 필요도 없어요.

## 실행과 미리보기

`server/translation-guide.ts`가 채팅의 고정 소속 봇에서 현재 지침을 읽어요. `server/source-editing.ts`의 번역 접수 시 `job.input.translationGuide`에 봇 ID·자료 개정·이름과 지침을 담고, `resolveJobPrompt`는 이 작은 메타데이터를 해당 번역용 snapshot에만 연결해요. 실행 도중 DB를 재조회해서 지침을 바꾸지 않아요. 모든 과거 자료 개정이나 전체 프롬프트를 재현하는 새 이력 시스템은 없어요.

`translationInput`은 `context.translationGuide`에 지침을 넣어요. 기존 context 슬롯과 누락 시의 호스트 보충 전달을 재사용하므로 기본 프롬프트, Hermēneía와 context 슬롯을 생략한 사용자 프리셋에서도 지침을 전달해요. 별도 glossary 슬롯에 같은 표기를 다시 넣지 않아요. 번역 원칙 설명은 기존 번역 역할의 참조 정책에 연결해요.

편집기의 ‘번역에 전달할 지침 미리보기’는 **현재 편집 중인 내용**을 보여줘요. 저장하지 않은 내용은 번역 요청에 들어가지 않아요. `POST /api/chats/:id/prompt-preview`의 translation 모드는 **현재 저장된 봇 지침**을 사용하고 응답의 `translationGuide`로도 반환해요. 프리셋이 context 슬롯을 생략하면 그 지침은 실제 요청에서 호스트의 보충 문맥으로 전달되므로, compilation만 보고 누락으로 판단하지 않아요. 기존 provider 미리보기의 `mapping-only` 의미는 유지하며 전체 실행 도구 호출을 재현한다고 주장하지 않아요. main 모드에는 이 필드를 전달하지 않아요.

## 검증

```sh
npm run quality
npm test -- tests/translation-guides.test.ts tests/translation-prompt-delivery.test.ts tests/translation-continuity.test.ts tests/source-translation.test.ts
npm run build
npm run verify:translation-guides
```

`tests/translation-guides.test.ts`는 저장·검증·되돌리기·자료 교환·요청 시점 고정·판정 복구·미리보기/작문 분리를 확인해요. 기존 전송 검사는 다섯 프로토콜의 실제 직렬화 결과에서 기본/Hermēneía/context 생략 프리셋의 지침·표기·원문이 누락되거나 중복되지 않고 CBS 문자도 그대로 남는지 확인해요. 로컬 공급자 대역을 사용하며 실제 유료 모델을 호출하지 않아요.

`verify:translation-guides`는 데스크톱·모바일 너비의 실제 앱에서 편집·저장·JSON 편집·미저장 입력 복구·취소·표기 삭제·잘못된 입력 보존과 봇 한정 노출을 확인해요. 합성 전송·브라우저 검사는 실제 작품의 번역 품질이나 물리 기기 동작을 보증하지 않아요.

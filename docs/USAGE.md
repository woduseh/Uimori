# 사용 안내

Uimori는 봇과 대화를 만들고 긴 원고를 읽거나 이어 쓰는 개인 작업실이에요. 자료와 모델 설정은 공유하지만, 입력 중인 편집 내용은 각 기기에 남아요.

## 처음 시작하기

`npm ci` 후 `npm run dev`로 빌드하고 실행해요. 기본 주소는 `http://127.0.0.1:4310`, DB는 `.local/uimori.sqlite`예요. 현재 DB 형식은 [개인 작업실 v1](DATA-MIGRATIONS.md)이에요. 다른 버전 DB를 자동으로 덮어쓰거나 변환하지 않아요.

**서재 → 봇**에서 새 자료를 만들거나 Risu 카드를 가져와요. 자료 상세의 **편집**에서 내용을 바꾸고 **변경사항 저장**으로 저장해요. 봇을 선택해 **새 채팅**을 만들고, 필요한 경우 페르소나와 프리셋을 골라요. 본문 생성에는 역할에 사용할 모델이 필요하지만, 모델 없이 자료를 편집하거나 저장된 대화를 읽을 수 있어요.

**설정 → 프로바이더·모델**에서 API 기본 주소와 API 키를 직접 등록해요. **역할별 모델**에서 작문·번역·도우미 모델을 선택해요. 사용자 지정 API 주소에 대한 별도 승인 목록이나 키 변경 후 재시작은 필요하지 않아요. Codex는 [전용 실행기 로그인](CODEX.md)을 사용해요.

장면 요청은 입력창에서 보내요. 기본 전송 키는 Ctrl/Cmd+Enter예요. 원고의 **번역 보기**로 번역을 요청하고, 완료된 번역은 다시 모델을 호출하지 않고 볼 수 있어요. 본문 거절 감지는 기본적으로 꺼져 있어요. JEV를 사용하는 로어·이미지 선택이나 선택적인 거절 감지를 사용하려면 해당 키를 등록해요.

## 봇별 채팅과 폴더

왼쪽 탐색에서 봇과 그 채팅을 찾고 폴더로 정리해요. 채팅의 소속 봇은 고정이며 페르소나와 프롬프트 설정은 별도로 다룰 수 있어요. 서재 자료를 수정하면 연결된 채팅의 다음 요청부터 최신 내용을 사용해요. 이미 작성된 원문을 다시 생성하지 않아요.

## 원문과 번역 직접 수정

원문이나 완료된 번역을 직접 편집하고 저장할 수 있어요. 원문 수정은 그 텍스트에 의존하는 요약·로어 상태를 무효화할 수 있어요. 늦게 도착한 번역이 사용자가 저장한 새 본문을 덮어쓰지 않도록 현재 수정 번호를 확인해요.

완성된 답변을 다시 쓰거나 과거 장면에서 다른 전개를 시작할 때는 독립 채팅 사본을 사용해요. 원본과 이후 수정은 서로 분리돼요. 새 생성에는 현재 자료와 설정을 사용하며 과거 모든 모델 입력을 재현하지 않아요.

## 자료와 프롬프트 편집

봇·페르소나·모듈은 **기본 정보 / 첫 메시지 / 로어북 / 에셋 / 고급 설정 / 제작 정보**에서 편집해요. 프리셋은 구성·기본 옵션·변수·토글·정규식·협업으로 나눠요. 정확한 편집 범위는 [서재 안내](LIBRARY.md)를 참고해요.

**변경사항 저장**으로 현재 자료를 저장하고 **편집 취소**로 저장본을 다시 불러와요. 원문 JSON·정규식·트리거 입력도 일반 저장 시 함께 확인해요. `폼에 반영`은 GUI 편집을 계속하기 위한 선택 동작이며 필수 저장 단계가 아니에요. 잘못된 문법은 오류를 표시하고 입력을 유지해요.

이 기기의 최신 미저장 입력은 IndexedDB에 복구용으로 보관해요. 서버 초안이나 미저장 입력의 기기 간 동기화는 없어요. 보관 성공 상태가 표시된 입력만 복구를 기대할 수 있어요. 저장·취소하면 해당 복구 입력을 정리해요. 다른 창이나 도우미가 먼저 저장했다면 입력을 보존한 채 충돌을 알려줘요. 직전 저장본 한 번을 되돌릴 수 있어요. [저장 동작](EDITING.md)

## 도우미와 독립 가정 장면

채팅과 서재의 **도우미**는 본편과 별도 대화 이력을 사용해요. 역할별 모델에서 도우미 모델을 선택하고 자료 제작·수정·설명을 요청해요. 검토·추천을 요청한 경우에는 그 범위에서 답하고, 실제 수정을 요청한 경우에는 도구로 저장할 수 있어요.

도우미에는 별도 검토/편집 모드나 자연어 승인 문구 판정이 없어요. 현재 선택한 편집기가 없어도 자료를 찾고 수정할 수 있으며, 채팅 ID를 지정해 다른 채팅도 작업할 수 있어요. 사용자 편집기와 같은 자료 저장 서비스를 사용해요. 현재 선택은 편의를 위한 문맥이지 별도 권한 경계가 아니에요.

도우미의 설명이 중간에 끊겨도 이미 저장된 변경은 남아요. 끝난 변경을 자동으로 되풀이하지 않도록 저장 결과를 확인하고 남은 작업만 요청해요. 독립 가정 장면과 본편은 별개이며 본편에 자동으로 합치지 않아요.

## 이야기 기억과 문맥·메모

사용자 메모는 자동 요약과 구분해서 남겨요. 채팅 설정에서 카드 변수와 채팅 전용 로어를 편집하고, 기억·문맥 화면에서 요약을 확인하거나 다시 만들 수 있어요. 요약과 관련 로어는 실제 원문 및 메모와의 일치 여부를 확인해 사용해요.

완료된 실행의 전체 입력을 영구 보관하지 않아도 이어 쓰기에 필요한 데이터는 남겨요. Lua가 실제로 추가하거나 수정한 메시지는 변경분으로 보관하고, 로어 유지 상태는 현재 채팅의 작은 상태로 보관해요. 새로운 원문 수정이 있으면 오래된 Lua 변경이나 로어가 그 수정을 무조건 덮어쓰지 않아요.

## 계층형 구성과 집필

구성 화면의 주제·스토리·사건·회차·작은 사건은 작가의 계획이에요. 작성된 본문과 구분해요. 독립 복사에서는 사용자 작성 구성과 고정 조건을 옮기되 진행 중인 생성·예약 작업·과거 실행 영수증을 재실행하지 않아요. 복사된 구성의 실행 진행 상태는 다시 시작해요.

## 장면 삽화와 이미지

대표 이미지와 본문 이미지는 업로드 후 공통 처리 경계에서 WebP로 저장해요. 입력 한도는 파일당 64MiB이며 전체 픽셀·프레임 처리 상한도 있어요. 고품질 손실 압축이므로 픽셀 단위 무손실을 보장하지 않아요. 이미 WebP인 파일은 다시 손실 압축하지 않아요.

이미지 이름·설명을 수정하면 다음 JEV 이미지 선택에 반영돼요. Risu 스크립트의 기존 참조 이름과 이미지 바이트는 이름 편집으로 바꾸지 않아요. [삽화 생성](ILLUSTRATIONS.md)은 별도 모델 호출이며 저장한 이미지의 단순 이름 변경에는 모델을 호출하지 않아요.

## 본문 복사와 백업

원고의 **이 장면까지 새 채팅으로 복사**는 선택한 지점까지 독립 사본을 만들어요. 원문·완료된 번역·유효한 메모·변수·Lua 메시지 변경과 이미지, 사용자 작성 구성·고정 옵션·채팅 전용 로어를 이어가요. 자동 요약과 진행 중 작업은 복사하지 않아요. 복사 자체로 모델을 호출하지 않아요.

개별 [채팅 백업](CHAT-BACKUP.md)은 필요한 봇·페르소나·모듈·고정 프리셋과 이미지도 포함해요. 가져오기는 항상 새 자료와 채팅 ID를 만들고 묶음 내부의 참조를 연결해요. 같은 이름의 자료를 덮어쓰지 않아요. 개별 자료는 [개별 백업](NATIVE-TRANSFER.md), Risu 파일은 [Risu 내보내기](RISU-EXPORT.md)를 사용해요.

작업실 전체 복구에는 **설정 → 데이터 관리**의 SQLite 백업을 사용해요. **전체 DB에는 API 키와 이미지도 포함**되므로 비공개로 보관해요. 개별 자료·채팅 파일에는 키를 넣지 않아요. 구형 전체 JSON 아카이브의 DB 테이블 재생·복원은 제거했어요. 외부 Codex 실행기 로그인은 DB 백업 범위와 별개예요.

## 데이터와 접속

[개인 서버 설치](SELF-HOST.md)에서는 HTTPS 공개 주소와 접속 토큰을 설정해요. 앱 로그인은 시간 만료 없이 서버 재시작 후에도 유지되지만, 로그아웃·브라우저 쿠키 삭제·접속 토큰 변경으로 해제될 수 있어요. 접속 토큰은 작업실 로그인용이고 프로바이더 API 키는 외부 모델 호출용이에요.

schema 24에서 새 개인 작업실 DB로 옮기려면 [일회성 자료 복사 도구](DATA-MIGRATIONS.md)를 사용해요. 원본 DB와 백업은 그대로 보관하고 결과를 검토한 뒤 새 DB 경로로 전환해요. `reset:dev`는 개발 데이터 삭제용이며 유지할 자료를 옮기는 수단이 아니에요.

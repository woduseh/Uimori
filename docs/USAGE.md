# 사용 안내

Uimori는 봇과 대화를 만들고 긴 원고를 읽거나 이어 쓰는 개인 작업실이에요. 자료와 모델 설정은 공유하지만, 입력 중인 편집 내용은 각 기기에 남아요.

## 처음 시작하기

`npm ci` 후 `npm run dev`로 빌드하고 실행해요. 기본 주소는 `http://127.0.0.1:4310`, DB는 `.local/uimori.sqlite`예요. 현재 DB 형식은 [개인 작업실 v1](DATA-MIGRATIONS.md)이에요. 다른 버전 DB를 자동으로 덮어쓰거나 변환하지 않아요.

**서재 → 봇**에서 새 자료를 만들거나 Risu 카드를 가져와요. 자료 상세의 **편집**에서 내용을 바꾸고 **변경사항 저장**으로 저장해요. 봇을 선택해 **새 채팅**을 만들고, 필요한 경우 페르소나와 프리셋을 골라요. 본문 생성에는 역할에 사용할 모델이 필요하지만, 모델 없이 자료를 편집하거나 저장된 대화를 읽을 수 있어요.

새 채팅 작성 중 **전역 모델 설정**을 열었다가 닫거나 뒤로 돌아오면 작성하던 제목과 선택을 유지해요. 새 채팅 창을 닫은 뒤 다시 시작하면 새 초안으로 시작해요.

**설정 → 프로바이더와 모델**에서 API 기본 주소와 API 키를 직접 등록해요. **역할별 모델**에서 작문·번역·도우미 모델을 선택해요. 사용자 지정 API 주소에 대한 별도 승인 목록이나 키 변경 후 재시작은 필요하지 않아요. Codex는 [전용 실행기 로그인](CODEX.md)을 사용해요.

설정 목록의 **설정 검색**에서 항목 이름이나 관련 단어를 입력하면 해당 설정 화면으로 이동할 수 있어요. 예를 들어 `글자 크기`는 **일반 → 원고 읽기**, `알림`은 **일반 → 앱과 알림**, `백업`은 **데이터 관리 → 백업과 복원**을 찾아줘요. 화면을 오가더라도 저장하지 않은 설정 초안은 닫거나 명시적으로 버리기 전까지 유지돼요.

**일반**은 화면과 입력, 생성 기본값, 원고 읽기, 앱과 알림, 접속 세션 순서예요. 앱 설치 방법은 **앱과 알림 → 앱 설치 → 설치 안내**를 펼쳐 확인하고, 설치·알림 상태와 오류는 바로 확인할 수 있어요.

장면 요청은 입력창에서 보내요. 기본 전송 키는 Ctrl/Cmd+Enter예요. 원고의 번역 버튼은 상태에 따라 **번역 생성 / 번역 다시 시도 / 번역 보기**로 표시해요. 번역 생성과 재시도는 모델을 호출하고, 완료된 번역 보기는 다시 모델을 호출하지 않아요. 본문 거절 감지는 기본적으로 꺼져 있어요. JEV를 사용하는 로어·이미지 선택이나 선택적인 거절 감지를 사용하려면 해당 키를 등록해요.

입력창 더보기의 **참고 이미지 첨부**, 이미지 붙여넣기 또는 파일 끌어놓기로 PNG·JPEG·정지 WebP를 최대 8장 첨부해요. 썸네일을 눌러 확대하거나 개별 제거할 수 있고, 이미지만 보내는 것도 가능해요. 이미지 내용은 선택한 본문 모델이 직접 참고하며 별도 이미지 분석 호출은 추가하지 않아요. 이미지 입력이 확인된 미지원 모델은 안내하고, 직접 등록한 미확인 모델은 전송을 시도할 수 있어요. 입력 번역은 텍스트만 바꾸고 첨부는 유지해요.

이미지 초안은 이 기기·탭의 IndexedDB에 텍스트와 함께 복구용으로 보관해요. 서버 초안 동기화는 없으며 브라우저 저장 실패 안내가 있으면 새로고침 전에 입력과 파일을 보관해 주세요. 전송 수락이 불명확하면 초안을 남기고 **이전 요청 확인**을 사용해요. 저장된 요청의 첨부는 다시 요청·독립 채팅 복사·채팅 백업에도 남아요. 과거 이미지는 해당 사용자 메시지가 최종 컨텍스트에 포함될 때만 다시 전달하며, 요약으로 빠진 이미지의 세부를 모델이 계속 볼 수 있다고 보장하지 않아요.

입력창 더보기의 **다음 요청 미리보기**는 작성 중인 요청과 현재 저장된 모델·프롬프트·페르소나, 로어·요약 상태와 첫 입력의 로컬 토큰 추정을 보여줘요. 미리보기로 모델을 호출하거나 원고·요약·설정을 저장하지 않아요. 로어 선별·컨텍스트 압축이 필요하거나 Risu 스크립트가 요청을 바꾸면 실제 전송 내용은 달라질 수 있어요. 계산할 수 없는 값은 미확인으로 표시해요. 요청·설정이 바뀌면 자동으로 갱신하고, 조회 실패나 확인 도중 변경이 발생한 때만 **다시 확인**을 표시해요. [추정 범위](CONTEXT-LIMITS.md)

이미지가 있으면 이미지 수와 해상도 기반 추정 토큰을 따로 표시해요. 미리보기에는 이미지 바이트를 업로드하지 않으며, 이 값은 제공사의 실제 이미지 토큰·과금량이 아니에요.

장면 아래 **이번 생성**을 펼치면 마지막 본문 호출의 사용량·입력 한도와 생성 당시 선택한 모델·프롬프트·페르소나, 요약 포함 여부를 확인해요. 캐시 사용량과 전송 로어는 펼칠 때 조회해요. 오래된 장면에 없는 기록을 현재 설정으로 채우지 않으며, Codex의 누적 턴 사용량은 한 번의 입력 점유율과 구분해요. [생성 기록](EXECUTION.md)

전송 로어는 고정·자동 선택·이전 요청 포함·도구 조회와 전체·구간·요약·미확인 상태를 묶어서 보여줘요. 같은 제목이어도 출처가 다르면 구별하고, 각 제목을 펼쳐 기록과 자료의 ID를 확인할 수 있어요. **마지막 장면의 로어**에서도 같은 기록을 확인해요.

**작업 현황**의 완료 작업은 요청·상태·원고 열기를 먼저 보여줘요. **이번 생성**과 **실행과 실제 입력 확인**을 펼치면 사용량·컨텍스트·실행 상세를 확인할 수 있어요. 진행 중이거나 실패한 작업의 상태와 복구 동작은 바로 표시해요.

전체 스냅샷·입력·도구 기록은 실행 상세의 **실행 원본 기록**을 펼쳐 확인해요.

**설정 → 사용량**에서 선택한 기간에 호출이 없으면 합계와 한 줄 안내를 보여줘요. 호출은 있지만 비용이 0이거나 미확인인 경우에는 차트와 상세 기록을 유지해요. 제조사별 요금표를 앱에 내장하지 않으며, 실제 연결의 지원 카탈로그 단가 또는 사용자가 입력한 단가로만 추정해요. 유효한 단가가 없으면 비용 미확인으로 표시해요. 도우미에게 공식 가격 출처 확인과 저장된 모델의 단가 갱신을 요청할 수도 있어요. [단가와 사용량](USAGE-REPORT.md)

표시할 번역 없이 번역이 실패하거나 중단되면 번역 화면에서 원문 보존 안내와 **번역 다시 시도**를 보여줘요. 이 버튼은 현재 설정으로 번역을 다시 요청하며, **원문부터 읽기**로 저장된 본문을 바로 볼 수도 있어요. 이전에 완료된 번역이 있으면 계속 표시하고, 보존된 번역문의 판정만 다시 시도하는 동작은 기존 작업 상세에서 제공해요.

원문 생성 취소를 요청하면 처리 중 상태를 표시하고 같은 요청을 중복 전송하지 않아요. 실패하면 다시 취소할 수 있으며, 다른 채팅으로 이동한 뒤 도착한 취소 오류는 새 화면에 표시하지 않아요.

요청문은 새 입력·과거 요청 수정·구성 집필·채팅 가져오기 모두 본문과 같은 200만 자 저장 상한을 사용해요. 긴 입력을 조용히 자르지 않으며, 생성할 때는 선택한 모델의 컨텍스트와 출력 토큰 설정이 적용돼요.

## 읽기 설정

채팅의 **읽기 설정**과 **설정 → 일반 → 원고 읽기**는 같은 기기별 설정을 사용해요. 글꼴·크기·본문 폭, 기본 원문/번역 보기, 강조·행간·문단 간격을 조절하고 예문으로 확인해요. 채팅 네비게이터는 끌 수 있고 집중 읽기에서는 항상 숨겨요.

**응답 표시 방식**은 기본값인 **실시간 표시**와 **완료 후 한 번에 표시** 중에서 고를 수 있어요. 완료 후 표시는 본문이 검증·후처리를 거쳐 저장되거나 도우미의 전체 작업이 끝난 뒤 저장된 답변만 보여 줘요. 진행 상태·소요 시간·취소는 그대로 사용할 수 있고, 중단·실패한 응답은 **일부 응답 보기**를 열어 확인해요. 도우미가 이미 저장한 변경은 응답 실패 여부와 별도로 안내해요. 이 설정은 이 브라우저의 표시만 바꾸며, 생성·도구 실행·번역 방식은 바꾸지 않아요.

**대사 줄바꿈 / 생각 줄바꿈**은 해당 인용문 앞뒤를 독립 문단처럼 띄워요. 이미 문단이 나뉜 곳에는 여백을 중복하지 않고 저장된 원문·번역과 복사 내용도 변경하지 않아요. 인용부호에 지정한 스타일을 따르며 문장의 의미를 판정하는 기능은 아니에요. 봇이 만든 상태창·입력 컨트롤은 재구성하지 않아요.

## 테마와 색상

**설정 → 테마와 색상**에서 기본 외관과 화면 모드를 선택해요. **고급 테마 설정**을 펼치면 기본·시네마틱·편지지·스크랩북·클래식 프레임 레이아웃과 팔레트를 따로 고르고, **꾸미기**로 사본의 색상과 CSS/HTML을 편집할 수 있어요. 레이아웃·팔레트·본문 바깥 배경은 작업실 기본·현재 봇·현재 채팅에 각각 지정하고, 현재 채팅 → 현재 봇 → 작업실 기본 순서로 상속해요. 새 테마는 미리 적용한 뒤 저장하고 카드에서 선택해요. JSON 가져오기·내보내기로 사용자 테마를 옮길 수 있으며, 별도 팔레트 선택과 배경 이미지는 전체 DB 백업에 포함돼요.

화면이 깨지면 **Ctrl/Cmd + .** 또는 `?theme-safe=1`로 이 탭의 테마를 끄고 복구해요. 에이전트 제작 규약·HTML 슬롯·검증 방법은 [테마 제작](THEME-AUTHORING.md)을 참고해요. 테마는 본문·프롬프트·봇 변수를 바꾸지 않아요.

설정 → **일반 → 접속 세션**의 **접속 해제**는 현재 브라우저의 로그인 세션만 해제해요. 서버에서 진행 중인 생성은 계속돼요.

## 봇별 채팅과 폴더

봇 메뉴의 **이 봇으로 본문 가져오기**에서 본문 JSON 파일을 바로 선택해요. **채팅 백업 복원**은 공통 데이터 관리 화면으로 이동하며, 선택한 봇 대신 백업에 담긴 봇과 자료를 독립 사본으로 가져와요.

**설정 → 일반 → 화면과 입력 → 좌측 사이드바 폭**에서 데스크톱의 펼친 탐색을 **보통 / 넓게 / 매우 넓게**로 선택해요. 기본은 기존 폭이며, 선택은 이 브라우저에 저장돼요. 공간이 부족하면 본문 폭을 지키도록 줄어들고, 접힌 아이콘 레일과 모바일 탐색 폭은 그대로예요. 도우미를 함께 열 때도 선택한 폭을 기준으로 나란히 표시하거나 탐색을 자동으로 접어요.

왼쪽 탐색에서 봇과 그 채팅을 찾고 폴더로 정리해요. 채팅의 소속 봇은 고정이며 페르소나와 프롬프트 설정은 별도로 다룰 수 있어요. 서재 자료를 수정하면 연결된 채팅의 다음 요청부터 최신 내용을 사용해요. 이미 작성된 원문을 다시 생성하지 않아요.

봇·폴더·채팅의 보조 메뉴는 데스크톱에서 행에 마우스를 올리거나 키보드로 포커스할 때 나타나요. 열린 메뉴는 계속 표시하고, 작은 탐색 창과 터치 기기에서는 보조 메뉴를 항상 표시해요. 선택된 채팅은 배경과 제목 굵기로 구분해요.

폴더 설정을 편집하는 동안 다른 곳에서 저장본이 바뀌면 작성한 이름과 페르소나를 유지하고 충돌을 알려줘요. **현재 저장된 설정 보기**로 확인하고 **최신 설정 불러오기**를 선택할 수 있어요. 미저장 입력이 있으면 버리기 전에 확인하며, 최신 설정을 불러온 뒤 다시 저장할 수 있어요.

## 원문과 번역 직접 수정

원문이나 완료된 번역을 직접 편집하고 저장할 수 있어요. 원문 수정은 그 텍스트에 의존하는 요약·로어 상태를 무효화할 수 있어요. 늦게 도착한 번역이 사용자가 저장한 새 본문을 덮어쓰지 않도록 현재 수정 번호를 확인해요.

원문 편집기에서 구절을 선택해 **선택 구절 퇴고**를 열면 도우미 모델에 수정 방향을 요청할 수 있어요. 모델 호출 비용이 발생할 수 있으며, **제안 받기 → 원문과 제안 비교 → 초안에 반영 → 원문 저장**으로 확정해요. 초안이나 선택 구간이 바뀌면 다시 선택해서 요청해요. [선택 퇴고의 저장 경계](EDITING.md#선택-구절-퇴고)

원고나 과거 요청의 **다시 쓰기**에서 실제 생성에 보낼 요청을 확인하고 고친 뒤 **기존 응답 교체 / 새 채팅에서 다시 요청**을 골라요. 기존 응답 교체는 새 생성이 성공한 뒤 적용하고, 실패·취소하면 기존 응답을 유지해요. 사본은 원본과 이후 수정이 분리돼요. 문맥에 쓰일 과거 요청의 수정·제외는 별도로 관리하며, 다시 쓰기 창의 문구가 실제 재요청에 사용돼요. 새 생성에는 현재 자료와 설정을 사용하며 과거 모든 모델 입력을 재현하지 않아요.

## 자료와 프롬프트 편집

채팅별 자동 번역은 **채팅 설정 → 생성 설정 → 본문 번역**에서, 작업당 모델 호출 한도는 같은 화면의 **고급 실행 설정**에서 바꿔요. **변경 취소**는 저장하지 않은 자동 번역·호출 한도 입력을 버리고 저장본으로 되돌려요.

봇·페르소나·모듈은 **기본 정보 / 첫 메시지 / 로어북 / 에셋 / 고급 설정 / 제작 정보**에서 편집해요. 프리셋은 구성·기본 옵션·변수·토글·정규식·협업으로 나눠요. 정확한 편집 범위는 [서재 안내](LIBRARY.md)를 참고해요.

**변경사항 저장**으로 현재 자료를 저장하고 **편집 취소**로 저장본을 다시 불러와요. 원문 JSON·정규식·트리거 입력도 일반 저장 시 함께 확인해요. `폼에 반영`은 GUI 편집을 계속하기 위한 선택 동작이며 필수 저장 단계가 아니에요. 잘못된 문법은 오류를 표시하고 입력을 유지해요.

이 기기의 최신 미저장 입력은 IndexedDB에 복구용으로 보관해요. 서버 초안이나 미저장 입력의 기기 간 동기화는 없어요. 보관 성공 상태가 표시된 입력만 복구를 기대할 수 있어요. 저장·취소하면 해당 복구 입력을 정리해요. 다른 창이나 도우미가 먼저 저장했다면 입력을 보존한 채 충돌을 알려줘요. 직전 저장본 한 번을 되돌릴 수 있어요. [저장 동작](EDITING.md)

## 도우미와 과거 가정 장면

도우미의 말투 설정을 열면 패널 본문에서 모델과 말투를 조정하고 하단에서 저장해요. 새 작업은 내부 호출·시간 정책을 사용하며 대화별 호출 한도는 편집하지 않아요. 설정을 닫아도 대화의 읽기 위치와 미저장 요청·말투 초안은 유지돼요.

채팅과 서재의 **도우미**는 본편과 별도 대화 이력을 사용해요. 역할별 모델에서 도우미 모델을 선택하고 자료 제작·수정·설명을 요청해요. 검토·추천을 요청한 경우에는 그 범위에서 답하고, 실제 수정을 요청한 경우에는 도구로 저장할 수 있어요.

도우미에는 별도 검토/편집 모드나 자연어 승인 문구 판정이 없어요. 현재 선택한 편집기가 없어도 자료를 찾고 수정할 수 있으며, 채팅 ID를 지정해 다른 채팅도 작업할 수 있어요. 사용자 편집기와 같은 자료 저장 서비스를 사용해요. 현재 선택은 편의를 위한 컨텍스트이지 별도 권한 경계가 아니에요.

단순 조회는 봇·페르소나·모듈·채팅의 필요한 원문 구간을 검색해서 읽어요. 자료 이름을 모르면 내용에서 먼저 자료를 찾고, 필요한 필드와 구간만 읽을 수 있어요. 현재 채팅에 예약된 자료, 서재의 최신 원본, 이 기기의 미저장 입력은 출처를 구분해요. 목록·관계·사용량 집계에는 읽기 전용 SQL을 사용할 수 있어요. 자료의 작은 원문 수정, 모델·채팅 설정 조회와 변경, 작업 상태 확인·취소·재시도도 요청 범위에 맞춰 도구 설명을 찾아 실행해요. 수정에는 현재 수정 번호를 확인하고, 불확실한 작업은 자동으로 재시도하지 않아요. 화면의 **누적 입력**은 작업 중 모든 모델 호출의 합계예요. [도우미 도구와 조회 범위](HELPER-TOOLS.md)

현재 편집 중인 자료는 도우미가 자동으로 참고하며 별도 초안 새로고침 버튼은 없어요. 도우미 대화는 계속 이어가거나 **새 대화**로 시작해요. 새 대화 분기는 제공하지 않으며, 과거에 만든 분기 대화는 읽고 이어갈 수 있어요.

도우미의 설명이 중간에 끊겨도 이미 저장된 변경은 남아요. 끝난 변경을 자동으로 되풀이하지 않도록 저장 결과를 확인하고 남은 작업만 요청해요.

별도 가정 장면의 새 생성·AI 재작성·직접 편집은 종료했어요. 과거 가정 장면은 카드에서 수정 번호를 골라 원문과 당시 요청을 읽고 복사할 수 있어요. 이 기기에 남아 있는 과거 편집 초안도 확인·복사만 할 수 있으며 자동으로 삭제하지 않아요. 다른 전개를 쓰려면 원고의 **이 장면까지 새 채팅으로 복사**로 사본을 만든 뒤 일반 입력창에서 이어 써요. 복사만으로 본문을 생성하거나 과거 가정 장면을 본편에 합치지는 않아요.

## 이야기 기억과 컨텍스트·메모

**채팅 메뉴 → 원작 참고**에서 작품·판본·스포일러 범위와 추가 자료를 정하고 **집필 전에 원작 참고**를 켤 수 있어요. 기본은 꺼져 있으며 참고문 생성에 모델 호출과 비용이 추가될 수 있어요. 현재 이야기의 선택과 관계를 함께 참고하고 마지막 집필 참고문을 보여줘요. 입력·설정·모델이 같아 유효한 참고문은 재사용해요. 전용 미리보기·질문 실행은 종료했으며 원작이나 인물에 관한 질문은 기존 도우미에서 해요. 도우미는 같은 참고 설정과 메모를 읽을 수 있어요. [원작 참고](STORY-GUIDE.md)

계속 지켜야 할 조건이나 원작과 달라진 설정은 **메모·정정**에 남겨요. **Risu 작가 노트**는 Risu 프롬프트의 정해진 위치에 넣는 집필 지침이며, 사용자 메모·정정 및 실제 사건 기록과 구분해요. 사용자 메모는 자동 요약과 구분해서 남겨요. 채팅 설정에서 카드 변수와 채팅 전용 로어를 편집하고, 기억·컨텍스트 화면에서 요약을 확인하거나 다시 만들 수 있어요. 요약과 관련 로어는 실제 원문 및 메모와의 일치 여부를 확인해 사용해요.

완료된 실행의 전체 모델 입력은 영구 보관하지 않지만 이어 쓰기에 필요한 자료는 남겨요. Lua가 실제로 추가하거나 수정한 메시지는 변경분으로 보관해요. 로어는 현재 컨텍스트와 성공한 본문 실행에서 읽은 구간을 채팅별 최신 상태 한 개로 보관하고, 다음 요청에서 출처와 내용이 여전히 유효한지 확인해 사용해요. 원문을 새로 수정하면 오래된 Lua 변경이나 로어 상태가 수정본을 덮어쓰지 않도록 확인해요.

## 계층형 구성과 집필

채팅 메뉴 → **계층형 구성**에서 [구성·집필 작업실](OUTLINE.md)을 열어요. 필요한 수준만 선택해 독립 회차부터 시작하거나, 같은 도우미에게 선택한 구성의 상세화를 맡겨요. 집필 전에 요청과 멈출 지점을 조정하고, 작성한 원문 뒤로 이어 쓰거나 원문과 구성을 비교할 수 있어요.

독립 장면의 신규 예약 대기열은 제공하지 않아요. 새 계획은 구성에 저장하고 필요한 단위를 골라 집필해요. 구성 집필의 내부 접수·중복 방지와 진행 중 작업 확인은 유지해요.

구성은 작가의 계획이며 실제 본문과 구분해요. 원문 연결은 의도 달성 점수가 아니고, 점검도 내용을 자동 수정하지 않아요. 독립 복사에서는 사용자 작성 구성·유지 조건·관련 항목과 복사 범위 안의 원문 연결을 옮기되 진행 중인 생성·예약 작업·과거 실행 영수증을 재실행하지 않아요.

구성 의도도 요청문과 같은 200만 자 저장 상한을 사용하고, 선택한 구성을 집필에 접수할 때 원문을 조용히 줄이지 않아요. 실제 집필에서는 전체 프롬프트가 모델의 컨텍스트 안에 들어가는지 확인해요.

## 장면 삽화와 이미지

업로드한 대표 이미지와 본문 이미지는 WebP로 저장해요. 입력 한도는 파일당 64MiB이며 전체 픽셀·프레임 처리 상한도 있어요. 고품질 손실 압축이므로 픽셀 단위 무손실을 보장하지 않아요. 이미 WebP인 파일은 다시 손실 압축하지 않아요.

이미지 이름·설명을 수정하면 다음 이미지 자동 배치에 반영돼요. Risu 스크립트의 기존 참조 이름과 이미지 바이트는 이름 편집으로 바꾸지 않아요. [삽화 생성](ILLUSTRATIONS.md)은 별도 모델 호출이며 저장한 이미지의 단순 이름 변경에는 모델을 호출하지 않아요.

## 본문 복사와 백업

원고의 **이 장면까지 새 채팅으로 복사**는 선택한 지점까지 독립 사본을 만들어요. 원문·완료된 번역·유효한 메모·변수·Lua 메시지 변경과 이미지, 사용자 작성 구성·고정 옵션·채팅 전용 로어를 이어가요. 자동 요약과 진행 중 작업은 복사하지 않아요. 복사 자체로 모델을 호출하지 않아요.

개별 [채팅 백업](CHAT-BACKUP.md)은 필요한 봇·페르소나·모듈·고정 프리셋과 이미지도 포함해요. 가져오기는 항상 새 자료와 채팅 ID를 만들고 묶음 내부의 참조를 연결해요. 같은 이름의 자료를 덮어쓰지 않아요. 개별 자료는 [개별 백업](NATIVE-TRANSFER.md), Risu 파일은 [Risu 내보내기](RISU-EXPORT.md)를 사용해요.

**설정 → 데이터 관리 → 백업 파일 가져오기**에서 개별 자료·채팅 백업 파일을 함께 선택할 수 있어요. 파일 내용을 판별하고 포함된 자료·채팅 수를 확인한 뒤 **새 자료로 가져오기 / 새 채팅으로 가져오기**로 진행해요. 기존 자료와 채팅을 덮어쓰지 않아요. 전체 SQLite 백업을 선택하면 서버에서 복원하는 방법을 안내해요. Risu 카드·프리셋 파일은 서재의 기존 Risu 가져오기를 사용해요.

**설정 → 데이터 관리**에서 백업과 복원 방법과 **백업 파일 가져오기**를 확인해요. 전체 복원은 서버를 종료하고 백업 DB를 별도 경로에 놓은 뒤 `UIMORI_DB`로 지정해 다시 시작하는 작업이에요. 복원을 확인할 때까지 기존 DB를 보관해요. **전체 DB에는 API 키와 이미지도 포함**되므로 비공개로 보관해요. 개별 자료·채팅 파일에는 키를 넣지 않아요. 외부 Codex 실행기 로그인은 DB 백업 범위와 별개예요.

## 데이터와 접속

[개인 서버 설치](SELF-HOST.md)에서는 HTTPS 공개 주소와 접속 토큰을 설정해요. 앱 로그인은 시간 만료 없이 서버 재시작 후에도 유지되지만, 로그아웃·브라우저 쿠키 삭제·접속 토큰 변경으로 해제될 수 있어요. 접속 토큰은 작업실 로그인용이고 프로바이더 API 키는 외부 모델 호출용이에요.

DB 복원에는 [현재 데이터 형식](DATA-MIGRATIONS.md)을 사용해요. 구형 DB는 해당 형식을 지원했던 앱 버전과 함께 별도로 보관해요. `reset:dev`는 개발 데이터 삭제용이며 유지할 자료를 옮기는 수단이 아니에요.

## 봇별 번역 지침

**서재 → 봇 → 편집 → 번역 지침**에서 작품별 말투·호칭과 이름·용어 표기를 지정해요. 같은 봇의 모든 채팅에서 다음 번역·명시적인 재번역부터 사용하며, 지침 저장만으로 기존 번역이나 진행 중 작업을 바꾸지 않아요. 표기는 모델에 전달하는 기준이지 강제 문자열 치환이 아니에요. 자세한 저장·도우미·자료 교환 동작은 [번역 지침](TRANSLATION-GUIDES.md)을 참고해요.

## 입력 번역과 요청 복사

입력창 옆의 번역 버튼으로 초안을 원하는 언어로 옮기고, 같은 입력창에서 수정한 뒤 보내요. 전송 전 원문 보기·되돌리기를 제공하고 전송이 수락되면 최종 전송문만 기록에 남겨요. 저장된 요청은 수정 버튼 옆의 복사 버튼으로 전체를 복사할 수 있어요. 자세한 동작과 범위는 [입력 번역](INPUT-TRANSLATION.md)을 참고해 주세요.

## 앱 버전 확인

**설정 → 앱 정보**에서 서버가 실행하는 앱 버전과 빌드 식별자를 함께 확인해요. 앱 버전은 `package.json`에서 가져오며, DB 스키마와는 별개예요. 조회 실패 시 버전을 추측하지 않고 재시도할 수 있어요. 설치한 소스가 아니라 실제 서버의 응답을 표시하므로, 버전이 기대와 다르면 [업데이트 안내](UPDATES.md#manual-release-update)를 확인해요.

### 작업 알림 확인

저장 완료 같은 짧은 알림은 작업을 막지 않아요. 저장 충돌이나 접수 여부가 불확실한 요청은 저장·재전송을 선택했을 때 확인창에서 처리해요. 저장본 확인은 현재 입력을 유지하며, 요청 접수 확인은 이전 요청을 그대로 사용해 새 초안을 보내지 않아요. 복구용 입력을 이 기기에 보관하지 못한 경우에는 이동 확인창에도 경고해요. 시작 설정 저장이 끝나지 않은 채팅은 생성 버튼에서 설정 저장을 다시 시도할 수 있으며, 복구만으로 본문을 생성하지 않아요.

작업 알림에서 **확인** 또는 **모두 확인**을 누르면 해당 실행의 알림만 숨기고 작업 기록은 보존해요. 확인 기록은 서버에 저장해 다른 브라우저·기기의 활동 목록에도 반영하며, 기존 브라우저 기록도 병합해요. 브라우저에도 기록을 남겨 서버 연결이 끊긴 현재 화면에서 사용할 수 있어요. 같은 작업을 다시 실행해 새로 실패하면 새 알림이 나타나요. 확인 기록을 보관하거나 서버에 반영하지 못하면 알림 창에 안내해요. [활동과 알림](PWA.md#앱-내부-활동-모드)

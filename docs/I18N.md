# 화면 언어 (UI Language)

Uimori의 화면 인터페이스 언어 설정, 번역 적용 범위 및 다국어 지원에 관한 안내예요.

---

## 화면 언어 설정과 변경 방법

### 지원 언어와 설정 경로
**설정 → 일반 → 화면 언어**에서 원하는 언어를 선택해요. 앱 로그인 화면에서도 동일하게 언어를 변경할 수 있어요.

- **한국어** (기본값)
- **English** (영어)
- **日本語** (일본어)
- **简体中文** (중국어 간체)

### 저장 및 동작 방식
- **브라우저 로컬 저장**: 선택한 언어는 이 브라우저의 `localStorage` 키 `uimori:ui-language`에 저장돼요.
- **기본값 정책**: 첫 접속 시, 지원하지 않는 언어 값이 감지될 때, 또는 저장소 읽기에 실패한 경우에는 기본 언어인 한국어로 표시돼요. 브라우저 언어 설정을 임의로 자동 채택하지 않아 기존 사용 경험을 안정적으로 유지해요.
- **탭 간 동기화**: 같은 origin에서 열려 있는 다른 탭에도 언어 변경이 즉시 전달돼요.
- **저장소 접근 제한 시**: 브라우저 보안 설정 등으로 저장이 차단된 경우, 현재 열린 화면에는 즉시 적용하되 재접속 시 유지되지 않을 수 있음을 안내해요.
- **기기 간 분리**: 언어 설정은 각 기기 브라우저별 로컬 설정이며, 기기 간 동기화나 서버 DB 설정을 변경하지 않아요.

---

## 언어 적용 범위와 콘텐츠 보존

| 경계 구분 | 적용 내용 |
| --- | --- |
| **앱 인터페이스 UI** | 앱 소유 버튼, 메뉴, 제목, 안내문, 진행 상태, 오류 메시지, 접근성 레이블은 선택한 화면 언어로 표현돼요. |
| **원고 및 사용자 창작물** | 원고 본문, 저장된 번역, 사용자 지정 채팅 제목, 서재 자료, 로어북, 프롬프트, 카드 HTML/CSS, 스크립트 알림, 입력 초안은 작성된 내용 그대로 보존돼요 (테마 및 읽기 미리보기의 fixture도 유지). |
| **자료 기본 이름 및 식별자** | 새 자료 생성 시의 기본 이름, 사본 접미사, 내보내기 파일명, 다운로드 텍스트, 저장 JSON 형식은 기존 데이터 규격을 유지해요 (UI 번역으로 저장 데이터를 변경하지 않음). |
| **모델 입력과 프롬프트** | 모델 입력, 도구 설명, 도우미 페르소나 설명, 생성 언어 옵션 등은 화면 언어에 따라 변경되지 않아요. 단, 자동 채팅 제목은 생성 예약 시점의 화면 언어로 작성돼요. |
| **시스템 내부 식별자** | API 에러 코드, 역할명, 작업 상태, ID, 옵션 값, 읽기 representation, 멱등성 키 등은 고정 식별자로 유지되며 표시 문구로 상태를 판정하지 않아요. |

### 읽기 언어 및 입력 번역과의 독립성
- `uimori:reading-language`는 화면 언어 코드가 아니라 원고 화면의 `original | translation`(원문/번역) 기본 보기 모드예요. 장면별 개별 보기와 읽기 위치는 별도로 유지돼요.
- 입력 번역 기능(`uimori:input-translation-language`)은 기존 7개 지원 언어를 사용하며, 모델에 전달되는 언어 `code`/`name`은 변경되지 않아요.
- 본문 생성 언어는 프롬프트 옵션에 따라 결정되며, 기본 저장 번역은 항상 한국어예요. 영어 UI에서 표시되는 **Korean translation**은 이 기본 저장 번역을 의미해요.

### 언어 전환 시 상태 보호
- 화면 언어를 변경해도 React 컴포넌트 트리, 본문 편집기, 장면의 DOM identity key를 재생성하지 않아요.
- 작성 중인 입력 초안, 선택 영역, 스크롤 읽기 위치, 진행 중인 작업과 취소·재시도 상태를 유지해요.
- 언어를 바꿨다는 이유만으로 모델을 다시 호출하거나 데이터를 재전송하지 않아요.
- 저장 충돌 검토 대화상자가 열려 있을 때 언어를 전환하면 데이터 재조회나 초안 변경 없이 표시 텍스트만 현재 언어로 다시 계산해요.

## 다국어 핵심 용어 대조표

Uimori는 여러 언어 환경에서도 일관된 개념을 전달하기 위해 핵심 용어를 다음과 같이 대응하고 있어요.

| 한국어 | English | 日本語 | 简体中文 | 비고 |
| --- | --- | --- | --- | --- |
| **서재** | Library | ライブラリ | 资料库 | 자료 보관소 |
| **자료** | resource | 資料 | 资料 | 개별 에셋/봇 |
| **도우미** | assistant | アシスタント | 助手 | 보조 모델/채팅 |
| **로어** | lore | ロア | 设定 | 세계관 설정 |
| **페르소나** | persona | ペルソナ | 角色 | 화자 인물 설정 |
| **에셋** | asset | アセット | 资产 | 이미지 등 리소스 |
| **컨텍스트** | context | コンテキスト | 上下文 | 프롬프트 문맥 |
| **작업실** | workspace | ワークスペース | 工作室 | 앱 전체 환경 |
| **원문 (본문)** | Original | 原文 | 原文 | 창작 본문 |
| **원문 (코드)** | source | ソース | 源码 | JSON/정규식 등 |
| **저장 / 적용 / 전송** | Save / Apply / Send | 保存 / 適用 / 送信 | 保存 / 应用 / 发送 | 버튼 동작 구분 |

> [!NOTE]
> 중국어 간체에서는 계정 로그인 시 사용하는 접속 토큰(`令牌`)과 AI 모델의 컨텍스트 토큰(`token` 또는 `词元`)을 문맥에 따라 명확히 구분해 표시해요.

## 구현 참고

이 섹션은 다국어 메시지 포맷팅, API 에러 변환, 서비스 워커 연동 및 테스트 자동화 규약을 다루는 개발자/에이전트 계약이에요.

### 메시지 표현 및 ICU 포맷 규약
- `web/i18n.ts`와 `web/locales/`가 메시지 표현을 소유해요.
- 단일 런타임 의존성으로 `intl-messageformat`을 사용하여 ICU 변수, `plural`, `select`, 숫자, 날짜 문법을 지원해요 (별도의 복수형 파서를 구현하지 않으며 HTML 보간은 지원하지 않음). 상세 문법은 [공식 ICU 문법](https://formatjs.github.io/docs/core-concepts/icu-syntax/)을 따라요.
- **렌더링 구독**: 컴포넌트는 `useI18n()` 훅을 구독하고 `t(key, values)`를 통해 문장 전체를 표현해요. 모듈 초기화 시 번역 결과를 전역 상수로 캐싱하지 않아요.
- **오래 보관되는 메시지 descriptor**: 알림창이나 상태 토스트 등 오래 유지되는 안내에는 `message(key, values)` descriptor를 사용하고, 실제 렌더링 시점에 `translateMessage()`로 변환해요 (번역문 문자열 자체를 식별자로 사용하지 않음). 이 descriptor는 UI 상태 전용이며 서버나 모델 요청으로 전달되지 않아요.
- **오류 전달과 번역 시점**: `onError`로 상위 상태에 전달되는 오류도 원문이나 descriptor를 보존하고 실제 화면에 렌더링되는 시점에 번역해요. 오류 발생 후 언어를 변경해도 요청을 재전송하지 않고 번역 문구만 전환돼요.
- **중첩 참조**: 중첩된 앱 안내만 `messageRef()`로 명시해요. 사용자 제목이나 원고 텍스트는 원본 그대로 출력하며 재귀 번역을 수행하지 않아요.
- **레거시 호환**: 기존 검증 헬퍼는 `legacyMessage()`로 한국어 `Error.message`를 유지하고 표현 계약만 등록해요. `registerMessage()`는 기존 API 에러 원문과 다국어 표시를 연결해요.
- **대체 정책**: 번역이 누락된 항목은 한국어 메시지로 fallback돼요. 완전히 정의되지 않은 키는 키 이름을 그대로 표시하고 정적 검사에서 오류로 검출돼요.
- **숫자 및 날짜 포맷**: `formatNumber`와 `formatDate`는 선택된 UI locale을 따라요. 통화는 USD 기준을 유지하며 KST 사용량 집계, 백업 시간대, ISO 조회 범위 및 원본 수치는 변경하지 않아요. 한국어 사용량의 K/M 축약 표기는 유지돼요. 구버전 대기 요청처럼 유효한 시각이 없는 데이터는 날짜 표시를 생략하고 나머지 화면은 계속 사용할 수 있어요.

### API 오류 및 외부 경계 처리
- `ApiError.message`와 `code`는 고정 계약을 유지해요. 한국어 wire 오류의 호환 비교는 원문에서 먼저 수행하고, `displayMessage`와 등록된 표현을 통해 UI 레이어에서만 다국어로 번역해요.
- 모델 설정 바로가기, 읽기 위치 출처, 도우미 단계, 0초 판단은 표시 문구가 아닌 코드·상태·수치를 사용해요.
- 외부 프로바이더 진단 로그, 사용자 이름을 포함할 수 있는 서버 DELETE 충돌 사유, 알 수 없는 신규 가져오기 finding 등은 원문을 그대로 보존해요. 가져오기 finding의 기존 코드나 전체 문장 형식이 바뀌면 표시 매핑과 검증도 함께 갱신해야 해요.
- **서비스 워커 및 푸시 알림**: 서비스 워커는 UI locale을 `uimori-presentation` IndexedDB의 `settings/ui-language`에 저장하고 푸시 수신 시마다 읽어와요. 워커가 종료된 후에도 언어 선택을 복구하며, 저장소가 없거나 사용할 수 없으면 한국어를 기본으로 사용해요. 알림 대상, 사용자 채팅 제목, 태그, 서버 payload는 유지하며 원고 캐시, 자동 재전송, 강제 새로고침을 추가하지 않아요.
- **웹 앱 Manifest**: 언어별 정적 manifest 파일을 선택해 제공해요. 앱 ID, 이름, 시작 주소, scope(`/`)는 고정 유지돼요. OS 알림 권한창·설치 메뉴 언어, 이미 설치된 manifest 갱신 시점, 기존 워커의 새 버전 활성화 시점은 브라우저와 OS가 결정하며 기존 창을 강제로 다시 열지 않아요.

### 자동 채팅 제목 생성 규약
- 새 채팅 생성 시의 자동 제목은 생성 예약 시점의 앱 화면 표시 언어로 작성돼요.
- 모델에 전달되는 생성 프롬프트 지시문은 영어로 전송되며, 이전 버전에서 언어 정보 없이 예약된 기존 작업은 한국어로 제목을 작성해요.

### 검증 도구와 테스트 명령어

```sh
# 메시지 키, 인자, ICU 문법 및 4개 언어 누락 검사
npm run check:i18n

# JSX 텍스트 및 접근성 속성의 한국어 후보 검토
npm run check:i18n -- --candidates

# 단위 테스트 실행
npm test -- tests/i18n.test.ts tests/api-errors.test.ts

# 빌드 후 합성 fixture를 활용한 종합 검증
npm run verify:i18n
```

- `npm run check:i18n`: 빈 번역, 중복 키, ICU 문법 오류, 언어 간 변수 인자 불일치 등을 검사해요. `-- --candidates`로 JSX 텍스트, 접근성 속성, 템플릿, 모듈 상수의 한국어 후보와 동적 호출을 검토해요 (후보에는 모델 입력, 저장 기본값, 레거시 오류도 포함되므로 자동 일괄 치환은 금지돼요).
- `npm test -- tests/i18n.test.ts tests/api-errors.test.ts`: 언어 선택 우선순위, 저장 실패 대처, 누락 키 fallback, 보관 메시지의 언어 전환, 사용자 입력 보존 및 레거시 에러 호환성을 검증해요.
- `npm run verify:i18n`: 실제 선택/재접속, 본문 로딩 실패 및 재시도 시 초안·읽기 위치·저장 자료 보존, 4개 언어 모바일 뷰포트 레이아웃, 완료 알림 타이머 지속 여부, 서비스 워커 재시작 후 푸시 언어 복구 등을 브라우저 fixture와 스크린샷으로 검증해요 ([개발 검증](DEVELOPMENT.md) 참고). 번역은 문맥과 의미를 함께 검토해요.

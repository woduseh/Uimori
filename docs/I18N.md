# UI language

**설정 → 일반 → 화면 언어**에서 한국어·English·日本語·简体中文을 선택해요. 로그인 화면에서도 선택할 수 있어요. 선택은 이 브라우저의 `localStorage` 키 `uimori:ui-language`에 저장해요. 저장한 지원 언어가 우선이며, 첫 접속·미지원 값·읽기 실패는 한국어예요. 브라우저 언어를 자동 채택하지 않아 기존 한국어 사용 경험을 유지해요. 저장이 막히면 현재 화면에는 적용하고 재접속 시 유지되지 않을 수 있음을 표시해요. 같은 origin의 다른 탭에도 변경을 전달해요. 기기 간 동기화나 DB 설정 변경은 하지 않아요.

## Ownership

| 경계 | 처리 |
| --- | --- |
| 앱 소유 버튼·제목·설명·상태·오류 안내·접근성 이름 | UI 언어로 표현해요. |
| 원고·저장 번역·사용자 제목·자료·로어·프롬프트·카드 HTML/CSS·스크립트 알림·입력 초안 | 작성된 내용을 그대로 보존해요. 테마·읽기 미리보기의 원고 fixture도 그대로예요. |
| 신규 자료의 기본 이름·사본 접미사·파일명·다운로드 본문·저장 JSON | 기존 데이터 형식을 유지해요. UI 번역으로 저장 내용을 다시 작성하지 않아요. |
| 모델 입력·도구 설명·도우미 인물 설명·생성 언어 옵션 | UI 언어를 주입하지 않아요. |
| API 코드·역할·상태·ID·옵션 값·읽기 representation·멱등성 키 | 안정 식별자로 유지해요. 표시 문구로 작업 상태를 판정하지 않아요. |

`uimori:reading-language`는 언어 코드가 아니라 `original | translation` 기본 보기예요. 장면별 보기와 읽기 위치도 별도로 유지해요. 입력 번역 대상은 기존 `uimori:input-translation-language`의 7개 언어이고, 모델에 전달하는 `code/name`은 바뀌지 않아요. 생성 언어는 프롬프트 옵션이 결정하고, 기본 저장 번역은 계속 한국어예요. 영어 UI의 **Korean translation**은 이 저장 번역을 뜻해요.

언어 전환은 React root·편집기·장면의 key를 변경하지 않아요. 초안, 선택 범위, 읽기 위치, 진행 작업과 취소·재시도·알 수 없는 전송 결과의 소유권을 그대로 유지해요. 언어 변경만으로 모델 호출·저장·재전송하지 않아요.

저장 충돌의 저장본 검토는 데이터를 한 번 읽고 표시만 현재 언어로 다시 계산해요. 검토 중 언어를 바꿔도 재조회하거나 편집 초안·적용할 저장본 snapshot을 교체하지 않아요.

## Messages and formats

`web/i18n.ts`와 `web/locales/`가 표현을 소유해요. `intl-messageformat` 하나를 직접 의존성으로 사용해 ICU 변수·`plural`·`select`·숫자·날짜 문법을 지원해요. 문자열 치환이나 별도 복수형 파서를 만들지 않아요. [공식 ICU 문법](https://formatjs.github.io/docs/core-concepts/icu-syntax/)을 사용하며 HTML 보간은 하지 않아요.

- 렌더 시 `useI18n()`으로 구독하고 `t(key, values)`로 문장 전체를 표현해요. 모듈 초기화 시 번역 결과를 상수로 저장하지 않아요.
- 오래 보관하는 오류·완료 안내에는 `message(key, values)`를 써요. 문자열 상태와 기존 callback을 유지하는 내부 메시지 descriptor이며 `translateMessage()`에서 현재 언어로 표현해요. 번역 결과 자체를 식별자로 사용하지 않아요. 이 descriptor는 UI 상태 전용이고 원고·자료·설정·모델 입력에 저장하거나 보내지 않아요.
- 중첩 앱 안내만 `messageRef()`로 명시해요. 사용자 제목·이름·원고 인자는 그대로 출력하며 모든 인자를 재귀 번역하지 않아요. 기존 한국어 오류·공통 기본 label의 표시 호환을 위한 한국어 역조회도 사용자 콘텐츠에는 사용하지 않아요.
- 기존 검증 helper는 `legacyMessage()`로 한국어 `Error.message`를 유지하고 표현 계약만 등록해요. `registerMessage()`는 기존 API 오류 등의 원문과 표시를 연결해요. 일반 렌더링·경과 시간은 등록하지 않아요.
- 누락 locale은 한국어 메시지로 대체해요. 없는 키는 진단 가능한 키를 그대로 표시하며 정적 검사에서 실패해요. 빈 번역·중복 키·ICU 오류·언어 간 인자 불일치도 검사 실패예요.
- `formatNumber`·`formatDate`는 선택한 UI locale을 사용해요. 통화는 USD 그대로이고 KST 사용량 집계·백업 시간대·ISO 조회 범위와 원본 숫자는 바꾸지 않아요. 검색·저장용 식별자는 표시 포맷으로 만들지 않아요.

한국어 사용량의 기존 K/M 축약 표기는 유지해요. 구버전 대기 요청처럼 유효한 시각이 없는 데이터는 날짜 표시를 생략하고 나머지 화면은 계속 사용할 수 있어요.

원고의 `원문`(`Original`·`原文`·`原文`)과 편집기의 코드·JSON·토글 `원문`(`source`·`ソース`·`源码`), 저장(`Save`)·적용(`Apply`)·전송(`Send`), 실패·취소·중단·접수 미확인, 재시도와 새 생성은 언어별 문구에서도 구분해요. 핵심 용어는 `서재`(`Library`·`ライブラリ`·`资料库`), `자료`(`resource`·`資料`·`资料`), `도우미`(`assistant`·`アシスタント`·`助手`), `로어`(`lore`·`ロア`·`设定`), `페르소나`(`persona`·`ペルソナ`·`角色`), `에셋`(`asset`·`アセット`·`资产`), `컨텍스트`(`context`·`コンテキスト`·`上下文`), `작업실`(`workspace`·`ワークスペース`·`工作室`)을 기준으로 맞추고, 중국어 간체에서는 접속 토큰(`令牌`)과 모델·컨텍스트 토큰(`token`·`词元`)을 구분해요.

## Errors and outside the screen

`ApiError.message`와 `code`는 기존 계약을 유지해요. 한국어 wire 오류의 호환 비교는 원문에서 먼저 수행하고, `displayMessage`·등록된 표현을 통해 UI만 번역해요. 모델 설정 바로가기·읽기 위치 출처·도우미 단계·0초 판단은 코드·상태·수치를 사용해요. 외부 프로바이더 진단, 사용자 이름을 포함할 수 있는 서버 DELETE 충돌 설명, 알 수 없는 새 가져오기 finding은 원문을 보존해요. 가져오기 finding의 기존 코드·전체 문장 형식이 바뀌면 표시 매핑과 검증도 갱신해야 해요.

서비스 워커는 UI locale을 `uimori-presentation` IndexedDB의 `settings/ui-language`에 저장하고 푸시마다 읽어요. 워커 종료 후에도 선택을 복구해요. locale이 없거나 저장소를 쓸 수 없으면 한국어예요. 알림 대상·사용자 채팅 제목·태그·서버 payload는 유지해요. 원고 캐시·자동 재전송·강제 새로고침을 추가하지 않아요.

manifest는 언어별 정적 파일을 선택해요. 앱 ID·이름·시작 주소·scope는 유지해요. OS 알림 권한창·설치 메뉴 언어, 이미 설치된 manifest 갱신 시점, 기존 워커의 새 버전 활성화 시점은 브라우저·OS가 결정해요. 기존 창을 강제로 다시 열지 않아요.

## Verification

`npm run check:i18n`은 메시지 키·인자·ICU 문법·4개 locale 누락을 검사해요. `-- --candidates`로 JSX 텍스트·접근성 속성·template·모듈 상수의 한국어 후보와 동적 호출을 함께 검토해요. 후보에는 모델 입력·저장 기본값·legacy 오류·SW 자체 사전도 포함되어 자동으로 모두 바꾸면 안 돼요. 한국어 후보가 없거나 검사 오류가 없다는 사실은 실행 중 표현의 완전한 번역을 보증하지 않아요.

`npm test -- tests/i18n.test.ts tests/api-errors.test.ts`는 선택 우선순위·저장 실패·누락 fallback·보관 메시지의 언어 전환·동일 번역문 충돌·사용자 값 보존·legacy 오류를 확인해요. 빌드 후 `npm run verify:i18n`은 로컬 합성 fixture로 다음을 확인해요.

- 실제 선택·재접속, 본문 로딩→실패→재시도와 입력 초안·읽기 위치·저장 자료 보존
- 진행 중 요청과 frozen 모델 입력 보존, 원문·번역 편집 중 값·선택·DOM identity 보존
- 4개 언어 모바일 화면·접근성 이름과 긴 가상 번역
- 완료 알림의 언어 전환이 기존 표시 시간을 다시 시작하지 않는지 확인
- 열린 저장본 검토의 필드·상태·본문 표현이 재조회와 초안 변경 없이 전환되는지 확인
- manifest/읽기 언어 독립성, 워커 재시작 뒤 합성 푸시의 저장 언어 복구

스크린샷도 확인해요. 이 검증은 실제 모델 품질·모든 화면 조합·전체 보조기술·실물 휴대폰 푸시·OS 설치 수락을 입증하지 않아요. 번역은 문맥 대조와 자체 의미 검토이며 원어민 감수와 별개예요. 기존 [개발 검증](DEVELOPMENT.md)을 함께 사용해요.

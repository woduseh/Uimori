# 봇 중심 작업 공간과 공통 패키지 개편

2026-09-07 사용자와 논의해 확정한 후속 설계예요. 이전 이야기 중심 UI와 CBS 호환 우선 계획보다 이 결정을 우선해요. 구현 결과는 별도 결과 문서에서 실제 검증과 함께 기록해요.

## 사용자 결정

- 채팅은 생성한 봇에 영구 소속돼요. 진행 중 봇 교체는 제공하지 않아요.
- 봇 안에 단일 깊이 채팅 폴더를 제공해요. 포크는 원본 폴더를 상속하고, 사용자가 이동할 수 있어요. 폴더 삭제는 채팅을 미분류로 이동해요. 폴더 기본 페르소나는 새 채팅에만 적용해요.
- 프롬프트가 옵션 정의를 소유하고, 창작 프리셋은 특정 프롬프트 revision의 옵션 조합이에요. 여러 봇/채팅에서 재사용해요. 고정 창작 제어는 기존 자료 보존용으로 남기고 기본 화면에서 분리해요.
- 프롬프트 제작 방식은 선택형 템플릿 문법과 TypeScript 제작 API를 비교할 수 있도록 열어둬요. 어느 쪽이든 기존 typed prompt 실행기로 전달하는 데이터 AST를 만들어요. 기본 제작 방식은 아직 확정하지 않았어요. CBS 전체 호환은 목표가 아니며 AI가 변환하기 쉬운 명세와 오류/미리보기를 제공해요.
- 봇/페르소나/모듈은 공통 패키지 형식을 사용하고 장착 역할을 분리해요. 모듈은 인물이 없는 지침/옵션/표현 묶음일 수 있어요. 역할 변환 시 원본을 보존하고 역할별 지침의 의미를 자동으로 같다고 가정하지 않아요.
- 로어·이름/번역 표기·고정 설정은 패키지 내부에서 관리해요. 채팅 전용 설정은 그 채팅에 보관해요. 기존 독립 자료는 버리지 않고 이전 자료 영역에서 연결·이동할 수 있어요.
- 상태창과 정규식 표시 변환은 필요해요. Risu 트리거 호환은 제외해요. Lua/임의 JavaScript 런타임은 선행 조건이 아니며, 선언형 표현과 명시적 동작으로 필요한 기능을 우선 표현해요.
- 공급자별 옵션은 Uimori 연결·모델 관리에서 설정해요. 파일 가져오기로 키/외부 권한을 늘리지 않아요.

## 화면 흐름

왼쪽 탐색은 봇·페르소나·모듈·프롬프트·설정으로 줄여요. 봇을 열면 해당 봇의 폴더와 채팅만 표시하고, 봇 설정에서 설명·로어·지침·표현을 편집해요. 데스크톱은 목록과 본문을 연결하고 좁은 화면은 목록을 drawer로 제공해요. 기존 색상·타이포·읽기 도구는 유지해요.

채팅 설정에서는 고정 봇을 표시하고 페르소나·추가 모듈·프롬프트·창작 프리셋·모델을 선택해요. 자료의 관리상 기본 분류와 이번 채팅의 장착 역할은 별개예요. 저장된 과거 입력은 현재 패키지 편집으로 바꾸지 않아요.

## 데이터와 실행 경계

기존 Content ID/revision과 불변 versions 저장을 확장해 공통 package body를 보관해요. Chat 소속/폴더는 별도 테이블로 관리해 기존 원문/Run/상태 자료를 재작성하지 않아요. 기존 채팅은 저장된 bot attachment에서 소속을 복원하고 봇이 없던 채팅은 이전 채팅 그룹에 보존해요. 백업·포크는 소속과 패키지 revision을 함께 보존해요.

패키지 장착은 `{id, revision, role}`로 저장해요. 내부 로어와 role별 지침은 생성 snapshot에 고정하며, 모델이 읽을 수 있는 자료는 그 snapshot 범위로 한정해요. 표시 정규식은 격리된 실행 제한 안에서 원문/번역의 읽기 표현에만 적용하며 원문·hash·기억을 바꾸지 않아요. 실패하면 원문과 명시적 오류를 보여줘요.

문법은 텍스트/조건/치환을 typed AST로 변환해요. 사용자 입력과 치환 결과는 다시 파싱하지 않아요. role·이력·현재 입력·cache 블록 배치는 기존 검증을 유지해요. 새 기능은 공통 구조에 추가하며 Risu 출처 여부로 실행기를 분기하지 않아요.

TypeScript 제작 API는 신뢰한 제작 코드를 명시적으로 한 번 실행하여 AST를 만드는 후보예요. 요청 때 일반 TypeScript를 실행하는 런타임과 다르며, 업로드된 코드를 실행하지 않아요. 옵션에 따른 실행 시점 분기는 `when`/`choose`와 typed expression으로 표현해요. [비교와 예제](../docs/PROMPT-AUTHORING.md), [선택형 템플릿 문법](../docs/PROMPT-LANGUAGE.md)을 함께 제공해요.

## 가져오기 계약

Risu 파일은 원재료 추출 → 구조적 변환 → 미지원 동작 보고 → 필요 시 Agent 각색 → native 패키지 검증 순서예요. 조용한 누락/무조건 성공/모르는 구문의 모델 전송은 하지 않아요. 가져온 자료를 동일 출력·전체 CBS/Lua 호환으로 광고하지 않아요. 자료 원문을 외부 모델에 보내는 유료 변환은 별도 사용자 실행이며 이 구현 검증에는 합성 자료만 써요.

## 검증

1. 기존 DB migration과 archive roundtrip, 봇 고정·폴더 scope/CAS·삭제 이동·포크 상속.
2. 새 문법의 위치 오류·nesting/size·치환 비실행·AST roundtrip·실제 요청 role/순서.
3. 같은 패키지의 bot/persona/module 장착, 내부 lore 검색, source-time revision, 지침 전용 모듈.
4. 프롬프트별 저장 조합을 다른 채팅에서 적용하고 불일치 revision/제어를 거부.
5. 정규식 timeout/출력 상한/원문 불변, 상태창 텍스트 안전 처리.
6. fresh DB/port에서 데스크톱·390px 새 채팅/폴더/포크/패키지 편집/프롬프트 조합 동선과 기존 생성·번역·보관 회귀.

현재 유저 DB, 실제 외부 모델·유료 평가, 배포는 이 검증에 사용하지 않아요.

## 계층형 구성과 지정 단위 집필 (2026-09-09)

기준은 origin/main `bac766d`예요. 상위 의도부터 세부 사건까지 구성한 뒤 그 구성에 따라 본편을 집필하는 기능을 추가했어요. 수준은 요청한 대로 **전체 주제 → 메인 스토리 → 큰 사건 → 회차 → 작은 사건** 다섯 개이고 상위는 정확히 한 수준 위로만 붙어요. 모든 수준을 채울 의무는 없고, 구성을 만들지 않은 기존 즉흥 집필 흐름은 그대로예요.

구성은 **채팅의 한 분기 소유**예요(`outline_nodes` 한 표, v15에 없으면 열 때 추가하고 스키마 버전은 유지). 진행도는 저장하지 않고 연결한 기존 `scene_commands`가 실제 원문을 확정했는지에서 계산해요 — 계획이 있다는 것만으로 완료가 되지 않아요. 집필은 새 경로를 만들지 않고 기존 `POST /api/scene-commands/:id/run`을 그대로 쓰며, 예약 시점에 적용 구성을 `RunSnapshot.outline`으로 고정해요. 고정하는 것은 대상까지의 상위 사슬(`path`), 대상의 직계 하위(`children`), 이 Run 자신의 계보에 있는 이미 집필한 항목(`written`, 최대 40개)뿐이고 형제 회차의 계획은 들어가지 않아요. 전달은 `state`·`notes`와 같은 방식으로 `outline` slot 또는 현재 요청 바로 앞의 host context 메시지예요. 기본 프롬프트는 바꾸지 않았어요. `OUTLINE_CONTRACT`가 구성은 계획이며 이미 일어난 사건·인물의 기억·세계의 사실이 아니고, 상위에 적힌 결말·반전은 그 단위가 올 때까지 드러내지 않는다고 명시해요.

권한은 사용자 직접 편집(`POST /api/chats/:id/outline`)과 도우미 도구(`outline.read`·`outline.write`)로 나뉘어요. 모델은 사용자가 고정한 항목과 이미 집필한 항목을 바꾸지 못하고 어떤 항목과 충돌하는지 이름을 담아 거절하며, 고정 값 자체는 사용자만 바꿔요. `outline.write`는 원문을 쓸 경로가 없고 한 호출로 `ref`/`parentRef`로 트리 전체를 만들 수 있어서 도우미 기본 한도(총 24회·도우미 12회)를 늘리지 않았어요. 허가 판정은 기존 `directHelperGrants`를 그대로 쓰며 인용문·로어·모델 출력은 허가를 만들지 않아요. 삭제·포크·내보내기·복원·분기 삭제에 모두 등록했고, 과거 지점 포크는 계획을 복사하되 포크 계보 밖에서 확정된 회차의 연결을 끊어요.

의뢰자 확인으로 첫 버전 범위는 **채팅·분기 소속 구성**, **지정 단위 실행만**, **사용자 요청 시에만 계획 수정**으로 확정했어요. 서재 공유 구성 템플릿, 여러 회차 연속 집필, 자동 재계획은 이번 범위가 아니에요. 계약·결정 기록·비채택 대안은 [계층형 구성](../docs/OUTLINE.md), 사용법은 [USAGE](../docs/USAGE.md)를 봐요.

자체 검토에서 찾아 고친 결함 세 가지를 기록해요. 포크가 원본 채팅의 **모든 분기** 구성을 새 채팅의 한 분기로 복사했고(포크 지점이 속한 분기만 복사하도록 수정, 회귀 검사 추가), 구성 편집 폼이 중첩 컴포넌트 정의 때문에 한 글자 입력마다 textarea를 remount해 포커스를 잃었고(편집기를 모듈 스코프로 이동, 브라우저 검사를 `fill` 대신 한 글자씩 입력으로 변경), 고정(`fixed`)이 그 항목 아래에 하위를 계획하는 것까지 막았어요(고정의 범위를 항목 자신의 문구·존재로 좁힘).

로컬 검증(이 Mac, Node 24.14.0으로 verify·Node 26.8.1로 vitest): `npm run quality:full`은 **1,610 PASS / 24 FAIL / 선택 1 skip**, tooling **27 PASS**, 서식·lint·타입·빌드 PASS예요. 이후 즉흥 집필 경로 검사를 1개 더 추가한 전체 Vitest는 **1,611 PASS / 24 FAIL / 선택 1 skip**이에요. 실패 3개 파일(`harness` 22, `server` 1, `context-lore-integration` 1)은 같은 커밋의 **깨끗한 worktree `bac766d`에서도 동일하게 실패**했어요(baseline 25 FAIL). 새 회귀는 없으며 실패를 PASS로 바꾸지 않아요. 새 검사는 `tests/outline.test.ts` **17개**예요.

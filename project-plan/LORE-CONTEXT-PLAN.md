# 로어 배치와 턴 사이 유지 작업 계획

2026-09-07 사용자 승인 범위는 앞선 공통 자료 구현 위에서 로어의 포함·배치·유지를 구현하고 로컬 검증까지 끝내는 것이에요. 기존 미커밋 변경과 별도 공급자 작업을 보존해요. 새 유료 요청·Risu 원본 변환·병합·DB 초기화는 포함하지 않아요.

## 구현 순서

1. 공통 로어에 배경/장면 배치, 배치 묶음, 묶음 안 순서를 추가해요. 고정/자동 포함 방식과 구분하고 폴더는 계속 편집용 분류로 유지해요. 고정 자료는 한 번 수집해 provenance를 붙이고, 실제 slot에서 제공한 자료를 host context에서 다시 넣지 않아요. 사용자 PromptProgram의 role·순서·cache anchor를 자동 재작성하지 않아요.
2. 완료된 source ancestry의 성공한 `knowledge.read`만 검증해 읽은 UTF-16 구간을 다음 Run에 고정해요. 검색 metadata·읽지 않은 전체 본문·실패/취소/다른 분기·보조 역할의 읽기는 유지하지 않아요. 이전 opaque continuation과 도구 호출을 새 Run에 재생하지 않아요.
3. 유지된 구간은 처음 읽은 이력 위치에서 안정적으로 표시하고, 새 구간은 추가해요. 같은 구간·겹친 구간은 중복을 줄여요. 최근 사용 정보는 정리 판단에만 사용하며 매 턴 자료 본문을 바꾸지 않아요. 문맥 예산을 넘으면 오래 사용하지 않은 자료부터 정리하고 그 결과를 기록해요. 단순 토큰화 추정 대신 현재 엔진과 같은 UTF-16 문자 수·항목 수 한도를 명시해요.
4. 고정 자료 예산 초과는 명시 오류로 알려요. 조회 자료는 다음 생성에서 ‘새 장면 · 조회 로어 정리’를 선택하거나 예산이 찼을 때 정리해요. 장면을 판별하는 별도 모델 호출은 추가하지 않아요. 자료의 scope/revision/hash, 원문 ancestry/hash, retcon을 매 새 Run에서 확인해 stale 자료가 캐시를 이유로 살아남지 않게 해요.
5. 변동 host context는 최신 입력 근처로 옮기고, 기본 프롬프트의 변동 memory도 같은 경계에 배치해요. 사용자 프롬프트가 명시한 순서는 유지해요. 유지 자료의 이력 배치는 고정된 자료 메시지이며 원래 대화나 실제 도구 이력인 것처럼 위장하지 않아요.
6. 제작 UI·채팅 정책·다음 생성의 정리 선택·미리보기·실행 진단을 연결해요. archive/fork는 출처를 재검증하고 원본 채팅이 없는 독립 포크도 보관할 수 있게 해요. 과거 Run은 현재 자료/retcon에 맞춰 수정하지 않아요.

## 검증 계약

- 고정/자동 포함·배경/장면 순서·그룹·옵션 제외·고정 예산 초과·중복 제거를 합성 검사해요.
- 실제 읽은 범위만 유지, 동일/겹친 구간 추가, 예산 정리, 장면 reset, 미리보기 무상태, 원문 수정·retcon·package revision·persona 제외·실패·분기와 응답 유실의 계약을 확인해요.
- archive 위조는 rollback하고, 정상 독립 포크를 복원해요.
- 기본 및 사용자 프롬프트를 실제 provider encoder에 넣어 system/tools/messages의 공통 prefix를 비교해요. 동일 Run의 도구 호출·결과 쌍과 opaque binding을 그대로 검증해요.
- 타입·빌드, 관련/전체 단위, 새 포트·합성 DB·격리 프로필의 브라우저 회귀와 390px 화면을 확인해요. 첫 실패를 보존해요.

실제 cached input 사용량·billing·모델의 lost-in-the-middle 완화/설정 준수율은 로컬 합성 PASS로 주장하지 않아요. 비교용 자료의 위치·선택 여부·입력 길이를 고정한 재현 가능한 증거를 만들어요.

## 전체 문맥 압축 작업과 조율

사용자 요청으로 `프로바이더 파라미터 지원 개편` 작업(`01a07c00-4a08-7b00-8e38-8c4f63f53f22`)과 2026-09-07 직접 논의했어요. 그 작업은 모델별 전체 입력 한도와 출처를 검증한 요약 checkpoint·최근 대화 구성, 요약 attempt/usage/취소를 담당해요. 이 작업은 로어의 현재 유효성·선택·문자 상한·읽은 구간·정리 결과를 담당해요.

합의한 경계는 전체 planner가 이쪽에서 제외한 로어를 ancestry 재검색으로 복원하지 않고, 원문과 과거 Run을 유지하며, 실행 중인 도구 쌍과 opaque prefix를 잘라 압축하지 않는 것이에요. 구체 계획 투영은 `자료·상태 고정 → 로어 선택 → 전체 문맥 계획 → PromptProgram 조립` 순서로 제안했어요. compiler는 전송 대상으로 확정한 메시지 집합 안에서 모든 이력을 포함하는 기존 검사를 유지해요. 전체 예산으로 로어를 더 정리할 때는 전달받은 entries에서 선택하고 그 결과를 새 Run에 고정해야 해요.

전체 요약 압축 본체는 별도 작업의 구현 범위예요. 이 브랜치의 로어 문자 상한을 모델 전체 입력 토큰 한도나 자동 요약 기능으로 표시하지 않아요. 구체 typed plan과 합친 실행 검증은 두 변경을 통합할 때 확인해요.

후속 교환에서 그쪽은 `RunSnapshot.contextPlan`의 pending/ready/failed, 전체 입력 추정치, 압축한 source/hash 목록, 최근 source ID 목록, summary·summaryCalls·usage를 제안했어요. `projectedLogicalHistory`가 summary와 최근 대화를 만들고, 그 뒤에 이쪽 `loreHistory`를 적용해요. 이쪽은 `context-summary` 또는 지정한 `carryAfterMessageId` 뒤에 원래 위치가 압축된 로어를 놓는 지원과 합성 검사를 추가했어요.

요약 입력에는 로어를 넣기 전의 실제 user/assistant 원문과 검증된 이전 summary만 사용해야 한다고 전달했어요. 조회 자료·고정 자료·검색 목록·도구 로그를 요약 안에 섞으면 삭제·개정한 로어가 summary에 남을 수 있기 때문이에요. 전체 planner가 더 줄인 로어는 현재 선택 후보에서 순서를 유지한 통째 항목 subset으로 고정하고, archive도 immediate parent의 유지 항목·성공 읽기에서 가능한 전이인지 검사해요. `o200k_base-v1`은 모든 공급자의 실제 tokenizer와 같지 않으므로 추정치 표시와 최종 wire의 system/tools/messages 포함, 실행 중 도구 문맥 초과 처리 필요성도 전달했어요.

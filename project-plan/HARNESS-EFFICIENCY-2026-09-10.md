# 하네스 효율과 도우미 도구 · 2026-09-10

사용자가 요청한 기억 외 하네스 성능·토큰 사용을 조사하고, 경량 모델부터 프론티어 모델까지 같은 도구 계약을 사용할 수 있도록 보완해요. 아래의 서버 합성 측정, 실제 모델 관찰, 미검증 범위를 구분해요. 기본 모델과 사용자 설정은 바꾸지 않아요.

## 서버 조회 비용

| 경로 | 이전 | 개선 | 범위 |
| --- | ---: | ---: | --- |
| 도우미 활성 문맥 조회 | 25.46ms | 2.19ms | 과거 checkpoint 100개·job 50개 합성 DB, 동일 모델 응답 |
| 서재 메타데이터 조회 | 35.75ms | 17.80ms | 자료 500개·프롬프트 100개, visible 450+90개, 동일 65,855B 응답 |

동일 DB에서 순서를 교대해 3회 예열 뒤 10회 조회 묶음을 9번 측정한 중앙값이에요. 초기 자료 생성과 JSON 응답 직렬화는 시간에서 제외했어요. 실제 서비스 지연이나 모델 응답 속도의 보장이 아니며 시간값을 테스트 통과 조건으로 삼지 않아요.

활성 문맥은 화면용 과거 이력 조회를 거치지 않고 현재 checkpoint만 읽어요. JS에서 해석한 checkpoint·job JSON은 합성 fixture 기준 5,499,254→754B예요. 서재는 최신·숨김 조건을 유지한 SQL 메타데이터 projection으로 바꾸어 JS에 옮겨 해석하던 전체 본문 540개·16,541,830B를 제거했어요. SQLite는 여전히 저장 JSON을 읽으므로 DB 본문 읽기 자체를 없앴다고 주장하지 않아요. 이 두 SQL 변경은 같은 모델 응답을 반환하므로 직접적인 모델 토큰 절감은 없어요.

증거는 `output/benchmarks/context-read-2026-09-10T12-54-41.362Z/context-read.json`과 `output/harness-payload-audit/2026-09-10T13-26-30.206Z/library-projection.json`에 있어요. 후자의 이전 경로는 기존 `all()+map()`을 재현하며 개선 경로는 구현한 `ProductStore.libraryMetadata()`를 실행해요.

같은 540개 항목에서 전체 목록은 25,220 o200k 토큰·65,855B, 고유 이름 검색 1건은 69토큰·194B, 첫 20개 페이지는 1,032토큰·2,890B예요. 각각 필요한 일부 항목만 찾는 경우의 99.7%·95.9% 감소이며 전체 페이지를 합산한 절감은 아니에요. 10개뿐인 서재에서 빈 검색으로 전부 읽으면 응답 봉투 때문에 463→513토큰으로 늘어요. 모델이 실제로 이 새 검색 도구를 선택하는지는 별도 미검증이에요.

실제 도우미 `context.read`에서 과거 요약 본문을 제외해 110,081→26,019자로 줄인 변경은 위 SQL 최적화보다 앞선 별도 변경이에요. 이때 도우미 작업은 16회 한도 소진에서 7회 완료로 바뀌었지만, 답변 정확도에는 한계가 남았어요. [실제 기억 평가](LIVE-MEMORY-RESULTS-2026-09-10.md)

## 도우미 계약 보완

- 읽기 실패의 `denied`·`errorKind`를 도우미 이벤트에 보존해요. 재시도 가능한 인자 오류와 출처·권한 실패를 구분하며, Anthropic의 도구 오류 표시에도 반영돼요. Vertex가 받는 기존 결과의 오류 코드는 유지해요.
- `notes.write`·`chat.lore`·`library.organize`의 필수 revision·selector·operation ID와 작업별 필드를 도구 정의에 설명해요. 서버의 권한·CAS 검사를 그대로 유지해요.
- `chat.lore` 조회에 서버가 계산한 필드 해시를 제공해요. 모델이 해시를 직접 계산하지 않고 발견한 selector·revision·hash로 채팅 전용 수정을 요청할 수 있어요. 공통 원본 자료는 바꾸지 않아요.
- `library.search`는 이름·ID·종류에 대한 메타데이터 검색과 페이지 조회를 제공해요. 찾은 ID의 본문은 `library.read`로 읽어요. 기존 전체 목록 응답은 유지해요.
- `options.read`와 선택 결과에는 프롬프트 전체 AST 대신 옵션 정의를 반환하고, pending 안에 중복된 delegation 객체를 제외해요. 현재 binding·revision·권한·고정값·위임·선택 영수증은 보존하며 UI 조회와 저장 데이터는 그대로예요.
- 자동 요약과 `context.write/new`는 중요한 주장에 간결한 `[scene 12]` 출처를 남기도록 안내해요. `story.list/search/read`와 `context.read/new`는 장면 번호와 동결된 ancestry의 범위를 함께 반환하고, `story.read({sceneNumber:12})`로 원문을 직접 읽어요. authored 시작문도 1번부터 세며 소설의 장 번호와 구분해요. 번호는 현재 분기의 조회 위치이고 실제 검증은 revision·hash·숨김 구간·문자 범위를 유지해요.

새 범용 실행 권한, 자동 권한 승격, 모델별 전용 우회 경로는 추가하지 않아요. 그 밖의 `workspace.settings` 조회 세분화는 별도 후보로 남겨요. 새 장면 번호 도구를 실제 모델이 선택하는지와 새 요약의 출처 정확도는 아래 합성 측정으로 보증하지 않으며, 61장 실모델 평가가 끝난 뒤 추가한 구현이에요.

## 가벼운 역할의 실제 모델 비교

Gemini 3.8 Flash와 Gemini 3.5 Flash-Lite에 동일한 제목 4개·번역 거절 판정 12개를 각각 보내요. 제목 요청 생성기와 거절 결과 parser는 제품 코드를 사용하고, 두 모델 모두 LOW 사고 설정이에요. 제목 출력은 제품과 같은 256 토큰, 거절 판정은 평가 전용 4,096 토큰 한도로 고정해요. 이 설정은 사용자 프리셋에 저장하지 않아요.

평가 파일은 `output/lightweight-harness-eval/`에 보존해요. 전송 전 durable 영수증과 독립 $5 예약 상한을 사용하며, 장편 $80·요약 A/B $10과 합쳐 사용자 $100 한도 아래로 제한해요. 사용자 제공 단가인 Flash $0.75/$3.75, Lite $0.30/$2.50(각 입력/출력 100만 토큰당)로 추정 비용을 계산하고 공급자 미보고 청구액은 null로 유지해요.

무과금 preflight는 입력·계약의 쌍별 일치, 32개 합성 응답과 부분 응답, 예산·출력·출처 경계를 확인했어요. 실제 요청 **32/32개를 완료**했고 다음은 각 항목을 한 번씩 실행한 관찰이에요.

Flash는 사과만 있는 문장을 거절로, 번역할 언어를 묻는 문장을 수락으로 판정했어요. 두 항목의 기대값은 정보 부족에 따른 `uncertain`이에요. 두 모델 모두 정상 번역·작중 인물의 거절·인용된 지침 공격을 포함한 나머지 항목은 맞혔어요. 제목에서는 Flash가 아직 기다리는 장면에 재회를 덧붙였고 Lite는 요청의 폭풍이 지나간 뒤를 폭풍 속으로 바꿨어요. 형식 통과를 의미 정확으로 세지 않았어요.

합산 추정 비용은 **$0.00643915**이고 공급자 청구액은 null이에요. 작은 표본이므로 Lite는 가벼운 역할의 후보라는 관찰까지만 가능해요. 도우미 전체의 추론·수정·창작 능력이나 모든 프론티어 모델의 호환성으로 일반화하지 않으며 기본 모델은 바꾸지 않았어요.

### 거절 판정 지침의 후속 비교

제품의 공통 지침에 사과나 확인 질문만 있고 번역·명시적 거절이 없는 경우 `uncertain`이며, 거절이 없다는 이유만으로 `accepted`로 판정하지 말라는 경계를 추가했어요. 원래 실패 2개와 대조 3개를 입력·기대값·생성 설정 그대로 두 모델에 한 번씩 보내 **10/10개 응답을 완료**했어요. `output/lightweight-refusal-followup/`에 이전 결과 참조·preflight·전송 영수증·원문 응답·비교를 보존해요.

| 선택한 5개 항목 | 이전 지침 | 보완 지침 | 입력 / 출력 토큰 | 보완 지침 추정 비용 |
| --- | ---: | ---: | ---: | ---: |
| Gemini 3.8 Flash | 3/5 정확 | 5/5 정확 | 995 / 375 | $0.0021525 |
| Gemini 3.5 Flash-Lite | 5/5 정확 | 4/5 정확 | 995 / 36 | $0.0003885 |

Flash의 사과·확인 질문 두 오류는 바로잡았지만 Lite는 원래 맞혔던 작중 인물의 거절 대사를 모델의 거절로 오인했어요. 이 모델 응답은 정상 JSON의 `refused`였으며 parser나 공급자 전송 오류가 아니에요. 공통 지침은 원하는 분류 경계를 명시하지만 **모델 전체의 품질 개선은 입증하지 못했어요.** 특정 예문이나 모델을 위한 우회 규칙은 추가하지 않았고 같은 표본을 반복 조정하지 않았어요.

이는 관찰한 실패를 보고 고른 후속 표본이며 독립 holdout·통계적 비교가 아니에요. 합산 추정 비용은 **$0.002541**, 전송 전 예약 상한은 $0.8310384이며 청구액은 null이에요. 실행 중 로컬 전체 단위 검사도 진행 중이었으므로 응답 지연으로 성능 우위를 주장하지 않아요. 최초 32개와 후속 10개 결과는 분리해서 해석해야 해요.

### 실제 평가의 합산 비용

장편·요약 A/B·최초 가벼운 역할·후속 거절 판정을 합치면 실제 전송은 **136회**이고, 보고된 사용량의 사용자 단가 추정 합계는 **$1.2611974**예요. 장편 EOF 2회의 미보고 사용량은 포함하지 않았으므로 전체 실제 비용이 아니에요. 청구액은 미확인이며 네 평가의 전송 전 누적 예약 상한 합계는 **$43.2801216**으로 사용자 $100 범위 안에 있어요. 원래 사용자 DB·프리셋·기본 모델은 수정하지 않았어요.

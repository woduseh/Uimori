# 2026-09-09 통합 감사 — 계층형 구성 서버

기준은 `09f34e8b1225571adc28f28705b8c2bbff4ce51b`, 환경은 Windows/Node v24.14.0이다. 원본 Store 회귀 **6 FAIL / 18 PASS**를 확보한 뒤 수정한 집중 검사는 **26 PASS / 0 FAIL**이다. 다른 도메인의 최종 전체 검사·브라우저 결과와 분리한다.

## 변경

- `server/outline-store.ts`에 전체 배치 멱등 영수증 `outline_batches`를 추가했다. 같은 키의 내용·분기·권한 재사용, 중복 ref를 거절하고 완료된 update/remove/create의 재확인은 새 쓰기를 만들지 않는다. 기존 revision CAS와 배치 원자성은 유지한다.
- 모델의 상위 이동은 고정·집필한 하위를 포함해 보호한다. 고정 항목 아래의 정상 하위 추가는 허용한다.
- 같은 scene-command 키는 연결한 구성에서 완료·진행 여부와 관계없이 재확인하며, 다른 구성 단위는 동일한 이름/의도라도 그 키를 공유하지 않는다.
- 영수증은 archive에서 보존하고 fork에는 복사하지 않는다. 삭제된 항목의 역사적 id는 허용하고 살아 있는 다른 채팅/분기의 참조는 거절한다. 채팅·분기 삭제에 영수증 정리를 등록했다.
- 현재 원문·포크·영수증 archive 왕복과 outline 추가 표가 없는 이전 v15의 실제 재열기를 검사했다. 운영 DB는 사용하지 않았다.
- `docs/OUTLINE.md`를 현재 고정 다섯 수준 계약에 맞춰 명확히 했다. 원하는 깊이까지 만들 수 있으나 회차에 필요한 상위 수준을 생략하는 기능은 추가하지 않았다.

## 남은 범위

P2 잔여: scene-command.request는 첫 단계 예약 시점, outline snapshot은 Run 예약 시점이므로 두 단계 사이 다른 탭·도우미/API가 계획을 편집하면 문구가 다를 수 있다. 현재 구성 패널은 미확인 요청이 있으면 새 변경을 막지만 외부 편집을 막지는 않는다. 자동 예약 취소·재작성 정책을 임의로 추가하지 않았다.

UI의 응답 유실·초안·reload 복구 및 E15의 context 전환 실제 전송은 각각 루트와 helper/context 담당의 결과를 참조한다. 실제 모델의 창작 품질/스포일러 준수, 유료 비용, 물리 IME·휴대폰, 운영 v15 전환·배포는 이 검사에서 검증하지 않았다.

## 구현

| 사용자 흐름 | 구현과 보존 경계 |
| --- | --- |
| 봇 → 채팅 → 폴더 | 채팅 소속 봇을 고정하고 한 단계 폴더, 이동, 폴더 기본 페르소나, 폴더 해제를 제공해요. 포크는 소속과 폴더를 상속해요. 과거 무봇 채팅은 이전 채팅으로 보존해요. |
| 공통 패키지 | 봇·페르소나·모듈에 본문, 내부 로어, 담당 작업별 지침, 옵션, 역할별 지침, 표시 변환을 함께 보관해요. 인물이 없는 지침 모듈과 역할 사본을 지원해요. 원본 사본·ID/revision·과거 Run은 분리해요. |

| 역할별 실행 | 패키지 지침을 main/translation/state/memory/status/image 담당 작업으로 나눠 기존 source-time snapshot과 자료 권한 안에 넣어요. 내부 로어는 상시 포함 또는 모델 자율 조회로 사용해요. |
| 읽기 표현 | 정규식은 격리 worker의 시간·출력 제한 안에서 읽기용 사본에 적용해요. 상태창은 해당 원문의 상태 결과에 키를 연결하고 미확인 값을 표시해요. 원문·번역 저장값과 hash는 유지해요. |
| 자료 가져오기 | JSON과 CHARX의 카드 JSON을 검사해 검토용 초안·차이 보고·Agent 전달 자료를 만들어요. blocking 항목이 있으면 UI 저장을 막아요. 바이너리 RISUP/RISUM은 구조화 추출 안내를 반환해요. |
| 저장과 복원 | schema/archive v6에 봇 소속·폴더를 추가해요. 공통 패키지와 전역 조합은 기존 불변 versions에 보관하고 archive roundtrip을 검증했어요. |

## 화면에서 확인한 내용

새 봇 `푸른 항구`와 내부 로어를 화면에서 작성하고, 봇이 고정된 `저녁 종소리` 채팅을 만들었어요. 정규식 표시에서는 `[note]`가 제거되지만 원문 편집창과 HTTP 조회에는 원래 태그가 남는 것을 확인했어요. 합성 실행만 사용했어요.

최종 빌드에서는 `항구의 일상` 폴더를 만들고 채팅을 이동한 뒤 포크했어요. 원본과 포크 모두 같은 폴더에 표시됐어요. [폴더·포크 화면](../output/redesign/screenshots/final-folder-fork.png)과 [QA 기록](../output/redesign/QA.md)을 남겼어요. 전체 브라우저의 패키지 편집·프롬프트 미리보기·390px/1440px 읽기 화면은 줄바꿈, 스크롤, 입력창과 버튼 접근을 직접 검토했어요.

## 남은 경계

- 실제 휴대폰·IME, 유료 공급자·문학/번역/장기기억 품질은 이번 검증 범위가 아니에요.
- Risu 전체 호환은 제공하지 않아요. 바이너리 RISUP/RISUM 직접 변환, CHARX 에셋 저장·첫 메시지 자동 삽입, CBS/Lua/트리거 실행은 미지원이에요. 지원하지 않는 동작은 변환 보고에 남겨요. 업로드 파일 선택기 자체는 별도 자동 UI 검사를 하지 않았고 HTTP 경로와 변환기를 검사했어요.
- 패키지의 `stateView`는 기존 상태 계산 결과의 표시 정의예요. 임의 HTML/CSS·스크립트를 실행하는 상태창이 아니에요. 같은 패키지를 두 역할로 장착하면 표시 변환도 부착 순서대로 두 번 실행돼요.
- Hidden Story가 사용하는 구간 경계를 보호하기 위해 해당 장면에서는 일반 패키지 정규식 표시를 생략하고 안내해요.
- TypeScript는 제작 시 AST를 생성하는 API예요. `compose`의 옵션은 runtime 값이 아닌 표현식 참조이며, 조건에는 `when`/`choose`를 사용해요. 이 후보를 기본 문법으로 확정하지 않았어요.

이 결과는 이번 개편의 로컬 구현·회귀 검사 완료를 뜻해요. 이전 M1/M2의 외부 인수·품질 조건은 [CURRENT](CURRENT.md)에 남아 있어요.

# Uimori 도우미·통합 문맥 관리 — 확정 계획 v3

> 2026-09-11 확장: 같은 채팅·전개의 다중 세션, 전체 동시 실행 2개, 세션 삭제와 다른 전개 보호는 [UI 개편 계약](../docs/UI-REDESIGN-2026-09-11.md)을 우선해요. 기존 모델·원문·도구 허가·불확실 요청 규칙은 유지해요.

작성일: 2026-09-09 · 상태: **텍스트·스트리밍 구현과 로컬 검증·인계 완료**. 최종 전체 브라우저의 간헐 닫기 실패와 수정 없는 재실행 통과를 포함한 실제 결과·제한은 [구현 결과](HELPER-CONTEXT-RESULTS.md)에 있어요. 전체 실행을 PASS로 바꾸지 않아요.

이 문서는 제품 방향 v4, 문맥 관리 제안, Fable의 계획 점검과 이후 사용자 결정을 통합한 구현·인계 기준이에요. 앞선 계획의 미결정 D1–D6를 다시 승인받거나 모든 이전 문서를 누적 적용하지 않아요. 현재 구현 사실은 [CURRENT](CURRENT.md)를 우선하고, 이번 변경의 목표·인수 범위는 이 문서를 사용해요. 문서 작성만으로 기능 구현·검증이 완료된 것은 아니에요.

## 2. 구현 시작 기준과 재사용 대상

정적 확인 기준은 `88fcba9`예요. 당시 가격/모델 관련 미커밋 작업이 있어 clean 상태를 전제하지 않아요. 구현자는 시작할 때 HEAD·작업 트리·CURRENT·관련 계약을 다시 확인하고 병행 변경을 보존해요. 과거 파일 줄번호와 테스트 개수를 현재 사실로 복사하지 않아요.

| 영역 | 재사용할 현재 기반과 주의점 |
| --- | --- |
| 실행 | `server/store.ts`, `server/model-runner.ts`, `core/transport.ts`: 서버 소유, durable attempt, 취소, source/hash, 한도, 도구 오류 교정. 하네스 전체를 교체하지 않아요. |

## 3. 실행·역할·공개 인터페이스

### 3.1 역할과 모델

- 기존 본문/번역/표시 상태/이미지의 `TaskRole`은 유지하고 `model-workspace`에 `helperModel`, `contextModel`을 추가해요. 기존 `titleModel`은 재사용해요. 설정 저장은 기존 workspace revision CAS를 사용해요.
- 공급자 실행·attempt 역할에 `helper`, `context`를 연결하고 추출용 `memory` 역할을 제거해요. 상태 job 내부 압축도 `context`예요. `PromptRole`은 작문/번역용 `main | translation`을 유지해요.
- 보조 job kind는 명시적인 `translation | status | image`예요. 새 모델 역할을 `Exclude<TaskRole, 'main'>` 같은 계산으로 보조 job에 섞지 않아요.
- `helperModel`이 없으면 도우미의 모델 실행을 안내와 함께 차단해요. `contextModel`이 없으면 **압축이 실제 필요한 시점**에 `MODEL_REQUIRED:context`로 실패해요. 요약 조회·직접 편집과 압축이 필요 없는 본문까지 막지 않아요. `titleModel` 미지정은 기존처럼 자동 제목 OFF예요.
- 새 프롬프트 슬롯 `notes`는 현재 유효한 사용자 메모·정정을 제공해요. `memory` 슬롯·추출 도구는 새 계약에서 제거하고 기본 프롬프트·제작 문법·역할별 도구·테스트를 함께 갱신해요. 기존 JSON을 재등록할 때 옛 슬롯이 있으면 정확한 위치를 알려주고 변환된 것처럼 저장하지 않아요.

### 3.2 작업과 도구

서버 작업 기록은 채팅이 없는 서재 작업도 수용해요. 도우미 대화와 작업, 메시지와 실행 이벤트, 산출물을 분리하고 SQLite·기존 worker/transport를 사용해요. 새 큐 서버나 범용 워크플로 엔진은 도입하지 않아요.

| 인터페이스 묶음 | 최소 동작 |
| --- | --- |
| `/api/helper/conversations` 및 대화별 messages/tasks/events | 대화 생성·페이지 조회, 메시지 접수, 작업 조회·취소, cursor 이후 이벤트 구독/재생 |
| `/api/chats/:id/context` 및 summary/compact/notes | 활성 요약 조회·편집·되돌리기, 수동 압축 예약, 메모·정정 조회·저장·퇴역 |
| `/api/edit-drafts` 및 초안별 validate/diff/save | 서버 초안 생성·조회·패치, 검증·변경 비교·공유 영향 확인·저장·폐기 |
| `/api/helper/artifacts` 및 개정 조회/수정 | 독립 장면 생성·조회·수정. 메시지는 산출물의 정확한 ID와 revision을 참조 |
| 기존 앱 서비스의 확장 | 제목·포크·폴더·자료 저장·채팅 전용 로어·옵션·위임 |

HTTP와 모델 도구는 같은 서비스를 호출해요. 수정 요청에는 고정 대상, 기대 revision, 요청 키를 받고 결과는 초안 반영/저장 완료/충돌/부분 완료를 구분해요. 복구 가능한 조회·인자 오류는 기존 교정 정책으로 반환하고 임의 SQL·파일·터미널·HTTP 실행 도구는 제공하지 않아요.

### 3.3 허가·멱등성·예산

- 첫 쓰기 도구부터 사용자 메시지/직접 UI 동작에 연결된 **1회 허가 기록**을 사용해요. 허용 대상·효과·공유 범위를 호스트가 고정·검사하고 자료/모델 출력은 이를 확장할 수 없어요. 모호한 대상만 확인해요.
- 지속 위임은 범위·허용 필드·시작·철회 이력을 보존해요. 명확한 직접 저장과 지속 위임을 같은 것으로 취급하지 않아요. 모델·외부 전송 범위를 기존 위임으로 임의 변경하지 않아요.
- 작업 request key와 각 변경의 안정적인 operation ID를 분리해요. 변경 트랜잭션에서 대상 revision 검사·효과 적용·결과 영수증을 함께 확정해요. 도구 호출 ID가 달라도 이미 확정한 operation은 기존 결과를 반환해요.
- 외부 호출에는 전송 전 attempt를 기록해요. 서버 중단 후 결과가 불확실하면 interrupted로 보존하고 자동 재전송하지 않아요. 취소 후 늦은 결과는 상태·owner·generation으로 막아요.
- 상위 작업 총 호출 한도와 목적별 호출 한도, 독립 산출물 생성 건수를 구분해요. 기본은 도우미 요청당 총 24회, 도우미 판단 최대 12회, 산출물 생성 작업 1건이에요. 작문 자식 실행은 현재 본문 `maxCalls`, 압축은 남은 전체 한도와 기존 조각 병합 제한을 따라요. 실제 전송마다 총한도에도 한 번만 합산하고 최종 응답 호출 여유를 남겨요. 이 값은 설정 가능한 초기값이며 품질 최적값으로 주장하지 않아요.
- `Usage`는 누적 측정값이에요. 사용량·잔여 예산·작업 건수를 혼용하지 않고 helper/writing/context/title 목적을 별도 기록해요. 공급자가 보고하지 않은 금액은 미확인으로 보존하고 병행 가격 추정 기능과 실제 비용을 구분해요.

## 4. 하나의 문맥 관리

### 4.1 저장과 활성화

자동 압축·수동 compact·사람/도우미 편집 모두 **Run 밖의 공통 context checkpoint ID와 불변 revision**을 사용해요. Run은 실제 사용한 ID·revision·hash를 snapshot에 고정해요. `run_id`만 가진 편집 테이블은 만들지 않아요.

- 체크포인트는 목적과 chat/branch 또는 helper conversation scope, 원문 ID/hash/viewHash와 순서, 이전 요약 revision, 사용자 정정 revision, 미압축 범위, 생성/편집 출처·attempt·usage를 보존해요.
- scope별 활성 참조에 CAS revision을 두어요. 자동 결과 적용 직전 기준 요약·정정 revision과 실제 읽은 원문 의존성을 다시 확인해요. 기준이 바뀌면 결과는 미적용 후보로 남기고 최신 편집을 밀어내지 않아요.
- 과거 Run과 archive 검증은 **그 실행이 사용한 요약 개정**을 확인해요. 현재 최신 요약을 다시 조회해 과거 증거를 판정하지 않아요.
- 입력은 유효한 활성 요약 + 그 이후의 모든 원문 + 현재 요청 + 필수 지침/설정 + 필요한 조회 결과로 구성해요. 임의 최근 N개 선택으로 중간 구간을 버리지 않아요. 프롬프트의 역할·배치·슬롯을 존중하고 요약을 두 번 주입하지 않아요.

### 4.2 압축·메모·검색

- 자동/수동 압축은 같은 서비스예요. 자동은 기존 85%/75%를 시작값으로 유지하고, 수동은 임계값 미만에서도 실행해요. 정리할 구간이 없으면 무과금 no-op으로 이유를 표시해요.
- 요약 조회·수정은 작은 편집 화면과 도우미 양쪽에서 제공해요. 저장은 실제 다음 입력에 반영하고 이전 개정으로 되돌릴 수 있어요. 실패·취소·빈/잘린 응답은 마지막 유효 결과를 바꾸지 않아요.
- 단순 요약 문장 편집은 요약 개정으로 보존해 후속 압축에 제공해요. 지속적인 설정 정정은 source anchor·사용자 요청·replacement 이력을 가진 `notes`에 한 번 저장하고 요약/검색에서 참조해요. 별도 작가 설정 관리자·잠금 시스템은 만들지 않아요.
- 세계 사실, 인물의 믿음, 과거 상태, 사용자 정정을 혼동하지 않도록 출처를 제공해요. 사용자 메모에 플레이한 원문 출처를 꾸며내지 않아요. 도우미 잡담이나 가정 장면을 본편의 사건으로 자동 저장하지 않아요.
- 원문 추가 자체는 일반 요약을 무효화하지 않아요. 단, 구간 유지 창으로 실제 `viewHash`가 달라지거나 압축한 원문/정정이 바뀌면 재판단해요. 입력 예산 변경과 의미 의존성 변경을 분리해요.
- 기본 검색은 기존 키워드·목록·범위 읽기를 사용하고 원문·유효 요약·메모·로어를 찾을 수 있게 해요. 허용 scope는 최종 반환 때도 검사해요. 사전 후보가 있더라도 추가 탐색을 막거나 매 턴 검색을 강제하지 않아요.

### 4.3 제거할 추출 경로

`StoryConfig.memory`, 추출 job/index/watermark, 추출 재시도·일괄 과거 색인·추출 설정 UI, `memory.search/read`와 추출 전용 타입을 제거해요. `memoryHash` 같은 공통 출처 함수는 적절한 source 모듈로 옮겨요. `canonHash`가 하던 의존성 검사는 새 사용자 메모·정정 revision/hash로 이어가요.

상태 계산과 authoritative 대기, 패키지 동작·추첨·장면 요청은 유지해요. 상태 job 내부 압축도 새 context 모델·영수증·예산 경로를 사용해요. 제거할 테스트 개수를 목표로 삼지 말고, 추출에만 속한 검사는 정리하며 출처·분기·누락 방지 검사는 새 문맥 경로에 옮겨요.

## 5. 공유 초안과 서재 작업

- 편집 세션은 재사용되지 않는 `draftId`와 루트 revision을 가져요. 신규 자료도 저장된 콘텐츠 ID 없이 초안을 만들 수 있어요. 폐기 후 새 초안은 새 ID이므로 과거 도우미 결과가 적용될 수 없어요.
- 루트 초안은 기준 자료 ID/revision/hash, 구조화된 편집 모델, 적용 전 원시 필드 텍스트, 검증 상태를 함께 보존해요. 개별 필드 테이블만으로 전체 초안의 원자적 저장을 대신하지 않아요.
- 입력은 로컬 버퍼에 즉시 보존하고 서버에는 묶어 동기화해요. 도우미 요청·저장 전에 최신 초안 동기화를 완료해요. 충돌·오프라인이면 오래된 DB 본문으로 요청을 대체하지 않아요.
- 도우미 변경은 읽었던 루트 revision에 CAS로 적용해요. 이후 사람이 수정했다면 덮어쓰지 않고 제안과 차이를 남겨요. 명확한 제작·수정·저장 요청은 최신 초안 검증과 기존 콘텐츠 CAS 저장을 완료한 뒤 영수증을 표시해요. 검토·제안·초안만 또는 저장 금지 요청은 그 범위를 지켜요.
- 공유 영향 조회는 직접/간접 모듈 연결과 역할, 영향받는 채팅, 다음 실행 적용 시점을 계산해요. 현재 프롬프트 작업본과 저장 프리셋의 편집 효과를 구분해요.
- 채팅 전용 로어는 선택한 attachment(패키지 ID·역할·필요한 모듈 연결 경로)와 lore ID/텍스트 필드에 귀속해요. 원본 package snapshot은 유지하고 **attachment별 override projection**을 별도로 고정해요. 동일 패키지를 여러 역할로 장착했을 때 하나의 변형 `profile.packages` 본문을 공유하지 않아요.
- 관련 원본 필드가 바뀌면 충돌을 알리고 마지막 유효한 로컬 변경과 기준을 보존해요. 무관한 원본 변경은 반영해요. 행동·상태 정의는 로어 텍스트 override 대상에서 제외해요.
- 저장 되돌리기는 이전 내용을 새 개정으로 저장하는 작업이에요. 그사이 사용자 편집이 있으면 충돌로 남겨요. 일괄 작업은 항목별 operation 영수증으로 부분 성공과 재시도를 처리해요.
- 초안은 백업/복원에 포함하고 포크에는 상속하지 않아요. 채팅 삭제 시 해당 초안·작업의 소유권과 진행 상태를 확인해 기존 삭제 서비스와 함께 처리해요.

## 6. 독립 가정 장면

새 생성 요청을 접수할 때 최신 완료 본편의 head와 source/hash, 현재 작문 프롬프트·옵션·모델, 봇·사용자 페르소나·자료, 유효 요약·메모·정정·미압축 원문을 고정해요. 생성 중 본편이 진행돼도 그 실행 입력은 바꾸지 않아요.

그 원문에 필요한 authoritative 상태가 미완료이면 고정된 원문·설정을 유지한 채 해당 상태를 기다려요. 대기는 취소·timeout을 지원하며, 상태 작업이 실패·취소·무효화되면 이유를 표시하고 중단해요. 이전 상태나 초기 상태로 대체하지 않고 가정 장면 때문에 본편 상태 재계산을 자동 예약하지 않아요.

공통 작문 snapshot 조립과 **문맥 준비/압축**을 산출물 작업에 적용해요. preview 결과만 보내거나 전체 이력을 예산 검사 없이 전달하지 않아요. 산출물 준비에서 생성한 요약·조회 기록은 해당 작업 소유이며 본편 활성 checkpoint를 갱신하지 않아요.

- 작문 프롬프트에는 가정 요청을 실제 current 입력으로 넣고 도우미 페르소나·관리 이력 전체를 넣지 않아요. 도우미는 완성 산출물을 임의로 다시 써서 전달하지 않아요.
- 읽기 도구는 허용해요. `behavior_*`와 본편 상태 변경 도구는 **요청 조립부터** 제외하고 패키지 상태는 읽기 snapshot으로만 제공해요. 기존 패키지 행동까지 실행한 결과라고 주장하지 않아요.
- `completeRunInTransaction`, 본편 후보 생성, 패키지 상태 초기화/commit을 호출하지 않아요. 본편 head·요약·상태·추첨·후속 요청은 그대로예요.
- 산출물은 `(artifactId, revision)`으로 저장하고 메시지/수정 요청은 정확한 개정을 참조해요. 수정은 원래 생성 맥락과 해당 산출물을 기준으로 새 개정을 만들어요. 최신 본편을 다시 반영하라는 요청은 새 산출물이에요.
- 별도 연속 외전 상태·요약·기억·본편 동기화·채팅 승격 기능은 이번에 만들지 않아요. 결과를 질문·복사·직접 편집할 수 있어요.

## 7. 패널·스트리밍·긴 작업

### 7.1 화면

도우미 패널은 App shell에서 관리하며 본편·서재 편집기를 열기/닫기 때문에 언마운트하지 않아요. 1100px 초과는 기존 옵션 패널과 같은 옆 공간, 그 이하는 오버레이로 제공해요. 일반 설정의 760px 목록/상세 전환까지 일괄 변경하지 않아요. 옵션과 도우미 보조 패널은 한 번에 하나만 열고 각 초안은 유지해요.

채팅·서재 헤더의 이름 있는 버튼과 응답 메뉴에서 진입해요. 첫 통합 뒤 문장 선택도 source/hash·block anchor·선택 범위로 연결해요. 현재 작업 대상은 짧게 표시하고 실행 중 화면 이동으로 바꾸지 않아요. 도우미 대화는 채팅별/서재 작업별로 보존하며 새 작업을 시작할 수 있어요. 작품 간 본문을 이전 대화에서 자동 재사용하지 않아요.

이력 인터셉터는 표면의 등록/해제와 최상단 소유권을 지원해 모바일 뒤로가기가 먼저 패널을 닫게 해요. 독서 위치·초점·두 입력창 초안·키보드 영역·44px 터치 영역을 유지해요. 도우미 후속 메시지는 서버에 대기 요청으로 보존하고 진행 중 작업을 묵시적으로 취소·재생성하지 않아요. 대상과 사용자 입력은 접수 때 고정하고 실행에 사용할 최신 초안은 시작 경계에서 검증해요.

### 7.2 응답 스트리밍 — 이번 완료 조건

현재 transport의 내부 SSE 누적에 **공개 답변 텍스트 전용 progress hook**을 추가하고 프로토콜 decoder → runner → durable 이벤트 → UI를 연결해요. 같은 경로를 도우미·가정 장면에 적용하고 일반 본편도 공개 텍스트를 지원하는 모드에서 점진적으로 표시해요.

- tool arguments, thinking/signature, opaque 상태, 내부 평가 출력과 비공개 진단을 답변 스트림에 섞지 않아요. 도구 호출 전 안내와 최종 산출물의 구획을 유지해요.
- `story.submit`, `eval_submit_artifact`, Codex JSON envelope처럼 최종 검증을 통과해야 본문을 확정하는 모드는 raw JSON을 노출하지 않아요. 안전한 텍스트 추출을 보장할 수 없으면 실제 작업 상태를 표시하고 검증된 본문을 완료 시 제공해요. 가짜 타이핑 효과로 스트리밍처럼 꾸미지 않아요.
- 청크는 작업/attempt/segment와 단조 순번에 연결해 묶어서 DB에 저장한 뒤 발행해요. 재접속은 cursor 또는 snapshot+offset으로 누락·중복을 복구해요. 토큰마다 전체 채팅 재조회나 DB 한 행 쓰기를 하지 않아요.
- 표시 중 텍스트는 미완성 응답이며 최종 결과 검증 후 확정해요. 취소·실패 때 받은 부분과 상태를 보존하고, 늦은 delta와 완료 결과가 terminal 상태를 바꾸지 않아요. 브라우저를 닫으면 구독만 끝나고 서버 작업은 유지해요.

### 7.3 세그먼트 경계의 압축

긴 도우미/API 작업은 완료된 도구 교환 뒤 다음 모델 호출 전에 압축할 수 있어요. 실제 실행 이력과 변경 영수증은 보존하고 전송용 history만 바꿔요. 새 provider 요청으로 시작하는 세그먼트 경계에서만 call ID/opaque 연속을 종료해요. 진행 중 도구·미확정 변경은 경계를 넘겨 완료된 것처럼 표현하지 않아요.

세그먼트가 바뀌어도 상위 task ID, operation ID·허가·취소·누적 사용량은 유지해요. 새 call ID로 같은 변경을 요청해도 DB 영수증으로 중복을 막아요. 요약에 ‘저장했음’이라고 쓰는 것으로 멱등성을 대체하지 않아요. 완료된 수정·거절·알 수 없는 도구 교환은 요약과 별도로 원형을 전송하고, 미처리 native 호출로 재구성하지 않아요.

2026-09-11 후속 개선에서 85%는 시도 기준으로 정리했어요. 후보가 원래 요청보다 작고 실제 입력 한도 이내이면 채택하며, 정상 완료한 후보가 도움이 없어도 원래 요청이 한도 안이면 기존 이력·도구 결과·공급자 연속을 유지해요. checkpoint 게시와 세그먼트 전환은 채택 때만 해요. 같은 데이터의 반복 읽기나 수정 영수증 추가만으로 다시 압축하지 않고, 새 읽기 데이터나 실제 상한 초과에서 재판정해요. 원래 요청도 넘치고 후보도 충분히 줄이지 못하면 중단해요. EOF·권한 오류·취소는 보류 가능한 요약 결과로 취급하지 않아요. 세부 계산과 후속 검증은 [입력 문맥 계약](../docs/CONTEXT-LIMITS.md)과 [하네스 후속 결과](HARNESS-OPTIMIZATION-RESULTS.md)를 봐요.

앱이 전체 요청을 구성할 수 있는 API 경로부터 지원해요. 프로토콜별 새 요청 구성·opaque 폐기 계약을 테스트하고 미지원 경로는 안전하게 중단해요. native 루프와 앱이 같은 실행 범위를 이중 압축하지 않아요.

## 8. 나머지 앱 기능과 페르소나

- 자료 제작·복제·정리, 프롬프트 조건/토글 의미를 보존하는 편집, 폴더 이동을 같은 초안·검증·저장 서비스에 연결해요. 새로운 설정을 창작한 경우 원작 사실인 것처럼 설명하지 않아요.
- 자연어 포크는 장면 번호를 안정된 source ID로 해석해 기존 결정적 포크를 호출해요. 선택 지점 이후 사건·요약·메모/정정·override를 가져오지 않아요. 더 이른 유효 요약 또는 원문에서 구성하고 도우미 이력·초안은 복사하지 않아요.
- 제목 설정·자동 제목은 최신 기존 서비스를 재사용해요. 제목의 수동 우선·revision/ABA·첫 완료 장면 1회·실패 비차단을 유지하고 helper 도구도 같은 변경 서비스를 사용해요.
- 옵션 추천은 저장하지 않아요. 실제 프롬프트 소속·옵션 정의로 검증하며 적용 우선순위는 전역 작업본 → 채팅 고정값 → 고정하지 않은 필드에 대한 위임 선택 → 명시적 일회 값이에요. 일회 값은 Run 예약에 원자적으로 귀속하고 동일 request key 재전송에서 다시 소비하지 않아요. 모델 선택·전역 프리셋 변경은 옵션 위임에 포함하지 않아요.
- 짧고 편집 가능한 우이 페르소나를 선택형으로 제공하고 기본은 담백한 도우미로 시작해요. 사용자 선택을 저장하며 안내·설명에만 적용해요. 작품·요약·번역의 문체와 업무 권한은 바꾸지 않아요. 공식 초상·음성·Live2D 도입은 선행 조건이 아니에요.

## 10. 데이터 초기화와 릴리스 경계

목표 DB와 archive는 v15예요. 새 DB 초기화와 **v15 → v15** export/import·backup/restore를 구현하고 이전 DB는 명확한 버전 오류로 안내해요. v14 이하 in-place 이관·전체 archive 변환·옛 실행 엔진을 추가하지 않아요. 과거 snapshot 호환성을 위해 제거한 기억 체계를 다시 유지하지 않아요.

사용자는 테스트 채팅/실행 이력과 필요시 전체 DB 초기화를 허용했어요. 이번 구현의 개발/인수 기준은 전체 fresh v15예요. 기존 자료·설정은 사용자가 필요하면 기존 DB나 개별 JSON으로 별도 보관하며, 새 형식으로 검증되는 자료는 기존 native JSON 편집/가져오기로 재등록할 수 있어요. 옛 슬롯·도구·형식이 자동 변환된다고 약속하지 않아요. 일괄 변환기를 이 작업에 추가하지 않아요.

초기화를 실제 수행할 때는 대상 경로·서버 소유권을 확인하고 필요한 보관이 끝난 뒤 그 앱 DB만 다뤄요. `reset:dev`는 해당 checkout의 기본 `.local/narrative.sqlite` 전용이며 운영 볼륨이나 임의 `NR_DB`를 초기화하는 도구로 사용하지 않아요. 작업 중인 다른 checkout·DB·secret·서비스를 정리하지 않아요. 운영 배포/볼륨 교체는 이번 계획 문서 작성이나 로컬 기능 구현과 구분해요.

새 archive에는 초안·도우미 이력·산출물의 정확한 개정·요약/메모·위임·변경 영수증을 포함해요. 채팅/자료 삭제와 포크의 복사/제외 규칙을 각 데이터의 실제 소유권에 맞춰 검증해요. 범용 scope 테이블을 모든 채팅 삭제 목록에 기계적으로 추가해 서재 작업까지 지우지 않아요.

### 이미지 이해를 후속으로 시작할 때

이번에는 이미지 열람 능력을 제공하지 않아요. 에셋의 파일명·설명만 읽은 경우 그 범위를 그대로 표시해요. 텍스트 편집과 기존 이미지 표시/배치를 구현했다는 이유로 이미지 이해가 완료됐다고 보고하지 않아요.

후속은 다음 순서로 별도 설계·구현해요.

1. 현재 provider-neutral 입력 타입과 각 사용 프로토콜의 공식 이미지 입력 계약을 확인해 텍스트+이미지 content part를 추가해요. 모델 코드표만으로 지원을 단정하지 않아요.
2. 사용자에게 허용된 실제 asset ID/revision/hash를 읽는 도구를 제공하고 MIME·크기·수량·해상도·입력 예산·전송 범위를 검증해요. 임의 파일 경로나 외부 URL 조회 도구로 대체하지 않아요.
3. 선택한 모델/프로토콜로 이미지를 전달했다는 근거를 작업에 남겨요. 미지원·전송 실패·손상 파일일 때 설명 텍스트만 보고 이미지 확인을 주장하지 않아요. 새 외부 공급자 전송과 비용 범위는 해당 실행 설정으로 명시해요.
4. 실제 이미지 관찰 결과를 에셋 설명·표정 메타데이터의 제안/동일 초안에 연결해요. 저장은 이번에 만든 허가·CAS·operation·되돌리기를 재사용해요.
5. 합성 이미지의 실제 전송 body, 미지원/오류, 이미지와 텍스트 불일치, 초안 경합을 로컬에서 검사하고 승인된 실제 이미지 이해 모델로 관찰 품질을 평가해요. 모델을 호출했다는 사실과 이미지 해석 정확도를 구분해요.

후속 이미지 구현 때문에 본편/도우미 입력을 다시 합치거나 작품별 맥락 분리를 없애지 않아요. 음성·Live2D·캐릭터 에셋 제작은 이미지 이해와도 별개예요. 임베딩/혼합 검색·native/원격 compact·연속 외전은 각각 필요성과 품질 근거가 생겼을 때 독립 범위로 다뤄요.

## 12. 이 문서 작성에서 수행한 범위

최종 사용자 결정과 계획 검토를 반영하고 현재 코드의 재사용 경로·제목 구현·모델 등록 보조 제거·스트리밍 경계를 읽기 전용으로 확인했어요. 기능 코드·DB·서버·실제 공급자·운영 배포는 이 문서 작성으로 변경하지 않았어요. 위 표는 인수 기준이며 실행 결과가 아니에요.

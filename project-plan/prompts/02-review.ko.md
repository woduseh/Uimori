# 별도 Codex 검토 — 현재 완료 주장 검증

사용자가 지정한 변경과 완료 주장을 독립적으로 점검해줘. 베타 진행은 [BETA-PLAN](../BETA-PLAN.md), 세부 동작은 해당 계약 문서가 기준이야. 작성자의 설명을 결론으로 받아들이지 말고 관련 code/build와 실제 변경·검사 증거를 확인해. 소스가 이후 바뀌었다면 영향받는 증거를 구분하고, 요청하지 않은 전체 프로젝트 재감사로 확장하지 마.

우선은 리뷰가 목적이므로 코드/기대값/검증 기준을 수정하지 마. 승인된 로컬·합성 검사는 필요한 범위에서 실행할 수 있지만 원래 작업 결과를 덮어쓰지 말고 별도 결과 경로를 사용해. 유료 모델/개인 원문은 호출하지 마.

변경이 도우미·모델 실행에 영향을 주면 조회/스킬 선택을 prefetch의 고정 목록에 가둔 부분, 역할별 지침·자료·출력 계약의 누수, 표현 annotation이 원고/canon을 바꾸는 경로, 요청 목적과 무관한 항상 실행되는 모델 단계를 점검해. 자율성은 호출 개수가 아니라 적법한 판단 범위로 평가하자.

요구사항 누락, 채팅/분기/source 혼동, 중복·늦은 job commit, 원문/번역/상태 결합, next-turn dependency, 저장 재시작/취소, 거절의 후속 처리, 실제 요청과 Inspector 불일치, false test oracle, required skip/zero-tests, 권한·비밀정보 문제를 변경 범위에 맞게 확인해. 도구가 있으면 실제 동작을 재현하고, 없으면 그 한계를 밝혀줘.

발견한 문제가 있으면 심각도, 파일/위치, 재현 방법, 사용자 영향, 가장 작은 수정 방향과 필요한 검사를 제시해. 무관한 재설계나 가상의 경고로 목록을 채우지 마. 문제가 없으면 ‘관찰한 범위에서 blocker를 찾지 못함’과 미검증 범위를 남겨줘. 검사 선택·재실행 기준은 [QUALITY](../../docs/QUALITY.md#실행-시점)를 따르고 필요 이상으로 동일 검사를 반복하지 마.

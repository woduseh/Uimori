# 다음 구현 작업 / 중단된 작업 이어가기

`project-plan/README.md`와 CURRENT.md, 실제 git 상태와 적용 지침을 확인해줘. 문서에 완료라고 적혀 있어도 현재 code/build와 증거가 일치하는지 확인하고, 현재 범위의 로컬 결함·회귀·빠진 구현부터 해결해. 키·예산·실제 기기 등 외부 전제만 부족한 검증은 BLOCKED로 기록하고, 같은 요청 범위에서 그 전제 없이 구현·검증 가능한 다음 로컬 흐름은 진행해. 이미 기록한 동일한 승인 대기를 반복 질문하거나 미래 milestone 검사를 현재 gate로 당겨오지 마. 외부 검증을 건너뛴 전체 단계가 완료됐다고 표시해서도 안 돼.

현재 단계가 실제로 끝났거나 외부 전제만 남아 독립적인 로컬 작업을 진행할 수 있다면, MILESTONES에서 다음으로 지정된 한 수직 슬라이스를 구현·검증해. M0 이후에는 M1a → M1b → M1c 순서를 기본 제안으로 사용하되, 공유 의존성을 줄이기 위한 작은 순서 조정은 이유를 남기고 진행해. 이미 존재하는 코드를 새로 만들지 말고 이전 결정과 검증된 경로를 재사용해.

M1에서는 메인이 자율적으로 로어를 찾아 글을 쓰고, 보조가 자기 catalog/skill/schema로 번역·이미지·표시 상태를 만드는 사용자 흐름을 지켜줘. preset과 capability가 충분하면 기존 허용 안에서 진행하되 provider 변경이나 새 유료 범위는 따로 다뤄.

수정할 사용자 동작·유지할 범위·관련 acceptance ID를 짧게 정리한 뒤 바로 구현해. 새로운 계획 문서를 만드는 것으로 완료하지 말고, 요구된 동작을 실제 앱에서 검증하고 CURRENT에 증거와 다음 한 단계를 남겨줘.

추가 API 비용은 별도로 승인된 설정이 있을 때만 사용해. 키/권한이 없으면 mock/protocol/local 구현을 계속하고, 실제 연결/품질 주장은 BLOCKED로 남겨줘. 기존 승인 범위 안의 반복 작업에는 매번 재확인을 요구하지 마.

완료 뒤 최종 변경과 실행 증거, 남은 결함, 다음 사용자가 직접 확인할 제품 흐름을 알려줘. 범위 밖의 공개 배포·대규모 리팩토링·전 provider 지원까지 자동 확장하지 마.

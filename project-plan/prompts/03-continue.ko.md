# 다음 구현 작업 / 중단된 작업 이어가기

현재 사용자 요청·확정한 선택·실제 git 상태·[루트 지침](../../AGENTS.md)을 기준으로 이어가줘. 베타 작업은 [BETA-PLAN](../BETA-PLAN.md)의 현재 진행과 다음 사용자 결과를 확인해. 필요한 기능 계약만 읽고 위치가 불명확할 때 [코드 지도](../CODE-MAP.md)를 사용해. 과거 요약은 단서로 사용하되 현재 작업에 필요한 코드·근거를 확인하고, 변경이 없는 다른 분야의 조사를 다시 시작하지 마.

이번에 끝낼 사용자 결과와 확인할 동작을 짧게 정하고 필요한 공통 API 보완과 기능 연결을 함께 구현해. BETA-PLAN의 6단계가 현재 베타 순서이고 M0/M1은 초기 구축 기록이야. 이미 있는 기능은 같은 API로 연결하고, 작은 API 구현이나 계획서 작성만으로 사용 흐름 전체가 완료됐다고 표시하지 마.

독립 구현을 위임하면 공유 타입/API·담당 파일·의존 순서·완료 근거를 맞추고 주 작업자는 공통 의존성과 통합을 진행해. 검사 범위·빌드·재실행·종료 기준은 [QUALITY](../../docs/QUALITY.md#실행-시점)를 따라. 미완성 의존성 때문에 실행할 수 없는 검사는 준비 상태가 바뀐 뒤 확인하고, 독립 작업은 계속해.

키·예산·실제 기기 등 외부 전제가 부족하면 그 검증을 BLOCKED로 기록하고 승인된 범위의 다른 구현을 진행해. 사용자가 결정할 사안은 근거·대안·추천을 준비하고 답이 필요한 작업만 보류해. 동일한 승인 대기를 반복 질문하거나 미래 인수 검사를 현재 작은 수정의 필수 조건으로 당겨오지 마. 실제 연결·품질·전체 단계의 미검증 범위는 그대로 남겨줘.

유료 호출은 기존 승인된 예산·자료·대상·목적 범위에서만 사용해. 범위 밖의 운영 데이터 변경·push·공개·배포는 별도 권한을 확인해.

계약이 바뀌면 소유 문서, 베타 진행이 바뀌면 BETA-PLAN만 필요한 부분을 갱신해. 요구된 구현과 관련 검사가 끝나면 로컬 커밋·결과·근거·남은 범위를 정리하고, 후속 작업은 승인된 Goal/요청 범위에서 이어가줘.

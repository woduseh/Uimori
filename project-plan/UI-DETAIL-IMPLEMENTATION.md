# 상세 화면의 공통 UI 적용

2026-09-08 후속 사용자 요청으로 채팅 설정·고급 패키지·프롬프트 편집·응답 하단 도구에 [공통 UI 원칙](../docs/UI-PRINCIPLES.md)을 적용해요. [앞선 공통 UI 결과](UI-COMPACT-IMPLEMENTATION.md)와 현재 작업공간의 미커밋 변경을 보존해요.

## 계획과 유지할 계약

| 범위 | 적용할 변화 | 유지할 계약 |
| --- | --- | --- |
| 채팅 설정 | 설정 전체 분야 목록, 모바일 목록→상세·데스크톱 병치, 명확한 저장 이름 | 분야별 기존 저장 API·CAS·초안·방문한 입력·뒤로가기 보호 |
| 고급 패키지 | 여러 줄 탭을 분야 탐색과 편집으로 전환, 공통 탐색 제어 | 로어 검색·선택·본문·임시 상태, 자료 전체 저장, 렌더 중 실행 금지 |
| 프롬프트 | 현재 대상 저장 우선, 복사/기본 복귀/삭제 메뉴, 작은 블록 조작부 | 저장과 채팅 적용 구별, pending 문법·협업 검증·undo·초안 |
| 응답 하단 | 응답별 관리 메뉴, 편집 종료 후 메뉴 초점·읽던 위치 복귀 | 직접 수정과 모델 호출의 구별, 원문 귀속·해시·명시적 호출·취소 |
| 작업 현황 | 실제 열린 화면을 먼저 확인한 뒤 필요한 범위·상태 분류만 보완 | 현재 채팅 범위, 진행·실패·불확실 상태·취소 접근 |

새 채팅·기본 입력창은 이번 개편 대상이 아니에요. 사용자 DB·개인 자료·실제 공급자 호출·배포·commit/push는 포함하지 않아요.

## 기준과 검증

기준 source/build는 `f064957943728cd7b3f07f3b7d3647cdf5c1e914894aac9dbd9f92c85d352361`이에요. 바로 앞 감사의 새 화면은 [평가 기록](../output/ui-followup-audit-2026-09-08/REVIEW.md)에 있어요. 작업 현황 캡처는 로딩 중이어서 화면 판단 근거에서 제외했어요.

앞선 집중 감사에서 `PKUI04`가 빈 서재의 `봇 만들기`를 `새로 만들기`로 찾는 진입 조건 오류를 확인했어요. 이번 기존 회귀 동선 수정에서 독립 실행도 가능하도록 보정하며 원래 로어 저장/검색/상태 검사는 유지해요.

수정 후 `npm run quality:full`, 새 반응형·초안·메뉴 집중 검사 및 `npm run verify:redesign`을 실행해요. 채팅 설정·장면 메뉴는 320·360·390·412·768·1440 CSS px, 패키지는 360·390·430·768·1024·1440 CSS px에서 확인해요. 키보드·뒤로가기·폭 전환·저장 실패와 실제 캡처도 검토해요. 첫 실패와 수정 뒤 결과, source/build와 cleanup을 분리해 보존해요. 실제 S25U·IME·글자 확대·운영 배포는 로컬 합성 검사와 구분해요.

## 구현

- 채팅 설정을 인물·자료, 프롬프트, 모델, 상태·기억, 이미지, 후속 작업, 읽기 설정의 7개 분야로 나눴어요. `ChatSettingsPanel`은 모바일 목록→상세와 넓은 화면 병치를 맡고, 기존 편집기의 저장 API와 CAS는 유지해요. 방문한 분야는 숨긴 채 유지하며 미저장 입력·파일·저장 중 상태를 합쳐 닫기·이력 이동·페이지 이탈을 보호해요. 집중 읽기로 전환할 때도 같은 확인을 거쳐요.
- `SectionNavigation`을 패키지와 채팅 설정이 공유해요. 고급 패키지의 9개 분야를 여러 줄 탭에서 목록·상세로 바꾸고 모든 편집기를 유지해요. 분야별 로어 검색·선택·미적용 문법·펼친 항목·커서·스크롤을 보존해요.
- 기존 프롬프트는 `수정 저장`, 새 프롬프트는 `새 프롬프트 저장`을 주된 행동으로 보여줘요. `이 채팅에 적용`·`저장하고 적용`은 보조 행동이며 복사·앱 기본 복귀·삭제는 관리 메뉴, JSON은 구성 도구에 있어요. 블록 이동·삭제·되돌리기는 기존 검증·초안과 초점을 유지해요.
- 장면 하단의 분기·원문 수정·번역 수정·이미지 선택을 `장면 작업 메뉴`로 묶고 위쪽으로 열어요. 직접 편집을 마치면 보이는 메뉴 입구로 초점과 읽던 위치를 돌려줘요.
- 이미지 등록 중 입력을 잠그고, 서버가 등록을 확정하면 파일과 필드를 비워요. 이어지는 목록 조회 실패를 등록 실패와 구별해 중복 등록을 유도하지 않아요. 숨겨진 상태·기억 분야는 주기 조회를 멈추고 다시 열 때 조회하며, 초안은 유지해요.
- 작업 현황은 합성 완료 기록 2개와 작업·실행 상세·호출 목록의 실제 HTTP 응답을 기다려 390/1440px 화면을 확인했어요. 현재 채팅 범위, 종료 상태, 원고 읽기와 분기, 접힌 진단 상세가 구별되고 버튼이 넘치지 않아 이번에는 배치를 유지해요. 이 판단은 합성 기록의 정보 배치에 대한 것이며 실제 공급자 비용·실패·모바일 기기의 실행 증거는 아니에요.

최초 빌드는 샌드박스의 `spawn EPERM`으로 실행되지 않았고, 승인된 동일 빌드 재실행은 PASS예요. 최초 `quality:full`은 1,334 PASS·1 opt-in skip이에요.

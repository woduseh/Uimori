# v0.1.0 베타 실행 계획

제품 원칙·공개 조건은 [2026-09-12 결정](../docs/DECISIONS-2026-09-12-BETA.md)이 소유해요. 이 문서는 실행 순서와 상태를 관리하며 기술 선택을 사용자 확정 사항으로 만들지 않아요. 소스의 현재 기능은 [CURRENT](CURRENT.md), 표본과 기능별 근거는 [BETA-SAMPLES](BETA-SAMPLES.md) · [JSON 기준](BETA-SAMPLES.json)을 봐요.

사용자는 아래 순서에 따른 설계·구현·검증을 승인했어요. 원칙 안의 기술 선택은 진행하고, 경험·의미·지원 범위를 바꾸는 선택은 검토 가능한 결과를 준비해 사용자와 논의해요. 새로운 유료 평가·개인 자료 외부 전송·배포의 실행 권한은 해당 단계에서 확인해요.

## 채택한 작업 방식 · 2026-09-13

현재 요청 범위는 **트리거·Lua 실행 연결과 동적인 봇·모듈 기능 구현**까지예요. Plugin v3는 주요 스펙의 어댑터 연동을 목표로 하는 후속 작업이고 특정 플러그인 전체 기능 재현은 요구하지 않아요. 전체 표본의 실사용 테스트는 사용자가 담당해요. 아래 날짜별 기록과 표본 대응표의 과거 전체 인수 조건은 [후속 결정](../docs/DECISIONS-2026-09-12-BETA.md#문서와-공개-조건)으로 대체되며, 현재 작업에서 배포·베타 인수까지 자동 진행하지 않아요.

사용자는 Risu의 고정 명세·실제 구현을 호환 동작의 근거로 삼고, Uimori 공통 API에 대응시키는 작업 방식을 채택했어요. 6단계와 공개 조건은 유지하며 **2~3단계의 필요한 기반 보완과 4단계의 기능 연결을 실제 사용 흐름 하나로 수행**해요. 제품 원칙은 Uimori가, Risu 함수명·자료 구조의 해석은 호환 어댑터가 소유해요. 새 Risu/RisuAI-Next 버전은 별도 지원 판단을 거치며 현재 공개 조건에 자동 추가하지 않아요.

사용 흐름별로 사용자에게 생기는 결과와 완료 조건을 정하고 **필요한 명세 확인 → 기존 API 대응 → 부족한 공통 기능과 어댑터 구현 → 관련 검증 → 필요한 문서 갱신·로컬 커밋**까지 마쳐요. 이 계획에 이미 정한 흐름의 작은 구현마다 별도 계획·결과 문서를 만들지 않아요. 대응은 기존 API 연결·기존 API 보완·새 공통 기능·의도적 차이·미확인으로 구분해요. 같은 기능은 같은 API/메서드를 사용하며 특정 표본명·옵션명을 본체의 실행 분기로 만들지 않아요. 표본은 실제 사용과 명세 누락을 확인하는 사례로 사용해요.

조사는 현재 완료 조건을 바꾸는 미해결 문제에 한정해요. 전체 명세 전수 조사나 범용 기반·검증 도구의 확대를 매 작업의 선행 조건으로 삼지 않아요. 필요한 검사와 사용자 흐름이 통과하면 해당 묶음을 마치고 다음 기능으로 이동해요. 기존 데이터 보호·필수 검사·후속 승인한 RPack·AGPL 라이선스 조건·유료 평가 승인 범위는 유지해요. 독립된 하위 작업만 난도·위험·비용에 맞는 모델과 추론으로 위임하고, 주 작업자가 연결 결과를 확인해요.

### 검사와 커밋 단위 · 2026-09-13

[QUALITY의 검사 시점](../docs/QUALITY.md#실행-시점)이 현재 기준이에요. 작은 구현·커밋에서는 품질·영향받는 집중 검사를 하고, 아래처럼 사용자에게 연결된 사용 흐름이 완성될 때 전체 품질·smoke·관련 영역 검사를 묶어요. 저장·권한·공통 실행 경계의 회귀는 즉시 확인하며, 문서만 바꿀 때는 내용·링크·명령·일관성·diff를 확인해요. 작은 후속 수정은 영향받는 검사만 갱신하고 이전 전체 결과와 구분하며, CI·릴리스 영수증·베타 공개 조건은 유지해요.

### 현재 구현 범위

> 가져온 봇·모듈의 공유 상태와 행동을 연결한다. 변수 변경 → 트리거/Lua 실행 → 지침·화면 반영 → 재접속·분기·복원까지 실제 사용 결과로 완성한다. 필요한 기능만 기존 공통 API에 보완하고 Risu 문법과 자료 구조는 호환 어댑터가 담당한다.
>
> Plugin v3 주요 스펙 어댑터, 대용량 자료, Linux/Docker 설치·업데이트·복구와 베타 인수는 별도 후속 작업이다. 전체 표본의 실사용 테스트는 사용자가 담당하고 개발 에이전트는 구현한 기능의 관련 회귀를 확인한다. RPack·AGPL 후속 승인, CharX의 메인 프롬프트 덮어쓰기·성격·시나리오 제외, 글로벌 노트의 추가 작문 지침 변환, 독립 .risum 제외와 CharX 내부 해독의 구분은 최신 결정 문서를 따른다.
>
> 특정 자료 전용 본체 예외·미래 Risu 버전 자동 추종·주 앱 DOM 접근을 도입하지 않는다. 원문·사용자 권한·개인정보·부가 기능 실패의 채팅 비차단 원칙을 유지한다. 구현·검사·문서·로컬 커밋을 사용 흐름에 맞춰 진행하고, 검사 시점과 재실행 범위는 docs/QUALITY.md를 따른다. 완료된 기반을 반복 정비하지 않으며 새 기반·검증 도구는 현재 사용 흐름에 필요한 경우에만 추가한다.
>
> 새로운 제품 의미·권한·지원 범위·필수 정보의 결정이 필요하면 의존 작업을 멈추고 구체적인 대안과 추천을 사용자에게 제시한다. 원칙 안의 기술 선택은 자율적으로 진행한다. 실제 모델 평가의 기존 승인 총 USD 100 미만을 지키고, 개인 자료 외부 전송·새 push·배포·운영 변경은 임의로 하지 않는다. 이 구현의 완료를 전체 표본 인수나 베타 공개 완료로 선언하지 않는다.

### 새 세션에서 이어갈 작업 · 2026-09-14

사용자 요청으로 남은 구현은 별도 세션에서 이어가요. 목표는 **가져온 자료의 행동이 같은 채팅의 상태를 갱신하고, 그 변화가 지침과 화면에 반영되며, 다시 열거나 복원해도 이어지는 것**이에요. 프리셋·기본 CharX 등록·공유 변수·Lua 격리 실행·첫 콜백·현재 분기 대화 읽기는 이미 구현했어요. 지침 정리도 끝났으며 새 세션의 선행 작업으로 다시 시작하지 않아요. 현재 브랜치는 `codex/beta-foundations`이고 로컬 커밋까지 인계하며 push·배포는 하지 않았어요. 다른 작업트리를 사용하면 먼저 이 브랜치의 최신 커밋을 포함하는지 확인해요.

| 권장 순서 | 남은 사용자 결과 | 먼저 사용할 구현 경로 | 완료를 판단할 근거 |
| --- | --- | --- | --- |
| 1. 입력·요청 훅 (완료) | `onInput`·`listenEdit(editInput)`·`listenEdit(editRequest)`가 실제 제출·모델 전송 시점에 실행되고 상태·전송문에 반영돼요. | `server/risu-lua-adapter.ts`; `package-behavior-run.ts`의 `prepareAutomaticRunBehavior`·`preparedBehaviorSnapshot`; `app.ts`; `model-runner.ts`; 기존 `prompt-transforms.ts` | 파일 가져오기부터 실제 전송 사본까지 연결해요. 원래 요청·snapshot을 보존하고 적용한 변경을 사용자에게 알리며 실패·건너뛰기·취소가 채팅을 막지 않아요. |
| 2. 출력·표시 훅과 동적 화면 (훅 완료) | `editOutput/editDisplay`와 상태 변화가 응답 표시·상태창·선택기에 반영돼요. 버튼은 같은 사용자 행동 API를 사용해요. | `app.ts`의 `stageRunOutput`·`prepareAfterResponse`; `package-after-response.ts`, `package-presentation.ts`, `package-requests.ts`; [패널 계약](../docs/PACKAGE-PANELS.md) | 원래 응답과 표시용 결과의 관계를 보존하고 명시 실행에서만 계산해요. 새로고침·분기·복원은 저장 결과를 읽으며 코드·모델을 재실행하지 않아요. HTML은 기존 격리 패널 경계를 사용해요. |
| 3. 필요한 나머지 Risu 효과 연결 | 위 흐름을 막는 혼합 트리거·지원하지 않는 CBS 쓰기/조건·자료/UI·구조화된 모델 요청 등을 공통 API에 대응해요. | `risu-import.ts`, `risu-lua-adapter.ts`, `risu-cbs.ts`; `package-extension-execution.ts`와 기존 Host 모듈 | 미지원 안내와 실제 고정 Risu 동작을 근거로 필요한 기능부터 연결해요. 선언 순서·효과·실패 의미를 보존하고 특정 봇의 규칙을 본체에 추가하지 않아요. 전체 Risu API 구현을 이 묶음의 선행 조건으로 삼지 않아요. |

첫 구현은 **입력·요청 훅 한 흐름**으로 시작해요. Risu의 `onInput`과 `onStart`를 같은 이벤트로 합치지 말고, 최종 전송 요청을 반복 생성하는 예산 계산·미리보기 안에서 제작자 코드를 실행하지 않아요. 기존 정규식 변환 영수증은 정규식 계약에 묶여 있으므로 Lua 계산 증거는 공통 `ExtensionProgramReceipt`로 보존하고 전송·표시 투영과 연결해요. 기존 일반 본문 문자열을 임의 HTML로 해석하지 않아요. 긴 문장·패널에 현재 결과/Host 한도가 부족한지는 실제 연결할 입력으로 판단해요.

2026-09-14 사용자가 이번 작업을 작은 구현 단계로 한정해 **`onInput` 콜백 연결만 완료**했어요. 공통 자동 준비에서 입력 단계를 `onStart`와 구분하고 입력 전 대화·선언 순서·조건을 유지해요. 기존 상태/변수 영수증과 본문 성공 시 채택을 사용하며 원래 요청·snapshot을 바꾸지 않아요. `editInput`·`editRequest`·출력/표시 훅·화면 확장은 다음 단계예요. 최종 `quality`가 통과했어요. 어댑터/계약 81개와 기존 준비·대화·복원 62개를 확인했고, 입력 전 대화 영수증의 저장 경계 누락을 고친 뒤 Lua 통합 6개를 재확인했어요. 실제 앱 제출 검사에서는 준비 변수가 예약 profile을 덮어쓰던 문제를 확인해 `persistedContextSnapshot`이 원래 profile을 보존하도록 수정했어요. 이후 앱 제출·합성 전송·상태 저장과 Lua 통합 9개, 문맥·확장 모델 준비 21개가 통과했어요. 단계별 실패/재검사 로그는 ignored `output/input-hooks-work/`에 보존해요. 전체 검사·빌드·smoke·브라우저·실모델·전체 표본 인수는 실행하지 않았어요.

2026-09-14 이어서 **`listenEdit("editInput")` 연결**을 마쳤어요. 공통 자동 준비에 Host가 입력을 소유하는 `hook: 'edit-input'` 단계를 추가해 입력 단계 다음·시작 단계 앞에서 실행하고, 등록 순서대로 이어 넘긴 텍스트를 이번 요청의 **전송 사본**에만 투영해요. 예약 snapshot·저장 요청·hash·편집 기준과 대화 읽기 Host의 본문은 그대로예요. 프리셋 전송 정규식·문맥 크기 계산·실제 전송·후보·포크·복원이 같은 투영을 사용하고 Reader의 요청 항목에서 원문과 전송문을 비교해요. Risu의 편집 경로와 같이 트리거 조건을 적용하지 않고 `nil` 반환은 직전 값을 유지하며, 문자열이 아니거나 100,000자를 넘는 결과는 준비 묶음 실패로 처리해 원래 요청으로 계속해요. 편집 텍스트는 모델 문맥의 `automaticResults`에 넣지 않고, 미리보기·예산 계산에서는 제작자 코드를 실행하지 않아 저장 원문을 보여줘요. 최종 `npm run quality`와 `npm run test:tooling`이 PASS이고, 전체 `npm test`는 2,494 PASS·23 FAIL이에요. 실패 23개는 같은 변경 전 트리에서도 동일하게 실패하는 `tests/harness.test.ts`·`tests/server.test.ts`의 로컬 환경(Node 26·tmp 심볼릭 링크) 항목이에요. Lua 통합 8개(편집 투영·원문 보존·Reader 표시·백업/복원·비문자열 결과 실패 포함), 어댑터·계약 83개, 준비·대화·복원·변환 72개를 확인했어요. 빌드·브라우저·실모델·전체 표본 인수는 실행하지 않았어요. `editRequest`·`editOutput`·`editDisplay`와 출력·표시 훅, 동적 화면은 다음 단계예요.

이어서 **`listenEdit("editRequest")` 연결**까지 마쳤어요. 사용자가 범위를 **전송용 원문 대화와 이번 요청만 `{role, content}` 목록으로 전달**하는 쪽으로 정했어요. 시스템 프롬프트·로어·다른 자료의 지침과 프롬프트 프리셋은 넘기지 않고, 메시지 수·역할은 고정하며 본문만 바뀔 수 있어요. 같은 대화 본문을 넘기므로 기존 **대화 읽기 허용**을 그대로 요구하고, 허용이 없거나 대화가 실행 한도(메시지 1,000개·메시지당 100,000자·합계 100,000자)를 넘으면 그 행동만 건너뛰고 Reader 안내로 알려요. 새 권한은 추가하지 않았어요. 실행 순서는 입력 → 입력 편집 → 생성 전 → 전송문 편집이고, 계산한 편집 결과를 프리셋 전송 정규식의 입력으로 사용해요. Risu는 정규식을 먼저 적용하므로 이 순서 차이를 문서에 남겼어요. 투영은 예약 snapshot이 아니라 준비 영수증에서 파생하며 문맥 축소 전송에서도 원래 메시지 index를 유지해요.

이 묶음의 최종 `npm run quality` PASS, 전체 `npm test`는 2,497 PASS·23 FAIL이고 실패 23개는 변경 전 트리와 같은 `tests/harness.test.ts`·`tests/server.test.ts`의 로컬 환경 항목이에요. Lua 통합 11개(입력·전송문 편집 투영, 원문 보존, 허용 없음·형식 위반·한도 초과의 건너뜀/실패, Reader 표시, 백업·archive 복원)와 어댑터·계약 83개를 확인했어요. 빌드·브라우저·실모델·전체 표본 인수는 실행하지 않았어요.

2단계의 **출력·표시 훅**도 연결했어요. 계획 2행의 "원래 응답과 표시용 결과의 관계를 보존하고 명시 실행에서만 계산"을 따라 `editOutput`·`editDisplay`를 응답 후 단계의 Host 소유 편집 단계로 만들고 `editOutput → onOutput → editDisplay` 순서로 한 번 계산해요. 저장 원문·hash·다음 턴 문맥·대화 읽기·`response.read.current`는 원래 응답을 유지하고, Reader는 영수증에서 파생한 표시 사본을 읽어요(프리셋 표시 정규식보다 먼저 적용). 읽기·새로고침·복원에서 코드를 다시 실행하지 않고, 구간 경계가 있는 응답과 원문 편집 뒤에는 적용하지 않아요. Risu가 편집 결과를 저장 대화에 반영하는 것과의 차이, 자료별로 세 단계를 묶어 실행하는 순서 차이는 가져오기 안내와 문서에 남겼어요. 이 묶음의 `npm run quality` PASS, 전체 `npm test` 2,499 PASS·23 FAIL(로컬 baseline 동일)이고 Lua 통합 13개로 표시 사본·원문 보존·재읽기 무실행·형식 위반 실패·archive 복원을 확인했어요.

5단계의 **1단계 유지보수 경계**를 구현했어요. `maintenance` 표의 status·epoch와 `GET/POST /api/maintenance`, 인증 다음의 쓰기 차단 경계, 취소·건너뛰기 허용 목록, job·삽화·story·확장 operation의 새 claim 정지, 후속 제목 생성 정지, `NR_MAINTENANCE=1` 후보 부팅(복구·worker 없음, API로 열 수 없음)을 연결했어요. 닫힌 상태는 재시작에도 유지하고 브라우저는 유지보수 안내를 표시하며 작성 중인 입력을 지우지 않아요. 검사는 `tests/maintenance.test.ts` 2개와 전체 `npm test` 2,501 PASS·23 FAIL(로컬 baseline 동일), `npm run quality`·`npm run build` PASS예요. controller·두 image/volume 전환·앱 안 Update 버튼과 실제 서버 적용은 남아 있어요.

3단계(나머지 Risu 효과)의 첫 묶음으로 **선언형 `setvar` 트리거**를 연결했어요. 스크립트가 없는 트리거는 Risu와 같이 `type`으로 실행 시점을 정해 `start`·`input`·`output`·`manual`을 공통 행동 하나로 옮기고, 조건은 기존 변환을 그대로 사용해요. 값 계산은 Risu의 고정 구현과 같은 JavaScript 숫자·문자열 의미를 위해 생성한 JavaScript 프로그램이 담당하고 공유 변수 Host와 기존 쓰기 허용·영수증 경계를 사용해요. `display`·`request` 시점, 변환할 수 없는 조건·효과 종류·동적 변수 이름, 스크립트와 섞인 트리거는 연결하지 않고 안내와 원본 보존으로 남겼어요. 검사는 어댑터 3개(합성 실행 포함)와 전체 `npm test` 2,504 PASS·23 FAIL(로컬 baseline 동일)이에요.

**혼합 트리거**도 연결했어요. 스크립트가 첫 효과가 아닌 트리거는 효과 → 스크립트 콜백 → 효과를 그 트리거의 실행 시점 하나에서 선언 순서대로 실행해요. 스크립트가 첫 효과인 경우(Risu가 모든 시점에서 실행), 수동 트리거의 클릭 하나로 묶어야 하는 경우, 트리거가 자기 조건이 읽는 변수를 바꾸는 경우는 의미를 보존할 수 없어 연결하지 않고 원본과 안내를 남겨요. 어댑터 검사 2개를 추가했고 전체 `npm test`는 2,506 PASS·23 FAIL(로컬 baseline 동일)이에요.

이 묶음의 브라우저 근거는 `verify:package-ui` A/B예요. 세션 시작 커밋 `c37c7fe`의 내보낸 트리와 현재 트리가 같은 환경에서 각각 **25 PASS · 1 FAIL**이고 실패는 같은 `PANELUI01@412px`이라 이 변경과 무관해요. 첫 실행에서 기존 DB가 `maintenance` 표를 얻지 못하는 회귀를 발견해 schema migration 20으로 고쳤어요(DB 19 → **20**). 실제 Windows CI·전체 브라우저 묶음·실모델은 이 세션에서 실행하지 않았어요.

트리거 효과의 **모델 요청·정규식 추출**도 같은 경로로 연결했어요. 카드가 저수준 접근을 선언한 경우에만 `runLLM`·`extractRegex`를 실행하고(선언이 없으면 Risu처럼 그 효과만 건너뜀), 모델 요청은 기존 확장 모델 권한·영수증을 사용하며 ChatML 프롬프트와 무매칭 정규식은 성공으로 처리하지 않아요. 어댑터 검사 3개를 추가해 합성 Host로 실제 실행까지 확인했고 전체 `npm test`는 2,510 PASS·23 FAIL(로컬 baseline 동일)이에요. 남은 효과 종류(`systemprompt`·대화 변경·앱 명령·이미지 생성 등)는 안내와 원본 보존으로 남겼어요.

유지보수 전환은 설정의 **내보내기와 복원 → 유지보수 모드**에서 직접 하고 공유 진단의 시스템 범위에도 상태·구간 번호가 들어가요. 화면을 추가한 뒤 `verify:chat-backup` 브라우저 묶음이 **7 PASS · 0 FAIL**이에요.

사용자가 남은 순서를 **대용량 자료 → 플러그인/모듈 프레임워크 → 배포 controller**로 정했고 controller 검증은 사용자가 맡아요. 첫 항목인 **대용량 자료**를 연결했어요. 24 MiB가 넘는 카드·모듈은 `POST /api/uploads`로 먼저 스트리밍해 DB 옆 `uploads`에 두고, 검토·등록은 그 파일을 읽어요. 등록이 끝나면 staged 파일을 지우고 미완료 파일은 24시간 뒤 정리해요. 한도는 256 MiB예요. 이 경로에서는 **원본 사본을 영수증에 담지 않고** 이름·SHA-256 지문을 가져오기 안내로 남겨요(24 MiB 이하 파일의 기존 원본 보존은 그대로). 백업·archive 계약은 바뀌지 않아요. 컨테이너 해석 한도는 파일 크기에 비례하되 한 항목 64 MiB로 묶고, 크기 대비 과도한 압축 확장은 계속 거절해요. 첨부 이미지 2 MB·형식 제한은 그대로라 큰 오디오·영상은 계속 안내로 남겨요. 검사는 합성 70 MiB 컨테이너의 업로드→검토→등록→staged 삭제→재사용 404와 압축 폭탄·초대형 항목 거절 2개를 포함한 `tests/risu-import.test.ts` 18개, 전체 `npm test` 2,512 PASS·23 FAIL(로컬 baseline 동일), `quality` PASS예요. 실제 140 MB 표본(Merry)은 사용자 파일이라 이 세션에서 실행하지 않았어요.

유지보수 안내 화면이 앱을 열 때마다 상태를 조회하면서 `PANELUI01@2560`이 새로 실패하는 것을 `verify:package-ui` A/B로 찾아 고쳤어요. 상태는 기존 세션 조회에 실어 보내고 닫힌 동안·거절된 쓰기 뒤에만 다시 읽어요. 고친 뒤 같은 묶음이 **25 PASS · 1 FAIL**로 baseline(`PANELUI01@412px`)과 같아졌어요.

플러그인·모듈 묶음의 첫 항목으로 [확장 경계 문서](../docs/EXTENSIONS.md#권한과-의존성)가 요구한 **로어 안 실행 자료와 모델용 문장의 구분**을 구현했어요. 로어 맨 앞의 `@@` 지시문을 본문에서 떼어 해석하고 `@@dont_activate` 항목은 모델에 보내지 않아요(`@@activate`는 항상 활성). 나머지 지시문은 본문에서 제거하고 재현하지 않는다고 안내하며, 본문 중간의 지시문은 해석하지 않고 차이를 알려요. 카드·모듈·CharX 내부 모듈이 같은 변환을 사용해요. 검사는 `tests/risu-import.test.ts` 19개예요.

플러그인 묶음의 다음 항목으로 **Risu 플러그인 파일 읽기와 지원 범위 보고**를 만들었어요. 같은 가져오기 화면에서 `.js`를 고르면 선언한 이름·표시 이름·API 버전·인자·링크를 읽고, 본문이 쓰는 `risuai.*` 이름을 현재 계약과 대조해 **대응 가능·미구현·제공하지 않음**으로 나눠 보여 줘요. 판정 근거는 v3 선언 목록 69개와 기존 결정(주 앱 DOM 미도입, 원문 보존, 일반 HTTP·제공자 어댑터 미구현, 격리 패널 경계)이에요. 코드는 실행하지 않고 자료로 등록하지도 않아요. 이 보고는 남은 108개 미구현 표본 기능의 범위를 실제 파일로 판단하는 입력이에요. 검사는 `tests/risu-plugin-import.test.ts` 3개이고 전체 `npm test`는 2,516 PASS·23 FAIL(로컬 baseline 동일), `quality`·`build` PASS예요.

배포 항목의 **운영자 CLI controller**를 구현했어요. `prepare → close → drain → stop → backup → candidate → switch → reopen`을 한 번의 요청 키로 수행하고, admission은 앱의 유지보수 게이트를 그대로 사용해요. 후보는 백업에서 만든 새 volume에 `NR_MAINTENANCE=1`로 부팅해 migration·읽기만 확인하고, 전환은 `.env.self-host`의 `UIMORI_IMAGE`·`UIMORI_DATA_VOLUME` 두 줄만 바꿔요. 쓰기 재개 전 실패·취소는 이전 바이트·이미지·volume으로 되돌리고 게이트를 열며, 재개 뒤에는 자동 복귀도 취소도 하지 않아요. journal은 앱 DB·이미지 밖에 두고 같은 키의 재요청은 기존 영수증을 돌려줘요. Docker·HTTP는 주입값이라 `scripts/update-controller.test.mjs` 6개(정상 전환·idempotency·후보 migration 실패·백업 실패·전환 health 실패·취소·동시 키 거절)가 `npm run test:tooling`에서 통과해요. **실제 Docker 호스트의 image/volume 전환 검증은 사용자가 맡기로 했고 이 세션에서 실행하지 않았어요.** compose의 `image:`를 `${UIMORI_IMAGE:-uimori:local}`로 바꿔 기본 동작은 그대로 유지했어요.

대화 권한은 이미 결정됐어요. 정확한 자료 개정에 별도 허용한 **현재 선택 분기의 사용자 가시 대화 전체**가 범위이며 모델 문맥 절삭과 별도예요. [대화 Host](../docs/EXTENSION-PROGRAMS.md#host-api로-현재-분기-대화-읽기)의 고정 참조·최신 권한·영수증·복원 경계를 사용해요. 새 요청으로 가시 대화가 달라지면 자동 동작 묶음을 재계산하지만 source/state에 따른 추첨 entropy는 유지해요. 진행 대기와 여러 채팅의 동시 사용도 기존 기능이에요.

지금 답을 기다리는 제품 결정은 없어요. 새 대화 변경·삭제, 다른 자료 읽기·외부 전송처럼 기존 허가보다 넓은 권한이 실제로 필요해지면 효과·보존 방식·대안과 추천을 준비해 사용자에게 물어요. 기존 원문 보존과 변경 안내 안의 API 배치·실행 연결은 구현자가 결정해요. 미지원 API를 성공한 것처럼 처리하거나 모든 봇의 로어북에서 기억을 자동 분리하지 않아요.

새 세션은 이 절과 [Lua 지원 범위](../docs/RISU-IMPORT.md#lua-콜백-가져오기), 필요한 [코드 지도](CODE-MAP.md)부터 읽으면 돼요. 검사 증거는 아래 날짜별 기록이 소유하며 현재 변경의 영향 검사만 선택해요. 현재 묶음에서 실제 외부 모델·실기기·전체 표본 인수는 수행하지 않았어요.

별도 후속 순서는 **Plugin v3 주요 스펙의 공통 API/어댑터 연결 → 대용량 자료 → Linux/Docker 설치·Update·복구·최소 진단/문서 → 베타 인수**예요. Provider Manager·LogPlus 등은 API 사용 사례이며 특정 플러그인의 모든 기능을 복제하는 것이 목표는 아니에요. 전체 제공 표본의 실사용 평가는 사용자가 진행해요.

### 완료한 첫 흐름: Risu 프리셋 가져오기와 실제 적용

**목표:** 프리셋 파일에서 프롬프트·커스텀 토글·정규식을 가져와 저장하고, 옵션을 바꾸어 실제 채팅에 적용할 수 있어야 해요. Phēmē 일반형·Tool Call형은 기능 확인 표본이고, 모델·프로바이더·파라미터·도구 설정의 복제는 완료 조건이나 미지원 손실에 포함하지 않아요. 파일에서 가져온 프롬프트·토글·지원 정규식을 실제 전송·표시에 연결했어요. 내장 Phēmē나 native JSON 가져오기의 존재와 구분하며, 전체 Risu 실행·실모델 품질 인수는 별도로 남겨요.

## 작업과 완료 기준

**현재 상태의 기준은 이 절과 아래 단계 표예요(2026-09-14).** 날짜별 구현·검증 기록의 ‘현재’·‘남아 있음’은 해당 작업 당시의 상태이며, 이후 구현과 상충하면 이 절을 따라요. 과거 검사 수·run ID·hash는 당시 근거로 보존하며 현재 소스의 새 검증 결과로 재사용하지 않아요.

현재 DB는 **20**, 전체 archive는 **15**, 채팅 백업은 **1**이에요. `user`·`model`·`before-turn`·`after-turn`의 JavaScript·Lua 격리 계산과 공통 변수·자기 자료·현재 분기 대화·모델 Host API를 제공해요. 카드/모듈 가져오기의 독립 Lua는 `onInput`·`onStart`·`onOutput`·`onButtonClick`과 `listenEdit`의 `editInput`·`editRequest`·`editOutput`·`editDisplay` 전부, 지원하는 조건과 대화 조회 함수를 기존 행동 경로에 연결했어요. 기본 변수·지원 CBS 읽기·사용자 공유 변수·예약 고정·분기/백업 보존은 기존 공통 경로를 사용해요. **현재 남은 구현은 나머지 트리거 효과 종류, 자료/UI API와 동적 화면 연결**이에요. 선언형 `setvar` 트리거와 스크립트가 첫 효과가 아닌 혼합 트리거는 연결했어요. 입력·전송문 편집(`editInput`·`editRequest`)은 전송 사본 투영으로, 출력·표시 편집(`editOutput`·`editDisplay`)은 응답 후 한 번 계산하는 표시 사본 투영으로 연결했어요. 일반 HTTP·공유 자료 권한·확장 설치 관리도 아직 미완이며 필요한 기능만 현재 흐름에 보완해요. Plugin v3 주요 스펙, 대용량 자료·Linux/Docker Update·배포는 별도 후속 범위이고 전체 표본 실사용은 사용자가 평가해요. 현재 연결을 요청 전체·전체 표본·베타 완료로 표시하지 않아요.

## 날짜별 구현·검증 기록

아래 기록은 작업 당시 상태와 증거를 보존해요. 현재 지원 여부는 위의 작업과 완료 기준을 먼저 확인해요.

### Lua 격리 실행과 첫 원본 콜백 연결 · 2026-09-13

`ExtensionProgram.language`로 Lua/JavaScript를 선택하며 과거 생략 값과 hash는 유지해요. Wasmoon 1.16.0의 Lua를 별도 Worker에서 고정 16 MiB WASM·8 MiB allocator와 기존 CPU/Host 대기·취소 한도로 실행해요. JSON 전용 경계와 같은 `executePackageExtensionProgram`·변수 영수증·권한·transaction 경로를 사용해요. 원본 Lua 길이를 담기 위해 공통 코드 한도를 512 Ki UTF-16 문자로 늘렸고 자료/입출력/CPU 상한은 유지해요.

CharX·모듈의 독립 Lua를 `onStart → before-turn`, `onOutput → after-turn`, `onButtonClick → user`로 가져와요. Risu 변수·JSON 상태·Changed·`async`·`simpleLLM`을 공통 Host에 대응하며 JSON null/빈 테이블과 저장 override 의미는 어댑터가 처리해요. `variables.read.overridden`은 목록 API와 같은 의미를 제공해 Changed 구현의 반복 조회를 줄여요. 일반 가져오기·미리보기·복원에서 코드가 실행되지 않아요.

관련 7개 파일의 집중 검사 총 79개와 최종 `quality`가 PASS예요. 실제 합성 파일 가져오기→HTTP 버튼→변수 저장→다음 프롬프트·archive/채팅 백업, 생성 전 콜백→모델 입력·응답 후 콜백→영수증 채택을 확인했어요. 첫 quality의 테스트 서식과 fixture 타입 2건은 실제 계약으로 수정해 재확인했어요. 입력·편집 이벤트와 동적 화면까지 완료한 흐름이 아니므로 이번 중간 커밋에서 전체 검사·브라우저/실모델·전체 표본 인수를 실행하지 않았어요. 그 범위를 완료했다고 주장하지 않아요.

### 현재 분기 대화 Host와 Risu 조회 · 2026-09-14

별도 `conversation.read` capability와 정확한 자료 개정의 채팅별 grant로 현재 선택 분기에서 사용자가 볼 수 있는 전체 대화를 읽게 했어요. 모델 문맥 절삭과 무관한 고정 run/source 참조, 호출별 `viewHash`, 예약·최신 권한 검사를 공통 JavaScript/Lua 실행과 사용자 영구 작업에 연결했어요. 요청이나 보이는 실패 이력이 달라지면 대화 읽기 자동 행동의 묶음을 다시 계산하되 기존 draw entropy를 보존해요. fork·전체 archive·채팅 백업은 참조와 영수증을 보존·검증하고 복원에서 코드를 실행하지 않아요.

Risu Lua의 단일/최근/전체 대화와 마지막 사용자·캐릭터 메시지 getter를 이 Host로 연결했고, 지원하는 `var`·`value` 비교/CBS 조건은 native `when`으로 옮겨요. 지원하지 않는 조건은 자동 콜백을 실행하지 않고 원본과 안내를 보존해요. `onInput`과 요청/입력/출력/표시 편집 이벤트는 남아 있어요.

최종 `npm run quality` PASS, `npm test -- tests/package-behavior-run.test.ts tests/package-behavior-run-archive.test.ts tests/extension-conversation-app.test.ts`는 **3파일 60 PASS**예요. 요청 변경 재계산·같은 추첨·fork·복원 회귀도 이 60개에 포함돼요. 그 전에 대화 Host·Risu 어댑터·archive·권한/패키지의 영향 검사를 별도로 통과했고, 후속 캐시 수정 뒤 위 세 파일을 다시 확인했어요. 문서 인계와 마지막 UI 설명 수정은 링크·내용·diff와 해당 파일 Biome으로 확인했어요. 실제 표본·외부 모델·Plugin v3·베타 인수 결과가 아니에요.

### 제작자 행동의 공통 변수 Host API · 2026-09-13

`variables.list/read/set/delete`를 기존 격리 JavaScript 행동과 공통 실행기에 연결했어요. 자료가 읽기/쓰기 capability를 선언하고 쓰기는 사용자가 해당 채팅에서 정확한 자료 개정에 대해 허용해야 해요. 모델 호출 권한과 독립적으로 켜고 끄며 실행·채택에서 최신 권한을 다시 확인해요. Host와 Worker의 공개 오류 목록도 한 곳에서 전달해 같은 거절을 처리해요.

기존 상태 저장·조건·source/revision CAS와 영수증을 재사용해요. HTTP 명령 재전송은 원래 시각/문맥으로 영수증을 비교하고, 패널의 상태 변경은 후속 모델 지침과 출력 해석에 연결돼요. 정의·상태는 기존 전체 백업/복원 경로로 보존해요. 상태 갱신 때 아직 제출하지 않은 다른 폼 입력을 유지하고, 부가 화면 오류는 기본 상태·행동과 채팅 입력을 남겨요. 새로운 DB 표·실험기·유료 모델 호출은 없어요.

검증: 기존 동작/프롬프트/순환 참조 집중 39개와 새 패널 4개가 PASS예요. 첫 새 패널 테스트의 합성 조건식/요청 header 오류는 수정 후 해당 4개만 재확인했어요. 브라우저에서는 선택자 가정, sandbox가 submit 이벤트까지 막는 문제, 초기 조회와 클릭 경합을 발견해 수정했어요. 앞선 실패는 보존하며 최종 `package-panels-2026-09-13T00-40-33-705Z-42241a04`의 PANELUI01(412/2560)·PANELUI02 합계 3개가 PASS예요. 지연 조회 중 클릭, 화면 변경/실패 중 입력 보존, 명시 저장, 기본 UI, 상위 DOM/저장소 차단과 외부 요청 0회를 확인했고 모바일 PNG를 열어 검토했어요. quality·빌드도 PASS이며 전체 릴리스 검사를 실행한 결과는 아니에요.

TVoN의 세부 원본 조회는 현재 사용 가능한 요약 근거로 한정됐어요. 이번 결과는 TVoN 같은 자료에 필요한 공통 시작/화면 기능이며 원본 선택 트리·전체 기능 수용 완료가 아니에요. 임의 JS/Lua 실행·원본 자료의 실제 연결·과거 원고별 패널·이미지/미디어와 전체 표본 인수는 남아 있어요.

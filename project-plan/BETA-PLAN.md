# v0.1.0 베타 실행 계획

제품 원칙·공개 조건은 [2026-09-12 결정](../docs/DECISIONS-2026-09-12-BETA.md)이 소유해요. 이 문서는 실행 순서와 상태를 관리하며 기술 선택을 사용자 확정 사항으로 만들지 않아요. 소스의 현재 기능은 [CURRENT](CURRENT.md), 표본과 기능별 근거는 [BETA-SAMPLES](BETA-SAMPLES.md) · [JSON 기준](BETA-SAMPLES.json)을 봐요.

사용자는 아래 순서에 따른 설계·구현·검증을 승인했어요. 원칙 안의 기술 선택은 진행하고, 경험·의미·지원 범위를 바꾸는 선택은 검토 가능한 결과를 준비해 사용자와 논의해요. 새로운 유료 평가·개인 자료 외부 전송·배포의 실행 권한은 해당 단계에서 확인해요.

## 채택한 작업 방식 · 2026-09-13

현재 요청 범위는 **트리거·Lua 실행 연결과 동적인 봇·모듈 기능 구현**까지예요. Plugin v3는 주요 스펙의 어댑터 연동을 목표로 하는 후속 작업이고 특정 플러그인 전체 기능 재현은 요구하지 않아요. 전체 표본의 실사용 테스트는 사용자가 담당해요. 아래 날짜별 기록과 표본 대응표의 과거 전체 인수 조건은 [후속 결정](../docs/DECISIONS-2026-09-12-BETA.md#문서와-공개-조건)으로 대체되며, 현재 작업에서 배포·베타 인수까지 자동 진행하지 않아요.

사용자는 Risu의 고정 명세·실제 구현을 호환 동작의 근거로 삼고, Uimori 공통 API에 대응시키는 작업 방식을 채택했어요. 6단계와 공개 조건은 유지하며 **2~3단계의 필요한 기반 보완과 4단계의 기능 연결을 실제 사용 흐름 하나로 수행**해요. 제품 원칙은 Uimori가, Risu 함수명·자료 구조의 해석은 호환 어댑터가 소유해요. 새 Risu/RisuAI-Next 버전은 별도 지원 판단을 거치며 현재 공개 조건에 자동 추가하지 않아요.

사용 흐름별로 사용자에게 생기는 결과와 완료 조건을 정하고 **필요한 명세 확인 → 기존 API 대응 → 부족한 공통 기능과 어댑터 구현 → 관련 검증 → 필요한 문서 갱신·로컬 커밋**까지 마쳐요. 이 계획에 이미 정한 흐름의 작은 구현마다 별도 계획·결과 문서를 만들지 않아요. 대응은 기존 API 연결·기존 API 보완·새 공통 기능·의도적 차이·미확인으로 구분해요. 같은 기능은 같은 API/메서드를 사용하며 특정 표본명·옵션명을 본체의 실행 분기로 만들지 않아요. 표본은 실제 사용과 명세 누락을 확인하는 사례로 사용해요.

조사는 현재 완료 조건을 바꾸는 미해결 문제에 한정해요. 전체 명세 전수 조사나 범용 기반·검증 도구의 확대를 매 작업의 선행 조건으로 삼지 않아요. 필요한 검사와 사용자 흐름이 통과하면 해당 묶음을 마치고 다음 기능으로 이동해요. 기존 데이터 보호·필수 검사·후속 승인한 RPack·AGPL 라이선스 조건·유료 평가 승인 범위는 유지해요. 독립된 하위 작업만 난도·위험·비용에 맞는 모델과 추론으로 위임하고, 주 작업자가 연결 결과를 확인해요.

### 검사와 커밋 단위 · 2026-09-13

[QUALITY의 검사 시점](../docs/QUALITY.md#실행-시점)이 현재 기준이에요. 작은 구현·커밋에서는 품질·영향받는 집중 검사를 하고, 아래처럼 사용자에게 연결된 사용 흐름이 완성될 때 전체 품질·smoke·관련 영역 검사를 묶어요. 저장·권한·공통 실행 경계의 회귀는 즉시 확인하며, 문서만 바꿀 때는 내용·링크·명령·일관성·diff를 확인해요. 작은 후속 수정은 영향받는 검사만 갱신하고 이전 전체 결과와 구분하며, CI·릴리스 영수증·베타 공개 조건은 유지해요.

| 등록·보존·재사용 | 읽은 프리셋의 원본과 사용자 설정 | 기존 프롬프트 저장·자료 이동·백업 계약 | 새 자료의 명시 등록과 원본·미지원 요소 보존, 반복 가져오기와 취소의 기존 자료 보호를 확인해요. |

완료에는 파일 가져오기·검토·저장·옵션 변경·채팅 실행의 연결과 프롬프트/정규식 효과가 포함돼요. 미지원·불확실·의도적 차이는 사용자에게 드러내고, 일부 JSON 경로나 파서만 완성한 경우 전체 묶음 완료와 구분해요. 모델 의미 품질 판단이 필요할 때만 기존 승인 범위의 실제 모델을 사용해요. 원본 코드·개인 자료를 공개 fixture나 로그에 복사하지 않아요.

현재는 `.risup`·구형 `.risupreset` 바이너리와 JSON/프로젝트 ZIP을 읽고 프롬프트·템플릿·토글의 검토·명시 등록·편집·기존 채팅 적용을 연결했어요. RPack 해독 치환표를 포함하고 AGPL-3.0-only와 원본 고지를 적용했어요. 프리셋 전송 전·표시 정규식도 기존 프롬프트 저장·편집·미리보기·본문 전송·Reader에 연결했어요. memory 슬롯의 위치·래퍼와 전체 메시지 CBS 재평가 차이는 안내해요. 카드·모듈의 기본 등록과 기본값 읽기, 정확한 자료 개정의 별도 허용을 사용하는 현재 분기 대화 Host와 Risu Lua 조회 함수를 구현했어요. 다음 구현은 위의 공유 상태·행동 흐름에서 남은 입력·요청/출력·표시 이벤트예요.

## 작업과 완료 기준

**현재 상태의 기준은 이 절과 아래 단계 표예요(2026-09-14).** 날짜별 구현·검증 기록의 ‘현재’·‘남아 있음’은 해당 작업 당시의 상태이며, 이후 구현과 상충하면 이 절을 따라요. 과거 검사 수·run ID·hash는 당시 근거로 보존하며 현재 소스의 새 검증 결과로 재사용하지 않아요.

현재 DB·archive·채팅 백업 버전은 [DATA-MIGRATIONS](../docs/DATA-MIGRATIONS.md#현재-버전)이 소유해요. `user`·`model`·`before-turn`·`after-turn`의 JavaScript·Lua 격리 계산과 공통 변수·자기 자료·현재 분기 대화·모델 Host API를 제공해요. 카드/모듈 가져오기의 독립 Lua는 `onInput`·`onStart`·`onOutput`·`onButtonClick`과 `listenEdit`의 `editInput`·`editRequest`·`editOutput`·`editDisplay` 전부, 지원하는 조건과 대화 조회 함수를 기존 행동 경로에 연결했어요. 기본 변수·지원 CBS 읽기·사용자 공유 변수·예약 고정·분기/백업 보존은 기존 공통 경로를 사용해요. **현재 작업은 위의 검토 후속 계획이고, 그 뒤 남은 호환 구현은 나머지 트리거 효과 종류·자료/UI API·동적 화면 연결**이에요. 선언형 `setvar` 트리거와 스크립트가 첫 효과가 아닌 혼합 트리거는 연결했어요. 입력·전송문 편집(`editInput`·`editRequest`)은 전송 사본 투영으로, 출력·표시 편집(`editOutput`·`editDisplay`)은 응답 후 한 번 계산하는 표시 사본 투영으로 연결했어요. 일반 HTTP·공유 자료 권한·확장 설치 관리도 아직 미완이며 필요한 기능만 현재 흐름에 보완해요. Plugin v3 주요 스펙, 대용량 자료·Linux/Docker Update·배포는 별도 후속 범위이고 전체 표본 실사용은 사용자가 평가해요. 현재 연결을 요청 전체·전체 표본·베타 완료로 표시하지 않아요.

## 날짜별 구현·검증 기록

작업 당시의 상태·수치·실패를 보존한 기록은 [베타 계획 기록 2026-09](history/BETA-PLAN-2026-09.md)로 옮겼어요. 현재 지원 여부는 위의 작업과 완료 기준을 먼저 확인하고, 이 문서에는 검사 수를 새로 쌓지 않아요.

## 유지할 기반과 보완할 경계

- SQLite·관계형 실행 이력·검증된 JSON 패키지, 프롬프트/모델 분리, 공통 예약 snapshot과 원문/분기 귀속을 유지해요. 측정 없이 전면 재작성·정규화·DB 교체를 선행 조건으로 삼지 않아요.
- 동시 채팅·작업 표시·모델 자율 조회·문맥 관리·DB 독립 채팅 백업은 이미 존재해요. 새 시스템을 중복해 만들지 않고 필요한 경계를 보완해요.
- 확장 코드와 의존성은 공통 host API를 사용하고 자료명별 본체 예외를 만들지 않아요. 파서 선택과 실행 격리의 실효성을 구분해 검증해요. 경계·후보·미검증은 [확장 설계 초안](../docs/EXTENSIONS.md)에 기록해요.
- 정상 준비·실패·건너뛰기와 지연 결과의 귀속을 분리해요. 실패한 부가 작업을 복구하면서 본문이나 성공한 효과를 재실행하지 않아요.
- 지원 migration, 자료·확장 상태·의존성의 이동과 삭제/포크/복원 생명주기를 함께 검토해요. 업데이트 버튼은 실제 보존·복구 경로 위에 연결해요.
- 자동 자료 조회·요약의 구조적 동작과 실제 창작 품질을 별도로 평가해요. 외부 기억의 출처를 보존하되 모든 자동 정리를 사용자 승인으로 만들지 않아요.

## 사용자 판단 시점

라이선스·Risu 코드 재사용·CBS 이중 구조·로어 활성화·Lua 대화 변경·Host 한도·Plugin v3 범위는 [2026-09-14 후속 선택](../docs/DECISIONS-2026-09-12-BETA.md#호환-실행의-범위--2026-09-14-후속-선택)으로 결정됐어요. 그 이전의 RPack 선택 이력은 같은 결정 문서의 "문서와 공개 조건" 절이 보존해요.

지금 답을 기다리는 필수 제품 결정은 없어요. 실행 중 다시 물을 항목은 위 검토 후속 계획에 적은 위치 지시문(E5 뒤)과 Plugin 상주 모델(E6 뒤)이에요. V5의 예산 단위는 채팅 설정의 조회 로어 문자 한도로 결정돼 닫혔어요. 그 밖에 다른 방식으로 옮긴 기능의 경험, 개별 자료의 모호한 의미·이용 조건, 실제 외부 평가 범위, 원칙 사이의 충돌, 공개 여부가 구체화되면 사용자와 논의해요. API 이름·테이블·런타임·수치·버튼명 같은 기술 선택은 원칙 안에서 구현자가 비교하고 검증해요.

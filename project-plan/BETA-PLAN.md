# v0.1.0 베타 실행 계획

제품 원칙·공개 조건은 [2026-09-12 결정](../docs/DECISIONS-2026-09-12-BETA.md)이 소유해요. 이 문서는 실행 순서와 상태를 관리하며 기술 선택을 사용자 확정 사항으로 만들지 않아요. 소스의 현재 기능은 [CURRENT](CURRENT.md), 표본과 기능별 근거는 [BETA-SAMPLES](BETA-SAMPLES.md) · [JSON 기준](BETA-SAMPLES.json)을 봐요.

사용자는 아래 순서에 따른 설계·구현·검증을 승인했어요. 원칙 안의 기술 선택은 진행하고, 경험·의미·지원 범위를 바꾸는 선택은 검토 가능한 결과를 준비해 사용자와 논의해요. 새로운 유료 평가·개인 자료 외부 전송·배포의 실행 권한은 해당 단계에서 확인해요.

## 채택한 작업 방식 · 2026-09-13

사용자는 Risu의 고정 명세·실제 구현을 호환 동작의 근거로 삼고, Uimori 공통 API에 대응시키는 작업 방식을 채택했어요. 6단계와 공개 조건은 유지하며 **2~3단계의 필요한 기반 보완과 4단계의 기능 연결을 실제 사용 흐름 하나로 수행**해요. 제품 원칙은 Uimori가, Risu 함수명·자료 구조의 해석은 호환 어댑터가 소유해요. 새 Risu/RisuAI-Next 버전은 별도 지원 판단을 거치며 현재 공개 조건에 자동 추가하지 않아요.

각 작업은 사용자에게 생기는 결과와 완료 조건을 먼저 적고 **필요한 명세 확인 → 기존 API 대응 → 부족한 공통 기능과 어댑터 구현 → 관련 검증 → 문서 갱신·로컬 커밋**까지 마쳐요. 대응은 기존 API 연결·기존 API 보완·새 공통 기능·의도적 차이·미확인으로 구분해요. 같은 기능은 같은 API/메서드를 사용하며 특정 표본명·옵션명을 본체의 실행 분기로 만들지 않아요. 표본은 실제 사용과 명세 누락을 확인하는 사례로 사용해요.

조사는 현재 완료 조건을 바꾸는 미해결 문제에 한정해요. 전체 명세 전수 조사나 범용 기반·검증 도구의 확대를 매 작업의 선행 조건으로 삼지 않아요. 필요한 검사와 사용자 흐름이 통과하면 해당 묶음을 마치고 다음 기능으로 이동해요. 기존 데이터 보호·필수 검사·후속 승인한 RPack·AGPL 라이선스 조건·유료 평가 승인 범위는 유지해요. 독립된 하위 작업만 난도·위험·비용에 맞는 모델과 추론으로 위임하고, 주 작업자가 연결 결과를 확인해요.

### Goal 재개에 사용할 목표

> 이 계획과 `docs/DECISIONS-2026-09-12-BETA.md`의 최신 사용자 결정을 기준으로 Uimori v0.1.0 베타를 완성한다. 합의한 6단계를 유지하며 기존 공통 API와 호환 어댑터로 실제 사용 흐름을 구현·검증·문서화·로컬 커밋한다. 완료된 프리셋 흐름을 반복하지 않고 CharX 봇·모듈, 필요한 Lua/트리거/CBS와 Plugin v3 기능 연결, 자료 보존, Linux/Docker 배포·업데이트·복구와 전체 표본 인수를 이어간다. Risu의 고정 동작을 참고하되 미래 변경 자동 추종·주 앱 DOM 의존·표본 전용 본체 예외를 도입하지 않는다. RPack과 AGPL의 후속 승인, 메인 프롬프트 덮어쓰기·성격·시나리오 제외, 글로벌 노트의 추가 작문 지침 변환, 독립 .risum 제외와 CharX 내부 해독의 구분을 따른다. 원문·상태·권한·실패 비차단을 보존하고 새 push·배포·운영 변경·개인 자료 외부 전송을 임의로 하지 않는다. 실제 모델 평가를 사용할 때 기존 승인 총 USD 100 미만을 지킨다. 새로운 사용자 결정이나 필수 정보가 필요하면 의존 작업을 멈추고 구체적 대안·추천·차이를 제시하며, 준비된 결과를 기준으로 논의한다. 전체 공개 조건을 충족하기 전에는 목표 완료를 선언하지 않는다.

### 첫 작업: Risu 프리셋 가져오기와 실제 적용

**목표:** 프리셋 파일에서 프롬프트·커스텀 토글·정규식을 가져와 저장하고, 옵션을 바꾸어 실제 채팅에 적용할 수 있어야 해요. Phēmē 일반형·Tool Call형은 기능 확인 표본이고, 모델·프로바이더·파라미터·도구 설정의 복제는 완료 조건이나 미지원 손실에 포함하지 않아요. 파일에서 가져온 프롬프트·토글·지원 정규식을 실제 전송·표시에 연결했어요. 내장 Phēmē나 native JSON 가져오기의 존재와 구분하며, 전체 Risu 실행·실모델 품질 인수는 별도로 남겨요.

완료에는 파일 가져오기·검토·저장·옵션 변경·채팅 실행의 연결과 프롬프트/정규식 효과가 포함돼요. 미지원·불확실·의도적 차이는 사용자에게 드러내고, 일부 JSON 경로나 파서만 완성한 경우 전체 묶음 완료와 구분해요. 모델 의미 품질 판단이 필요할 때만 기존 승인 범위의 실제 모델을 사용해요. 원본 코드·개인 자료를 공개 fixture나 로그에 복사하지 않아요.

현재는 `.risup`·구형 `.risupreset` 바이너리와 JSON/프로젝트 ZIP을 읽고 프롬프트·템플릿·토글의 검토·명시 등록·편집·기존 채팅 적용을 연결했어요. RPack 해독 치환표를 포함하고 AGPL-3.0-only와 원본 고지를 적용했어요. 프리셋 전송 전·표시 정규식도 기존 프롬프트 저장·편집·미리보기·본문 전송·Reader에 연결했어요. memory 슬롯의 위치·래퍼와 전체 메시지 CBS 재평가 차이는 안내해요. 다음 구현 묶음은 카드·모듈의 원본 파일에서 실제 사용까지 같은 방식으로 연결하는 것이에요. 이전에 제안한 대화 조회 API와 숨김 원문 권한 질문은 별도 선행 작업이 아니며, 해당 기능을 사용하는 실제 흐름에서 구체적인 결과와 함께 다시 판단해요. 해당 권한 선택은 아직 승인되지 않았어요.

## 작업과 완료 기준

**현재 상태의 기준은 이 절과 아래 단계 표예요(2026-09-13).** 날짜별 구현·검증 기록의 ‘현재’·‘남아 있음’은 해당 작업 당시의 상태이며, 이후 구현과 상충하면 이 절을 따라요. 과거 검사 수·run ID·hash는 당시 근거로 보존하며 현재 소스의 새 검증 결과로 재사용하지 않아요.

현재 DB는 **18**, 전체 archive는 **15**, 채팅 백업은 **1**이에요. `user`·`model`·`before-turn`·`after-turn` JavaScript와 자기 자료 읽기·`model.generate` Host API, 응답 후 완성 본문 읽기, 사용자 독립 모델 작업과 명시적 상태 변환을 구현했어요. 카드 `.charx`/JSON과 추출한 모듈 JSON/프로젝트 ZIP은 기본 자료를 가져와요. 기본 변수와 지원 CBS 읽기/조건은 공통 템플릿으로 연결했고 저장된 공유 변수 쓰기와 Lua/트리거는 아직 미완이에요. 일반 HTTP·Lua·공유 자료 권한·확장 설치 관리, 원본 스크립트 자동 이식과 전체 표본 인수는 미완이에요. Linux/Docker는 사용자가 선택한 설치 방향이며 일반 Update 실행기·버튼과 배포 인수는 남아 있어요. 2~3단계와 4단계를 위의 사용 흐름 단위로 연결하고 [표본 기준의 현재 구현 보충](BETA-SAMPLES.md#현재-구현-보충--2026-09-13)을 전체 표본 완료와 구분해요.

### 기본 변수와 공통 CBS 읽기 · 2026-09-13

카드·프리셋·프리셋 정규식이 `server/risu-cbs.ts`를 공유하며 `getvar`, 변수 조건과 `#if`/`#if_pure`를 기존 AST로 변환해요. 고정 Risu의 기본 변수는 저장 state의 초기 복사본이 아니라 읽기 fallback이라는 근거에 따라 `ContentPackage`·`PromptProgram`에 일반 문자열 기본값 선언을 추가했어요. `core/template-variables.ts`가 장착 역할·순서와 main 프롬프트 fallback을 해석해 본문·로어·시작문·지침·모델 자료 조회·프리셋 변환·편집 미리보기에 같은 값을 제공해요. Risu 카드 기본값은 bot 역할로만 참여하므로 모듈이 같은 변수를 읽되 카드의 bot 기본값을 덮어쓰지 않아요.

authored 시작문에 기존 `PromptTemplate`를 연결하고 미리보기·확정·fork/archive가 같은 고정 이름과 옵션을 사용하도록 했어요. Risu 시작문의 `{{char}}`·`{{user}}`는 이 공통 AST로 변환해요. 이름 문자열은 다시 해석하지 않고 원래 text/AST는 패키지에 보존해요. 직접 본문 수정이나 생성 방식 전환 때는 안내와 함께 템플릿을 해제해 사용자 편집을 적용해요. generated 시작문과 body/lore의 동적 템플릿은 이 단위에 포함하지 않았어요.

가져오기·시작문 집중 14개, quality·빌드가 PASS예요. 화면 검사의 첫 두 실행은 추가된 시작문 미리보기와 모바일의 역할 변경을 검사 선택자에 반영하지 않아 PFUI01이 실패했고 NSUI01은 통과했어요. 선택자를 해당 편집 영역으로 한정한 최종 `authored-start-template-2026-09-12T19-40-29-834Z-02edd7ff`에서는 두 흐름 모두 PASS예요. 새 하네스나 외부 모델 호출은 없어요.

### 등록 이미지 표시

시작문 미리보기·Reader에 패키지가 허용한 로컬 이미지 참조를 연결했어요. 서버는 원문 시점의 장착 패키지에서 실제 본문에 참조된 inline/both URL만 반환하고, Prose는 그 목록의 정확한 blob 경로만 이미지로 표시해요. 외부 이미지·미등록 이미지·코드/HTML은 자동 로드하지 않아요. 읽기·표시 관련 집중 47개와 통합 후 가져오기/Prose/문맥/순환참조 26개가 PASS였어요(서로 중복되는 검사가 있어 합산하지 않아요). `package-text-images-2026-09-12T19-55-50-158Z-759b27b2`의 NSUI01/PFUI01은 PASS이며 시작문 미리보기와 Reader에서 실제 이미지 디코딩까지 확인했어요. 원문 저장본·모델 호출·자동 배치 작업은 변경하지 않았어요.

### 본문·로어 이름 템플릿

본문/로어에 이름·옵션 AST를 확장하고 Risu 설명·로어·지시의 이름 표기도 연결했어요. resourcesOnly·override·모델 참고와 원문 시점 보조 처리가 같은 이름을 사용해요. 원문과 AST는 보존하고 사용자가 text를 직접 고치면 템플릿을 해제해요. 처리 실패는 원래 글과 진단으로 남기며, 경과 시간에 따라 예약/복원의 텍스트가 달라지지 않도록 기존 예산의 단계·값·출력 상한을 유지하는 호스트 전용 결정적 모드를 적용했어요. 일반 프롬프트의 시간 제한은 유지해요.

결정적 예산·저장 경계 focused 55개, 통합 focused 26개와 위 두 화면 흐름이 PASS예요. 실제 Vela를 운영 데이터와 분리된 임시 DB에 부분 가져오기한 결과는 로어 6개·시작문 3개·이미지 3개, 본문/로어의 미치환 이름 0개, 원본 바이트 보존, 기억 자동 선택/원문 사건 생성/모델 호출 0회였어요. 임시 DB는 제거했고 비본문 결과는 ignored `output/risu-import/vela/product-import-check.json`에 있어요. 내장 모듈·추가 확장 설정은 여전히 미지원으로 보고하므로 전체 Vela 수용 완료가 아니에요.

### RPack을 포함하지 않는 모듈 JSON 경로

기존 RisuToki 프로젝트 추출의 `module.json`을 독립적으로 해석해 로어·이름 템플릿·정적 표시 정규식·JSON 내 이미지와 사용자용 설명을 모듈로 가져와요. 같은 파일 검토/영수증 경로를 쓰되 봇·채팅·기억은 만들지 않고, namespace·트리거·Lua·외부 에셋 등 미지원 부분은 먼저 표시해요. RPack 바이너리 직접 해석은 남아 있어요. quality·빌드, 가져오기/자료 이동 집중 33개, 기존 `verify:native-transfer`의 4개 화면 흐름이 PASS예요. 화면 결과는 `native-transfer-2026-09-12T23-43-34-544Z-e564dc5f`에 있고 실제 원본 `.risum`의 전체 인수 결과는 아니에요.

후속 단위로 모듈 프로젝트 ZIP의 `module.json`·`.risutoki/workspace.json`·분리된 이미지 파일을 연결했어요. 상위 폴더 하나를 포함하는 ZIP도 읽고 파일 목록의 순서를 보존해요. 누락 에셋은 미지원으로 알리고 외부 경로/여러 정의는 거절하며 선택한 ZIP을 원본 영수증에 보관해요. 기존 제한된 ZIP reader와 이미지 저장을 재사용했고 RPack/제3자 ZIP 구현은 추가하지 않았어요. 관련 가져오기 8개와 quality가 PASS예요. 이 경로의 안내는 [RISU-IMPORT](../docs/RISU-IMPORT.md)에 있어요.

### 시작 선택의 종속 옵션 · 2026-09-13

기존 `controls/visibleWhen`을 새 채팅의 시작 선택 영역에 연결했어요. 직접 요청과 각 시작문 사이를 오갈 때 사용자가 바꾼 옵션을 각각 기억하고, 처음 고른 시작에만 제작자 기본값을 적용해요. 미리보기와 확정 snapshot은 같은 최종 값을 사용해요. `__direct__`라는 실제 시작 ID도 직접 요청과 충돌하지 않아요.

quality·빌드가 PASS이며 `package-panels-2026-09-13T00-22-01-541Z-b3e0e772`의 NSUI01과 기존 PREQUESTUI01/02는 PASS예요. 같은 실행의 새 패널 검사는 실패했으므로 실행 전체를 PASS로 해석하지 않아요. 이번 단위는 공통 시작 UI 연결이며 TVoN의 원래 선택 트리·전체 이식 완료는 아니에요.

### 현재 상태의 커스텀 패널 · 2026-09-13

`ContentPackage.panels`의 HTML/CSS와 기존 식 템플릿을 현재 패키지 상태·옵션에 연결했어요. 중첩 목록, 조건별 화면, 접힘, 버튼·폼을 제작자가 구성하고 같은 패키지의 user 행동만 요청해요. 주 앱 DOM·직접 통신·제작자 script를 허용하지 않으며 HTML은 DOMPurify 3.4.15로 정화하고 iframe/CSP로 범위를 제한해요. 실제 사용·제작·한도는 [커스텀 패널](../docs/PACKAGE-PANELS.md)이 소유해요.

기존 상태 저장·조건·source/revision CAS와 영수증을 재사용해요. HTTP 명령 재전송은 원래 시각/문맥으로 영수증을 비교하고, 패널의 상태 변경은 후속 모델 지침과 출력 해석에 연결돼요. 정의·상태는 기존 전체 백업/복원 경로로 보존해요. 상태 갱신 때 아직 제출하지 않은 다른 폼 입력을 유지하고, 부가 화면 오류는 기본 상태·행동과 채팅 입력을 남겨요. 새로운 DB 표·실험기·유료 모델 호출은 없어요.

검증: 기존 동작/프롬프트/순환 참조 집중 39개와 새 패널 4개가 PASS예요. 첫 새 패널 테스트의 합성 조건식/요청 header 오류는 수정 후 해당 4개만 재확인했어요. 브라우저에서는 선택자 가정, sandbox가 submit 이벤트까지 막는 문제, 초기 조회와 클릭 경합을 발견해 수정했어요. 앞선 실패는 보존하며 최종 `package-panels-2026-09-13T00-40-33-705Z-42241a04`의 PANELUI01(412/2560)·PANELUI02 합계 3개가 PASS예요. 지연 조회 중 클릭, 화면 변경/실패 중 입력 보존, 명시 저장, 기본 UI, 상위 DOM/저장소 차단과 외부 요청 0회를 확인했고 모바일 PNG를 열어 검토했어요. quality·빌드도 PASS이며 전체 릴리스 검사를 실행한 결과는 아니에요.

TVoN의 세부 원본 조회는 현재 사용 가능한 요약 근거로 한정됐어요. 이번 결과는 TVoN 같은 자료에 필요한 공통 시작/화면 기능이며 원본 선택 트리·전체 기능 수용 완료가 아니에요. 임의 JS/Lua 실행·원본 자료의 실제 연결·과거 원고별 패널·이미지/미디어와 전체 표본 인수는 남아 있어요.

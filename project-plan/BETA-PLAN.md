# v0.1.0 베타 실행 계획

제품 원칙·공개 조건은 [2026-09-12 결정](../docs/DECISIONS-2026-09-12-BETA.md)이 소유해요. 이 문서는 실행 순서와 상태를 관리하며 기술 선택을 사용자 확정 사항으로 만들지 않아요. 소스의 현재 기능은 [CURRENT](CURRENT.md), 표본과 기능별 근거는 [BETA-SAMPLES](BETA-SAMPLES.md) · [JSON 기준](BETA-SAMPLES.json)을 봐요.

사용자는 아래 순서에 따른 설계·구현·검증을 승인했어요. 원칙 안의 기술 선택은 진행하고, 경험·의미·지원 범위를 바꾸는 선택은 검토 가능한 결과를 준비해 사용자와 논의해요. 새로운 유료 평가·개인 자료 외부 전송·배포의 실행 권한은 해당 단계에서 확인해요.

### 실행 기준 재확인 · 2026-09-13

사용자가 위 6단계와 적절한 추상화를 다시 명시했어요. 현재 집중 범위는 **2~3단계**예요. 이전 기록의 A~F는 위 1~6단계와 대응해요. 표본은 공통 경계의 요구·빈틈을 발견하는 근거로 사용하고, 개별 봇의 전체 재현을 공통 기반보다 앞세우지 않아요. 이번에 시작한 TVoN 세부 이식은 중단했으며 읽기 전용 조사와 ignored 중간 산출물만 보존해요.

- 본체는 자료·상태·권한·실행/작업·입출력·화면의 공통 계약을 소유하고, 자료별 규칙·선택 트리·콘텐츠는 자료/확장에 둬요.
- 새 요구는 먼저 기존 기능, 공통 Host API, 확장 코드 중 적절한 위치를 판단해요. 표본의 함수·변수·동작마다 본체 분기나 스키마 옵션을 추가하지 않아요.
- 선언형 표현은 일반적인 정적 구성과 제한된 계산에 사용하고, 복잡한 알고리즘을 담기 위해 계속 확장해 임의 코드 실행 기반을 대체하지 않아요.
- 각 구현 단위는 현재 단계·공통 계약·자료에 남는 부분·실제 구현과 검증 범위를 짧게 기록해요. 구현된 공통 기능과 표본 전체 수용을 구분해요.
- 4단계의 전체 표본 보존 조건, 5단계의 설치/업데이트 경험, 6단계의 사용자 인수는 그대로 유지해요. 기반 검증을 이유로 별도 실험기·진단 체계를 다시 확대하지 않아요.

### 자기 자료 조회를 위한 Host API · 2026-09-13

**현재 단계: 2~3.** 상태 계산 코드에 `api.host.call` 비동기 메시지 경계를 연결했어요. 첫 메서드는 자기 패키지의 자료 목록/본문 조각 읽기예요. capability 선언, 호출자 고정 범위, 기존 이름/옵션·채팅별 로어 투영과 매 호출의 소유권 검사를 공유해요. 자료를 선택·해석하는 알고리즘은 확장 코드에 두고 특정 표본용 함수를 본체에 추가하지 않아요.

사용자·자동·모델 행동 모두 같은 broker를 사용해요. 게스트 CPU와 호스트 대기를 분리하되 전체 실행 시간·호출 수·프레임/누적 결과 제한을 유지하고 취소 후 요청/결과를 닫아요. 영수증은 capability를 포함한 프로그램 지문과 승인 결과를 보존하고 복원에서 코드를 재실행하지 않아요. 별도 DB 표/로그 수집기는 추가하지 않아요. 제작 경로와 정확한 현재 범위는 [EXTENSION-PROGRAMS](../docs/EXTENSION-PROGRAMS.md#host-api로-자기-자료-읽기)를 봐요.

이 단위는 공통 Host API의 첫 실제 기능이에요. 코드에서의 모델·통신 호출, 다른 자료/의존성 권한, 응답 후 hook과 설치 권한 관리는 남아 있어요. 표본 전체 기능·Linux 제품 실행·베타 인수를 완료로 표시하지 않아요.

검증은 `quality:full` **2169 PASS / 1 SKIP**, smoke F02/F03/F06과 기존 패키지 화면의 EXTPANELUI01/PROGTOOLUI01/PROGPREPUI01 세 경로 PASS예요. 읽기·권한·취소·고정 revision·원문 커밋·복원과 실제 패널 호출을 확인했어요. 최종 로그는 ignored `output/extensions/host-read-quality-full-02.log`, smoke는 `2026-09-13T04-02-26-318Z-bb83ce76`, 화면은 `extension-host-read-2026-09-13T04-02-25-972Z-df0087cf`이며 둘 다 cleanup PASS예요. 첫 품질 실행은 테스트 미사용 import로 멈춘 뒤 정리했고, 직접 Playwright 실행의 환경 미설정 실패는 정식 실행기의 PASS와 구분해요. 새 유료 모델 호출·운영 변경은 없어요.

### 공통 입출력 계약 보완 · 2026-09-13

**현재 단계: 2~3.** 출력 해석은 기존 JSON/구분자 파서에 명시적 줄 범위, 허용 열 수, 누락 가능한 필드의 이전 값 보존을 추가했어요. 여러 레코드의 같은 닫는 기호를 혼동하지 않고, 잘못된 값·중복 레코드·형식 손상은 기존 상태 검증/원자적 저장 경계에서 거절해요. 기존 block 규칙은 유지해요. 레코드 이름·상태 필드·자료별 계산은 본체에 넣지 않아요. 관련 상태/통합/복원 32개 검사가 PASS예요.

이 보완은 선언형 입력 해석의 범위를 명확히 하는 작업이며 임의 코드 실행기의 대체 구현이 아니에요. 새 요구마다 이 스키마를 늘리는 대신 공통 Host API와 확장 코드의 책임을 먼저 판단해요.

생성형 시작은 기존 이름/옵션 템플릿을 사용해 **표시한 요청 = Run.request = snapshot.request = packageStart.text**를 유지하도록 연결했어요. 트랜잭션 안에서 확정하고 재전송은 원래 요청과 전체 명령을 대조해요. 원본/설정 변경 후 과거 실행을 재해석하지 않으며 초과 입력은 상태 저장 전에 거절해요. 한 표본에 맞춘 생성형 전용 길이 예외는 제외하고 기존 4,000자 요청 계약을 유지했어요. 더 넓은 요청 길이 정책은 편집·재요청 등 공통 흐름 전체를 함께 판단할 후속 과제예요.

생성형 시작의 관련 검사 12개, quality·빌드가 PASS예요. `common-boundaries-2026-09-13T01-10-15-713Z-18f9ee5c`에서 선택값/이름에 따른 생성 요청 미리보기와 기존 패키지 편집 흐름(NSUI01/PFUI01) 2건도 PASS예요. 실제 외부 모델 호출·표본 전체 인수·운영 데이터 반영은 하지 않았어요. 이번 단위 이후에도 2~3단계의 핵심 미완료는 임의 코드 실행과 공통 Host API의 제품 연결이에요.

### 사용자 행동의 코드 실행 연결 · 2026-09-13

**현재 단계: 2~3.** `behavior.actions[].program`의 `uimori-state-action-v1`을 실제 서버와 기본 버튼/커스텀 패널에 연결했어요. 제작자는 자료의 알고리즘을 JavaScript에 두고, 호스트는 해당 상태/입력만 전달해 반환한 상태를 schema·코드 지문·프로필/분기/원문/상태 개정과 대조한 뒤 기존 journal에 저장해요. 계산은 transaction 밖에서 수행하며 늦은 결과·중복 명령·실패가 기존 상태와 본문을 덮어쓰지 않아요. 코드/결과 영수증은 포크·archive에서 보존하고 복원 중 코드를 다시 실행하지 않아요.

실행은 새 Worker와 새 QuickJS WASM 인스턴스를 사용해요. 내부 allocator 한도와 별도로 WASM 선형 메모리를 실제 16 MiB로 고정했고, 시간·입출력·동시 실행 상한을 두었어요. 별도 실험기를 다시 늘리지 않고 제품의 상태 저장/화면 경로로 연결했어요. 첫 API는 사용자 행동의 순수 계산이에요. 시작의 `initialAction`, 자동 hook, 모델/통신 broker, Lua 및 확장 설치 권한 관리는 미완 범위로 남아요. [현재 API](../docs/EXTENSION-PROGRAMS.md).

- `npm run quality`와 빌드 PASS.
- 실행기·계약·실제 HTTP·상태/시작/요청·포크/복원·순환 의존성 관련 **12파일 122검사 PASS**. 초기에 런타임 abort 테스트의 rejection handler 등록 시점 문제를 고친 뒤 실행한 최종 묶음이며 전체 회귀 결과로 표시하지 않아요. 로그: ignored `output/extensions/state-program-tests.log`.
- 기존 브라우저 실행기의 **EXTPANELUI01/PFUI01 2건 PASS**: 코드로 계산한 상태의 패널 반영/새로고침 보존, 코드 실패 후 채팅 입력 유지와 기존 자료 편집. run `extension-state-actions-2026-09-13T01-35-29-257Z-f7ee2845`.
- Windows Node 24.14에서 확인했어요. Linux/Docker의 현재 제품 실행·전체 RSS 제한, 실제 표본/모델 인수는 미검증이에요. 운영 데이터 수정·외부 모델 호출·push·배포는 하지 않았어요.

다음 구현은 같은 실행/소유권 경계에 비동기 준비 hook과 필요한 공통 작업 API를 연결하는 단계예요. 특정 자료의 함수를 본체에 옮기거나 선언형 옵션을 계속 늘리는 방식으로 진행하지 않아요.

### 공통 비동기 모델 행동 · 2026-09-13

**현재 단계: 2~3.** 기존 자동 준비가 예약 transaction과 snapshot 확정에 묶여 있음을 확인했어요. 자동 준비 hook을 연결하기에 앞서, 계산과 효과 채택을 분리한 공통 async 경로를 모델 행동에 적용했어요. `uimori-state-action-v1`과 기존 `triggers`를 재사용하며 자료별 실행기·스키마 옵션·별도 상태 테이블을 추가하지 않았어요.

- 제작자는 같은 코드 행동을 사용자/모델 또는 양쪽에 허용할 수 있어요. 모델은 해당 Run에 고정된 도구와 입력 schema로 호출하고, 코드에는 자기 상태와 행동 입력만 전달해요.
- 계산은 transaction 밖에서 하고, 취소/원문 소유권과 임시 상태 개정을 재검사한 뒤 opportunity/progress에 채택해요. 현재 상태는 성공 원문 저장 때 게시해요. 동일 입력의 동시 호출은 합치고 호출 ID는 각각 유지해요. 원래 요청과 예약 snapshot은 바꾸지 않아요.
- 코드 실패는 알려진 실패 코드로 모델에 전달하며 본문은 이어갈 수 있어요. 사용자 취소·소유권·실제 DB 오류를 부가 오류로 숨기지 않아요. 커밋과 복원은 입력/호스트 조건 및 코드/결과 영수증을 확인하고 게스트 코드를 재실행하지 않아요.
- `before-turn`의 비동기 코드 준비·건너뛰기, 코드에서 별도 모델/통신 호출, Lua·설치 권한 관리는 후속 범위예요. 공통 async 행동 경로를 자동 준비에 재사용하되, 준비 상태/가공입력은 예약 원본과 구분하는 계약을 유지해야 해요.

시작문 미리보기·Reader에 패키지가 허용한 로컬 이미지 참조를 연결했어요. 서버는 원문 시점의 장착 패키지에서 실제 본문에 참조된 inline/both URL만 반환하고, Prose는 그 목록의 정확한 blob 경로만 이미지로 표시해요. 외부 이미지·미등록 이미지·코드/HTML은 자동 로드하지 않아요. 읽기·표시 관련 집중 47개와 통합 후 가져오기/Prose/문맥/순환참조 26개가 PASS였어요(서로 중복되는 검사가 있어 합산하지 않아요). `package-text-images-2026-09-12T19-55-50-158Z-759b27b2`의 NSUI01/PFUI01은 PASS이며 시작문 미리보기와 Reader에서 실제 이미지 디코딩까지 확인했어요. 원문 저장본·모델 호출·자동 배치 작업은 변경하지 않았어요.

### 본문·로어 이름 템플릿

본문/로어에 이름·옵션 AST를 확장하고 Risu 설명·로어·지시의 이름 표기도 연결했어요. resourcesOnly·override·모델 참고와 원문 시점 보조 처리가 같은 이름을 사용해요. 원문과 AST는 보존하고 사용자가 text를 직접 고치면 템플릿을 해제해요. 처리 실패는 원래 글과 진단으로 남기며, 경과 시간에 따라 예약/복원의 텍스트가 달라지지 않도록 기존 예산의 단계·값·출력 상한을 유지하는 호스트 전용 결정적 모드를 적용했어요. 일반 프롬프트의 시간 제한은 유지해요.

결정적 예산·저장 경계 focused 55개, 통합 focused 26개와 위 두 화면 흐름이 PASS예요. 실제 Vela를 운영 데이터와 분리된 임시 DB에 부분 가져오기한 결과는 로어 6개·시작문 3개·이미지 3개, 본문/로어의 미치환 이름 0개, 원본 바이트 보존, 기억 자동 선택/원문 사건 생성/모델 호출 0회였어요. 임시 DB는 제거했고 비본문 결과는 ignored `output/risu-import/vela/product-import-check.json`에 있어요. 내장 모듈·추가 확장 설정은 여전히 미지원으로 보고하므로 전체 Vela 수용 완료가 아니에요.

### RPack을 포함하지 않는 모듈 JSON 경로

기존 RisuToki 프로젝트 추출의 `module.json`을 독립적으로 해석해 로어·이름 템플릿·정적 표시 정규식·JSON 내 이미지와 사용자용 설명을 모듈로 가져와요. 같은 파일 검토/영수증 경로를 쓰되 봇·채팅·기억은 만들지 않고, namespace·트리거·Lua·외부 에셋 등 미지원 부분은 먼저 표시해요. RPack 바이너리 직접 해석은 남아 있어요. quality·빌드, 가져오기/자료 이동 집중 33개, 기존 `verify:native-transfer`의 4개 화면 흐름이 PASS예요. 화면 결과는 `native-transfer-2026-09-12T23-43-34-544Z-e564dc5f`에 있고 실제 원본 `.risum`의 전체 인수 결과는 아니에요.

후속 단위로 모듈 프로젝트 ZIP의 `module.json`·`.risutoki/workspace.json`·분리된 이미지 파일을 연결했어요. 상위 폴더 하나를 포함하는 ZIP도 읽고 파일 목록의 순서를 보존해요. 누락 에셋은 미지원으로 알리고 외부 경로/여러 정의는 거절하며 선택한 ZIP을 원본 영수증에 보관해요. 기존 제한된 ZIP reader와 이미지 저장을 재사용했고 RPack/제3자 ZIP 구현은 추가하지 않았어요. 관련 가져오기 8개와 quality가 PASS예요. 이 경로의 안내는 [RISU-IMPORT](../docs/RISU-IMPORT.md)에 있어요.

### 시작 선택의 종속 옵션 · 2026-09-13

기존 `controls/visibleWhen`을 새 채팅의 시작 선택 영역에 연결했어요. 직접 요청과 각 시작문 사이를 오갈 때 사용자가 바꾼 옵션을 각각 기억하고, 처음 고른 시작에만 제작자 기본값을 적용해요. 미리보기와 확정 snapshot은 같은 최종 값을 사용해요. `__direct__`라는 실제 시작 ID도 직접 요청과 충돌하지 않아요.

quality·빌드가 PASS이며 `package-panels-2026-09-13T00-22-01-541Z-b3e0e772`의 NSUI01과 기존 PREQUESTUI01/02는 PASS예요. 같은 실행의 새 패널 검사는 실패했으므로 실행 전체를 PASS로 해석하지 않아요. 이번 단위는 공통 시작 UI 연결이며 TVoN의 원래 선택 트리·전체 이식 완료는 아니에요.

### 현재 상태의 커스텀 패널 · 2026-09-13

`ContentPackage.panels`의 HTML/CSS와 기존 식 템플릿을 현재 패키지 상태·옵션에 연결했어요. 중첩 목록, 조건별 화면, 접힘, 버튼·폼을 제작자가 구성하고 같은 패키지의 user 행동만 요청해요. 주 앱 DOM·직접 통신·제작자 script를 허용하지 않으며 HTML은 DOMPurify 3.4.15로 정화하고 iframe/CSP로 범위를 제한해요. 실제 사용·제작·한도는 [커스텀 패널](../docs/PACKAGE-PANELS.md)이 소유해요.

기존 상태 저장·조건·source/revision CAS와 영수증을 재사용해요. HTTP 명령 재전송은 원래 시각/문맥으로 영수증을 비교하고, 패널의 상태 변경은 후속 모델 지침과 출력 해석에 연결돼요. 정의·상태는 기존 전체 백업/복원 경로로 보존해요. 상태 갱신 때 아직 제출하지 않은 다른 폼 입력을 유지하고, 부가 화면 오류는 기본 상태·행동과 채팅 입력을 남겨요. 새로운 DB 표·실험기·유료 모델 호출은 없어요.

검증: 기존 동작/프롬프트/순환 참조 집중 39개와 새 패널 4개가 PASS예요. 첫 새 패널 테스트의 합성 조건식/요청 header 오류는 수정 후 해당 4개만 재확인했어요. 브라우저에서는 선택자 가정, sandbox가 submit 이벤트까지 막는 문제, 초기 조회와 클릭 경합을 발견해 수정했어요. 앞선 실패는 보존하며 최종 `package-panels-2026-09-13T00-40-33-705Z-42241a04`의 PANELUI01(412/2560)·PANELUI02 합계 3개가 PASS예요. 지연 조회 중 클릭, 화면 변경/실패 중 입력 보존, 명시 저장, 기본 UI, 상위 DOM/저장소 차단과 외부 요청 0회를 확인했고 모바일 PNG를 열어 검토했어요. quality·빌드도 PASS이며 전체 릴리스 검사를 실행한 결과는 아니에요.

TVoN의 세부 원본 조회는 현재 사용 가능한 요약 근거로 한정됐어요. 이번 결과는 TVoN 같은 자료에 필요한 공통 시작/화면 기능이며 원본 선택 트리·전체 기능 수용 완료가 아니에요. 임의 JS/Lua 실행·원본 자료의 실제 연결·과거 원고별 패널·이미지/미디어와 전체 표본 인수는 남아 있어요.

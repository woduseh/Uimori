# v0.1.0 베타 실행 계획

제품 원칙·공개 조건은 [2026-09-12 결정](../docs/DECISIONS-2026-09-12-BETA.md)이 소유해요. 이 문서는 실행 순서와 상태를 관리하며 기술 선택을 사용자 확정 사항으로 만들지 않아요. 소스의 현재 기능은 [CURRENT](CURRENT.md), 표본과 기능별 근거는 [BETA-SAMPLES](BETA-SAMPLES.md) · [JSON 기준](BETA-SAMPLES.json)을 봐요.

사용자는 아래 순서에 따른 설계·구현·검증을 승인했어요. 원칙 안의 기술 선택은 진행하고, 경험·의미·지원 범위를 바꾸는 선택은 검토 가능한 결과를 준비해 사용자와 논의해요. 새로운 유료 평가·개인 자료 외부 전송·배포의 실행 권한은 해당 단계에서 확인해요.

## 작업과 완료 기준

| 단계 | 결과 | 상태 |
| --- | --- | --- |
| A. 기준 정리 | 결정·현재 동작·미구현 구분, 기존 제한의 관계 정리, 표본 지문과 추적 가능한 기능/증거 기준 | 완료: 결정·지도·12개 표본 지문·212개 발견 항목/coverage gap. 세부 조사 전체 완료와는 구분 |
| B. 공통 경계 | 확장 권한·실행·자료/상태·UI·실패/복구·버전 계약. 복잡한 표본의 대표 동작으로 경계 확인 | 진행: 기존 상태/behavior 실패 분리와 확장 엔진 후보 검증 |
| C. 보존·확장 기반 | migration·자료/프롬프트/의존성 이동·백업/복원, 확장 실행, 최소 진단 | 진행: migration 기반 검증 후 native 자료 묶음 이동·개인정보 제외 진단 보고서 구현. 확장 실행·추가 진단 수집은 후속 |
| D. 전체 표본 | 자동 가져오기·호환 실행·네이티브 이식, 실제 자료의 기능과 조합·기억 활용 검증 | 대기 |
| E. 배포 경험 | 일반 Linux/Docker 설치와 Update·복구·진단 공유, 사람/에이전트 문서 | 대기 |
| F. 베타 인수 | 지원 환경·실제 표본/모델·회귀·사용자 만족도 근거와 공개 판단 | 대기 |

각 단계의 독립된 작업은 병행할 수 있어요. B에서 Merry·라이트보드·Provider Manager처럼 다른 어려움을 가진 대표 동작을 먼저 확인하되, 모든 표본의 필요한 전체 기능을 공개 전에 끝내는 조건은 유지해요. 문서와 진단은 각 구현에 함께 반영해요.

## 유지할 기반과 보완할 경계

- SQLite·관계형 실행 이력·검증된 JSON 패키지, 프롬프트/모델 분리, 공통 예약 snapshot과 원문/분기 귀속을 유지해요. 측정 없이 전면 재작성·정규화·DB 교체를 선행 조건으로 삼지 않아요.
- 동시 채팅·작업 표시·모델 자율 조회·문맥 관리·DB 독립 채팅 백업은 이미 존재해요. 새 시스템을 중복해 만들지 않고 필요한 경계를 보완해요.
- 확장 코드와 의존성은 공통 host API를 사용하고 자료명별 본체 예외를 만들지 않아요. 파서 선택과 실행 격리의 실효성을 구분해 검증해요. 경계·후보·미검증은 [확장 설계 초안](../docs/EXTENSIONS.md)에 기록해요.
- 정상 준비·실패·건너뛰기와 지연 결과의 귀속을 분리해요. 실패한 부가 작업을 복구하면서 본문이나 성공한 효과를 재실행하지 않아요.
- 지원 migration, 자료·확장 상태·의존성의 이동과 삭제/포크/복원 생명주기를 함께 검토해요. 업데이트 버튼은 실제 보존·복구 경로 위에 연결해요.
- 자동 자료 조회·요약의 구조적 동작과 실제 창작 품질을 별도로 평가해요. 외부 기억의 출처를 보존하되 모든 자동 정리를 사용자 승인으로 만들지 않아요.

## 사용자 판단 시점

현재 A/B 착수를 막는 필수 제품 결정은 없어요. 다른 방식으로 옮긴 기능의 경험, 개별 자료의 모호한 의미/이용 조건, 실제 외부 평가 범위, 원칙 사이의 충돌, 공개 여부가 구체화되면 사용자와 논의해요. API 이름·테이블·런타임·수치·버튼명 같은 기술 선택은 원칙 안에서 구현자가 비교하고 검증해요.

- QuickJS 0.32.0 후보는 기능상 유망하지만 제품 격리용으로 승인하지 않았어요. 로컬 초기 메모리 검사 실패, 단일 대형 할당에서의 제한 성공, 한정된 반복 할당에서의 한도 초과를 각각 보존했어요. 마지막 Linux 반복 할당 검사도 release는 한도 초과 후 정상 완료, debug는 실험 deadline 종료로 기대한 OOM에 도달하지 않아 0 PASS / 2 FAIL이에요. 원인은 미확정이며 외부 격리의 실제 OOM/복구·host broker 검증은 남아 있어요. ignored `output/beta-planning/2026-09-12/runtime-prototype/`와 `oracle-test-environment/ENVIRONMENT.md`가 근거예요. 환경 설정 PASS를 실행 엔진 전체 PASS로 합치지 않아요.

- 개인 자료와 로컬 조사 산출물은 Git 제외 경로에 두고 공개 fixture에는 합성 자료를 사용해요. 이 계획에 개인 원문·키·계정 정보를 기록하지 않아요.

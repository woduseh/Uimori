# Project planning

Use the current request to choose the relevant reference. This directory contains product plans and evidence; it is not a checklist to read before every change.

| Need | Reference |
| --- | --- |
| Product direction and agreed scope | [Beta decisions](../docs/DECISIONS-2026-09-12-BETA.md) |
| Current beta work, progress, and evaluation approvals | [BETA-PLAN](BETA-PLAN.md) |
| Feature contracts and implementation entry points | [CODE-MAP](CODE-MAP.md) |
| Capability summary and remaining work | [CURRENT](CURRENT.md) |
| Sample-specific support and evidence | [BETA-SAMPLES](BETA-SAMPLES.md) |
| Development checks and completion | [QUALITY](../docs/QUALITY.md#verification) |
| Setup and troubleshooting | [DEVELOPMENT](../docs/DEVELOPMENT.md) |
| Acceptance claims and evidence definitions | [VERIFICATION](VERIFICATION.md), [ACCEPTANCE.json](ACCEPTANCE.json) |

[AGENTS.md](../AGENTS.md) is the project agent entry point. Update a feature's owning contract when behavior changes and BETA-PLAN when beta progress changes.

Dated plans, `*-RESULTS.md`, [history](history/CURRENT-2026-09.md), [REVIEW](REVIEW.md), and `KIT_VALIDATION.json` describe earlier work. Their commands, budgets, hashes, and completion claims apply to those snapshots. Initial specification versions such as v0.6.1 are not app release versions. Retired bootstrap prompts, templates, and guidance audits are available in Git history.

Links under `output/` work only where the original local evidence is retained.

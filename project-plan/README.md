상태: **개발 전 통합 명세. 앱·제품 테스트·라이브 모델을 실행한 결과가 아니다.**
작성일: 2026-09-06. v0.6의 최종 소규모 정정본이다. 모델 주도 로어·스킬 선택, 메인 창작/보조 처리, 기술 조합과 M0–M3 범위를 유지한다.

## 이번 묶음만 작업 기준으로 사용

이 문서 묶음은 이전 v0.1–v0.6을 매번 겹쳐 읽도록 하는 추가 덧붙임이 아니다. 제품 결정과 개발 계약을 통합했다. 기존 자료는 삭제하지 않지만, 새 작업에서는 이 디렉터리를 기준으로 삼고 과거 지시문을 동시에 실행하지 않는다. 대화 전체가 Codex에 자동 전달된다고 가정하지 않는다.

현재 사용자의 명시적 요청과 상위 도구/조직 정책을 따르며, 범위 내 프로젝트 계약의 소유권은 다음과 같다.

| 파일 | 소유하는 내용 |
|---|---|
| [PROJECT.md](PROJECT.md) | 사용자 목적, 우선순위, 실제 사용 조건, 비목표 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 데이터·자율 조회·역할별 작업 공간·번역·상태·이미지 표현 계약 |

처음에는 PROJECT, MILESTONES의 M0, ARCHITECTURE의 §1–6 및 §9, VERIFICATION을 읽는다. 이후에는 변경에 필요한 절만 읽는다. ACCEPTANCE의 모든 향후 케이스를 첫 작업에서 구현할 필요는 없다. 파일 간 실질적 충돌은 조용히 선택하지 말고 짧게 결정과 영향을 기록한다.

## 이번 개정의 중심

**작업 목적과 완료 계약은 명확하게, 읽을 자료·조회 순서·표현 선택은 모델에게.** 로어는 model-led discovery가 기본이며 prefetch는 후보 힌트다. 메인에는 창작에 필요한 자료/도구, 보조에는 자기 역할의 지침/자료/도구/출력 스키마를 제공한다. 원문과 표현층을 분리하고 M0 범위는 F01–F06으로 유지한다.

v0.6.1은 원문·후속 예약의 커밋 경계, 미처리 원문의 watermark 방향, 단계별 검증·외부 차단 처리만 보정했다. 새 역할·서비스·단계·수용 ID를 추가하지 않았다. 세부 근거는 [REVIEW.md](REVIEW.md)에 있다.

## 사용 방법

새 프로젝트 폴더 아래에 `project-plan/`이 놓이도록 압축을 푼다. 예시는 `C:\dev\narrative-runtime\project-plan\README.md`다. 기존 저장소에서는 같은 이름의 디렉터리가 있으면 덮어쓰지 말고 별도 위치로 풀어 경로를 알려준다.

Codex에서 그 프로젝트 폴더를 열고 [첫 작업 지시](prompts/01-build-M0.ko.md)를 보낸다. 빈 디렉터리에서도 시작 가능하다. Git 초기화와 일반적인 로컬 준비는 작업 지시 범위에서 에이전트가 수행하며, 외부 공개나 push는 하지 않는다.

완료 후 별도 검토가 필요하면 [독립 검토 지시](prompts/02-review.ko.md)를 사용한다. 다음 구현에는 [이어가기 지시](prompts/03-continue.ko.md)를 사용한다. 이는 세 지시를 처음부터 동시에 실행하라는 뜻이 아니다.

## 자료·비밀정보

이 ZIP에는 실제 소설, 캐릭터 파일, 이미지, 플러그인 소스, API 키를 넣지 않았다. 기존 원문 분석은 설계 근거일 뿐 새 앱의 실행 지시가 아니다. 실제 창작 자료를 제공할 때는 git 제외된 `.local/reference/` 등에 제한해서 놓고, 공개 테스트에는 합성 자료를 사용한다. 파일을 로컬에 두었다고 Codex 모델이 읽는 내용까지 로컬에만 머문다는 뜻은 아니다. 다른 공급자 평가로 재전송하거나 공개하려면 별도 허용이 필요하다.

AGENTS 템플릿은 [templates/AGENTS.md.template](templates/AGENTS.md.template)에 있다. 기존 지침을 덮어쓰지 않는다. 실제 명령을 구현·실행 확인한 뒤 저장소 root의 짧은 지도에 반영한다.

`KIT_VALIDATION.json`은 이 자료 묶음의 구조 검사 결과다. 앱, Windows, 브라우저, provider 또는 번역 품질의 검증 결과가 아니다.

## H01 · 도우미 압축 판정

주요 위치는 `server/helper-runtime.ts`와 `tests/helper-draft-runtime.test.ts`예요. 본문의 `server/model-runner.ts`는 비교 기준으로 사용해요.

- 85%는 압축 시도 기준으로 유지해요. 후보의 실제 전송 입력이 원래 요청보다 작고 모델 입력 한도 이내이면 채택해요. 전체 요청의 10% 감소나 85% 이하를 별도로 요구하지 않아요.
- 정상 완료한 요약이 도움이 되지 않아도 원래 요청이 입력 한도 이내이면 원래 요청·대화·도구 결과·공급자 연속 정보를 유지해요. 원래 요청도 한도를 넘으면 다음 도우미 호출 전에 실패해요.
- checkpoint 게시, 세그먼트 증가, 이전 결과와 공급자 연속 정보 제거는 후보 채택 때만 해요. 후보 계산 중에는 저장 상태를 바꾸지 않아요.
- 도움이 없거나 작은 감소에 그친 압축 직후, 같은 요약 대상에 비용을 반복 지출하지 않도록 실행 중 재시도 기준을 둬요. 새로운 요약 대상이 생기거나 실제 입력 상한을 넘는 등 조건이 달라질 때 재판정해요. 본문의 마지막 읽기 ID 조건을 그대로 복사하지 않고 도우미의 대화·도구 이력에 맞춰요.
- 완료된 변경의 operation ID·revision·결과 영수증은 정확히 유지해요. 압축 여부가 이미 완료된 수정을 재실행할 이유가 되지 않아요.
- EOF·빈 응답·권한 변경·취소를 “도움 없는 요약”으로 취급하지 않아요. 실패한 요약의 호출 수와 사용량도 기록에 남겨요.

회귀 기준은 ① 85% 위의 작은 유효 감소, ② 도움 없는 후보 뒤 서명된 공급자 연속과 원래 결과 유지, ③ 같은 대상의 반복 요약 방지와 새 대상 재판정, ④ 원래 요청·후보 모두 초과 시 전송 차단, ⑤ 변경 효과 한 번·권한·취소·호출 한도·checkpoint CAS 보존이에요. 기존 사례를 확장하고 서로 다른 실패 경계를 필요한 만큼 검증해요.

## H02 · 네 요약 경로의 정보 보존 기준

주요 위치는 `server/context-compaction.ts`, `core/context-tools.ts`, `server/context-tool-compaction.ts`, `server/helper-runtime.ts`예요. 반복되는 의미 지침만 공통 모듈로 추출하고 네 실행기와 저장 수명은 유지해요.

- 핵심 사실은 **누가 → 누구에게 → 무엇을 → 어떤 조건으로** 했는지 보존해요. 별개 약속의 조건, 다른 인물의 계획, 시간 표현을 서로 옮기지 않아요.
- 발생한 사건·계획·인물의 믿음·이행 여부 미확인을 구분해요. 이행 미확인을 실패나 미이행 확정으로 바꾸지 않아요.
- 명시적 사용자 정정, 정확한 식별자·코드·문구, 알려진 출처 위치, 현재 요청과 미해결 질문을 보존해요. 모르는 출처나 결말을 만들지 않아요.
- 이전 요약을 통째로 버리지 않고 현재에 필요한 내용을 다시 구성해요. 모든 장면의 줄거리나 오래된 해결 사건을 계속 누적하지 않아요.
- 공통 기준 위에 경로별 차이를 남겨요. 자동 대화 요약은 다음 턴의 작업 기억, `context.write/new`는 모델이 작성하는 저장·창 전환, 조회 요약은 해당 Run의 임시 참고, 도우미 요약은 대화와 작업 진행·정확한 영수증을 다뤄요.
- 요약·조회 자료는 권한을 부여하지 않아요. 사용자 메모의 우선순위, source/hash 귀속, 과거 Run snapshot, checkpoint 공개 시점을 유지해요.

로컬 검증은 네 경로에 필요한 지침·원문·정정·출처가 실제 요청으로 전달되는지와 저장 경계를 확인해요. fixture가 지침 문장을 받았다는 사실을 실제 모델의 의미 보존 성공으로 보고하지 않아요.

## H03 · 조회 진행 상황과 답변 완료 안내

주요 위치는 `core/context-tools.ts`, `server/context-tool-compaction.ts`와 필요한 실행기 연결 부분이에요. 현재 보존하는 조회 인자·원문 참조를 우선 활용해요.

- 요약 뒤에도 확인한 원문 위치·범위와 아직 답하지 못한 질문을 구별할 수 있게 해요. 필요한 근거를 이미 얻었으면 그 근거로 답변을 마무리하도록 안내해요.
- 정확한 인용·정정·빠진 범위 확인을 위한 재조회는 허용해요. 같은 조회를 강제로 금지하거나 조회 횟수만으로 답변을 성공 처리하지 않아요.
- 진행 정보는 현재 실행의 파생 참고로 관리해요. 원문·정사에 쓰거나 새 영구 기억 스키마를 만들지 않아요.
- 같은 장면이라도 revision/hash나 요청 범위가 다르면 같은 근거로 뭉개지 않아요. 필요한 출처를 전달하지 않고 모델에게 “이미 확인했다”고 주장하지 않아요.

합성 검사에서는 반복 압축 뒤 조회 인자·범위·수정 영수증이 유지되는지 확인해요. 반복 조회 감소와 올바른 완료는 실모델 평가 항목으로 남기며, 단순 호출 수 감소만으로 품질 개선을 판정하지 않아요.

## H04 · 요약 설정의 공통 관리

주요 위치는 세 요약 요청 생성부와 필요한 순수 설정 함수예요. 현재 자동 요약의 최대 2,048 토큰 목표·4,096 토큰 출력 상한을 출발점으로 삼되 소비 모델의 여유와 요약 모델 설정에 맞춰요.

- 목표 길이, 공급자에 보낼 출력 상한, 사고 토큰과 출력 상한의 정합성을 한 기준에서 계산하고 역할별 차이는 명시해요.
- 목표 길이는 모델 지침이며 강제 문자열 자르기가 아니에요. 완성된 후보의 실제 전송 body를 재측정하고 입력 상한을 적용해요.
- `context.write/new`는 별도 요약 모델을 호출하지 않으므로 작업 기억 작성 지침을 공유해요. 이를 별도 유료 요약 경로로 바꾸지 않아요.
- 수치·timeout·일반 호출 한도는 앞서 사용자가 위임한 개발 판단 범위에서 조정하고 근거를 기록해요. 새 설정 화면이나 조절 항목은 이번 범위에 필요하지 않아요.

검증은 작은 입력 한도·낮은 출력 한도·사고 토큰 설정의 경계와 예약 snapshot 불변성을 중심으로 해요. 공통 함수 추출 때문에 새 모듈 값 import 순환이 생기지 않도록 해요.

## 승인된 실모델 비교와 비용 경계

**H01–H04 구현·로컬 검증 후 Gemini 전후 비교를 포함해요.** 구조·저장 경계는 로컬에서 확인하고, 조건 보존과 반복 조회 개선은 실제 모델의 원문·답변으로 따로 평가해요.

실행 기준은 다음과 같아요.

- 기존에 승인한 Gemini 계열과 같은 장부를 이어서 사용하고, 총 상한만 **$150**로 높여요. 기존 R1–R4 예약액 **$38.49258**은 유지해요. 공급자가 실제 비용을 제공하지 않은 호출은 보수적인 예약액을 임의로 환급하지 않아요.
- 합성 자료 네 사례를 출발점으로 약속·정정의 반복 요약, 모델 작성 요약 뒤 원문 회수, 도우미 압축 뒤 완료된 변경 보존, 조회 후 답변 마무리를 비교해요. 필요한 조건·추가 사례는 결과에 따라 조정하며, 완료한 긴 평가를 근거 없이 반복하지 않아요.
- 기준 커밋과 변경본에 같은 입력·모델·입출력/호출 설정을 적용해요. 원인을 비교하는 쌍에서는 설정을 고정하고, 설정 조정이 필요하면 별도 비교로 기록해요. 각 실행은 독립 DB와 새 요청 키를 사용해요.
- 요약을 포함한 모든 공급자 전송 전에 최악 조건의 비용을 같은 장부에 저장하고, 과거 예약과 합해 **$150 이하인 요청만** 보내요. 전송 전 최신 모델·가격을 확인해요. 작업별 호출·출력·시간 한도로 예기치 않은 반복을 제한하되, 일반 설정이나 실행계획 변경에 별도 재승인을 요구하지 않아요.
- 발언자·수신자·행동·조건·이행 여부·정정·출처를 미리 적은 정답표로 원문과 답변을 검토하고, 반복 읽기·압축 수·최종 완료·사용량을 함께 기록해요. 소수 사례를 전체 모델 품질 보증으로 해석하지 않아요.
- 비용 상한·권한 오류·취소·불확실 전송이면 전체 실행을 멈춰요. 응답이 확정된 사례 실패는 실패로 보존하고 독립적인 다음 사례의 진행 가능성을 구분해요. 미완료 외부 요청이나 완료된 수정은 재전송하지 않아요.

일반 설정값과 내부 구현 방식은 에이전트가 판단해요. 실제 검증 범위와 미실행 경로를 구분하고, 승인된 개선·관련 검증이 완료되면 종료해요. 원격 푸시·배포·운영 데이터 변경은 이번 범위에 포함하지 않아요.

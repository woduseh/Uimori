# Uimori

[English](README.md) · **한국어**

긴 원고를 읽고 다음 장면을 이어 쓰는 개인용 창작 웹앱이에요. 내 PC에서 바로 실행하거나, 개인 서버에 올려 PC와 휴대폰에서 같은 작업실을 쓸 수 있어요.

- 봇별로 채팅·폴더를 관리하고, Risu 원본 봇·페르소나·모듈을 사용해요.
- 프롬프트와 모델을 따로 설정해요.
- 원문·번역을 직접 편집하고, 채팅을 독립 사본으로 복사해요.
- 이야기 기억과 백업 기능을 제공해요.

> **현재 버전 `v0.12.17` · DB 스키마 15**
>
> 하네스 전반의 호출·도구 진단 기록을 보존하고, 도우미 사용량은 마지막 입력과 이번 작업 출력을 간결하게 표시해요. 자세한 변경은 [릴리스 노트](docs/releases/v0.12.17.md), 기존 설치의 업데이트 절차는 [업데이트 안내](docs/UPDATES.md)를 참고해요.

## 빠른 시작 (Windows)

**준비물**: Node **24.22.1 이상 24.x**, npm, Chrome 또는 Edge. SQLite는 Node에 포함된 기능을 사용하므로 따로 설치하지 않아요.

1. [GitHub Releases](https://github.com/woduseh/Uimori/releases)에서 `v0.12.17` 릴리스가 공개됐는지 확인해요.
2. 소스를 받아 실행해요.

   ```powershell
   git clone --branch v0.12.17 --single-branch https://github.com/woduseh/Uimori.git
   cd Uimori
   npm ci
   npm run dev
   ```

3. 브라우저에서 [로컬 앱](http://127.0.0.1:4310)을 열어요.

참고:

- 이미 소스를 받았다면 프로젝트 루트에서 `npm ci`부터 실행해요.
- `npm run dev`는 빌드 후 서버를 시작해요. 이미 빌드했다면 `npm start`로 바로 실행할 수 있어요.
- 이전 서버가 켜져 있으면 해당 터미널에서 Ctrl+C로 종료한 뒤 다시 시작해요.

### 처음 사용할 때

1. **채팅 만들기**: **서재 → 봇**에서 자료를 만들거나 고른 뒤 **봇으로 새 채팅**을 눌러요. 왼쪽 탐색에서 봇을 고르고 **새 채팅**을 눌러도 돼요.
   - 봇은 필수이고, 만든 채팅의 소속 봇은 바꾸지 않아요.
   - 페르소나·프롬프트·창작 프리셋은 선택 사항이에요.
2. **모델 등록**: **설정 → 프로바이더와 모델**에서 프로바이더와 모델을 등록하고 전역 역할별 모델로 선택해요. API 키는 앱에서 바로 입력해요.
   - 모델 없이도 채팅을 만들거나 작성된 시작문을 사용할 수 있어요. 본문 생성·번역처럼 모델을 실행하는 역할에는 모델 선택이 필요해요.
3. **장면 요청**: 하단 입력창에 장면 요청을 보내요. 기본 전송 키는 Ctrl/Cmd+Enter예요.
4. **번역**: 원고의 **번역 생성**을 누르면 번역을 시작해요. 저장된 번역은 **번역 보기**로 열고, 실패한 번역은 **번역 다시 시도**로 다시 요청해요.
   - 저장된 번역의 보기 전환과 원문·번역 직접 저장은 모델을 호출하지 않아요.

> **JEV (선택)**: 프로바이더 추가에서 **TypeSafe AI**를 선택하면 **JEV**가 모델 목록에 등록돼요. 본문·번역 거절 판정과 로어 관련성은 JEV가 담당하고, 기존 이미지 배치에는 작문 모델이나 JEV를 선택해요. JEV를 사용하는 기능에만 키 등록이 필요하며, 본문 거절 감지는 기본으로 꺼져 있어요.

화면 언어는 **설정 → 일반 → 화면 언어**에서 한국어·영어·일본어·중국어(간체) 중에서 골라요. 선택은 브라우저에 저장되며, 원고·저장된 번역과 생성·번역 대상 언어는 바뀌지 않아요. 자세한 내용은 [언어 설정과 적용 범위](docs/I18N.md)를 참고해요.

### ChatGPT 구독으로 에이전트 실행 (선택)

개인 ChatGPT 구독으로 에이전트를 실행하려면 [Codex 연결 안내](docs/CODEX.md)에 따라 서버 실행기를 준비하고 **설정 → Codex 연결**에서 로그인해요.

## 개인 Linux 서버에서 사용

[개인 서버 배포 안내](docs/SELF-HOST.md)에 Docker Compose와 Nginx HTTPS 구성이 있어요. 도메인·인증서·접속 토큰을 설정하면 PC와 휴대폰에서 같은 작업실에 접속할 수 있어요. SQLite DB는 영구 volume에 저장해요.

## 버전 확인과 업데이트

- **설정 → 앱 정보**에서 현재 서버의 앱 버전과 빌드 식별자를 확인해요. 앱 버전은 릴리스 번호이며 DB 스키마 번호와는 별개예요.
- 업데이트 알림, 앱 내 설치, 무인 자동 업데이트는 제공하지 않아요.
- 기존 설치는 [수동 업데이트](docs/UPDATES.md#manual-release-update) 절차를 따라요. 운영 중인 Oracle 설치는 [전용 배포 안내](docs/ORACLE-RELEASE.md)를 사용해요.
- 태그나 GitHub Release를 만드는 것만으로는 서버가 업데이트되지 않아요.

## 데이터와 접속

**DB와 백업**

- 기본 DB는 `.local/uimori.sqlite`예요.
- 빈 DB와 [현재 데이터 형식](docs/DATA-MIGRATIONS.md#현재-버전)의 DB만 열고, 구형 DB는 변경하지 않고 거절해요. 옛 백업은 당시 앱 버전과 함께 보관해요.
- **설정 → 데이터 관리 → 백업과 복원**에서 SQLite 백업을 저장해요. 개별 자료와 채팅은 새 사본으로 가져올 수 있어요. [백업·격리 DB 사용법](docs/USAGE.md)
- 테스트용 개발 DB를 초기화하려면 서버를 종료한 뒤 `npm run reset:dev`를 실행해요.

**접속**

- 기본은 `127.0.0.1` 로컬 모드이며, `UIMORI_ACCESS_TOKEN`으로 인증을 켤 수 있어요.
- 개인 서버 모드는 `UIMORI_PUBLIC_ORIGIN`에 HTTPS 주소 하나를 지정하고, 32자 이상의 접속 토큰이 필수예요.
- `UIMORI_HOST`로 수신 주소를 정해요. 외부 수신은 개인 서버 모드에서만 허용해요. [접속 조건](docs/SELF-HOST.md#프록시와-접속-조건)

**API 키**

- 프로바이더 API 키와 JEV 키는 앱에서 입력하고 DB에 저장해요.
- 전체 SQLite 백업에는 키와 이미지가 포함돼요. 사용자 DB와 실행 산출물은 Git에서 제외해요.
